# New migrations go here, never into schema.go's literal

`schema.go`'s `legacyMigrations()` is frozen at 1–43 (shipped, immutable — see
AGENTS.md §3's "forward-only" rule). Every migration from here on is its own
file in this directory, so two worktrees adding a migration at the same time
add two different files — a conflict-free Git merge — instead of two edits to
the same line of the same slice literal.

## Naming

```
<14-digit-YYYYMMDDHHMMSS>_<slug>.sql
```

The timestamp is the migration's real ordering key (`ID` — what the runner
actually sorts and applies by) and must be exactly 14 digits:
`date +%Y%m%d%H%M%S`. The slug is free text, lowercase, underscore-separated.
Two files landing in the same second is harmless (both still apply; the
ledger dedups by the full filename, slug included), not something to guard
against.

## Content

A leading `-- ` comment line becomes the migration's `Description` (what
`aeon db info` prints next to it); everything else is the SQL, applied
verbatim, in one transaction. Example:

```sql
-- S42 T1's widget table
CREATE TABLE widget (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL
);
```

No other Go-side change is required — `Migrations()` (`schema.go`) picks up
every `*.sql` file here automatically, sorted by filename, after the frozen
legacy block. A file whose name doesn't start with 14 digits fails the build
loudly rather than being silently skipped or mis-ordered.

A shipped file is immutable, exactly like the legacy block: new shape, new
file, never an edit to one already merged.

## A CHECK that names another column goes LAST

A table-level `CHECK` — a constraint inside the parenthesised column list that
is not attached to one column definition — must be the **last** item in that
list. Write it anywhere else and SQLite parses the statement against columns it
has not seen yet: `agent_change` failed at store open with
`near "summary": syntax error` for `CONSTRAINT ck_agent_change_slug_names_a_row
CHECK (slug IS NOT NULL OR op = 'migrate')` placed two items before the columns
it names, while the identical constraint placed last applies cleanly (measured
with `sqlite3` on three variants, 2026-11-06, which is why
`20261106181435_agent_change.sql` ends its column list with it).

The failure is not a lint: it is a migration that never applies, discovered by
every test that opens a store rather than by whoever wrote the file.

## What a new file costs elsewhere

Every migration moves a set of pinned counts, and the payments belong in the
same change as the file: `internal/store/backup_run_test.go`'s frozen file and
migration counts, `cmd/aeon/bk_golden_test.go`'s `bkDatabaseLine` applied
count, the two `cmd/aeon/testdata/bk/*.golden` bodies (regenerated by running
the real binary the way the contract test runs it — see that file's headers),
`cmd/aeon/backup_cli_test.go`'s frozen pending-window literal and its
`status --json` applied count. S73 T3's record
(`docs/aeon/S73-agent-crud-page/tasks/T3.md`) is the worked example of paying
all six at once.
