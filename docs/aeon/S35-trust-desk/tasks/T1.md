**Deviation from TD1's own DDL — `created_by`/`decided_by` split into the OL7 actor pair.** TD1 specified
single `created_by TEXT` / `decided_by TEXT` columns, written the same day as the brief, before this
codebase's now-repeated convention for "who did it" solidified. Every authored row added since — S38's
`goal`/`task` (`created_by_kind`/`created_by_id`), S40's `event_trigger` (same), and S38's `review`
(`by_kind`/`by_id` for the *decision* half) — uses the OL7 actor pair, documented verbatim in
`internal/store/actor.go`'s own header comment: *"every record row carries created_by_kind/created_by_id,
and a decision carries the same pair under by_kind/by_id."* This task's own instruction ("read how an
existing write records authorship… use the same token, not a guess") pointed straight at that pair rather
than TD1's single column, so the migration ships `created_by_kind`/`created_by_id` (general three-kind
CHECK, same as goal/task — a proposal is a socket write, not inherently human) and
`decided_by_kind`/`decided_by_id` (CHECK'd to `'user'` alone, mirroring `review.by_kind` exactly, nullable
unlike `review`'s because a proposed row genuinely has no decider yet). **Answers Q3**: `created_by` is the
`store.Actor{Kind, ID}` pair (`internal/store/actor.go:28`) — `Kind` one of `user`/`agent`/`trigger`, `ID`
the human handle/agent name/trigger id. T3/T7 render `CreatedByKind`/`CreatedByID` verbatim (flat fields on
the `Proposal` struct, matching `Goal`/`Task`'s own flat-field convention, not a nested `Actor` on the read
side).

`decideGuarded` is the one guarded-UPDATE both `DiscardProposal` and `DecideProposal` call — the exact
claimed-FROM shape `TransitionPluginAgent` uses (`plugin_state.go:147`): zero rows affected re-reads the
row and returns `"already <status> by <decided_by_id> at <decided_at>"`, matching design.md §2's own
worked example (`"already committed by cjlapao at …"` — confirmed `<who>` is the bare id, not a
kind-prefixed string). `DecideProposal` additionally refuses any `by.Kind != "user"` in Go, ahead of the
schema CHECK — belt-and-suspenders, since T5 (its only caller) is CLI-only by construction, but the
function itself should not trust that forever.
