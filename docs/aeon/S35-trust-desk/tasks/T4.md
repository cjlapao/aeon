# T4 · `agent.enable / disable / revoke` on the socket, and `SaveConfig`

**Prefix:** TD · **Rules:** TD5 (reason discipline), TD4 (`SaveConfig`'s birth) · **Depends on:** T1 (tests
only), conceptually after T3. **Answers plan.md's Q2.**

## Reality finding — the real call path is not `TransitionPluginAgent` directly

Brief §3/design TD5 say the methods call `TransitionPluginAgent` "verbatim." Verified this session: the CLI
verbs do not call it directly either —

- **enable** (`cmd/aeon/agent.go`'s `cmdAgentMove` → `moveVerb`, `agent.go:229-280,346`): reads the record
  with `PluginAgentState`, **re-runs `plugin.Rehydrate`** on the package (a safety re-check — "a package
  that grew a request after install is caught before a verb trusts it"), then `moveVerb` transitions it.
  `TransitionPluginAgent` is underneath `moveVerb`, not called standalone.
- **disable**: the same `cmdAgentMove`/`moveVerb` path with `to: plugin.StateDisabled`, no Rehydrate check
  (that's enable-specific — disabling never re-trusts a package, it only stops one).
- **revoke** (`cmdAgentRevoke`, `agent.go:282+`): calls `plugin.Revoke(name, reason)`
  (`internal/plugin/state.go:130`), which wraps the transition plus whatever else revocation records
  (`VERIFY: read `Revoke`'s body — it may write `plugin_refusal` rows for in-flight work, per
  `store/plugin_state.go`'s `PluginRefusal` type seen in T1-of-S34's recon; if so, the socket method must
  trigger the same side effect, not a thinner one).

**This means the socket methods need the same func-seam pattern as S34's `Agents`/`Plugins`, not a local
`ProposalStore`-style interface** — `internal/plugin` is banned from `internal/protocol` by
`internal/plugin/absent_test.go`'s own stated invariant ("the set of packages carrying the import is
exactly `{cmd/aeon, internal/plugin}`"). Update `../design.md` TD5 and `../brief.md` §3 to say this plainly
in this task's commit: the methods call the **same cmd/aeon functions the CLI verbs call** (`moveVerb`,
`plugin.Revoke`), not the store function one layer further down, so the Rehydrate re-check and whatever
`Revoke` does beyond the bare transition both travel through the new door too.

## Goal

1. A new seam, `Table.AgentTransition` (func, dispatched by method name — same shape as `Table.Agents`/
   S34's `Table.MCP`), carrying `agent.enable {name}` / `agent.disable {name}` / `agent.revoke {name,
   reason}` to the real `cmd/aeon` functions.
2. `internal/mcp/config.go` gains its first and only writer, `SaveConfig(path string, cfg Config) error`:
   validate (`cfg.Validate()`) → write to a temp file in the same directory → `os.Rename` (atomic on the
   same filesystem) → release a per-path lock. **Q2 answered**: measured this session, zero existing
   writers of `mcp.json` anywhere in the codebase (`VERIFY: grep -rln 'mcp.json\|MCPConfigFile' --include=
  *.go | grep -v _test` and confirm every hit is a reader), so a simple in-process mutex keyed by the
   resolved path is sufficient — no cross-process file lock needed yet. Record this decision beside the
   function, per Q2's instruction, so the next writer (if one ever arrives outside this process) inherits
   the reasoning rather than re-deriving it.
