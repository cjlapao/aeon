# T3 · `proposal.create / list / discard` on the socket

**Prefix:** TD · **Rules:** TD2 (guard-blind), TD6 · **Depends on:** T1, T2.

## The wiring pattern — a local interface, not a func-seam like S34's MCP methods

Unlike `internal/mcp` (banned from `internal/protocol` by its own `absent_test.go`), `internal/store` is
**not** banned there — `internal/daemon` already holds `Store *store.Store` on `Options`
(`internal/daemon/daemon.go:144`, confirmed this session) and protocol already gets narrow, package-local
interfaces for exactly what it needs (`protocol.StepStore`, `step.go:166`; `protocol.QuestionStore`,
`:182`), adapted by small functions in `internal/daemon` (`stepStore(s *store.Store) protocol.StepStore`,
`daemon.go:571`). **Follow that pattern, not T2's `cmd/aeon` seam** — `proposal.create`'s store writes are
ordinary writes, not domain logic that lives outside `internal/store`.

T2's `ValidateProposal` seam (in `cmd/aeon`, wired through `daemon.Options`) is still needed for validation
— this task's handler calls **both**: `t.Proposals` (the local-interface store write) and `t.ValidateProposal`
(T2's seam) before writing.

## Notes

**Built 2026-10-29.**

**The `ProposalStore` interface deviated from the task's own sketch twice, both forced by reality:**
1. T1's real `CreateProposal`/`DiscardProposal` take `by Actor` (the OL7 pair), not the flat `createdBy
   string` the sketch guessed before T1 existed — expected, the task said as much.
2. Less expected: `*Session` does NOT belong on the interface at all. The established precedent for "who
   is the human behind this socket call" is `table.ActorFor func(ctx, sess) Actor` (already wired in
   `daemon.go`'s `New()`, stamping `Actor{Kind:"user", ID:<peer uid>}` from the same `d.peer(connID)` call
   `socketRecords.actor` and `triggers.go`'s own handler already use) — a `Table`-level seam, resolved
   ONCE in the handler, not re-resolved inside the store adapter. So `ProposalStore.CreateProposal`/
   `DiscardProposal` take plain `byKind, byID string`; `handleProposalCreate`/`handleProposalDiscard` call
   `t.ActorFor(ctx, sess)` and pass the result through. This also means `proposalStoreAdapter` in
   `internal/daemon` needs only `*store.Store`, not `*Daemon` — simpler than my first draft, which tried
   to resolve the peer uid a second time inside the adapter before I found `ActorFor` already existed.

**`decodeParams`, not raw `json.Unmarshal`.** No existing protocol handler decodes `params` with a bare
`json.Unmarshal` — `decodeParams(raw, v)` (`handshake.go`) is the real shared helper, wrapping a decode
failure in `ErrBadParams` so the transport answers JSON-RPC's own `-32602` rather than an Aeon code.
Switched all three handlers to it after the first draft used `json.Unmarshal` directly and needed a
(nonexistent) `ErrInvalidParams` I had guessed at.

**`ErrProposalRefused` (code `-31710`)** — the highest code in use across `internal/protocol/*.go` was
`-31700` (`ErrQueueRefused`, S24 T7, declared in `queue.go` not `errors.go` — the registry list spans
files); took the next free slot in that family. Declared beside its handler in `proposals.go`, registered
in `errors.go`'s list, matching `ErrQueueRefused`'s own precedent exactly (comment and all).

**Two refusal shapes, deliberately different, both from design.md's own text:** `proposal.create`'s
validation failure is a thrown RPC error (`ErrProposalRefused`) — the payload itself is wrong, same
category as every other "the input is bad" refusal in this codebase. `proposal.discard`'s "already
decided" is an `{"ok": false, "error": "..."}` **result**, never an RPC error — design.md §2's own worked
example shows exactly this shape for discard, and the reasoning holds: a racing decider is an outcome the
UI renders inline, not an exceptional failure to catch. `Half-wired is visible, never silently
permissive` (the discipline S34's seams state): a nil `ValidateProposal` field makes `handleProposalCreate`
refuse — it does not skip straight to the write (an earlier draft of the comment said the opposite; fixed
before the field was ever used).

**Conformance fixtures live in their own `conformance/proposal/` directory**, not `routes/` — found
`conformance/queue/refused.json` is ALSO its own directory (S24 T7's own precedent), so every subject
getting its own folder is the real convention, not routes/-for-everything-else as S34's own fixtures might
have suggested. 5 fixtures: `create.json`, `create-refused.json` (exercises `ErrProposalRefused`, required
by `TestEveryErrorCodeHasAFixture` now that the code is registered), `list.json` (one proposed + one
committed row, showing `decided*` fields present-only-when-decided), `discard.json`,
`discard-already-decided.json` (the ok:false shape, not required for coverage but real).

**`handshake_test.go`'s exhaustive method list** updated with the three new names, same block S34 T3/T4
used.

Tests: 6 new in `internal/protocol/proposals_test.go` (the 4 the task table named, plus
