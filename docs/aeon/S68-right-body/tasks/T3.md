## Notes — the deviations, all reasoned

1. **Schema-pin tests were updated as LEDGER-tracking assertions**
   (`chat_message [source source_ref skills]`, `step_steer [source skills]`,
   the gained-columns count at `automation_schema_test.go:323` → 2). They
   say "tracks the ledger"; the ledger gained columns, the assertions follow.
2. **Deviation (6): doors REFUSE where the offer skips+logs** — no catalog
   wired or a scan fault refuses a CHOICE ("nothing was chosen") while
   no-choice traffic passes untouched (P31's third state kept). The resolver
   is one closure (`chosenCatalogResolver`) shared by every door — Daemon
   field + both steer doors — so a test substitutes a fake scanner without a
   filesystem and no door can drift.
3. **Deviation (7): replay-after-restart softens a resolve fault** to a
   `ChosenSkillsNote` + `d.log.Infof` (never kills the replay, never claims
   the skills rode). The door still refuses — asymmetry is the point: a
   live caller can retry, a replay has nobody to ask.
4. **Unknown ⇒ refuse naming EVERY offender at once** — one offender per
   round-trip is a interrogation, not a door (measured: two unknowns, both
   named, the valid name NOT punished).
5. **Caps count DEDUPED RENDERED content** and refuse rather than truncate —
   a truncated choice is a lie.
6. **Deviation (9): an empty-goal socket start with chosen skills records
   the choice cache-only** (no row to file it on; documented, not silently
   skipped).
7. **`steerWireText` is the ONE join point** (B7): lines, blank line, PURE
   text; resolver fault ⇒ pure text alone. A storeless/nil-resolver daemon
   delivers byte-identical pre-S68 steers (D7).
8. **The queue's named refusal passes through** the protocol door as
   `ErrBadParams` (the caller's mistake) while any other queue fault stays
   `ErrStoreUnavailable` — classification honoured BOTH ways by its own
   test.
9. `TestStepSteerFixturesAreUntouched`'s CR10 digest for `steers.json` was
   re-pinned the way the guard itself demands — the task named in the test's
   own comment block (S68 T3, the additive `skills` receipt field);
   `steer.json` and `steer-cancel.json` untouched at their original digests.
10. A skills-ONLY steer (no text/route/effort) is REFUSED at the protocol
    door — a steer must say or change something; the queue layer would
    compose lines-only fine, the door keeps the contract honest.
