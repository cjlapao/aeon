## Why this exists

`design.md` M2/M4: a directed board question is an ordinary S14 skill invocation targeting the `answer`
skill (T6) on a named agent; on completion, the answer becomes a `learning` row with `provenance: 'relayed'`
(M1) — the one caller allowed to write that provenance (T4's write-protection).

## Scope

**1. `AskBoard(ctx, callerAgent, targetAgent, question string) (Task, error)`**: calls `agentsvc.Invoker.
Invoke` with `Invocation{CallerAgent: callerAgent, CalleeAgent: targetAgent, SkillID: "answer", Text:
question, Mode: TaskAsync}` — never a broadcast, never an unaddressed call (D8, N2); `CalleeAgent` is
always a single named agent, never empty, refused before this function calls `Invoke` at all if it is.

**2. A call naming a skill other than `answer` is refused before reaching `Invoke`** (mirroring S14's own
D4 shape: refused before any model call) — this function's own signature does not even accept a skill
parameter, so there is no code path that could pass one through.

**3. On the Task reaching `TaskCompleted`** (`agentsvc.TaskStore.Complete`/`CompleteWithCost` — poll or
subscribe, whichever this project's existing Task-completion pattern uses elsewhere; check T14's actual
call sites for the established convention rather than inventing a new one), call
`internal/learnings.Append` with `scope: 'project'` (`design.md` M6 — scoped to the asking loop's
`project_root`, not the agent), `provenance: 'relayed'`, `body` the Task's result text.

**4. No new depth bound, no new cycle check (M2).** This task adds zero lines to any chain/cycle logic in
`internal/agentsvc`; it is purely a caller of the real, already-built mechanism there.

(AS11's deletability).

**Two recorded gaps, not authored.** (1) **Resume wiring is not in the daemon.** `AskBoard` files the
`relayed` learning only when the task it created is already completed (an async task is a suspension,
P2/AS4 — `AskBoard` returns while the task is still waiting); a *waiting* task is meant to have the
daemon's task-completion handler call `fileRelayed` on resume, the same completion the `AgentInvoke`
seam settles. That handler does not yet name the board's `fileRelayed`, so the resume half is not
reachable — recorded here as the seam this slice leaves for the next, not fabricated. (2) **The
`SkillAccess` grant is not authored.** The board's invoke needs a `SkillAccess` rule letting one agent
ask another's `answer`; S14's `internal/policy/spec_skillaccess.go` holds no such row, and authoring a
live grant is outside this slice's scope (PL15's authoring door is human-only). Both are named so the
next slice that wires the board knows what it must also do.

**Daemon-first, the board's one write.** The board's `relayed` dep is `learnings.AppendRelayed`
reached through the daemon's one write path (P34); the public `Append` refuses `relayed` (M1), and
`AppendRelayed` is the board's one permitted exception — write-protected to the board hook alone, the
same shape T4's write-protection test pins.
