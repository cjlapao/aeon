# T4 — `aeon learnings` CLI and `learnings.*` socket methods

## Why this exists

The first concrete surface over `internal/learnings`, combined (CLI + socket) the same way S26's T5 combined
them — small surface, no independent validation logic on either side to parallelize against.

**Naming check before starting**: confirm `learnings.*` does not collide with any existing method prefix in
`internal/protocol/method.go` (it should not — `memory` is not a used prefix there either, but this task
double-checks rather than assumes).

## Scope

**CLI verbs**: `aeon learnings add --scope person|project|agent --scope-key … --body … --provenance
told|observed|assumed [--observed-count N] [--tag …]…` · `list [--scope …] [--tag …]` · `show <id>`.

**Socket methods**: `learnings.add`, `learnings.list`, `learnings.show` — `add` never accepts
`provenance: 'relayed'` directly from this surface (M1: `relayed` is written only by T7's board-answer hook,
never hand-authored — refused here with a named reason if attempted).

**Every result renders provenance and strength visibly** — "assumed" prints as the word "assumed," not a
blank or an inferred confidence bar.
