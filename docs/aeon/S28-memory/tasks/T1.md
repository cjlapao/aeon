# T1 — `schema.go`: `learning`, `learning_tag`, `learning_vec`

## Why this exists

Everything else in this slice writes rows here. Find the current highest migration number at the time this
task starts — do not hardcode one.

**Read first:** `design.md` §5 (the schema shape) and §2 (why this is the *first* `vec0` table in this
schema, not a follower of an S22 precedent that does not exist yet). `AGENTS.md` §3's sqlite-vec section —
`sqlite_vec.Auto()` must be called before the database service initialises, and the DSN pragma syntax is
driver-specific — both already proven generically working; this task is the first real consumer of that
proof for a non-S22 corpus.

## Scope

**1. `learning`**: `id` (PK), `scope` (`TEXT NOT NULL CHECK (scope IN ('person','project','agent'))` — D1's
three, closed), `scope_key` (`TEXT NOT NULL`), `body` (`TEXT NOT NULL`), `provenance` (`TEXT NOT NULL CHECK
(provenance IN ('told','observed','assumed','relayed'))` — M1's four), `observed_count` (`INTEGER`,
nullable), `source_loop_slug`, `source_step_id` (both nullable, no FK enforcement required — traceability
only), `created_at`.

**2. `learning_tag`**: `learning_id` (`INTEGER NOT NULL REFERENCES learning(id) ON DELETE CASCADE`), `tag`
(`TEXT NOT NULL CHECK (tag != '')`). Index on `(tag, learning_id)` and on `(learning_id)`.

**3. `learning_vec`**: a `vec0` virtual table (sqlite-vec), one row per `learning.id` where an embedding
route is configured. **No row is required to exist** — a learning with no configured route has no
corresponding `learning_vec` row, and that is the normal, working state (D5), not a gap to fill later.

**4. No SQL foreign key from `learning.scope_key` to anything agent-shaped.** `design.md` §3 explains why:
there is no `agent` table to reference. This task does not add one.
