## Why this exists

**Its own task** (R7), because two requirements here are easy to get wrong and neither is about the action set.

And because of what a key **is not**. The socket's access control is filesystem permissions on a `0600` path (P26). **That
does not project onto a port** — so HTTP needs a key, and the honest framing of what a key buys is what settles N16 in T5:
a key authenticates *a caller*; it does not make the caller a human.

## Scope

### Out of band only (O1, I6, D7)

**Never a command-line argument.** A key on a command line is in the process list and in shell history, and the failure is
**silent and permanent** — nothing errors, and the key is exposed to every process on the machine and every future reader of
`~/.zsh_history`.

**Answer Q9**: where it comes from — a file path or an environment variable — and what happens when it is missing.

```
aeon serve --http 127.0.0.1:7777 --http-key-file ~/.config/aeon/http.key
AEON_HTTP_KEY=... aeon serve --http 127.0.0.1:7777
```

A **path** or a **variable**. The value never appears in `argv`.

### An address without a key refuses to start (N15, D7)

Not a warning. Not a generated default.

```
refused: --http requires a key; a bound port with no key is open to anything on this host
```

**A generated default would be worse than a refusal**, because it works — and something that works is something nobody
revisits.

### Never logged, in any path (I6)

Not in a startup line, not in an error, not in a debug capture, not in `aeon doctor`. Redacted to `<redacted>` wherever a
request is recorded.

Asserted by running **every** error path and grepping the output — the same shape S16's T11 used for a forge token, and for
the same reason: the one path that leaks is the unusual one nobody exercised.

### Errors are discriminated (O5)

An auth failure is **`auth`**, distinct from `not-found` and from `transport`. A caller polling a loop needs to tell *"your
key is wrong"* from *"that loop does not exist"* from *"the daemon is restarting"* — and a single 400 makes all three look
like the caller's mistake.

Constant-time comparison, so a wrong key does not leak its correct prefix through timing.

### Reuse, do not rebuild (Q5)

**Answer Q5**: what does the scaffolding provide for auth, and does it fit one key, one user? **If it provides more than
needed, S1's removal discipline applies** — a multi-tenant auth service configured down to one key is a multi-tenant auth
service someone will later configure back up.

### Not in scope

The HTTP mounting itself (T4). This task is the key and its plumbing; T4 binds the port.
