## Why this exists

Three properties of a **live** surface, which is why they follow the mountings rather than accompanying them.

## Scope

### A slow caller never delays a loop (N8, D11)

N8's rule was written about third-party MCP servers — *"a failing or slow MCP server degrades; it never blocks a step"* —
and the same discipline applies inward: **a slow or abandoned narrow caller must not delay a running loop.**

The failure to avoid: a CI job that opens a connection, polls, and dies without closing. A surface holding a store lock or
a goroutine for it is a surface that degrades the thing it is watching.

So: reads answer from the store and hold nothing; every handler has a timeout; an abandoned connection is reaped. **Bounded
like `bash` is** (W3's discipline, applied here).

### Reads are scoped to this daemon's loops (O4, I7, E4)

There is one user (§8 N5), so this is **not a tenancy check.**

It is a guard against a read action that takes an id and **returns whatever it finds** — which is the shape that *becomes*
a tenancy bug the day multi-user arrives, and which is much cheaper to get right now than to retrofit.

**Answer Q11**: how the scope is expressed. The honest version is that a read resolves an id **within this daemon's store**
and a miss is `not-found` — not a lookup that could reach further if the store ever held more.

### Four discriminated error kinds (O5, D-checks)

```go
type Kind string   // transport | auth | not-found | refused
```

The same shape S16's forge errors used, and for the same reason: **a caller polling a loop needs to tell "your key is
wrong" from "that loop does not exist" from "the daemon is restarting."**

A single 400 makes all three look like the caller's mistake, and the one that is not — a restarting daemon — is the one
where retrying is correct.

| Kind | HTTP | When |
| --- | --- | --- |
| `auth` | 401 | Missing or wrong key (T2) |
| `not-found` | 404 | No such loop, step, or **action** (T5's absence) |
| `refused` | 409 | The daemon understood and declined — a domain refusal |
| `transport` | 503 | Restarting, or the store is unavailable |

**`refused` and `not-found` must not be merged.** T5 deliberately uses 404 for an absent action; a domain refusal on a real
action is 409, and conflating them would make T5's absence indistinguishable from a rejection.

**No error body carries a key** (I6), asserted on every path.

### Not in scope

Auth's own mechanics (T2). Streaming (§8 N4 — the socket carries it).

it; a dead CI job is not, and the second is what happens in practice.
