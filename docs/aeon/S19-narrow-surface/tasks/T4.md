## Why this exists

The mounting CI uses. And **the set-equality test lives here** (R6), because it cannot be written until both mountings
exist — which is the whole reason the mountings are separate tasks.

## Scope

### No port without an explicit address (N15, D7)

The daemon binds nothing by default. **A daemon that listens on a port by default is a daemon somebody exposed by
accident.**

```
aeon serve                                    → no listener
aeon serve --http 127.0.0.1:7777              → refused (T2: no key)
aeon serve --http 127.0.0.1:7777 --http-key-file …   → listening
```

**Confirm Q3**: does the scaffolding already provide an HTTP listener? **If so, use it rather than a second one** — S1's B8
established that services are removed from the registry rather than configured off, and two listeners in one binary is the
kind of thing that ends with the wrong one bound.

### Set equality with stdio (N18, D4, C5)

```
diff <(aeon narrow list --mounting=stdio) <(aeon narrow list --mounting=http)
```

**Empty, and asserted both directions.** An action available over HTTP but not stdio is a **third surface**, and P25 says
there are two.

This is the test that makes N18 real, and it is why the mountings are ordered rather than parallel.

### Say so when it is open (O8, D-checks)

**At startup and in `aeon doctor`** — the address, and that a key is set. **Never the key** (I6).

```
listening on 127.0.0.1:7777 (narrow surface, key configured)
```

**A default only helps the first time.** A listening port nobody remembers opening is exactly what N15 exists to prevent,
and six weeks later the default is not what someone is looking at — the running process is.

### Bind address is not localhost by default either

`--http 0.0.0.0:7777` is permitted, because a CI runner in a container needs it. But **the flag takes an address, not a
port**, so exposing beyond the host is something someone typed rather than something they got.

`aeon doctor` says when the bind is non-local, because that is worth noticing.

### Routes project the table, mechanically (T1, T3)

Same rule as stdio: the mapping is mechanical. A `read` action becomes a GET, a `trigger` a POST, and **no route exists
that the table does not** — asserted on the mux rather than on the table.

### Not in scope

Error discrimination and degradation (T7). Questions (T5). This task binds, projects, and proves equality.
