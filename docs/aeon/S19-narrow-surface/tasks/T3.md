## Why this exists

The mounting editors use. `claude mcp add aeon -- aeon mcp`, and no port involved — which is why it comes before HTTP:
**everything about the surface can be proven here without auth or a listener existing.**

## Scope

### An MCP server over stdio

Each `Action` from T1's table becomes an MCP tool. The mapping is mechanical, and **mechanical is the requirement** — a
mounting that shapes the table is a mounting that has become a second surface.

| Action field | MCP tool field |
| --- | --- |
| `Name` | the tool name |
| `Cannot` | **in the description**, so a model reading the tool learns its limits |
| `Kind` | not exposed; it constrains the table, not the caller |

**`Cannot` reaching the description matters.** A model choosing between tools reads descriptions, and a tool whose limits
are documented only in this repository is a tool the model will try to use for the wrong thing.

### The boundary reaches the client (N14, D2)

`tools/list` carries T1's boundary statement — as a tool-less entry, a server instruction, or whatever the protocol's
natural place is. **Answer that from the MCP specification**, and pick the place a client actually surfaces.

The failure to avoid: a statement present in the protocol response that no client displays. **Verify against Claude Code**,
not against the spec — legibility means a person reads it, and the demo's §2 is where that is checked.

### No operational tool is listed (D1)

The enumeration from T1 holds here too, asserted **on what the mounting emits** rather than on the table it read. A
mounting that added a tool the table does not contain would be the third surface N18 forbids, arriving by a different
route.

### Bounded (N8, N10's discipline)

A slow client must not delay anything. Reads are answered from the store; a trigger returns as soon as the loop is
started, not when it finishes — **a `trigger` that blocked until completion would turn every CI job into a held
connection.**

### Not in scope

Auth (there is none over stdio — the transport is a pipe the parent process owns). HTTP (T4). Questions (T5).

| `TestStdioExposesTheWholeTable` | Every action in T1's table appears as a tool, and **nothing else does** — both directions |
| `TestBoundaryReachesTheClient` | The boundary statement is in the `tools/list` response, in a field a client displays (D2, C3) |

| `TestCannotIsInTheDescription` | Each tool's description contains its `Cannot` entries |
| `TestTriggerReturnsImmediately` | A `trigger` returns a loop id without waiting for the loop, asserted on timing |
| `TestReadsDoNotBlockALoop` | A read issued while a loop advances does not delay it (N8) |
| `TestMappingIsMechanical` | A table entry added in a test fixture appears as a tool with no mounting-side change |
| `TestMalformedRequestIsAnMCPError` | Not a crash, and not a partial response |

`TestMappingIsMechanical` is what keeps the mounting honest. The moment a mounting needs a per-action special case, the
table has stopped being the single source and N18 is at risk.
