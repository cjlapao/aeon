## Why this exists

A slice is not done when its tests pass. It is done when someone who did not build it can follow `DEMO.md` and watch the
thing work (§14).

**And one section of this demo cannot be verified by a test at all**, which is why it is a walk.

## Scope

### Walk every section

**§1 proves a negative first.** No port, connection refused, *before* changing anything. A default that opens something is
the failure N15 exists to prevent, and the only way to show a default is to look at it untouched.

Then confirm an address without a key **refuses to start** — not a warning, and not a generated key, because something that
works is something nobody revisits.

**§2's third question is the slice.** In Claude Code, ask it to kill a loop.

Both halves must land:

- **The capability is absent, not refused.** A `kill` tool that says no is still discoverable, and R6's point is not
  handing an agent the means at all.
- **The absence is legible.** A bare *"unknown tool"* reads like a version mismatch and sends someone hunting for a newer
  Aeon. The boundary statement must reach a field **Claude Code actually displays**, and it must name what to use instead.

**Verify this against Claude Code, not against the MCP specification.** A statement present in a protocol response that no
client surfaces has failed at exactly the thing it was for. If it does not appear, the fix is which field it goes in — and
that is a finding worth recording, since the next client will differ too.

**§3's last exchange** — a keyed POST to answer a gate returning 404 with a reason — is the one people will try to
"improve". Confirm the body says a gate needs a person and names the alternative.

**§4 shows CI's limits holding by composition.** A CI-triggered loop is unattended, so an outward action denies **without
this slice deciding anything.** If that turns out to need configuring, the property is weaker than claimed and the demo
should say so rather than the wording being softened.

**§5's `diff` must be empty.** Set equality between mountings, both directions.

**§6 runs with neither mounting**, because *"at the edge" has to be true in the build, not only in the diagram* (N1).
