# T8 · Walk it, record it, close it

**Rules:** all of PG/AR/CU; the record discipline in `aeon/AGENTS.md` §4a and the demo rule in §4b.
**Depends on:** T1–T7.

## Goal

The page is walked against a running daemon with real agent rows, the findings are recorded whether or not they are
flattering, and the slice's rows in the tracker say what is true.

## Steps

1. Full suites, in this order, each with its `rc=` and tail logged:
   `go build ./...`, `go vet ./...`, `make guard`, `make check-protogen`,
   `go test -tags sqlite_fts5 ./internal/store/ ./internal/protocol/ ./internal/agentmgr/ ./internal/agentseed/
   ./internal/daemon/ ./cmd/aeon/`, then `npx vitest run` and `npx vite build`. Any red that exists at the base commit
   is proved red at the base and named, not edited.
2. A real walk (system Chrome over the built shell, real daemon on a throwaway store, the S72 T4 stub-harness
   precedent under `aeon/scripts/qa-s73-walk/` if it is needed). Walked, in order:
   1. `/config/agents` with the seeded first-party rows — the table's first paint, page 1 of N, and what `total` says.
   2. Sort by `updatedAt` desc, page to 2, search something that matches nothing, then something with a `%` in it.
   3. New agent → the slug the daemon named; edit it → change the description only → reopen and confirm the unread
      fields survived (the AR5 hazard, walked with the real store, not only in a test).
   4. Duplicate it; export it; delete it with the wrong slug typed, then the right one.
   5. Delete an agent a blueprint or policy references and read the refusal as the person sees it.
   6. Import a package from disk (path 5) and commit an `agent_import` proposal (`aeon proposal commit`, path 8), then
      open History on that row and confirm both stamps and the `proposal <id>` line.
   7. `aeon agent import` on the CLI (path 7) and confirm `cli:cli` shows in History.
   8. Migrate (path 6), and confirm one `migrate` row naming the person, not `system`.
   9. With the daemon down: the page shows the not-connected state and every write control is disabled.
   10. The Test bench's `agent-management` page still works as the raw panels it is.
3. Record the findings table with the honest columns — what was walked, what happened, what is now a follow-up. Number
   them from where S72 left off (its F-1…F-8 are its own namespace; S73 opens its own `G-1…` list and says so).
4. Record, in the same change as the code it describes:
   - the slice row in `docs/aeon/SLICES.md` (after S72's) and the eight task rows in the task table;
   - the `docs/aeon/STATUS.md` paragraph;
   - the cumulative demo: `docs/aeon/DEMO.md`'s §S73 section under §4b, with what was walked and what could not be on
     this machine named as a gap;
   - `docs/aeon/PAGING.md`'s adoption table (T1 wrote it; T8 confirms it matches what shipped);
   - this slice's deviations, copied from design.md's list, in the SLICES row's cell so a reader of the tracker sees
     them without opening the design.
5. State the desktop gap honestly if the Tauri window was not opened here (the S49/S58/S59 named-gap precedent), and
   say which evidence stands in for it.

## Definition of done

- The walk ran, its output is on disk under `.s73-scratch/logs/`, and its findings are in this file's Notes.
- `SLICES.md`, `STATUS.md`, `DEMO.md` updated in the same change as the last code commit they describe.
- Acceptance 1–12 of `brief.md` each answered with the thing that proves it (a test name, a walk line, a command with
  its `rc=`), not with a claim.
- `wc -l` of every file this slice touched, collected, with any file that crossed a threshold named and split here.

## Do not

- Do not mark the slice built while a task's gap is unfilled; record the gap the way S70 and S72 recorded theirs.
- Do not fix what the walk finds beyond this slice's scope. Open a `G-n` line and leave the fix to its own task.
- Do not copy long narratives into `SLICES.md`; link the task Notes.
