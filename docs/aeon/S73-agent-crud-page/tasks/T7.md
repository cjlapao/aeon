# T7 · The side panel, the delete modal, the row's verbs

**Rules:** CU4, CU5, CU6, AR5, AR7. **Depends on:** T5, T6.

## Goal

Everything a person does to an agent happens in a panel or a modal, seeded by the daemon and answered by the daemon —
including the nine-field hazard that makes `agent.view` load-bearing.

## Steps

1. New `src/features/agents/AgentPanel.tsx`, a `SidePanel` with `mode: "create" | "edit" | "view" | "import"`:
   - **create** — the three fields `agent.create` takes (`name`, `description`, `functionality`), `FormField` each; the
     daemon's answer shows the created slug, and the person learns the slug from the answer rather than guessing it.
   - **edit** — opens with `agent.view`, holds the whole row in a draft, and renders the **nine** fields `Edit`
     actually writes (design §AR5: Name, Description, Functionality, Prompt, Skills, Metadata, AvatarType, AvatarColor,
     AvatarMood). The rest of the row renders read-only, with the sentence naming why (`version`, `tools`,
     `temperature`, `handoff`, `policyAgent`, `origin`, `internal`, `signed` are not writable through this door). Slug
     and id immutable (AM2), and a name change does not re-slug — in the field's helper text.
   - **view** — `AgentDetail` over the `agent.view` answer, with the History tab beside it.
   - **import** — one field (the package path) and the daemon's answer: created, updated or no-op. Per CU4 the panel
     does not imply a consent review the socket does not carry.
   - On every tab, `agent.changes {slug}` fills **History**: op, actor (`user:1000`, `cli:cli`, `system:seed-engine`),
     `occurredAt`, the summary, and `proposal <id>` where the summary carries one. Its own honest three states. The tab
     carries a **this agent / everything** toggle (`slug` simply absent for everything — no new wire key), and the
     rows that name no single agent (a `migrate` run) render with `every agent` where the slug would be, not a blank.
   - Posting `agent.edit` sends the **whole** draft row in `fields`, not the fields the form showed. This is the shape
     that keeps the nine unrendered fields alive; a test says so in its name.
2. Delete (CU5): `useTypeToConfirm` from `src/lib/useConfirm.tsx`, `confirmValue` the row's **slug**, description the
   daemon's law in the app's words. On `agent.delete`'s refusal — the AM4 sentences naming blueprints, policies and
   MCP servers — the message prints whole and the row stays. On success the table refetches; the screen never drops a
   row locally.
3. Row verbs wired: `Duplicate` (a small `SidePanel` asking the copy's name — `agent.duplicate` needs a slug **and** a
   new name), `Export` (a panel with an optional path, printing the path the daemon answered with), `View`, `Edit`,
   `Delete`. Header verbs wired: `New agent` → create; `Import` → the import panel; `Migrate` → the confirm modal
   printing the daemon's `{created:n}` answer afterwards.
4. A dirty draft asks before being thrown away (`onDirtyChange`, the `BlueprintDrawer` pattern). A close mid-flight
   does not cancel the daemon's write and does not pretend it did.
5. i18n: every new string in en and pt, parity test green.
6. Tests, co-located as the family does it (`src/features/agents/AgentPanel.test.tsx`):
   - opening edit for a planted row calls `agent.view` and not the table's cache;
   - **the nine-field hazard test**: a planted row with `version: "7"`, non-empty `tools`, `bodyHash` and
     `policyAgent`, an edit that changes only the description, and the posted `fields` still carrying everything else
     — the test's name says what it exists for;
   - an `internal` row cannot reach edit/delete from the menu, and the reason is visible;
   - delete requires typing the slug: a wrong slug leaves the button disabled; the refusal renders verbatim; the row
     survives;
   - create shows the slug the daemon named; duplicate names the copy's required name; import shows
     created/updated/no-op distinctly;
   - History renders `user:`/`cli:`/`system:` actors distinctly, shows `proposal 12` when the summary carries it, says
     plainly when the ledger is empty, and the toggle's two states ask `agent.changes` with and without `slug`.

## Definition of done

- The new tests plus T6's pass; `npx tsc -b --noEmit --force` gains no new error; `npx vite build` builds; the guard
  test's allow-list now covers the ten methods with no addition beyond it.
- Every panel and modal opened once in a browser (or the T6 stub harness if no daemon is on hand), the outcome recorded
  for T8 to walk again.
- `wc -l` recorded; `AgentPanel.tsx` under 400 or split (panel shell / form / history) in the same change.

## Do not

- Do not seed the edit form from a table row. AR5 is the reason this task exists.
- Do not render a control for a field `agent.edit` will drop.
- Do not add undo, a diff, or a version rollback to the History tab — it is a ledger, and the tab says so.
- Do not make the delete a one-click button.

### The split the task asked for came from a test, not from a line count

The DoD allowed a split "in the same change" if `AgentPanel.tsx` grew past 400. It did not (273), and it was split
anyway — shell / row body / write hook — because `AgentsScreen.test.tsx`'s boundary case caught a real defect:
`useRpcQuery` asks **when it mounts**, so a single body that served all four modes asked
`agent.view {slug: ""}` the moment a person pressed *New agent*. The daemon would answer that with a refusal naming an
empty slug, in a panel that had done nothing wrong. The fix is structural, not a guard clause: `AgentRowPanel` is the
only component on this page that calls `useRpcQuery("agent.view")`, and the shell mounts it only for `edit` and `view`.
A create form cannot ask for a row it does not have because the code that asks is not in the file it renders.

`post` became `rpcWrite` in the same change, for a reason that is about the guard rather than the UX: the census
(`extractRpcMethods`) reads literal method names passed to a bridge door, and a page may route its writes through one
helper of its own but may not thereby hide them. Naming the helper `rpcWrite` and adding it to the census regex is the
difference between a guard that covers the panel's three writes and one that pretends to.

### Four things the kit does that the plan could not have known (measured, and now in the tests)

1. **`MultiToggle`'s options are `role="radio"` inside a `role="radiogroup"`**, so `getByRole("button", …)` finds
   nothing. The scope toggle is queried as a radio (`AgentHistory.test.tsx`'s `toggleTo`), which is the markup on the
   screen rather than the markup the plan guessed.
2. **`FormField` renders a real `<label htmlFor>`** — `labelFor` wins over the child's `id` — but a `required` field's
   label text is `Name*`, the star being an `aria-hidden` span whose characters are nonetheless in `textContent`. So
   `getByLabelText("Name")` fails on exactly the one field that is required, and the helper matches
   `/^Name\*?$/` instead. Both facts are in the helper's comment because both cost a debugging cycle to find.
3. **`DeleteConfirmModal` is the kit's `alertdialog`** (`dist/index.js:44259` onward), not a `dialog`; the delete tests
   query the role the component has. It also emits the kit's own dev-mode a11y warning
   (`Panel:clickable-nested-interactive`) from inside itself — observed once, in the delete case, and nowhere else in
   the folder's 55 tests. Nothing on this page causes it and nothing on this page can fix it; recorded as **G-1**
   (S73 opens its own finding namespace, per T8's step 3 — S72's F-lines stay its own) rather than patched in a
   shared component mid-slice.
4. **The catalogs cannot contain an apostrophe.** The kit's i18n runs ICU parsing over every value, and a lone `'`
   throws `IcuParseError: unterminated quoted section` **during render**, which React reports only as "recovered by
   synchronously rendering" — the string appears in the DOM while a hidden error path runs. `en.json` carries zero
   apostrophe-bearing values today; `en-agents.json` was written to the same rule, and the test that proved the rule
   was the one that first rendered the panel.

### The hazard test, in the words it asserts in

`the nine-field hazard: editing the description alone posts the row back whole` mounts the screen with the window's row
and `agent.view`'s answer **disagreeing on purpose** (same slugs, different names and versions), so a panel seeded from
the table's cache cannot pass it. It changes one field, and then asks the posted `fields` for the description *and* for
`version: "7"`, `tools`, `bodyHash`, `policyAgent`, `prompt`, `skills`, `metadata`, both avatar columns, `internal` and
`createdAt` — and closes with a key-for-key census, `Object.keys(fields).sort() == Object.keys(VIEW_ROW).sort()`, which
is the same claim with no room for "most of them". Then the table is asked again (2 `agent.rows`), because a row leaves
a table when the daemon says so.
