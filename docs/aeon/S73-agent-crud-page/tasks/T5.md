# T5 · `agent.changes` — the ledger's read

**Rules:** AR6, PG1–PG5, AR8. **Depends on:** T1, T3.

## Goal

The rows the last two tasks mint are answerable over a door, and the paging convention has a second adopter so PG5's
claim is about a shape, not about one file.

## Steps

1. `internal/store/agent_page.go` gains `AgentChangesPage(ctx, slug string, req paging.Request) ([]AgentChange, int,
   error)`: `WHERE slug = ?` when a slug is given, `ORDER BY id DESC`, `LIMIT ? OFFSET ?`, and the filtered `COUNT(*)`
   before the window. No `sort`/`dir` — one order, newest first — and no `q`.
2. `MethodAgentChanges` in `internal/protocol/method.go`, registered like `agent.rows` (a read: `RequiresInitialize`,
   not `Debug`, `agentManageCall`, no actor).
3. `cmd/aeon/agent_rows.go` gains the sibling door: decode `{page,pageSize,slug}`, **ignore** every other field
   (T3's forward-compat rule) and refuse only the closed set `limit`/`cursor`/`offset`/`order`/`search`/`actor`/
   `actorKind` by name, `Normalise` with the ledger's `Bounds`, answer `{changes,page,pageSize,total,slug}` — a shape
   error returning `protocol.ErrBadParams` naming the key, exactly as `agent.rows` does. A slug that matches no row answers an empty
   window and `total: 0` — that is the truth, not an error. An absent slug answers the whole ledger.
4. Fixtures: `changes.json` (two rows, `total` above the window), `changes-slug.json`, `changes-empty.json`,
   `changes-bad-key.json` (an invented `sort` key refused naming it).
5. Surface entry `SurfaceRead` + `HumanDoorOnly`; run the classification guards.
6. `make protogen` && `make check-protogen`; widen any pinned method list with a comment naming S73.

## Definition of done

- Tests over a real store: newest first across three writes by three different actors; a slug filter that cannot see
  another agent's rows; a page past the end answering `[]` with the honest total; an unknown key refused naming it;
  `pageSize` clamp and echo. The same four properties T2 pinned for `agent.rows`, re-pinned here — a convention has to
  hold twice to be a convention.
- `go test -tags sqlite_fts5 ./internal/store/ ./internal/protocol/ -run 'Agent|Conformance|Surface'`,
  `make check-protogen`, `make vet`, `make guard` pass.
- A ledger row written by T3's seed path is visible here with `actorKind: "system"` and `actorId: "seed-engine"` —
  the two tasks meet in a test, not in a hope.
- A `migrate` run's row (its `slug` is NULL, AR1) appears **only** in the unfiltered answer, and a `slug`-filtered
  query does not invent it. Its JSON `slug` is `null`, and the fixture for the unfiltered read carries it so the app's
  type has the nullability from the contract, not from a guess.
- `wc -l` recorded for every file touched; `agent_page.go` is the file to watch, and if it grows past two concerns
  (window + ledger) it splits in this change.

## Do not

- Do not add filters the page has no control for.
- Do not join `agent` to `agent_change` to enrich a ledger row with the row's current name. The ledger says what was
  true when it was written; a slug whose row is gone still has a history, and a join would erase exactly that.
- Do not offer update/delete accessors on the ledger to make a screen easier.
