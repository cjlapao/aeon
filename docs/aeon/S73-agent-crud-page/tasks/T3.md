# T3 · `agent_change`, and the un-audited writers stop existing

**Rules:** AR1, AR2, AR3. **Depends on:** none. Parallel-safe with T1 and T2 (different files; T2 adds
`agent_page.go`, this task edits `agent.go`, `agent_seed.go` and adds `agent_change.go`).

## Goal

One append-only ledger for agent rows, and no exported way to change an `agent` row without naming who did it. After
this task the ledger cannot be skipped by accident — the compiler is the guard, with a source walk beside it.

## Steps

1. New migration `internal/store/migrations/<14-digit-YYYYMMDDHHMMSS>_agent_change.sql`, its first line a `-- `
   description, its DDL exactly design §AR1: the table, the op CHECK, the `slug` length CHECK, the
   `ck_agent_change_slug_names_a_row` constraint (only a `migrate` run may carry a NULL slug), the actor-kind CHECK, the
   `idx_agent_change_slug` index, and the two `RAISE(ABORT, 'agent_change is append-only (S73 AR1)')` triggers. No
   foreign key to `agent` — the ledger outlives the row, and a `delete` row must be statable about a slug that is gone.
   A test plants a `migrate` row with a NULL slug and a `create` row with a NULL slug and shows SQL refuses the second.
2. Re-mint the four goldens the new file moves, each with a comment naming S73: `frozenFileCount` 56→57 with the name
   appended to the running list, `frozenMigrationCount` 101→102 (`internal/store/backup_run_test.go:505,509`),
   `bkDatabaseLine`'s `101 applied`→`102 applied` (`cmd/aeon/bk_golden_test.go:130`) and the doctor/backup golden
   bodies that embed that line. Run the backup family and record which goldens actually moved.
3. New file `internal/store/agent_change.go`: the `AgentChange` row struct (JSON tags camelCase, matching `Agent`'s
   discipline), `AgentActor{Kind, ID}` with `Valid()` (blank kind, blank id, id `"0"`, kind outside `user|cli|system`
   — refused in Go before SQL), `AgentChangeInsertTx(ctx, tx, c)` (no update, no delete accessor — the trigger is the
   enforcement), and the summary formatters (§AR4's summaries) so nine paths cannot invent nine sentences.
4. Convert the writers in `internal/store/agent.go`:
   - `CreateAgent`, `UpdateAgent`, `DeleteAgentBySlug` become unexported tx primitives `createAgentTx`,
     `updateAgentTx`, `deleteAgentTx` (each takes `ctx, tx`; the `INSERT`/`UPDATE`/`DELETE` text moves there and
     nowhere else).
   - The exported doors become audited: `CreateAgentAudited`, `DuplicateAgentAudited`, `UpdateAgentAudited`,
     `DeleteAgentAudited`, `ImportAgentCardAudited`, `MigrateFirstPartyAgentsAudited`. Each takes a `context.Context`
     and a `store.AgentActor`, opens one `s.w.Begin()`, calls `actor.Valid()` **before** the first statement, does its
     row write and `AgentChangeInsertTx` in that tx, and commits. `DuplicateAgentAudited` mints `duplicate`;
     `ImportAgentCardAudited` keeps the (slug, version) idempotency law (AM3) intact — created, updated and no-op
     still refuse-lower-version exactly as today — and mints `import` for the two writes and **nothing** for the no-op
     (a no-op is not a change). `MigrateFirstPartyAgentsAudited` mints **one** `migrate` row for the whole run.
   - `agent_seed.go`'s `SeedAgentInsert` / `SeedAgentUpdate` gain an `AgentChangeInsertTx` call on their caller's tx
     with the `seed` op (the `mcpseed/applier.go:295-301` shape). Their signature gains the change row's fields or an
     `AgentChange`; the applier passes `system:seed-engine` — T4 wires the value.
5. Every caller in `internal/agentmgr` moves to the audited door, each method gaining an `actor store.AgentActor`
   parameter (`Create`, `Duplicate`, `Edit`, `Delete`, `Import`, `Migrate`; `List` and `View` do not). Where a refusal
   is the answer (AM1's internal guard, AM2's collision, AM3's lower version, AM4's references) it still returns
   before any tx opens, with its sentence unchanged — this task moves the plumbing, it does not restate a law.
6. `internal/agentmgr/agentmgr.go`'s header gains the S73 paragraph: the manager is where the actor is threaded, and
   it is not where the actor is invented.
7. Tests:
   - `internal/store/agent_change_test.go`: the ledger is append-only both ways (an `UPDATE` and a `DELETE` each die
     with the trigger's sentence, named); one row per write, in the same tx as the write; a rolled-back write mints no
     ledger row; `AgentActor.Valid()` refuses each of its four cases by name; the `import` no-op mints nothing.
   - `internal/store/agent_audited_test.go`: `TestAgentAuditAndWriteAreOneTransaction` (copy
     `TestBugAuditAndWriteAreOneTransaction`), `TestDeleteMintsALedgerRowNamingAGoneSlug`,
     `TestMigrateMintsOneRowForTheWholeRun`, and each actor stamp (`user:1000`, `cli:cli`, `system:seed-engine`)
     landing byte-what-the-caller-said.
   - `internal/store/agent_audited_guard_test.go`: `TestAgentRowsAreWrittenOnlyThroughTheAuditedPath` walks the
     package's non-test `.go` files and asserts `INSERT INTO agent`, `UPDATE agent SET` and `DELETE FROM agent` appear
     only in the audited owner files; `TestAgentChangeIsAppendOnlyByTrigger`; and `TestAgentAuditGuardHasTeeth`, which
     plants a rogue writer into a temp copy of a file in a scratch dir (or injects a fixture string) and proves the
     walker names it — a guard with no canary is a rumour.
   - `internal/agentmgr`'s existing tests updated for the new parameter, their assertions unchanged (an AM test that
     starts passing differently is a bug in this task, not a test to edit).
