# T6 · The page: header, table, paging, sorting, search

**Rules:** CU1, CU2, CU3, CU7, CU8. **Depends on:** T2 (the page is typed against `RpcMethods["agent.rows"]`).

## Goal

`/config/agents` becomes a management page: a primary action in the header, a table whose pages, order and filter the
daemon decides, and the honest states in between.

   `useAppSettings`), with explicit props still winning. Read `SurfaceVariant`'s value set for the right word instead
   of assuming `"glass"` is one. The file re-exports the kit already, so this is the house default and not a fork of
   the component.
2. New `src/features/agents/agentsModel.ts`: the page's own vocabulary — the seven sort names as a `const`, the page

   computes a page count, an order, or a match — those are the daemon's answers (PG2's UI half).
3. New `src/features/agents/AgentsScreen.tsx`:

### The three plan questions, answered by measurement

**Q2 — does `Table`'s `pagination` render a page-size selector and a total,
un-clipped?** Yes, both, read from `node_modules/@cjlapao/ui-kit/dist/index.js`
(the footer block at offset ~58199) and then confirmed in a real browser at
1280 × 900 against the real daemon. The footer is: a `Showing {from} to {to} of
{total} results` span, a page-size `<select>`, a Previous button (disabled on
page 1 **or while `loading`**), a `Page {page} of {pages}` span, and a Next
button (disabled on the last page **or while `loading`**). Measured on this
page: `Showing 1 to 20 of 34 results`, `Page 1 of 2`, select at
`x=605 w=82 h=24` with options `20 / 50 / 100 per page`, footer box
`x=381 w=988 h=38` inside a 1,070 px content column — nothing clipped. Two
things the footer does that the plan did not say: it renders **only when
`total > 0`** (an empty store has no footer to clip), and its page-size selector
is seeded `new Set([20, 50, 100, pageSize])` — which is why
`AGENT_PAGE_SIZES` is exactly those three. A fourth option (a 10) could only
ever appear by already being the current size, so offering one is a phantom
choice the control cannot show.

**Q3 — which column set fits 1280 px without horizontal scroll?** The widths
shipped are the SECOND try. The first used `minWidth: 16rem` on the name column;
the walk harness (`aeon/scripts/qa-s72-walk/bridge.mjs` serving the built
`ui/dist`, the Tauri stand-in injected, the real daemon's socket on the other
side, the seeded store's 34 agents) measured that page in Chrome at 1280 × 900
and found the name column **2,885 px** wide, the table 3,653 px inside a 1,466 px
container, and the shell's own content column pushed to **1,500 px** at a
1,280 px viewport. The mechanism: an auto-layout table cell takes its content's
min-content width, and a `truncate` line's min-content is the WHOLE line —
`minWidth` never caps that, only a definite `width` does. With definite widths
the same walk measures: name 320 · slug 200 · version 88 · first-party 110 ·
signed 100 · updated 170 · actions 48 = **1,036 px of table in a 1,070 px
column**, `document.scrollWidth` 1,280 (no page overflow), and the table's own
scroller reporting `scrollWidth == clientWidth == 1,036` — no horizontal scroll.
`origin` (120 px) starts `defaultHidden`, and with it on the arithmetic says
1,156 px in a 1,036 px window, so the table scrolls sideways inside its own
container; that one number is arithmetic on the two measured ones, not a third
measurement (`showColumnSelector` renders a toggle, and the walk's click on it
did not produce a checkbox panel this session — T8's walk should exercise it
properly; recorded as a gap, not a claim).

**Q4 — does `SearchBar` debounce, or does the page own it?** The kit's bar
debounces: `SearchBarProps.debounceMs` exists and defaults to 400 ms
(`index.d.ts:3281`, `onSearch(query, signal?)`, `autoSearch` default true). So
the page passes `debounceMs={300}` — CU3's number — and owns **no** timer. The
test asserts one ask per term, not one per keystroke.

### What the walk's first measurement taught the code

Two bugs the browser found that jsdom could not:

1. The 2,885 px column above, fixed by definite widths (in
   `AgentsTable.tsx`'s header, with the numbers).
2. **A page-size change made during the first load used to be silently lost.**
   The first draft copied the daemon's echoed window back into the ask
   (`windowOfAnswer`) so the controls would "tell one story" with the rows. When
   an answer to an EARLIER ask landed after the person had moved the control,
   the copy overwrote the new intent, the params went back to what they were,
   and no request ever went out — measured with a probe: the DOM `change` fired,
   React restored the select to 20, and the ask log had exactly one entry. The
   adoption is gone (`sameWindow` is now only the in-flight signal), and the
   reason is in `agentsModel.ts`'s doc comment: every window this page can build
   is one the daemon answers as asked — the three sizes are inside its clamp, the
   sort names are its own seven, the direction is one of its two words, a term is
   trimmed before it goes, and an over-long one is REFUSED rather than truncated
   (`internal/paging/paging.go:39`, `MaxQuery` is a cap that names itself, not a
   silent cut) — so an echo that disagrees is a clamp this page cannot cause, and
   the controls show the answer either way. `AgentsScreen.test.tsx`'s page-size
   case is the regression witness.

### Where each design word landed in code

- **CU2, no second title**: `pages/agents.ts` keeps `frame: "titled"` (the
  registry default, written out because it is load-bearing) so the FRAME renders
  the group line, the `h1` and the new `summary`; the screen renders an action
  bar and a table and no heading — a test asserts no `h1` and no `h2` in the
  mounted subtree.
- **CU3, the daemon is the brain**: `manualSorting` + a controlled
  `sortState={columnId, direction}` that is never `undefined` (the kit reads
  `undefined` as "keep your own order" and `null` as "cleared"; the daemon always
  answers an order, so this table is always controlled), `pagination` fed from
  the ANSWER's `page/pageSize/total`, and `onSortChange(null)` mapped to the
  daemon's own default order rather than to a client-side "no order".
  `AgentsScreen.test.tsx`'s header case proves the client moved nothing by
  having the fake answer `sort=slug` with a REVERSED slice — a local sort would
  show the opposite list.
- **In flight**: `useRpcQuery`'s `loading` is first-load only, so the page's own
  signal is `busy = loading || (no error && ask ≠ echo)` — built entirely from
  the daemon's echo, and while it holds, the kit covers the rows with its Loader
  (`loadingMessage` = the page's own sentence) and disables the pager.
- **Error keeps the window**: a refusal renders an `Alert` with the daemon's
  message verbatim (via `Alert description`, because `ErrorPanel` takes an
  `RpcError` and `useRpcQuery`'s `error` is a `string` — the same split the
  environments section makes) plus a retry button **outside** the Alert, since
  the kit's Alert body is `description ?? children` and a child beside a
  description is a child nobody sees. `query.data` still holds the last window,
  so nothing blanks.
- **CU6, read-only visibly**: the two sentences are `agentmgr`'s own, quoted in
  `agentsModel.ts` and pinned byte-for-byte against
  `internal/agentmgr/agentmgr.go` by the guard (`toContain` on the Go source,
  plus a negative control that a paraphrase is not in it). A menu item has no
  `tooltip` prop — the kit's `MenuItem.description` is its per-row second line
  and that is where the reason rides; the test reads it out of the open menu.
- **PG2 in the UI, with teeth**: the guard scans every product file for
  `.sort(`/`.filter(`/`.slice(`/`localeCompare(` and `Math.ceil(`, so the page
  cannot re-order, re-slice or count in the browser — and the ban is shown to
  catch a synthetic local sort and a synthetic page count.
- **CU8's census is a closed literal list**, with the ten bench files named in
  an exemption constant, and a `PENDING_T7` list of the nine doors T6 has not
  reached — each asserted UNCALLED, so T7 must delete lines rather than add
  them. `AgentPanel.tsx` is already in the product list and skipped while it
  does not exist, so T7 joins the census without editing the scope.
- **Two cross-language pins** the design implied and no jsdom test could make:
  `AGENT_SORTS` equals the keys parsed out of `AgentRowBounds.Sorts` in
  `internal/store/agent_page.go`, and `AGENT_PAGE_SIZES` sits inside its
  `MaxSize` with `AGENT_DEFAULT_PAGE_SIZE` equal to its `DefaultSize`. A sort
  added on one side and not the other now reddens a test instead of earning
  someone a −32602.
