# T2 · `agent.rows` — the paged read the table asks for

**Rules:** PG1–PG5, AR5, AR7, AR8. **Depends on:** T1.

## Goal

`agent.rows {page,pageSize,sort,dir,q}` answers a window of agent rows and the truth about the whole filtered set. The
roster (`agent.list`) does not change by one byte.

## Steps

1. New file `internal/store/agent_page.go` — the plane's SQL stays in the plane. One read, one count, both on `s.r`,
   both taking the same `WHERE`:
   - `AgentPage(ctx, req paging.Request) (rows []AgentRowSummary, total int, err error)`, where `AgentRowSummary` is
     the nine-column shape in design §"The shape on the wire". No `prompt`, no `skills`, no `metadata`.
   - The `WHERE` is `slug LIKE ? ESCAPE '\' OR name LIKE ? ESCAPE '\' OR description LIKE ? ESCAPE '\'` when `q` is
     set, three bound parameters of the same `paging.Like(q)` value. `q` empty adds nothing.
   - `ORDER BY <resolved column> <dir>, slug asc` — the column comes from `paging.Column` over the seven-name map
     (`"createdAt" → "created_at"`, `"updatedAt" → "updated_at"`, the rest identity). The SQL text is composed from
     map values and fixed words only.
   - `LIMIT ? OFFSET ?` from the normalised request; `total` is the `COUNT(*)` of the same `WHERE`, taken **before**
     the window, in the same call.
2. Register `MethodAgentRows` in `internal/protocol/method.go` beside `MethodAgentList` (~:696), registered in the
   agent block (~:2178-2199) with `RequiresInitialize: true`, not `Debug`, handled by the existing
   `agentManageCall(MethodAgentRows)` — it is a read, so it needs no actor.
3. In `cmd/aeon/agent_management.go`, replace the unreachable `case "agent.list":` (the roster has its own seam at
   `method.go:2178` → `internal/protocol/agent_roster.go:32`, so this case never runs) with `case "agent.rows":`:
   decode the five optional keys (**ignoring** any other field, per T3's forward-compat rule, and refusing only the
   closed set `limit`/`cursor`/`offset`/`order`/`search`/`actor`/`actorKind` by name), `paging.Normalise`,
   `store.AgentPage`, and return the struct whose JSON is exactly the design's answer. A bad page or an unknown sort returns
   `protocol.ErrBadParams{…}` naming the key (→ −32602, the `agent_mailbox.go:551` seam precedent); a store failure is
   a plain `error` (infrastructure); a domain refusal keeps the `refusal string` channel.
4. Fixtures: `internal/protocol/conformance/agent-management/rows.json` (a two-row page with a non-trivial `total`),
   plus `rows-past-end.json` (empty rows, honest total), `rows-bad-sort.json` (the refusal, naming the name) and
   `rows-q-escape.json` (a `q` containing `%`). The refusal fixtures are part of the contract, not decoration.
5. Surface: `surface_table_agents.go` gains `MethodAgentRows` as `SurfaceRead` + `HumanDoorOnly`, and the seven CRUD
   writes gain `HumanDoorOnly` (§AR8). Run the classification guards; if
   `TestHumanDoorOnlyMeansAbsentFromEveryNonHumanDoor` refuses a mark, **stop and record which one** — the mark is a
   claim with a proof and the proof is the arbiter, not this task's preference.
6. `make protogen` then `make check-protogen`. Record what changed in `ui/src/proto/contract.ts`.
7. Add `agent.rows` to whatever pinned method-name list the guards hold (search for the list `agent.list` appears in;
   each widening gets a comment naming S73).

## Definition of done

- `go test -tags sqlite_fts5 ./internal/store/ -run 'Agent'` and `./internal/protocol/ -run 'Agent|Conformance|Surface'`
  pass; `make guard`, `make vet`, `make check-protogen` pass.
- Tests pinned, by name, over a real store: page 1 and page 2 of a five-row set with `pageSize: 2`; `pageSize: 500`
  answers 100; a page past the end answers `[]` and the honest `total`; `q=review` counts only matches in each of the
  three columns; `q=%` finds the planted `100%_sure\thing` and nothing else; every sort name returns the order it
  names, and `createdAt` ties break by slug; `sort=slug;DROP TABLE agent--` is refused naming it and the table is
  still there.
- `agent.list`'s fixtures untouched and its tests green; `git diff --stat` shows no change to
  `internal/protocol/agent_roster.go` or `cmd/aeon/agent.go`'s `agentRoster`.
- Every new/changed file's `wc -l` recorded.

## Do not

- Do not add an index. Sorting a few hundred rows is not a problem, and an index added without a measurement is a
  guess with a write cost.
- Do not filter `internal` rows out of the answer, and do not add `internal`/`origin`/`signed` as query keys — a key
  without a control is a lie about the page (design §"the shape on the wire").
- Do not fold `agent.rows` into `agentRoster()`. The roster is identity for dispatch; this is a management window.
