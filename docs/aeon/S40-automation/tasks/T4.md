# T4 · `StartFromEvent` — S20's start door, extended for events (narrow extraction, unattended, kickoff in the pin transaction)

**Prefix:** AU · **Rules:** AU2, AU5, AU9, AU10 · **Depends on:** T1 (`loop.automation_depth`); T3 (`EventFireReasons` names the refusal reasons); S20 (built: `StartFromTrigger`, `loop.started_by`/`trigger_id`); S19 T6 (`allow_outward`); S39 T8 (kickoff renderer, `chat_message.source`); S38 T6/T7 (goal/task reads, `loop.start` goal/task ids, `requires:` refusal)

## Goal

Add `(d *Daemon) StartFromEvent` **beside** S20's `StartFromTrigger` (same shape, same unattended guard) and extract the closure body into
`startLoopWith` so that provenance (`started_by='event'`, `trigger_id`), `automation_depth` and the rendered kickoff (first chat message,
`source = automation`) are written **in `CreatePinnedLoop`'s one transaction, before the runner starts**. The socket path and S20's path stay
byte-for-byte what they are.

## Why not just call `StartFromTrigger` (measured, so nobody re-derives it)

`daemon/trigger_fire.go`'s `StartFromTrigger(ctx, trigger.Fire)` is the existing fire door: it calls `d.Table.StartBlueprintLoop` with `attended := false`,
then `Store.SetLoopProvenance`. It cannot carry an event fire because (a) `trigger.Fire` has no kickoff/goal/task/depth and S20 pins that it carries no
hints (`TestStarterCarriesNoHint`); (b) it refuses any provenance but `trigger`/`webhook`; (c) it stamps provenance **after** `StartBlueprintLoop`
returned, by which time `d.loopRunner.Start` has run — a first step could execute before its first message exists. So: reuse the door's
**shape and guards**, add a sibling, and leave S20's code **unedited**.
