## Steps

1. **Types and seam** (`protocol/triggers.go`). JSON names are camelCase; every field appears in a fixture so protogen emits it as required:
   ```go
   package protocol

   type EventFireView struct {
       ID          int64  `json:"id"`
       TriggerID   string `json:"triggerId"`
       OutboxID    int64  `json:"outboxId"`
       SubjectKind string `json:"subjectKind"`
       SubjectID   string `json:"subjectId"`
       Depth       int    `json:"depth"`
       Outcome     string `json:"outcome"`   // "started"|"refused"|"limited"|"skipped"|"could-not-say"; "" = claimed, not yet decided
       Reason      string `json:"reason"`
       LoopID      string `json:"loopId"`
       LoopSlug    string `json:"loopSlug"`
       CostNote    string `json:"costNote"`  // ""|"cost-unknown"|"cost-floor"
       ClaimedAt   string `json:"claimedAt"`
       DecidedAt   string `json:"decidedAt"`
   }
   type EventTriggerView struct {
       ID               string          `json:"id"`
       Name             string          `json:"name"`
       Source           string          `json:"source"`
       ProjectID        string          `json:"projectId"`
       ComponentID      string          `json:"componentId"`
       Match            json.RawMessage `json:"match"`            // the canonical match object
       Blueprint        string          `json:"blueprint"`
       Kickoff          string          `json:"kickoff"`
       MaxRunsPerHour   int             `json:"maxRunsPerHour"`
       MaxCostPerDayUSD *float64        `json:"maxCostPerDayUsd"` // null = no cost cap
       Enabled          bool            `json:"enabled"`
       DisabledReason   string          `json:"disabledReason"`
       CreatedByKind    string          `json:"createdByKind"`
       CreatedByID      string          `json:"createdById"`
       CreatedAt        string          `json:"createdAt"`
       UpdatedAt        string          `json:"updatedAt"`
       LastFire         *EventFireView       `json:"lastFire"`         // null when it never fired
   }
   type EventTriggerListParams struct {
       ProjectID   string `json:"projectId,omitempty"`
       ComponentID string `json:"componentId,omitempty"`
       Enabled     *bool  `json:"enabled,omitempty"`
   }
   type EventTriggerListResult struct{ Triggers []EventTriggerView `json:"triggers"` }
   type EventTriggerShowParams struct{ ID string `json:"id"` }
   type EventTriggerFiresParams struct {
       TriggerID string `json:"triggerId,omitempty"`
       Outcome   string `json:"outcome,omitempty"`
       BeforeID  int64  `json:"beforeId,omitempty"`
       Limit     int    `json:"limit,omitempty"`
   }
   type EventTriggerFiresResult struct {
       Fires  []EventFireView     `json:"fires"`
       Counts map[string]int `json:"counts"` // always the five outcome keys; zero is shown as zero
   }
   type EventTriggerReader interface {
       ListEventTriggers(EventTriggerListParams) ([]EventTriggerView, error)
       ShowTrigger(id string) (EventTriggerView, bool, error) // bool = found
       ListEventFires(EventTriggerFiresParams) ([]EventFireView, map[string]int, error)
   }
   ```
2. **Handlers** (copy `handleProjectUpdate`, `projects.go`): `decodeParams`; validate; `if t.TriggerReads == nil { return nil, ErrStoreUnavailable }`.
   - `handleTriggerList`: returns `EventTriggerListResult{Triggers: …}` with a **non-nil empty slice** when none.
   - `handleTriggerShow`: `strings.TrimSpace(p.ID) == ""` → `ErrBadParams{Err: fmt.Errorf("id is required")}`; not found → `ErrBadParams{Err: fmt.Errorf("no trigger %q", id)}`.
   - `handleTriggerFires`: `p.Outcome` non-empty must be one of the five (else `ErrBadParams` naming them); `Limit` ≤ 0 → 50, > 500 → 500.
   - Add to `Table` struct (`method.go`, next to `Projects`): `TriggerReads EventTriggerReader`. Register:
     ```go
     t.register(&Method{Name: MethodAutomationTriggerList,  RequiresInitialize: true, Handle: t.handleTriggerList})
     t.register(&Method{Name: MethodAutomationTriggerShow,  RequiresInitialize: true, Handle: t.handleTriggerShow})
     t.register(&Method{Name: MethodAutomationTriggerFires, RequiresInitialize: true, Handle: t.handleTriggerFires})
     ```
     consts: `MethodAutomationTriggerList MethodName = "automation.trigger.list"`, `"automation.trigger.show"`, `"automation.trigger.fires"`.
3. **Daemon reader** (`daemon/triggers.go`): `type triggerReads struct{ s *store.Store }`; `NewTriggerReads(s *store.Store) protocol.EventTriggerReader`.
   - `ListEventTriggers`: `s.ListEventTriggers(store.EventTriggerFilter{…})`, each → `EventTriggerView` (`Match: json.RawMessage(t.MatchJSON)`), `LastFire` from `s.ListEventFires(store.EventFireFilter{TriggerID: id, Limit: 1})`.
   - `ListEventFires`: `s.ListEventFires(store.EventFireFilter{…})` + `s.EventFireCounts(p.TriggerID)` (empty trigger id = all triggers: add `EventFireCounts("")` meaning "all" — **one-line change in T3's function: `WHERE ? = '' OR trigger_id = ?`**).
   - Store errors are returned as-is (the handler layer wraps nothing; `ErrStoreUnavailable` is for the unwired case only).
   - In `daemon.go` inside the existing `opts.Store != nil` block add `table.TriggerReads = NewTriggerReads(opts.Store)`.
4. **Fixtures** — three files, hand-written (`conformance/automation/`), shape per `conformance/store/project-list.json`. Example `trigger-fires.json`:
   ```json
   {
     "description": "The fire log of one trigger: every outcome is a row with its reason, and the counts always carry all five outcomes (zero included) so the page can show five pills.",
     "method": "automation.trigger.fires",
     "request": {"jsonrpc": "2.0", "id": 201, "method": "automation.trigger.fires", "params": {"triggerId": "tr1", "limit": 50}},
     "response": {"jsonrpc": "2.0", "id": 201, "result": {
       "fires": [{"id": 2, "triggerId": "tr1", "outboxId": 7, "subjectKind": "goal", "subjectId": "g1", "depth": 0,
                  "outcome": "limited", "reason": "max-runs-per-hour: 2 started since 2026-10-27T08:00:00Z, limit 2",
                  "loopId": "", "loopSlug": "", "costNote": "cost-unknown",
                  "claimedAt": "2026-10-27T08:30:00Z", "decidedAt": "2026-10-27T08:30:00Z"},
                 {"id": 1, "triggerId": "tr1", "outboxId": 4, "subjectKind": "goal", "subjectId": "g0", "depth": 0,
                  "outcome": "started", "reason": "", "loopId": "l1", "loopSlug": "auto-tr1-4", "costNote": "",
                  "claimedAt": "2026-10-27T08:10:00Z", "decidedAt": "2026-10-27T08:10:01Z"}],
       "counts": {"started": 1, "refused": 0, "limited": 1, "skipped": 0, "could-not-say": 0}}}
   }
   ```
   `trigger-list.json` has one trigger **with** `lastFire` populated and one with `"lastFire": null`, `"maxCostPerDayUsd": null` and `"enabled": false` with a `disabledReason`; `trigger-show.json` shows one full `EventTriggerView` (the `match` object canonical: `{"event":"goal.approved","goal_type":["feature"]}`).
5. **Conformance cases** (`conformance_test.go`, in `paramsTypeFor` ~`:452` and `resultTypeFor` ~`:504`): `case MethodAutomationTriggerList: return &EventTriggerListParams{}` / `&EventTriggerListResult{}`; same for show (`EventTriggerShowParams` / `&EventTriggerView{}`) and fires.
6. **Regenerate and check:** `make protogen` then `make check-protogen`. Commit the regenerated `ui/src/proto/contract.ts`; read the diff — only the three methods' types and constants may appear.
7. **Tests** (below), then the suites.

## Notes

**Shipped 2026-10-28.** The three reads, the seam, the fixtures, the regenerated contract —
plus four things the task file could not have known:

- **`PROTOCOL_VERSION` is 2, not 1.** The plan's round-trip test as written asserts `== 1`
  and would have failed on arrival; the repo's own two pins (`ask_test.go`,
  `s38_invariants_test.go`) say 2 is the S39-era value with the dated history, so the new
  test asserts 2 and the sentence says why. Additive stayed additive: no bump, no fixture
  edited, `PROTOCOL_VERSION` untouched.
- **S20 already owns the handler names.** `protocol/trigger.go` (the S20 schedule surface)
  has `handleTriggerList` — so `automation.trigger.*` handlers are `handleAutomationTrigger*`,
  and the plan's assumed names were a build-time collision, caught by the compiler not review.
  The `internal/narrow` HTTP surface is its own enumerated actions table; socket methods do
  **not** auto-project, so nothing there needed touching (verified, not assumed — its
  coverage tests pass unchanged).
- **protogen is fixture-driven, and fixtures can lie.** The first contract generation typed
  the list params as `Record<string, never>` (my fixture's params were `{}`) and the show
  result as `maxCostPerDayUsd: number` — non-nullable — because the one show fixture happened
  to carry a number. Both are contracts the TS page would trust and the real daemon would
  break. Fix: the list fixture now carries all three filters, and two more fixtures joined the
  set — `trigger-show-paused.json` (null `lastFire` = never fired, null cap = no cap) and
  `trigger-fires-limited.json` (the `outcome` filter answering with only its rows) — so the
  contract now says `null | number`, `null | {…}`, and `beforeId?`/`outcome?` genuinely
  optional. `match` is `json.RawMessage` in Go (views carry the canonical object verbatim,
  precedent: `memory.go`'s `Messages`); protogen inferred it across the two fixture matches
  as `{event: string, goal_type?: string[], task_type?: string[]}` — which is the match
  grammar's own shape (one required key). Five fixtures for three methods is not bloat: each
  carries a state the others cannot show at once.
- **The conformance harness decodes, it does not dispatch.** Fixtures round-trip through
  `paramsTypeFor`/`resultTypeFor`; handler *behaviour* (the []-never-null rule, the five-name
  refusal message, the 50/500 clamp, the unwired `ErrStoreUnavailable`) lives in
  `triggers_test.go` where the handlers are actually called. Five handler tests plus the
  version/registration test, two daemon reader tests over a real store.
