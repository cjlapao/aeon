# T9 · The bench page — triggers, enable/disable, the fire log

**Prefix:** AU · **Rules:** AU12, AU14, AU15 · **Depends on:** T7 (reads), T8 (writes); S34/S35 precedent (a bench page, no designed experience)

## Goal

A minimal **bench page** "Automation" (`/bench/automation`): the trigger table (name, event, blueprint, scope, enabled, last outcome), an
enable/disable control (disable asks for a reason), a **fire log with the five outcomes as distinct pills — zero shown as zero —** and
their reasons verbatim, and a plain JSON textarea that calls `automation.trigger.create` and shows the daemon's refusal sentence untouched. It
has no approval, delete or run-now button, and it renders an honest *unwired* note on a daemon without trigger support.

## Steps

1. **Types** (append to `lib/protocol.ts`, each with a comment `/** \`automation.trigger.list\` — conformance/automation/trigger-list.json */`). They mirror T7/T8 exactly:
   ```ts
   export const METHOD_AUTOMATION_TRIGGER_LIST = "automation.trigger.list";
   export const METHOD_AUTOMATION_TRIGGER_SHOW = "automation.trigger.show";
   export const METHOD_AUTOMATION_TRIGGER_FIRES = "automation.trigger.fires";
   export const METHOD_AUTOMATION_TRIGGER_CREATE = "automation.trigger.create";
   export const METHOD_AUTOMATION_TRIGGER_ENABLE = "automation.trigger.enable";
   export const METHOD_AUTOMATION_TRIGGER_DISABLE = "automation.trigger.disable";
   export type FireOutcome = "started" | "refused" | "limited" | "skipped" | "could-not-say";
   export const FIRE_OUTCOMES: readonly FireOutcome[] = ["started", "refused", "limited", "skipped", "could-not-say"];
   export interface EventFireView { id: number; triggerId: string; outboxId: number; subjectKind: string; subjectId: string; depth: number;
     outcome: FireOutcome | ""; reason: string; loopId: string; loopSlug: string; costNote: "" | "cost-unknown" | "cost-floor"; claimedAt: string; decidedAt: string; }
   export interface EventTriggerView { id: string; name: string; source: string; projectId: string; componentId: string; match: { event: string; [k: string]: unknown };
     blueprint: string; kickoff: string; maxRunsPerHour: number; maxCostPerDayUsd: number | null; enabled: boolean; disabledReason: string;
     createdByKind: string; createdById: string; createdAt: string; updatedAt: string; lastFire: EventFireView | null; }
   export interface EventTriggerListResult { triggers: EventTriggerView[] }
   export interface EventTriggerFiresResult { fires: EventFireView[]; counts: Record<FireOutcome, number> }
   ```
2. **The page** (`AutomationPage.tsx`). Structure (use the kit and the tone mapping PolicyPage uses; no new CSS):
   ```tsx
   export function AutomationPage() {
     const [triggers, setTriggers] = useState<EventTriggerView[] | null>(null);
     const [fires, setFires] = useState<EventTriggerFiresResult | null>(null);
     const [selected, setSelected] = useState<string>("");          // "" = all triggers
     const [error, setError] = useState<RpcError | null>(null);
     const [unwired, setUnwired] = useState(false);                  // daemon answered "unknown method"
     const [draft, setDraft] = useState("");                         // the JSON textarea
     const [createError, setCreateError] = useState<string>("");
     const [disabling, setDisabling] = useState<{ id: string; reason: string } | null>(null);
     const load = useCallback(async () => { /* rpc automation.trigger.list, then rpc automation.trigger.fires {triggerId: selected, limit: 50}; unknown method (-32601) => setUnwired(true) */ }, [selected]);
     useEffect(() => { void load(); }, [load]);
     // render: Panel "Triggers" (table + Enable / Disable buttons), Panel "Fire log" (five Pills with counts, then rows),
     //         Panel "New trigger (JSON)" (textarea + "Create" button; on RpcError show err.message VERBATIM in an Alert).
   }
   ```
   Rules that are the point of the page (each has a test):
   - **Five pills, always:** render `FIRE_OUTCOMES.map(o => <Pill>{o} {counts[o] ?? 0}</Pill>)` — a missing key renders `0`, never hides the pill. Each outcome has its own tone; `could-not-say` is visually distinct from `skipped` (P31) and the page prints its one-line gloss *"we cannot prove whether this started"*.
   - **Reasons verbatim:** `{fire.reason}` in a monospace cell, unmodified. `costNote` shows as a small pill (`cost-unknown`, `cost-floor`).
   - An undecided fire (`outcome === ""`) renders a pill labelled `claimed` (not one of the five; it is the transient state).
   - Disable requires a non-empty reason (button disabled until typed); Enable is one click. Both then call `load()`.
   - A disabled trigger row shows its `disabledReason`.
   - **No buttons** named delete, approve, run, fire or retry; no keyboard shortcut for any write.
   - `unwired` renders *"This daemon does not know the trigger methods (it predates S40)."* — never an empty table pretending there are none.
   - The textarea posts `JSON.parse(draft)` as the params of `automation.trigger.create`; a JSON syntax error is shown locally as *"not valid JSON: …"* and **nothing is sent**.
3. **Register the page** (`routes.ts` row; `TestBench.tsx` import and branch). Check the menu shows "Automation" under the bench section.
4. **Tests** (`ui/test/automation.test.tsx`; copy the imports and `beforeEach/afterEach` of `ui/test/policy.test.tsx`; use `installFakeDaemon({ responses: {...} })`; a daemon error is thrown as `JSON.stringify({code, message, data})` like `refusal()` in that file). Payloads are **T7/T8's fixtures** copied verbatim, in `const` blocks with a comment naming the fixture file.
5. Run `make -C aeon/ui test` and `make -C aeon/ui typecheck`.

## Tests

| Name | Asserts | How it can fail |
| --- | --- | --- |
| `shows all five outcomes as distinct pills, zero included` | with counts `{started:1,limited:1,refused:0,skipped:0,"could-not-say":0}` the DOM has five pills each with its count; `could-not-say` and `skipped` have different tone classes/labels | a zero pill hidden |
| `renders each reason verbatim and the cost note` | the `max-runs-per-hour: 2 started since …` string appears byte-identical; `cost-unknown` pill present | reason reformatted |
| `a claimed fire is labelled claimed, not given an outcome` | `outcome:""` row → pill text `claimed` | undecided mapped to a real outcome |
| `lists triggers with event, blueprint and last outcome; a disabled one shows its reason` | `match.event`, `blueprint`, `lastFire.outcome`, `disabledReason` all visible | missing column |
| `disable needs a reason and sends exactly it` | Disable button disabled until a reason is typed; click → `paramsOf("automation.trigger.disable")` equals `{id, reason}`; then `automation.trigger.list` is called again | empty reason sent |
| `enable sends only the id` | `paramsOf("automation.trigger.enable")` equals `{id}` | extra params |
| `the create box sends nothing on invalid JSON` | invalid text → local message; `methods()` contains no `automation.trigger.create` | request sent |
| `the create box shows the daemon's refusal verbatim` | fake `automation.trigger.create` throws `-32602` with the grammar sentence → the sentence appears unchanged | message rewritten |
| `renders an honest unwired note on a daemon without the methods` | fake throws `-32601` for `automation.trigger.list` → the *predates S40* note, no empty table | silent empty state |
| `the page has no delete, approve, run, fire or retry control` | `queryByRole('button', {name: /delete\|approve\|run\|fire\|retry/i})` is null | forbidden affordance |
| `the page only ever calls the six trigger methods` | after interactions, `methods()` ⊆ `{automation.trigger.list, automation.trigger.fires, automation.trigger.show, automation.trigger.create, automation.trigger.enable, automation.trigger.disable}` | stray RPC |
