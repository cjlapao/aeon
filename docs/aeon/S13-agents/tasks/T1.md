# T1 — The handler file format and loader

## Notes (2026-10-25, measured on this box)

**Q1 — is the front matter uniform across all 26 `*-loop` files?** Yes, measured exhaustively rather than from the
task's "all 75" claim: all 26 declare `name`, `description`, `mode` (**subagent ×26**), `variant`
(**coder-fast ×21, coder-thinking ×5**), `temperature` (0.2 ×3, 0.3 ×7, 0.4 ×15, 0.5 ×1) and `tools`.
**25 of 26 declare `permission` — `project-planner-loop` declares none** (it is consequently absent from
`corpus.json`; its loaded `CommandRules` is nil, not an empty slice — the two claims differ). No variants to
enumerate; the loader nonetheless records what each file declares.

**Q2 — does `variant` affect behaviour?** **No — it is inert selection metadata, nothing in the corpus reads it.**
Grepped: zero occurrences of `coder-fast`/`coder-thinking` in any body prose, in `dev-loops.md`, or in the
`dev-loop-protocol` skill — the string appears only in front matter (51 files repo-wide). Nothing to raise, but the
loader keeps the field and `TestVariantIsRecorded` greps production sources for any future branch on it: an
inert field stays inert by assertion, not by drift.

**Q4 — does the extractor expose policy consumably?** **Yes, no new accessor needed**: `policy.ParseCorpus(raw)`
returns a `Corpus` with `RulesFor(agent) ([]CorpusRule, bool)` — pattern, verdict, authored order preserved. The
loader calls exactly that over `policy.EmbeddedCorpus()` and never opens `permission.bash`; `TestPolicyIsByteIdenticalToTheExtractor`
proves independence mechanically by **mangling each original's deny→allow on a copy and reloading — rules unmoved**
(a self-proof of "byte-identical" no comparison of two same-source values can give). 25 originals have corpus
entries checked rule-by-rule in order; 1 (project-planner-loop) is provably absent and checked as nil.

**Deviations and decisions the task file could not know:**

- The loaded type is **`Definition`, not `Handler`** — S8's `handler.Handler` (registry.go) is the runtime entry
  `Build` consumes, and two same-named types in one package is how one shadows the other. Direction is one-way:
  file → `Definition` → registry entry → `runtime.StepHandler`.
- Rewrites get a **`policy-agent:` front-matter key**: the corpus is keyed by the `*-loop` names and `opencode/` is
  read-only (A10), so a rewrite named `docker-engineer` declares which corpus agent's rules it ships
  (`docker-engineer-loop`). Absent the key, the name is its own agent. `TestPolicyAgentKeyLinksTheRewriteToItsCorpusAgent`
  asserts docker's two mid-pattern wildcard rules survive byte-intact.
- **Measured YAML reality:** two originals — `git-loop.md` and `qa-engineer-loop.md` — fail strict YAML (unquoted
  description scalars containing `": "`), the same class corpusgen documented. The loader parses strictly, then
  falls back to per-key extraction **for scalars only**; structured blocks (`tools`, `handoff`) keep the strict path.
  `TestStrictFailuresAreTheTwoMeasuredFiles` pins the fallback's customer list to exactly those two: a third file
  failing strict parse is a YAML fix, not a wider fallback.
- The design table says `patch` was declared in **13** of 26; measured it is **`patch: true` in 26/26**
  (`grep -l '^\s*patch: true'` = 26, `patch: false` = 0). The conclusion is unchanged — patch is retired either
  way — but the record measures rather than repeats.
- **`RetiredFound` and `DeclaredFalse` are separate record fields.** A v1 `task: false` entry was a *denial of a
  name that exists*; `patch: true` was a *desire for a name that no longer exists*. The golang original hits both,
  and a test failed loudly the first time these categories were mixed.
- `Reject` gained `IO bool` (DB19): `Load`/`LoadOriginal` distinguish *disk* from *domain* inside one discriminated
  result — a format error is never retried as if it were a disk hiccup, and both name the file.
- The registry set is `tools.ToolNames()` behind a seam (`toolsOf`, `loadWithTools` for the O1 test): 10 honest
  names, the hidden `write_file` alias filtered — **read, never hardcoded**, so S22's `search` will flow.
- `Compile` lives as specified; the slice passes nil everywhere and `TestThisSliceAlwaysPassesNoSections` greps
  production call sites to keep that true (word-boundary regex: `MustCompile(` is not `Compile(` — a first
  version of the grep proved nothing by matching the regexp constructor).

**Measured:** `internal/handler` **28** top-level `--- PASS` (`go test -v | grep -c`, 2026-10-25) — S8's 7 registry

## Why this exists

Nothing can be verified, let alone rewritten, without a format to write into.

## Scope

### The format

A markdown file: YAML front matter plus a body. The front matter mirrors the originals' shape, which is **uniform and
machine-readable** — all 75 agent files declare `name`, `description`, `mode`, `temperature` and `tools`.

```yaml
---
name: golang-engineer
description: …
temperature: 0.1
tools: [read, write, edit, bash, glob, grep, todo, question]
handoff:
  summary:     the paragraph a reader of this step's output needs
  tests_added: paths of tests written, or "none"
---
```

**Answer Q1 first**: is the front matter uniform across all 26 `*-loop` files, including `variant`? **If not, enumerate
the variants** — a file the loader mishandles is a handler that silently behaves differently from the one whose
behaviour was reviewed.

**And answer Q2**: 51 files declare `variant` and **no decision mentions it**. Does it affect behaviour, or only
selection? **If it affects behaviour, that is a finding to raise** before 25 rewrites are made on the assumption that it
does not.

`mode` does not port: A1 removed the distinction, since nothing spawns and there are no subagents.

### The prompt has a seam for retrieved content (Stage 5)

**One cheap decision now**, and it is the one that protects the thing this whole project exists for.

Stage 5 records **learnings** as an agent works. If those get **concatenated into the body**, then after six months an
agent's prompt is half unreviewed generated text — **exactly the context injection this project exists to remove**, arriving
by a route nobody was watching.

So the compiled prompt is **not one string**:

```go
type Handler struct {
    Body string   // the reviewed markdown. NEVER appended to.
    // …
}

// Compile assembles a prompt from the reviewed body plus zero or more
// retrieved, attributed sections. Stage 5 fills the second argument;
// this slice always passes none.
func Compile(h Handler, retrieved []Section) StepRequest
```

Two properties that make it work:

- **`Body` is never mutated or appended to.** It stays the reviewable artefact — S13 rewrote 25 of them with drop records
  precisely so each is diffable against its original, and an agent whose prompt has grown is one nobody reviewed.
- **A retrieved section is attributed in the transcript**, so *"why did this agent behave differently"* has an answer.

**This slice always passes an empty slice.** The seam costs a parameter now; without it, Stage 5's only options are to
concatenate or to change every call site.

### `tools` is translated, not ported (A19, D4a)

**The superseded design's "the frontmatter ports mechanically" is half wrong.** Measured across the 26 originals, the
`tools` map names five tools Aeon does not have:

| Declared | Count | Fate |
| --- | --- | --- |
| `task` | **26 of 26** | **Dropped.** A1: nothing spawns. **Not renamed** — a rename would reintroduce delegation through a config file, which is exactly what A1 removed |
| `todowrite` | **26 of 26** | Renamed to `todo` |
| `codesearch` | 25 | Retired (W1) |
| `lsp` | 24 | Retired (W1) |
| `patch` | 13 | Retired (W1) |

The loader carries the translation table. A retired tool in a **rewritten** handler is an error; in an **original** it
is expected, since T1's format test runs against the originals.

### `description` is model-facing prose (A20, D4b)

It is subject to the same checks as the body, because the model reads it. Measured: **25 of 26** originals describe a
caller guard that declines work from anyone but `dev-loops`, 22 name a `FINAL REPORT`, 17 say "NEVER runs git".

A rewrite that carefully strips the body and ports the description verbatim ships a handler instructing the model to
decline work from an orchestrator that no longer exists.

### `tools` is an allow-list (A6, D4)

Not a map. The runtime grants exactly what is named, so a `false` entry denies something never granted — v1's 34
`filesystem_*: false` entries are dead config. S11's T12 already made accepting one a configuration error; the loader
must produce that error rather than tolerating the shape.

`tools` must be a subset of the registry's set. **Read the set from the registry** (O1, I2), never a hardcoded nine —
a hardcoded list is a second source of truth about the toolset and it goes stale the moment S22 adds `search`.

### Policy comes from S11's extractor (A16, D5)

The loader does **not** parse `permission.bash` itself. It reads S11's corpus output.

Two parsers over the same front matter is how the policy the guard enforces and the policy the registry reports come to
disagree — and the disagreement would be invisible until a command someone believed was denied ran.

**Answer Q4**: does the extractor expose policy in a consumable form, or does it need an accessor? A16 forbids a second
**parser**, not a second accessor.

### Not in scope

No verification of body content — that is T2. No handoff **validation** — T3. This task loads and reports what it
found.

## Tests

| Test | Asserts |
| --- | --- |
| `TestFrontMatterParsesForAllOriginals` | Every one of the 26 `*-loop` originals' front matter parses. **The originals**, because they are the shape the format must accommodate — a format that only accepts the rewrites is a format designed after the fact |
| `TestPolicyIsByteIdenticalToTheExtractor` | For each agent with a policy, the loaded rules are **byte-identical** to S11's corpus entry — not "equivalent", which would pass a reordering (D5, C3) |

| `TestModeIsNotPorted` | A `mode:` key is ignored, and its absence is not an error. A1 removed the distinction |
| `TestVariantIsRecorded` | Whatever Q2 found: if it is inert, it loads and is unused; if it affects behaviour, this test asserts that behaviour |
| `TestToolsTranslation` | `task` is **absent** from a loaded handler (not present-and-false); `todowrite` becomes `todo`; `codesearch`, `lsp` and `patch` are errors in a rewritten handler (A19) |
| `TestTaskIsDroppedNotRenamed` | No loaded handler has any tool that could start another step — asserted against the registry, so a future spawn-like tool cannot slip in |
| `TestBodyIsNeverAppendedTo` | `Compile` with retrieved sections leaves `Body` byte-identical — asserted, so Stage 5 cannot take the concatenation route |
| `TestCompileTakesRetrievedSections` | The parameter exists and an empty slice is the normal case in this slice |
| `TestRetrievedSectionsAreAttributed` | With a fixture section: it appears in the transcript naming its source |
| `TestLoadErrorsAreDomainErrors` | A malformed front matter is a domain refusal naming the file, distinguishable from a disk error (S4's DB19) |

`TestFrontMatterParsesForAllOriginals` running against the **originals** is the point. It is the only available check
that the format was derived from the corpus rather than fitted to the first rewrite.
