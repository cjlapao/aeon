## Why this exists

Five handlers that produce **documents rather than code**, and whose originals carry the file schemas A5 identified as
the skills' real content.

One of them has a problem the others do not.

## Scope

Five rewrites, T4's pattern, plus the following.

### The file schemas survive (A5)

`project-planner-loop` (183 lines), `intent-clarifier-loop` and `investigator-loop` between them own the shapes of
`plan.md`, `prompt.md` and `discovery.md` — fixed section orders, required sections, what each is for.

A5 is explicit that these belong to **the one handler that writes that file**. So each schema goes into exactly one
body, and a schema appearing in two bodies is a finding: two sources of truth about a document's shape.

S8's `produces:` enforces that the file **exists**; the schema is what makes it the right file. Neither replaces the
other.

### `memory-steward` and the tool that no longer exists

**This handler's entire job was `memory_append`.** All 26 originals reference that tool and this is the one whose domain
*is* it.

There is no `memory_append` in Aeon's nine. So the rewrite has to answer what `memory-steward` is **for** now:

- Its **judgement** — what constitutes a durable lesson rather than an incident detail, how to phrase one so it is
  useful later, when not to record something — is real domain and survives.
- Its **mechanism** — appending to a memory store — is gone. S4 has a `memory` table and S22 will index it; **neither is
  a tool a handler calls** in this slice.

So `memory-steward` becomes a handler that **writes** a lesson through `write`, into a path the blueprint declares with
`produces:`. That is a genuine change of shape, and the drop record must say so plainly rather than pretending the
handler is unchanged.

**If that shape turns out not to work, it is a finding to raise** — not a reason to add a tool (N6, N9).

### `technical-writer` and the audience question

Its domain is knowing who a document is for. That is judgement and it survives. What goes is any instruction about
*where* to put the file — the blueprint's `produces:` decides that now.

### The trap in this batch

These five produce prose, which makes their bodies **easy to pad**. A rewrite that expands guidance because "the model
needs more direction for writing than for coding" has invented content (A17).

The drop records here should show a **negative** delta with **zero added lines**, like every other batch.
