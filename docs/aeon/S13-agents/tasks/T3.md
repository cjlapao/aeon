# T3 — The handoff schema

## Notes (2026-10-25, measured on this box)

**The model's claim is an input, never the verdict.** `HandoffSchema.Check(claimed)` takes the handoff the step
claimed and returns the verdict: a claimed `ok` that withheld a declared field comes back `reject` with the reason
naming the field (D12) — the test asserts the *claimed value stays untouched* while the verdict moved, so "S8's
routing then takes over" acts on a real reject, not on a model's self-report. A claimed `blocked`/`failed`/`reject`
**passes through untouched**: a handler that said blocked is not additionally punished for fields a finished run
would have carried; its reason is the report.

**Deviations and decisions the task file could not know:**

- Front matter marks optionality with a `?` key suffix (`tests_added?: paths written or none`) — the spec's
  `FieldSpec{Required bool}` needs a front-matter syntax and YAML has none; `foo` and `foo?` in one file is refused
  as two contracts for one field.
- **Present-but-empty is not produced.** `summary: "   "` rejects like absence — the next step received nothing
  either way, and treating whitespace as content is how a handoff "passes" while starving its consumer.
- **Extra fields are ignored AND KEPT**, not dropped: "ignored, not an error" means the next step may want what the
  model volunteered. The asymmetry test asserts both directions (outcome unharmed, content retained).
- Type identity is asserted with `reflect.TypeOf(back.Outcome) == reflect.TypeOf(runtime.OutcomeOK)` — assignability
  would pass a local string-typed clone with the same four values, and the clone **is** the second set L4 forbids.
  `TestNoSecondOutcomeSet` greps non-test sources for any competing `type Outcome`/`Outcome = "` declaration and
  carries its positive control inline (the four S8 constants must be non-empty or the grep proves nothing).
- N4 is a **live refusal**, not an absence: `BuildSchema` refuses `pr_summary` naming S16 as its owner, so the field
  lands with its reader rather than quietly arriving in a rewrite's front matter.
- Check is deterministic on a single missing field; with several missing it names one (a redo edge has something to
  act on; re-checks name the next). Documented in code.

## Why this exists

A5 observed that the retired skills' real content is **mostly file schemas** — `prompt.md`'s fixed section order,
`discovery.md`'s sections, `plan.md`'s shape — and that each belongs either to the one handler that writes that file or
becomes a `produces` declaration plus a handoff schema.

S8's `produces:` already enforces that the artifact **exists**. The handoff carries what the **next step needs**, which
is a different question.

It comes before the rewrites because each body declares its fields, and a schema invented after twenty-five bodies is a
schema that fits none of them.

## Scope

```go
type Handoff struct {
    Outcome runtime.Outcome   // ok | reject | blocked | failed (L4)
    Reason  string
    Fields  map[string]string
}

// A handler declares its fields and what each is for.
type HandoffSchema map[string]FieldSpec

type FieldSpec struct {
    Purpose  string  // required (O6)
    Required bool
}
```

### The four outcomes are S8's, not a new set

`ok`, `reject`, `blocked`, `failed` — L4's universal outcomes, with the routing S8 already implements. **Do not define a
second set.** S8's T9 asked the same question about `StepResult.Outcome` and the answer was the same: reuse it.

### A declared field not produced is a `reject` (D12)

Not a silent gap, and not an `ok` with a missing key.

A handler that declares a summary and returns none has not finished its job, and the next step is entitled to what it
was promised. S8's routing then takes over — the lane's `rework` target, bounded by `on_reject` — which is exactly what
that machinery is for.

The reject's reason **names the missing field**, so a redo edge has something to act on.

### Every field states its purpose (O6)

S16 and S17 consume these. A field named `notes` with no contract is a field nobody can rely on and everybody
populates differently.

`Purpose` is required at load time, so a handler cannot declare a field without saying what it is for.

### `pr_summary` is not here (N4)

L3 says every step handoff gains `pr_summary`, *"the paragraph a human will read on the PR"*. **S16** adds it, because
S16 is what reads it. The mechanism is this task; the field is not.

## Tests

| Test | Asserts |
| --- | --- |
| `TestDeclaredFieldNotProducedIsAReject` | `reject`, with the reason naming the field. **Not** `ok` with a missing key (D12) |
| `TestUndeclaredFieldIsIgnoredNotAnError` | A handler returning extra fields is not punished — the schema is a floor, not a ceiling, and a model adding useful context should not fail a step |
| `TestOptionalFieldMayBeAbsent` | `Required: false` behaves |
| `TestFourOutcomesRoundTrip` | All four survive persistence and re-read, using **S8's** outcome type — asserted by type identity, not by value equality |
| `TestNoSecondOutcomeSet` | A grep asserting no new outcome enumeration exists |
| `TestEveryFieldHasAStatedPurpose` | A schema with a purposeless field fails at load (O6) |
| `TestRejectReasonNamesTheField` | So S17's redo edges can act on it |

`TestUndeclaredFieldIsIgnoredNotAnError` is worth stating deliberately. The symmetrical-looking rule — punish extra
fields as well as missing ones — would make a model volunteering useful information into a step failure.
