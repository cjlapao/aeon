## Why this exists

A3: there are **26** `*-loop` agents and **25** handlers, because `git-loop` becomes **no handler at all**. Its work
becomes S16's code actions — opening a pull request is a mechanical call, not a judgement.

But it is **the largest original in the set at 372 lines**, and dropping the largest one silently loses the most (O8).
So this task produces a drop record for a handler that does not exist.

It comes last among the rewrites because its disposition depends on knowing what the other 25 absorbed.


**The `LOST` section is the one that matters, and it may be empty.** If it is not empty, each entry is a decision
someone should be able to disagree with later — which is only possible if it is written down.

### It must not become a handler (A3, D8)

Asserted: `git-loop` is absent from the registry, absent from `handlers.json`, and there is no
`bodies/git-loop.md`.

The reason is worth keeping visible in the record: **its work is not a handler's work.** L3 settles the split — code
owns every identifier and every API call, prose stays a model concern. Opening a pull request is a mechanical call plus
a writing task, and splitting them removes the identifier-integrity bug class, *including the recorded
branch-inheritance bug*. A handler doing both would reintroduce it.

### Feeding S16

The `BECOMES A CODE ACTION` section is **S16's input**, so it must name the action each range maps to. S16's registry is
closed and typed (L3), and this record is where the list of what it must contain comes from.

A range mapped to an action S16 does not plan to build is a finding to raise **now**, while the original is still in
front of someone.
