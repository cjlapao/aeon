## Why this exists

**The batch most likely to lose something.** It holds the three largest originals — `code-reviewer` at 204 lines,
`qa-test-spec` at 287, `qa-engineer` at 293 — and their length is not ritual padding: much of it is **schemas and
judgement criteria** that are exactly the content A4 warned would be lost because it "reads like incidental detail".

## Scope

Five rewrites, T4's pattern. Plus three things specific to this batch.

### The test-suite schema is domain, not ritual

`qa-engineer-loop` and `qa-test-spec-loop` carry a full schema for `docs/test_suites/` documents — environment setup,
prerequisites, environment variables, test data preparation, the `TC-001` case format, the execution checklist.

**That is domain content and it survives.** A5 is explicit: the skills' real content is mostly file schemas, and *"each
belongs to the one handler that writes that file, or becomes a `produces` declaration plus a handoff schema."*

So: the schema stays in the handler that writes those documents. It is long, and length is not a reason to cut it — this
repository's own QA suites follow that schema, and they are the reason the suites are readable.

### The `.secrets` discipline is domain with a security dimension

`qa-engineer-loop` has a section headed *"Authentication — the `.secrets` file (allowed, with discipline)"*.

**Keep it, and keep the discipline part.** A rewrite that keeps "you may read `.secrets`" and drops the discipline has
made the handler more permissive than the original — the worst possible direction for a rewrite to err, and easy to do
while shortening.

Note also that S11's path enforcement (W18) already governs *where* it can read, and the tool allow-list governs
whether it can read at all. The prose covers what the mechanism cannot: what to do with what it finds, and what never
to put in a transcript.

### Playwright is the clearest `DEFERRED` case (A18)

`qa-engineer-loop`'s *"UI cases — Playwright MCP first, HTTP fallback second"* is the sharpest instance of content
needing a capability Aeon lacks. Record it: the handler wants browser automation, the MCP client was deferred when this was written
(**S19's N17, now reversed** — it lands at S12, before this slice; see `ROADMAP.md` §7), and the HTTP fallback is
what it did meanwhile.

**The fallback is keepable domain**; the Playwright half is `DEFERRED`. Splitting one section across two categories is
exactly the judgement this batch requires.

### `verifier-engineer` and the outcome vocabulary

`verifier` returning invalid, `security` failing and `review` requesting changes are **the same event** — L4's `reject`.
The blueprint routes it. So any prose in these bodies describing how to signal a send-back is ritual: the handoff's
outcome does it (T3).
