# T8 — The A-to-B-to-A round trip

## Notes (2026-10-26, at implementation)

**Q6, answered from the code: the assumption was real, in two places.** The
answer door resolved the resume route from the **saved request bytes** —
`protocol/answer.go` re-resolved the step's *original route name* against the
live table (so re-pointing that one id worked, but a loop steered to another
named route still resumed where it began), and `daemon/recover.go` rebuilt the
re-issued call from `snapshot.Request` outright: a crash between a steered
switch and the next dispatch silently reverted it. Both lifted. A
loop-owned step — resume or recovery — now takes the loop's **current**
route, the same `RuntimeState.Route` the next dispatch reads, through a new
`QuestionStore.StepRoute`; a step outside any loop keeps its own row's
opinion (an ask has no newer one), and recovery whose current route no longer
resolves **fails loudly** naming it — running the old route quietly is the
silent revert wearing reliability's clothes.

**O5, implemented where steers actually drain.** Both boundaries
(`loop.go`'s before-the-call and after-the-turn blocks) live **inside** a
step, so a steer-borne route is always deferred: `LoopState.PendingRoute` →
`StepResult.PendingRoute` → `loop.ModelResult.PendingRoute` →
`applyPendingRoute` (advance + continue paths), which emits
`loop.route.applied` — route is loop state, the runtime reports what it owes
and never writes it. Effort alone stays immediate (same route's dial); effort
steered **with** a route defers as its pair, so the named dial is what the
next dispatch compiles against. The refusal is an event
(`step.route.deferred`) naming the step and saying when it applies, and the
CLI prints the daemon's sentence verbatim.

**Deviations, named.** `files_expected` listed three files; the nine gates
live where the nine behaviours live: four in `runtime/crossprovider_test.go`
(the three legs, provenance order, cost split, mid-step refusal), two in
`adapters/crossprovider_wire_test.go` (the wire halves beside the code that
makes them — a runtime test cannot reach `ToWire`), two in
`daemon/crossprovider_resume_test.go` (the store bytes at every point, and
recovery's route), one in `protocol/answer_test.go` (the answer door's Q6).
Implementation touched the steer machinery, the loop's apply sites, the
answer door, and recovery; three LW6-era steer pins evolved with the doctrine
(their guard — the in-flight call is never yanked — survives strengthened:
now NO call of the step carries the new route), and the event vocabulary grew
one kind with its renderer.

**What was not verified.** No live provider was contacted (I7): what a second
server says to an Anthropic-made transcript is named as an open observation
in `CAPABILITIES.md` rather than claimed, and the app-side rendering of
`loop.route.applied` is bench work, recorded as such.


## Why this exists

**This is the slice's claim**, and an integration test rather than a unit one (R6).

The demo says it: *"a loop suspended on Anthropic is resumed on OpenAI — the proof the canonical format earned its cost."*

**The third leg is what makes it a proof.** A→B shows the adapters translate, which is useful. **A→B→A shows the record
survived** — and that is the property M1 was bought for. Without the return trip, a drop that leaked into the store would
pass unnoticed until somebody tried to go back.

## Scope

### The round trip (D1, D2)

1. Start a loop on an **Anthropic** route. Let it produce thinking blocks and suspend on a `question` (S6).
2. **Switch the route** to OpenAI. Answer. Let it resume and complete a turn.
3. **Switch back** to Anthropic. Run another step.

**Assert the store at every point** (C3): the thinking blocks are present after step 1, after step 2, and after step 3.
Byte-identical, signatures included.

**Confirm Q6 first**: does S6's resume or S7's recovery assume the same route as the original step? If either does, that
assumption is this task's to lift — and it is a small change with a large consequence, since a loop that cannot change
route cannot be resumed on another provider at all.

### A mid-step switch is refused (O5, N9)

A route switch takes effect at the **next step**.

Changing provider between a `tool_use` and its `tool_result` produces a turn **no adapter can construct honestly**: the
tool call came from one provider's format and the result must be attached in another's, with provenance that describes
neither.

So the switch is refused mid-step, naming the step and that it will apply next.

### What the round trip proves, stated in the test

The test's name and comment should say which property each leg establishes, because a future reader will otherwise see
three similar steps:

| Leg | Proves |
| --- | --- |
| A → suspend | Thinking blocks are produced and recorded with provenance |
| → B | The adapter drops them at the wire, counts the drop, and **the store keeps them** |
| → A | The record survived, and the replay is byte-identical |

### `CAPABILITIES.md` (R7)

Append whatever this task encountered — particularly anything about how a provider reacted to a transcript it did not
produce, which is the least-documented part of the whole exercise.

| `TestStoreUnmodifiedAtEveryPoint` | The thinking blocks are in the store after each of the three legs, byte-identical (D2, C3) |
| `TestOpenAIRequestHasNoThinking` | And the drop count is in the step's record (T5) |

| `TestProvenanceShowsBothProviders` | The transcript reports Anthropic and OpenAI turns, in order (T1) |
| `TestCostSplitsAcrossTheTrip` | Per-route attribution over a transcript that spans both (T7) |
| `TestMidStepRouteSwitchIsRefused` | Naming the step, and stating it applies next (O5) |
| `TestResumeDoesNotAssumeTheOriginalRoute` | Per Q6; a resumed step honours the current route |
| `TestRecoveryAlsoHonoursTheCurrentRoute` | S7's recovery path, same property — a crash mid-trip must not silently revert the route |

`TestRecoveryAlsoHonoursTheCurrentRoute` is worth having. S7 recovers a step from persisted state, and if it reconstructs
the route from the step's original provenance rather than the loop's current route, a crash silently undoes a deliberate
switch.
