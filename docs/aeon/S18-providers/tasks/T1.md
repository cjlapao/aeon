# T1 — Provenance — provider, model and route on every assistant turn

## Notes (2026-10-26, the build)

* **The rule is a WRITE rule, not a read rule — the one deviation that matters.** The task said a turn

  callers and five of them are READ/recovery paths (resume, recover, `MigrateTranscript`, compile,

## Why this exists

**First** (R4), because three things need it and adding it after the adapters have branched means editing both.

M27 needs it: thinking blocks are replayed **only to the provider that produced them**, and nothing can know the producer
without a record of it. Cost attribution needs it. And a transcript spanning providers cannot otherwise answer *"which
model wrote this?"* — which stops being an exotic question the moment a loop can switch.

## Scope

```go
type Provenance struct {
    Route    string   // O4 — two routes can share a provider and model
    Provider string   // "anthropic" | "openai" | "openai-compatible"
    Model    string
}
```

Set on **every assistant turn**, by the adapter that produced it.

### The route, not just the model (O4)

Two routes can point at the same provider and model with **different prices or base URLs**. Cost attribution needs the
route; "which model wrote this" needs the model; and a local server behind an `openai-compatible` route needs both to be
identifiable.

Recording only provider and model would make two routes indistinguishable in the ledger, which is the one place the
difference matters.

### Per turn, not per loop (I4)

A loop that switches provider mid-run has turns from both. A loop-level field cannot describe that, and would report the
*last* provider as though it produced everything.

### Storage (Q1 — **answered 2026-10-26 from the shipped tree**)

Q1 is settled by measurement, so this section is a decision, not a question:

- `model.Message` (`internal/model/types.go:59`) is `{Role, Content}` — **no room**. It gains
  `Provenance *Provenance` with `json:"provenance,omitempty"`; **nil means absent**, which is exactly what a user
  or `tool_result` turn needs.
- `step_message` (`internal/store/schema.go:854`) carries `role` as a column but `marshalBlocks`
  (`internal/store/transcript.go:403`) persists **only `m.Content`** — there is nowhere to carry provenance.
  **A migration is therefore required**: `ALTER TABLE step_message ADD COLUMN provenance TEXT NOT NULL DEFAULT ''`
  as **0027**, following the ALTER pattern of 0008/0009/0010 — numbered, one transaction, ledger-recorded, and
  the fresh-equals-migrated equivalence test (`TestSchemaFreshEqualsMigrated`) must still hold.
- `AppendMessages` marshals `m.Provenance` into the new column; the transcript read path rehydrates it back onto
  `Message` — the field must survive both directions like any other part of the record.
- The adapters (`internal/model/adapters/`) set provenance at **production**, never at read.

Provenance is on the **assistant** turn only. A user turn has no producer, and a `tool_result` was produced by a tool, not
a model — inventing provenance for either would make the field mean two things.
