# T6 — The OpenAI-compatible path — no third adapter

## Notes (2026-10-26, at implementation)

**M13 stands, and the pin is a file list.** `TestNoThirdAdapterFile` reads the directory: the non-test
`.go` files are exactly the four, and `model.RegisteredProviders()` answers to exactly `anthropic` and
`openai`. Nothing needed a third file — including the one difference a flag genuinely cannot express
(`delta.reasoning`, below), which went into the existing adapter as a field mapping and into
CAPABILITIES.md's Findings as the record. No stop-and-report trigger fired.

**The gates are absence-of-key, and `wireSays` is one function.** `wireSays(route, cap)` answers yes
to everything when `WireCapabilities` is nil — an undeclared route keeps S3's exact request bytes
(I5), which the pre-existing adapter tests pin by not changing. Only a *declared* route gates:
`tools` key absent (never `tools: []` — the shape S3 pinned for retries, because some servers 400 on
an empty array but every server ignores the missing key), `stream_options` not sent at all (asking a
server that 400s on unknown keys is a dead route, and an `include_usage: false` is a different
request), `parallel-tools` documented as today's standing behaviour (never sent; the flag reserves
its name rather than pretending to control code), and the system fold. The fold keeps the canonical
system turn (M1, asserted on marshalled bytes both ways) and falls back to a leading user message
when there is no user turn to fold into — silently losing the instruction would change behaviour
with nothing saying so.

**Q11 answered: handled, and the synthesis records itself.** `normalizeCallID`, shared by both wires:
an absent id becomes `aeon-synthesized-<index>` — the id IS the record, so a transcript read years
later distinguishes provider-issued ids from made-up ones without a side channel — and a duplicate
gets `-aeon-2`, `-aeon-3`. The reassembler was already index-keyed (S3's M8), so two calls were never
merged *in flight*; what duplicates actually break is the return path, where tool results pair back by
id, so two calls must stay two addresses. **Measured, no server here emits these shapes**: Ollama
0.18.0 issued well-formed `call_…` ids on every probe, so the two Q11 fixtures are `hand-written`,
labelled as such in the manifest with what was not verified (O4). They test the defence, not a
documented behaviour.

**The finding a flag cannot express.** Ollama 0.18.0 streams thinking as `delta.reasoning` with
`content` empty while the model thinks (measured: `qwen3.5:latest` spent 1,484 reasoning tokens to
answer "Hello there"). Ignoring it meant a reasoning model streamed thirty silent seconds. Reading it
into thinking deltas is safe *because* T5 already guarantees no thinking ever returns on this wire —
it is event and display material, never replayed. This is M13's mechanism working as designed: a
compat difference that is code, recorded under Findings, absorbed by the one adapter.

**The "tested against" line is from the run that happened (O7).** Three fixtures are `recorded`
captures from this machine's Ollama 0.18.0 with `qwen3.5:latest` on 2026-10-26, distilled from the
raw streams (reasoning chunks, the usage-on-final-empty-`choices`-chunk shape, the tool call with its
provider id, and — measured with `stream_options` *not* requested — a stream with no usage anywhere,
which is where M9's unknown comes from). Tests stayed offline (I7): they read the fixtures through
the same loader as every other fixture, and `TestToWirePerformsNoIO`'s panicking transport is
re-asserted from this file so the compat tests cannot have quietly needed a server. **No second
server has been run for this record**, and the file says exactly that rather than naming vLLM from
memory; naming it belongs to a run, and until then the gap is named, not assumed filled.

**Deviations, small and stated.** The spec's gate list became eight tests including a reasoning-read
test and the manifest-side I7 check; `TestAgainstRecordedFixturesOnly` checks the labels and the
standing guard rather than re-implementing the no-IO test. `parallel-tools` is the one flag that
controls nothing yet — honest either way, and the flag table row says so.

## Why this exists

**M13's claim, made good on or disproved.**

> *The OpenAI-compatible path is the OpenAI adapter plus capability flags, not a third adapter. A near-duplicate file
> drifts; the differences are absences, not behaviours.*

M31 makes it falsifiable: **a difference that cannot be a capability flag is a finding about M13**, recorded and raised —
not a third adapter added quietly, which would disprove M13 without anyone noticing.

## Scope

### Capability gating in the existing adapter

The OpenAI adapter reads its route's wire capabilities and adjusts — both wire formats behind the one `openai`
provider id (`openai.go` dispatches to `openai_responses.go` on `route.openaiEndpoint`; a capability absence
applies on whichever format the route selects):

| Absence | Adapter behaviour |
| --- | --- |
| `tools` | Omit the `tools` key entirely — S3 already tests that a retry carries **no tools key**, which is the same shape |
| `streaming-usage` | Do not request `stream_options.include_usage`; take usage from the final chunk or **not at all** (M9) |
| `parallel-tools` | Do not send `parallel_tool_calls` |
| `system-role` | Fold the system message into the first user message |

**Every one is an absence.** That is M13's argument, and this table is where it is either true or not.

### The behaviours that are not absences (D13, Q11)

Two real cases from actual servers:

**A tool call with an empty or duplicate `id`.** S3's reassembler keys on it (M8). **Answer Q11**: handled or refused —
and state which. Synthesising an id is defensible if the transcript records that it was synthesised; silently accepting a
duplicate is not, because two calls would merge into one.

**Usage only in the final chunk.** Covered by the `streaming-usage` absence, and worth confirming it genuinely is rather
than assuming.

The **Findings** section may be empty. Its presence is what stops the question being skipped.

### Not in scope

**No new adapter file** (N7, D10). If the differences genuinely require one, **record the finding and stop** — that is
information about M13, and it is more valuable than the file.

**The `openai_responses.go` precedent (reality alignment, 2026-10-26).** `internal/model/adapters/` already ships
`anthropic.go`, `openai.go` **and** `openai_responses.go`. That third file is not a third provider and not a
compatibility adapter: it is a **second wire format behind the one `openai` provider id**, justified by a measured
400 (`/v1/chat/completions` refuses function tools while reasoning is on; `/v1/responses` does not), and the
registry registers `openai` once through a dispatcher. M13's claim is about the **OpenAI-compatible** path:
Ollama and vLLM run on the existing adapter plus flags. The pin below encodes exactly that.
