# T2 — Capability flags on the route, and the three states

## Why this exists

**M13's whole argument rests on this file.** *"The differences are absences, not behaviours"* — so the differences must be
expressible as flags, and this task is where that becomes concrete rather than asserted.

Separate from the probe (R5): declaring is a data shape, probing is a request and a cache, and they fail differently.

## Scope

### The flags (Q8)

**Answer Q8 first** — the full set, and what each absence changes. **A missing table blocks the plan**, because M13's
viability *is* that table.

```go
type Capability string

const (
    CapTools          Capability = "tools"
    CapStreamingUsage Capability = "streaming-usage"
    CapThinking       Capability = "thinking"
    CapSystemRole     Capability = "system-role"
    CapParallelTools  Capability = "parallel-tools"
)
```

Each names an **absence** when unset. `CapStreamingUsage` absent means usage arrives at the end or not at all — and the
cost path already handles "not at all", which is M9's every-field-optional shape doing its job three slices later.

### The three states (M28, D6)

```go
type CapabilityState string

const (
    StateDeclared     CapabilityState = "declared"      // declared, not probed
    StateVerified     CapabilityState = "verified"      // declared, probe confirmed
    StateContradicted CapabilityState = "contradicted"  // declared, probe disagreed
)
```

**`verified` is not the same as `declared`**, and neither is the same as `contradicted`. A declaration alone lies when a
route is copied from a colleague; only a probe can tell you otherwise (T3).

This is [P31](../../ARCHITECTURE.md#8-product-decisions)'s **sixth** instance. At six the shape is load-bearing: assume
any new verification will need it.

### Two capability vocabularies, and they never merge (reality alignment, 2026-10-26)

`Route.Capabilities []string` **already exists** — shipped by the model-management wave (migration `0026_route_metadata`,
validated by `internal/model/metadata.go`'s `NormalizeMetadata` against the closed set
`text|image|tool-calling|pdf|file|thinking|thinking-effort`, surfaced on `RouteView`). That vocabulary describes
**what a model is** for the app's catalogue and editor.

This task's flags describe **how an OpenAI-compatible wire behaves** — and both vocabularies contain the string
`"thinking"` meaning different things. They are different axes and must not share a field:

- The new field is `WireCapabilities []string` (`json:"wireCapabilities,omitempty"`) on `model.Route` and on
  `SetRouteParams`/`RouteView` in `internal/protocol/routes.go`.
- Its closed set is the five flags above, validated **in `capability.go`** — never through `metadata.go`'s
  `normalizeSelection`, which rejects unknown values and belongs to the other vocabulary.
- A test pins that the two sets are disjoint in meaning: `TestWireAndMetadataCapabilitiesAreDistinct` — the string
  `"thinking"` may appear in both, and the validation paths must remain separate code paths, asserted by call site.
- **No coupling rule between them is invented.** A route may declare `tool-calling` in metadata and lack wire
  `tools`; that is a coherent statement about a model and a server, not a contradiction to police.

### A missing price is a configuration error (O8)

An unmetered route must declare `--no-price` **explicitly**.

**A route with a silently missing price is how a typo makes a metered model report `unknown` forever** — and nobody
notices they stopped tracking cost, because `unknown` is a legitimate answer they have been trained to accept.

So: no price and no `--no-price` is a **configuration error naming the route**. Declaring `--no-price` is a decision
someone made.

**The enforcement point (settled 2026-10-26, containment of a breaking change):** the refusal lives at
**`routes.set` / `MutableRoutes.SetAndPersist` for newly persisted routes**. A route row that predates the rule still
loads — a daemon must not die on a row it accepted under yesterday's contract; it renders `Priced:false`, which is
the warning `RouteView` already carries. Environment routes are unchanged (they are ephemeral configuration, not the
ledger). `SetRouteParams` gains `noPrice *bool`, `aeon routes set` gains `--no-price`, and the app's two route
editors — the bench's ProvidersPage and S23-era ModelEditor — gain the explicit checkbox so the just-shipped model
editor cannot be broken by the rule.

### The CLI

The verb is **plural** — `cmd/aeon/routes_verbs.go` ships `aeon routes list|set|delete`; there is no singular
`route` command. T2 extends it in place: `aeon routes set --capabilities tools,streaming-usage --no-price`, and
`aeon routes list` prints each route's wire capabilities with their three states and timestamps (T3 supplies the
timestamps; before it, everything reads `declared`).

### Not in scope

The probe (T3), the pre-call check (T4). This task declares and reports.
