The store additionally **refuses to cache a zero-timestamp or model-less verdict** — refuse the cache, not
the probe; the caller already holds the answer to show.

**Q9, answered where it is enforced.** The table lives in `internal/model/probe.go`'s header comment and

(1) **only definitive evidence moves a state** — the provider's own 400 *naming* the feature, or the
measured arrival/absence of a stream part that was actually asked for; (2) **a probe failure is the third

indistinguishable in one request), `parallel-tools` unless two calls actually arrive, `thinking` unless a

stored**: absence of a row *is* the state.

# T3 — The probe

## Why this exists

A declaration alone lies when a route is copied. A probe alone answers about *a* model rather than **this** one, and costs
a request every time.

So the route declares and the probe **verifies** — and the interesting requirement is what happens when they disagree.

## Scope

### Probing (Q9)

**Answer Q9**: how each capability is probed, and what it costs. Some are cheap: a single minimal request reveals whether
`tools` is accepted and whether usage arrives in the stream. Some cannot be probed without a real call, and for those the
honest answer is that they stay `declared`.

**A capability that cannot be cheaply probed stays `declared`, and says so.** Inventing a probe that half-works produces
`verified` badges nobody should trust — which is worse than an honest `declared`.

### One request per route, cached (D7)

Not per step. A probe paid per step is a tax on every call for a fact that does not change hour to hour.

**Where the cache lives (settled 2026-10-26): the store, not memory.** A new migration — the next free number
after T1's, so **0028** if T1 took 0027 — adds

```sql
CREATE TABLE route_probe (
  route_id     TEXT NOT NULL,
  capability   TEXT NOT NULL,
  state        TEXT NOT NULL,   -- verified | contradicted (declared = absence of a row)
  detail       TEXT NOT NULL DEFAULT '',
  probed_model TEXT NOT NULL,
  probed_at    TEXT NOT NULL,
  PRIMARY KEY (route_id, capability)
);
```

so results **survive a restart** — a daemon that forgets its probes on restart would silently return every route to
`declared` and lose the contradiction that protects Friday's loop. `declared` is represented by the **absence of a
row**, so a probe never writes the declaration (I5) and the three states stay derivable. The in-flight lock is
memory-only — it guards concurrent requests, not facts.

### The result carries its timestamp and the model probed (O2)

```go
type ProbeResult struct {
    Capability Capability
    State      CapabilityState
    Detail     string     // what the probe saw
    ProbedAt   time.Time
    Model      string     // WHICH model was probed
}
```

**A cached `verified` from three weeks ago against a model that has since been replaced is a stale claim wearing a
verified badge.** The timestamp and the model are what let someone notice.

### It never rewrites the declaration (M28, I5)

The probe records what it found **alongside** the declaration, never over it.

A probe that rewrote the route would make the declaration meaningless and **the contradiction invisible** — the very thing
the three states exist to surface.

### A contradiction refuses, twice (O3, D6)

**At probe time**, so someone running `aeon routes probe` finds out. **And at use time**, so someone who probed on Monday
and runs on Friday does not have to remember.

The second is what actually protects the loop:

```
refused: route 'local-wrong' declares 'tools' but the probe contradicted it
         (probed 2026-09-06T14:02Z against llama3.2:1b)
```

Quietly dropping `tools` because a probe found none is how a loop runs three steps, discovers it cannot call a tool, and
**blames the model for a route's mistake.**

### The daemon method, not only the CLI (D16, I10, P34 — added 2026-10-26)

**`routes.probe {route}` is a registered socket method**, locked exactly like S34's `mcp.check`: operator-
triggered only (no auto-probe on `routes.list`, on route save, or on daemon start), one in-flight probe per
route (a second call while one is running returns the in-flight result, not a second request), bounded
timeout. `aeon routes probe <id>` — a subcommand of the existing `aeon routes` verb in
`cmd/aeon/routes_verbs.go`; there is no singular `aeon route` command — becomes a thin socket client of this
method: **the probe implementation lives in `internal/model/probe.go` and nothing under `cmd/aeon/`** implements
one; a divergence between what the CLI shows and what the socket returns is a bug, the
same discipline S34's own `aeon mcp list --agent` / `mcp.check` pair established.

`routes.list`'s existing response gains each route's capability states (`ProbeResult` per declared
capability, or `declared`-with-no-probe-yet if `routes.probe` has never run for it) — **this is what makes
the probe's result visible to the app without a second round trip**, the same way `mcp.status` already
carries tier/declare facts `mcp.check` doesn't duplicate.

### Not in scope

The pre-call check for a capability a route legitimately **lacks** (T4). This task handles a route that **claims** one it
does not have — a different failure with a different message.

## Tests

| Test | Asserts |
| --- | --- |
| `TestContradictionRefusesAtProbeAndAtUse` | **Both.** A probe reports it; a later step refuses it without probing again (O3, C5) |
| `TestProbeIsOneRequestPerRoute` | Against a recorded fixture: one request, then cached. A hundred steps issue no further probes (D7) |
| `TestProbeNeverRewritesTheDeclaration` | The declaration is byte-identical after a contradicting probe (I5, E4) |
| `TestProbeResultCarriesTimestampAndModel` | Both present; a result without them fails (O2) |
| `TestUnprobableCapabilityStaysDeclared` | And says so, rather than being invented as `verified` |
| `TestProbeAgainstFixtures` | Every capability's probe, against recorded responses. **No live provider** (I7) |
| `TestStaleProbeIsVisible` | A probe older than its route's model change is identifiable — the information is there even if nothing acts on it |
| `TestProbeFailureIsNotAContradiction` | An unreachable server leaves capabilities `declared`, not `contradicted`. *"Could not check"* and *"checked and wrong"* are different facts |
| `TestRoutesProbeSocketAndCLICallSameFunction` | A call-site check: the socket handler and `aeon routes probe` both reach the identical probe function in `internal/model/probe.go` — no second implementation under `cmd/aeon/` (D16, P34) |
| `TestProbeNeverAutoFires` | `routes.list`, route save and daemon startup each produce zero probe requests against a spy transport — only an explicit `routes.probe` call does (M32) |
| `TestRoutesListCarriesCachedProbeResults` | After one `routes.probe` call, the next `routes.list` response includes that route's `ProbeResult`s with their timestamp and probed model, with no second probe fired |

`TestProbeFailureIsNotAContradiction` is the distinction that would be missed. A network failure during a probe is not
evidence about the server's capabilities, and recording it as `contradicted` would refuse every subsequent step for a
reason that was never true.
