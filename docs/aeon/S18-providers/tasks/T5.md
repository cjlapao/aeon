## Notes (2026-10-26, at implementation)

**Migration 0030.** `0030_step_thinking_dropped` — `ALTER TABLE step ADD COLUMN thinking_dropped INTEGER
CHECK (thinking_dropped IS NULL OR thinking_dropped >= 0)`, in 0028's ALTER style. NULL means *nobody
recorded* (every row predating T5) and reads back 0 — honest here where it would not be for cost (DB11),
because the number counts an **event**: an adapter either withheld blocks or it did not, and the adapter
building the request always knows. `SetStepThinkingDropped` is the ONE writer; it refuses a negative (not
a number, a bug) and an unknown step (`ErrNotFound`), and the runners call it only when a block actually
fell — zero stays unrecorded.

**O1 carried the work past the spec's three adapters.** The count has to *reach the step's record*, which
meant following the number all the way (each hop the same optional-interface idiom D6's `OwedToolErrors`
uses):
- `model.StreamResult.ThinkingDropped`, collected by type assertion beside `OwedToolErrors` in `client.go`;
- `runtime.LoopState`/`StepResult.ThinkingDropped`, accumulated per call at the same site as `st.Usage` —
  so a **failed** step still reports what it withheld (`TestThinkingDropsRideAFailedStepToo`, M15's
  ranking applied to the new number);
- `daemon.StepRunner.ThinkingCount` files it at completion (`ThinkingRecorderFor(store, log)` — the same
  function-field seam as T3's `ContradictionCheck`, same K22 reason; a failed write is spoken, never
  fatal: the step ran, the cost is real, a lost counter is incompleteness not failure);
- the **ask** path: `AskSaveParams.ThinkingDropped` → `memory.go` writes it beside `SetStepCost`.
  `AskResult` is deliberately **unchanged** — the spec's record is the step row; `ask.done` is a streaming
  payload and T10 renders from the rows.

**`openAIDispatch` must forward `ThinkingDropped`.** Same trap `OwedToolErrors`' comment warns of: the
client asserts on the dispatcher, and a wrapper that does not forward answers "nothing was dropped" for
whichever wire actually withheld — a wrapper's silent zero, which is the exact M4 failure this counter
exists to prevent. `TestAThinkingBlockIsNotSentAndIsCounted` was evolved to pin both halves: the
dispatcher forwards, and the request-direction count does NOT leak into the response-direction
`Finalise().dropped` (responses used to merge them; the two directions answer different questions).

**Two bugs the task surfaced.** (1) The handoff-retry append in `loop.go` did not stamp provenance on its
assistant turn — T1 stamped the main append only. An unstamped turn is nobody's, so T5 would withhold that
provider's own thinking from its own next call: the P21 break smuggled in through the branch that builds
its append by hand. `TestTheHandoffRetryTurnCarriesItsProvenance` pins the stamp. (2)
`aeon debug roundtrip --provider openai` could never run: `wireSignatures` decoded OpenAI chat's
string-form `content` into Anthropic's block-array form and died on the unmarshal error — latent since S3
because only the anthropic direction was ever walked. Content now reads as raw and unmarshals per
message; the verb also gained a **WITHHELD** verdict (`TestDebugRoundtripReportsTheWithheldBlock`),
because after T5 it is the one screen where "the fidelity broke" must be told apart from "M27 fired".

**Per-request because the adapter instance is per-request** — the registry's factory hands out a fresh
adapter per request and `openAIDispatch` builds both wires fresh. One honest subtlety: `model.Client`
holds one adapter across **retry attempts**, so a retried call reports the withheld blocks summed across
its attempts. That is still the truth (each attempt did withhold them) and still per-call, not
step-cumulative; `TestDropCountIsPerRequestNotCumulative` pins the two-adapter semantics.

**Nil provenance: dropped and counted.** The spec's rule names the producer case; a turn with no
provenance has no producer to name, and replaying it is the bet on somebody else's validator M27 exists
to refuse. Proves are not sent.

**Reality recorded.** The step path's transcripts do not yet carry thinking blocks — the loop emits
thinking as events and appends text + tool_uses to the transcript — so the rule's live consumers today are
the ask save path (whose transcript stores thinking *without* its signature: S3's streaming surface never
carried it, recorded in `AskSaveParams`' own comment) and any S7 replay of stored rows. The rule, the
count and the record are in place for the day the loop persists thinking; the adapter tests test
behaviour, not wiring.

# T5 — The thinking-replay rule

## Why this exists

**This is what makes cross-provider resume safe rather than hopeful.**

M17 replays `thinking` blocks verbatim, signature included, because *"Anthropic rejects a tool-use turn whose prior
thinking was altered or dropped"* (P21). OpenAI has no such concept, so they are dropped — which M4 permits, provided they
are **dropped and counted**.

The second-order problem is the one the naive version misses. After a turn on OpenAI, the transcript holds an **Anthropic
signature followed by a turn Anthropic did not produce.** Replaying that is a bet on somebody else's validator.

So: **thinking blocks go only to the provider that produced them** (M27), which is what T1's provenance is for.

## Scope

### The rule, keyed on the producer (M27, I3, O6)

```go
// In the Anthropic adapter, per assistant turn:
if turn.Provenance.Provider == "anthropic" {
    // replay thinking verbatim, signature included (M17)
} else {
    // drop, and count (M4)
}
```

**It keys on who produced it, never on whether the target supports thinking** (O6).

That distinction matters for a provider that arrives later supporting reasoning in a *different* format: it still cannot
receive Anthropic's signatures, so a rule reading *"does the target support thinking?"* would send them and fail. The rule
reads *"did this target produce it?"*

### The store is never modified (M1, I1, D2)

**A drop is a wire-level translation.** The transcript in the store keeps every thinking block, always.

That single property is what makes the round trip work in both directions. If a drop ever reached the record, A→B→A would
become one-way and nobody would find out until they tried to go back.

Asserted by comparing the store's bytes before and after a request is built.

### Dropped and counted, and the count reaches the record (M4, O1)

```
3 thinking blocks dropped (provider 'openai' does not support them)
```

**Not only a log line** (O1). The count goes into the step's record, so S9 can render it and *"why did this turn behave
differently"* has an answer where someone is looking.

### Not in scope

The round trip itself (T8), and the OpenAI path's capability gating (T6). This task is the rule and its
**three** adapter sites — `anthropic.go` (replay, producer-keyed), `openai.go` **and** `openai_responses.go`
(drop and count: one provider, two wire formats, and neither accepts a foreign signature).

## Tests

| Test | Asserts |
| --- | --- |
| `TestThinkingReplayedOnlyToItsProducer` | An Anthropic-produced turn's thinking is replayed to Anthropic **byte-identical, signature included**; an OpenAI-produced turn's content is not replayed as thinking (M27) |
| `TestCrossProviderDropIsCounted` | An OpenAI request built from a transcript with three Anthropic thinking blocks contains **none**, and the count is **3** in the step's record (M4, O1, C4) |
| `TestStoreIsUnmodified` | The store's bytes are identical before and after building an OpenAI request (D2, I1, C3) |
| `TestRuleKeysOnProducerNotTargetCapability` | A hypothetical target declaring `CapThinking` still does **not** receive Anthropic's signatures — the test that fails against the plausible wrong implementation (O6, I3) |
| `TestSignatureIsNeverAltered` | Replayed signatures are byte-identical; no re-encoding, no whitespace change (M17) |
| `TestMixedTranscriptToAnthropic` | A transcript with Anthropic and OpenAI turns replays only the Anthropic thinking, and Anthropic accepts it (against a recorded fixture) |
| `TestDropCountIsPerRequestNotCumulative` | Two requests each report their own count |

`TestRuleKeysOnProducerNotTargetCapability` is the one to write first. The plausible implementation checks the target's
flags — it reads naturally, it passes every other test here, and it breaks the first time a second reasoning provider
exists.
