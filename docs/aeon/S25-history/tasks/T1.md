# T1 — the merge query

## Why this exists

Every other task in this slice calls into this package. This is where D7 (history does not stop at the
archive boundary) and H6 (P32's floor, applied across many loops) are enforced once, not re-derived per
surface.

**Read first:** `design.md` §2 in full — the archive-boundary finding and why a naive `loop`-only query
fails silently rather than loudly. `internal/store/archive.go`'s `ListArchives`/`ReadArchive`, and S9's
existing per-loop floor logic (wherever it renders "at least $…") as the shape H6 generalizes.

## Scope

**1. The merge**: one function returning a time-ordered sequence of entries, each either a live-loop summary
(from `ListLoops` or equivalent) or an archived-loop summary (from `ListArchives`'s `Archive` header) —
distinguishable by a tag on the entry, never by the caller having to know which table it came from.

**2. Four lane groupings** (H1): `ByLoop`, `ByPhase`, `ByTask`, `ByAgent` — each a `GROUP BY` over existing
columns (`loop.slug`, `step.phase`, `step.taskid`, `step.agent`). No new join shape; if one of these turns
out to need one, say so in this task's Notes rather than silently adding it.

**3. The P32 floor** (H6): a rollup type that is never a bare number — `{Total float64, Floor bool,
UnknownCount int, StepCount int}` or equivalent, rendered downstream (by T3/T4/T5) as "at least $X (K of N
steps unknown)" whenever `Floor` is true, a bare "$X" only when `UnknownCount == 0`.

## Notes

**Decided — `internal/history` is a read-only package over the store.** It reads through `ListLoops`,
`ListArchives`, `LoopCost`, `ListSteps` and `ReadEvents`; it adds no store method, no table and no
column (D5). The diff touches only `internal/history/*` — no `schema.go` line, no migration — so the
"no new table / no migration" gate is satisfied by construction (the slice adds nothing the store must
remember). The four lanes (H1) read the existing `ListSteps` per loop and group in Go rather than a new
SQL `GROUP BY`, so a new join shape cannot exist; `TestFourLanesNoNewJoinShape` pins the grouping is
correct for each of the four and records the read (no new shape, no new column the plan must index).

**Merge (D7).** `Merge` returns one time-ordered sequence over live loops (`ListLoops`) and archived
loops (`ListArchives`), each entry tagged by `Kind` (Live/Archived) so a caller never has to know which
table a row came from. Ordering is by the loop's OWN timeline — `updated_at` for a live loop, `ended_at`
for an archived one — so an archived loop is placed by when it ran, not pinned to the end just because
it was archived last (DEMO step 1's prediction).

**P32 floor (H6).** `Rollup{Total, Floor, UnknownCount, StepCount}` — the spec's shape. `costFloor`
mirrors the store's `costQuery` SUM(cost_usd) exactly (an unknown never contributes a number; it
contributes a count), so a loop's figure is identical whether read through the store or this package.
`Aggregate` sums the per-loop floors; a floor in any loop floors the whole. The render is one function
(`Rollup.Render`): "at least $X (K of N steps unknown)" when `Floor`, a bare "$X" only when
`UnknownCount == 0` — the count of unknowns travels with the number (P32). A second place that phrases
a cost is a second truth, so T3/T4/T5 render through `Rollup.Render`, not their own.

**Archived cost (recorded, an honest floor not a zero).** An archived loop's header carries no step
costs — the archive preserves the header and the document files, not the step costs (Q3) — so its cost
is honestly an unknown floor (`Floor: true, UnknownCount: 1, StepCount: 1`), never a total. This is a
deliberate approximation of an uncountable cost as "one unknown" (the header has no step count); a
future slice could carry the count in the archive header. It floors the whole rollup and names the
unknown, never drops it (R1/R2) and never invents a number.

**Blocked reason (D4/H4).** A blocked loop's reason is read verbatim from the `loop.blocked` event
payload (`{"reason": …}`) — the source design.md names — never a synthesized verdict. A blocked loop
with no recorded event returns "" (an honest "no recorded reason," not a fabricated "failed"). An
archived loop's reason is not read here (it lives in the cold-stored state, Q3), so the list shows ""
rather than invent one.

**Deviation (files_expected).** The task's `files_expected` lists `query_test.go` and `rollup_test.go`;
`TestFourLanesNoNewJoinShape` lives in a separate `lanes_test.go` (the other two gates take query_test.go
and rollup_test.go). The three named gates are the same; one extra test file, no extra gate.
