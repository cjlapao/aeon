# T4 — `history.*` socket methods

## Why this exists

The app (T5) reads through the socket, never the CLI, matching every other surface in this project. Every
method here is **read-only** — like `policy.*`'s four socket methods, unlike S24's `queue.*` (which is
deliberately writable, CG9 in that slice's own `design.md`). This slice has nothing to author; there is no
CG9-equivalent decision to make here.

**Read first:** `internal/protocol/method.go`'s existing `MethodPolicyList` shape for the registration
pattern.

## Scope

**Methods**: `history.list`, `history.show` (drill-down), `history.export` — mirroring T3's CLI verbs,
calling the same `internal/history` functions.

## Validation

- [ ] `TestHistorySocketAndCLIProduceIdenticalRows` — same fixture, both entry points, byte-identical
      results
- [ ] `TestHistoryMethodsReadOnlyNoAuditRow` — none of the three methods writes anything, anywhere (no
      `policy_event`-style audit row either — there is nothing to audit, this is a read)
- [ ] every method requires `Initialize`, matching `policy.*`'s convention

## Notes

**Decided — the three reads mirror `policy.*` (read-only), and the same `internal/history` the CLI reads (H3).** `history.list`, `history.show`, `history.export` are handlers on `*Table` in `internal/protocol/history.go`, registered in `NewTable` with `RequiresInitialize: true` (the `policy.*` pattern, S10 T13). They read the SAME `internal/history` the CLI reads (S25 T3): the ONE query `history.Query` and the ONE row shape `history.Row` live in `internal/history`, so the socket and the CLI cannot drift — H3 is structural here, not a rot-prone test. The CLI's `rowOf` is a thin pass-through to `history.Row`, and its `historyQuery` is a thin pass-through to `history.Query`; the socket's `list`/`export` call the same query.

**The store seam — `*history.Store`, not `*store.Store` (the four-package boundary).** The task's `files_expected` names `aeon/internal/daemon/history_handlers.go`; the handlers instead live in `internal/protocol/history.go` (the `policy.*` seam, where every read handler already lives), and the registration is in `method.go`'s `NewTable` (the `MethodPolicyList` pattern). The load-bearing discovery: the four-package boundary (`TestTheFourPackagesCannotSeeEachOther`) forbids `protocol` importing `store`, so a `HistoryStore *store.Store` field is not permitted — it would carry the persistence layer into the leaf S19 mounts on HTTP. The fix mirrors `policy.Store`: a `*history.Store` facade (new `internal/history/store.go`) that owns the `*store.Store` and exposes `List`/`Show` through `history` types only, so the protocol imports `history`, not `store`. The daemon wires it: `table.HistoryStore = history.NewStore(opts.Store)`. The CLI keeps calling the free functions over `*store.Store` directly; the facade is the socket's door only.

**H3 — the socket and CLI render the SAME rows, proven structurally.** `TestHistorySocketAndCLIProduceIdenticalRows` seeds a live loop (with a known-cost step and a transcript), an archived loop (cold-stored content), and a blocked loop (a recorded reason), dispatches `history.list` over the socket, and compares the result's rows to `history.Row` of the socket's own `history.Query` — same function, same entries, asserted in order. Because both surfaces turn an `Entry` into a `HistoryRow` through ONE `history.Row` and read through ONE `history.Query`, a cost or a reason cannot come out differently under the socket than under the CLI; the gate fails the instant a second query or a second formatter appears.

**Zero writes (the gate's other half).** `TestHistoryMethodsReadOnlyNoAuditRow` dispatches all three reads against a fixture and asserts the event count is unchanged: none of the three touches the recorder, so no `policy_event`-style audit row appears — a read is not an event (there is nothing to audit, the slice has no CG9-equivalent write door). `store.Store` is a concrete type, so the gate is the absence of any write path in the handlers, not a spy.

**DB19 — a wrong door travels verbatim, never read as empty.** `history.show` finds the entry in the shared query (by id or slug), then reads it through its own door — a live loop's transcript, an archived loop's cold-stored content. A live entry asked of the archived door (or vice versa) is a `*WrongDoor` that travels across the wire as a named refusal (`refused`), never an empty read; a not-found id is the protocol's own `ErrHistoryRefused` (`-31800`) by name. `TestHistoryShowRefusesWrongDoor` pins the live entry's show returns its transcript (the right door), and the refused fixture pins `-31800`.

**Conformance + protogen (the registry).** Three success fixtures (`conformance/history/list|export|show.json`) and one refused fixture (`refused.json`, `-31800`) were added so `TestEveryMethodHasASuccessFixture` and `TestEveryErrorCodeHasAFixture` hold; the three names were added to `TestTheMethodTableHasExactlyTheExpectedMethods`'s `want`; `make protogen` regenerated `ui/src/proto/contract.ts` (the protogen tests pin the diff). `-31800` was chosen free (`-31700` is `ErrQueueRefused`, `-31500`/`-31613`/`-31610`/`-31600` are taken).
