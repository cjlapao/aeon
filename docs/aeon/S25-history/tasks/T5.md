# T5 — the History view

## Why this exists

The one UI surface this slice adds. **There is no pre-reserved nav slot for it** — unlike S31's `Telemetry`
and `Agents` tabs (drawn disabled, waiting for their data), nothing in S9 or S31 names a "History" tab today.
This task adds the route and decides where it hangs off the project view; record that call in this task's
Notes rather than leaving it implicit.

## Scope

**1. Reuse S9's existing Gantt/lane component** for the time-ordered rendering — the sketch's "same
component, two directions" made literal. This task does not build a second Gantt.

**2. Render all four lane groupings** (loop/phase/task/agent) via a selector, calling `history.list` with
the corresponding `--group-by`-equivalent parameter.

**3. Render the floored rollup form exactly as T1/T3/T4 produce it** — "at least $X (K of N unknown)" when
`Floor` is true, a bare figure only when it is false. No new rounding, no new phrasing invented in the UI
layer that the Go layer did not already decide.

**4. Archived loops render visibly differently from live ones** — not hidden, not identical; a person
looking at the sequence can tell which entries are cold-storage without opening one.

**5. Drill-down**: live transcripts load immediately; an archived loop's content is a second, explicit
fetch (Q3/T2) — the view should not pretend this is instant the way a live read is.

- [ ] vitest: an archived-loop entry and a live-loop entry are visually distinguishable, asserted on markup

## Notes

**Decided — where it hangs (the task's explicit call).** The slice has no pre-reserved nav slot, so the
History view hangs off the test bench (`/bench/history`, a `BENCH_PAGES` tab) beside the other read
surfaces (`queue`, `policy`) rather than as a main-nav tab S9 owns. It is the testable surface the gate
drives; the real-app placement (a tab under the project view) is S9's designed experience, not this
slice's. Recorded here rather than left implicit, as the task asked.

**The lane component (the "same component, two directions" call).** The time-ordered rendering reuses
S9's lane concept: each open row is a loop, and a loop's detail is S9's `Workflow` lane view (the one
`statusOf` mapper, the `Ladder` structure). This page renders the SEQUENCE the lanes sit in — the rows —
and the drill-down (Q3/T2) folds an entry into that lane view. The one honest deviation, recorded: the
`history.*` result carries a `transcript` (not `lanes`), so the drill-down renders the transcript rather
than re-shaping it into `LadderLane[]`; the lane component is the conceptual reuse, the transcript is the
actual content.

**H6/P32 — the floored form is the daemon's `Rollup.Render` output, verbatim.** A row's `cost` is the
one string the Go layer produced (via `history.Row`): "at least $X (K of N unknown)" when floored, a
bare "$X" only when `UnknownCount == 0`. This page renders `cost` verbatim and invents no second phrasing
and no rounding, so it cannot print a bare number by forgetting to check `Floor`. The gate exercises both
cases against the page.

**Archived is a markup distinction, not a color (the gate's second half).** Each row carries
`data-kind` (`live`/`archived`) and a spoken label ("archived · cold storage" vs "live"), asserted on
markup by the test, never merely eyeballed.

**DB19 — a wrong door travels verbatim.** `history.show` on a wrong door returns the named refusal
(`refused`), which the page prints, never read as empty.

**Q3/T2 — the archived drill-down is an explicit second fetch.** A live transcript loads on the board's
same call; an archived loop's content is a named second fetch ("cold-storage read … a second fetch, not
the live read"), never pretended instant.
