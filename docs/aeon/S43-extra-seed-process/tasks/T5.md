# T5 · Dispatch reads the row

**Prefix:** SD · **Rules:** SD1, SD7, SD8 · **Depends on:** T4.

## Goal

Make the database — not the embedded markdown — the **source of truth for first-party dispatch**. The handler guards,
`Compile` and `BuildSchema` are unchanged; what changes is where a `Handler` comes from. Done **characterization-first**
because ~9 call sites (T0's inventory is authoritative) depend on `handler.Lookup/Build/Names/LoadDefinition`.

## Phase A — characterize (commit first, green on untouched code)

`aeon/internal/handler/dispatch_golden_test.go` + `testdata/dispatch/*.golden`: for **every** registered body, record the
exact `Compile` output (system prompt, tools, temperature, handoff schema JSON) and the values `policy_gate.go:210`,
`learnings/scope.go:39`, `agentsvc/cards.go:103`, `plugin/import.go:304`, `daemon/handlers_ops.go:30` observe through
`Lookup/Names/Preset/RegisteredBodies`. Hash the golden set; record the Phase A commit in Notes.

## Phase B — the change

- `aeon/internal/handler/source.go` — **new**:
  ```go
  type Source interface {
      Lookup(name string) (Handler, bool)
      Definition(name string) (Definition, *Reject)   // where a caller needs front matter (temperature etc.)
      Names() []string                                // dispatchable (system, seeded) names
      Preset(name string) bool
  }
  func FromRow(a store.AgentView) (Handler, *Reject) // see below — takes a handler-local view struct, NOT store.Agent (no store import)
  func SetSource(s Source)                            // production wiring at serve; panics if called twice
  ```
  `FromRow` **re-runs the existing guards** on the row's content — tools ⊆ the tool registry (O1), `BuildSchema(handoff)`,
  `Verify` where it applies — so a hand-edited system row cannot smuggle a tool the registry lacks (SD8 defence in depth).
  It returns a `*Reject` naming the agent and the field on any failure; dispatch refuses that agent rather than running it.
  `handler` takes a small local `AgentView` struct (fields only), **not** `internal/store` types — the daemon adapts
  `store.Agent` to it, keeping `internal/handler`'s imports as they are today (verify with the import test).
- `aeon/internal/handler/registry.go` — the package-level `Lookup/Build/Names/LoadDefinition/Preset/RegisteredBodies`
  delegate to the installed `Source`. **Two implementations ship:** `embeddedSource` (the current `bodyEntries`; used by
  every test that builds no database, and by the **seeder** as its record source) and `rowSource` (production, backed by
  a store adapter supplied at serve). Production calls `SetSource(rowSource)`; **no production path falls back to
  `embeddedSource`** (a silent fallback would reintroduce two truths — SD8).
- `aeon/internal/daemon/handler_source.go` — **new**: the store adapter implementing `handler.Source` (reads
  `Store.Agents…` for `origin='system'` rows; caches **nothing** beyond the call — a seed update must be visible at the
  next dispatch, N8's "no cache" rule).
- `aeon/cmd/aeon/serve.go` — install the row source after the store opens and **after the inert seed** (T6 adds the seed
  call; this task orders the hook so the install happens when the seed has run). CLI verbs that need `Names()`/`Preset()`
  without a database (`aeon blueprint validate`, `aeon handlers`) keep using `embeddedSource` through a **named, documented**
  `handler.UseEmbeddedForOfflineTools()` — a deliberate offline-tool path (listed in Notes), never reachable from `serve`.
- **Custom agents (SD7):** `Lookup` for a slug whose row has `origin != 'system'` returns `(Handler{}, false)` and the
  dispatcher's refusal sentence names it: *"agent `<slug>` is a custom agent and is not dispatchable yet"*. A system row
  that fails `FromRow` refuses with the `*Reject` text.
- **Missing row:** a first-party name with no row at dispatch → refusal *"agent `<name>` is not seeded — run `aeon seed
  apply`"*; **never** a fallback.
- The 9 consumer sites change **only if their signatures need it** (T0's inventory says which); behaviour identical.
