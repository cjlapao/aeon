# T6 · The daemon doors: startup apply, `seed.*` methods, the read-only tool, the guards

**Prefix:** SD · **Rules:** SD5, SD10 · P34 · **Depends on:** T3, T5.

## Goal

Wire the engine into the daemon: **inert sets apply at start (after migrations, before loops are accepted)**; the four
`seed.*` methods exist on the socket (reads open, writes human-door); a read-only `seed_status` tool exists; and the
boundary is pinned by guards with canaries. Includes the bridge `seed.Repo` ↔ `internal/store` and the one shared instance.

## Behaviour

1. `seed.status {set?}` and `seed.plan {set, keys?}` are reads: **zero writes** (spy-pinned). `seed.apply {set, keys?}` and
   `seed.restore {set, key}` take the actor from `table.ActorFor`, never params (`DisallowUnknownFields`).
2. **`seed.apply` is the explicit path** (`via=explicit`); it may apply `guard` sets (none exist in this slice — the
   mechanism is exercised by a fake guard set in tests; S45 declares the first real one). It returns per-record
   `{key, op, fromVersion, toVersion, reason}`.
3. **The startup path cannot reach a guard set** — T3's behavioural and structural tests are re-asserted *through the
   daemon*: a daemon built with a fake guard set declared **does not apply it at start** and `seed.status` shows it
   `absent`; applying it requires `seed.apply`.
4. A `seed.apply` for a guard set returns, in addition to the result, `requiresConfirmation:false` — the **confirmation
   is a UI/CLI concern** (SD11); the daemon does not pretend a socket can prove a human is present (S45 PM7's stance).
5. `seed_status` is the only seed tool; **no tool applies or restores**.

## Guards (siblings in `cmd/aeon/seed_guard_test.go`, with canaries)

`TestSeedWritesAreAHumanDoor`: positive — the four methods registered when the service is wired, `RequiresInitialize`, not
`Debug`; absent (V13) when nil. Negative, one subtest per door — `narrow.Actions()` names no `seed.apply/restore`;
`protocol.AgentServiceMethods()` none; `tools.Registry()` names no `seed_apply/seed_restore`; `records.Catalog()` has no
`Mutates:true` seed spec; text grep: `"seed.apply"`/`"seed.restore"`/`MethodSeedApply/Restore` appear in no non-test file
under `internal/narrow`, `internal/agentsvc`, `internal/tools`, `internal/records`. `TestSeedGuardsHaveTeeth`: a canary
feeds each predicate a synthetic violation and asserts each is reported. `TestStartupSeedNeverReachesAGuardSet`
(daemon-level, with a fake guard set). **Extends, never edits,** D4's existing policy guard
(`authoredRecordCall`) — T0 recorded its body hash; a sibling asserts it is unchanged.

## Definition of done

- [ ] Inert sets apply at start before loops; failures visible, start not aborted; one log line per set.
- [ ] Four `seed.*` methods (conditional), reads read-only, writes human-door peer-stamped.
- [ ] `seed_status` is the only tool; counted bump; not granted.
- [ ] The guards (with canaries) pass; the D4 guard untouched and proven unchanged.
- [ ] Fixtures, handshake, `contract.ts` current; the pre-existing red set unchanged.

## Do NOT

- Do not make startup apply any `guard` set, ever; do not add a flag that makes it so.
- Do not accept an actor in params or stamp a placeholder.
- Do not add a tool that applies or restores; do not mount a seed write on the narrow surface or agent services.
- Do not abort daemon start on a seed failure, and do not hide it either.
- Do not edit an existing guard test body.
