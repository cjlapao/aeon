# T3 · The engine: apply, plan, status, restore — classes, divergence, retirement

**Prefix:** SD · **Rules:** SD2, SD3, SD5, SD6, SD9, SD10 · **Depends on:** T1, T2.

## Goal

Join T1's pure decisions to T2's storage: an `Engine` that reads the ledger and live fingerprints, plans, and applies each
record **atomically with its ledger and audit rows**, enforces the inert/guard boundary, never clobbers an operator's
choice, and reports status. Tested against an in-memory fake `Repo` and a fake `Applier` (no SQLite); T4 proves the
same against the real store and a real domain.

- `engine.go` — `Repo`, `Engine`, `NewEngine`, operations.
- `engine_test.go`, `engine_class_test.go`, `fake_test.go` (fake repo/applier with a call log and injectable failures).

type Repo interface {                                   // implemented by internal/daemon over internal/store (T6)

## Behaviour

1. **`Status`** = for each set: available `Set.Version`, applied max version, per-record `{key, state, availableVersion,
   appliedVersion}`; states come from T1's `Plan` over live fingerprints (`Applier.Fingerprint` inside a read tx). A set
   with no ledger rows is wholly `absent`. Never writes.
2. **`Plan`** returns `Plan`'s decisions plus any `Refusal`; never writes; identical to what `Apply` would do on the same
   state (a property test: plan-then-apply on a deterministic fake equals apply alone).
3. **`Apply`** — per record, in key order, **each in its own transaction** (`WithTx`): `Applier.Upsert(tx, record, adopt)`
   → `PutLedger(applied, version, hash(record.Content))` → `InsertEvent(op, from→to, reason, actor)`; a failure rolls back
   that record only and marks it `failed` **in a second, separate transaction** with the error text (≤ 512), so one bad
   record never blocks the set and is visible in `status`. A `Refusal` (downgrade) fails the **whole apply before any
   write** with the sentence. Skips write an audit event only when the *state is news* (first time `diverged`/`removed` is
   seen, or the skip reason changed) — a no-change re-apply writes **zero** rows (idempotence is observable).
4. **Class gate (SD5, the headline invariant).** `Apply` takes `via Path`. `via=startup` **refuses any set whose Class is
   `guard`**, returning an error that names the set and says guard sets are human-door only; `ApplyInert` iterates the
   registry and applies **only `inert`** sets, with `via=startup` and actor `system:startup`. There is no code path from
   `ApplyInert` to a guard set; a structural test enforces it (below).
5. **Restore** applies `PlanRestore`: only for a record in state `removed`/`diverged`/`retired`; re-applies the code
   version over the live row (for `diverged`, the Applier overwrites — that is the explicit consent `restore` is);
   writes `op=restore`. Restoring an `applied`/up-to-date record is a no-op with a reason.
6. **Adoption (SD9).** When `Plan` says `adopt`, `Upsert` is called with `adopt=true`; the engine records `op=adopt`.
   A conflict (same key, not adoptable) is a `skip` with the conflict reason and **no** write.
7. **Operator rights (SD6).** The engine reads `Applier.Operator()` only to *explain* skips in `status`/`plan`; enforcement
   of "may an operator edit/remove this row" stays in each domain (SD4).
8. **Actor** must be non-empty (an unattributed seed is refused); `ApplyInert` supplies `system:startup`.
9. **No global state, no goroutine, no timer**; `Now` is injected.

## Definition of done

- [ ] `Status/Plan/Apply/Restore/ApplyInert` over the `Repo`/`Applier` seams, tested against fakes.
- [ ] Per-record atomicity incl. `failed` marking; idempotence observable as zero writes.
- [ ] The class gate is behavioural **and** structural; downgrade refused before any write.
- [ ] Never overwrites diverged/removed; restore is explicit; retire never deletes; adoption keeps identity.
- [ ] Stdlib-only still holds for the package.

## Do NOT

- Do not give the startup path any route to a guard set, now or "for convenience".
- Do not auto-restore, auto-delete, or auto-overwrite a diverged row.
- Do not catch and hide a record failure; it becomes `failed` state, visible.
- Do not import `internal/store`; the daemon bridges (T6).
