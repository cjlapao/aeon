## The migration drills (two migrations)

1. **Fresh apply:** a new temp store — ledger/audit tables, triggers, the six agent columns exist.
2. **Upgrade from S43's vintage:** a store seeded with S43's stub first-party rows (use the pre-T4 `agent.migrate`
   output) → open with the new binary → migrations apply; `origin` backfilled (`internal=1`→`system`); run the seed:
   every stub **adopted** (identity unchanged, content filled, ledger `adopt`); a planted `internal=0` row with a
   first-party slug is reported as a **conflict** and untouched.
3. **Idempotent re-open and re-apply:** no second migration; second `seed apply` writes nothing.
4. **Append-only:** `UPDATE/DELETE seed_event` fail.
5. **Rollback is not offered** (forward-only); recorded.
6. **Row counts of unrelated tables** (`policy`, `loop`, `plugin_agent`) unchanged across the upgrade.
