# T8 · The "System records" panel in Settings

**Prefix:** SD · **Rules:** SD5, SD6, SD10, SD11 · P34 · **Depends on:** T6. Parallel-safe with T7.

## Goal

A person can see **what the app ships** and whether it is current: every seed set with its class, available vs applied
version and per-record state; plan, apply and restore from the app, with a guard-set confirmation that names what it
permits. Descriptor-driven from `seed.status`: no set id, record key or sentence is hardcoded. A panel on the real
Settings screen (not a bench page).

## Behaviour

1. `seed.status` via `useRpcQuery`; error ⇒ `ErrorPanel`; **empty registry** ⇒ `EmptyState` "No system records are
   declared yet." (never a blank panel).
2. One **card per set**: id, a class `Pill` (`inert`/`guard`, text + colour), available vs applied version, counts by
   state, and a status line — `Up to date` / `N behind` / `N removed` / `N diverged` / `N failed` — each distinct.
3. **Expand** to the record list: key, state pill, versions; every non-`applied` record shows the daemon's **reason**
   verbatim. `failed` records show the error text in an `Alert`.
4. **Plan** (button): `seed.plan` → `SeedPlanDialog` lists decisions (op, key, from→to, reason). Read-only.
5. **Apply:** for an **inert** set, one click after the plan is shown → `seed.apply`. For a **guard** set, `useConfirm`
   first, text composed from the **plan and the set's description fields the daemon sends** (record keys and ops — no UI
   prose about what it permits beyond what the daemon returned), naming the count and `guard`; decline sends nothing.
6. **Restore** (per `removed`/`diverged`/`retired` record): confirm with the reason ("replaces local changes with
   version N") → `seed.restore`. Disabled for up-to-date records.
7. After any write, **replace the card from the response/`seed.status`**, never optimistically; refusals show the
   daemon's sentence inline and restore the control.
8. `live.state !== 'current'` ⇒ writes disabled with the kit's reconnecting affordance; reads still render last data.
9. No `localStorage`; no `fetch`; no client-side version comparison (the daemon sends the states).
