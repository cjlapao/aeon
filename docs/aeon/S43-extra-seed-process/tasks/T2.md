# T2 · The ledger and audit tables, and the store's SQL half

**Prefix:** SD · **Rules:** SD3, SD4 (origin is each domain's, not here), SD10 (audit) · **Depends on:** T0 (trigger-parsing answer, error-block). Parallel-safe with T1.

## Goal

Persist what the engine needs — the **ledger** (what was applied, at which version, hash and by whom) and the
append-only **audit** — with SQL only in `internal/store` (invariant I2), and transactional accessors so a domain row and
its ledger row commit together.

## Files

- `aeon/internal/store/migrations/<14-digit>_seed_ledger.sql` — **new**; timestamp from `date +%Y%m%d%H%M%S`, after the
  newest file T0 recorded; **no `schema.go` edit**. First line is the `Description`.
  ```sql
  -- S43-extra T2: the seed ledger (what the seed process applied, per set and record) and its append-only audit. The domain rows live in their own tables with origin='system'; the ledger is the engine's memory of versions and hashes so status can say what is out of date, removed or diverged. seed_event is append-only by trigger (the setting_event precedent).
  CREATE TABLE seed_ledger (
    set_id          TEXT NOT NULL CHECK (length(set_id) BETWEEN 3 AND 64),
    record_key      TEXT NOT NULL CHECK (length(record_key) BETWEEN 1 AND 128),
    applied_version INTEGER NOT NULL CHECK (applied_version >= 1),
    applied_hash    TEXT NOT NULL CHECK (length(applied_hash) = 64),
    state           TEXT NOT NULL CHECK (state IN ('applied','removed','diverged','retired','failed')),
    applied_at      TEXT NOT NULL,
    applied_by      TEXT NOT NULL CHECK (length(applied_by) BETWEEN 1 AND 256),
    PRIMARY KEY (set_id, record_key)
  );
  CREATE TABLE seed_event (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    set_id       TEXT NOT NULL,
    record_key   TEXT NOT NULL,
    op           TEXT NOT NULL CHECK (op IN ('apply','update','skip','restore','retire','adopt')),
    from_version INTEGER,
    to_version   INTEGER,
    reason       TEXT NOT NULL CHECK (length(reason) <= 512),
    actor        TEXT NOT NULL CHECK (length(actor) BETWEEN 1 AND 256),
    occurred_at  TEXT NOT NULL
  );
  CREATE INDEX idx_seed_event_set ON seed_event (set_id, record_key, id);
  CREATE TRIGGER seed_event_no_update BEFORE UPDATE ON seed_event
  BEGIN SELECT RAISE(ABORT, 'seed_event is append-only (S43-extra SD3)'); END;
  CREATE TRIGGER seed_event_no_delete BEFORE DELETE ON seed_event
  BEGIN SELECT RAISE(ABORT, 'seed_event is append-only (S43-extra SD3)'); END;
  ```
  No FK to any domain table (the ledger is domain-agnostic; a domain row can vanish and the ledger still says
  `removed`). If the migration parser cannot carry a trigger body (T0 item 4.4), use S44 T1's documented fallback
  (no update/delete accessor + a package grep test) and say so in the description line.
- `aeon/internal/store/seed.go` — **new**, SQL only, parameterised:
  ```go
  type SeedLedgerRow struct { SetID, RecordKey string; AppliedVersion int; AppliedHash, State, AppliedAt, AppliedBy string }
  type SeedEvent struct { ID int64; SetID, RecordKey, Op string; FromVersion, ToVersion *int; Reason, Actor, OccurredAt string }
  func (s *Store) SeedLedgerList(ctx context.Context, setID string) ([]SeedLedgerRow, error)           // "" = every set; ordered by set, key
  func (s *Store) SeedLedgerGet(ctx context.Context, setID, key string) (SeedLedgerRow, bool, error)
  func (s *Store) SeedWithTx(ctx context.Context, fn func(tx *sql.Tx) error) error                    // one transaction; the domain Applier and the ledger/audit writers share it
  func SeedLedgerPutTx(tx *sql.Tx, row SeedLedgerRow) error                                             // upsert
  func SeedEventInsertTx(tx *sql.Tx, ev SeedEvent) error
  func (s *Store) SeedEventList(ctx context.Context, setID, key string, limit int) ([]SeedEvent, error) // newest first; clamp [1,500], default 50
  ```
  Reuse the store's existing read-then-write transaction idiom (VERIFY the helper: `grep -n 'func (s \*Store) .*[Tt]x' aeon/internal/store/*.go`); do not invent a second.
