# T3 · The steer store (D4)

**Prefix:** LW · **Contract:** [`../brief.md`](../brief.md) §6 T3 · **Code map:** [`../CODEMAP.md`](../CODEMAP.md) §10

## Context

D4 is one of the two that matter: a queued steer is a row (`pending` → `delivered` | `cancelled`), survives a daemon crash, and is delivered **in the same transaction** as the checkpoint that contains it — never delivered twice, never lost. S7's replay then sees either "not delivered" (re-drain) or "in the transcript and delivered" — never both, never neither (LW5).

## What to do

- New table `step_steer(id, step_id FK, text, route, reasoning_effort, state CHECK IN ('pending','delivered','cancelled'), created_at, delivered_at, delivered_iteration)` as a **new numbered migration — 0021**, never an edit to a shipped one. Index on `(step_id, state)`. Bump the pinned count in `schema_test.go` (currently 20) **and** its sentence.
- Store methods on the existing single-writer pattern (`s.w`, `BeginTx`): `QueueSteer`, `PendingSteers(stepID)`, `CancelSteer` (only a `pending` steer; refusing is a **discriminated result** naming the state found, never an `error`), and — the important one — **`CheckpointWithSteers(stepID, messages, deliveredIDs, iteration)`**: writes the transcript checkpoint (same shape as `SaveRunningCheckpoint`, checkpoint.go:13) and marks those steers delivered in **one transaction**.

## Validation

CHECK rejects an unknown state; cancel of a delivered steer is refused (discriminated result); `CheckpointWithSteers` is atomic — inject a failure after the transcript write and assert neither the transcript nor the steer state changed; migration count test updated (both the `!= 20` guard and the sentence). Follow the S7 recovery cases in `docs/aeon/S7-recovery/`.

### Decisions the task file could not make

- **`step_steer` carries three CHECKs, not one.** The spec named the `state` CHECK. Two more are
  here and argued in the migration comment: `ck_step_steer_delivery` ties `delivered_at` +
  `delivered_iteration` to the state that earns them (so a row cannot say `delivered` without being
  able to say *when*, and cannot say `pending` while carrying a timestamp — the disguise the
  double-delivery case wears), and `ck_step_steer_content` refuses a row carrying neither text nor
  route nor effort. Both are D4 at the schema rather than in Go: a rule a future caller can forget
  is a rule the database should refuse.
- **`AllSteerStates()` is the lock, and the test reads the live DDL.** Same shape as §3's policy
  lock: `checkValues` pulls the vocabulary out of `sqlite_master`, and a Go-side list edited in the
  same commit cannot agree its way past it.
- **NULL, not `''`,** for the three optional payloads, per 0003's `question.tool_use_id` and 0020's
  `pause_reason`: "the person said nothing" and "the person did not address the text" are different
  facts, and the runtime has to be able to tell them apart before it decides whether to append a
  message.
- **A steer belongs to the step that queued it, and delivery says so.** `CheckpointWithSteers`
  refuses (as an `error`, rolling everything back) a named id that does not exist or belongs to
  another step — a caller that cannot say what it drained cannot say what it persisted. A named id
  that merely *left* `pending` is not an error: its text is already in the messages the caller is
  committing, so the transaction commits and the row is reported in `NotDelivered` with the state
  found. That is the post-drain cancel race, and it is the only place LW5's "never both, never
  neither" needs an exception-shaped answer.
- **The delivery stamp is write-once.** A checkpoint naming an already-delivered steer leaves the
  original `delivered_at` and `delivered_iteration` standing; `TestASteerIsDeliveredOnceEvenAcrossAReopen`
  pins it with two opens over one directory and two clocks, because a re-stamped timestamp is how a
  double delivery hides.
- **The store does not refuse a non-running step at queue time, and does not enforce LW10's caps.**
  Both belong to `step.steer`'s handler (brief §6 T4), which is the surface that can name the remedy
  (`answer`, `step.continue {message}`) and the bound a person can act on. `CheckpointWithSteers`
  *does* require `running`, mirroring `SaveRunningCheckpoint`'s guard at checkpoint.go:46, because
  that write is a stale goroutine's, not the person's.
- **`step_steer` cascades on step delete** (`ON DELETE CASCADE`), the same choice `tool_receipt`
  made in 0011: a steer outliving its step is a queue nobody drains, and the ledger test
  `TestTheLedgerRecords0021ExactlyOnceAcrossTwoOpens` is what pins the ledger half.

### Deviations, and why

1. **`CheckpointWithSteers` takes a leading `ctx`.** The brief's signature is
   `(stepID, messages, deliveredIDs, iteration)`. The context is what `BeginTx` needs to honour a
   deadline, `SaveRunningCheckpoint` and the runtime's own `CheckpointWriter` (`SaveCheckpoint(ctx,
   …)`, protocol/step.go:204) both take one, and a checkpoint that ignores its step's cancellation
   is a small version of the bug this task exists to prevent. **For T4: pass the step's ctx, and
   pass the iteration the step is about to run** (it is recorded verbatim; a negative one is
   refused).
2. **It returns `CheckpointSteersResult`.** Nothing in the spec'd signature carries the "named but
   not delivered" answer, and T4 needs it to emit `step.steer.delivered` honestly (brief §5's event
   set) and to tell the person which cancel won the race.
3. **`store.go` was edited** (comment only, one block in the surface table). Outside task-3's
   `write_scopes`, and unavoidable: the package's own guard test
   `TestEveryExportedMethodIsNamedInTheSurfaceTable` fails when an exported `*Store` method is not
   named there, so a green suite required the entry.
4. **`policy_test.go` was edited** (three count pins: 307, 454, 1311, all moved from `!= 20`).
   Also outside `write_scopes`, and also forced — those pins assert the current migration count, so
   0021 turns them red unless moved. Each sentence now names `0021 … by S31's steer queue — none of
   them this task's`, following the existing wording. The task file named only schema_test.go's two
   spots; there were five in the package.
5. **`STATUS.md` and `TASKS.md` were not touched.** Several teammates are landing S31 tasks in this
   same tree right now; the slice's record is safer moved once, by whoever closes it (T9's brief
   already carries the §4a obligation).

### What was NOT verified

- **`make ci` was not run end-to-end.** `go build ./...` currently fails in `internal/protocol`
  (`stepSink` arity — T1's in-flight edit), so the module-wide build and the packages that import
  protocol (`daemon`, `cmd/aeon`) could not be checked from here. Everything in this task's scope
  was: `go test ./internal/store/` green (302), `go vet ./internal/store/` clean, `gofmt -l` clean.
  **The next person to touch the store should re-run `make ci` after T1 lands.**
- **No `-race` two-goroutine test of drain-then-cancel.** The state is constructed rather than raced
  (K30's argument: staging an instant is unreliable; constructing it is not), and the single-writer
  pool makes the interleaving deterministic. `concurrency_test.go` covers writer serialisation
  generally.
- **Nothing calls this from the runtime yet.** The API is what T4 calls — `PendingSteers` before the
  model call, `CheckpointWithSteers` at both persistence points — and it has not been exercised
  against `runtime/loop.go`. `TestCheckpointWithSteersWithNoIDsIsAPlainCheckpoint` exists so the
  no-steer turn has one call, not two, which is the shape T4 is meant to use.
- **No cost measurement.** `PendingSteers` runs before every model call and reads through
  `idx_step_steer_step_state`; with LW10's 16-pending bound it is an index seek on a ≤16-row
  partition, and that is a reasoned claim rather than a measurement.
- `checkValues` (schema_test.go:2117) says *"migration 0016 carries no CHECK list"* when it fails.
  It is the right parser for this CHECK and was reused rather than duplicated; the message is now
  slightly wrong for a second user. Cosmetic, recorded rather than fixed.
