# T8 · Rust shell forwards terminal notifications (D10)

**Prefix:** LW · **Contract:** [`../brief.md`](../brief.md) §6 T8 · **Code map:** [`../CODEMAP.md`](../CODEMAP.md) §12, §13

## Context

`session.rs` `handle_frame` (530–565) forwards only `method == "event"`; everything else is logged and dropped. Terminal notifications (`terminal.output`, `terminal.exit` — the shapes T7 publishes) must reach the app as a Tauri event **`aeon://terminal`**, params verbatim, under the same "report a failed emit, never discard it" rule `AppSink` follows (129–148). **No new `#[tauri::command]`** (N7) — the generic `rpc_call` bridge carries every new method (AGENTS §4b).

## What to do

- Add `terminal.output` and `terminal.exit` → emit `aeon://terminal` with params verbatim. Keep an **explicit allow-list**: an unknown notification method is still logged and dropped, never forwarded blindly.
- Mirror `EventSink`'s trait pattern for the terminal sink so the path is testable outside a running app; `AppSink` reports emit failures to stderr, never discards.
- `ui/src/lib/bridge.ts`: a typed `onTerminal(listener)` helper beside `onEvent` (same `subscriber` seam + channel const; **no UI components** — N1).

## Validation

Rust (existing recording-`EventSink` pattern, `ui/src-tauri/tests/`): a frame with `terminal.output` reaches the sink as a terminal event; `event` frames unchanged; an unknown method is dropped and logged. Vitest for `onTerminal` with a mocked `listen`. `make -C ui rust-test` and `make -C ui test` green (note honestly if the Rust arm cannot link on this machine — say what you did not verify).

## Notes

Built 2026-10-24 (shell-rust). N7 honoured: no `#[tauri::command]` added; `rpc_call` untouched.

**Decided (Rust).** The terminal sink is a **required third method on the existing `EventSink`
trait** (`fn terminal(&self, params: Value)`), not a second trait: the trait's own doc is "where
notifications go", and a parallel `TerminalSink` would double the plumbing through
`connect`/`spawn_reader`/`handle_frame` for no added testability. Required, not defaulted to a
no-op, for the AppSink reason — a sink that never decided what it does with terminal output should
not compile. `handle_frame`'s id-less arm is now an explicit `match`: `event` → event sink (verbatim,
the "new event kind needs no Rust change" rule untouched); `terminal.output` | `terminal.exit` →
terminal sink, params verbatim; **anything else — including a frame with no `method` at all — is
`eprintln!`-logged and dropped**. That log is not decoration: the pre-change code *silently* dropped
unknown methods (CODEMAP §12 recorded the intent, the code had not caught up), so a dropped frame
was indistinguishable from one never sent. Measured under `--nocapture`:
`aeon: dropped notification for unforwarded method "daemon.mystery"`.

**Decided (bridge).** `onTerminal` gates on a hand-written `terminalMethodOf` — the allow-list of
brief §5's two **shapes**, since the params arrive verbatim and carry no `kind`; routing them
through `isKnownEventKind` would have swallowed every one (asserted both ways in the vitest).
Consequence for T7: the exit arm admits a frame carrying `exitCode` **or** `signal`; a
`terminal.exit` carrying *neither* is not the published shape and would be dropped, not guessed —
flagged for the T7 build and T9's fixture pass. One stated deviation: `onTerminal` maps a failed
subscription through `listenerUnavailable` **itself**, where `onEvent` leaves that to each page —
N1 means this slice has no consumer to remember the wording, and it makes the three-part error
assertable at the bridge.

**Measured.** `make -C ui rust-test`: **28 passed, 4 ignored** (baseline before this change: 23/4 —
new `tests/terminal_notify.rs` adds 5: output/exit verbatim on the terminal sink, event frames
unchanged + no stream-crossing, unknown method reaches neither sink, method-less frame likewise; it
drives the real `Session`+reader against the `tests/session.rs`-shaped FakeDaemon). The existing
`Recorder`s in `tests/liveness.rs`/`tests/live_stream.rs` grew a recording `terminal` impl (required
method; recording, never silently dropping). `make -C ui test` (vitest): **275 passed across 27
files** (baseline 271/26; new `test/bridge-terminal.test.ts` adds 4). `make -C ui typecheck` clean —
it earned its keep by refusing `toBe`'s non-existent message argument.

**Did not verify.** Tauri's own `emit` onto `aeon://terminal` (an `AppHandle` cannot be built
outside a running app — the same one untested hop every channel in this file has, one hop, not
three); and no **real daemon** has ever put a terminal frame on the wire — T7's publisher is
unbuilt at time of writing, so the frames are fake-daemon-pushed. The webview side is asserted
against the mocked subscriber only. The drop **log** is `--nocapture`-eyeballed, not in-test
asserted (integration tests cannot read their own stderr in-process); the security half — neither
sink receives it — is asserted.
