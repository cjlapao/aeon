# T6 · Git status and diff (D7, D8)

**Prefix:** LW · **Contract:** [`../brief.md`](../brief.md) §6 T6 · **Code map:** [`../CODEMAP.md`](../CODEMAP.md) §8, §9

## Context

Three-state honesty (P31, D7): `workspace.git.status` answers `ok` (branch, upstream, ahead/behind, changed paths with status) | `not-a-repo` | `unavailable` (with the reason) — **never a reassuring empty list for "could not tell"**. Read-only, through the bounded process layer (LW11): `git status --porcelain=v2 --branch -z` and `git diff` via `tools.Run`-style bounded execution (timeout ~5 s, output caps reported). S16 later owns git *actions* and may absorb these reads.

## What to do

- New `internal/workspace` (plain package): `GitStatus(ctx, root)` and `GitDiff(ctx, root, path)`. Parse porcelain v2 with `-z` (paths with spaces/newlines). `git` missing → `unavailable: "git is not installed"`; not a repo → `not-a-repo`; timeout → `unavailable` naming the timeout.
- `workspace.git.diff` → unified diff for one path (working tree vs HEAD; untracked files as synthesised all-added; binary → `binary: true`, no body; capped ~512 KiB with `truncated: true` reported).
- Socket handlers `workspace.git.status` / `workspace.git.diff`: `projectRoot` must be a **registered project root** (`project.list`) — anything else refused with the path named; diff paths go through the same resolver as `loop.file.read` (`tools.Resolve`) — no escaping the root.
- Registered refusals name the thing refused and the reason (I4), discriminated results (DB19).

## Notes

**Built 2026-10-24 (solo pass).**

- **The parse layer was inherited from a stopped teammate** (`internal/workspace/git.go` +
  `git_test.go`, 1269 lines, uncommitted) and **audited line by line** before adoption: it
  covers the full validation list — porcelain v2 `-z`, modified/added/deleted/renamed(with
  `origPath`)/untracked, detached HEAD, ahead/behind over two local repos (one bare-as-remote),
  not-a-repo, spaced paths, huge-diff truncation with the true `BodyBytes`, NUL-sniff binary,
  fake-`PATH`-without-git → `unavailable: "git is not installed: …"`, and timeout → group-kill
  (spawn.go's lesson: `exec.CommandContext` kills only the process). It was already three-state
  by construction: **every unparseable fact is `unavailable`, never a skipped line** — unknown
  record types, malformed `ahead/behind`, a rename missing its NUL-continued `origPath`, and a
  truncated listing all answer `unavailable` rather than rendering short. Adopted as-is; no
  parse changes.
- **New: the two doors.** `protocol.Table` gained three seams — `ProjectRootKnown` (shared
  with T7's terminals: both open only on `project.create`-registered roots; an unreadable
  registry CONFIRMS NOTHING, the door stays shut), `GitStatus`, `GitDiff`. Protocol stays
  pure: `os/exec` is named in `import_test.go`'s forbidden list and the resolver's package is
  off-limits too, so resolution happens once in the daemon adapter (`tools.Resolve`, same
  door `loop.file.read` bounds through) and an escaping path comes back as `ErrBadParams`
  naming the path — which the handler passes through untouched.
- **States are answers; errors are about who may ask.** `not-a-repo`/`unavailable`+reason
  arrive as *successful responses* (the daemon asked git and git answered — asserted on the
  wire). Only two things are errors: `ErrProjectRootUnknown` (-31524, the path named, I4) and
  `ErrGitUnavailable` (-31523, no reader wired — guessing is the one answer it may not give).
  Both got conformance fixtures; the skeleton's `conformance/workspace/{git-status,git-diff}.json`
  pin the wire shapes and pass against the real handlers' types (the "?" / "U" untracked
  convention is what the status fixture pins).
- **P31 as data, asserted at the socket**: pointer fields — no upstream means `ahead`/`behind`
  are ABSENT, not zero; a `not-a-repo` answer carries no `changed` list; the `ok` clean case
  carries an empty list (it claims it saw the tree and found it clean).
- **XY codes ride verbatim** — an unstaged modification is `{"index":".","worktree":"M"}`
  (a daemon-wire test learned this the honest way when my first expectation said `"M"`).
- **Not covered here:** the CLI verbs for git reads (the brief asks for none — the ladder
  consumes the socket); real-remote network state (ahead/behind tested over local file remotes,
  per §5's "never a real repository").
