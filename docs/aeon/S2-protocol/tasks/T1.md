> ## Notes — done 2026-10-15
>
> ### Q1 · the transport exists. **The slice is not blocked.**
>
> `framework/localrpc`, at `framework/v0.10.1`. It is a **service, not a `net.Conn`** — it owns the
> listener, the framing and the dispatch, and a consumer registers handlers:
>
> ```go
> type Handler func(ctx context.Context, params json.RawMessage) (any, error)
>
> Register(method string, h Handler) error   // errors on a duplicate method
> Notify(connID, method string, params any) error
> Connections() []ConnInfo
> EndpointPath() string
> Ready() bool
> Shutdown(ctx context.Context) error
> ConnIDFromContext(ctx) (string, bool)
> ```
>
> Three facts from reading it that the rest of the slice is built on:
>
> - **The handler's `ctx` IS the connection's**, cancelled when the client disconnects
>   (`conn.go`: `ctx, cancel := context.WithCancel(s.ctx)`, and `close()` cancels before closing the
>   socket). **This is the teardown hook T3/T5/D6 need** — there is no close callback, so a reaper
>   goroutine parked on `ctx.Done()` at `initialize` is how a connection's subscriptions are reaped.
> - **`Notify` to a closed connection returns `nil`**, not an error. The race T3 step 3 worries about is
>   already resolved in the transport, so nothing here has to handle it.
> - `Register` **must be called after `svc.Start`**, or it fails `localrpc: service is not running` (S1).
>
> ### Q2 · it already speaks JSON-RPC 2.0. **So Q4 is moot: no library was added.**
>
> Newline-delimited frames, envelope validated, `id` echoed verbatim, notifications unanswered, panics
> recovered as `-32603`, batches refused whole with `-32000`. The transport also owns eight codes:
> `-32700 -32600 -32601 -32602 -32603` plus `-32002` not-ready, `-32001` connection-limit,
> `-32000` batch-unsupported.
>
> ### The error table — five codes, banded
>
> | Code | Name | Fatal | What it means |
> | --- | --- | :--: | --- |
> | `-31001` | `ErrNotInitialized` | **yes** | a method before `initialize` (T7) |
> | `-31002` | `ErrProtocolVersionUnsupported` | **yes** | negotiation refused, either direction, naming both numbers |
> | `-31003` | `ErrAlreadyInitialized` | no | a second `initialize` would change the version under a live subscription |
> | `-31010` | `ErrInvalidFilter` | no | a wildcard that is not one trailing `*` (O1) |
> | `-31011` | `ErrSubscriptionLimit` | no | the per-connection or total bound (O4) |
>
> **Bands**, so later slices cannot collide: `-31001–09` session · `-31010–19` subscriptions ·
> `-31020–99` reserved protocol-level · `-31100+` domain, allocated by the slice that needs it.
>
> **`-31004` is deliberately left unallocated**, with a test enforcing it. The design's §Errors
> illustrates the three-part shape with `-31004: no pending question` — that is an illustration inside a
> JSON blob, not an allocation, and questions arrive at S6 from the domain band. Leaving the number free
> means the two can never be confused by someone reading the design later.
>
> ### Two deviations, both recorded rather than silent
>
> **1. The invariant tests tokenize; they do not grep.** The task says "asserted by grep". Both guards
> were written that way first and both cried wolf immediately: `import_test.go` names every forbidden
> import by definition, and `types.go`'s own doc comment explains that nothing calls
> `DisallowUnknownFields` — which a text search reads as a call to it. The usual repair is to weaken the
> pattern until it matches nothing, and then the invariant is unguarded and nobody knows. So imports are
> checked by parsing the import list, and identifiers by `go/scanner`, where a comment is not a token.
> **Both were verified with a negative control** — a file that imports `net` and calls
> `DisallowUnknownFields` — which fails both tests; it was then deleted. A guard nobody has watched fail
> is not a guard.
>
> **2. `negotiate(want, min, max)` is a pure function under `Negotiate(want)`.** Today
> `MinSupportedVersion == PROTOCOL_VERSION`, so through the real constants the *serve-an-older-version*
> branch is unreachable — and that branch is the entire difference between version negotiation and
> version checking. Tested through the constants it would be a `t.Skip`, and a skipped test is not a
> passing one. With the bounds injected it is exercised for real at `min=1,max=2`, six cases, years
> before the first bump makes it live.

## Context

Two jobs, both of which must happen before any method exists.

**First, the question that can stop the slice.** The socket transport is `go-backend-scaffolding`'s (N1). Read
what it actually offers — a `net.Conn`, a framed message stream, or a request/response callback — and quote the
interface in this task's notes. **If it does not exist, stop and report the slice blocked.** Do not implement
one: that duplicates the thing §1a says is built elsewhere, and it would be discovered only when someone tried
to run the demo.

**Second, the two cross-cutting rules.** Both are retrofitted at the cost of revisiting every handler, so they
land before there is anything to revisit.

The **error table is enumerated in full**, not grown a code at a time. D9 asserts over the whole table, so a
code added at S9 without its three parts fails a test written now — which is the point. And a code is **never
reused for a different meaning**, even after the method that produced it is removed: reuse breaks the promise
years later, when nobody remembers the first meaning.

**Read first:** the scaffolding's transport (Q1, Q2); `docs/_archive/aeon-v1-horizontal/13-cli/tasks/T2.md` for C9's
three-part error shape; the JSON-RPC 2.0 specification for its reserved code ranges.

## What to do

**1. Answer Q1 and record it.** The transport's interface, quoted. Then Q2: does it already speak JSON-RPC or
only frame messages? If the former, this slice consumes it rather than adding a library (Q4).

**2. `version.go`** — `PROTOCOL_VERSION` as an `int`, starting at 1, and **the additive/breaking rule as a doc
comment directly beside it**:

> Additive, does not bump: a new method; a new **optional** field; a new event kind; a new capability; a new
> error code.
> Breaking, bumps: removing or renaming a method or field; making an optional field required; changing a
> field's type or meaning; changing an error code's meaning; changing `seq` semantics.

The rule lives next to the constant because that is where someone about to change it will be.

**3. `errors.go`** — the Aeon range `-31000`–`-31999`, every code allocated in **one** place (I2), each with
its `what`, `means`, `todo` and `fatal`. Enumerate the full initial table (Q10). Include a `//` note on the
range that JSON-RPC's own codes are reserved and must not be reused.

**4. `types.go`** — the request and result types for the five methods, all in this one file (I4). The
fixtures in T5 are tested against these.

**5. Import nothing transport-related** (I1, D11). No `net`, no listener, no scaffolding transport package.
Assert it by grep in the test — it is the invariant whose breach is invisible, because everything works and
S19 then cannot mount the same table on HTTP and stdio.
