> ### The staleness check (Q9): hand-written, with coverage asserted
>
> Not generated. Three tests — every method, every error code, every event kind — and each was **verified
> with a negative control**: deleting a fixture and watching the right test fail.
>
> **One of those controls found a real hole.** Removing `ping/ok.json` failed nothing, because
> `errors/not-initialized.json` also names `ping` (it documents calling ping too early). The check now
> requires a **success** fixture per method: a method whose only fixture is an error fixture has no stated
> happy path, which is what a third-party client needs most.
>
> ### Semantic comparison, and the correction that mattered
>
> First version required every field a fixture states to appear in the Go output. **`forward-compat.json`
> failed it** — the fixture carries `featureWeHaveNotWrittenYet`, the Go type does not know it, and the
> re-marshal drops it. Demanding the Go side reproduce it would have required keeping a field it has never
> heard of, which is the opposite of T3, and would have made the one fixture that proves additive evolution
> impossible to pass.
>
> So comparison is over the **type's own JSON field names**, by reflection: a field the type declares and
> the fixture states must match; a field the fixture states and the type does not know is ignored, because
> tolerating it *is* the contract. With a guard against the degenerate case where nothing matches at all —
> which is how a renamed json tag would otherwise slip through green.
>
> ### What the README carries beyond the rules
>
> The two `seq` numbers, which is the thing most likely to be got wrong by someone implementing this from
> the fixtures alone.

## Context

**The fixtures are what make this protocol real for anyone who is not us.**

Aeon's own client and the daemon can agree with each other while both being wrong about the specification —
they share a codebase, a set of assumptions and an author. The third-party clients this protocol exists for
will not use Aeon's client library: a VS Code extension in TypeScript, the Tauri shell in Rust, and whatever
somebody else writes.

So the contract is a committed set of JSON request/response pairs (T9). Codegen is deferred with a named
trigger — a third client, or the first drift bug — because generated types are convenience and can still be
used wrongly, while a fixture is a fact about the wire.

**One fixture matters more than the rest**: the one containing a field no current code knows. It is the
standing proof that additive evolution works (D3, T3), and it is the file a future contributor will be tempted
to "fix" because it looks like a mistake. Its README entry should say why it is there.

**A fixture set nobody regenerates goes stale**, so name the check that catches it and run it in CI (Q9).

**Read first:** `types.go` (T1) — the fixtures are tested against these types; the full error table from T1;
`conformance/README.md`'s purpose as stated in the design.

## What to do

**1. `conformance/` layout** — one directory per method, each with named request/response pairs as JSON:
`initialize/ok.json`, `initialize/version-too-new.json`, `subscribe/filtered.json`, and so on.

**2. Cover every method and every error code.** Every code in T1's table gets a fixture, because a code
without one is a code no third-party client can implement against.

**3. The forward-compatibility fixture** — a request carrying `somethingFromTheFuture` and a response
carrying an unknown field, both of which must be accepted. Name it clearly (`forward-compat.json`) and say in
the README that removing it removes the only standing test of T3.

**4. `conformance_test.go`** — every fixture round-trips: the request parses into the Go type, the handler's
result matches the expected response. Compare **semantically**, not by byte equality: key order in JSON is not
part of the contract and asserting on it makes every formatting change a failure.

**5. The staleness check** (Q9). Either generate the fixtures from the Go types and assert the committed copy
matches, or hand-write them and assert every method and error code has one. Both work; say which, and run it
in CI.

**6. `conformance/README.md`** — state that this directory **is the contract** the Rust and TypeScript clients
test against, that key order is not significant, and why `forward-compat.json` must not be deleted.
