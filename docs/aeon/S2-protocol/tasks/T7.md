## Context

S1's app showed the daemon's version. This one shows the **negotiated protocol version**, which means the
Rust shell now performs a real handshake rather than a single call.

**The test that matters is the negative one**: no protocol number while disconnected. A number present with
the daemon down means the app is displaying a build-time constant and the negotiation it claims to have done
never happened — and that would pass a naive check while the whole protocol layer was broken.

**The Rust shell is still the only thing touching the socket.** A browser cannot speak a unix socket, which is
why the Tauri shell is the UI rather than optional packaging. The web layer calls Tauri commands; if the web
layer ever imports a socket library, something has gone wrong.

**The app gains no other capability.** No loop list, no chat, no settings. Those are S9. This task exists so
that when S9 arrives, the handshake, the connection lifecycle and the Rust/TS boundary are already known
quantities rather than three simultaneous unknowns.

**Read first:** `aeon/ui/` as S1 left it; `internal/protocol/client.go` (T6) for the handshake the Rust side
must mirror; the fixtures (T5) — the Rust side should be testable against the same JSON.

## What to do

**1. `protocol.rs`** — dial the socket, `initialize`, hold the negotiated version, and expose two Tauri
commands: connection state, and the negotiated versions.

Perform `initialize` **first** (T7). Assert it on the wire in a test, not by reading the code.

**2. Three connection states** — *connecting*, *connected* (with both versions), *disconnected* (with the
socket path it tried). Three rather than two, because a two-state UI lies while the daemon is starting.

**Show the path it tried** in the disconnected state. It is the first thing anyone debugging needs.

**3. `App.tsx`** — render the state. `Aeon 0.1.0 · daemon: connected · protocol 1`.

**4. Test against a fake returning an unexpected version** — if the app shows the expected one, it is
displaying a constant. That is the whole point of the test, and it is why the fake returns something the code
could not have guessed.

**5. Test the disconnected case asserts the absence of a protocol number**, not merely the presence of a
disconnected label.
