## Context

`DEMO.md` was written from the design, before the code. Every stated output is a prediction, and predictions
about your own software omit the step you do without noticing.

**This demo has a property worth preserving: several steps are raw `nc -U` requests.** That is deliberate. A
demo driven only by Aeon's own client proves the client and the daemon agree — which they would even if both
misread the specification, since they share a codebase and an author. The third-party clients this protocol
exists for will not use Aeon's client library, so the demo speaks to the daemon the way they will.

**When a step does not match, record which was wrong.** Editing the demo is faster than fixing the code and is
therefore the default, and a demo silently adjusted to match a bug is worse than no demo.

**Read first:** `DEMO.md` in full; `docs/test_suites/aeon-bootstrap.md` (S1) for the suite format and case-id
convention; the brief's §2.

- `seq` resetting on restart, confirming the documented limitation is real
