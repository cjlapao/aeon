# T4 · "To whom": the pure grants function, the shared `GrantedSet`, and the differential tests

**Prefix:** TC · **Rules:** TC5, TC4, TC9 (scoping inputs) · **Depends on:** T1 (core half); the policy half uses S45's/S10's reads and the MCP half S46's seam (T0 records what has merged; each half is testable with fakes before its neighbour lands).

## Goal

One pure function answers "can agent A call tool T, and if not, why" — with the **same evaluator** the gate uses and the **same grant logic** `BuildToolset` uses — and a **differential test** proves it equals both
for every (tool, agent) pair in the fixtures. Everything the read methods (T5), agent tools (T7), CLI and UI show about grants comes from this one function.

## Files

- `aeon/internal/tools/granted.go` — **new, tiny, behaviour-preserving extraction**: `func GrantedSet(granted []string) (names []string, err error)` = the grant-list handling `BuildToolset` performs today (unknown name ⇒ the same error text; alias dedupe via `CanonicalToolName`, SEC-051; order preserved), **and `BuildToolset` is changed to call it** (T0 item 5 recorded the exact logic and the characterization tests; **those tests are committed first and must stay green untouched**). This is the only edit to an existing `internal/tools` file besides adding `granted.go`; record the diff in Notes.
- `aeon/internal/toolcatalog/` — **new** package, pure:
  ```go
  type State string // "not_granted" | "granted_allowed" | "granted_ask" | "granted_denied" | "granted_no_rule"
  type Entry struct { Tool, Agent string; State State; Reason string; GrantedBy []string /* "default","handler","mcp-declare" */ ; Dispatchable bool }
  type Inputs struct {
      DefaultGrant []string
      AgentGrants  func(agent string) (granted []string, dispatchable bool, ok bool)   // the agent row's tools allow-list; custom agents ⇒ dispatchable=false
      MCP          MCPView                                                            // seam: per-agent MCP tools + core narrowing + GrantView (supplied by cmd/aeon)
      Policies     []policy.Policy
      At           time.Time
  }
  func Effective(tool, agent string, in Inputs) Entry
  func ForAgent(agent string, tools []string, in Inputs) []Entry
  func ForTool(tool string, agents []string, in Inputs) []Entry
  func PoliciesTouching(tool string, ps []policy.Policy) []policy.Policy   // tool_access rows whose spec toolName canonicalises to the tool, plus all-agents/lane-type rows that match
  ```
  **Semantics:** `not_granted` if the tool is not in the agent's granted set (`GrantedSet(default ∪ agent allow-list)`; for MCP tools: not declared/narrowed per the MCP view). Otherwise the state comes from **`policy.Evaluate(Policies, Request{Type: ToolAccess, Agent, Tool}, At)`**: `Allowed ⇒ granted_allowed`, `Asked ⇒ granted_ask`, `DefaultDeny ⇒ granted_no_rule` (reason = the MC10/PL5 sentence the existing code uses), `!Allowed ⇒ granted_denied`; `Reason` = the verdict sentence **verbatim** (`Verdict.Sentence()`), never reworded. An MCP tool takes the S12 `GrantView` state through the MCP view (it already folds policy + effect-ask) — mapped 1:1 (`available→granted_allowed`, `ask`, `unavailable→granted_no_rule`, `refused→granted_denied`). `GrantedBy` lists the sources that grant it. No I/O, no clock (`At` injected), no store.
- `aeon/internal/toolcatalog/*_test.go`, fixtures.
- **No edit** to `internal/policy`, `internal/mcp`, `internal/runtime`.

## The differential tests (the headline proof)

`TestEffectiveEqualsTheGateForEveryPair`: build a fixture policy set (allow/deny/ask rows across `agent`, `all-agents`, `lane-type` targets, an expired row, an `ask`), a fixture agent set (system agents with differing allow-lists; a custom non-dispatchable agent), and **for every (registry tool × agent)** assert `Effective(...).State` matches `policy.Evaluate`'s verdict for the identical `Request` — including canonical-name handling (`write_file` vs `write`). `TestGrantedSetEqualsWhatBuildToolsetBuilds`: for every agent's grant list, `GrantedSet` names equal `Toolset.Granted()` of a real `BuildToolset` over a stub `ToolContext` (and the unknown-name error text is identical). `TestMCPStatesMapOneToOne` over S12's fixture configs. A **property test** (seeded RNG, 500 random policy sets) asserts monotonicity facts the engine promises (a `deny` row never yields `granted_allowed`; adding an `allow` for an already-denied tool cannot flip it — PL4), so the catalog can never disagree with the evaluator's own laws.

**Deviation, and it is the task's own contradiction.** The Files section described `GrantedSet` as doing "alias
dedupe via `CanonicalToolName`, SEC-051", while the Tests section demanded
`TestGrantedSetEqualsWhatBuildToolsetBuilds`: "`GrantedSet` names equal `Toolset.Granted()`". Both cannot be true,
because `BuildToolset` **keeps both spellings** (`byName` must answer to either and `Granted()` is the author's
list; the SEC-051 dedupe is `Specs()`', "first granted spelling wins the slot" — toolset.go:289-308, and T0 item 5
recorded exactly this before the code was touched). The test is the load-bearing half: a deduping `GrantedSet` is
the disagreement TC5 forbids. So `GrantedSet` is the byte-preserving extraction and the dedupe is its own named
step, **`CanonicalGrant`** — same rule, first spelling wins, `TestGrantedSetEqualsWhatBuildToolsetBuilds` and the
characterization both green.

**Three behaviours the tests found, not the tests were told.** Each was a package bug, fixed in the package:

1. A non-dispatchable (custom) agent's `Reason` survived the downgrade to `not_granted`, so the panel would have
   shown "refused: … default deny (PL5)" about a call that can never exist. SD7 now clears the reason with the
   state and keeps `GrantedBy` — the list is a fact about the agent's row, `not_granted` is the fact about the step.
2. `TestReasonIsTheVerdictSentenceVerbatim` demanded D1's visible half (a refusal naming the allow it looked past)
   and the fixture had no allow under the bash deny — a catalog that dropped `OverriddenAllow` from the sentence
   would have looked fine. `allow-bash-atlas` joined the fixture so that clause is actually exercised.
3. `TestPoliciesTouchingAgreesWithTheEvaluator` first compared a per-tool candidate list against an evaluator asked
   about one fixed agent, and correctly refused to pass `allow-write-file-reviewer`. The candidate list spans
   agents — that is what a panel shows — so the oracle now asks each row about the agent its own target names.

**The differential is a differential.** `TestEffectiveEqualsTheGateForEveryPair` recomputes the held-set from the
raw fixture lists and calls `policy.Evaluate` itself, with its own switch over the verdict's flags: no helper from
under test is reused, so agreement is evidence and not a tautology. **31 granted pairs** across 8 agents × 68
honest tools carry a verdict, every one with the sentence byte-identical to `Verdict.Sentence()`; the ~510
not-granted pairs are asserted to carry **no** reason at all. `TestPolicyLawsHoldThroughTheCatalog` ran 500 seeded
rounds and refused **378** in-force denies that tried to read as allowed and the same number of PL4 flip attempts.

**Where `PoliciesTouching` differs from the evaluator, on purpose.** It lists *candidates for a panel*: the
lapsed row is listed (a panel shows it as lapsed) and a `lane-type` row is listed although `Effective`'s request
carries no lane — a catalog row is not scoped to a step's lane, and inventing one would be the catalog deciding
something it was not given. Loop- and MCP-server-targeted rows are excluded (the per-agent view; `MCPView` renders
those). Both exceptions are pinned by name in `TestPoliciesTouchingAgreesWithTheEvaluator`, which otherwise
requires exact agreement with the evaluator deciding each row alone.

**MCP mapping, 1:1 and once.** `available→granted_allowed`, `ask→granted_ask`, `unavailable→granted_no_rule`,
`refused→granted_denied`, reason verbatim from `GrantView` — and no `policy.Evaluate` on the MCP path at all,
because `GrantView` already folds the set and the effect-ask (MC10, TC5). A fifth state is not read as available.
An unwired `MCPView` (nil) is `not_granted` with no reason: an absent answer, never a refusal (V13).
