# T5 · The read methods: `tools.list`, `tools.get`, `tools.byAgent`, `tools.status`

**Prefix:** TC · **Rules:** TC1, TC4, TC5, TC10, TC11 · P34 · **Depends on:** T3, T4 (MCP half needs S46 T3's rows and scoped seam).

## Goal

The daemon can answer, over the socket: *what tools exist, what can each do, who can call each and why not, what is one agent's whole tool view, and is the catalog current* — all read-only, none on the narrow surface.
`tools.grants` (S34) is untouched.

## Files

- `aeon/internal/protocol/tools_catalog.go` — **new**: local interface `ToolsCatalog` (S33/S35 pattern, no `internal/store` import) and handlers; `Table.ToolsCatalog` field (nil ⇒ the methods are **absent**, V13).
  - `tools.list {family?, source?: "system"|"mcp", capability?, available?: bool, q?: string}` → `{tools: ToolEntry[], statement?}` (`statement` "no tools match this filter." only when a filter matched nothing); `q` is a case-insensitive substring over name/description (daemon-side).
  - `tools.get {name}` → `{tool: ToolEntry, agents: AgentGrantRow[], policies: PolicyRef[], mcp?: {server, tier, link}}`; `AgentGrantRow = toolcatalog.Entry`; `PolicyRef{id, action, source, origin?, target, describe}` using **S45's `Describe`** when merged (else the policy `Verdict` sentences — T0 records which). Unknown name ⇒ `ErrToolUnknown` naming the nearest names.
  - `tools.byAgent {agent}` → `{agent, dispatchable, tools: toolcatalog.Entry[]}` for **every** tool that exists (granted or not); unknown agent ⇒ `ErrToolAgentUnknown` naming known agents (the existing `tools.grants` sentence shape).
  - `tools.status {}` → `{seed: {set, availableVersion, appliedVersion, state}, drift: DriftEntry[], counts{system, mcp, conditionalUnwired}}`.
  `ToolEntry` per design TC10; `schema` is the code-built schema (from `Registry()`), `rowCurrent` from the drift check; `available` = the tool is in `Registry()` now; MCP entries carry `server`, `tier`, `effect`, `classified:false` for MC6-unclassified tools.
- `aeon/internal/daemon/tools_catalog.go` — **new**: the adapter. System entries from `Registry()`+`MetaFor`+the `tool` rows; **MCP entries from the cmd/aeon seam** (`MCPAdmin` unscoped read — S46 T3 — never `internal/mcp` directly); grants through `toolcatalog` with `Inputs` built from the live agent rows (`origin='system'` dispatchable; custom not), `DefaultGrant()`, `policy.Store.List`, `At = time.Now().UTC()` **injected at the adapter**; **no cache** (N8) — every call reads rows/policies fresh.
- `aeon/internal/protocol/method.go` — four consts in a labelled block after the last block; `RequiresInitialize`, **not** `Debug`; conditional on the service.
- `aeon/internal/protocol/errors.go` — `ErrToolUnknown`, `ErrToolAgentUnknown` (block from T0).
- Contract chain: conformance cases, handshake block "S47 reads", fixtures (success per method + the two refusals), `make protogen`.
- `aeon/cmd/aeon/` — wire the adapter and the MCP seam entry (one line in the serve wiring; `daemon.Options.ToolsCatalog`).

## Behaviour notes

1. **Complete:** `tools.list` (no filter) = system tools (`Registry()` honest names; the wired conditionals; the alias shown as `aliases:["write_file"]` on `write`, never its own entry) ∪ enabled MCP tools. `available:false` entries (unwired `search`/`graph`) are listed only when `available` is not filtered to true, with `available:false` — an honest "exists but not wired in this build".
2. **MC2 is not relevant here** (human-door, unscoped, like S46's reads); the scoped agent view is T7's separate path. A test asserts no agent-tool handler calls these.
3. **No write, no probe, no audit** (reads): spy-pinned.
4. **Policy refs**: every `tool_access` row that touches the tool (including `all-agents`), each with its `describe` sentence and, if present, S45's `origin`; links are **data** (`{kind:"policy", id}`), the UI builds the navigation.
5. **Status** reports the seed state from the engine's `seed.status` for `tools.core`; a `differs` is rendered as data, not an error.

four vocabulary consts, the list's empty-table sentence), `internal/protocol/errors.go` (the two codes,

`ErrorRegistry()`), `internal/protocol/method.go` (four consts + `Table.ToolsCatalog`),
`internal/daemon/tools_catalog.go` (the adapter), the mount in `internal/daemon/daemon.go` beside the

`internal/daemon/tools_catalog_test.go` (17 answer tests), `internal/daemon/tools_catalog_fixtures_test.go`

**V13 holds at both ends.** `RegisterToolsCatalog()` returns false on a nil seam and registers nothing, so the
four names are ABSENT and a client gets JSON-RPC's own -32601 — never registered-and-refusing; a belt in each
handler answers `ErrNotWired` if the field is unset after registration rather than dereferencing nil.
`newToolsCatalogService(Options{})` hands back nil, so a storeless daemon produces exactly that absence. All
four are `RequiresInitialize: true` and `Debug: false`: they are product surface, and what keeps them off HTTP
and MCP-stdio is the allow-list that never names them, not a flag.

**TC2 is the test that matters, and it is a pair.** `TestSchemaServedIsTheCodeSchema` first asserts the served
schema equals `tools.CanonicalSchema(registry["bash"].Spec)` and the hash equals `tools.SchemaHash`, then
tamper-writes the ROW (description, schema text and hash all three — through `ToolUpsertTx`, the only writer,
so a test cannot smuggle a row any other way) and asserts the served schema is UNCHANGED while `rowCurrent`
flips and `tools.status` gains `differs` naming `description` and `schema_hash`. Then it re-reads the row and
asserts the tampering SURVIVED: TC11 is report-and-never-repair, and `TestToolsStatusMissingRowIsReportedNotRepaired`
makes the same claim for a deleted row (`DELETE` through the raw handle — the store has no delete accessor,
which is the property T2 built, and it stays missing when the test ends).

**TC5 was made a differential, not a tautology.** `TestToolsByAgentCoversEveryToolAndMatchesTheGate` re-derives
atlas's held set from `tools.GrantedSet` (the function `BuildToolset` calls, T4's extraction) and asks
`policy.Evaluate` about the tool the fixture set refuses, then requires: a tool outside the set answers
`not_granted` with **no reason quoted**, a tool inside it is never `not_granted`, and bash's row carries
`Verdict.Sentence()` byte for byte. `toolcatalog` is not consulted as an oracle anywhere in that test. The same
discipline runs through `tools.get`'s column: every agent that EXISTS appears, `not_granted` rows carry no
sentence, and `PolicyRef.Describe` is compared against `policy.Describe` re-called in the test.

**What the tests found, rather than what they were told.**

1. `ToolsStatus` shipped the whole `toolseed.Drift` map — 70 entries all saying `current` — as the drift
   report. A panel that must filter 70 rows to find the one disagreement learns to ignore the field, which is
   how drift gets hidden. The report is now the DISAGREEMENT list; the `current` rows still do their work by
   setting `rowCurrent` on each entry. Deviation from "drift: DriftEntry[]" as a complete roster, and the
   reading the falsification ("drift hidden") asks for.
2. `mcpGrantsView` is per-request with its own memo, and a policy list that returns a `*Reject` is turned into
   an ERROR: an empty policy set would read as "nothing refuses anything", the most dangerous plausible answer
   this file could produce (V11). `TestToolsReadsFailLoudlyWhenTheStoreIsUnreadable` breaks the world four
   ways — `tool`, `agent`, `policy` dropped, and the ledger — and requires no answer from any door.
3. The MCP `unavailable` state is `granted_no_rule`, not `not_granted`: S12's four states map 1:1 (T4's
   shipped mapping), and a held-but-unclassified tool has been looked at and had no rule speak. My first
   assertion said `not_granted` and the test was wrong, not the package.

**Deviations.**

1. **No `daemon.Options.ToolsCatalog` field, and no `cmd/aeon` line.** The task's Files section asked for
   "wire the adapter and the MCP seam entry (one line in the serve wiring; `daemon.Options.ToolsCatalog`)". The
   adapter needs three authorities and `Options` already carries all three (`Store`, `Seed`, `MCPAdmin` — the
   last set by `wireMCPServices` in `cmd/aeon/serve.go`), so `newToolsCatalogService(opts)` builds it where the
   table is built, beside the MCPAdmin mount, exactly as `NewAutonomyService(opts.Store)` does. A fourth Options
   field naming the same dependency would be a second configuration source for one seam, and the CLI verb (T9)
   needs nothing from `cmd/aeon` that `serve` does not already wire.
2. `newToolsCatalogService` is a **free function**, not a `*Daemon` method: the mount runs while the table is
   being assembled, before any `Daemon` value exists (`undefined: d`, measured).
3. `PolicyRef` carries two fields beyond the task's `{id, action, source, origin?, target, describe}`:
   `toolName` (the spec's own name, so a panel groups rows without re-parsing the spec) and `link`
   (`{kind:"policy", id}`) — note 4's "links are **data**, the UI builds the navigation". Additive on a
   brand-new type, so nothing existing reads it.
4. The list's `statement` is added by the **protocol door**, not the adapter: only the layer that saw the filter
   can say "the filter matched nothing", and an unfiltered empty list never carries it (that sentence would
   claim the build has no tools). `TestToolsListStatementIsOnlyForAFilteredEmpty` pins all three shapes.
5. `ToolsSeedState.State` has a fifth word, `unavailable`, beside the spec's `never_applied`/`failed`/
   `partial`/`current`: with no engine wired (or a ledger that answers nothing) the honest state is "nobody
   looked", which is not the claim `never_applied` makes about another process. The store case is asserted
   disjunctively — an error, or `unavailable` — because `Engine.Status` answers an absent `seed_ledger` with
   nothing rather than a failure.
6. **MCP entries carry no description.** `mcp_server_tool` has no description column and `S46`'s `MCPToolView`
   no field, so `ToolEntry.Description` is EMPTY for an MCP tool: the alternative is the catalog authoring a
   contract no authority holds. The honest fix is a column and a view field in S46's files, which TC13 says are
   not this slice's to move. Named here rather than papered over.
7. MCP entries carry `version: 0` (they are not `tool` rows, TC4), `origin` from the SERVER row, `family` =
   server name, and `capabilities: []` (the closed vocabulary is code's; inventing a word per server would be
   the second truth TC13 refuses).
8. The two refusals are built by the **adapter** — the only layer holding both the registry and the rows — as
   typed `*protocol.Error`, and the door ships them verbatim. Nearest-name ranking is a small Levenshtein
   (`nearestToolNames`, top 3): nothing in the repo ranked names, and a bare not-found was the answer the task
   named as its own falsification.
9. `tools.byAgent`'s universe is every honest code name (walked from `toolseed.Source()`, so an alias never
   becomes an entry and an unwired conditional is still listed) ∪ that agent's `view.ToolsFor(slug)`. A display
   `Name` is accepted when unambiguous and the answer echoes the SLUG — the key every grant chain, policy target
   and dispatcher uses.
10. Test names follow the task's table where the content matches; six of mine were renamed to it. Two of its
    rows are covered by differently-named tests, deliberately: `TestToolsStatusReportsDriftAndSeedState` and
    `TestToolsStatusMissingRowIsReportedNotRepaired` split the status row (seed state + injected drift vs. the
    report-not-repair claim), and `TestToolsReadsAreLive` carries the MC11 seam-count claim as well (the fake
    counted exactly one `mcp.servers` read for a list — the daemon's only path to the MCP half).

**The fixtures are generated, not typed.** `internal/daemon/tools_catalog_fixtures_test.go` (env-gated:

closed-store read guard belongs to `internal/store` and its own slice.
