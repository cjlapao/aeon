# T8 · The CLI as a client: `aeon tools` and `aeon surface`

**Prefix:** TC · **Rules:** TC10 · standing rule 1 · P34 · S45 PM4 · **Depends on:** T5, T6.

## Goal

The CLI, today with no way to list tools (`aeon handlers list` prints names), becomes a **client of the T5/T6 reads**. Offline (no daemon) it falls back to the same code through the same pure
packages, saying so. Parity is a test.

## Verbs

```
aeon tools list     [--family F] [--source system|mcp] [--capability C] [--available] [--q TEXT] [--json]
aeon tools show     NAME [--json]                     # tools.get: details, schema, capabilities, per-agent table, policy rows
aeon tools agent    AGENT [--json]                    # tools.byAgent: one agent's whole tool view with states and reasons
aeon tools status   [--json]                          # tools.status: drift + seed state
aeon surface list   [--kind K] [--door D] [--human-door-only] [--q TEXT] [--json]
aeon surface show   METHOD [--json]
aeon handlers list / verify                           # unchanged
```

## Files

- `aeon/cmd/aeon/tools_cmd.go` — **new** (`cmdTools`, `cmdSurface`); `main.go` — dispatch + usage lines.
- `aeon/cmd/aeon/tools_door.go` — **new**: `socketDoor` (default) and `directDoor` (offline; builds the same adapter over a directly opened store — `internal/toolcatalog`, `toolseed.Drift`, `protocol`'s surface function; actor `{cli,cli}` is irrelevant — these are reads); `selectDoor()` as S45 T8 / S43-extra T7 (dial; "no daemon" ⇒ direct + the fixed stderr line `daemon not running — read from the store directly`; **any other dial failure refuses**). The surface listing offline needs a fully wired `protocol.Table`; if the direct door cannot build one faithfully, `surface` **requires the daemon** and says so (a surface listing from a partially wired table would be a lie) — T0/T6 decide and record.
- `aeon/cmd/aeon/tools_parity_test.go` — the parity guard.

## Printer — what it must never hide

`list`: one row per tool — name, family, source, capability chips as words, rerun class, `available`/`UNWIRED`, `UNCLASSIFIED` (MCP), `row stale` when drift. `show`: description, schema pretty-printed, capabilities, **governed by** policy types, the per-agent table (agent · state · reason verbatim), and each touching policy row with its `describe` sentence and id. `agent`: every tool, grouped by state, reasons verbatim; `dispatchable: no` agents print that, not a grant table. `status`: seed version available/applied and each drift entry with field names. `surface list`: method, kind, doors as words (`person` `narrow:<action>` `agent-service` `tool:<name>`), `HUMAN-DOOR-ONLY` marker. Empty filter results print the daemon's statement. **Never prints an MCP env value** (names only, as everywhere).

## Definition of done

- [x] Six verbs dial the daemon; offline fallback via the same packages (or an explicit "requires the daemon" for `surface`, recorded); other dial errors refuse.
- [x] Parity guard both directions; output identical across doors; reasons verbatim; `--json` verbatim; no write verb.

## Do NOT

- Do not re-derive a state, a reason or a door in the CLI; do not fall back on a non-"no daemon" error.
- Do not add a verb that changes anything; do not change `aeon handlers`.
- Do not import `internal/store`/`toolcatalog` outside `directDoor`.

### Deviations, each with its reason

1. **`surface` requires the daemon — the spec's allowed branch, and the honest one** (the spec left the call to T0/T6; T8 is the CLI task that owns the answer). `surface.list`'s subject is *which methods a fully wired build registers*, and registration is seam-conditional (V13: unwired seam ⇒ methods absent). The wiring that settles it is `serve.go`'s (`wireMCPServices`, `wireAgentServices`, the autonomy/settings seams, `Table.NarrowMethods` at `serve.go:396`). An offline listing would either duplicate that wiring in the CLI — a second, drift-prone authority over the very fact the listing reports — or under-wire it and print a partial table as the surface; the completeness tests tolerate absent conditional entries, so an under-wired table does not even fail loudly. `policy_parity_test.go:110` says the same thing about `parityDaemonTable` ("so 'registered' means what it means in production, not what a hand-built table happens to hold") and `protocol.NewTable` appears in `cmd/aeon` only in tests. `TestSurfaceOfflineRefusesRatherThanList` pins the refusal, `surfaceNeedsDaemon` states the reason on the terminal, and an empty listing offline is a test failure rather than a possibility.
2. **`TestSelectDoorFallsBackOnlyWhenNoDaemon` is named `TestSelectToolsDoorFallsBackOnlyWhenNoDaemon`.** `seed_test.go:204` already owns the bare name in this package and two tests cannot answer to one name. Same asserts, family-prefixed.
3. **`--json` prints the door's own bytes.** Each door returns `(typed, json.RawMessage, error)`; the socket door's raw is the wire verbatim (`Call` into a `json.RawMessage`, the `callJSON` precedent at `loop_control_verbs.go:46`), so `printRawJSON` cannot drop a `null` the daemon sent. `printJSON` (`settings.go:394`) re-marshals the decoded value and is NOT used here. `TestJSONIsTheWireVerbatim` proves the distinction has teeth: the stub's explicit `"mcp":null` survives `printRawJSON` and vanishes from `json.Marshal(res)` — and the test fails if the two printers ever converge. The direct door has no wire; its raw is the same value from the same adapter marshalled, which is what the daemon would have sent.
4. **The direct door reaches the adapter through a new exported constructor**, `daemon.NewToolsCatalogService(daemon.Options{Store, Seed, MCPAdmin})`, a five-line wrapper over `newToolsCatalogService` sharing its nil guard. The alternative was `daemon.New(opts).Table.ToolsCatalog`, which builds ~30 services the CLI does not speak to. It follows the `NewAutonomyService(opts.Store)` precedent (an exported free function over `Options`), and it is the ONE implementation: the entry point's own `Store`, the one `seed.Engine` (`daemon.NewSeedEngine(st, seed.Options{}, mcpSeedValidator(st))`), the one MCP admin func (`mcpAdminHandleFor(st, newMCPProbeCache())`, the value `wireMCPServices` hands the daemon). `TestDirectDoorUsesTheSamePackages` names all seven constructors at the parser.
5. **`protocol.ShapeToolsListResult` exported.** The empty-filter sentence ("no tools match this filter.") now has ONE definition, called by the socket handler (`tools_catalog.go:470`) and by the direct door. A second copy of "when does an empty list get a sentence" is precisely the drift the parity guard exists to catch, on the one answer where the doors most need to agree.
6. **`buildDirectToolsDoor(st)` split out of `newDirectToolsDoor`** so the parity test can hand the direct door the *same store handle* the daemon's table was built over. The policy family's parity (`policy_client_test.go`) compares two databases (a spawned daemon and an offline env); the claim here is two doors over one database, so any difference is the doors' and not the data's.
7. **The parity harness is the in-process pipe** (`parityPipeServer`, `autonomy_parity_test.go:173`) — a real `protocol.Client`, a real handshake, a real `Table.Dispatch` — rather than a spawned daemon. Faster, and it dispatches through the same table the daemon registers. Seven scenarios compared on typed re-marshal, raw bytes and refusal text: unfiltered list, filtered list, filtered-empty list, `--available=false`, `get read`, `get reed` (refusal), `status`, plus `agent atlas` (a planted row) and `agent nobody` (refusal).
8. **`row stale` covers both drift states.** `ToolEntry` carries one bool (`rowCurrent`); `missing_row` and `differs` both read false, and which one it is lives in `tools.status` (T5's own comment at `tools_catalog_entries.go:71` says so). Printed as the spec names it, with the comment saying where the kind lives.
9. **`tools list` on a fresh store prints `row stale` on every row.** Correct, not noise: `tools.core` has never been applied there, and `tools status` says `never_applied · available v1 · applied v0`. The first `aeon seed apply --set tools.core` (S43's verb) clears it.
10. **`TestEveryStepEventKindRendersSomething` is fixed here** — T0 found it red and *handed it forward* to "this slice's CLI task, which owns the same renderer" rather than absorbing it silently (`T0.md:222`). `renderStepEvent` printed nothing for `agent.message.asked` and `agent.message.delivered` (`EventStepCompacted` was already handled); both cases now print the daemon's own payload (`Tool`, `MessageID`, `Iteration`, `Summary`) with the sender printed as `unknown` when absent (P31). `cmd/aeon`'s pre-existing reds go from 13 to 12; the remaining twelve are T5's eleven plus `TestDoctorGoldenDown`, none of them this slice's.
11. **The exemptions the spec's own table names.** `tools.mine.list`/`tools.mine.show` (own-view reads answering SELF — a person's connection is not an agent) and `tools.grants` (S34's agent-facing grants read, registered unconditionally in `method.go:1665`, refused without the `ToolGrants` seam, answered through `ErrAgentRefused`) each carry a reason in `toolsExemptMethods`; `TestEverySocketToolsMethodHasAVerb` fails on any `tools.*` method registered and unlisted, and `TestToolsExemptMethodsStayNamedAndReasoned` fails on a reason going blank.
12. **`--available` distinguishes "not given" from `false`** through `fs.Visit`, so `--available=false` filters and absence sends a nil field. An empty filter is a different answer from no filter, and the wire's pointer fields are what make that expressible.

### What the tests found (each one changed the code, not the assertion)

- **Seven `tools.*` methods are registered, not six.** `tools.grants` (S34) was there before this slice; the first run of `TestEverySocketToolsMethodHasAVerb` named it. It is exempt for the same reason the own-view reads are, exactly as the spec's table anticipated.
- **`protocol.MethodName` is a type, not a method constant** — `TestNoWriteVerbExists`'s parser walk flagged `callRaw`'s parameter type. The walk now skips the type name and still refuses any `protocol.Method*` constant outside the six.
- **A same-package constructor is an `*ast.Ident` call, not a selector.** The first version of `TestDirectDoorUsesTheSamePackages` could not see `storeOpenOptions`, `mcpAdminHandleFor`, `newMCPProbeCache` or `mcpSeedValidator` at all, and reported them missing. Collecting bare calls too is what makes the guard say something true: those four are the point of it.
- **`SurfaceKind`'s words are `read|write|control|diagnostic`** — a draft usage line said `diag`; the usage text and the tests now say the closed set's real words (`surface.go:61`).
- **`HumanDoorOnly` is a field of `SurfaceEntry`, not of `SurfaceDoors`** (`surface_doors.go:46`); the marker prints from the entry.
