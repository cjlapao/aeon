# T1 · Tool metadata in code: capabilities, family, governed-by — with a completeness test

**Prefix:** TC · **Rules:** TC3 · **Depends on:** T0 (the capability proposals). Parallel-safe with T2, T6.

## Goal

Make every tool say, in code and checked by a test, **what it can do**. Today `Tool` has a re-run class and nothing else; the catalog (and a person deciding whether to
grant `bash`) needs to know it spawns, `webfetch` egresses, `write` mutates the workspace. A tool **cannot ship without declaring this**. No behaviour of any tool changes.

## Files (`aeon/internal/tools/`; existing tool files **not edited**)

- `meta.go` — **new**:
  ```go
  type Capability string
  const (
      CapWorkspaceRead  Capability = "workspace_read"
      CapWorkspaceWrite Capability = "workspace_write"
      CapSpawnProcess   Capability = "spawn_process"
      CapNetworkEgress  Capability = "network_egress"
      CapAsksHuman      Capability = "asks_human"
      CapOrgRecordsRead  Capability = "org_records_read"
      CapOrgRecordsWrite Capability = "org_records_write"
      CapStartsLoop     Capability = "starts_loop"
      CapIndexRead      Capability = "index_read"
      CapGraphRead      Capability = "graph_read"
  )  // T0 may propose ONE addition with evidence; never a free string
  func Capabilities() []Capability   // the closed set, sorted
  type Meta struct {
      Family       string       // "core" | the records Spec.Family | "task" | "search" | "graph"
      Capabilities []Capability // non-empty; sorted; no duplicates
      Governed     []string     // policy type names that decide this tool: always "tool_access"; "command_access" for bash; …
      Notes        string       // ≤ 200 chars, one fixed sentence a person reads ("spawns a process only with a policy allow token")
  }
  func MetaFor(name string) (Meta, bool)      // canonical or alias name (CanonicalToolName)
  func AllMeta() map[string]Meta              // a copy
  ```
  The table is a **function-built map** (the `Registry()` stance: no package variable anyone can append to). Records-catalog tools are derived: `Family = Spec.Family`, `org_records_write`
  iff `Spec.Mutates`, else `org_records_read`; the derivation is a function, asserted consistent in a test, and the `Meta` for the core ten and the conditional/`run_start` tools is written by hand from T0's proposals.
- `meta_test.go` — tests below.
- `canon.go` — `SchemaHash(spec model.ToolSpec) string` (SHA-256 hex of the canonical JSON of the spec's schema — reuse the canonicalisation T1 of S43-extra defines **if merged**, else a local copy with a TODO naming it; **VERIFY**) used by T3.

## Rules (each a test)

1. **Completeness, both directions:** every key of `Registry()` (honest names + the wired conditionals; the alias resolves to `write`'s) has a `Meta`; every `Meta` key is a registry name (or a conditional name, asserted present when its seam is wired). A new tool with no `Meta` fails the suite naming it.
2. **Closed vocabulary:** every capability string is in `Capabilities()`; `Governed` entries are valid `policy.AllPolicyTypes()` names (the policy vocabulary, not restated).
3. **Truthfulness pins** (the facts a person relies on): `bash` has `spawn_process` and `Governed ∋ command_access`; `webfetch` has `network_egress` (and **no other tool does**); `write`/`edit` have `workspace_write`; `question` has `asks_human`; `run_start` has `starts_loop`; `read/list/glob/grep` have `workspace_read` and **none** of write/spawn/egress; no core tool has `org_records_write`; `DefaultGrant()` tools have **neither** `spawn_process` nor `network_egress` (the existing "no shell, no egress by default" claim, now stated in capability terms).
4. **Derivation consistency:** for every records-catalog tool, `org_records_write ∈ Capabilities ⇔ Spec.Mutates`.
5. **Notes** are fixed sentences ≤ 200 chars with no control characters (rendered in a UI; SEC-033).
6. **No behaviour change:** the existing `internal/tools` suites pass unedited; `TestRegistryExactNames` unedited.

## Tests

| Test | Asserts | Fails when |
| --- | --- | --- |
| `TestEveryRegistryNameHasMeta` / `TestEveryMetaNamesARealTool` | rule 1 (with and without the conditional seams wired) | an undeclared tool / a stale entry |
| `TestCapabilityVocabularyIsClosed` | rule 2 | a free-string capability |
| `TestGovernedNamesAreRealPolicyTypes` | rule 2 | a typo'd policy type |
| `TestCapabilityPins` | rule 3, table of ≥ 12 facts | a capability silently dropped/added |
| `TestDefaultGrantHasNoSpawnOrEgress` | rule 3 | the default grant widened |
| `TestRecordsToolsDeriveFromTheCatalog` | rule 4 | catalog and meta disagree on writes |
| `TestMetaNotesAreSafeText` | rule 5 | control characters in a rendered sentence |
| `TestMetaIsAFunctionBuiltMapNotAPackageVariable` | `go/parser`: no package-level `var` of `map[string]Meta` | an appendable global |
| `TestSchemaHashIsStableAndSensitive` | equal for reordered keys; differs for a changed schema | unstable drift detection |
| *Existing `internal/tools` suites* | green, unedited | regression |

## Definition of done

- [x] Closed capability vocabulary; `Meta` for every registry tool (and every wired conditional); completeness both ways.
- [x] Truthfulness pins pass, incl. "only `webfetch` egresses" and "default grant spawns/egresses nothing".
- [x] No tool behaviour changed; `TestRegistryExactNames` and all existing tool tests unedited.

## Do NOT

- Do not edit an existing tool file or test; do not add a package-level mutable map; do not accept a free-string capability.
- Do not infer capabilities from tool *descriptions* — read the implementation (T0's proposals) and pin the facts.
- Do not make any tool depend on `Meta` at runtime (it is catalog data only).

**Deviations, recorded (T0's Notes carry the evidence):**

1. **`Capabilities` is empty for exactly two tools** — `todo` and `report_size`. The task's struct comment says
   "non-empty", and the honest alternatives were both worse: inventing a twelfth term ("writes the step's own
   handoff", for one tool) is exactly the free string TC3 forbids, and copying `org_records_read` onto a tool that
   reads no record would be a false declaration. Neither writes a row, a file, a process or a socket
   (`todo_test` counts the rows; `report_size.go:18-21`). Emptiness is therefore **permitted by name and pinned by
   test** — `TestEmptyCapabilitySetsAreOnlyTheDeclaredTools` fails any other tool arriving empty, so the guarantee
   the "non-empty" comment wanted is enforced more tightly than the comment itself. `MetaFor` still requires an
   entry for every tool: the declaration is the row, not the array length.
2. **`question`'s `Governed` is empty** — `runtime/loop.go:434` routes a `question` tool_use to the suspend path
   *before* `runTool`, so `Policy.Decide` is never asked about it; naming `tool_access` would promise a gate that
   does not run. Notes names the grant list as its only control.
3. **`bash` stays `spawn_process` alone** (T0 §4.4) — the shell's transitive read/write/egress is gated by
   `command_access` and the one-shot allow token, and widening this column would claim a classification the tool's
   own code path does not have. Pinned so nobody "fixes" it later.
4. `recordMeta`'s `Notes` is `Spec.Description` folded to one safe sentence (control characters dropped, 200-rune
   cap) rather than 56 hand-written sentences — the description *is* the catalog's own words, and a second copy
   would be a second truth to drift.
