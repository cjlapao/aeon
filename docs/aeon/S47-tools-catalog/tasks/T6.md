# T6 · The surface classification and `surface.list` / `surface.get`

**Prefix:** TC · **Rules:** TC6, TC8, TC10 · P34 · **Depends on:** T0 (the method inventory). Parallel-safe with T1–T5 (adds `internal/protocol/surface*.go` and a wiring line only).

## Goal

Answer "**what does the daemon expose, and to whom**" with a complete, classified, honest listing of every socket method and the doors that reach it. The classification is a **closed table
with a completeness test** (a new method cannot ship unclassified), and the door flags are **computed from the real structures**, then proven against them by a differential test.

## Files

- `aeon/internal/protocol/surface.go` — **new**: `type SurfaceKind string` (`read | write | control | diagnostic`); `type Surface struct{ Kind SurfaceKind; Summary string; HumanDoorOnly bool }`; the table as a **function-built map** `surfaceTable() map[MethodName]Surface` (no appendable package variable); one entry for **every** method in T0's inventory (summaries from the const comments, ≤ 140 chars, fixed sentences). Definitions: `read` returns state and changes nothing; `write` changes stored state; `control` acts on a running thing (start/stop/steer/answer/terminal); `diagnostic` is `Debug`-marked. `HumanDoorOnly` is **declared** for the methods the guard slices made human-door (S35 commit/reject, S45 authoring/decision, S46 writes, S43-extra seed apply/restore, `step.stop`/`loop.answer`/`step.steer*`/`terminal.*`, the policy and MCP authoring methods) — T0 lists them.
- `aeon/internal/protocol/surface_doors.go` — **new**: `func (t *Table) Surface() []SurfaceEntry` computing each entry's `Doors` from the live structures: `socket` (registered), `public` (`!Debug`), `narrow` (an `internal/narrow` action projects it — supplied through a **func seam** `Table.NarrowMethods func() map[MethodName]string` set by the daemon/cmd wiring, because `internal/protocol` must not import `internal/narrow`; **VERIFY the import direction** — `narrow` imports `protocol`), `agentService` (`AgentServiceMethods()`), `toolTwin` (records catalog `Method` ⇒ tool name; `internal/records` is stdlib-only and importable). `SurfaceEntry{method, kind, summary, humanDoorOnly, requiresInitialize, debug, doors{socket, public, narrow?: actionName, agentService, toolTwin?: toolName}}`.
- `aeon/internal/protocol/surface_methods.go` — **new**: `surface.list {kind?, door?, q?, humanDoorOnly?}` → `{methods: SurfaceEntry[], counts{total, byKind, byDoor}}`; `surface.get {method}` → `{entry}` (unknown ⇒ `ErrSurfaceUnknown` naming nearest). Conditional on the table being built (always, in practice; absent-not-refusing if `Table` has no seam wiring for `NarrowMethods` — then `narrow` is reported `unknown` for every entry **explicitly**, never `false`).
- `aeon/internal/protocol/method.go` — two consts in a labelled block; `RequiresInitialize`, **not** `Debug`.
- `aeon/internal/protocol/errors.go` — `ErrSurfaceUnknown`; contract chain: conformance, handshake block, fixtures, `make protogen`.
- `aeon/cmd/aeon/` or `internal/daemon/` — wire `Table.NarrowMethods` from `narrow.Actions()` (one line where the daemon builds the table for serve).

## Behaviour

1. **Completeness (both directions):** every registered method has exactly one table entry; every entry names a registered method. The test enumerates `Table.Methods()` after a **fully wired** table (all services non-nil) **and** a minimally wired one (conditional methods absent ⇒ their entries are simply not listed; an entry for a conditional method is allowed).
2. **Door truth is computed, then proven:** `TestSurfaceDoorsEqualTheRealStructures` — for every method, `narrow` equals membership in `narrow.Actions()` socket methods; `agentService` equals `AgentServiceMethods()`; `toolTwin` equals the records catalog's `Method`; `public` equals `!Debug`.
3. **Kind truth is cross-checked against known facts:** records twin ⇒ `kind==write` iff `Spec.Mutates`; agent service ⇒ `write` iff `!ReadOnly`; narrow `KindTrigger/Webhook/Callback` ⇒ `control`; `Debug` ⇒ `diagnostic`.
4. **`HumanDoorOnly` is proven:** `TestHumanDoorOnlyMeansAbsentFromEveryNonHumanDoor` — every `HumanDoorOnly:true` method has `narrow == none`, `agentService == false`, `toolTwin == none` (or the twin is a **propose-only** one, listed by name); and every method whose name matches S35/S45/S46/S43-extra's write families (`policy.add|remove|seedCorpus`, `proposal.commit|reject`, `mcp.server.*`, `mcp.grant.*`, `mcp.core.*`, `mcp.importFile`, `seed.apply|restore`) **is** declared `HumanDoorOnly` — so the table cannot quietly forget one.
5. **Summaries** are fixed sentences without control characters, ≤ 140 chars, unique enough to tell methods apart (a test rejects exact duplicates).
6. **Read-only and person-only:** the two methods write nothing, are absent from the narrow surface, agent services and tools (T9 guards).

## Definition of done

- [x] Door flags computed and differentially proven; kinds cross-checked; `HumanDoorOnly` proven incl. the name-family check. (`TestSurfaceDoorsEqualTheRealStructures`, `TestSurfaceNarrowDoorEqualsTheRealProjection`, `TestSurfaceKindAgreesWithKnownFacts`, `TestHumanDoorOnlyMeansAbsentFromEveryNonHumanDoor` both directions.)
- [x] `surface.list/get` registered, fixtured, in the generated contract; person-only; no new import in `internal/protocol`. (8 fixtures, `contract.ts` regenerated; the only new import in the package is `internal/records`, which is stdlib-only and the source the `toolTwin` door is computed from — `TestSurfaceTableIsFunctionBuiltAndImportsNothingNew` refuses `internal/narrow`, the transports and every store package.)

## Do NOT

- Do not type door membership into the table — compute it; do not import `internal/narrow` into `internal/protocol`.
- Do not mark a method `HumanDoorOnly` unless the proof holds; do not leave a method unclassified to "do later".
- Do not mount the surface methods on the narrow surface or as an agent tool (recon).
- Do not edit `method.go`'s existing registrations or any existing guard test.

## Notes

Built 2026-11-02. What exists, and what the task could not have known.

**The table.** 269 entries — the 267 names a fully wired daemon registers (T0's
measurement) **plus the two surface doors themselves**, which are classified like
everything else: a listing that exempts itself is a listing that cannot answer
"who can reach `surface.list`". The classification lives in six plane files
(`surface_table_core/agents/governance/mcp/records/projects.go`, 102–354 lines
each), each one a function returning its slice; `surfaceTable()`
(`surface.go`) merges them and **panics on a duplicate**, so two planes cannot
quietly disagree. Entries are keyed by the declared `MethodX` constant wherever one
exists — a renamed constant is then a compile error, not a stale row — and by
`MethodName("x.y")` for the 49 names that exist only as records-catalog
projections.

**Deviations.**
1. **Six table files, not the one `surface.go`** the Files section named: 269
   entries in one file is ~1,100 lines, which is SIZE1; the split is by plane
   (cohesion — "opened for the MCP surface" finds all of it in one file) and each
   file's own doc comment says what plane it is.
2. **`loop.run` is NOT `HumanDoorOnly`.** It was on my family list and the proof
   killed it: `run_start` is its records twin and an agent may call it (S39 CR5 —
   it asks the person first). "The only door is the person" is false of a method an
   agent reaches with a confirm; the ask is S39's guard, not a door.
3. **The propose-only exception set exists and is currently EMPTY of overlap.**
   `surfaceProposeOnlyTwins()` names the six proposal twins (TC10's justification),
   and `TestHumanDoorOnlyMeansAbsentFromEveryNonHumanDoor` measures the stronger
   fact first: **no** `HumanDoorOnly` method has a tool twin at all, so nothing
   needs the exception today. It stays a named closed function because the day one
   does, the addition is a reviewable diff with a reason attached.
4. **The kind cross-check has one named relaxation**: a records twin whose spec
   mutates may be `write` **or** `control`. `run_start`/`loop.run` starts a loop
   *and* writes rows — `control` is the same fact seen from the running side. The
   non-mutating direction stays strict (`⇒ read`), and it is the strict half that
   caught a real bug: my first parse of `catalog.go` attributed the *following*
   entry's `Mutates: true` and classified `loop.get` a write.
5. **`counts` is `{total, unfiltered, byKind, byDoor}`** — `unfiltered` is the
   addition: a filtered answer still says how big the surface is, so "9 of 269"
   cannot be read as "there are 9". All four kind buckets are always present,
   zero included.
6. **`SurfaceListResult.statement`** carries `no methods match this filter.` and
   only when a filter matched nothing (V11: an empty list is otherwise readable as
   "this daemon exposes nothing").
7. **The narrow door is one string with three values** (`none` · `unknown` · the
   action name) rather than a bool plus a name, and a `door=narrow` **filter** on a
   daemon that never wired the seam is an `ErrNotWired` refusal naming the missing
   seam — never an empty list. "Unknown" is a value; collapsing it into "none" is
   the failure TC8 exists to prevent.
8. **`Table.NarrowMethods` is wired in `cmd/aeon/serve.go`, not `daemon.New`.**
   `internal/narrow` imports the framework's HTTP middleware; a
   `daemon → narrow` import would drag HTTP into the daemon package for a fact it
   does not own, and the daemon's own test suite would pay for it. The func value
   is assigned in the one place that already imports narrow, immediately after
   `daemon.New` and before `Register()`.
9. **`RegisterSurface` registers whenever the table exists** and returns the bool
   the other `Register*` methods return. The spec's "conditional on the table being
   built (always, in practice)" is satisfied by that reading: there is no seam
   whose absence should make the doors refuse, because both read the table itself;
   `nil` receiver is the only `false`.
10. **`ErrSurfaceUnknown` = -31913** (T0's block, next after T5's two), fixtured;
    the refusal carries the three nearest registered names in `Data.What`
    (Levenshtein over runes) and `Error()` stays the message, so the tests read
    `Data.What` — the same discipline as -31911.
11. **The `terminal.` human-door prefix was dropped** from
    `surfaceHumanDoorPrefixes()`: it swept `terminal.list`, a read, into a claim
    the slice never made. The six terminal *write* doors are named whole in
    `surfaceHumanDoorFamilies()`, which spells the S45 authoring names as
    **constants** — `TestPolicyAuthoringNamesStayConfined` forbids a second
    dotted spelling of them anywhere but `method.go`.
12. **Summaries: 62 from the method's own doc comment, 46 from the records
    description, 38 from the handler's doc, 143 authored by hand.** `budget.list`'s
    catalog description measured 141 characters, so it got a shorter authored
    sentence rather than a raised limit.
