# T7 · Agent tools: own-view `tools_mine` and `tool_show`

**Prefix:** TC · **Rules:** TC9 · standing rule 2 · S38 OL2/OL3/OL10 · MC2 · S46 MG8 · **Depends on:** T4, T5.

## Goal

An agent can see **its own** tool situation — which tools it holds, what each can do, and whether the policy would let it call them — and nothing about any other agent or any tool it does not hold.
Read-only (TC1: there is no write operation to expose). Two catalog specs, one definition with its socket twin, **granted to no one by default**.

## The two specs (`internal/records/catalog.go`, additive; family `tools`)

| Tool | Socket twin | Class | Mutates | What it does |
| --- | --- | --- | --- | --- |
| `tools_mine` | `tools.mine.list` (new) | safe | no | List the tools **you** hold: name, family, one-line description, capabilities, your effective state (`granted_allowed/ask/denied/no_rule`) and the reason sentence |
| `tool_show` | `tools.mine.show` (new) | safe | no | Show one of **your** tools in full: description, input schema, capabilities, re-run class, which policy rows touch it, your state and reason |

## Rules (each a test)

1. **Identity stamped, never named:** schemas are `additionalProperties:false` with **no** `agent` field; "self" is the stamped agent identity (OL3). A param naming another agent is a parse error.
2. **Own tools only:** the output contains exactly the agent's granted set (`toolcatalog.ForAgent(self, granted-only)`); a tool it does not hold is **absent** — not listed as "not granted".
3. **`tool_show` of a tool the agent does not hold** answers the **same sentence** as for a name that does not exist ("no such tool in your set"), so it is not an existence oracle for MCP private tools (MC2) or for tools the agent was not given. "Nearest name" hints come from the caller's own set only.
4. **MC2:** another agent's private MCP tools/servers never appear in any output, error, hint or count (a test plants a private server for B and asserts A's bytes exclude it across both tools).
5. **Policy rows shown are only those that could affect this agent** (`agent` target equal to self, `all-agents`, or matching lane-type) — never another agent's rows (they could reveal another agent's restrictions).
6. **Socket twins are agent-scoped:** they serve the session's stamped agent identity and **refuse a person session** with a pointer sentence ("this door is agent-scoped; use tools.byAgent") — so the twins cannot serve as an oracle and the person's unscoped reads remain a separate path (S46 T8's pattern; T0 recorded how `table.ActorFor` distinguishes an agent actor).
7. **No schema smuggling:** the schema returned is the code schema the model is already offered for tools it holds.
8. ≥ 40-char descriptions; counted `TestRegistryExactNames` bump (**+2**, from T0's recorded count; dated comment); **not** in `DefaultGrant()`.

**Deviations, each with its reason.**

1. **The family `tools` did not exist.** The task says it does; `Catalog()` held no
   `tools`-family spec (T5's four reads are socket methods with no catalog entry, and
   `tools.grants` was never a catalog action). Created here, with exactly these two
   members — which is why `TestNoWriteToolInTheToolsFamily` asserts on the *family*
   and `TestCatalogHasTheTwoToolsSpecs` refuses a third member arriving without an
   amendment.
2. **The implementation is on the catalog service, not inside `records_tools.go`.**
   The own-view needs the catalog world — the registry, the tool rows, the policy
   set, the scoped MCP view — and only `*toolsCatalogService` holds it; `Do` would
   have had to re-read all four, which is a second authority over what the gate just
   decided (TC5). The arms keep the door's own business: identity, decode, the V13
   statement. Same shape as T5's four reads.
3. **There is no `RegisterToolsMine`.** `registerRecords()` already registers every
   `Spec.Method` it finds in the catalog (the mechanism behind `recordTools()`'s
   tool projection), so a spec cannot exist without its door and the two cannot
   drift. What that *costs*: `TestRegistryExactNames`, `TestRegistryClasses`,
   `TestBuildToolset…`'s two `want` lists and the handshake want-list all bumped by
   hand, and `tools.mine.*` joined the `tools.` prefix family the T5 guard watches.
4. **The T5 guard was amended by name, not loosened.**
   `TestToolsCatalogMethodsNotDebugRequireInit` asserted
   `countPrefix("tools.") == len(toolsCatalogMethodNames)+1` with the message "a
   sixth name is a write door in TC1's clothes". It failed red, correctly, at seven.
   It now asserts the exact **set** by name (the four reads + `tools.grants` + the
   two twins), which says the same thing and survives a rename. Precedent: T5's own
   amendment of the S55 registry guard.
5. **`lane-type` rows are kept in the shown policy list.** `rowsThatCouldReach`
   drops `policy.AgentKind` rows whose `Target.ID` is not the caller — the rule the
   task names — and keeps `all-agents`, `lane-type` and `lane`. The catalog world
   carries no per-agent lane truth, so "this row cannot reach you" is not something
   it can honestly say about a lane row; hiding a rule that *might* refuse the caller
   is the worse direction (P31), and `PoliciesTouching` is the one function that
   knows how lane rows are matched.
6. **An MCP name with no catalog row gets a minimal synthesized entry**
   (`name`, `family` = server, `source: mcp`, `server`, empty `capabilities`/
   `governed`) rather than a dropped row or a fabricated schema: the agent declared
   it and the view may call it, so it is in the inventory, and the zeros are the
   honest state of "the classifier has not spoken about this" (MC6), which the
   granted state and reason carry anyway.
7. **The near-name hints come from the caller's own held set only.** That is the
   leak vector: the requested name is echoed (the caller typed it) and the hints are
   built from `heldNames(self)`, never from `w.entries()`.
