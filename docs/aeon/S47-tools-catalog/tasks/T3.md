# T3 · The `tools.core` seed set (inert), the versions golden, and drift status

**Prefix:** TC · **Rules:** TC2, TC7, TC11 · S43-extra SD2/SD3/SD5/SD6/SD12 · **Depends on:** T1, T2 and **S43-extra T3** (the engine).

## Goal

The system tools' catalog entries become seeded rows, produced by the seed process, current at every start, with a **drift report** that says when code and rows disagree. Nothing about execution
moves to the database (TC2): `Registry()` remains what the runtime offers.

## Files

- `aeon/internal/toolseed/` — **new** package (domain side of the engine; imports `internal/tools`, `internal/records`, `internal/seed`; **not** `internal/mcp`):
  - `source.go` — `Source() []seed.Record`: one record per **system** tool (honest registry names + `search`/`graph` always, flagged `conditional`; the alias is recorded in `aliases` on `write`, not its own record). `Content` = canonical JSON `{name, family, description, schema, schema_hash, rerun_class, capabilities, governed, twin, aliases, conditional, notes}` built from `Registry()` (spec, class), `tools.MetaFor` (T1), the records catalog (`Method` twin). For `search`/`graph`, whose `Tool` exists in code but is only *registered* when a seam is wired, `Source` calls their constructors directly (`tools.Search()`, `tools.Graph()` — VERIFY they are callable without a resolver) so the record exists in every build; if not, T0's note says how the metadata is obtained without the seam.
  - `applier.go` — `Upsert(tx, r, adopt)` writes the `tool` row (`origin='system'`, `created_at` kept on update); `Fingerprint` = hash of the canonical content columns of the live row; `Retire` flags only; `GuardAffecting() == false`; `Operator() == {Edit:false, Remove:false}`.
  - `decl.go` — `init()` registers set `tools.core`, class **inert**.
  - `status.go` — `Drift(ctx, rows []store.ToolRow, code []seed.Record) []DriftEntry` (pure): `current | missing_row | retired | differs{fields[]}`; `fields` names which of `description, family, schema_hash, rerun_class, capabilities, governed, twin, aliases, conditional, notes` differ.
  - `testdata/tools.versions.golden` — `key version hash` lines.
- `aeon/internal/seed/registry_test.go` — the default-registry assertion includes `tools.core` alongside the sets present (T0 records which).
- No edit to `internal/tools`, `internal/records` or the runtime.

## Behaviour

1. **Per-record versions** start at 1; `TestToolVersionsBumpWithContent` compares each record's hash to the golden and fails with *"content changed but version did not — bump it"* — so a tool's description, schema, class, capabilities or twin cannot change without a catalog version bump. (This also makes `TestRegistryExactNames` bumps visible in the golden diff.)
2. The set applies **at daemon start** with the other inert sets (S43-extra T6); a failure of a record is `failed` in `seed.status` and does not abort start. The runtime never reads these rows (T2's guard).
3. **Drift is reported, never repaired silently:** `Drift` is a pure function used by T5's `tools.status`; there is no code that rewrites a `differs` row except a normal seed apply (which needs a version bump).
4. A tool **removed from code** leaves its row; the ledger marks it `retired` (SD6) and `Drift` reports `retired` — never auto-deleted.
5. Adding a tool (any sibling slice) = one new record; no migration, no new mechanism (S43-extra SD12's promise, exercised).

`NewSeedEngine`. `internal/tools`, `internal/records`, `internal/runtime` and every existing test are untouched.

**70 records, zero new mechanisms.** `Source()` = the 68 honest registry names **plus** `search` and `graph` in
every build (their constructors are callable unwired — `search.go:103`, `graph.go:53` check the seam inside `Run` —
so the record exists in every build and usability stays a live fact, which is TC7). The alias is **derived, not
named**: every `Registry()` key `ToolNames()` filters out, mapped through `CanonicalToolName` onto its owner — a new
compatibility key appears in its owner's `aliases` with no edit here, and `write_file` is not a record (one
executor, one row). Every field is read from code: `Registry()`'s spec/class, `tools.MetaFor`,
`records.Catalog()`'s `Method` twin, `tools.CanonicalSchema`/`SchemaHash`. Nothing is restated in this package.

**The golden is the version discipline.** `TestToolVersionsBumpWithContent` fails with *"content changed but
version did not — bump it"* naming the tool, and separately refuses *"version moved with no content change"* — so a
description, schema, class, capability set or twin cannot move without a version bump, and a version cannot be
bumped as a counter. Versions come from `revised()` (empty today: the set ships at 1 across the board) over
`baseVersion = 1`; `SetVersion()` is the maximum (SD1); the four-step ritual (fail → add the line → `-update` →
commit the golden's diff) is written into `versions.go`, which is also what turns a sibling slice's
`TestRegistryExactNames` bump into a one-line golden diff instead of a silent catalog lie.

**Deviations, recorded.**

1. **`decl.go` declares; it does not `init()`.** The task's sketch had `init()` register the set and asked
   `internal/seed/registry_test.go` to list `tools.core` among the sets present. Neither is possible: `internal/seed`
   cannot import `internal/toolseed` (cycle), and that test — `TestDefaultRegistryHasOnlyDeclaredSets` — pins the
   package-global registry **empty**, because a domain widening it from a distance bricks the test engines that
   build against it with their own appliers maps (`seed.NewEngine` refuses a registry set with no applier). So this
   set follows **`policyseed`/`mcpseed`'s recorded precedent** (function mount in `daemon.NewSeedEngine`) and not
   `agentseed`/`watchdogseed`'s `init()`. T0's inventory now reads: global registry empty in `internal/seed`'s own
   binary; `agents.firstparty` + `watchdog.default` init-registered; `policy.corpus`, `mcp.servers`, `mcp.grants`
   and **`tools.core`** mounted by `NewSeedEngine`. The presence assertion therefore reads **`seed.status`** — the
   enumeration the person and the Settings panel actually see — in
   `internal/daemon/tool_seed_test.go/TestToolsCoreIsDeclaredInEveryDoorsEngine`, which is the stronger test: a set
   invisible there is a set that never applies.
2. **`Retire` moves `updated_at` and no content column, because there is no `retired` column to flag.** The engine's
   SD6 flag lives in the **ledger's state** for this domain, and `Drift` reports `retired` from the two sides it is
   handed (a row with no code record). Editing a content column in `Retire` would have been the worse lie: it would
   read as *divergence* against the applied hash for a tool nobody touched. `Adoptable` is `false` always for the
   same kind of reason — no earlier slice created `tool` rows, so a present row with different content is a conflict
   to report, never a stub to fill in place (returning true would let a start overwrite an operator's row).
   `Operator()` is `{Edit:false, Remove:false}` as the task specifies.
3. **`Drift` is pure by construction, tested twice over.** It holds no store, transaction or clock:
   `TestDriftNeverRepairs` calls it 50× and `driftSourceHasNoStore` scans `status.go` for any reach at storage
   (`database/sql`, `*store.Store`, `Exec(`, `BeginTx`); `TestDriftReportNeverWritesAtTheStore` stages a real hand
   edit in a real store, reports it 100×, and reads the row back byte-identical. `differs` names fields in
   `DriftFieldNames`' declared order (exported, so T5's door and T6's classification share one spelling), and a
   re-indented schema copy is **not** drift — the comparison is the hash, which is the whole reason the row carries
   one.
4. **The engine's class gate is shown to have teeth, not trusted.**
   `TestToolsCoreIsInertAndApplierIsNotGuardAffecting` registers the real declaration with a faithful applier
   (accepted) and with a copy that reports guard-affecting (**refused**) — the second half is what makes the first
   half mean anything.
5. **`Source()` reads the whole meta table once, because the engine asks for the records per record.** Measured on
   this box with `MetaFor` called per name: **100 ms per `Source()`** — `MetaFor` is function-built (T1's rule
   against a package-level map), so 68 calls rebuilt all 68 entries — and `seed`'s `recordFor` (`engine.go:598`)
   calls `Set.Records()` **once per record**, making one startup apply of a 70-record set cost ~7 s. That broke
   `cmd/aeon`'s `controlLoopFixture`, which waits **20 s** for the daemon's startup seed to become visible
   (`loop_control_parity_test.go:287`): `TestJSONIsTheWire` and `TestYesPrintsTheStatementFirst` failed with *"the
   daemon's startup seed never became visible"*. `Source()` now takes `tools.AllMeta()` once (keeping its single
   `Registry()` and `records.Catalog()` passes): **4.8 ms**, ~20× cheaper, with `MetaFor` untouched as the per-name
   door T5 and T6 want. The general lesson for the next seeded domain — worth more than this slice — is that a set's
   `Records()` runs **O(n²)** inside the engine, so its cost is a startup property and not a per-call one.
