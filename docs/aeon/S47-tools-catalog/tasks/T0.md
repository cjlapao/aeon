### 6. Extracting `GrantedSet` (item 5): the exact logic, and what to pin first

`BuildToolset` (toolset.go:251-286) does, in order: `panic` if `tc.WorkspaceRoot == ""` → `registry := Registry()`
→ `set.granted = append([]string(nil), granted...)` (**order and duplicates kept**) → for each name, a registry
lookup, misses appended to `unknown` → if `unknown`: `sort.Strings` and return the error naming them **and**
`strings.Join(ToolNames(), ", ")` → else `set.byName[name] = tool`. So
`GrantedSet(granted []string) ([]string, error)` is precisely: validate every name against `Registry()`, return the
names **in grant order with duplicates preserved** (the SEC-051 dedupe lives later, in `Specs()` — "ONE tool, ONE
spec", first granted spelling wins the slot while `byName` keeps both), and return that error **byte-identically**.
`BuildToolset` then calls it and builds `byName` from its answer, which is what makes TC5's "the catalog and the
builder cannot disagree" structural. **Characterize before extracting**, on the three behaviours that already pin
it: `BuildToolset([]string{aliasWriteFile})` constructing a callable, class-correct, `Has()`-true toolset
(toolset_test.go:227-248), `TestGrantingBothWriteNamesOffersTheToolOnce` (toolset_test.go:~295), and the
unknown-name error's two halves. The `WorkspaceRoot` panic stays where it is — it is a programmer check, not part
of "what a grant list yields".
