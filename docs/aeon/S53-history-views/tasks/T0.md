`Merge` (query.go:89) is the merge: `ListLoops` + `ListArchives` folded into one timeline-descending sequence — an archived entry is placed by its OWN `Timeline` (ended_at, fallback started_at), a live one by `updated_at`. `Query` (query.go:254) is the ONE read both surfaces call; non-loop groupings fold `Lanes` (lanes.go:65 — by phase/task/agent regroup the LIVE steps only, so an archived loop is in the by-loop lane and in no step grouping, the honest shape). `Store` (store.go) is the protocol's read-only facade (`List`/`Show`); `Row` (row.go:38) is the ONE Entry→HistoryRow conversion; `Rollup.Render` (rollup.go:117) the ONE cost formatter.
**Decode-failure behaviour today (HV1's fact):** the merge decodes NOTHING — `ListArchives` (store/archive.go:223) reads headers only. A blob that fails to decode surfaces **only at drill-down**: `ReadArchive(id, true)` fails the WHOLE read on `ungzipBytes` error or stored-sha mismatch (archive.go:205-214), and `Store.Show` propagates it (store.go:92-99) — the protocol turns it into a generic dispatch error (protocol/history.go:167). So today the failure is **loud but late**: the entry shows in every list as if fine, and only its drill-down dies. The defect `coverage` exists to expose is exactly that — **nothing before the drill-down can say which archives will not decode**; not silently absent, silently *unprobed*. `coverage` must probe with the SAME decode code (`ReadArchive(id, true)` per in-scope archive, error ⇒ undecodable id). (Incidental: `Archive.state` is scanned by `ReadArchive` and unused — nobody decodes the state blob at all today.)
