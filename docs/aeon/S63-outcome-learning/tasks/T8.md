# T8 · The optional model retrospective

**Prefix:** RT · **Rules:** RT5, RT3 · **Depends on:** T3, T5; **S55** (a per-loop budget cap), **S48** (the seeded `retrospective`
blueprint), **S43-extra** (the `retrospective-author` agent seed), **S52** (`learning_add`, LM4/LM7), **S44** (setting
declarations). **Blocked until those merge** — T0 records which have. No other task depends on this one.

## Goal

An operator may opt in to a model-written retrospective on notable outcomes. It is capped, unattended and
outward-incapable, reads only the recorded fact record, and can file nothing stronger than `assumed`. With the setting
off (the default) none of this code runs.

## Files

- `aeon/internal/retro/model.go` — **new**: `ShouldRunModel(settings, outcome, usage) (bool, reason)` (pure), the
  fact-record serializer (`FactRecord(outcome, agents) []byte` — enums/ids/numbers only).
- `aeon/internal/daemon/retro_model.go` — **new**: starts the loop through the one `loop.start` door
  (`d.Table.StartBlueprintLoop`, F16) with `Attended=false`, `AllowOutward=false`, the S55 budget cap, blueprint
  `retrospective`, input = the fact record (as the kickoff data, not a file the agent can edit).
- Settings declarations (S44 shape, adopted here after S44 merges, S44 T10's pattern): `retro.model.enabled` (bool,
  default `false`), `retro.model.maxUsd` (default `0.25`), `retro.model.maxPerDay` (default `5`); the declaration
  **refuses `enabled=true` while S55's cap facility is absent** ("a model retrospective needs a budget cap — S55").
- Seed contributions (declared in S43-extra's engine, **owned by the sibling slices**, requested here): agent
  `retrospective-author` (grant: `read`, `learning_add` only; handler states "summarise only the facts given; do not
  invent causes") and blueprint `retrospective` (one model-step lane).
- `aeon/internal/retro/skip.go` — already skips `retrospective` loops (T2); this task adds the test that proves the
  chain cannot recurse.

## Behaviour

1. On a **notable** outcome with the setting on and today's count < `maxPerDay` for the component: start one
   retrospective loop; record `retro_outcome` for it? **No** — skipped (RT2), so it never counts and never triggers.
2. The agent reads the fact record, calls `learning_add` once (scope `project`, scope key forced to the loop's
   `component_root` by the records service, provenance forced `assumed` — S52 LM4: an agent cannot claim `observed`),
   with a body capped at 600 bytes and tags `retro`, `retro:model`.
3. A start refusal (budget, setting, rate) is logged and counted; the template learning (T3) is unaffected.
4. If the loop blocks (budget hit), the loop's own blocked reason stays on that loop; nothing is retried automatically.

## Definition of done

- [ ] Off by default; refuses without a cap; unattended/no-outward; no recursion; `assumed` only; minimal grant.
- [x] Or: recorded **"not built — blocked on <slices>"** in Notes, with T9 accounting for it.

## Do NOT

- Do not feed a transcript or any free text to the agent. Do not widen the agent's tools. Do not let the retrospective
  loop create a fact or a learning of its own through any path but `learning_add`. Do not enable by default.
