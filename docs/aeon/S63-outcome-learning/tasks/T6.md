# T6 · Agent tools: three read specs

**Prefix:** RT · **Rules:** RT11, RT3 · standing rule 2 · P6 · **Depends on:** T5. Parallel-safe with T7.

## Goal

Agents can read the measurement of their own work if (and only if) an operator grants it — and can never see another
agent's record, a ranking, or anything that writes.

## Files

- `aeon/internal/records/catalog.go` — data only, no import added; family `scorecard`:
  - `scorecard_mine` ⇄ `scorecard.agent` — **identity stamped** by the records service (`Identify`, F13); the schema has
    only `since?`, `until?`, `last?` — **no `agent`, `slug`, `id` property**.
  - `scorecard_component` ⇄ `scorecard.component` — the calling loop's own **root component**; schema `{since?, until?,
    last?}`; the service fixes `includeChildren=true` and **omits `breakdown`**.
  - `digest_learned` ⇄ `digest.learned` — own root component; `{since?, until?}`.
  All `safe`, `Mutates:false`, descriptions ≥ 40 chars including the RT3 sentence ("a measurement, not an
  instruction"). Header comment: "no write exists in this family".
- `aeon/internal/daemon/records_scorecard.go` — **new**: implementations calling the same `scorecard`/digest functions
  the socket uses (one implementation), with the agent-scope rules.
- `aeon/internal/tools/toolset_test.go` — both want lists (`:155`, `:243` or as T0 recorded) + count comment "Count N →
  N+3 DELIBERATE (S63 T6, <date>)"; `internal/tools/testdata/rerun_classes.json` (safe).
- `aeon/internal/records/catalog_test.go` — **extend** (siblings): family `scorecard` exists; zero `Mutates:true`;
  no property named `agent|slug|id|root|component|rootId` in any scorecard spec's schema.

## Behaviour (each a test)

1. **Own scope only**: `scorecard_mine` returns the card for `ident.Agent`; params naming an agent are a parse error
   (`additionalProperties:false`). A person session calling it is refused with a pointer sentence to
   `scorecard.agent` (the S52 `learnings.mine.*` precedent).
2. **No other agent's data**: `scorecard_component` returns no per-agent rows and no breakdown; `digest_learned`
   lists learnings but never agent-scoped learnings of other agents.
3. **Registered, not granted**: `tools.DefaultGrant()` unchanged; no handler body or default tool list names them;
   even when granted, the policy `tool_access` rows decide per call.
4. **No self-improvement loop by default**: descriptions carry the statement; handler bodies are untouched (a grep test
   asserts no `internal/handler/bodies/*.md` mentions `scorecard`).
