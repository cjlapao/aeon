## The schema

```text
retro_outcome(
  id INTEGER PRIMARY KEY, component_root TEXT NOT NULL, loop_slug TEXT NOT NULL,
  terminal_key TEXT NOT NULL,                       -- RT2 idempotency (event seq, else status+updated_at; T0 decides)
  outcome_kind TEXT NOT NULL,                       -- done | aborted | blocked/<kind> | blocked/other:<kind> (≤ 48)
  blueprint_id TEXT NOT NULL DEFAULT '', blueprint_version INTEGER,
  started_by_kind TEXT NOT NULL DEFAULT '', attended INTEGER,          -- NULL stays NULL
  goal_id TEXT NOT NULL DEFAULT '', goal_version INTEGER,
  wall_ms INTEGER,
  cost_usd_floor REAL, cost_steps INTEGER, cost_partial_steps INTEGER, cost_unknown_steps INTEGER,
  tasks_done INTEGER, tasks_failed INTEGER,
  retries INTEGER, review_rounds INTEGER, security_rounds INTEGER, qa_rounds INTEGER,
  total_failed_gates INTEGER, splits_done INTEGER, escalations INTEGER,
  unverified_steps INTEGER, verified_pass INTEGER, verified_fail INTEGER,
  complete INTEGER NOT NULL DEFAULT 1 CHECK (complete IN (0,1)),
  source TEXT NOT NULL DEFAULT 'recorder' CHECK (source IN ('recorder','backfill')),
  recorded_at TEXT NOT NULL,
  UNIQUE (component_root, loop_slug, terminal_key));        -- any column NULL = not recorded (P31), never 0
retro_agent(
  id INTEGER PRIMARY KEY, outcome_id INTEGER NOT NULL REFERENCES retro_outcome(id),
  agent TEXT NOT NULL, agent_slug_known INTEGER NOT NULL DEFAULT 1,
  steps INTEGER, steps_done INTEGER, steps_rejected INTEGER, steps_blocked INTEGER,
  verify_pass INTEGER, verify_fail INTEGER, verify_unverified INTEGER,
  cost_usd_floor REAL, cost_partial_steps INTEGER, cost_unknown_steps INTEGER, agent_ms INTEGER,
  UNIQUE (outcome_id, agent));
retro_learning(
  outcome_id INTEGER PRIMARY KEY REFERENCES retro_outcome(id), learning_id INTEGER NOT NULL, written_at TEXT NOT NULL);
retro_template(
  kind TEXT PRIMARY KEY, version INTEGER NOT NULL, template TEXT NOT NULL, origin TEXT NOT NULL DEFAULT 'system'
  CHECK (origin IN ('system','user')), created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
```

Indexes: `retro_outcome (component_root, outcome_kind)`, `(blueprint_id, recorded_at)`, `(recorded_at)`,
`retro_agent (agent)`. **No FK** from a fact to `loop` or `learning` (history/learnings outlive each other — P3); the
`retro_agent → retro_outcome` FK is within the fact set only.

Append-only by trigger (the repo's trigger convention, timestamped files can carry bodies — S44 T0 3.1 / T0 here
verifies): `retro_outcome_no_update`, `retro_outcome_no_delete`, same for `retro_agent` and `retro_learning`
(`RAISE(ABORT, 'retro facts are append-only')`). `retro_template` is mutable (seed engine upserts it).

## Store functions

`RecordRetroOutcome(RetroOutcome, []RetroAgent) (id int64, inserted bool, err)` — **one transaction**, `ON CONFLICT DO
NOTHING` on the unique key (a replay returns `inserted=false`); `RetroTally(root, kind string) (int, error)`;
`RetroOutcomeByID`; `ListRetroOutcomes(RetroFilter{Root, Agent, Blueprint, Outcome, Since, Until, Limit, Cursor})`;
`RetroAgentsFor(outcomeID)`; `LinkRetroLearning(outcomeID, learningID)` (insert-only); `UnlinkedMilestoneOutcomes(root?,
milestones []int)` (the reconcile query); `RetroCoverage() (since string, loops int, dropped int)`;
`CountRetroDropped/IncRetroDropped` — the dropped counter is **a row-less in-memory counter owned by the daemon**, not a
table (no second truth to drift): the store exposes none. Template CRUD for the seed engine: `UpsertRetroTemplate`,
`GetRetroTemplate`, `ListRetroTemplates`.
