# T7 · The CLI: `aeon scorecard`, `aeon retro`

**Prefix:** RT · **Rules:** RT10, RT12, RT13 · standing rule 1 · P5 · **Depends on:** T5. Parallel-safe with T6.

## Goal

Everything the socket answers, the CLI prints — as a pure client — and the backfill is reachable by a person. No CLI
verb exists for any of this today, so there is nothing to keep compatible: the parity table (T0) is the fixture.

## Files

- `aeon/cmd/aeon/scorecard.go` — **new**: `aeon scorecard agent SLUG|blueprint ID|component ID [--children=false] [--since
  RFC3339] [--until RFC3339] [--last N] [--root ID] [--json]`, `compare KIND SUBJECT --a SINCE..UNTIL --b SINCE..UNTIL`,
  `vocabulary`.
- `aeon/cmd/aeon/retro.go` — **new**: `aeon retro list [--component ID] [--agent SLUG] [--blueprint ID] [--outcome
  KIND] [--since] [--limit]`, `show ID`, `status`, `backfill [--yes]` (dry-run unless `--yes`), `digest ID [--since
  --until]`.
- `aeon/cmd/aeon/main.go` — usage text and verb dispatch for `scorecard` and `retro`.
- `aeon/cmd/aeon/scorecard_parity_test.go` — **new**.

## Behaviour

- Every verb: `dial(*want)` → `c.Call(method, params, &out)` → print. `--json` prints the wire result verbatim. The CLI
  **re-validates nothing**: flag parsing refuses only what cannot be a value (a non-RFC3339 time); everything else is
  the daemon's sentence verbatim.
- Human output: each metric as `name  value  (n=…)  [state]`, `too-few` and `cannot-say` printed as words, floors as
  "at least $X (K of N steps unknown)", the coverage line first, the RT3 statement last. No colour-only meaning. No
  ranking and no sort-by-score flag exists.
- `retro backfill` without `--yes` prints the dry-run preview and the sentence "nothing written; pass --yes to
  write"; `--yes` is a seatbelt (P5), not a security control.
- No offline fallback (none of these reads has a no-daemon use; recorded deviation from P5 — the scorecards read
  recorded facts the daemon owns; a stopped daemon says so with the standard dial error).

## Notes

Built 2026-11-05 (merged to main the same day).

**The two files.** `cmd/aeon/scorecard.go` (335) and `cmd/aeon/retro.go` (374) — pure clients, proven
by import rather than comment: `TestScorecardVerbsNeverOpenTheStore` PARSES both files' imports
(`go/parser`, ImportsOnly) and allows nothing outside `encoding/json, flag, fmt, io, sort,
strconv, strings, time` + `internal/protocol`. No `internal/store`, no plane package — which means
`scorecardImportAllow` in `retro_guard_test.go` was NOT exercised: the CLI renders wire types
(`MetricWire` et al.) and needs no import of the plane (recorded, so the next reader does not go
looking for a payment that isn't owed). Both share one code path each (`scCall`/`retroDoor`:
dial → `c.Call(method, params, &json.RawMessage)` → print raw bytes for `--json`, else decode and
print), so `--json` can't drift from the human path's source. `var scDial/retroDial = dial` — the
mqDial idiom; the offline law is dial's own words, and the walk PROVED the no-fallback deviation
standing (below).

**Flag law held.** Parsing refuses ONLY what cannot BE a value (a non-RFC3339 `--since/--until`,
`retro show` needing a numeric id). Everything semantic is the daemon's sentence.
`TestCLIRefusalsAreVerbatim` pins that sentence's arrival: `renderError` lays the door's
`protocol.Error` down — message, what, means, todo — every non-empty part appears UNCHANGED in the
CLI's output; the test asserts each part by containment (this family's verbatim: the S47 error
shape, not one flat string).

**The printed card** (`printCard`/`formatMetricLine`, one metric-line shape shared by the card and
the digest's round metrics): coverage line first, window, subject, metrics ALPHABETICAL
(presentation, not rank — `TestNoRankingFlag` regex-walks every `fs.*` flag name in both files for
sort/rank/best/worst and finds none), each line `name  value  (n=…)  [state]`; a NULL value prints
"—" (never a zero) with its state word; the cost metric's value is the store's own
`detail.rendered` floor sentence ("at least $X (K of N steps unknown)"), never a re-render; the
RT3 statement prints LAST from the answer's own field — no copy of the sentence in the CLI (RT3's
one constant stays upstairs). `printDigest` walks RT12's seven sections in field order; the
digest's quoted sentences ride through verbatim (one-formatter law).

**Backfill — RT13, found by walking the door's own law.** `retro.backfill` defaults to the preview
server-side (`dryRun := true` unless the param says otherwise) AND refuses a write that lacks
`yes: true` — the door demands BOTH words. The first CLI sent only `yes:true` and got… another
preview (`TestBackfillDefaultsToDryRun` caught it: "the --yes run still previewed"). Fixed in the
CLI to send `dryRun:false, yes:true` together — obeying the law, not paraphrasing it. Without
`--yes` the print adds exactly one sentence — "nothing written; pass --yes to write" — beside the
door's preview counts. `TestBackfillDefaultsToDryRun` then proves: preview writes NOTHING, `--yes`
writes the one eligible row, and `learningsWritten` stays 0 (RT13: outcomes are facts; lessons are
the reactor's).

**Dispatch, pinned S53's F-1 way.** One `case "scorecard", "retro":` in `main.go` with the
`verb == "scorecard"` selector, both callees, and BOTH usage lines pinned by
`TestScorecardVerbsAreDispatchedByTheBinary` — and the pin EARNED its keep: the first draft tested
`args[0]`, but `main.go` slices `args := os.Args[2:]` so the verb lives in `verb`; the
real-binary test (not the static one) walked `aeon scorecard agent …` into cmdRetro's usage text.
Pinned so the class dies here.

**Parity both ways.** `cliVerbRows` is the ten-method ⇄ ten-verb map (scorecard: agent, blueprint,
component, compare, vocabulary; retro: list, show, status, backfill, digest).
`TestEveryScorecardMethodHasAVerb` reads the two files' sources and demands a `case "verb":` per
method; `TestEveryVerbNamesAMethod` regex-walks both switches the other direction — an invented
verb is as loud as a missing one. `TestScorecardJSONIsTheWire` runs EVERY verb (plus `retro show`
with the id the list itself printed) through the REAL binary against a census daemon and compares
byte-for-byte with a second, direct socket Call of the same method+params — nine verbs + show, all
identical.

**The census daemon** (`censusDaemon`): seed-before-start (the learnings-parity pattern) — two
`RecordRetroOutcome` rows (done + blocked, agent atlas, blueprint census-blueprint, costs, wall,
rounds) into a fresh store, then `startDaemonInStateDir`. It surfaced one honest display fact:
agent-scope cards carry six metrics (`loops, stepsRun, costPerStep, stepRejectRate, verifyFailRate,
verifyUnverifiedRate` — scope-dependent sets, T4's design), so the golden asserts n-and-state on
