# T3 · The retrospective learning: milestones, templates, the `retro.templates` seed set, reconcile

**Prefix:** RT · **Rules:** RT4, RT4a, RT16 · P8 · **Depends on:** T1, T2; S28 (built); **S43-extra T3** (the seed
engine).

## Goal

From recorded facts, file bounded, honest, template-rendered `observed` learnings through S28's one write path — at
milestones, never as a flood, never with free text — and ship the templates as a seeded, versioned record set.

## Files

- `aeon/internal/retro/learn.go` — **new**: `Notable(Outcome) bool` (RT4a, one function), `Milestones` constant
  (`1,3,10,30,100,300,…`, generated by ×3.33 steps to 10^6 — one definition), `Render(template, Facts)` with the closed
  placeholder set, `Write(ctx, Deps, outcomeID)`.
- `aeon/internal/retro/templates.go` — **new**: the placeholder registry (`{count, outcome_kind, blueprint,
  rounds_review, rounds_security, retries, gates_failed, cost_floor, cost_state, wall, escalations, window}` with
  type and formatter each), `Validate(template) error`.
- `aeon/internal/retro/seed/` — **new**: `Source() []seed.Record` (one template per outcome-kind family:
  `done-with-rework`, `aborted`, `blocked`, `unverified`, plus `default`), `Applier` (`Upsert/Fingerprint/Retire/
  GuardAffecting=false/Operator={Edit:false,Remove:false}`) writing through `store.UpsertRetroTemplate`.
- `aeon/internal/seed/decl_retro.go` — **new**: registers set `retro.templates`, class **inert**, applied at daemon
  start and by `aeon init`; per-record `Version` guarded by a golden.
- `aeon/internal/daemon/retro_reactor.go` — after a successful `RecordRetroOutcome`, call `retro.Write` (same
  goroutine); `aeon/internal/daemon/retro_reconcile.go` — `ReconcileRetro(ctx)` at startup (after the seed set applied,
  before the recorder is armed).
- `aeon/internal/retro/testdata/` — template goldens.

## Behaviour

1. After an outcome row is inserted, compute `n = RetroTally(root, kind)`. If `Notable(outcome)` and `n ∈ Milestones`
   and no `retro_learning` row exists for the outcome: render and `learnings.New(store).Append(AppendInput{Scope:
   project, ScopeKey: component_root, Body, Provenance: observed, ObservedCount: &n, SourceLoopSlug, Tags:
   [retro, retro:outcome:<kind>, retro:blueprint:<id>]})`; on success `LinkRetroLearning`. A `*Refusal` is logged;
   reconcile retries it.
2. **Render** reads the template row from `retro_template` (the **row**, never code — rule 6), substitutes only closed
   placeholders; every value is an enum, integer or formatted floor. A template with an unknown placeholder fails
   `Validate` at seed time and render time (the render refuses; no learning is written; a log names the template).
3. Cost rendering reuses the P32 sentence shape ("at least $X (K of N steps unknown)") from `history`'s renderer — call
   it, do not copy it.
4. **Reconcile**: `UnlinkedMilestoneOutcomes(Milestones)` ⇒ write each missing learning once; idempotent (link row is
   the lock).
5. The body never contains the loop slug's goal, task titles, reason detail, agent output or model output; tags carry
   only kind and blueprint id.

## Commands

P10, `./internal/retro/... ./internal/daemon/ ./internal/seed/ ./internal/learnings/ -run 'Retro|Notable|Milestone|Template|Reconcile|Seed' -count=1 -race -v`.

## Definition of done

- [ ] Milestone-only, template-only, one write path; reconcile idempotent; seed set with golden; no free text provable.

## Do NOT

- Do not bump a learning's observed count (no API; M3). Do not write `told`, `assumed` or `relayed` here. Do not call
  a model. Do not read code-defined templates at runtime. Do not edit the triage feed or S28 code.
