# T2 · The recorder: a reactor at the existing emission point, and the optional backfill

**Prefix:** RT · **Rules:** RT2, RT6, RT9, RT13 · **Depends on:** T1.

## Goal

Every ordinary loop's `loop.finished`/`loop.blocked` writes its facts — without delaying the event path, without
ever claiming more than it read — and a human can dry-run and apply a backfill of earlier loops from history.

## Files

- `aeon/internal/retro/` — **new package**, write side. `record.go` (`Compose(ctx, st Reader, ev Event) (Outcome,
  []Agent)` — pure over a `Reader` interface so tests need no daemon), `kinds.go` (reason-kind normalization,
  closed prefix + `other:<kind>` cap 40), `skip.go` (skip rules). Imports `internal/store` interfaces only, no
  `loop`/`runtime`/`policy` (RT3.2 guard in T5).
- `aeon/internal/daemon/retro_reactor.go` — **new**: `onRetroTerminal` (goroutine, never blocks — V18) +
  `handleRetroTerminal`; the in-memory `retroDropped` counter (atomic), last-write time.
- `aeon/internal/daemon/blueprint.go` — **one added call** in `publishLoop`'s terminal block (`:602`), beside the queue,
  roadmap and triage calls, with a comment citing RT2. No other edit.
- `aeon/internal/daemon/retro_backfill.go` — **new**: `RetroBackfill(ctx, dryRun)` over `history.Merge` (history is the
  read source; RT13) — returns the preview counts, writes `source='backfill'` rows only when not dry-run.

## Behaviour

1. **Skip** (record nothing, log at info): `triage-validate-*` slugs; loops whose pinned blueprint id is `retrospective`;
   `loop.run.finished`; a loop with no readable pin.
2. **Compose** per RT2's table. Each unreadable field → NULL, `complete=0`, one log line naming the field. The
   floor is `LoopCost` (never re-summed); wall from `loop_run` else NULL; reason kind from the event reason's leading
   token via the closed list T0 recorded.
3. **Agents**: group the loop's steps by agent; resolve slug via the agent row (`agent_slug_known=0` if unresolved);
   counts from step status/outcome and handoff verdicts; cost per agent as a floor with partial/unknown counts.
4. **Write**: `RecordRetroOutcome` once; on any error increment `retroDropped`, log, return (no retry loop here — the
   next event is independent; reconcile (T3) covers the learning half).
5. **Backfill** (`retro.backfill` socket method lands in T5; the function lands here): history rows for loops with no
   `retro_outcome` ⇒ outcome rows with status, started/ended, floored cost, blocked kind from the stored reason,
   everything else NULL and `complete=0`; archived loops only for fields T0 §3 says survive. Dry-run returns counts by
   outcome kind and "would write N, skip M (already recorded)". Never writes a learning (RT13).
6. The recorder never starts a loop, edits a setting or calls any package that can (RT3.2).

## Commands

P10, `./internal/retro/ ./internal/daemon/ -run 'Retro|Recorder|Backfill|PublishLoop' -count=1 -race -v`.

## Definition of done

- [ ] Facts recorded for finished/blocked loops; non-blocking proved; null-not-zero; dropped counter; backfill dry-run
  default and history-only.

## Do NOT

- Do not read loop text, task titles, briefs, transcripts or reason detail into a fact. Do not retry in a loop inside the
  reactor. Do not change any existing reactor. Do not write learnings here.

**Decisions and deviations — the ones a reader cannot re-derive from the code:**

- **`verified_pass` is NULL on EVERY recorder row and every recorder row is `complete=0`.** T0 §1.9's
  measurement, re-verified while building: a `done` step cannot tell a handoff that DECLARED
  `verification=pass` from one that said nothing — the engine only refuses the DECLARED `unverified`
  (`handler/handoff.go:175` turns an ok-handoff declaring unverified into a reject; silence passes).
  Counting `done` steps as passes would fabricate the declaration. The NULL is permanent-by-design and is
  named in `missing` (so it logs like any unreadable field); T4's scorecard `partial` state exists for
  exactly this and must be read as the honest posture, not a degradation to fix.
- **T0 §1.3 correction:** `loop.finished`'s status vocabulary measures `done|aborted` — S55's cancel sets
  the aborted flag and `endStatus` produces `aborted`; `cancelled` is the **loop_run STATE word**
  (`rest.go:47`), not an event status. `OutcomeKindForFinished` passes all three words through anyway
  (defensive mapping), and any other word becomes `other:finished-<token>` — the `other:` namespace
  WITHOUT the `blocked/` prefix, because an unknown finish status is not a block. (The schema CHECK is
  length ≤48 only — the closed vocabulary is a code-side law, T1's design.)
- Blocked kinds: the 18 T0 measured; tail capped at 40 then again at 48 total (`blocked/other:` eats 14).
  The engine's `step-<outcome>` reasons are unmapped → `blocked/other:step-reject` etc.
- Reason arrives in TWO shapes at the reactor: the engine's `*loop.BlockedReason` struct and plain strings.
  The duck-typing lives in the daemon (`retroReasonKind`), not in retro — RT3.2 keeps the import out.
  Consequence measured for the backfill: history's `blockedReason` reads only a STRING payload, so
  struct-payload blocks surface there as `blocked/other:unknown` while the recorder stores the true kind.
- `qa_rounds`/`total_failed_gates`/`splits_done` come from the pinned loop row's own columns — same data
  `loop` would offer, without the import. Wall = the LAST ENDED `loop_run`'s span, else NULL (a running
  tail row is not a span). `agent_ms` NULL in practice: nothing in production writes `step.agent_ms`
  (measured); Compose sums it when present.
- Steps with an empty agent belong to no agent row — counted nowhere, nobody invented.
- Test seam `var retroCompose = retro.Compose` in `retro_reactor.go`: the only way to hold a stuck
  recorder without slowing the store for every other reactor's tests; production never reassigns it.
- **P10 deviation:** the spec command carries `-race`; the sandbox cannot run tsan (ENOMEM) — the suite
  ran WITHOUT `-race` throughout. Recorded, as P10 demands.
- Backfill dry-run is the default at this layer (the socket method with `--yes` lands in T5); archived
  loops contribute header fields only (T0 §3 survival), no agent rows, and the `retrospective` skip is
  pin-visible for live loops only — an archived loop's blueprint was never recorded, so an archived
  retrospective loop would be indistinguishable and gets recorded as-is (honest RT13 limit).
