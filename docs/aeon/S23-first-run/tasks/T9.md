# T9 — The timed measurement

## Why this exists

**Alone** (R7), and last. *A task that both polishes and measures will report the measurement it wanted.*

**This is the only Definition of Done in seventeen slices that a machine cannot evaluate**, and the only task in the plan
whose gate is a person rather than a test.

## Scope

### The measurement (D1, C14)

Hand a tester:

- A **clean machine** — fresh container or VM — with the binary available and nothing configured.
- **One API key.**
- The **README**, or its URL.
- **Nothing else.** No instructions, no hints, no *"you probably want to…"*.

Ask them to get a loop running against a small repository. **Start the stopwatch.**

**Under five minutes is a pass.**

### Per provider, with different testers (C21)

**Repeat for each of the three presets**, ideally with a different tester each time.

One tester on one provider is one data point, and the three have different friction — **the OpenAI-compatible path asks a
question the other two do not** (a base URL), which is exactly where a stranger is most likely to stop.

### The tester has not read the design (C14, C2 of the self-check)

**This is not negotiable and it cannot be worked around.**

Every author of every onboarding flow believes theirs is clear. A tester who has read the design knows which flag exists,
and **their five minutes are not a stranger's.**

**If no such person is available, the slice is not done.** You cannot self-certify a first-run experience.

### Record, and record on a pass too (O1, O2)

`FIRSTRUN-LOG.md`, committed:

- **Their exact words**, not a paraphrase (O1). *"I didn't know if I needed a project first"* names a missing sentence;
  "confused about setup" does not — and a paraphrase is what the second one is.
- **Every question they asked.** Each is a failure of the previous screen, and **the question is more valuable than the
  answer.**
- Anything they typed that did not work.
- Where they hesitated, and for how long.
- The clock time when a loop was running.

**Recorded even on a pass** (O2). A four-minute run with a forty-second hesitation has found a problem, and a pass that
records nothing throws it away.

### If it takes longer

`aeon-cli.md`'s QAC2-01 puts it best and the wording is worth keeping: **a twenty-minute result is not a slow tester; it is a
list of places the product failed to explain itself.**

So the finding is **which question cost the time** — never that the target was optimistic.

And if that question exists because of an earlier slice — a capability that needs configuring, a route that needs
hand-writing — **that is a finding about that slice** (N8), recorded as one rather than papered over with documentation.

§2 to §7: `init` asking about providers; a key in config refused; errors that say what to do; `doctor` telling the truth

**§5 is the one to read carefully.** If any line reads "ok" over something uncertain, six slices of design work have been
discarded at the last possible moment.
