# T5 — `forge.openIssue` and `forge.openPR`

## Notes — built tests-first 2026-10-25

**Found by searching, pinned three ways.** (1) Behaviour: the issue is found with the stored number
gone, and a caller remembering #7 while the forge holds #9 loses — the forge decides. (2) Structural:
`OpenIssue`/`OpenPR` take no int parameter at all (reflection) — a stored number cannot be passed IN
even by accident. (3) The fake's call log: the second run issues a search and no create, per action, in
separate subtests (D1/O6/C2).

**`BranchProbe` is one method wide — a type guarantee, not a behavioural one.** openPR CANNOT recreate
the task branch because branch creation is not expressible through the probe at all; the task's
"rather than recreating" assertion became a compile-time fact, and the test says so rather than
counting commands that cannot exist. The branch-absent half keeps a behavioural teeth: blocked with
`head-missing`, naming commitAndPush as the way forward — opening a PR against a ref nobody can fetch
is O8's phantom-ref failure at the forge boundary, refused rather than opened.

**Conflict (a race to open) resolves with ONE re-search, never a retry loop** — a FailMethod(conflict)
fixture would otherwise spin the recursion the first draft had. Found → Reused; still nothing → the
conflict error surfaces.

**`open` is part of the check** — the fake's closed-state seed proves a deliberately-closed record is
not resurrected (new number opens), and FindOpenIssue matching on exact title plus `dev-loop` keeps the
search scoped to loop-opened issues. The PR key is the HEAD REF — the same-title-different-head decoy is
seeded alongside to prove title never participates.

**Evidence (Q7)**: numbers return in ForgeResult AND land in the injected sink as
`issue_number=`/`pr_number=` state rows and `forge.openIssue: N` transcript lines; T10 wires the sink to
the real store, tests wire a recorder — the seam exists NOW so the evidence path is testable before the
wiring exists.

**BlockedError is a distinct type from ForgeError refusals** (O5): transport and refused pass through
with their kinds intact (the classify seam flattens nothing — a flattening mapper would turn "your
network is out" into "the forge said no", which retries differently and tells a different sentence to a
human).

## Why this exists

The two actions that create outward-facing records, and the two where a duplicate is most visible: two issues for one
task, or two PRs for one branch, in a repository other people are reading.

## Scope

| Action | Class | The check |
| --- | --- | --- |
| `forge.openIssue` | `outward` | Search **open** issues for the exact title `[{taskid}] {task title}` with label `dev-loop`. Found → return its number |
| `forge.openPR` | `outward` | An **open** PR whose `head` is `task/{loopSlug}/{taskid-slug}`. Found → return its number. **Also: if the task branch exists, reuse it rather than recreating** |

### Found by searching, not by remembering (D1)

Both checks query the forge. **Neither trusts a stored number.**

That matters because the stored number may be missing — a crash between creating and recording is exactly the case S7
was built for — and because a stored number may be *stale*: an issue closed and reopened, a PR closed manually. The
forge is the truth about the forge.

The search keys are the reason this works: an issue's **exact title plus label**, and a PR's **`head` ref**. Both are
natural business keys, which is why these two need no receipt (contrast T7's `postReview`, which has none).

### `open` is part of the check

Searching **open** issues, not all issues. A closed issue for the same task means the task was done and reopened work is
a new issue — reusing a closed one would resurrect a record someone deliberately closed.

### Evidence is returned and recorded (Q7)

Each action returns its number, which lands in loop state and the transcript. That is what a later `forge.merge` or
`forge.closeIssue` reads, and what a template renders.

### Governance

Both are `outward`, so both ask (T2). And in an unattended loop, both are denied — **which means an unattended loop
cannot open a PR unless someone opted in at start.**

## Tests

| Test | Asserts |
| --- | --- |
| `TestEachOpenActionTwiceIsANoOp` | **Per action**, on the fake's call log: the second run issues a search and **no create** (D1, O6, C2) |
| `TestIssueFoundBySearchNotByMemory` | With the stored number deleted, the action still finds the issue. And with a **stale** stored number, the search wins |
| `TestClosedIssueIsNotReused` | A closed issue with the same title does not satisfy the check — a new one is opened |
| `TestPRFoundByHeadRef` | The `head` ref is the key; a PR with the same title but a different head does not match |
| `TestExistingTaskBranchIsReused` | Rather than recreating it |
| `TestEvidenceIsRecorded` | The issue and PR numbers reach loop state and the transcript (Q7) |
| `TestBothAreOutwardAndAsk` | And both are denied unattended (T2) |
| `TestTransportFailureIsNotARefusal` | An unreachable forge yields `blocked` with a transport reason, distinct from "the forge said no" (O5) |

`TestIssueFoundBySearchNotByMemory` with a **stale** number is the half people skip. Deleting the number tests the crash
case; a wrong number tests the case where somebody closed the issue by hand.
