# T9 — `pr_summary`, and what code can and cannot check about prose

## Notes — built tests-first 2026-10-25

**Q9 ANSWERED — the thresholds, committed in `prose.go` and pinned by TestThresholdsAreCommitted**:
minimum **120 RUNES** (not bytes — non-English summaries are real; 120 is two ordinary sentences, below
which a fragment is posing as a paragraph) and restatement slack **15 runes** beyond a title-prefix
match. The placeholder check compares normalized text against the COMMITTED templates' own token
spellings — one class, not an enumeration someone must maintain.

**Check ORDER is a finding**: restatement is judged BEFORE the floor, deliberately — a PR title is
always under 120 runes, so the naive order made every title-restatement report as "too short" (the red
this session). The deeper diagnosis must be the one that names itself.

**The N4 test evolved, not deleted**: S13's `TestPrSummaryIsNotHere` pinned the guard that was built to
be lifted when the reader arrived; T9 replaces it with three tests that are STRICTER, not looser — the
field is legal, but its Purpose is enforced verbatim at load (`the paragraph a human will read on the
pull request`), because "a field described as 'a summary' gets a restatement of the title" and twenty
bodies must not each paraphrase the contract of the one paragraph a human reads. S13's
missing-field-still-rejects behaviour now covers pr_summary for free — it IS a declared field.

**Drop-record accounting caught the edit honestly**: adding one handoff line to thirteen bodies moved
their rewrite counts, and `TestDropRecordsAccountForTheDelta` failed the arithmetic (original + added =
rewrite + removed) until each of the thirteen drop records recorded the honest `+1 added` — a
declared-but-unaccounted line is exactly the "omission nobody reviewed" the arithmetic exists to stop
(D6). The `only-PR-reaching-handlers` set excludes security-engineer by stated reason (audits rather
than ships), and the test checks BOTH directions against the bodies on disk.

**TestQualityIsNotChecked passes against a fluent lie** — a well-formed paragraph about a pizza module
for a version-endpoint PR sails through, on purpose; it is the limitation written down so nobody later
mistakes shape checks for a quality gate (D12/C9).

Counts dated 2026-10-25: internal/action **60** (T9 adds 5), internal/handler **97** (N4's one test
became three).

## Why this exists

L3: *"the authored paragraph comes from the upstream step's handoff"*, and every step handoff gains `pr_summary` —
**"the paragraph a human will read on the PR"**. S13's T3 built the mechanism and deliberately left the field to this
slice (N4), because this is what reads it.

Measured against v1's `git-loop`, the authored surface is **one paragraph per PR plus the review body**. Everything else
is a template. This task is that one paragraph.

## Scope

### Declared where it is produced

`pr_summary` is declared by handlers whose output can reach a PR body — **not universally.** A handler that never runs in
a PR-producing lane declaring it would be noise, and a declared-but-unused field is a field nobody maintains.

T8's load-time validation is what makes this safe: if `pr-body.md` names `{{pr_summary}}` and the producing handler does
not declare it, that is `invalid` at load rather than an empty paragraph at PR time.

Its `Purpose` (S13's O6) is the framing itself: *the paragraph a human will read on the pull request*. That wording is
the specification — a field described as "a summary" gets a restatement of the title.

### A missing field is already handled

S13's T3 made a declared-and-absent field a **`reject`**. Nothing new is needed for the missing case.

### A stub is refused (L21, D12, O4)

Present-but-useless is the new case:

| Refused | Because |
| --- | --- |
| Empty or whitespace | Nothing to read |
| Identical to the template's placeholder text | The model echoed the instruction |
| Shorter than a floor | A sentence fragment is not a paragraph |
| A restatement of the PR title | Adds nothing a reader does not already have |

**Answer Q9**: the exact thresholds. State them, because a floor nobody wrote down gets adjusted until it passes.

The refusal is a **`reject`**, routed by the blueprint (O4) — the handler can be asked again; a failed loop cannot.

### Code cannot check quality, and does not pretend to (L21, D12)

**The stub checks are existence and shape, not quality.** A well-formed paragraph that is wrong, or misleading, or
describes a different change, passes all of them.

That is the honest limit, and it is recorded as a test (D12) so nobody later mistakes the stub check for a quality gate
— or worse, adds a "quality score" and puts a number nobody should trust in front of something outward-facing.

The control that does exist for quality is the same one that exists for a handler's code: **a human reads the PR.** The
`ask` on `forge.openPR` (T2) is where they see it.

## Tests

| Test | Asserts |
| --- | --- |
| `TestStubSummaryIsAReject` | Each refused case — empty, whitespace, placeholder-identical, below the floor, title-restating — yields a **`reject`** naming the reason, not a hard failure (D12, O4) |
| `TestQualityIsNotChecked` | A well-formed paragraph describing **the wrong change** passes. **A test that records the limit** so nobody mistakes the stub check for a quality gate (D12, C9, L21) |
| `TestOnlyPRReachingHandlersDeclareIt` | Handlers outside PR-producing lanes do not declare `pr_summary`; a declared-but-unreachable field is a finding |
| `TestPurposeIsTheFraming` | The declared `Purpose` says *the paragraph a human will read on the pull request*, not "a summary" |
| `TestMissingFieldStillRejects` | S13's T3 behaviour unchanged |
| `TestThresholdsAreCommitted` | Q9's numbers are in code with a comment, not scattered as literals |
| `TestRejectRoutesToRework` | The blueprint's `rework` target handles it, and the redo round is consumed (S8's L4) |

`TestQualityIsNotChecked` is an unusual test — it asserts a limitation. It is worth writing because the alternative is
someone later reading the stub checks as a quality gate and trusting them for something a person should have read.
