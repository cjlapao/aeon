# T1 — The `Forge` interface and its fake

## Notes — built tests-first 2026-10-25

**Tests written before the implementation**, as the file says: `fake_test.go` first, then `forge.go` and
`fake.go` to answer it. Gate green on the full run: `TestFakeReportsBaseRef`, `TestFakeRecordsEveryCall`,
`TestFakeScenarios` (six scenarios), `TestForgeErrorKindsAreDistinct`, `TestNoNetworkInAnyTest`,
`TestInterfaceIsTypedNotGeneric`. **Count dated 2026-10-25: `internal/forge` 6** (top-level `--- PASS`,
measured; the scenario test's six subtests ride inside one of them).

Three decisions the spec left open, recorded:

- **`Find*` answer absence with `(nil, nil)`, `Read*` with `KindNotFound`.** Absence is what routes
  check-then-act to its create step — the normal answer — while reading a numbered thing that must exist
  and isn't there is a domain error. The five kinds stay exactly as specced; this is which side of the
  line each method sits on.
- **`SeedPR` panics without `BaseRef`.** L26 says the field is required; a fake that quietly accepts a
  base-less PR would let T6's guard scenario be written wrong and pass. The panic is the fake refusing to
  hold a scenario that cannot be trusted to speak about merges.
- **The log records the call BEFORE the injected failure answers** — a refused call still belongs on the
  log; "what did the code try, in what order" must include the attempts that failed, or D1's surface
  under-reports retries.

**One trap measured while writing `TestNoNetworkInAnyTest`:** the banned-token list indicts its own file
(the literals `os.Getenv`, `https://`… sit in the test that greps for them), so the tokens are built by
concatenation — `os.` + `Getenv` — and the test indicts only the package. **T11's note:** this grep walks
the whole package; when `github.go` arrives it must be **excluded by rule, not by deletion** — the guard
is what keeps O7 true for every other file, and T11's own `TestNoOtherTestGrewANetwork…` is the
counterpart. `t.Fatal` on a `github*` filename is correct only for T1's state and was named as such here
rather than left for T11 to trip over.

## Why this exists

**First, because every later task's tests depend on it** (R4, L26) — and it is the reason the automated suite never needs
a network or a token (O7). A unit suite requiring both is a suite people stop running, and this is the slice where a
skipped test has outward-facing consequences.

## Scope

### The interface

Typed, with named methods rather than a generic call. `Forge` is what keeps a second implementation possible: **a typed
interface with per-forge implementations beats discovering a tool by function and hoping**, which is what v1's runtime
MCP tool-name discovery did.

```go
type Forge interface {
    FindOpenIssue(ctx context.Context, title string, label string) (*Issue, error)
    OpenIssue(ctx context.Context, req IssueRequest) (*Issue, error)
    ReadIssue(ctx context.Context, number int) (*Issue, error)
    CloseIssue(ctx context.Context, number int) error

    FindOpenPR(ctx context.Context, head string) (*PR, error)
    OpenPR(ctx context.Context, req PRRequest) (*PR, error)
    ReadPR(ctx context.Context, number int) (*PR, error)
    MergePR(ctx context.Context, number int, method MergeMethod) (*MergeResult, error)

    ListReviews(ctx context.Context, pr int) ([]Review, error)
    PostReview(ctx context.Context, pr int, body string, verdict Verdict) (*Review, error)
}
```

### `PR.BaseRef` is not optional (L26, D5)

```go
type PR struct {
    Number  int
    Head    string
    BaseRef string   // REQUIRED — the phantom-merge guard reads this
    Merged  bool
    MergeSHA string
}
```

**The phantom-merge guard is untestable without it.** A PR merged into the wrong base looks merged, reports merged, and
its work is not where the loop believes it is — and the only way to catch that before merging is to read `base.ref` and
compare.

An interface that omitted this one field would make T6 impossible to test, which is why L26 names it explicitly rather
than leaving it to be discovered.

### The fake

It must do three things beyond returning plausible values:

**1. Record every call, in order.** D1's assertion is on the **call log**, not on a returned value: a test checking that
running an action twice returns the same thing passes against code that acted twice and returned the same thing. The log
is what distinguishes "recognised its prior work" from "did it again".

**2. Be configurable per scenario** — an existing open issue, an existing open PR, a PR with the wrong base, a merged
PR, a PR with many reviews, an unreachable forge (O5, Q11). Every later task's tests are a scenario plus an assertion.

**3. Distinguish transport failure from domain refusal.** *"GitHub is down"* and *"GitHub said no"* need different
responses, and conflating them sends someone to check their permissions when their network is out. So the fake can
simulate both, separately.

### Errors are discriminated (O5, S26)

```go
type ForgeError struct {
    Kind   string  // "transport" | "auth" | "not-found" | "conflict" | "refused"
    Detail string
}
```

Five kinds, because a loop's response differs for each: retry, stop and tell a human, treat as absent, reconcile, or
report.
