A slice is not done when its tests pass. It is done when someone who did not build it can follow `DEMO.md` and watch the
thing work (§14).

never need either (O7). If a unit test grew a network dependency, that is the finding.

## Scope

### Walk every section

**On a throwaway GitHub repository whose history does not matter.** Everything lands there for real.

**§2 is the slice's claim.** Run the whole loop twice and then check **the repository, not the logs**: one issue, one PR,
one commit. A loop that *reports* reuse and created a duplicate is the exact failure, and the logs would look fine.

Also confirm `git status --porcelain` is empty, with **no exclusion** — the assertion exists because of a recorded
incident where hand-picked files were left behind and then **dropped by the squash merge**.

**§3 closes the gap.** Both must return `ask`:

```
aeon policy check --agent github-steward "gh pr merge 15"
aeon action check forge.merge
```

If the code action does not, expressing an action as a code action rather than a command launders it past S11's guard.
**That asymmetry was invisible until it was written down**, which is why the demo compares the two routes explicitly
rather than testing each alone.

**§4's second half is the one people get wrong.** After a squash merge the **squash SHA** is an ancestor of the feature
branch and the task branch's **original commits are not**. **Both results are correct.** A guard checking the originals
reports every successful squash merge as a failure, and the natural fix looks like relaxing the guard — which removes it.

**§5** — confirm the task issue was closed by `forge.closeIssue` and not by GitHub. `Closes #n` only fires on a merge
into the **default** branch, and task PRs target the feature branch.

**§8** — `dev-loop.yaml` passes `--strict` for the first time, and its nine `unverifiable` diagnostics are gone.
