# T11 — The GitHub implementation

## Why this exists

**Late and separate** (R7), so a network dependency cannot leak into any earlier task's tests. Every other task in this
slice was built and tested against T1's fake, which is what keeps the automated suite runnable without a token (O7).

## Scope

### The implementation

`Forge`, over GitHub's API. Nothing more — no convenience methods, no extra endpoints, no capabilities the interface
does not declare. **The interface is the contract**, and an implementation richer than its interface is an implementation
somebody will reach into directly.

### Errors map to the five kinds (T1, O5)

| GitHub says | Kind |
| --- | --- |
| Connection refused, DNS failure, timeout | `transport` |
| 401, 403 with a scope message | `auth` |
| 404 | `not-found` |
| 409, 422 on a duplicate | `conflict` |
| 403 from branch protection, a rejected merge | `refused` |

**`transport` and `refused` must not be conflated.** *"GitHub is down"* and *"GitHub said no"* need different responses,
and merging them sends someone to check their permissions when their network is out — or to retry forever against a
protected branch.

A 403 is the interesting case: it is `auth` when the token lacks a scope and `refused` when branch protection declined.
Distinguish them by the response body, and when it cannot be distinguished, **say so** rather than guessing.

### One identity, and the finding that it may not be enough

This implementation reads **one token** and acts under **one identity**.

**`conversational-map` says that is not sufficient for a protected branch**: *"because the reviewer account differs from the
steward's author account, the approval actually counts against branch protection."* A PR opened and approved under one identity
is self-approved, and **the approval counts for nothing** while S17's merge gate sees `APPROVED` and proceeds.

**Do not build two identities in this task.** It is a real design question — two credentials under C17's rule, a per-action
identity mapping, and a decision about what happens when only one is configured — and inventing an answer mid-task is worse
than recording the limit.

**What this task must do**: state the limit in `FORGE.md`, so someone running against a protected branch finds out from the
documentation rather than from a refused merge whose cause is two commits upstream.

### The token never appears anywhere (standing non-goal)

- Not in a log line, not in an error message, not in a captured request.
- Not in a test fixture — redacted to `<redacted>`.
- Read from the environment or a credential store; **never from a blueprint, a handler, or model output.**

Asserted by a test that runs every error path and greps the output for anything token-shaped.

### Rate limits and retries

A `transport` failure may be retried with backoff; a `refused` never is. And a rate-limit response is `transport` with
the reset time in its detail, because retrying is correct and the caller needs to know how long.

**Bounded retries.** An unbounded retry inside an action makes S5's step deadline a lie.

### `aeon/docs/FORGE.md`

What scopes the token needs, how to supply it, what happens when it is missing, and what Aeon will never do with it. The
last part matters: someone handing a token to a coding agent is entitled to know that it is never sent anywhere but the
forge, and never used to force-push or delete a branch (N8, N9).

## Tests

| Test | Asserts |
| --- | --- |
| `TestGitHubMapsErrorsToKinds` | All five, from real response shapes recorded as fixtures. A 403 from a missing scope is `auth`; a 403 from branch protection is `refused`; an indistinguishable 403 **says so** (O5) |
| `TestNoOtherTestGrewANetworkDependency` | A grep over the whole repository's tests: only this package's fixtures reference GitHub, and **none makes a live call** (O7, I7) |
| `TestTokenIsNeverLogged` | Every error path exercised; no output contains anything token-shaped |
| `TestTokenIsNotReadFromModelOutput` | The token comes from the environment or a credential store only; no signature accepts one |
| `TestRetriesAreBounded` | A `transport` failure retries with backoff, bounded; a `refused` never retries |
| `TestRateLimitCarriesResetTime` | Classified `transport`, with the reset in the detail |
| `TestImplementationIsNotRicherThanTheInterface` | No exported method beyond `Forge`'s |
| `TestFixturesAreRecordedNotLive` | Every response fixture is a committed file; the test suite makes no request |

`TestNoOtherTestGrewANetworkDependency` scanning **the whole repository** is the point. This is the task where a live
call would be convenient, and the guard has to be repository-wide rather than package-local.
