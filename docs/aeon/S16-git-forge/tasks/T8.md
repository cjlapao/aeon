## Why this exists

L3's split needs a join: **identifiers from code, one paragraph from the model, assembled into something a person
reads.** The template is that join, and it is the last thing between Aeon and a pull request other people will see.

It precedes T9 because slots must exist before a handler declares one, or the load-time validation has nothing to check
against.

## Scope

### The templates

`templates/pr-body.md`, `issue-body.md`, `review-body.md`, with `{{slot}}` placeholders drawn from **the manifest plus
the upstream step's handoff**.

**Answer Q8 first**: every template, every slot, and which handler produces each. **A missing table blocks this task**,
because L20 validates against it.

### Slots validated at **load** (L20, D10)

S8's L9 says validation is loud and **at load**. So a template naming a slot the producing handler does not declare is
**`invalid` at load**, with the diagnostic's path naming the template and the slot.

**Discovering `{{pr_summary}}` is empty while opening a real pull request means a PR with a hole in it, in front of
people.** That is the failure this check exists to prevent, and it is a load-time check because a load-time check runs
before anything is outward-facing.

This extends `internal/blueprint/validate.go` with a new class, joining the seven S8 built — and like those, its
diagnostic carries a machine-readable `kind` and a path.

### An unresolved slot **fails the action** (L23, D11)

A template engine's default is to emit the placeholder. **A PR body containing `{{pr_summary}}` is worse than no PR** —
it is visibly broken, in a permanent record, attributable to whoever opened it.

So: rendering with an unresolved slot is an error, and the action fails. Never a partial render, never a placeholder,
never an empty string silently substituted.

Asserted as **no `{{` reaches a rendered body** (C8), which catches the whole class rather than the one slot a test
thought of.

### Every identifier comes from code (L3, I3)

The manifest side of a template supplies numbers, refs and SHAs — all of them from code. The handoff side supplies
prose. **A slot must not be able to draw an identifier from a handoff field**, or a model could supply a PR number.

Asserted: the slot resolver's identifier slots read from evidence and state only.

### One field vocabulary (S8's L18)

Slots resolve against **the same manifest declaration** conditions do. S8's L18 exists because three copies of a field
vocabulary drift, and a template is the third consumer that decision anticipated.
