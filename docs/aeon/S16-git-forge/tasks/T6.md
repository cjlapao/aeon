# T6 — `forge.merge` and the phantom-merge guard

## Notes — built tests-first 2026-10-25

**One task, structurally enforced**: `MergePR` refuses to run at all without the probe wired ("an
unguarded irreversible action would not run") — the window R6 worries about (merge works, guard does
not) is not expressible through the API: the action cannot be constructed guard-less.

**The sha the guard asks about is asserted, not just the outcome**: the probe records its queries, and
the test pins `queries == [mergeResultSHA]` — the ORIGINAL never consulted. Both directions of the
truth table are proven against REAL git in the same test (squash IS an ancestor of feature; the
task-branch original is NOT), which is C5's trap closed: a test asserting only the positive half passes
against a guard checking the wrong commits, and the tempting response to that false failure is relaxing
the guard into nothing.

**Method default is squash** — and the phantom guard verifies the merge RESULT's own SHA, so a
reported-but-unlanded merge fails as `phantom merge (D5): PR #n reported merged at <sha> but that
commit is not an ancestor of <feature>` — naming PR, sha and base. The forge's report never outranks
the tree.

**Already-merged: success with the recorded SHA** (never merge twice, never fail) — and the
already-merged path runs NO git at all (probe queried zero times), which is the check-then-act shape at
its strictest: the desired end state costs one read.

**N4 pinned on the call log**: a protected-branch refusal produces exactly ONE MergePR attempt, no
second method, no push, no side channels — honest failure naming the refusal. "No workaround" is a
property of the log, not a promise.

**Mis-based refusal runs before the forge's merge door**: MergePR count zero is asserted, and the
refusal names the observed base AND the expected feature branch — actionable (D5). A base-less PR
(L26) is refused identically: something that cannot say what it merges into cannot be merged.

Counts dated 2026-10-25: internal/action **33** (8 + 9 + 8 + 8), internal/forge **6**. Tests written
before the implementation; two compile-level reds (missing Merge field, one unused var), no behavioural
red — the guard design was right the first run, and the real-git truth table made that checkable rather
than assumed.

## Why this exists

**One task** (R6), because the guard is not a check bolted beside the merge — **it is what makes the merge correct.**
Splitting them creates a window where the merge works and the guard does not, and this is the only `irreversible` action
in the registry.

## Scope

### The action

`forge.merge`, class **`irreversible`**, check-then-act:

> Read the PR; `merged == true` ⇒ return the recorded merge SHA. **Never merge twice, never fail.**

"Never fail" is deliberate: an already-merged PR is the desired end state, and treating it as an error would fail a loop
whose work is done.

### The guard, before merging (D5)

**Assert `base.ref == {feature_branch}`.**

This is the phantom-merge **root cause**. A PR merged into the wrong base looks merged, reports merged, and its work is
not where the loop believes it is. Everything downstream — the feature branch's tests, the next task's base, the final
merge — then operates on a tree missing the change, and the symptom appears several steps later as a test failing for no
visible reason.

T1's `PR.BaseRef` exists for this one assertion (L26).

### The guard, after merging (D5)

**Assert `git merge-base --is-ancestor {mergeSha} {feature_branch}`.**

And the half that is easy to get wrong: **verify the squash SHA, never the task branch's original commits.**

A squash rewrites history. The originals are **never** ancestors of the target, even after a perfectly correct merge — so
a guard checking them reports every successful squash merge as a failure. And the natural response to that is to relax
the guard, which removes the check entirely.

So the test asserts **both** directions: the squash SHA **is** an ancestor, and an original commit **is not**. Both
results are correct, and a test asserting only the first passes against a guard checking the wrong thing.

### Governance

`irreversible`, so it asks (T2), and the ask carries the PR number, the base and the repository (O1) — *"approve
`forge.merge`?"* tells a human nothing about what they are merging.

**An unattended loop denies it.** That is the correct default for the only action in the registry that cannot be undone.

### Not in scope

**No merge-queue or protected-branch workaround** (N4). A repository that refuses the merge produces an **honest
failure** naming the refusal. Working around branch protection is working around a decision someone made deliberately.

## Tests

| Test | Asserts |
| --- | --- |
| `TestMisBasedPRIsRefusedBeforeMerging` | A PR whose `base.ref` is not the feature branch is refused, and **`MergePR` is never called** — spy at zero (D5) |
| `TestSquashSHAIsAncestorAndOriginalsAreNot` | **Both** assertions: the squash SHA is an ancestor, an original commit is not. A test asserting only the first passes against a guard checking the wrong commits (D5, C5) |
| `TestNeverMergesTwice` | An already-merged PR returns its recorded SHA, calls nothing, and **succeeds** (D1) |
| `TestAlreadyMergedIsNotAFailure` | Explicitly — the case "never fail" exists for |
| `TestIrreversibleAsks` | And carries PR number, base and repository (O1) |
| `TestUnattendedDeniesMerge` | Denied, naming the class (D8) |
| `TestProtectedBranchIsAnHonestFailure` | A refusal from the forge produces a failure naming it, with **no workaround attempted** (N4) |
| `TestPostMergeGuardFailureIsLoud` | If the squash SHA is somehow not an ancestor after a reported merge, the action **fails** rather than reporting success — the phantom merge caught after the fact |

`TestSquashSHAIsAncestorAndOriginalsAreNot` is the highest-value test in the slice. Every plausible wrong implementation
passes a test that only checks the positive case.

## Definition of done

- [x] Check-then-act; an already-merged PR returns its SHA and succeeds
- [x] `base.ref` asserted **before** merging, with `MergePR` never called on failure
- [x] The squash SHA asserted an ancestor **and** the originals asserted not
- [x] A post-merge guard failure is loud, not a reported success
- [x] `irreversible`; asks with PR, base and repository; denied unattended
- [x] A protected-branch refusal is an honest failure with no workaround
- [x] `make test`, `make lint` green
