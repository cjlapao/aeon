## Why this exists

**This task closes a gap that was invisible until it was written down**, and it comes second (R5) — before any
`outward` action exists — because an action that works before it is governed is an action someone can call in the window
between.

**S11's evaluator guards `bash`. Code actions do not go through it.**

The corpus shows the intent clearly: `github-steward` marks `gh pr merge*` and `gh pr close*` as **`ask`**, and
`gh pr merge*` carries `allow`, `ask` **and** `deny` across different agents. Someone thought carefully about who may
merge.

But those are **command-line patterns**. A blueprint naming `forge.merge` reaches the same effect through a path with
**no guard at all** — same outcome, two governance routes, one of them empty. Expressing an action as a code action
rather than a command would launder it past everything S11 built.

## Scope

### The classes (L22)

```go
type EffectClass string

const (
    // Effects confined to the working tree.
    EffectLocal EffectClass = "local"

    // Visible to other people: a push, an issue, a PR, a review.
    EffectOutward EffectClass = "outward"

    // Cannot be undone by another action: a merge.
    EffectIrreversible EffectClass = "irreversible"
)
```

Every action declares one. `outward` and `irreversible` default to **`ask`**.

**Not configurable** (N7, I4). Effect classes are code, deliberately: a config-defined class is a way to downgrade
`irreversible` to `local`, and the whole value of the classification is that nobody can.

### The `ask` carries what is affected (O1)

S11's G18 established that a permission ask names the command **and** the rule. The same reasoning applies harder here,
because *"approve `forge.merge`?"* tells a human nothing about **what** they are merging or **where**:

```
ask    Merge this pull request?

       forge.merge  #15  →  feature/4a17-version
       repository:  cjlapao/throwaway

       effect: irreversible — this cannot be undone by another action

       [ approve ]  [ deny ]
```

**Answer Q5 first**: does this reuse S11's `kind: 'permission'` question, or need a fourth kind? Reuse if the payload
fits; a fourth kind is only warranted if something must dispatch differently. Either way, S9's U14 holds — it renders
through the same affordance a step question and a gate do.

### Unattended denies (G7, G14, D8)

An unattended loop resolves an `outward` or `irreversible` ask to **deny**, naming the class:

```
forge.merge denied — effect class 'irreversible' resolves to deny (loop is unattended)
```

**So an unattended loop cannot open a PR or merge one unless someone opted in at start.** That is the correct default
for something other people will see, and it follows from G14's pinned attendedness rather than being a new rule.

### The closed registry is why classes suffice

A blueprint cannot name arbitrary code (L8, D14), so the classes govern a **known** set. That is the difference between
this and `bash`: `bash` needs a pattern matcher because its input is unbounded; the action registry needs classes
because its input is eight things.

Closed is not the same as safe to run unattended, though — which is the whole point of the classes.

### `aeon action check` (the demo's §3)

Prints an action's class and the verdict it produces, so the two governance routes can be compared side by side.
