# T2 — the injection seam (`runtime/skills_inject.go`, `daemon/skills_wire.go`)

## What exists

`runtime`: `SkillsSection` (Text/Names/Count/Truncated/Marker +
defaulted Title), `SkillsProvider`, `SetSkillsProvider`/
`TheSkillsProvider`, `skillsSectionForStep` (empty/blank = nothing);
`CompileRequest` appends the section LAST as `CategoryInjectedContext`
and adds `MarkerSentence()` to the notes (which ride `step.started`'s

`StepSkills`; `runstep.go` stamps the marker on the ONE `step.started`

`wireSkills` — the single `SetSkillsProvider` call.

## Notes

- **The first live walk caught the silent wiring**: `wireSkills`
  existed but a later edit had replaced its call site with the event
  emit, so the daemon watched, listed, and injected NOTHING — and
  every existing guard stayed green (the one-place guard counts
  `SetSkillsProvider`'s call site, which lives inside `wireSkills`; an
  uncalled `wireSkills` still passes it). The repair added
  `TestNewWiresTheProviderAndUnwiredLeavesItInert`: `New(Options{
  Skills:…})` must make `TheSkillsProvider()` answer the catalog, and
  a no-catalog `New` must leave it nil. **A wiring fact needs a test
  that observes the effect, not the text.**
- **warn rides** (brief INJ2): the same walk's first fixture scanned
  `warn` (a 10-character description is "thin"), the offer came back
  empty, and the injection lane read as broken. A warning is a
  usability note, not a validator refusal; the invokability line is
  invalid/shadowed, exactly as the renderer now encodes it.
- No `recover()` at the seam: `runstep_test`'s
  `TestConstructionIsNotInsideThePanicBoundary` rejected it (this
  package's own rule — construction lives outside the panic
  boundaries). A panicking provider surfaces, pinned by a test that
  insists the panic arrives.
- The marker rides the REQUEST and the EVENT, never the frozen
  manifest: resume replays frozen transcripts (D12 byte-reproducibility)
  and must not re-derive a fact the original compile carried.
- One renderer for every sentence: `Marker` feeds the chat tooltip,
  the `step.started` note and the row — the plan's "live and reload
  print the same words" is structural, not a discipline.
