# T3 — announcements (`skills.changed`, the wire payload, serve)

## What exists

`protocol/events.go`: `KindSkillsChanged = "skills.changed"` (daemon-
wide notice, payload-not-state, documented beside the loop kinds).
`daemon.New`: `opts.Skills.SetEventEmit(… table.OnEvent(KindSkillsChanged, ev))`
— late-bound because the service predates the event door.
`cmd/aeon/serve.go`: `skillSvc.StartWatch(ctx)` after the startup scan;
the watch state is logged (both roots / NOT watching — reason / partly
blind). `protocol/step.go`: `StepEventPayload.Skills *runtime.StepSkills`
(additive MD7; `stepEventPayload` copies it — the ONE payload builder,
so start and continue paths cannot drift). `conformance/events/
skills-changed.json` (enters `knownEventKinds` via protogen);
`conformance/skills/list.json` gained `watching`/`watchError` so the
generated `SkillListResult` carries them. CLI `skills list` prints the
watch line (verbatim daemon words).

## Deviations from the plan (rulings, recorded)

- **No `step.skills.injected` event kind.** The marker rides
  `step.started.skills`: same moment, one carrier, and the chat page's
  existing `step.*` subscription already delivers it to live AND
  `after:0` replay. One fixture (skills.changed), not two.
- **No per-run `chat_message` system row.** The bench chat's reload
  lane IS the event replay; a second copy of the fact in `chat_message`
  would be a second truth. (If S9's transcript lane ever needs the
  marker, it reads `step.started` rows — same field.)
- The `skills.list` HANDLER projection had to be fixed: it rebuilt the
  ScanResult field-by-field and dropped the watch pair — found live,
  by the walk (`watch off —` with an empty reason), never by a unit
  test that trusted the service. Projections must carry the honesty
  fields, now pinned in the source comment + the live walk step.
