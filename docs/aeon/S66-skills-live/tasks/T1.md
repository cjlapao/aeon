# T1 — the filesystem watcher (`internal/skills/watch.go`)

## What exists

`watch.go`: `DefaultWatchDebounce` (500 ms), `ChangeEvent`, `watchState`
(+ `watchError()`), `StartWatch`, the `watchLoop` (debounce →
`refreshOnWatch` → diff → announce), dynamic watch add/drop, dot-tree
skip, `diffScans` on `name:source`. `catalog.go` gained `Options.
WatchDebounce`/`Options.OnWatchChange`, the watch fields under `s.mu`,
**stamped shallow copies** from `Scan`, `SetEventEmit`, `RecheckNow`.
`types.go`: `ScanResult.Watching`/`WatchError`.

## Notes

- **The baseline is established inside `StartWatch`, synchronously** —
  not on the first event. Written first without it, the tests caught
  the real bug: the first dropped folder was silently consumed as the
  diff baseline, which is exactly the silence the slice exists to
  delete. `Scan(true)` before `watching=true`; a failed baseline is a
  spoken watch error, not a refusal to watch.
- Missing roots at boot are NOT watched (no inotify lie): `Watching:
  false` + "no root existed to watch … discovered by the next scan";
  one-missing keeps `Watching: true` and names the blind root. The
  never-started state has its own sentence — the three states are
  distinguishable in the payload and on screen.
- fsnotify v1.10.1 became a **direct** dependency (`go mod tidy`
  promotes it; Op checks use `ev.Op.Has(...)` — the v1.10 API).
- The burst test asserts the honest property (one Added, follow-ups
  only ever about the bursting folder) rather than "exactly one event
  forever", which would flake on a loaded box — a refresh racing the
  tail of a burst is a fact of real filesystems, not a bug.
- Timer is real time (`s.debounce`), never the service clock: the
  clock is for scan stamps; a test clock must not speed a syscall path.
