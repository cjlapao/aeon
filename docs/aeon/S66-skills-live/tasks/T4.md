# T4 — the app (chat row + catalog page)

## What exists

`agent-chat/types.ts`: `ChatItem` variant `injection` (`Base`;
count/names/truncated/marker). `fromEvents.ts`: the `step.started`
case maps `p.skills` (count>0, names array) to the row, defaulting
the marker from the same shape; `ChatStream.tsx`: `InjectionRow`
(compact mono, daemon sentence verbatim as the tooltip), and
`filterForAgent` keeps injection rows in the agent zoom (the offer
belongs to the daemon). `lib/skills.ts`: `watching`/`watchError` on
`SkillListResult`; `useSkills` holds one `subscribe {kinds:
["skills.changed"]}` per mount and re-reads on every announced diff
(subscriptionId-matched; a subscribe failure leaves the manual doors
working, silently). `SkillsPage`: the watch line renders the three
states (on / not-watching + the daemon's own reason / unknown on an
old daemon) and the doc comment tells the truth about injection now
riding every step.

## Notes

- The row is NOT the divider with a new tone: the operator's question
  is *which skills*, and a centred rule cannot answer it. It is also
  not a `message` row — it is not anyone speaking.
- The negative case is a test, not an absence: `skills:null` renders
  nothing at all — an empty pill would read as "the catalog exists
  and offered nothing", which is a different (and false) sentence.
- `useSkills` deliberately swallows subscribe failure: silence is
  absence of news, never an error state; the pin says so.
