# T5 · The optional read-all seed proposal

**Rules:** TA15. **Depends on:** T2. Q2 answered yes (2026-11-07).

## Goal

Offer, not impose, one policy: allow `*.*.read` for all agents, shipped disabled.

## Steps

1. Add one seed record in the policy seed set (`internal/policyseed`) through the seed engine, `origin=system`, disabled by default, with a plain explanation ("lets every agent call every tool that only reads"). Authoring stays human-door only (PL15): the seed engine is the system's own door, as it is for the other seeded policies; confirm by reading how existing seeded policies are written and follow it.
2. Test: the seed exists after a fresh start, is disabled, and enabling it by the human door makes `glob` and `read` allowed for an agent with no other grant; disabling it restores the refusal.

## Do not

- Do not enable it by default.
- Do not seed any write allow.

## Notes

**Closed 2026-11-07 without code, as not implementable as written.** Two facts found while reading the code: (1) the policy seed set (`internal/policyseed`) is the command-access corpus only, and (2) a policy has no enabled/disabled state (only an optional expiry), and PL1/D4 refuse an allow authored by anything but the operator, so a system-seeded `allow *.*.read` cannot exist. The operator's goal (one rule for every read tool) is met by the picker's "All read tools" row plus one submit through the human door. If a one-click starter is still wanted it is a UI button that prefills the form, not a seed; say so and it becomes a small task.
