# T3 · Policy form pickers and the live preview

**Rules:** TA10–TA13. **Depends on:** T2.

## Goal

The operator never types a tool name or an agent name from memory. Every value field is a picker; the tool field shows what the pattern matches.

## Steps

1. Contract: give the `toolName` field the control `tool-address` in the policy spec description the daemon sends (`policy.vocabulary` / `describe.go`), and the target fields controls `agent`, `component`, `project`, `skill`, `mcp-server` where the spec has them. Keep unknown controls falling back to text with the existing warning.
2. `SpecFields.tsx` (225 lines or less today; measure): render a picker per control. Put each picker in its own file under `features/settings/policy/pickers/` so the form stays small: `ToolAddressPicker.tsx`, `EntityPicker.tsx` (agent, component, project, skill, server share it, each fed by its list read). A picker is a searchable select with a "type a value" escape.
3. `ToolAddressPicker`: groups by category, each tool row with address and a read/write badge, plus the wildcard rows of TA12 at the top of each group and the "all …" rows at the very top. Selecting fills the field; the field text stays editable.
4. Preview: below the field, call `tools.matchPattern` on change (debounced, 250 ms, the latest call wins) and render "matches N tools" with the first few addresses and an expander, or "matches no tool today". A failing call shows the refusal, never a stale count.
5. Tests: picker renders the catalog groups from a fake daemon; choosing "all read tools in workspace" fills `workspace.*.read`; the preview shows the daemon's answer, and a refused pattern shows the refusal; the unknown-control fallback still works; the existing `PolicyForm.test.tsx` passes unedited except where it typed a tool name into a text box (update and list each in Notes).

## Definition of done

- The create-policy flow can author `allow workspace.*.read for agent brainstormer` using only selects and clicks.
- Preview answers match `tools.matchPattern` for the same pattern.
- `tsc` clean for touched files (the nine known base errors stay as they are), touched tests pass, `npx vite build` passes.

## Do not

- Do not match patterns in the browser.
- Do not remove the free-text escape.
