# T2 · Wildcard `toolName`: validation, matcher, evaluator, preview method

**Rules:** TA5–TA10, TA9b. **Depends on:** T1.

## Goal

A `ToolAccess` row may hold an address pattern, the gate honours it through one matcher, and a read method answers what a pattern matches.

## Steps

1. `internal/policy`: add `MatchToolAddress(pattern, address string) bool` in its own file, with the grammar of TA6. Pure, total, no panic on any input. The empty pattern matches nothing. A bare name (no dot) is TA8: equal to the tool segment.
2. Property test: `MatchToolAddress` against a literal reference implementation written independently in the test (split on `.`, compare segment by segment), fuzzed; the same pattern the older `pattern_test.go` uses for `MatchPattern`.
3. `spec_toolaccess.go`: widen `toolName` validation per TA5/TA6. Refusal sentences name the offending segment ("segment 2 of \"workspace.*r.read\" is a partial wildcard; use a whole * or a literal"). Update the pinned `shape` string and let `TestThePinnedSpecShapesMatchTheirGoStructs` confirm it. Keep the file under 1000 lines; if it would pass, split validation into a sibling file by cohesion.
4. The gate: find where `ToolAccess` rows are matched against a requested tool (`grep -rn "ToolAccess" internal/policy/evaluate.go internal/daemon`). It must receive the tool's address, resolved through the registry/MCP rows by a seam in `daemon.Options` (the protocol package must not import `internal/tools` or `internal/mcp`). A tool that cannot be resolved matches bare-name rows only, never a wildcard (absent is not zero).
5. Tests: bare-name rows behave byte-identically (run the existing evaluate tests untouched); `workspace.*.read` allows `glob` and refuses `write`; a `deny` on `workspace.read.read` beats it; `*.*.read` and `workspace.*.*` cases; a refused partial star; an unresolved tool matches no wildcard.
6. New read method `tools.matchPattern {pattern}` returning `{ pattern, matches: [address…], count }`, using TA7 over the catalog. Register it in the protocol surface table and the completeness test (`TestSurfaceEveryEntryNamesARegisteredMethod` style); read-only, not in the write door. Add the CLI twin `aeon policy match-tools <pattern>` if the policy CLI already has read verbs (daemon first, CLI second).
7. Record the TA9 amendment in `docs/aeon/S10-policy/design.md` as a dated note under the PL list.

## Definition of done

- All the cases in step 5 pass; the old `ToolAccess` tests pass without edits.
- `tools.matchPattern` answers on a running daemon (note the exact output in Notes).
- No file over 1000 lines, measured.

## Do not

- Do not let the UI or the CLI match patterns on its own (TA7).
- Do not change deny-wins or specificity (TA9b).
- Do not add a policy type.
