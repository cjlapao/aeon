# T1 · Address, category and access on the catalog

**Rules:** TA1–TA4. **Depends on:** nothing.

## Goal

Every tool in the catalog, system and MCP, answers three new facts: `category`, `access`, `address`. Nothing else changes.

## Steps

1. In `internal/tools`, add `Access(m Meta) string` implementing TA2 over `Meta.Capabilities`. Add `Address(family, name string, access string) string`. One file, one concern; keep `meta.go` under 1000 lines (measure it first).
2. Table test: one row per registered tool (`tools.Registry()`) naming the expected access. A new tool with no row fails the test. Include `todo` and `report_size` (read), `webfetch` (`write`, operator answer Q1), `bash` (write), `question` (read), `run_start` (write).
3. MCP side: in the tool catalog assembly (`internal/toolcatalog`), build the MCP address as `mcp.<server>.<tool>` and the access per TA3. Check whether S46 stores a read-only hint on the MCP tool rows (`grep -rn "readOnly" internal/mcp internal/store`); if it does not, every MCP tool is `write` and Notes records that as a finding for a follow-up, not a fix here.
4. Add `category`, `access`, `address` to the `tools.list` and `tools.view` results (`grep -rn "\"tools.list\"" internal/protocol`). Regenerate the contract the way the repo does (`make` target named in `aeon/AGENTS.md`) and commit the generated file.
5. Existing `tools.*` tests keep passing unedited except for golden files that list result shapes; update those and say so in Notes.

## Definition of done

- `tools.list` returns the three fields for every tool, system and MCP.
- The completeness table test exists and fails when a tool is added without a row (prove it once by removing a row).
- `go test -tags sqlite_fts5 ./internal/tools ./internal/toolcatalog ./internal/protocol` passes for the touched packages.

## Do not

- Do not store the address. It is computed (TA4).
- Do not rename a family to `system` (Q3, answered: the family names stand).
