# T9 · The CLI: `aeon autonomy`

**Prefix:** AL · **Shape:** P5 (with the recorded offline asymmetry) · **Rules:** AL13 · standing rule 1 · **Depends on:** T7. Parallel-safe with T8, T10.

## Goal

A person can read and manage autonomy from a terminal as a **client of T6's socket methods**, with an offline path **only for the restrictive verbs** — so authority can always be pulled, and is never widened without the peer-attested identity. The CLI re-validates nothing.

## Files

- `aeon/cmd/aeon/autonomy.go` — **new**: `cmdAutonomy` dispatch; verbs and flags:
  - reads: `list [--root ID] [--state allow|deny] [--all] [--json]`, `show ID [--json]`, `vocabulary [--json]`, `effective --root ID [--origin schedule|webhook|event|scheduler] [--label L …] [--json]`, `pinned LOOP [--json]`, `changes [--root ID] [--grant ID] [--limit N] [--json]`, `uses [--root ID] [--grant ID] [--loop ID] [--limit N] [--json]`;
  - writes: `grant --root ID --action NAME|--outward [--require-gates=…] [--require-budget=…] [--label L …] [--max-per-day N] [--expires RFC3339|--for 30d] [--note TEXT] --yes`, `deny --node ID --action NAME|--outward [--note TEXT]`, `revoke ID --reason TEXT --yes`.
  Flag *parsing* refuses only what cannot be a value (a non-RFC3339 `--expires`, a `--for` that is not a duration); **every other refusal is the daemon's sentence verbatim** (the CLI re-validates nothing; `--action` vocabulary is never typed twice — `--help` is generated from `autonomy.vocabulary`).
  Human output: list → one grant per block (`describe` sentence from the wire, root, state, expiry, conditions, used N times, active/revoked); `effective` → one line per action with verdict and reason; `--json` prints the wire result verbatim. `--yes` is a **seatbelt** on `grant` (it widens authority) and `revoke` (a revoked grant is never re-activated — restoring it is a new grant, a new decision), refused without it with the daemon's `statement`; it is not a security control. `deny` needs none: it only restricts.
  No flag, stdin or prompt accepts a secret (C17); nothing here handles one.
- `aeon/cmd/aeon/autonomy_client.go` — **new**: `type autonomyDoor interface{…}`; `socketDoor` (default; `dial`, `Call`, maps wire errors to the CLI's refusal text **verbatim**) and `directDoor` (**read-only methods, `deny` and `revoke` only**, built on the **same** `internal/autonomy`/`internal/store` functions the daemon's service calls — a `go/parser` test forbids a local copy of any moved function; actor `{user, cli}`, audited `actor_kind='cli'`).
  `selectDoor(verb)`: dial once; success ⇒ `socketDoor`; "no daemon" ⇒ for a read, `deny`, `revoke`: `directDoor` **and the fixed stderr line** `daemon not running — applied directly to the store`; for **`grant`: refuse** with *"daemon not running — grants are written through the daemon so the audit carries who asked; start the daemon, or use `aeon autonomy deny`/`revoke` to restrict"*;
  any **other** dial failure (permission denied, protocol mismatch, version skew) is **refused, not fallen back from** (S45 PM4: falling back from an error that is not "nobody is home" would route around a daemon that exists).
- `aeon/cmd/aeon/main.go` — one `case "autonomy"` and its usage lines. `store.go`'s two-access-path note gets one sentence: autonomy verbs reach the store directly **only** as the documented restrictive/read fallback.
- `aeon/cmd/aeon/autonomy_parity_test.go` — **new**: the parity guard (both directions) with T0's drafted table as its fixture.

## Definition of done

- [ ] Ten verbs, parity in both directions; help generated from the vocabulary; refusals verbatim; JSON is the wire.
- [ ] `grant` never offline; `deny`/`revoke`/reads offline through the same code with the fixed line; other dial errors refuse.

## Do NOT

- Do not re-validate in the CLI or add a second formatter. Do not fall back for `grant`. Do not fall back on a dial error that is not "no daemon". Do not accept a secret as a flag value. Do not change any existing verb's output.

**Deviations the spec could not know.**

1. **Type rename.** The spec's `socketDoor`/`directDoor` names are already declared in `seed_door.go` (same `main` package), so the doors are `autonomySocketDoor`/`autonomyDirectDoor`. The spec's test name `TestDirectDoorUsesTheSameFunctions` is kept verbatim (a name, not a type).
2. **T3 design gap, corrected in this commit (the fix rides with T9).** AL13 requires offline `deny` through the direct door with `actor_kind='cli'`, but T3's store door and the migration's CHECK refused `cli` for deny. Fix: `store/autonomy.go`'s actor check is now state-aware (`CreateAutonomyGrant` → `a.autonomyRefusal(in.State == "deny")`); the migration's CHECK is now `CHECK (created_by_kind = 'user' OR (state = 'deny' AND created_by_kind = 'cli'))`; the T7 guard's CHECK-literal assertion was amended to match; new store test `TestCliActorCanDenyButNotGrant`; design.md AL10 annotated. Full `./internal/store/` suite re-run green 2026-11-01 (`ok … 246.018s`). The socket's lock-2 still refuses every kind but `user` — `cli` reaches the store only through the direct door, exactly the asymmetry AL13 wants.
3. **`list` has no used-count.** The human-output spec asks for "used N times", but the wire's `GrantView` carries no count (only `AutonomyShowResult.UsedCount` does). `list` prints the describe sentence, root, state, expiry, conditions, active/revoked; `show` carries the count. The CLI re-validates nothing and does not add a second query.
4. **One `--action` flag** takes an action name **or** the `outward` class as its value (the spec's `--action NAME|--outward` is one flag, two value shapes).
5. **No `--dry-run` flag** — it is not in the spec's flag list, and the wire `DryRun` stays false from the CLI.
6. **Conditions are pointer-semantic via `fs.Visit`**: any of `--require-gates/--require-budget/--max-per-day/--label` set ⇒ a present `AutonomyConditions` with the values verbatim; none set ⇒ nil, and the daemon applies its `{RequireBudget:true}` default (proven live: the bare `--yes --for 30d` grant came back `conditions: requireBudget`).
7. **`--expires` (RFC3339, non-RFC3339 refused) XOR `--for`** (Go durations or whole days `Nd`, via `parseGrantDuration`); both set is refused.
8. **P10's literal glob misses four of the test names**: `TestCLIRefusalsVerbatimBothDoors`, `TestGrantRequiresYes`, `TestRevokeRequiresYes`, `TestCLINeverImportsTheStoreOutsideTheFallback` match none of `Autonomy|Parity|SelectDoor|DirectDoor|Vocabulary`. The recorded extension is the union alternation `'Autonomy|Parity|SelectDoor|DirectDoor|Vocabulary|CLIRefusals|RequiresYes|CLINeverImports'`; the full set is green (see below).
9. **Environment artifact, not a product bug**: on this box a unix-socket file under a throwaway `/tmp` directory was observed unlinked between a session checkpoint and resume while the daemon kept listening (the listen fd survived, dials then failed with ENOENT). A fresh daemon bind restores the file; the live run below used a fresh daemon and the file was present for the whole session.
