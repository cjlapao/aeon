# T8 · Agent tools and the two proposal kinds

**Prefix:** AL · **Shape:** P6 · **Rules:** AL12 · standing rule 2 · **Depends on:** T7, **S45** (`internal/desk`, generic `proposal.commit`, `proposal.create` validate-at-create). Parallel-safe with T9, T10.

## Goal

Agents can **see** what autonomy exists and **propose to narrow it** — and nothing more. Five catalog specs (one definition, two doors), two new closed proposal kinds committed by a person through S45's generic commit, no tool that creates or commits a grant, and the new names granted to no one by default.

## The five specs (`internal/records/catalog.go`, data only, family `autonomy`)

| Tool | Socket twin | Class | Mutates | Notes |
| --- | --- | --- | --- | --- |
| `autonomy_list` | `autonomy.list` (T6) | safe | no | grants with details; filters `rootId`, `state`, `includeInactive` |
| `autonomy_show` | `autonomy.show` (T6) | safe | no | one grant with last change, use count, pinned loops |
| `autonomy_effective` | `autonomy.effective` (T6) | safe | no | what an unattended loop on a root could do and why not |
| `autonomy_propose_revoke` | `autonomy.proposeRevoke` (new here) | detectable | **yes** | inert proposal to revoke grant `id`; `reason` required (1–512 bytes) |
| `autonomy_propose_deny` | `autonomy.proposeDeny` (new here) | detectable | **yes** | inert proposal to add a veto on a root or child for an action or `outward`; `reason` required |

`registerRecords` **skips** a twin whose dot-name already stands (`records.go` header), so the three reads reuse T6's methods; only `proposeRevoke`/`proposeDeny` are new socket methods, implemented by the **records** service (`RecordsAPI.Do`), not the authoring service — they create proposals, never grants.

## Schemas — what is deliberately absent

`additionalProperties: false` on every schema; **no** `actor`, `createdBy`, `proposedBy`, `status`, `kind`, `state` or `conditions` field. `autonomy_propose_deny`'s input is `{nodeId, subject:{kind,name}, reason}` — `state` is implied (`deny`) and there is **no `allow` anywhere in an agent-reachable schema**. The service stamps `proposed_by` from the agent identity
the records service already stamps (T0 of S45 T7 recorded what that is); the tool never names it. Per-agent open-proposal limit and 8 KiB payload bound are S45's named constants (reused, not re-declared).

- `aeon/internal/desk/autonomy_kinds.go` (S45's registry) — `Validate` (the **same** validators `autonomy.revoke`/`autonomy.deny` run: grant exists and is active; node exists; subject valid by `autonomy.ValidateGrant`'s deny half; `reason` non-empty), `AlreadyApplied` (grant already revoked / identical active veto exists), `Apply` (calls the store's `RevokeAutonomyGrant` / `CreateAutonomyGrant{state: deny}` with the **committer** as actor and the proposal's author as `proposed_by`), `Describe` (the fixed-template sentence). Create/commit validator parity (`TestProposeValidatorParityWithCreate` pattern).

## Behaviour (each a test)

1. **Inert:** after a propose, `autonomy.effective` and every grant row are byte-identical; only a `proposal` row exists.
2. **Commit effects:** a committed `autonomy_revoke` sets `revoked_*` with the **committer** (kernel peer) as actor and writes one `autonomy_change`; `proposed_by` names the agent; a committed `autonomy_deny` creates a veto.
3. **Restrictive only:** a revoke of an already-revoked grant and a duplicate veto are `AlreadyApplied` no-ops at commit; a revoke proposal naming a *deny* row is refused ("a veto is removed by a person, not proposed away") — an agent cannot propose to **remove a veto** (that would widen).
4. **Forced identity:** schema bypass attempts (a payload with `state:"allow"`) are refused by the validator with the same sentence `proposal.create` gives.
5. **Rate and size:** the 21st open proposal by one agent is refused naming the limit (S45's constant).
6. **Granted to no one by default:** `tools.DefaultGrant()` unchanged; the five are registered, not granted; a handler that lists them still goes through the policy engine's `tool_access` rows per call.
7. **Counted registry bump:** `TestRegistryExactNames`'s `want` lists (`toolset_test.go`, both) and count comment gain the five names **deliberately** (+5, computed from T0's real count, dated); `rerun_classes.json` updated.
8. Descriptions ≥ 40 characters and distinguish siblings (the catalog test enforces).

### Deviations

1. **No `state` filter in the agent-facing `autonomy_list` schema.** The spec's own table lists `rootId`, `state`, `includeInactive`, but the spec's schema section is stricter: "no `state` … field" on every schema, and "no `allow` anywhere in an agent-reachable schema". The two contradict; the schema section wins, because a `state` filter is the one input that could address grant rows by polarity (the read is already complete without it — every row carries its own `state`). The socket's human door keeps the full filter (T9's `--state`), and the arm passes `""` for it (`records_autonomy.go` header).
2. **`RevokeAutonomyGrant` keeps its T3 signature** — `(actor, id, reason)`. The spec's behaviour 2 wants the revoke's change row to carry `proposed_by` naming the agent, but the T3 store door (shared with T6's socket human door, where a revoke has no "author" at all) writes `""` in that column, and widening a shared store door's signature for one caller is a larger change than the deviation. The identity is not lost: the **proposal row** keeps `created_by_kind/id` (who proposed), and the commit's `policy_change` audit row (op `commit`, `proposal_id`, the committer) links the decision to it — the agent is named in two rows of the chain, the change row carries the committer as its actor. The deny half gets the full treatment: `CreateAutonomyGrant{ProposedBy: "agent:<id>"}` stamps the grant row and its change row.
3. **The skip is a map, not "already standing".** The spec says `registerRecords` skips a twin "whose dot-name already stands" — but at the records projection's registration point T6's autonomy methods are not yet standing (the human door registers after the records projection in this order), so the three reads would double-register. `autonomyCatalogSkip` (all **five** dot-names, `protocol/records.go`) tells the records projection to register none of the family: T6's human door owns the three reads, and the two proposes register as the records service's own socket methods beside their tools. The parity walk (`TestRecordsParityAutonomyFamily`) still pins tool↔twin both directions every run.
4. **`Describe` is the store's `changeSummary`, not a new sentence.** The spec's "Describe (the fixed-template sentence)" is already the store's own SEC-033 fixed template (`store/autonomy.go`'s `changeSummary` — ids and enums only, never the note or the reason), which every autonomy change row carries; the desk's `Effect` has no `Describe` half (the registry's three halves are Validate/AlreadyApplied/Apply), and the commit door's `policy_change` row uses the generic `committed <kind> proposal <id>` summary (op `commit` with an empty `policy_id` is schema-legal under 0042's CHECK: the `commit` op is in the audit branch, not the `policy_id IS NOT NULL` branch).
5. **The reason check lives in the seam's desk half, not the arm.** The spec's "reason required (1–512 bytes)" for the tools is enforced by `desk.ProposeReasonSentence`, which the seam's Validate runs — the same function `proposal.create`'s shared validator runs, so the create door and the commit door refuse an empty/overlong reason with the same bytes (the parity test compares the sentence). An arm-level copy would be a second definition.
