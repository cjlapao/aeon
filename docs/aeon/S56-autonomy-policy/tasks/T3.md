# T3 · Migration and store: grants, audit, use log, the pin

**Prefix:** AL · **Shape:** P3 · **Rules:** AL3, AL5, AL6, AL8, AL10 · **Depends on:** T1. Parallel-safe with T2.

## Goal

The four tables, their triggers, and the store's SQL half (I2: SQL only in `internal/store`): create/revoke grants with the audit row in the same transaction, the live read the decision site needs, the use log, and the pin written
inside `CreatePinnedLoop`'s transaction. No Go outside the store knows a table name.

## Files

- `aeon/internal/store/migrations/<date +%Y%m%d%H%M%S>_autonomy.sql` — **new**, leading `-- ` description line. Never edit `schema.go` or a shipped migration. T0 recorded whether `CREATE TRIGGER … BEGIN … END;` is allowed in a `.sql` migration; if
  not, the triggers ride in a `migration`-registered Go string beside it (T0's finding decides; record which).
  1. `autonomy_grant` (AL10): `id TEXT PRIMARY KEY`, `node_id TEXT NOT NULL REFERENCES component(id)` (the node the row sits on — a root for allows, a root or a child for denies; `autonomy_change.root_id` is the **root of that node**), `subject_kind CHECK IN ('action','class')`, `subject TEXT NOT NULL`, `state CHECK IN ('allow','deny')`, `conditions TEXT NOT NULL DEFAULT '{}'`, `note TEXT NOT NULL DEFAULT ''`,
     `expires_at TEXT`, `created_by_kind TEXT NOT NULL CHECK (created_by_kind = 'user')`, `created_by_id TEXT NOT NULL`, `proposed_by TEXT NOT NULL DEFAULT ''`, `created_at TEXT NOT NULL`,
     `revoked_at TEXT`, `revoked_by_kind TEXT CHECK (revoked_by_kind IS NULL OR revoked_by_kind IN ('user','cli'))`, `revoked_by_id TEXT`, `revoked_reason TEXT`,
     table `CHECK ((revoked_at IS NULL) = (revoked_by_id IS NULL) AND (revoked_at IS NULL) = (revoked_reason IS NULL))`, `CHECK (state = 'allow' OR (expires_at IS NULL AND conditions = '{}'))`,
     `CHECK (subject_kind = 'action' OR subject = 'outward')`. Indexes: `idx_autonomy_grant_node (node_id, state)`.
  2. `autonomy_change` — append-only; `BEFORE UPDATE` and `BEFORE DELETE` triggers `RAISE(ABORT, 'autonomy_change is append-only')`. Index `(root_id, id)`.
  3. `autonomy_use` — append-only, same triggers; `CHECK ((phase = 'begun') = (begun_id IS NULL))`; index `(grant_id, at)`, `(loop_id)`.
  4. `loop_autonomy_pin` — `loop_id TEXT PRIMARY KEY` (**no FK**: `store/archive.go` moves loop rows out), `root_id`, `rev INTEGER NOT NULL`, `origin CHECK IN ('schedule','webhook','event','scheduler')`, `labels`, `allowed`, `pinned_at`;
     `BEFORE UPDATE`/`BEFORE DELETE` triggers abort (a pin is immutable — AL6/AL8).
  5. Component triggers (additive, on S44-extra's table): `autonomy_grant_allow_root_only` (BEFORE INSERT on `autonomy_grant`: abort `'autonomy: allow grants sit on a root component'` when `state='allow'` and the node has a parent or is archived),
     `autonomy_grant_no_attach` (BEFORE UPDATE OF `parent_id` ON `component`: abort `'autonomy: revoke the autonomy grants of X before attaching it under another component'` when `NEW.parent_id IS NOT NULL` and an **active** allow exists for it).
- `aeon/internal/store/autonomy.go` — **new**: types `AutonomyGrant`, `AutonomyChange`, `AutonomyUse`, `AutonomyPin`; functions (all take a `store.Actor` where they write, refuse a non-`user`/`cli` kind **before any SQL** — AU1 lock 3):
  `CreateAutonomyGrant(a Actor, in NewAutonomyGrant) (AutonomyGrant, *AutonomyRefusal, error)` (one transaction: validate node exists/root-ness as sentences, INSERT grant, INSERT `autonomy_change` with the **fixed summary template**; refusal is a discriminated result, DB19);
  `RevokeAutonomyGrant(a Actor, id, reason string) (AutonomyGrant, []string /*affected running loop ids*/, *AutonomyRefusal, error)` (already revoked ⇒ no-op, no change row — "no-ops write nothing");
  `ListAutonomyGrants(f)`, `ReadAutonomyGrant(id)`, `AutonomyChanges(f)`, `AutonomyUses(f)`; `AutonomyRev(rootID) int64` (= `MAX(autonomy_change.id)` over the root, 0 if none);
  `AutonomyLive(ctx, loopID string, action string, now) (AutonomyLiveView, error)` — **the one read the decision site makes**: resolves the loop's component → root (`RootOf`), reads the pin row (if any), then for the pinned grant ids covering `action`: revoked? expired (`expires_at <= now`)?; and any active `deny` row on the loop's component **or** its root covering the action (by name or by `outward` expansion — the expansion list is passed in by the caller so SQL never encodes the registry); returns the raw facts, not a verdict (the pure side decides);
  `RecordAutonomyUse(loopID, grantID string, rev int64, action, phase string, beginID int64, ref string) (int64, error)`;
  `CountAutonomyUses(grantID string, since string) (int, error)` (the `maxPerDay` input).
- `aeon/internal/store/blueprint.go` — **minimal edit** inside `CreatePinnedLoop`: after the loop INSERT (line ~157) and in the same `tx`, `INSERT INTO loop_autonomy_pin` when `in.AutonomyPin != nil`. `NewLoop` (`store/loops.go:77-120`) gains `AutonomyPin *AutonomyPin` (a doc comment says *internal only, never on the wire; written once; no UPDATE touches the pin*). `CreateLoop` (the non-pinned legacy creator) is **not** changed.
- Count assertions bumped per T0 item 9 (one migration ⇒ +1), each with a dated comment; the literal vintage slices are before this file and do not change.

**Deviations from the spec.**
- **Count assertions (DoD "Count assertions bumped, dated"):** not done, and not needed. The 2026-10-30 file mechanism made the migration count dynamic (`len(Migrations())`, `frozenMigrationCount()`), so a new migration file needs no count bump; `TestFreshAndUpgradedSchemaIdentical`/`TestMigrationsApply`/`TestMigrationDir` already pass with the new file. The T3 spec's "bump the count" is superseded.
- **`AutonomyLive`'s veto expansion:** the spec (line 29) says the veto matches "by name or by `outward` expansion — the expansion list is passed in by the caller so SQL never encodes the registry". This build matches a class-`outward` deny by the literal in SQL (`subject_kind = 'class' AND subject = 'outward'`) rather than a caller-passed list. Consequence: a class-`outward` deny currently vetoes any action passed to `AutonomyLive`, not only outward ones. The store is pure (no registry), so it cannot decide outward-ness; per the spec the caller (the decision site, T5) passes the expansion. To be corrected when the decision site is built; the tests cover only outward actions, so the latent gap is not caught. Recorded, not fixed.

**Unrun.** The `aeon` CLI and socket surfaces that will call `AutonomyLive` (T5–T9) are not built yet, so the live read is exercised only by the store tests, not by a running daemon.
