# T5 · The decision site: live checks, conditions, the use log

**Prefix:** AL · **Rules:** AL4, AL6, AL9, AL10 · **Depends on:** T2, T3. Parallel-safe with T4.

## Goal

`internal/loop/execute.go` asks `ResolveWithGrant` instead of `Resolve`, feeding it the loop's pinned snapshot and the **live** facts; action-time conditions are evaluated through the seams (failing closed);
every unattended effect taken under a grant is logged begun → completed/failed. Everything after the verdict switch is unchanged.

## Behaviour — each is a test driven end to end (forge fake as witness, as `allowoutward_test.go` does)

1. **Granted run:** a schedule-pinned loop with an `allow forge.openPR` grant reaches `forge.openPR` ⇒ the fake **saw** the call; `autonomy_use` has `begun` then `completed`; the event carries `grant` and `rev`; the loop's `allow_outward` is still 0.
2. **Not covered:** the same loop reaching `forge.postReview` (not granted) ⇒ blocked `action-denied`, T2's sentence **verbatim**, zero fake calls.
3. **Revocation mid-run:** pin under the grant, revoke it, advance ⇒ blocked with the "was revoked at … by …" sentence naming the grant and the pinned rev; zero fake calls.
4. **Widening never reaches a running loop:** pin with no grant, then add `allow forge.openPR`, advance ⇒ denied.
5. **Veto beats the pin and beats a typed flag:** a veto on the component denies a pinned-and-granted action; and denies an action in a person-flagged (`allowOutward=1`, no pin) unattended loop.
6. **Expiry:** advance the store clock past `expires_at` ⇒ denied naming expiry; no row was written by time passing.
7. **Merge:** with `allow forge.merge` (forced `requireGates`, expiry) and the Gates seam answering `met` ⇒ the fake saw `MergePR`; with `unmet` ⇒ denied with the S57 sentence verbatim; **seam nil ⇒ denied naming that the merge rule could not be asked**; **a grant on `outward` alone ⇒ merge denied**
   (T1's `allowOutward does not grant it` sentence is still what a no-grant loop gets — T1 golden unchanged).
8. **`maxPerDay`:** the (N+1)th begun use in 24 h ⇒ denied naming the limit.
9. **Unauditable ⇒ no effect:** make `RecordAutonomyUse("begun")` fail ⇒ the fake saw **zero** calls and the loop is blocked.
10. **Crash window:** a `begun` with no outcome is returned by `autonomy.uses` as `outcome: unknown` (T6 renders it); here the store function returns it unpaired.
11. Attended loops: with a pin row present (contrived), an attended loop still **asks** exactly as before (OD2).
12. Zero-grant context path: T1's matrix, pin and execute goldens pass **unedited**.

### Deviations from the spec (and why)

1. **`AutonomyLive` treats `ErrNotFound` as no-grant, not an error.** The spec's step 2 says "a read error is returned". But a loop whose `component_root` resolves to **no registered component** is the *normal* no-grant case (the legacy byte-identical path), not a broken store — collapsing it into an error turned every unattended loop on an unregistered workspace into a runner-error (the T4 fix had to carry the same distinction, and the loop side regressed without it — **7 goldens**). Now: `ComponentForRoot`/`RootOf` `ErrNotFound` ⇒ `AutonomyLiveView{}` (Pinned=false ⇒ `ResolveWithGrant` returns base, byte-identical); only a genuine non-`ErrNotFound` read is returned, and the runner turns it into runner-error, fail-toward-deny (AL9).
2. **`AutonomyLive` takes `outward []string` (the caller's registry expansion).** T3's store matched a class/outward veto with a SQL literal (`subject_kind='class' AND subject='outward'`), so a class/outward veto would have overreached a **local or irreversible** action — AL2 says class/outward is shorthand for *every current outward action*, and the store never encodes the registry. The decision site passes `outwardActions()` (from `action.Classes()`); the store matches the name directly and the class only when the expansion names the action.
3. **Behaviour 9 (unauditable ⇒ no effect) uses a second, read-only handle on the same file.** There is no fault-injection hook on `*store.Store`, and the receipt-first property needs `RecordAutonomyUse("begun")` to *fail* while everything else reads. The test opens a second `store.Open` on the same directory with `Options.Env` returning `DATABASE_SQLITE_DSN = "file:<dbPath>?mode=ro"` and `SkipMigrations: true` (the first handle already migrated; the DB is already WAL, so mattn's `_journal_mode=WAL` pragma on a `mode=ro` connection is a no-op). Every write on it refuses at once; the test asserts `Run` returns an error (the block's own status save rides the same refused writer — the daemon's runner-error path, AL9: a write failure is a blocked kind of stop, never a run), the fake saw zero calls, and zero use rows (read through the writable handle).
4. **Behaviour 4 (widening never reaches a running loop) pins with an EMPTY allowed snapshot** (`"[]"` — valid store shape; `CreatePinnedLoop` writes the pin whenever `AutonomyPin != nil`). Contrived: the daemon's start path never writes an empty pin (no grant ⇒ no pin). The property tested is the immutable snapshot (AL8): an allow that appears on the root **after** the pin is not in it, and the live read of the pin's `allowed` (not the root's grants) decides — denied, byte-identical to the no-grant sentence, the fake stays shut across a second advance.
5. **The granted-run test (behaviour 1) needs a real git repository.** `forge.openPR` refuses a head nobody has pushed (the phantom-ref guard, O8): `svcWith`'s `ForgeActions` has no branch probe (`"no branch probe wired"`), and even wired, `BranchExistsRemote` needs `origin/task/<slug>/<task>` to exist. The test builds `gitTestRepo` + `pushTaskBranch(t, root, "task/granted/4a17")` and wires `ForgeActions.Git: &git.Client{}` (the probe is the client itself — the daemon's shape). Side finding: the pre-existing `TestOutwardRunsWhenOptedIn` asserts `strings.Contains(c.Method, "OpenPR")`, which **also matches `FindOpenPR`** — it passes on the pre-dispatch probe, not the effect. Not fixed here (T1 golden, unedited by mandate); recorded so the next task does not inherit the illusion.
