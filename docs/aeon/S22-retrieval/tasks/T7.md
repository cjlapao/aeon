# T7 — Context resolution feeding the manifest

## Why this exists

**V7's differentiator**, and its own task (R6):

> *"Retrieval can feed context declaration, not only answer a tool call. With declared context, the highest-value use is
> resolving 'this step needs the code relevant to T3' at assembly time. **This is the differentiator; the tool is the
> obvious half.**"*

That was written before context declaration existed. Now it does, and **two decisions constrain it absolutely**: K13
freezes the manifest, and K14 with S7 forbid re-resolution on resume or recovery.

## Scope

### Resolution happens once, at declaration (I3, D6, N7)

Retrieval feeds the manifest at declaration and **never again.**

**If a resumed step re-resolved, it could get a different context from the one that suspended** — and the manifest would
stop meaning anything, along with K14's report of what changed and S7's recovery.

**Answer Q4 first**: do resume and recovery share a context path, or two? **D6 must cover both** (C5), with the retrieval
spy at **zero** on each.

This is permanent (N7). There is no flag.

### A manifest entry records how it was resolved (V14, D5, O2)

```go
type ManifestEntry struct {
    Path       string
    Hash       string
    Resolution Resolution   // declared | retrieved
    Query      string       // retrieved only
    Score      float64      // retrieved only (O2)
}
```

**Why this matters more than it looks.** A declared entry is a human's or a plan's assertion. **A retrieved one is a
guess** — similarity picked it, and the file the step actually needs might not be there.

**A model that knows its context was guessed will verify with `grep`; a model that thinks it was declared will trust it.**
Same information, opposite behaviour — which is the whole reason to record it rather than to quietly merge the two.

**The score is included** (O2) because it is already computed, and a model deciding whether to trust a retrieved file
benefits from knowing it was the fourth result at 0.61 rather than the first at 0.93.

### Nothing found is recorded, not silent (O6, D-checks)

If resolution returns nothing, the step proceeds with its declared context **and the manifest says retrieval returned
nothing.**

**It is not an error, and it is not silence.** A step whose retrieval found nothing behaves differently from one where
retrieval was never asked — the first knows the index had no opinion, the second does not know retrieval exists.

### It reaches the model

The resolution provenance is in the context the model receives, not only in the store. S9 renders it for a human; the model
needs it for the reason above.

### Not in scope

The tool (T6). Reindexing (T8). This task is resolution and the manifest's new fields.
