# T4 — The code corpus, FTS5, and hybrid fusion

## Notes

**Fusion, stated (the task demands the method and its why)**: reciprocal rank
fusion — each list contributes `1/(k + rank)` at the rank **it** awarded
(k=60, the stock smoothing; its exact value is not load-bearing, WHAT is is
that only ranks enter the arithmetic). A cosine and a BM25 penalty are
different quantities with different ranges and sign conventions; a weighted
sum of them is "a number with no meaning that happens to sort" (the task's
sentence, quoted in the file). `TestFusionDoesNotCompareScoresDirectly`
enforces it two ways: a scan of `fuseRanked`'s body for any **read of a
source hit's score** (`.Score`-style reads of list magnitudes — the fused
output's own score comparison is legitimately comparable with itself, which
is precisely the line RRF draws), and behaviorally — a rank-0 hit with
score 1e-9 outranks a rank-1 hit with score 1e9, because the magnitudes
never reach the sum.

**Measured (vec0 knn, before writing the door)**: `WHERE embedding MATCH ?
AND k = ?` answers `(rowid, chunk_id, distance)`, L2, joinable through a
subselect (`FROM (SELECT chunk_id, distance FROM <vec> WHERE …) v JOIN
retrieval_chunk c ON c.id = v.chunk_id` — a JOIN directly on the virtual
table with the MATCH left to the planner answers ZERO rows silently, so the
subselect is not decoration). Distance is a penalty (smaller nearer); it
crosses the store boundary **negated**, the same sign discipline bm25
crosses under and for the same reason: one boundary rule beats N caller
memories. The dim-0 answer ("no embedding pass ever ran") is the store
door's and the wrapper's, not a `no such table` surprise.

**Measured (FTS5 bare words are an AND)**: the first fixture query
"where is resolveSocketPath defined exactly" returned NOTHING — "defined"
and "exactly" exist in no document, and AND kills the whole match. The
structural query is now the single token `resolveSocketPath` (which is what
a structural query actually looks like), and the conceptual fixture's token
check is **token-equality against the body** (camelCase `clampBackoff` is
ONE token, ≠ `backoff` — substring checks would have failed the gate

have missed it" claim is now *checked* in the test, not claimed.

## Why this exists

V3: retrieval is **hybrid** — vector plus FTS5 keyword, merged — because *"pure embedding search over code is mediocre, and
SQLite has FTS5 natively. The two failure modes are complementary."*

**Fusion is proven on code first** (R-ordering), where both failure modes are visible, before being applied to prose in T5.

## Scope

### Two indexes, one query

The vector index from T3's embeddings; an FTS5 index over the same chunks. A query hits both and the results are fused.

### The two failure modes, and why they are complementary (V3, D13)

| Query | Vectors | FTS5 |
| --- | --- | --- |
| *"where is `resolveSocketPath` defined"* | mediocre — an exact identifier has no useful neighbourhood | **wins** — it is a literal |
| *"how do we bound a retry"* | **wins** — the concept appears under several names | mediocre — no shared literal |

**Both must be present in fused results** (D13). A fusion that lets one source dominate has one failure mode rather than
none, which is worse than either alone because it looks like it is doing both.

### Rank fusion

Reciprocal rank fusion or an equivalent that does not require the two scores to be comparable — **and they are not.** A
cosine similarity and a BM25 score are different quantities, and a weighted sum of them is a number with no meaning that
happens to sort.

State the fusion method and why it does not compare the scores directly.

### The code corpus (V2)

Source files under the project root, chunked by T2, respecting the project's ignore rules — and **saying what it skipped**,
the same rule S11's `glob` and `grep` follow: an unexplained absence reads as "no matches".

### Results are locations (V4, D8, I5)

`file:line` ranges. **No chunk text, ever.** Quoting *"burns context, hands the model a stale snapshot, and disconnects it
from the real file"*.

Asserted as a property over every result, not per query — the same shape S16's T8 used for template placeholders.

### A query names its corpus (O8, I7)

No default. *A default corpus is a query whose scope depends on a setting the caller did not state*, and V2's whole point is
that the scopes differ.

### Not in scope

The history corpus (T5). The `search` tool (T6). Context resolution (T7).

worked; a set is the only way to see that the other did not stop contributing.
