# T6 — The `search` tool, registered only when built

## Why this exists

**The tenth tool** (W1), and **its conditional registration is D1's other half** — T1 proved the suite passes without the
package; this proves the tool is absent rather than present-and-empty.

## Scope

### Registered only when retrieval is built (V13, D1, D2)

In the no-retrieval configuration, `search` is **not in the registry.** Not registered-and-failing, not
registered-and-empty.

**An empty result is a claim about the repository.** A handler that searches for *"where is the retry policy"* and gets
nothing reasonably concludes there isn't one and moves on. A handler with no `search` tool reaches for `grep` — which is
what V5 wanted.

**And empty is not absent** (D2). With retrieval present and the index not yet built, `search` **exists** and reports
`index-empty` — a different observation, and the one that tells someone to run an index rather than to give up.

### The description carries V5's rule (O7, V5)

V5's stated reason is *"so a model does not reach for similarity when it wants a definition"* — **which only works if the
description says so**, in the words a model reads:

```
Semantic and keyword search over this project's code or its loop history.
Returns file:line locations, never file contents — read the file to see current truth.

Complements `grep`; it does not replace it. For an exact identifier, a literal
string, or a definition, use `grep` — it has an exact answer and this does not.

Requires a corpus: "code" or "history". There is no default.
```

**A rule stated only in a design document governs nobody.** The model reads the description.

### Results are locations (V4, D8)

`file:line` ranges with scores. **No chunk text.** Inherited from T4 and asserted again at the tool boundary, because this
is where a model would see it.

### The corpus is required (O8)

No default, and the description says so. A query without a corpus is a tool error the model can correct — not a guess.

### Re-run class (Q6, S7's W16)

`search` is **`safe`**: read-only, so recovery re-runs it without thought. S11's committed class list marked it absent; it
becomes present here, and the fixture is updated.

**In the no-retrieval configuration the fixture must still be consistent** — `search` marked as not-registered rather than
missing, so the list does not fail in a build where the tool legitimately does not exist.

### The socket twin, not only the tool (D15, I10, P34 — added 2026-10-26)

**`search.query {projectRoot, corpus, query}` is a registered socket method**, calling the identical
resolver function `search` the tool calls — not a second search implementation. Same `file:line`-only shape
(D8), same corpus-required rule (O8), same `index-empty`/keyword-only honesty (D2, D4). Registered in the
no-retrieval build configuration too — absent there, mirroring the tool's own conditional registration
(V13), asserted the same way. This is what lets a human exploring the app search the project the way an
agent step already can; without it, the only way to search from the app is to start a loop and read its
transcript.
