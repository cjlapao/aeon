## Why this exists

**This is the corpus the demo's first question needs**: *"have we decided this before?"* — answered from past briefs and
handoffs.

And it is a **separate task** because V15's rule is the whole content of it: **nothing is indexed that has not passed
through something that could redact it.**

## Scope

### The rule, applied (V15, D7, I4, N6)

The inherited statement is unchanged and worth keeping verbatim: **`step_message` is never indexed, because transcripts
hold tool output no redaction pass has seen.**

Generalised, it becomes a **test** for any candidate source, not a list to memorise:

| Source | What stood between it and the index |
| --- | --- |
| `produces:` artefacts — briefs, plans, discovery | **Written to a file a person reads and reviews** |
| Handoffs | **A declared schema with stated field purposes** (S13's O6) |
| Chat messages | **Human-authored** |
| **`step_message`** | **Nothing.** Raw `bash` output, file contents, whatever a command printed |

**Answer Q8**: the full list, and for each, what stood between. **A missing list blocks the task** — V15 is a property, and
the list is where it is applied.

`CORPUS.md` records that list and its reasoning, so a future corpus is decided by the same test rather than case by case.

### It is permanent (N6)

Not behind a flag. Not for a trusted project. Not for a project whose author asserts their transcripts are clean.

The reason is that **the author cannot know**: a transcript holds whatever a command printed, and a command's output is not
something anyone reviewed before it landed. A flag would be a promise nobody is in a position to make.

Worth a comment in the code saying so, because the next person to want it will look for the flag first.

### Chunking prose (V11's fallback, T2)

History is mostly prose, so it takes T2's **line-window** path — which T2 established is the normal path rather than a
degraded one. Sections make natural boundaries where a document has them.

### Never merged with code (V2, D12)

Different chunking, different staleness, different value. And merging them makes *"search only past decisions"*
**impossible** — which is exactly the demo's first question.

Asserted both ways: a history query returns no code, and a code query returns no history.

### Not in scope

The `search` tool (T6). Context resolution (T7). Async reindex (T8).

direct case; grepping the indexer's inputs catches the version where somebody adds a source that happens to read a
transcript on the way.
