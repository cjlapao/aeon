# T5 · The `blueprints.standard` seed set, and retiring the hash table

**Prefix:** BP · **Rules:** BP5, BP6 · S43-extra SD2/SD3/SD5/SD6/SD12 · **Depends on:** T3, T4 and **S43-extra T3** (the engine).

## Goal

The shipped blueprints are **seeded records**: current at every start, versioned, hash-checked, never overwriting an operator's edit. The hand-rolled `pristineUpgrades` table is retired (its intent is the engine's rule), with a test proving nothing it
recognised is lost.

## Files

- `aeon/internal/blueprintseed/` — **new** package (domain side of the engine; imports `internal/blueprint`, `internal/seed`; no `internal/mcp`, no policy):
  - `source.go` — `Source() []seed.Record`: one record per **embedded** standard blueprint (T0 settled the exact list incl. the `two-step` question); `Key` = name; `Content` = canonical JSON `{name, version, content}` where `content` is the embedded YAML bytes **verbatim**; per-record `Version` guarded by `testdata/blueprints.versions.golden` (`TestBlueprintVersionsBumpWithContent`: "content changed but version did not — bump it").
  - `applier.go` — `Upsert(tx, r, adopt)`: write `blueprint` (`origin='system'`, `updated_by='system:seed'`) + `blueprint_revision` (`op='seed'` new / `'update'` higher version / `'restore'` via restore) + `blueprint_ref` — **through `store.BlueprintPutTx`, the one write path**; `Fingerprint` = `content_hash` of the live row; `Retire` flags only; `GuardAffecting()==false`; `Operator() = {Edit:true, Remove:false}`. **Adoption rule:** a live row with `origin='system'` whose hash equals the shipped content or a known pristine hash is adoptable (update in place); any other live row ⇒ **conflict (skip, reported)** — an edited shipped blueprint is never overwritten.
  - `pristine.go` — the **previously recognised hashes** (`legacyTwoStepWithoutReworkSHA256`, `legacyTwoStepWithReworkSHA256`, the `dev-loop` hash) as one documented constant slice **moved from `standard.go`** and used by `Adoptable`/T4's classifier; `standard.go`'s `pristineUpgrades` and `upgradePristineStandard` are **deleted** from the production path (the legacy file resolver may keep a test-only copy if existing tests need it — listed).
  - `decl.go` — `init()` registers `blueprints.standard`, class **inert**.
- `aeon/internal/seed/registry_test.go` — the default-registry assertion lists `blueprints.standard` with the other present sets (T0 records which merged).
- The set applies **at daemon start** with the other inert sets (S43-extra T6) — **after** T4's adoption.

## Behaviour

1. **Fresh store:** every shipped blueprint is a system row at start; `blueprint.list` shows them with `origin=system`.
2. **Upgrade of a pristine copy:** row at an older shipped content ⇒ engine `update` in place (revision `update`) — what `upgradePristineStandard` did for `two-step` and `dev-loop`, now for **every** shipped blueprint and recorded.
3. **Edited shipped copy:** `conflict`/`diverged`, **skipped and reported** in `seed.status` with the reason; the operator's content stays; `seed.restore {set:"blueprints.standard", key}` (human door) re-applies shipped content as a new revision (`restore`); `blueprint.diff … shipped` shows the difference.
4. **Removed from code in a later release:** `retired` (row kept), never auto-deleted.
5. Applying writes `seed_event` (engine) and the blueprint's own revision; no `policy`/`mcp` involvement.

## Definition of done

- [x] `blueprints.standard` declared (inert), one record per shipped blueprint, versions guarded by a golden; applied at start after adoption.
- [x] Pristine upgrades via the engine for every shipped blueprint; edited copies never overwritten; restore explicit; retire keeps rows.
- [x] The hash table retired from production with every hash proven; both audits (revision + `seed_event`) written.

## Do NOT

- Do not overwrite an edited blueprint; do not auto-delete a retired one; do not write rows outside `BlueprintPutTx`.
- Do not register the set as guard; do not keep two upgrade mechanisms in production.
- Do not edit an engine file (S43-extra) or the blueprint engine.

**Deviations (recorded).** D-T5-1 **Fingerprint re-envelopes**: the engine
hashes a record's canonical JSON Content, while the row stores the YAML
bytes verbatim (BP-verbatim wins) — so `Fingerprint` rebuilds the
`{name, version, content}` envelope from the live row and hashes that
(`seed.Hash`); applied==live exactly when the row holds the record, and a
hand edit of the content column still reads as a diverge. Without this the
up-fixture reported "11 diverged" from boot (measured).
D-T5-2 **Revision op is inferred**: the engine's `Upsert(tx, r, adopt)`
carries no op (Restore calls the same `adopt=false`), so the op comes from
(adopt flag × row presence × the ledger's state/applied hash — a READ of
the engine's memory via `store.SeedLedgerList`, never a write):
no-row⇒`seed`, adopt⇒`update` (pristine in place), unmodified-under-ledger
⇒`update`, other-bytes⇒`restore` (only seed.restore may reach a diverged
row). The plan makes those states exclusive, so the inference is total.
D-T5-3 **Retire writes nothing**: the blueprint table has no retired
column and the revision op vocabulary is closed by T1's CHECK; the memory
is the engine's ledger (`state='retired'`), asserted directly.
D-T5-4 **The New-time arrival net stays** (T3's D-T3-2): `SeedStandardBlueprints`
creates missing rows ONLY (never upgrades) so direct `daemon.New` callers —
the whole S8–S47 test surface — stay green unedited; the engine owns
adopt/update/idempotency in production. A fresh production boot therefore
carries two honest revisions per shipped name (the net's `seed`, the
engine's `update`-on-adopt) and one ledger row; the audit reads true and
the second start writes nothing (pinned).
