# T6 · Writes: save, duplicate, delete, revert — revisions, refs, and agent-delete protection

**Prefix:** BP · **Rules:** BP4, BP6, BP7, BP10, BP11, BP12 · **Depends on:** T3. (Develop on one branch with T3 — T3 leaves `save` unwired.)

## Goal

A person can create, edit, duplicate, revert and delete blueprints through the socket. Every write validates with the **unchanged** `Analyze`, writes the row, its revision and its derived refs in **one transaction** through `BlueprintPutTx`, and is attributed to
the peer. Deleting an agent that blueprints still use is refused **by name** (an adaptation of S43's merged delete path — S48's own change).

## Files

- `aeon/internal/daemon/blueprint_write.go` — **new**: the single write service (`save`, `duplicate`, `delete`, `revert`); the only daemon file calling `store.BlueprintPutTx/BlueprintDeleteTx`.
- `aeon/internal/protocol/blueprint_loop.go` — **no edit**; new file `aeon/internal/protocol/blueprint_manage.go`: params/results and handlers for the three new write methods and the **rewritten** `blueprint.save`:
  - `blueprint.save {name, content, createOnly?, mode?, note?}` → `{name, changed, revision, origin, version, report, references}`. Order: strict decode → actor (`table.ActorFor`; unresolvable ⇒ `ErrBlueprintNoActor`, nothing written) → size ≤ 1 MiB → **`Analyze` (same options as today)** → `!OK(false)` ⇒ refusal carrying the **report verbatim** (today's behaviour) → `report.Blueprint == name` → `createOnly` collision ⇒ refusal naming the existing name → **identical content ⇒ `changed:false`, no revision** → `BlueprintPutTx` (row + next revision `op='create'|'save'` + `References(...)`) → result.
  - `blueprint.duplicate {from, name, note?}` → `Duplicate(src, name)` (T2: textual, comments preserved) → the same `Analyze` + write path with `op='duplicate'`; `from` unknown ⇒ refusal naming nearest names; `name` taken ⇒ refusal.
  - `blueprint.delete {name}` → refused for `origin='system'` ("a shipped blueprint cannot be deleted; restore or duplicate it"); refused while `BlueprintReferences` is non-empty, **naming every referencing trigger/schedule/queue item** (`ErrBlueprintInUse`); otherwise `BlueprintDeleteTx` and result `{deleted:true, loopsStartedFromIt: N, note: "started loops keep their pinned content"}`.
  - `blueprint.revert {name, rev, note?}` → loads the revision, runs it through the same `Analyze` + write path with `op='revert'` (a **new** revision; a revision that no longer validates — e.g. an agent it names was deleted — is refused with the report, never silently written).
  Params carry **no** `actor`, `origin`, `rev` for create, timestamps (`DisallowUnknownFields`); the actor is stamped.
- `aeon/internal/protocol/method.go` — consts `MethodBlueprintDuplicate/Delete/Revert` in a labelled block; `MethodBlueprintSave` keeps its registration (handler updated); `RequiresInitialize`, not `Debug`; conditional on the write service (V13) **for the three new ones**; `save` keeps today's seed seam name (`Table.SaveBlueprint`) so the existing registration and bench keep working — its **implementation** is replaced.
- `aeon/internal/protocol/errors.go` — `ErrBlueprintRefused` (carries the report/sentence verbatim), `ErrBlueprintNoActor`, `ErrBlueprintInUse`; contract chain: conformance cases, handshake block "S48 writes", fixtures (success + each refusal), `make protogen`.
- **Agent-delete adaptation (listed in Notes; S43's tests unedited):** `internal/agentmgr`'s delete path gains the blueprint reference check — one added accessor use `Store.BlueprintRefsFor("agent", slug)` (T1) beside its existing checks; the refusal names every referencing blueprint. If T0 found S43's current blueprint check is a text scan, it is **replaced by this query** in the same function (one added/changed branch, recorded).

## Behaviour notes

1. **One write path:** every blueprint write ends in `BlueprintPutTx` (T1); a guard (T8) pins the call sites.
2. **Revisions:** exactly one per changing write; none for a refusal or `changed:false`; numbering continues across delete/recreate.
3. **System blueprints** (BP6) may be saved (edit ⇒ the ledger will read `diverged`; the next seed skips it), duplicated and restored; never deleted.
4. **Refs** are rebuilt in the same transaction from the saved content; a consistency test re-extracts and compares.
5. **Pinned loops are untouched** by any write (`loop_blueprint` is not written here).
6. **Live:** the next `loop.start`/fire sees the new content with no restart (T3).
7. The `note` is a ≤ 256-byte free text stored in the revision; it is **never** interpolated into an advisory or log line unescaped (SEC-033).
