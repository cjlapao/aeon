# T3 · The source switch: every reader from files to rows, byte-identically

**Prefix:** BP · **Rules:** BP2, BP4, BP12 (compat) · **Depends on:** T1, T2.

## Goal

The database becomes the source of truth for **every** blueprint reader, with output identical to the file-based behaviour. This is the riskiest step of the slice, so it is **characterization-first**; T0's reader inventory is the work order.
After this task no runtime path reads a blueprint file; the file code survives only for T4's importer.

## Phase A — characterize (commit first, green on untouched code)

`aeon/internal/daemon/blueprint_golden_test.go` + `aeon/cmd/aeon/blueprint_golden_test.go` + `testdata/bpgolden/*`: with each standard blueprint materialized as a **file** exactly as today (and one edited standard copy, one custom file), record: `blueprint.list`,
`blueprint.show`, `blueprint.validate` (content and by-name), `blueprint.save` results (valid, invalid, id-mismatch, createOnly collision), the **pinned content** a `loop.start` writes to `loop_blueprint` for each, the trigger/queue **fire-time validation** outcomes
(valid, invalid, missing blueprint), and `aeon blueprint list|validate|path|fields` output. Record the Phase A commit in Notes.

## Phase B — the change

- `aeon/internal/blueprint/source.go` (extend T2's) — `SetSource(Source)` (production wiring; panics if called twice) and package-level `Get/Names/Standard` delegating to the installed source; **`Resolve`, `NamedPath` and the file `Names()` are retained but marked file-only (importer + tests) and renamed with a `Legacy` prefix in a follow-up edit inside this task** (`LegacyResolve`, `LegacyNamedPath`, `LegacyNames`) so a stray caller fails to compile and is found. Existing tests that call the old names move to the legacy names mechanically (list in Notes).
- `aeon/internal/daemon/blueprint_source.go` — **new**: the store-backed `blueprint.Source` (`Get` = `store.BlueprintGet`; `Names` = rows; `Standard` = the embedded standard names), **no cache** (N8: a write is visible to the next `loop.start`).
- `aeon/internal/daemon/blueprint.go` — `ListBlueprints/ShowBlueprint/ValidateBlueprint/loadStartBlueprint` read through the source. `SaveBlueprint` is **not** rewritten here (T6) — until T6 it returns `ErrNotWired`-style "blueprint writes move to the database in S48 T6" **only if** T3 lands alone on a branch; otherwise T3 and T6 are developed on one branch (record which). `blueprint.list` keeps `{names}` and gains nothing yet; `blueprint.show` keeps `{name, path, content}` with `path` `""` (BP12 — T0 item 5 says whether anything breaks).
- The trigger/queue/automation **fire-time validators** (T0 item 3) read through the same source; an unknown blueprint refuses with the sentence they use today.
- `aeon/cmd/aeon/blueprint.go` — `list` prints source names (**includes custom blueprints — the one intentional change, BP13**, listed in Notes with the golden diff); `validate` by name reads the source; `path` is **left unchanged until T11** (it still calls the legacy resolver; T11 retires it) — recorded.
- `aeon/cmd/aeon/serve.go` — install the store-backed source after the store opens and **after** T4's adoption/T5's seed run (hook point recorded in T0); CLI verbs with no database use `embeddedSource` through a named `blueprint.UseEmbeddedForOfflineTools()` (never reachable from `serve`; a test proves it).
- **No fallback**: a name not in the table is "unknown blueprint" — never read from a file or the embed in production paths.
