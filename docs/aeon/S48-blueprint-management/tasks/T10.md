# T10 · Agent tools: four reads and one propose

**Prefix:** BP · **Rules:** BP9 · standing rule 2 · S38 OL2/OL3/OL10 · **Depends on:** T7, T8, T9.

## Goal

Agents can **see and check** blueprints and **propose** one — never save, delete, duplicate or revert. Five catalog specs (one definition, two doors), registered and granted to no one by default.

## The five specs (`internal/records/catalog.go`, additive; family `blueprint`)

| Tool | Socket twin | Class | Mutates | What it does |
| --- | --- | --- | --- | --- |
| `blueprint_list` | `blueprint.list` (existing) | safe | no | List blueprints: name, origin (shipped/yours), version, whether a shipped one has been edited, how many things use it |
| `blueprint_show` | `blueprint.show` (existing) | safe | no | One blueprint's full YAML, its validation report and what it references |
| `blueprint_validate` | `blueprint.validate` (existing) | safe | no | Validate YAML text you provide (nothing is saved) and return the three-state report |
| `blueprint_lint` | `blueprint.lint` (T7) | safe | no | Advisories for a blueprint or YAML text: which steps' agents the policy would currently deny or has no rule for, as of now |
| `blueprint_propose` | `blueprint.propose` (new, this task) | detectable | **yes** | Create an **inert proposal** to add or change a blueprint (kind `blueprint_save`); nothing changes until a person commits it |

`registerRecords` skips a twin whose dot-name already stands; only `blueprint.propose` is a new socket method.

## Rules (each a test)

1. **Schemas** are `additionalProperties:false` with **no** `actor`, `source`, `status`, `kind`, `origin` or `rev`; `blueprint_propose` input `{name, content, create_only?, note}`; `note` ≤ 256, `content` ≤ 1 MiB (+ envelope). Identity is stamped (OL3).
2. **Propose is inert and validated at create:** the service calls `desk.Validate` (T9) first — an invalid blueprint is refused **at create** with the report (S35 TD3) and creates nothing; a valid one creates a `blueprint_save` proposal via the same path as `proposal.create` with `created_by` = the stamped agent.
3. **No tool writes:** none of the five can save, duplicate, delete, revert or commit (T8 asserts the catalog/registry); `blueprint_validate` and `blueprint_lint` take **text** and persist nothing (a spy asserts zero writes, including no revision and no proposal).
4. **Reads equal the socket reads** field for field (one implementation); `blueprint_lint` carries its `evaluatedAt`; an unwired catalog yields the explicit `unavailable` state, not an empty "all clear".
5. **Limits:** a per-agent open-proposal limit (the named constant S45 defined) with a counted refusal naming it and how to see them; the validate/lint tools are size-capped (1 MiB) and refuse over-size input by name.
6. **Counted registry bump** (**+5**, from T0's recorded count; dated comment); descriptions ≥ 40 chars; **not** in `DefaultGrant()`; the lint's policy reasons are shown **verbatim**.
7. A person's `proposal.discard` of an agent's proposal is unchanged (S35).
