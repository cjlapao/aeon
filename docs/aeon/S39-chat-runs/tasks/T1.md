   ```go
   const migrationNNNN = `
   CREATE TABLE loop_run (
     loop_id            TEXT    NOT NULL REFERENCES loop (id) ON DELETE CASCADE,
     run_seq            INTEGER NOT NULL CHECK (run_seq >= 1),
     blueprint          TEXT    NOT NULL,
     blueprint_version  INTEGER NOT NULL,
     content            TEXT    NOT NULL,
     runtime_json       TEXT,
     state              TEXT    NOT NULL CHECK (state IN ('running','done','failed','cancelled')),
     started_by_kind    TEXT    NOT NULL CHECK (started_by_kind IN ('user','agent','trigger')),
     started_by_id      TEXT    NOT NULL DEFAULT '',
     kickoff_message_id INTEGER,
     goal_id            TEXT,
     goal_version       INTEGER,
     task_id            TEXT,
     started_at         TEXT    NOT NULL,
     ended_at           TEXT,
     PRIMARY KEY (loop_id, run_seq),
     CONSTRAINT ck_loop_run_end CHECK (
          (state = 'running' AND ended_at IS NULL)
       OR (state <> 'running' AND ended_at IS NOT NULL))
   );
   CREATE INDEX idx_loop_run_state ON loop_run (loop_id, state);
   ALTER TABLE step ADD COLUMN run_seq INTEGER;
   INSERT INTO loop_run (loop_id, run_seq, blueprint, blueprint_version, content, runtime_json, state,
                         started_by_kind, started_by_id, started_at, ended_at)
   SELECT b.loop_id, 1, b.blueprint_id, b.blueprint_version, b.content,
          CASE WHEN l.status IN ('done','aborted') THEN b.runtime_json END,
          CASE l.status WHEN 'done' THEN 'done' WHEN 'aborted' THEN 'cancelled' ELSE 'running' END,
          CASE WHEN l.started_by = '' THEN 'user' ELSE 'trigger' END, l.trigger_id, l.started_at,
          CASE WHEN l.status IN ('done','aborted') THEN l.updated_at END
   FROM loop_blueprint b JOIN loop l ON l.id = b.loop_id;
   UPDATE step SET run_seq = 1
    WHERE EXISTS (SELECT 1 FROM loop l JOIN loop_blueprint b ON b.loop_id = l.id
                   WHERE l.slug = step.loop_slug AND l.project_root = step.project_root);
   `
   ```

What the task file could not know (all three from T0, honoured here):

- **The seed SQL speaks `component_root`, not `project_root`** — 0035 renamed it on `step` AND `loop`; the first test draft died exactly as T0 predicted. The migration's UPDATE JOIN is scoped `l.component_root = step.component_root` (the live name); the shipped `CREATE TABLE step` still says `project_root` — document-vs-live drift is by design.
- **`COALESCE(l.trigger_id,'')`**: the task's INSERT passed `l.trigger_id` directly, but `trigger_id` is NULLABLE (loops.go reads it through COALESCE) and an explicit NULL into a `NOT NULL DEFAULT ''` column breaks the backfill of every pre-S20 and non-trigger loop. The CASE for `started_by_kind` also tolerates NULL (`started_by IS NULL` → user), measured by `TestLoopRunMigrationMapsStartedByToTheRunsStarter` (trigger/t1 vs user/'').
- **`l.goal_id, l.goal_version` ride the backfill; `l.task_id` does not exist** (S38 T13 put goal coords on `loop`, task links live in `task_loop`) — the task's VERIFY step resolved that way: goal coords copy for the single-run case (CR2's "loop column is kept as the first run's goal"), `task_id` stays NULL until a run actually works a manual task.
- **Count bumps were EIGHT sites in three files, not the task's "two/three in policy_test"** (T0-Q9's list — the task was written before S38's two migrations moved them): `schema_test.go:909/922`, `policy_test.go:307/458/1318` (heads read 37 now, per the precedent S38 set of head-only edits), `loop/counters_test.go:280/284` (which also pins `last.ID`/name — moved to 37/`loop_run` per its own contract).
