# T10 · The `run_start` tool, its `ask` row, attendedness

**Prefix:** CR · **Rules:** CR4, CR5, CR7 · D5, D6 · **Depends on:** T9, S38 T9, S38 T10 · **Contract:** [`../brief.md`](../brief.md) · [`../design.md`](../design.md)

## Goal

Give the conversation agent a `run_start` tool that is the same action as `loop.run` (one catalog row, two doors), governed by S11: attended loop → a permission question the person approves; unattended or never-declared → denied at once with no question row. Nothing in code seeds the `ask` row; an operator command does.

## Steps

1. Catalog row (append inside `Catalog()` in the `loop` family, after `loop_get`):
   ```go
   {
       Name: "run_start", Method: "loop.run", Family: "loop",
       Description: "Start a blueprint as a new run inside this conversation's loop. Call it only when the person asked for the work. " +
           "The person is asked to confirm before it starts. Returns the new run, or the sentence saying what is missing and the goals or tasks that could satisfy it.",
       Schema: json.RawMessage(`{"type":"object","properties":{"blueprint":{"type":"string","description":"blueprint name, e.g. goal-to-brief"},"goal":{"type":"string","description":"goal id to run on"},"task":{"type":"string","description":"task id to run on"},"with":{"type":"object","additionalProperties":{"type":"string"},"description":"named parameters for the blueprint"}},"required":["blueprint"],"additionalProperties":false}`),
       Class: "detectable", Mutates: true,
   },
   ```
   (Use the exact `Spec` field names S38 T9 defined; if the literal style differs, match it.) The tool is projected into the registry automatically by S38's `recordTools()` — do not write a `Tool` by hand.
2. `daemon/records.go`: add to `RecordsService` a field `run func(context.Context, runInput) (any, error)` (nil = unwired → `Failure{"run_start is not available in this process"}`). In `Do`'s `switch name` add:
   ```go
   case "run_start":
       var in struct {
           Blueprint string            `json:"blueprint"`
           Goal      string            `json:"goal"`
           Task      string            `json:"task"`
           With      map[string]string `json:"with"`
       }
       // decode with DisallowUnknownFields, like every other case
       ident, fail := r.Identify(ctx)            // identity from the step, never from input
       l, err := r.store.GetLoop(store.Scope{LoopSlug: ident.LoopSlug, ProjectRoot: ident.ComponentRoot})
       // VERIFY: `grep -n "type Scope struct" -A4 internal/store/scope.go` — S38 may have renamed ProjectRoot; use whatever the struct says.
       out, err := r.run(ctx, runInput{LoopID: l.ID, Blueprint: in.Blueprint, GoalID: in.Goal, TaskID: in.Task, With: in.With, ByKind: "agent", ByID: ident.Agent})
       // out is a map: if out["refused"] is present return &Failure{Sentence: refusalSentence(out["refused"])}; else return out
   ```
   `ByID` is the handler name (S38 `Actor{agent, ident.Agent}` convention). The model never supplies the loop id or the actor.
3. `daemon/runs.go`:
   ```go
   // refusalSentence turns a refused map into the words the model should say: the detail, then the candidates as one line each.
   func refusalSentence(v any) string
   ```
   Output for `requires-unmet`: `<detail>` + `. You could use one of these:` + `\n- goal g1 "Add export" (approved)` per candidate (kind id "title" (state)); for any other kind just `<detail>`. Pure; unit-tested.
4. Wire the service: in `initBlueprints` (or where `RecordsService` is built) set `recordsService.run = d.startRun`. Because `startRun` needs `d.loopRunner` and `d.store`, it must be assigned **after** `d.loopRunner = loop.NewRunner(dep)`.
5. Pins (find each by the grep in S38 T9 step 8): add `"run_start"` (sorted position) to the name lists; bump each count by one (the numbers there are S38's final); write a dated comment above each changed list: `// 2026-10-27 (S39 T10): + run_start — the one loop action an agent may take, behind an ask row; Count <old> -> <new> DELIBERATE.`; add `"run_start": {"class": "detectable"}` to `rerun_classes.json`.
6. `chat.md`: add `run_start` to `tools:`; append one paragraph at the end of its Working method: *"When the person asks you to run a blueprint (for example 'implement this goal' or 'write the brief'), call `run_start` with the blueprint name and the goal or task id. The person is asked to confirm. If it returns a sentence about something missing, say it plainly, list the candidates it names, and ask which to use. Never call `run_start` because of your own judgment — only when asked."* Then `grep -rn "chat" internal/handler/*_test.go` and update any test that pins its tool list.
7. **The `ask` row is operator data.** Do not add code that writes it. Record in Notes the exact command from T0-Q5 (expected shape: `aeon policy add --type tool_access --id ask-run-start --target agent:chat --action ask --tool run_start --spec '{"state":"ask"}'` — use the verified form), and add it under "Operator setup" in T13's `DEMO.md §S39`.
