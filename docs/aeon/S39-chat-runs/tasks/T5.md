# T5 · Message `source`, the `loop.message.posted` event, nudge labelling

**Prefix:** CR · **Rules:** CR6, CR10 · D7, D10 · **Depends on:** T4, S38 T12 · **Contract:** [`../brief.md`](../brief.md) · [`../design.md`](../design.md)

## Goal

Every thread message and every queued steer records where it came from (`user | template | automation | blueprint`), and the daemon can publish a `loop.message.posted` event so the loop screen can draw thread messages. Steer wire shapes stay byte-identical.

## Prerequisites

- T4 merged; S38 T12 merged (the engine's `missingRecord` nudge exists).
- T1's migration is the last one: `grep -n "_loop_run" aeon/internal/store/schema.go` prints its entry (id L+1, see T1's numbering rule). This task adds id **L+2** named `MMMM_message_source` (`MMMM` = L+2 zero-padded; example: L+1=37 gives `0038`). Never assume 0030: it is taken.
- T0-Q4 verdict read: does S38 already add `step_steer.source`? Check now: `grep -n "ALTER TABLE step_steer" aeon/internal/store/schema.go`. If a line adds a `source` column, **skip every `step_steer` item below** (Step 1's second `ALTER`, Steps 4, 5, and the steer tests) and only confirm its value set equals `user, template, automation, blueprint` — if it differs, STOP and report to the coordinator.

## Steps

1. Migration. Append to `Migrations()`: `{L+2, "MMMM_message_source", "chat_message.source and step_steer.source — where a message came from: user, template, automation or blueprint (S39 CR6)", migrationMMMM}` and
   ```go
   const migrationMMMM = `
   ALTER TABLE chat_message ADD COLUMN source TEXT CHECK (source IS NULL OR source IN ('user','template','automation','blueprint'));
   UPDATE chat_message SET source = 'user' WHERE author = 'human';
   ALTER TABLE step_steer ADD COLUMN source TEXT NOT NULL DEFAULT 'user' CHECK (source IN ('user','template','automation','blueprint'));
   `
   ```
   `chat_message.source` is NULL when the row was not typed or rendered by a person or automation (agent and system rows, legacy rows). Before committing, apply it to a populated copy using the recipe in T1 step 4 (`rawGorm` + `applyMigrations(Migrations()[:L+1])`, seed rows, `Open`) — if SQLite refuses `ADD COLUMN … CHECK`, STOP and report; do not rebuild the table. Bump every `len(Migrations())` assertion (T1 step 3's grep) by one.
2. `chat.go`: add `Source string` to `NewChatMessage`; add `Source string \`json:"source,omitempty"\`` to `ChatMessage`; add `func ValidSource(s string) bool` (true for `""`, `user`, `template`, `automation`, `blueprint`). In `appendThread` (line ~486): compute
   ```go
   source := m.Source
   if source == "" && author == "human" { source = "user" }
   ```
   (after `author` is defaulted), return an error if `!ValidSource(source)`, and add `source` to the `INSERT` column list and values using `nullable(source)`. In `Thread` and `readChatMessage` add `COALESCE(source,'')` to the `SELECT` and scan into `&m.Source` (scan order must match the column order you wrote).
3. `appendThread`'s existing callers (`Ask`, `Answer`, `CommitGate`, `AnswerGate`, `Note`) pass no `Source`; they get NULL (agent/system) or `user` (human) with no edit.
4. `steers.go`: add `Source string` to `NewSteer` and `Source string \`json:"source,omitempty"\`` to `Steer`; add `, source` to the end of `steerColumns`; add `&st.Source` to the end of `scanSteer`'s `Scan`; in `QueueSteer`, `INSERT` the source (`orDefault(in.Source, "user")`, refuse `!ValidSource` or `""`-only values other than empty). Read `QueueSteer` fully first (line 167-232) and change only the `INSERT`.
5. `protocol/steer.go`: add `Source string \`json:"source,omitempty"\`` as the LAST field of `SteerView`. `daemon/steers.go`: in `steerViewOf` add
   ```go
   if st.Source != "" && st.Source != "user" { v.Source = st.Source }
   ```
   (build `v` first, then `return v`). Result: a person's steer serialises byte-for-byte as before; only a labelled one carries `"source"`.
6. S38 T12's nudge: find where the engine queues it — `grep -rn "QueueSteer" internal --include='*.go' | grep -v _test`. For the call that queues the `missingRecord` push-back, set `Source: "blueprint"` in the `store.NewSteer`. If S38 T12 already set a source another way, leave it and record in Notes. If the nudge goes through `protocol.SteerStore.QueueSteer(stepID, text, route, effort)` (no source parameter), do **not** change that interface (three test fakes implement it); add `QueueSteerFrom(stepID int64, text, source string) (SteerView, error)` to `daemon.StepStore` only, and have the engine's caller use it via a type assertion `if q, ok := store.(interface{ QueueSteerFrom(int64, string, string) (protocol.SteerView, error) }); ok`.
7. Event. `protocol/events.go`: add `KindLoopMessagePosted = "loop.message.posted"` next to `KindLoopStepDispatched` and the same constant into `Kinds()` after it. Fixture `conformance/events/loop-message-posted.json` (copy `loop-finished.json`'s envelope; payload):
   ```json
   {"loopId":"loop-9","messageId":41,"seq":7,"author":"human","kind":"note","source":"user","body":"ok, create the goal"}
   ```
   with a `description`: "A message was appended to a loop's thread: who wrote it, what kind, where it came from."
8. `daemon/messages.go`:
   ```go
   // publishMessage announces one appended thread message. loopID is the loop's id (not slug).
   func (d *Daemon) publishMessage(loopID string, m store.ChatMessage) {
       d.publishLoop(protocol.KindLoopMessagePosted, map[string]any{
           "loopId": loopID, "messageId": m.ID, "seq": m.Seq, "author": m.Author,
           "kind": m.Kind, "source": m.Source, "body": m.Body,
       })
   }
   ```
   (`publishLoop` adds `snapshot`/`row` and files the event under the loop's project root; see `func (d *Daemon) publishLoop` in `daemon/blueprint.go`.) Nothing calls it yet; T6 and T8 do.
9. `make protogen && make check-protogen`; commit the regenerated `contract.ts`.

- **Step 6's condition never fired, in a way the task's own DoD alternative covers.** The `missingRecord` nudge is **not a steer at all**: the engine rejects the step with `contractRejection(why)` (advance.go:328, continue.go:93) and the reason rides the ladder — there is no engine→`QueueSteer` call anywhere (grep: `store.NewSteer{` has exactly one non-test caller, `daemon/steers.go:47`, the socket door a person types through). The four-word vocabulary is in place for the day a nudge (or a blueprint-authored steer) is born; until then the only steer writer says `user`, which is the truth.
- **Seed facts measured the hard way, all three FK/constraint bites:** `loop.trigger_id` is NOT NULL with no default — the pre-0038 seed passes `""` (seedPin's shape; `nil` is refused); `step` HAS a foreign key to `loop (component_root, slug)` — the steer test seeds the loop first (T1 learned ghost steps are impossible; this is the same rule met fresh); `chat_message` FKs `(component_root, loop_slug)` → loop, so the CHECK-refusal test seeds the loop via `seedLoop` and leaves the CHECK as the only thing standing.
- **The migration's asymmetry is load-bearing and pinned**: `chat_message.source` NULL means NO source (agent/system/legacy rows read back NULL — `TestMessageSourceMigrationBackfillsHumanRowsAsUser` asserts `agent` and `system` stay `nil`, not `'user'`: inventing 'user' for them puts words in a person's mouth); `step_steer.source NOT NULL DEFAULT 'user'` states history — a pre-S39 steer could only be a person's.
- `publishMessage` has **no callers yet, as the task says** — T6 (a turn posting) and T8 (kickoff posting) wire it; the test drives the door directly so the wire shape is pinned before a caller can drift it. The negative half is tested too: a subscriber filtered on a DIFFERENT project root must not receive the loop's message (the `publishLoop` root-filing is the point of the test, not decoration).
- `SteerView` byte-identity is asserted as **key-set**, not string equality: the unlabelled view has every S38 key and no other, `source` rides only when `!="" && !="user"` — the CR10 promise a sha-pin could not make for a type the fixtures never serialise empty-vs-labelled both ways.
