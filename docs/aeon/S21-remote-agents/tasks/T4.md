# T4 — `egress.go`: `RouteAccess` before the request is built

## Why this exists

**This is the one genuinely new risk in the slice, and the test is about an *order*, not a behaviour.**

A skill request carries this product's own material — a file path and whatever the skill needs to read; its
transcripts, its plans, its source. **Locally that is bookkeeping. Remotely it is sending it to somebody
else.**

So egress is a policy (RA4). *"Never send code to a non-local route"* was already sayable about models
(S18's `RouteAccess`); **the same sentence has to be sayable about agents.**

### Why "before the request is built" and not "before it is sent"

**Both placements produce the same refusal message.** Only one is safe.

A request **assembled** and then discarded **has already read the files it was going to carry** — and in a
long-running daemon that assembly may be logged, cached, or held in a buffer that outlives the refusal.
The data has left the file and entered the process; the socket was never the boundary.

**So the check belongs where the decision is, and the test is a spy on the assembler** — because a check at
the socket passes every test that only looks at what crossed the network.

**Read first:** S18's `RouteAccess` — **this extends its subject, it does not add a type**; `dial.go` (T3);
the design's RA4 and the brief's R3.

## Scope

**1. Evaluate `RouteAccess` before assembly.** Order it so the assembler is unreachable on a denial.

**2. Extend `RouteAccess`'s subject to agent egress.** A route expression that can name a remote peer
(`remote:*`, `remote:docs-peer`) alongside model routes. **No new policy type** — a second one would be a
second authorship story.

**3. A denied egress reads no files.** Assert with a filesystem spy at zero, which is the concrete form of
§Why above.

**4. The refusal is S10's sentence**, plus the line that makes the guarantee legible: *"the request was not
assembled. no file was read."*

**5. Evaluated per invocation**, not per peer-configuration. A peer allowed yesterday may be denied today,
and the policy's `NotAfter` is how.

**What the task file could not know, decided here:**

- **The subject extension is a VALUE, not a constant.** The gate builds
  `policy.Request{Type: RouteAccess, Route: "remote:" + peerID}` — `TestNoNewPolicyTypeWasAdded` reads
  `../policy/types.go` and refuses any `PolicyType = "egress"|"agent_egress"|"remote_access"` declaration
  while asserting `AllPolicyTypes()` still holds exactly seven. The canonical spelling `EgressSubject`
  lives in remote (policy never imports remote); policy-side and remote-side tests pin the two ends to
  each other.
- **The pattern language is CommandAccess's shape narrowed to names**: exact, or one trailing `*`
  (`remote:*`, `*`). Mid-name and doubled stars are refusals to decide, never accidental grants;
  `remote:*` can never reach a model route because the prefix IS the namespace. Exact comparison alone
  was rejected: the validation list demands a wildcard, and per-peer rows at ten peers is a story nobody
  keeps current.
- **A policy set that cannot be read FAILS CLOSED** with the guarantee line still attached —
  *"the policy set could not be read … failing closed; the request was not assembled. no file was read."*
  A half-loaded permission table is exactly the moment the boundary must be strongest. (Task text did not
  name this case; PL12's spirit does.)
- **The three zeroes are the test.** RA4's claim is an order, so the spies are the proof: the assembler is
  an interface (spy counts `calls`), the files it would read are counted by an `os.ReadFile` loop
  (`fsReads`), and the socket is counted at the `rawDial` seam. A denial must show `0/0/0` — and every
  denial test carries a **control** (same fixtures, allow row → 1/1/1) so the zeroes cannot come from a
  broken spy, which is the failure mode S10's T5 records for pins that can't fail.
- **Per-invocation is per-INVOCATION, same gate object**: the clock is a seam, a row's `NotAfter` falls
  between two `Admit` calls on the SAME `EgressGate`, and the second is denied — nothing was rebuilt
  between them, so no cached verdict is surviving anywhere.
- `Admit` reads no files, touches no socket, builds nothing — it is the function the flow reaches *before*
  the code the flow might regret, and the sentence is `policy.Evaluate(...).Sentence()` **concatenated,
  never re-worded** (the one formatter; the test computes the expected verdict through the engine itself so
  a paraphrase here fails CI rather than passing review).

D5 (order-with-spy) is satisfied as written: the assembler is unreachable on a denial, observed.
