# T6 — `callback.go`: verified AND bound

## Why this exists

**The sharpest security task in the slice, and the trap is that verification feels sufficient.**

An async remote Task cannot be a held connection (RA7): **a held connection dies with the daemon, and P2
exists precisely so a suspended step survives that.** So the completion arrives as an **inbound call to
our own narrow surface.**

Which means there is now an endpoint that accepts *"here is the result of a skill"*.

> **Verification proves who sent it. Binding proves what they were asked.**

A callback that is **authenticated but unbound** lets anybody who can reach the endpoint — including a
legitimate peer, misbehaving or compromised — **inject a skill result into a transcript.** The loop then
treats it as the agent's work and acts on it.

**That is a fabricated answer, and S19's N6 already refuses the same shape for questions**: *"a fabricated
prompt, once answered, feeds a value into a transcript as though the model had asked for it."* The
reasoning transfers exactly.

**Read first:** S19's N6 and its action table; AS4 and `task.go` in S14; TR9's HMAC verification in S20 —
**the same mechanism**; the design's RA7, RA8.

## Scope

**1. The endpoint is a projection on S19's existing table.** **Assert no second listener**, by grep for
bind/listen.

**2. Verify the signature** — the same HMAC discipline as S20's webhook (TR9), with the secret from the
environment or a path.

**3. Bind, and this is the point.** The completion must name a Task **this daemon created**, still awaiting
completion, **whose callee is the peer that sent it.** Three conditions, and all three are refusals:

| Refused | Because |
| --- | --- |
| unknown task id | we never asked for this |
| task not awaiting completion | already complete, or never async |
| **callee ≠ sender** | **peer A answering peer B's task** |

**4. Replay is refused.** A completion delivered twice lands once.

**5. An async remote Task suspends with no held connection and no goroutine.** Assert both — this is AS4's
property, inherited, and the place a "just keep the connection" implementation would break it.

**6. The refusals are recorded.** An endpoint being probed is something somebody should be able to see.

**Decisions the task file could not know:**

- **Replay got TWO guards, and they say different things.** The byte-identical resend of a LANDED
  completion is refused by a bounded in-process cache of landed signatures (TR9's replayCache shape and
  its exact honesty argument — in-process catches the retry storm; the restart that loses it also hands
  the CAS the whole story). A DIFFERENT completion for a terminal task is refused by the store's own
  reading: "already complete, or never async". Collapsing the two into one sentence would blur two
  distinct facts (P31); both refuse, only the wording differs — and the CAS is what makes "lands once"
  survive a restart, which any cache alone could not claim.
- **The store's silence is `could_not_say`, never `refused`** (P31, third outcome added — the webhook's
  five-word vocabulary narrowed to the three this surface can honestly mean; closed set pinned by test).
  Rendering the store's inability to answer as a verdict would claim the decision the store refused to
  make; it is still recorded, because an endpoint whose store went quiet mid-decision is exactly what
  somebody should see.
- **Unknown peer and wrong signature are ONE sentence, byte-identical** (asserted): the pre-authentication
  answer proves nothing and must reveal nothing — no enumerating which peers this daemon configured.
  Peer keys are the shared secrets — the SAME `KeyRef` T1 made peers carry (env XOR path, use-time read,
  C17 intact); RA9's off-by-default reaches its last surface: unwired Callbacks resolves nothing,
  unwired daemon answers "no remote peers are wired in this daemon" — the wiring fault named as itself,
  never a silent "refused" blaming the peer for the daemon's shape.
- **The canonical form is LENGTH-PREFIXED** (`len\nvalue\n` per field, over peer·task·timestamp·result):
  a completion has no body, so its FIELDS are the message, and result is free text — an unprefixed join
  would let a result containing the delimiter forge a different claim over the same HMAC. The injectivity
  is tested with a deliberate field-shifting forgery. `SignCompletion` is exported so the fake peer
  (tests, T9's DEMO) signs through the SAME canonicaliser — a fake that signs its own way proves the
  fake, not the mechanism.
- **R-5's exemption is a FUNCTION with a name, and the keyless SET is now enumerated** (webhook +
  completion, both POST collections, both HMAC-first, both pinned by name in two tests): a peer knows its
  own pinned key and has never seen `AEON_HTTP_KEY`; a key-401'd completion proves the wrong thing. The
  exemption grows only by naming — that is what "a grep finds it" keeps true.
- **The landing IS `TaskStore.Complete`** — S14's waiting→completed CAS + cold `Resume`: the first record
  wins, and the suspended step re-drives from rows. RA7's "suspends with no held connection and no
  goroutine" is asserted three ways: 100 deliveries with `NumGoroutine` pinned before/after (settling
  window then exact equality), a reflection sweep that `Callbacks` has no field that could HOLD anything
  (no conn, no channel, no timer), and the store row being the only place a suspension can live.

  the red line; `Awaiting` reads `TaskWaiting && TaskAsync` (the P2-survivable state; sync tasks have no
  promotion path, so they are simply not awaiting), and `Land` maps the store's own `Reject.Field`:
