# T5 — Remote results are untrusted, always

## Why this exists

**AS12 and AP9, taken to their conclusion.**

AS12 labels a non-first-party skill result. AP9 made first-party **a registry field set by us, never read
from the package** — because a package that could claim it would skip the labelling.

**For a remote peer there is no claim to evaluate at all** (RA5). **First-party means reviewed in our pull
request.** Nothing on another machine qualifies, whatever it says about itself.

**So this is the simplest task in the slice**, and its value is that the simplicity is *asserted*: there is
**no code path** by which a remote result is unlabelled. Not a flag, not a trusted-peer list, not a
same-organisation exception.

**Read first:** AS12 in [`../../S14-agent-services/design.md`](../../S14-agent-services/design.md) —
**reuse its mechanism**; AP9 in S15; the design's RA5.

## Scope

**1. Every remote result is labelled**, through S14's existing mechanism. **Do not write a fifth
implementation** — W23, MC7, AS12, TR10 and this are one rule on five surfaces.

**2. No first-party path exists for a remote peer.** Assert by grep: no trusted-peer flag, no exception
list, no configuration that suppresses the label.

**3. A peer claiming first-party is ignored, visibly** — `aeon remote list --provenance` shows *"peer
claimed first-party — ignored"*, because a peer that tried is worth knowing about.

**4. The label names the peer**, so a transcript with results from two peers is readable.

**5. Anti-spoofing holds**, same as MC7: a result containing the literal label text must not close the
labelled region.

## Validation

- [ ] **unit test `a remote result is labelled untrusted` passes**, through S14's mechanism
- [ ] **unit test `no first-party path exists for a remote peer` passes**, by grep — no flag, list or exception
- [ ] unit test `a peer claiming first-party is ignored and reported` passes
- [ ] unit test `the label names the peer` passes
- [ ] unit test `the label survives a result containing the label text` passes
- [ ] unit test `the labelling mechanism is S14's` passes — no fifth implementation

## Notes

**Built 2026-10-28.** T5's code is ~60 lines added to `dial.go` (the task's file list — two methods on
`Outcome`, exactly the seams T3 left: "T5 labels its payload's trust … as methods over this one struct")
plus `untrusted_test.go` (5 tests); remote at **46/46**; full-suite official **2958 PASS / 0 FAIL rc 0** (`/tmp/s21t5-official-1.log`, attempt 1) — 2953 + exactly 5.

- **The mechanism is S14's, imported, never echoed.** `Labelled()` calls `label.Region(...)` —
  internal/label is the ONE grammar W23/MC7/AS12/TR10 share, and `TestLabellingMechanismIsS14s` holds the
  line from both ends: the boundary literals (`[untrusted-`, `[/untrusted-`) must NOT appear in dial.go,
  and `label.Region(` MUST. A fifth implementation is the failure the label package exists to prevent;
  the label header carries the peer's name (scope 4 — two peers in one transcript stay readable) and
  RA5's own sentence, so a reader sees not just *that* it is untrusted but *why nothing else could be*.
- **The absences render unlabelled on purpose.** Deadline and error sentences are AEON's own words about
  a peer that never spoke — wrapping them would hand the label back to the text that replaces the
  stranger (S15's AP7 refusal short-circuit, one layer up), and `Provenance()` says so:
  *"aeon · generated locally — the peer did not answer"*.
- **The claim scanner over-reports deliberately** (P31): any spelling of first-party in a payload —
  claim, denial, or mere discussion — earns *"peer claimed first-party — ignored, and the attempt is
  reported"*. Suppressing the note to dodge false positives is one judgement call away from suppressing
  it for the true positives; the note costs a transcript line, the miss costs an unexamined peer.
- **D6's grep bans identifiers, not prose**: `IsFirstParty(`/`SetFirstParty(`/`firstParty`/`TrustedPeer`/
  `trust-peers`/`skipLabel`/`bypassLabel`/`noLabel`, assembled so the hunter cannot contain the hunted,
  scanned across dial/egress/peer/trust. RA5's whole value is that the simplicity is *asserted* — the
  predicate is never even consulted on this path, which is stronger than consulting it and hard-coding
  false.
- **Anti-spoofing (scope 5) is the label package's crypto/rand token doing its job**: the test forges an
  opener and a closer inside the payload and asserts exactly one genuine closer, at the end, with a
  token the forger did not predict — and the stranger's spoof text still rides verbatim inside, because
  labelling is not filtering.

**Not built here, recorded:** the task's `aeon remote list --provenance` surface needs a daemon method +
CLI verb, and S21 has no CLI task — `Provenance()` is the socket-ready string; the mount is a
demonstrated gap for T9's walk to price (Findings, not code, this slice — P34's exception is narrow and
inventing a method table entry inside a test task would be worse).
