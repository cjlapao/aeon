# T9 — Walk the demo, write the QA suite

## Why this exists

**A slice is done when someone else can follow `DEMO.md` and watch it work** — and this demo has two steps
that are easy to appear-to-pass.

**§2 — the unpinned certificate.** It must be refused while being **genuinely valid**: a real certificate
from the test CA, for the right hostname, not expired. **If the certificate is invalid for any other
reason, the step proves TLS works and says nothing about pinning** — which is the one thing it exists to
test.

**§7 — the callback binding.** Three refusals, and they are different: unknown task, wrong callee, replay.
**A single "it was refused" observation covers none of them specifically.** Confirm each, and confirm the
wrong-callee case in particular, since that is the one a merely-authenticated implementation passes.

**Read first:** `DEMO.md` in full; `docs/test_suites/` for the house format; S11's note on asserting
**properties, not counts**.

## Scope

**1. Walk all nine sections** against the fake peer on a clean checkout. Add what is missing. **Do not
soften a step that failed** — that is a finding.

**2. Confirm §2's certificate was genuinely valid** apart from the pin, and record how.

**3. Confirm all three of §7's refusals separately**, and record which implementation detail each one
caught.

**4. Check §4 did what it says.** The line *"no file was read"* is a claim about an order. **Verify it** —
if the file was read and the request discarded, the demo is describing a guarantee the code does not make.

**5. Keep the "does not show" section** and verify after T1–T8 — particularly that **Aeon being a remote
agent is still out of scope**, since that is the inversion somebody will assume this slice delivered.

**6. Write `docs/test_suites/aeon-remote.md`.** Status `draft`, ids `QARA-01` upward.
