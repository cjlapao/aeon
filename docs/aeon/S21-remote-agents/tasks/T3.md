# T3 — `dial.go`: TLS only, deadlines, degradation

## Why this exists

**Three properties, and the first one is a refusal to be helpful.**

**No plaintext mode** (RA1). Not a flag, not a scheme, not an exception for localhost. **A plaintext option
is the one somebody uses in production** — and the local case already has a unix socket with filesystem
permissions and peer credentials (P26), which is strictly better than plaintext TCP to localhost.

**A hung peer degrades** (RA6). MC9's discipline, and it matters more here: **remotely the failure is
somebody else's outage**, arriving on a schedule nobody controls.

**And a deadline is not an empty result.** A timeout rendered as `[]` is a model concluding **the peer
found nothing** — and then reporting that absence as a finding.

**Read first:** `trust.go` (T2) — **this dials through it, and must not have a path that does not**; MC9
and N8/N10 in S12; the design's RA1, RA6.

## Scope

**1. TLS only.** Assert by grep: no `ws://`, no `http://`, no plaintext dialer, no localhost branch.

**2. Dial through T2's verification, with no second path.** **This is the ordering risk the plan names**:
if a dial works without verification during development, that path persists. Assert there is exactly one
dial function and it verifies.

**3. Answer Q3: the deadline, per-call and per-Task.** A per-call deadline is a connection timeout. **An
async Task cannot have one** once RA7 removes the held connection — so it needs a **Task-level expiry**,
evaluated when a completion arrives or when the Task is swept. State both numbers.

**4. Three outcomes, three renderings**: a result, a **deadline**, and an error. Distinct, as MC9 required
locally.

**5. No retry** (N5). A retry doubles the wait and **the model cannot tell one outage from two.** If a
retry is wanted it is the model's call, visibly.

**6. A dead peer degrades its skills, not the step.** The peer's skills are absent from what the agent can
ask for, **and the absence is reported** — a skill silently missing is a model wondering why it cannot do
what its prompt says it can.

## Notes

**Built 2026-10-28.** `dial.go` + `dial_test.go`; package at **33 tests / 33 PASS** (T1's 13 + T2's 9 +
T3's 11), wall **1.03 s** — the wall is the degraded calls themselves, which is the property. Full-suite
official recorded in STATUS.md's S21 row.

**Q3, both numbers as the scope demands:** per-call — **connect 5 s, call 30 s** (the call bound is MCP's
`DefaultCallTimeout` verbatim, the same shape of thing: a third-party round-trip, an order of magnitude
past healthy and short enough that a step's human sees progress; deliberately nowhere near bash's 600s
because the failure modes differ); per-Task — **1 hour**, and it is NOT a connection timeout: RA7 removed
the connection, so the async Task carries an expiry stamped at suspension, evaluated when a completion
arrives (T6 refuses expired ones) or when the Task is swept. Both caller-**shortenable, never
caller-lengthenable** (bash's rule; `boundCall` mirrors mcp's, and a test measures both directions: a 150 ms
caller gets its own Bound spoken, an hour-long caller gets the band's, never more).

**What the task file could not know, decided here:**

- **The one path is asserted by shape AND by the wire not moving.** Grep: exactly one `tls.Client(`, one
  `tls.Config{`, one `VerifyPeerCertificate:`, one `func dialVerified(`, zero `tls.Dial(`. Behaviour: a
  pin-less peer — impossible via Validate, constructible by struct literal — is refused **before the
  counting seam moves**: the raw-dial counter stays at zero. "No second path" is observed, not just shaped.
- **The plaintext grep bans assemble their own tokens** (`"http:" + "//"` and friends) so the hunting list
  cannot trip the scan, and the *loopback* ban is on the **string literal** `"localhost"` — prose may name
  the host (RA1's own sentence has to), code may not branch on it. Banned outright as literals: the
  cleartext schemes, `net/http`, the bare `net.Dial(` form, and `Listen` (this package dials, never serves).
- **A "hung peer" fake must never send close_notify.** The first iteration reused T2's `serveTLS` and the
  hung tests returned `result` — the helper's polite `Close()` had said *zero bytes, sincerely, the peer*,
  which is an answer, not an outage. The real hung fake blocks forever without closing; the lesson is
  recorded here because D8's entire argument is that these two are never the same value.
- **Three outcomes are one struct and one formatter.** `Outcome{Kind: result|deadline|error}` with
  `Render()` as the single sentence-maker (policy's `Verdict.Sentence` discipline): the deadline sentence
  says the peer *did not answer* and refuses to mean the peer *reported nothing*; the empty-result sentence
  owns the emptiness as the peer's answer. The two renderings must not borrow each other's words — asserted
  literally. `DegradeNote()` is scope 6's spoken absence (peer, reason, consequence); a live peer's note is
  the empty string.
- **No retry is counted, not promised:** `rawDial` is a seam the tests wrap; refused port → 1 attempt,
  hung peer → 1 attempt, two calls → 2 (per-call, never per-retry).
- **One connection per call is measured from the server side**: two calls, two accepted conns, two closed —
  RA7 on the wire, nothing here to hold. Tests mint their own certificates (127.0.0.1 SAN added to the
  leaf mint so loopback handshakes verify; ServerName still carries the identity story and the
  wrong-hostname test is untouched).

D7 (hung peer: step continues — caller holds a value, a second call proves the dialer never wedged), D8
(deadline ≠ empty ≠ error, three sentences that cannot be confused) sit on the DoD table satisfied at this
layer; the step-level half of D7 arrives with the invoke path above this file.
