# T7 — The chain through a remote peer

## Why this exists

A remote invocation is a chain edge like any other (AS6) — **and then there is a question the local case
never had to answer.**

> **Does a remote peer's internal fan-out count toward AS7's depth?**

**No, and the reason is observability rather than preference** (Q4). The chain records **what we invoked**.
If `docs-peer` internally asks four other agents, we cannot see it, cannot record it, and cannot bound it.

**So depth counts our hops** — and that must be *stated*, because the alternative is a bound that cannot be
enforced, which is worse than a smaller bound that can. A guarantee nobody can check is not a guarantee.

**The honest consequence:** a remote peer is a point past which our depth accounting stops. **Say so**,
rather than implying the bound is global.

**Read first:** AS6 and AS7 in [`../../S14-agent-services/design.md`](../../S14-agent-services/design.md);
`callback.go` (T6); the design's Q4.

## Scope

**1. A remote invocation records a chain edge**, with the peer identified as remote — so the chain
rendering can show where our visibility ends.

**2. Depth counts our hops.** Assert it, and **document the boundary**: the chain view marks a remote edge
as a point beyond which depth is not observable.

**3. A cycle is refused where it is observable.** If a remote peer calls back into *us* and that invocation
appears in our chain, AS7's cycle rule applies normally. **A cycle entirely inside the peer is not
observable and is not ours** — and the peer's own depth bound, if it has one, is its business.

**4. Answer Q4 and state it in the notes**, including what it means for the guarantee: AS7 bounds *our*
delegation, not the transitive closure.

**5. The chain survives a restart**, as AS6 requires — a remote edge is a row like any other.
