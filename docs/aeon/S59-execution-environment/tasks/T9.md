# T9 · The container backend, the provision ledger and reconcile

**Prefix:** EV · **Rules:** EV3, EV8, EV11, EV12, EV13, EV15 · **Depends on:** T2, T5. Parallel-safe with T7, T8.

## Goal

A real isolation backend behind the T5 seam. A bound `container` environment runs each command in a per-loop
container with only the working directory mounted, secrets never in argv, limits and `--network none` enforced,
output redacted by the same boundary — and the lifecycle is write-ahead, reconciled at startup, torn down at loop end.
An unavailable runtime **refuses** the command; it never runs it on the host.

## Files (new package `aeon/internal/execenv/container/`)

- `runtime.go` — `type Runtime interface { Available(ctx) error; ImageExists(ctx, ref) (bool, error); Pull(ctx, ref) error;
  Create(ctx, CreateSpec) (handle string, err error); Start(ctx, handle) error; Exec(ctx, handle, ExecSpec) (*exec.Cmd, error);
  Remove(ctx, handle) error; List(ctx, label string) ([]Handle, error); NetworkCreate/NetworkRemove(ctx, name) error }`.
  `Exec` returns a **prepared `*exec.Cmd`** so the shared `tools.runProcess` captures, redacts, caps, times out and
  group-kills it identically to a host command (EV13).
- `cli_runtime.go` — the `docker`-compatible driver: picks `docker` or `podman` (record field or discovery on `PATH`;
  recorded in the provision row); builds argv from `CreateSpec`: `run -d --name aeon-<slug>-<provisionId> --label
  aeon.managed=1 --label aeon.loop=<slug> --user <non-root uid:gid> --cap-drop ALL --security-opt no-new-privileges
  --pids-limit N --memory Nm --cpus C [--network none|<loop net>] -v <workDir>:/workspace:rw -w /workspace --env NAME …
  <image> sleep infinity`; **secret and `set` values are passed as `--env NAME` with the value in the `docker` CLI
  process's environment, never `NAME=value` in argv** (`ExecSpec` does the same for `docker exec`); no docker-socket
  mount, no privileged flag, no extra mounts (refused at validation).
- `executor.go` — `container.Executor` implementing `tools.CommandExecutor`: `Exec(ctx, req)` ensures provisioned
  (ledger, below), builds the prepared command, calls `tools.RunPrepared` (T5 exports the `runProcess` entry), with the
  environment's `Redactor`; `req.Dir` must equal the provision's mounted work dir (else refused — a loop whose root
  changed mid-flight gets a fresh provision).
- `provision.go` — `Ensure(ctx, st LoopRef, env BoundEnv) (Provision, error)`: **write-ahead** — `CreateProvision` row
  (`provisioning`) → `ImageExists`/`Pull` per `image.pull` → `Create`+`Start` → `MarkReady(handle)`; any failure ⇒
  `MarkFailed(last_error)` and a `provision-failed` refusal naming the driver's exact reason. Teardown
  `Teardown(ctx, id)`: `MarkTearingDown` → `Remove` → `MarkRemoved` (reverse order, settle-once).
- `reconcile.go` — `Reconcile(ctx)` at daemon start (beside `ReconcileLoops`, `daemon/reconcile_loops.go`): for every
  live row ask `Runtime.List(label aeon.managed=1)`: **adopt** a `ready` row whose handle exists; **finish** a
  `provisioning` row (`Start` or `Remove`, then settle); **remove** a labelled resource with no live row (orphan — only
  ever resources carrying `aeon.managed`); mark `failed` a `ready` row whose resource vanished. A runtime that is down at
  start ⇒ rows stay as they are and a warning is logged once (never a crash, never a guess).
- `aeon/internal/daemon/execenv_wire.go` — registers `container` with the T5 resolver; teardown hook on
  `loop.finished` (status `done`/`aborted`) in the `publishLoop` reactor point (`daemon/blueprint.go:567-612`) as
  `onEnvironmentTerminal`; a `blocked` loop's provision is removed after `provisionIdleTTL` by a ticker started with the
  daemon (cancelled with `recoveryCtx`); a retried blocked loop re-provisions (new row).

## Behaviour (each a test against the **fake runtime's recorded command log**)

1. One container per loop (second command reuses it); name and labels as above; mounts exactly `[workDir:/workspace:rw]`.
2. Hardening flags present on every `run`; none of `--privileged`, `-v /var/run/docker.sock`, `--net=host`.
3. `egress.mode=none` ⇒ `--network none`; `unrestricted` ⇒ default bridge; `allow` refused at validation (T3).
4. `limits.memoryMiB/cpus` ⇒ `--memory/--cpus`; `wallSeconds` shortens the exec timeout.
5. **No recorded argv contains a sentinel secret or `set` value.**
6. Output redacted, capped and group-killed by the shared boundary (T1/T5 goldens apply to a container command
   through the fake: same `RunResult` fields).
7. Runtime unavailable ⇒ `environment-unavailable` refusal, **zero host spawns**.
8. Image absent with `pull: never` ⇒ `provision-failed` naming the image; `missing` ⇒ one `Pull`.
9. Crash tests: kill the "daemon" after each ledger/runtime step (row written, container created, row marked ready)
   and reconcile — no orphan container, no live row without a resource, settle-once.
10. Teardown on `done`/`aborted`; `blocked` kept until the TTL then removed; retry re-provisions.

## Definition of done

- [ ] Container executor behind the seam; write-ahead ledger; labelled-only reconcile; teardown + TTL; secrets never in argv.
- [ ] Unavailable runtime refuses, never falls back; fake-runtime crash matrix green; real-runtime test run once on a lane that has one (or recorded "not run — reason").

## Do NOT

- Do not mount anything but the working directory; do not pass a secret or `set` value in argv; do not run a command on
  the host when the container cannot run; do not remove an unlabelled resource; do not add a capability, privileged
  flag, host network or docker-socket mount; do not duplicate the capture/redaction code.

Wired in three places: `newStepExecResolver` registers `container.Backend` whenever there is a store (a daemon that registered only while docker happened to be up would make "is this executable" a boot-order question; with no store there is no ledger, so the backend is simply absent and a container-bound step is refused — EV11's no-fallback registry); `publishLoop` calls `onEnvironmentTerminal` at the reactor point, so the loop package never learns the word `container`; `cmd/aeon/serve.go` runs the sweep before the step-recovery walk and starts the hourly ticker, deliberately NOT gated by `--no-recover` (that flag says "do not resume my loops", not "leave my containers running").

**Four production bugs the tests caught, none of them theoretical:**
1. `CLIRuntime.Exec` never set `cmd.Dir`, so `RunPrepared`'s directory guard refused every container command — the two `Dir` facts are genuinely different (the container's `/workspace` vs the client's host directory) and `ExecSpec` now carries both.
2. The prepared path was not putting the child in its own process group, so the timeout's `Kill(-pgid)` hit nothing and a 30-second `sleep` outlived a 1-second ceiling. `RunPrepared` now sets `Setpgid` itself: a driver that forgets it would lose the group kill silently, which is precisely the failure EV13 cannot afford.
3. `docker run … <image> sleep infinity` does NOT override the image's `ENTRYPOINT`: on `lscr.io/linuxserver/code-server` the image's `/init` consumed the arguments and the container was `"not running"` before the first exec. `runArgv` now passes `--entrypoint /bin/sh … -c "sleep infinity"` — the stay-alive is the driver's command, and the golden asserts the flag pair.
4. `ValidateMounts` refused any host path with the `/home` **prefix**, which is every real component root there is (measured: the honest lane's own working root was refused, so the loop could not run at all). It now refuses `/` outright, a socket/runtime/kernel path at any depth, and a home directory *as a home* (`/home` or `/home/<user>`), while allowing a project directory inside one.

**Deviations.** `RunPrepared` refuses a nil `cmd.Env` (the spec asked for the entry; this is what makes opening it safe) and sets `Setpgid` itself. The `--user`, the group and the engine binary are the DAEMON's knobs (`AEON_CONTAINER_USER`, `AEON_CONTAINER_GROUP`, `AEON_CONTAINER_BIN`), never the environment's — a spec that could name its own user could name root. `--pids-limit` always gets a floor (256) while memory/cpus are absent-when-undeclared, because 0 is never "no pids-limit". The start sweep is not gated by `--no-recover`. `ExecSpec` carries two directories (host `Dir`, container `WorkDir`). The stay-alive overrides the image entrypoint. The unlabelled-container count is reported so a reader can see what the sweep declined to touch.

**Not verified, named.** The daemon-side TTL sweep (`SweepIdleProvisions`) and `onEnvironmentTerminal` have unit-level coverage of their parts (`Teardown` settle-once, the `blocked` gate is a store read) but no end-to-end run where a real loop finished and its container came down, nor one where a blocked loop aged past `execenv.provisionIdleTTL` — the fake ledger and the fake runtime could not stage a real clock without the daemon's store; both belong to T12's walked demo. Reconcile at daemon start is covered as a function, not as `serve`'s boot. The cgroup memory ceiling is unverified on this lane (above). A vm driver remains out of scope (EV3, later slice).
