# T8 · The CLI: `aeon env` and `aeon secretref`

**Prefix:** EV · **Shape:** P5 (client half) · **Rules:** EV7, EV18 · standing rule 1 · **Depends on:** T6. Parallel-safe with T7, T9.

## Goal

The CLI gains the environment and secret-reference verbs it never had, as **pure clients** of T6's methods. It
re-validates nothing, prints what the wire said, and **cannot accept a secret value in any way**. Recorded deviation
from P5: **no offline "direct door"** — every operation needs the daemon's resolver, the seed engine and reconcile
state, and `aeon` has no first-run path that needs one (design EV18).

## Verbs (`aeon/cmd/aeon/env_verbs.go`, `secretref_verbs.go`; dispatched from `main.go`; usage text updated)

```text
aeon env list [--scope workspace|component] [--backend B] [--archived] [--json]
aeon env show <id|slug> [--json]
aeon env effective [--component ID|PATH] [--attended|--unattended] [--json]
aeon env vocabulary [--json]
aeon env changes [--subject ID] [--limit N] [--json]
aeon env provisions [--state S] [--limit N] [--json]
aeon env create --name N --backend B [--description D] (--spec-file PATH | spec flags) [--yes] [--json]
aeon env update <id|slug> (--spec-file PATH | spec flags) --expect-revision N [--json]
aeon env archive|restore <id|slug> [--json]
aeon env bind (--workspace | --component ID|PATH) <id|slug> [--dry-run] [--yes] [--json]
aeon env unbind --component ID|PATH [--yes] [--json]
aeon env teardown <provision-id> [--yes] [--json]
aeon secretref list [--archived] [--json]
aeon secretref show <id|name> [--json]
aeon secretref check <id|name> [--json]
aeon secretref create --name N --inject-as VAR (--from-env VAR | --from-file PATH) [--description D] [--json]
aeon secretref update <id|name> [--inject-as VAR] [--description D] [--json]
aeon secretref archive|restore <id|name> [--json]
```

Spec flags (`create`/`update`): `--passthrough A,B,LC_*`, `--set K=V` (repeatable), `--secret NAME` (repeatable),
`--home real|scratch`, `--wall-seconds N`, `--memory-mib N`, `--cpus N`, `--egress MODE`, `--image REF`, `--pull
never|missing`; or `--spec-file PATH` (the JSON of EV4 — it contains no secret by construction, and the daemon refuses
one that tries). `--help` for `create`/`update` is **generated from `environment.vocabulary`** (the live daemon's
backends, capabilities, default allowlist, deny list) so the closed sets are never typed twice.

## Rules

- Each verb names its socket method in a single exported table (`envVerbs`, `secretrefVerbs`); `list/show/...` print the
  result with one presentation helper (the daemon's `Describe` text comes back in the wire result — **one formatter**).
- `--yes` is a **seatbelt** (P5), required for `bind`, `unbind`, `teardown` and `create --backend host-inherit`
  (which prints the daemon's statement first). `bind` shows the dry-run **statement** and asks nothing else — a terminal
  command is already a deliberate act; the confirmation friction lives in the panel.
- **No flag, stdin or prompt accepts a secret value** (C17). `secretref create` takes a *location* (`--from-env`,
  `--from-file`); there is **no** `--value`, `--secret-value`, `--from-stdin` or interactive prompt. A grep test over the
  CLI source (the S19 T2 precedent) and a flag-set walk both enforce it.
- A refusal prints the daemon's three-part sentence verbatim (what/why/do) and exits non-zero; `--json` prints the
  wire result verbatim.
- No daemon ⇒ the standard "daemon not running" message from `dial`; **no** direct store access (the `internal/store`
  import guard for the CLI stays as is).

## Definition of done

- [ ] Every verb ⇔ method (both directions); no secret-value path exists; help generated from the vocabulary; `--yes`

## Do NOT

- Do not re-validate in the CLI. Do not add a flag, stdin path or prompt that takes a secret value. Do not open the

### Deviations and findings, each named

1. **No direct door** — the task already records this as the deviation from P5, and the implementation makes
   it structural: `selectEnvDoor` has one implementation (the socket), and the same guard asserts that
   `selectEnvDoor()` **refuses** when the seam is not stood in — a fallback would fail the guard that is
   supposed to catch forgetting one.
2. **`envParse` (found by a test, not by theory).** The task's own usage spells
   `aeon env update <id|slug> … --expect-revision N`, but Go's flag package **stops at the first positional**,
   so the flags after it were silently never parsed and the verb refused for the wrong reason. `envParse`
   re-parses with the positional moved last, so a person gets to type it either way. Nine verbs use it.
3. **`--help` is answered BEFORE `fs.Parse`.** The flag package's own `-h` prints its usage and returns
   `ErrHelp`, which is exactly the "closed sets typed twice" failure the task forbids — the first run of the
   test caught it (`create --help: flag: help requested`), and both verbs now check `wantsHelp` first.
4. **`--from-env`/`--from-file` are the only source kinds the CLI spells** (`daemon-env`, `key-file`). `store`
   has **no** flag: its door refuses with a sentence until the vault lands (D3), and a flag for it would
   promise a door that answers nothing. The AST walk carries that exception openly — `--secret` is legal on
   `env create` (a reference NAME) and illegal on `secretref create`, and the test says so rather than
   skipping the check.
5. **`env list` carries `--origin` and `--limit`** beyond the task's verb line, because the list door already
   FILTERS on both (T6's `EnvironmentListParams`) — hiding a filter the daemon answers would only push the
   person to `--json` and a pipe.
6. **One formatter, twice honoured.** `bind` prints the daemon's `execenv.DescribeBind` sentence verbatim and
   adds one line saying a dry run wrote nothing; `secretref check` prints the resolver's own sentence. No
   daemon sentence is re-worded anywhere in these two files.
7. **`--json` is asserted against the decoded wire**, not against a hand-typed expectation: the test compares
   `reflect.DeepEqual` of the printed document with the answer the door carried, and separately requires the
   fields the human printer drops (`revision`, `capabilities`, `createdAt`, `origin`) to be present — the
   failure mode it is aimed at is a CLI that reshapes.
