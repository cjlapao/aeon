# T11 · The Environments panel in Settings

**Prefix:** EV · **Shape:** P7 · **Rules:** EV1, EV6, EV15, EV18 · standing rules 3, 4 · P34 · **Depends on:** T6, **S45 T9** (shared UI components). Parallel-safe with T7–T10 once T6 is done.

## Goal

A person can see **what every loop's commands run in, what that environment can and cannot enforce, where it is
bound, what a command on a given component would see, and who changed it** — and can change the binding with the
daemon's own confirmation statement. A panel on the real Settings screen (not the bench), built from the daemon's
descriptors, never typing a vocabulary, never showing or accepting a secret value. (The component-tree UI itself is a
separate piece of work; this panel reads `component.list`/`component.show` for its picker.)

## Files (`aeon/ui/src/features/settings/environments/`; read the neighbouring Settings sections S45 T9 built and follow their composition, hooks and i18n)

- `EnvironmentsSection.tsx` — registered as a Settings section; `Tabs`: **Environments**, **Secret references**,
  **Provisions**, **Effective**.
- **Environments tab** — list from `environment.list` with daemon-side filters (scope, backend, archived). Each row:
  name, backend, **capability chips** from `environment.vocabulary` (✓ env allowlist · ✓ redaction · ✗/✓ filesystem
  isolation · ✗/✓ egress enforced · ✗/✓ memory/CPU limits), where it is bound (workspace / component names), `origin`
  (system/user), a **legacy** badge, last change ("`<actor>` `<RelativeTime>`") from `environment.changes`. Detail pane:
  the spec (variable **names**, secret reference **names**, limits, egress, image, services), revisions with a diff
  (the audit rows carry `spec_after`), and the **honesty line** (`execenv.Honesty`, verbatim from the vocabulary).
  A **warning banner** while the workspace default is the legacy row: "commands on attended loops still inherit the
  daemon's environment — provider keys and the forge token are visible to them. Unattended loops are already scrubbed."
  (text from the daemon's `bind` statement machinery, not typed in the UI).
- **Editor** (`EnvironmentForm.tsx`) — generated from `environment.vocabulary`: backend select (only backends with a
  registered driver; `vm` shown disabled with the daemon's sentence), `passthrough` as chips with the **default
  allowlist** one click away, the deny list shown as the daemon's sentence on refusal, `set` pairs (credential-shaped
  names refused by the daemon, shown verbatim), secret-reference picker (names), limits (disabled with the reason where
  the backend cannot enforce them), egress mode by capability, image, services. **Refusals are shown verbatim and the
  draft is kept**; `expectedRevision` carried so a stale edit is refused, not overwritten.
- **Bind** (`BindDialog.tsx`) — `environment.bind {dryRun:true}` → shows the **daemon's statement** → `useConfirm`;
  declining sends nothing; on confirm `bind` is called and the row updates **from the response** (never optimistic).
- **Secret references tab** — list from `secretref.list`: name, `injectAs`, source kind, **source** (a human sees it; it
  is a location, never a value), where used, last change; a **Check** button calls `secretref.check` and shows
  resolvable / too short / not set — never a value or its length. Create form takes a **location** only (env var name or
  file path); there is **no value field** anywhere in the section (a source grep test).
- **Effective tab** — a component picker (S44-extra `component.list`) and an attended/unattended toggle →
  `environment.effective`: the resolved environment, **why** (binding source: component / root / workspace), a
  **downgrade note** when an unattended loop would not inherit, and a table of **variable names with their source**
  (`passthrough`, `set`, `secret:<name>`) — never a value.
- **Provisions tab** — `environment.provisions`: state, loop, backend, handle, ages, `last_error`; **Tear down** (human
  door, `useConfirm`) for stuck rows.
- `ui/src/lib/i18n/en.json`, `pt.json` — `settings.environments.*` (en/pt parity test).
- `ui/test/environmentsRpc.guard.test.ts` — extracts every literal passed to the rpc helpers in this section and asserts
  each is a registered method in the generated `contract.ts`; found ≥ 1 per tab (never vacuous); a canary flags a bogus
  method. A source grep test forbids hardcoded vocabulary literals (backend names, deny words, egress modes).

## Rules

- No new dependency, no `localStorage` for domain data, no `fetch` — everything through the rpc helpers.
- Offline ⇒ writes disabled, reads show last data (the neighbouring sections' idiom).
- Existing Settings sections, the bench pages and the existing panels are untouched.
- The panel says, in the Environments tab, that **parallel units share one working tree until S32's follow-up lands**
  (EV15) *only if* T0 proved the finding and it is still unfixed (the daemon exposes a boolean in the vocabulary
  `knownLimits` list so the UI does not hardcode a status).

## Definition of done

- [ ] Four tabs working against the real methods; verbatim refusals; confirmation with the daemon's statement;
  no value field and no value rendered anywhere; guards with canaries; en/pt parity; lint and deps green.
- [ ] Demo walk against a real daemon recorded in T12.

## Do NOT

- Do not type a vocabulary, sentence or authority text in the UI. Do not add a value input for a secret. Do not render
  a source to a non-human surface. Do not edit other Settings sections or bench pages. Do not add a dependency or
  persist domain data locally.

**The pre-flight gap this task needed first (it is the reason the commit is half Go).** The spec requires the EV15 shared-working-tree warning to come from "a boolean in the vocabulary `knownLimits` list so the UI does not hardcode a status" — **that field did not exist**, and T0's proof says the limitation is live (every unit's worktree is created and ledgered while `runOneUnit` hands the model step the shared component root, F8/F9). So the daemon grew it: `execenv.KnownLimit{Key,Sentence,Active}` + `KnownLimits()` + `SharedWorktreeSentence`/`SharedWorktreeLimit` in `internal/execenv/vocab.go` (338), `protocol.KnownLimitView` and `knownLimits` on `EnvironmentVocabularyView` in `internal/protocol/environment.go` (772), the mapper `knownLimitViews` in `internal/daemon/environment.go` (834), and `vocabulary-definitions.json`'s result extended so the generated `contract.ts` carries the field (+5 lines, and only those). `TestVocabularyServesHonestyAndLimits` now asserts the sentence is the core's verbatim, the count is the code's, and the status is the daemon's — a client that kept saying it after the fix would fail that test, not merely look stale.
