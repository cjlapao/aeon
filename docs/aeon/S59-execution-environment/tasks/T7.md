# T7 · Agent tools and the `environment_restrict` proposal kind

**Prefix:** EV · **Shape:** P6 · **Rules:** EV16, EV7 (agents never see a source) · standing rule 2 · S38 one-definition-two-doors · **Depends on:** T6, **S45** (`internal/desk`, the generic `proposal.commit`). Parallel-safe with T8, T9.

## Goal

Agents can **see** the environment their commands run in and **propose that it be tightened** — nothing more. Five
catalog specs (four reads, one propose), each with a socket twin; a new closed proposal kind committed only by a
person through S45's generic commit, whose validator is `execenv.Restricts`. An agent can never create, update,
bind, unbind, tear down or reference a secret value, and can never widen anything.

## The five specs (`internal/records/catalog.go`, data only, family `environment`)

| Tool | Socket twin | Class | Mutates | What it does |
| --- | --- | --- | --- | --- |
| `environment_list` | `environment.list` | safe | no | Environments with backend, capabilities, where bound, origin, legacy flag, last change |
| `environment_show` | `environment.show` | safe | no | One environment in full: spec (names only), capabilities, bindings, revisions |
| `environment_effective` | `environment.effective` | safe | no | What a command on a component would run in: backend, variable **names with sources**, secret reference **names**, whether an unattended loop would be downgraded |
| `secretref_list` | `secretref.list` | safe | no | Secret references: `name`, `injectAs`, `sourceKind`, description — **no source, never a value** |
| `environment_propose_restrict` | `environment.proposeRestrict` | detectable | **yes** | Create an **inert** proposal to tighten an environment's spec; nothing changes until a person commits |

`registerRecords` skips a twin whose dot-name already stands (`records.go` header): the four read twins are the T6
methods; only `environment.proposeRestrict` is new, implemented by the **records service**, not the authoring service
(it creates a proposal, never an environment).

## Schemas — what is deliberately absent

`additionalProperties:false` on every schema. `environment_propose_restrict` input:
`{environmentId, spec, reason}` — **no** `backend` field (a backend change is never an agent proposal: strength only
goes up by a person), no `source`/`actor`/`createdBy`/`status`/`kind`, no value field. `reason` required (1–512 bytes).
`secretref_list` takes `{includeArchived?}` only. Reads for an agent are **own-view where the domain has a rule**:
environments are workspace-wide records, so lists are open, but `environment_effective` for an agent defaults to the
agent's own loop's component and refuses another component's tree it has no loop in (T0 confirms the scoping rule used
by `goal_list`/`loop_list` and mirrors it).

### Deviations from the task file, and why

1. **The payload carries `baseRevision`; the TOOL SCHEMA does not.** The spec's propose input is
   `{environmentId, spec, reason}` and it stayed exactly that — `baseRevision` is stamped by the records
   arm from the row it READS, so a model cannot type a baseline, and the store's compare-and-set has
   something honest to refuse. The catalog guard asserts the tool's three members exactly.
2. **`store.UpdateEnvironment` gained an optional `Note`** (≤ 1 KiB, `note-too-large` refused) so the
   committed tightening can carry `"tightened by committed proposal #N · <reason>"` in its audit line.
   The human door's rows are byte-identical — the note is empty unless a committer passes one.
3. **`execenv.DescribeTightening` stands where the spec said "Describe".** `desk.Effect` has no Describe
   hook (only Validate / AlreadyApplied / Apply), so the statement is a function beside `Restricts`
   rather than a registry member; it re-runs `Restricts(new, old)` and is the one formatter of the
   before/after sentence, so the CLI, the panel and the audit cannot render it three ways.
4. **T7 amends T6's own guard file** (`cmd/aeon/environment_guard_test.go`) — the S56/S48 pattern: the
   three predicates `environmentAgentSurfaceTool`, `environmentAgentSurfaceSpec` and
   `environmentLiteralExempt` are DEFINED in T7's file (the exemption is T7's claim to own), each half
   of a pair must match so `environment_list` → `environment.create` still fires, and the literal walk's
   exemption is ONE file (`internal/records/catalog.go`) and TWO wire prefixes — the
   `MethodEnvironment*`/`MethodSecretRef*` constants are exempt nowhere. `TestEnvironmentProposeGuardHasTeeth`
   fires every one of them at a poisoned fixture.
5. **The change also closes two reds that were main's, not this slice's**: the plane's 21 surface rows
   were never classified (`TestSurfaceEveryRegisteredMethodIsClassified` was red for the environment
   family before T7 — `RegisterEnvironment()` runs in `New()` with no surface entries), and five
   environment store methods (`SeedEnvironmentTx · EnvironmentRowTx · SeedWorkspaceBindingTx ·
   ListProvisions · EnvironmentsReferencingSecretRef`) were exported without being named in
   `store.go`'s surface table (`TestEveryExportedMethodIsNamedInTheSurfaceTable`). Both are named now,
   with their consumers.
6. **`internal/daemon/daemon.go` grew 15 lines** (a standing violation, 1,392 → 1,407): the two seam
   assignments and the conditional registration belong beside `table.RegisterSecretRef()` where the
   plane is wired, and splitting `New()` is not this task's split.
