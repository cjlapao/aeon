## Goal

Six tables, their triggers and indexes, and every SQL statement the slice needs — in `internal/store` only (I2: SQL
lives nowhere else; `TestNoSQLLivesOutsideTheStore`). The migration is conditional so an upgraded store keeps today's
behaviour and a fresh store gets the seed (EV19/EV20).

## The tables (read the current DDL of anything referenced first)

```sql
CREATE TABLE environment (
  id TEXT PRIMARY KEY, slug TEXT NOT NULL UNIQUE, name TEXT NOT NULL, description TEXT NOT NULL DEFAULT '',
  backend TEXT NOT NULL CHECK (backend IN ('host-inherit','host-scrubbed','container','vm')),
  spec TEXT NOT NULL CHECK (json_valid(spec)),
  origin TEXT NOT NULL DEFAULT 'user' CHECK (origin IN ('system','user')),
  legacy INTEGER NOT NULL DEFAULT 0 CHECK (legacy IN (0,1)),
  revision INTEGER NOT NULL DEFAULT 1, created_at TEXT NOT NULL, updated_at TEXT NOT NULL, archived_at TEXT);

CREATE TABLE environment_binding (
  scope_kind TEXT NOT NULL CHECK (scope_kind IN ('workspace','component')),
  component_id TEXT REFERENCES component (id),
  environment_id TEXT NOT NULL REFERENCES environment (id),
  bound_at TEXT NOT NULL,
  CHECK ((scope_kind = 'workspace' AND component_id IS NULL) OR (scope_kind = 'component' AND component_id IS NOT NULL)));
CREATE UNIQUE INDEX environment_binding_workspace ON environment_binding (scope_kind) WHERE scope_kind = 'workspace';
CREATE UNIQUE INDEX environment_binding_component ON environment_binding (component_id) WHERE component_id IS NOT NULL;

CREATE TABLE secret_ref (   -- NO value column, ever (EV7)
  id TEXT PRIMARY KEY, name TEXT NOT NULL UNIQUE, description TEXT NOT NULL DEFAULT '',
  source_kind TEXT NOT NULL CHECK (source_kind IN ('daemon-env','key-file','store')),
  source TEXT NOT NULL, inject_as TEXT NOT NULL, origin TEXT NOT NULL DEFAULT 'user',
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL, archived_at TEXT);

CREATE TABLE step_environment (   -- names only; append-only; one row per DISTINCT outcome per step (EV9)
  id INTEGER PRIMARY KEY AUTOINCREMENT, step_id INTEGER NOT NULL, environment_id TEXT, backend TEXT,
  downgraded INTEGER NOT NULL DEFAULT 0, downgrade_reason TEXT, refusal_kind TEXT, refusal TEXT,
  var_names TEXT NOT NULL DEFAULT '[]', secret_refs TEXT NOT NULL DEFAULT '[]', resolved_at TEXT NOT NULL);
CREATE INDEX step_environment_step ON step_environment (step_id);

CREATE TABLE environment_provision ( ... EV12's columns ...,
  owner TEXT NOT NULL DEFAULT 'loop',   -- 'loop' | 'service:<name>' (T10)
  state TEXT NOT NULL CHECK (state IN ('provisioning','ready','tearing_down','removed','failed')) );
CREATE UNIQUE INDEX environment_provision_live ON environment_provision (component_root, loop_slug, owner)
  WHERE removed_at IS NULL;      -- settle-once and one live resource per owner

CREATE TABLE environment_change ( ... EV17's columns ... );   -- append-only
CREATE TRIGGER environment_change_no_update BEFORE UPDATE ON environment_change BEGIN SELECT RAISE(ABORT,'environment_change is append-only'); END;
CREATE TRIGGER environment_change_no_delete BEFORE DELETE ON environment_change BEGIN SELECT RAISE(ABORT,'environment_change is append-only'); END;
-- the same pair for step_environment
```

`step_environment.step_id` and `environment_provision.loop_slug` carry **no FK** (history outlives the record, P3;
the `loop_worktree` ledger does carry one — T0 decides per table with the cascade facts in hand).

**Conditional legacy rows** (EV20), in the same file:

```sql
INSERT INTO environment (id, slug, name, description, backend, spec, origin, legacy, revision, created_at, updated_at)
SELECT 'env-host-inherit', 'host-inherit', 'Host (inherited environment)', '…legacy…', 'host-inherit',
       '{"env":{"passthrough":[],"set":{},"secrets":[]},"home":"real","limits":{},"egress":{"mode":"unenforced"},"services":[],"preview":null}',
       'system', 1, 1, strftime('%Y-%m-%dT%H:%M:%fZ','now'), strftime('%Y-%m-%dT%H:%M:%fZ','now')
WHERE EXISTS (SELECT 1 FROM component) OR EXISTS (SELECT 1 FROM loop);
INSERT INTO environment_binding (scope_kind, component_id, environment_id, bound_at)
SELECT 'workspace', NULL, 'env-host-inherit', strftime('%Y-%m-%dT%H:%M:%fZ','now')
WHERE EXISTS (SELECT 1 FROM environment WHERE id = 'env-host-inherit');
```

(Use the clock format the other migrations use — T0 records it. The legacy spec lists no variables because the
legacy backend ignores `passthrough`: it inherits everything.)

## Store API (all discriminated results — `…Refusal` values, DB19; `error` only for infrastructure)

- `CreateEnvironment`, `UpdateEnvironment{ID, Spec, ExpectedRevision}` (optimistic: a stale revision is a refusal
  naming the current one), `ArchiveEnvironment`, `RestoreEnvironment`, `GetEnvironment(idOrSlug)`,
  `ListEnvironments(filter)`; `BindEnvironment`, `UnbindEnvironment` (the workspace binding cannot be removed — refused),
  `BindingFor(componentID)` returning `(Binding, source "component"|"root"|"workspace", err)` using S44-extra's
  `RootOf`; `ListBindings()`.
- `CreateSecretRef`, `UpdateSecretRef` (name immutable), `Archive/Restore`, `GetSecretRef`, `ListSecretRefs`.
  Refusals: duplicate name, unarchived reference still named by a non-archived environment (cannot archive a
  referenced ref — sentence lists the environments).
- `RecordStepEnvironment` (dedupes by distinct outcome), `StepEnvironments(stepID)`.
- `CreateProvision` (state `provisioning`), `MarkProvisionReady/TearingDown/Removed/Failed` (each guarded so a repeat
  is a no-op — settle-once), `ListLiveProvisions`, `ProvisionsFor(loop)`.
- Every *changing* write appends an `environment_change` row **in the same transaction** with the actor passed in
  (`store.Actor{Kind, ID}` from `table.ActorFor` at the door — never from params); `ListChanges(filter)`.
- A reference check used by `bind`: `EnvironmentSecretRefs(id)` (names in the spec) so a bind can verify each exists
  and is unarchived.

### Deviations, and the fact that forced each one

1. **`environment_change.go` split out of `environments.go`.** Completing the reads pushed the single file past
   1000; the split is by cohesion — opening `environments.go` answers "what does the record say", opening
   `environment_change.go` answers "who changed it, when, and how do I know". Both files are recorded at their
   measured sizes above, and the task's file list gains one entry.
2. **`txExec` did not exist.** The truncated draft called a helper that was never defined; the two bind call
   sites now use `tx.Exec` directly. Nothing else in the package uses that shape.
3. **The provision ledger takes no `Actor` and writes no audit row.** `environment_change`'s `subject_kind`
   CHECK admits exactly `environment`, `secret_ref` and `binding`; a container is not a decision, and inventing
   a fourth subject kind to make a rule look uniform would audit noise. The ledger's honesty lives in `state`,
   `handle` and `last_error`, and `MarkProvisionFailed` refuses to write without the sentence. The reasoning is
   in the file header, where the next reader will look for it.
4. **`TestNoCredentialShapedColumnExists` has an allow-list of exactly one entry**,
   `step_environment.secret_refs`, which EV9 defines as the JSON array of reference NAMES. It is the only column
   in the six tables whose name contains a credential word while not being a value column. The claim that it
   holds names and nothing else moved to
   `TestRecordStepEnvironmentDedupesDistinctOutcomes`, which reads the stored text and fails on a `=` or a
   `postgres://`. Any NEW credential-shaped column still fails the walk.
5. **The legacy-row test re-applies the migration's OWN INSERT text** (sliced out of `Migrations()`' entry
   rather than retyped), because a test that re-types the INSERTs proves nothing about the file. The
   loop-without-component branch is genuinely reachable and tested: `loop` is keyed by `(component_root, slug)`
   and carries **no** `component_id`, so `EXISTS (loop)` is not belt-and-braces for an unreachable case.
6. **`CreateSecretRef(a, in, reserved []string)`** takes the daemon-credential name list from its caller. The
   store does not import `config`, `daemon` or `forge` (its allow-list is model, database, paths, mergerule) —
   what counts as one of the daemon's credentials is those packages' knowledge; the store's job is to refuse the
   row. `UpdateSecretRef` passes `nil`, so an edit cannot smuggle a reserved name in through a changed `source`
   without the caller that owns the list being present.
7. **The `store` source kind is admitted (A1 GRANTED at T0)**, with a path-shaped or dot-leading source
   refused (`store-source-shape`): the value lives in `internal/secrets`' 0600 credential file, whose paths
   belong to that package and not to a row.
8. **`sortedKeys` is the store's existing helper** (from `backup_run.go`); no second sort helper was added.

   (T5's `BindingFor`/`RecordStepEnvironment`, T6's writes, T8's CLI, T9's ledger, T11's panel) must actually
   arrive or this block is a list of promises.

    `internal/execenv/` do.
