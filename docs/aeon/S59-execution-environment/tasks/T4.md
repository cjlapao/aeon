# T4 · Secret references and redaction

**Prefix:** EV · **Rules:** EV7, EV8 · standing rule "never a secret value anywhere" · **Depends on:** T3 (types), T2 (the reference rows). Merges with T2–T5.

## Goal

A secret reference can be **checked and resolved at spawn time** without its value ever being stored, returned,
logged or audited, and everything a command prints is **redacted** of the injected values on its way out. This task
is the slice's security core; its acceptance is a scan of every sink.

## Files

- `aeon/internal/execenv/secret.go` — `type Secret struct{ name string; b []byte }` with `String`, `GoString`,
  `Format(fmt.State, rune)`, `MarshalJSON`, `MarshalText`, `LogValue() slog.Value` all answering `<redacted>`
  (F17's pattern, widened to every formatting verb); no exported accessor — bytes leave only through
  `Injection{Name, injectAs string; value Secret}` consumed by `Build` and by `NewRedactor`.
- `aeon/internal/execenv/resolve_secret.go` — `ResolveRef(ref RefSpec, getenv func(string) string, open FileOpener)
  (Secret, *Refusal)`:
  - `daemon-env`: `getenv(source)`; empty ⇒ `secret-unresolvable` "variable X is not set in the daemon's environment";
  - `key-file`: path must be absolute, a **regular file** (via `open`'s `Stat`, `Lstat` semantics: a symlink is
    refused), mode no wider than `0600`, owned by the daemon user, ≤ 64 KiB; value is the file trimmed of one
    trailing newline;
  - `store`: **refused "not built"** until T0's approval A1 is granted and read (D3);
  - any value shorter than **8 bytes** ⇒ refused "too short to redact reliably";
  - refusal sentences name the reference and the source, **never** the value or its length.
  - `ResolveAll(refs, …) ([]Injection, []Refusal)` resolves every reference of an environment; the caller decides
    (EV11) — a single unresolvable one refuses the command.
- `aeon/internal/execenv/redact.go` — `NewRedactor(secrets []NamedSecret) *Redactor`; `(*Redactor).Writer(dst
  io.Writer) io.WriteCloser`: a **streaming** filter with an overlap carry of `maxLen-1` bytes (a match split across
  `Write` calls, or straddling the output cap, is still found), replacing with `[secret:<name>]`. Matches: exact bytes,
  base64 std/URL × padded/unpadded, lowercase hex, percent-encoding (computed once per secret, longest-first so a
  prefix of a longer form cannot leave a tail). `RedactString(string) string` for the echoed command and command-activity
  text. `Close` flushes the carry. Counting: `Redactions() []NameCount` (counts per secret **name**, never values — for
  the step record).
- `aeon/internal/forge/` — **listed adaptation (approval A2):** an exported `TokenEnvNames() []string` assembled from
  the same constants `DefaultTokenSource` uses; `DefaultTokenSource` calls it (characterized: behaviour identical).
- `aeon/internal/execenv/daemoncreds.go` — `IsDaemonCredentialEnv(name string, provider []string, forge []string)
  bool`: `AEON_` prefix, the provider and forge names **passed in** (the daemon supplies them from `daemon.Env…` and
  `forge.TokenEnvNames()`; the core never imports them), `narrow.KeyEnv`'s name, the card-key env name. `ValidateRef`
  refuses a reference whose `source` is one of these (EV7).
- `aeon/internal/tools/spawn.go` — **not here** (T5 wires `Redactor` into the capture); this task exports the
  `Redactor` and proves it standalone.

## Commands

P10, `./internal/execenv/ ./internal/forge/ -count=1 -race -v`.

## Definition of done

- [x] `Secret` cannot print; resolution refuses unsafe sources and short values; redaction is streaming, boundary-safe
  and honest about its limits; the daemon's own credentials cannot be referenced; the sink scan is clean.

## Do NOT

- Do not give `Secret` an accessor that returns bytes or a string. Do not log, wrap into an error, or audit a value
  or its length. Do not accept a value over any door (params, flag, stdin, prompt). Do not build the `store` kind
  before A1. Do not re-type the daemon's credential names.

### The bug the tests caught, recorded because it is the kind this file invites

`candidateForms` began its list with the exact bytes and then filtered every form with `bytes.Equal(f, value)`
— **which dropped the exact form itself, by comparing it with itself**. Nothing was redacted at all: the first
run failed on the exact, percent, cap-boundary, longest-first, count and concurrency cases at once. The fix is
one line (the exact bytes always ship; only the *encodings* equal to them are dropped), and the reason the
record carries it is that a matcher whose candidate list is built by a filter is exactly the shape that fails
open while every encoded form still looks fine in a spot check.

### Deviations, and the fact that forced each one

1. **The `store` kind is built (A1 GRANTED at T0), so `TestStoreKindRefusedUntilApproved` became two cases**:
   an unwired daemon refuses with the new kind `store-not-wired`, naming the missing wiring; a wired one resolves
   through `ResolveEnv.Store func(credentialID string) (string, bool)`. The daemon hands over a lookup, never a
   path — `internal/secrets` owns where its 0600 credential file lives, and a row that carried a path would put
   that package's layout in a database record.
2. **`FileOpener` is `{Lstat, Open}`, not `{Stat, Open}`** — `Open` also reports the facts of the descriptor it
   *actually read*, and `keyFileProblem` runs against both sets. A stat-then-read pair is a swap window: the
   checks describe one inode and the bytes come from another. `OSFiles.Open` therefore uses `O_NOFOLLOW` +
   `fstat` and caps the read at `MaxKeyFileBytes+1`. The non-POSIX implementation reports `UID: -1`, and
   `ownerIsDaemon` treats an unknown owner as a **refusal**: a platform that cannot prove the file is the
   daemon's does not read it.
3. **`ResolveRef` takes one `ResolveEnv` struct** instead of `(getenv, open)`, because resolution needs five
   inputs to be checkable: the reader, the filesystem, the daemon's uid, the credential-name list, and the
   store lookup. Two of the five (`Lookup`, `Files`) are nil-able and each nil has its own refusal, so a
   half-wired daemon says which half is missing.
4. **`NewRedactor([]Injection)`, not `[]NamedSecret`.** The task names the parameter type `NamedSecret`; it is
   `Injection`'s exact shape, and a second type with the same three fields is a drift waiting to happen — worse,
   a `NamedSecret` constructible from a plain string would be a door for a value, which `Secret` exists to
   close. The rule the task cared about (bytes leave only through `Build` and `NewRedactor`) holds: both are in
   this package, and no accessor returns bytes.
5. **Counting is per `Redactor`, mutex-guarded, and shared by its writers.** Two writers from one redactor is
   the real shape (transcript and activity row from different goroutines of one step); a tally that loses a
   concurrent increment under-reports how much redaction a step needed, and that number is what a person reads
   when deciding whether an environment is safe.
6. **The resolution kinds are shared with the store's write-time door**, and
   `TestStoreAndExecenvShareOneRefusalVocabulary` locks the seven strings both doors emit — a UI or CLI that
   branches on a kind stops branching silently the day one side renames it.
7. **`RedactionLimits` (vocab.go) was widened to name URL-safe and unpadded base64**, which the matcher does
   compute and the old sentence did not claim, and to say `across chunk boundaries` and `split by a character`.
   `TestRedactLimitsAreTrue` asserts the sentence and nothing wider — it asserts the reversed, XORed,
   space-split and ROT13 forms are **not** redacted, so the honesty line cannot drift ahead of the code.
8. **The sink-scan test lives in `package store_test`**, not `package store`: `envtest` imports `store` for
   `*store.Store`, so an in-package test would be an import cycle. It reaches the store through its exported
   doors, which is the same door the daemon uses.
9. **`forge.TokenEnvNames()` (A2)** is exported so the EV7 gate reads the *same* list `DefaultTokenSource`
   reads; the split literals are kept (they are what the file's own scanner exemption is about), and the test
   pins accessor ≡ source rather than naming the three variables a second time.

### Not verified, and what would verify it

- **The `Redactor` has never filtered a real command's output.** T5 wires `Writer` into the capture; until then
  "the transcript is redacted" is a claim about a filter tested standalone — which is exactly what this task
  contracted, and nothing more.
- **No daemon has ever assembled the credential list.** `ValidateRef`'s `Credentials` is tested with lists the
  test wrote; the real assembly (`daemon.EnvAnthropicKey`, `daemon.EnvOpenAIKey`, `forge.TokenEnvNames()`,
  `narrow.KeyEnv`, the card-signing and cursor-signing names) is T6, and a name missed there is a
  referenceable credential that no test here can see. `execenv_test`'s `TestCredentialWordsSupersetOfConfigMarks`
  covers `config`'s marker list only.
- **The owner rule against a file owned by another real uid is untested** — it needs a second account and a
  `chown`; the swap and owner rules are tested with the facts a real `fstat` produces, not with two users.
- **`Percent`/hex/base64 coverage beyond the sentinels used** is not enumerated; the encodings are computed
  from the value, so the risk is a form the command prints that is not in the set (documented in
  `RedactionLimits`, asserted against widening by `TestRedactLimitsAreTrue`).
