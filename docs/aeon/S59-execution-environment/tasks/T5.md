# T5 · The execution seam: `Spawn` demands a `ChildEnv`, executors, resolution per step, the unattended rule, the other spawn sites

**Prefix:** EV · **Shape:** P2 (Phase B) · **Rules:** EV5, EV6, EV9, EV10, EV11, EV15 · **Depends on:** T2, T3, T4; **S44-extra** (`RootOf`). Merges with T2–T4.

## Goal

The one risky change to existing behaviour. After this task a model-run command executes with a **built** environment
(or, for a legacy binding on an attended loop, an explicitly **legacy** one), `Spawn` cannot be called without one,
the output passes through the redactor, an unattended loop is never inherited, and the daemon's other subprocesses
stop inheriting except the two named sites. **T1's goldens stay byte-identical**; the only intended difference is the
leak test, which flips.

## Behaviour (each a test)

1. **Scrubbed by default.** A `bash` step bound to `host-scrubbed` runs `env`: only allowlisted, `set` and injected
   names appear; the sentinel provider key and forge token do not.
2. **Unattended ⇒ never inherited.** Legacy binding + loop attended `NULL`, `0`, or a read error ⇒ the command runs
   scrubbed, `step_environment.downgraded=1`; attended `1` ⇒ legacy inherit (upgraded-store continuity); no loop at all
   (a bare `aeon ask`) ⇒ scrubbed; the system `host-scrubbed` row removed ⇒ refused `environment-unavailable`.
3. **No silent downgrade.** Container bound, no driver registered ⇒ refused, **zero** host spawns (a spy asserts
   `exec.Command` was never reached).
4. **Policy first.** A command the verdict refuses never reaches `Exec` (a spy executor records zero calls).
5. **Secrets.** A referenced secret appears in the child's environment and is redacted from the result, the echoed
   command, and every sink (T1's scanner), including at the cap boundary.
6. **Bounds unchanged.** All T1 bounds goldens byte-identical; `wallSeconds` only shortens `BashTimeout`.
7. **Daemon git.** A hook that dumps its environment, run through a `git.Client` commit, sees no provider key or forge
   token; `SSH_AUTH_SOCK` is passed only here (D9).
8. **UI git.** `gitEnv()` keys equal the golden minus the inherited ones; hardening unchanged.
9. **Working directory.** `ExecRequest.Dir` equals the step's `WorkspaceRoot` (EV15); a table test with `WorkspaceRoot`
   set to a worktree path executes there — so S32's follow-up needs no change here.

### Deviations and the things the task file could not know

1. **`spawnWith` is a second, unexported door.** The spec fixes `Spawn` at five parameters and also requires the
   capped output to pass through `Redactor.Writer`. A redactor cannot travel in `SpawnOptions` (Do-NOT), so
   `Spawn` delegates to `spawnWith(…, red *execenv.Redactor)` and `HostExecutor.Run` — the thing that built the
   redactor from its own injections — calls that. `Spawn`'s public arity is exactly as specified; the filter is a
   property of the executor, not a sixth proof.
2. **The gate keeps its own path.** `verify.Runner` passes an **inert** `ChildEnv{}` with `SpawnOptions.Env =
   GateEnv(os.Environ())` (S57 VG5). The two sources are mutually exclusive: both present is refused, both
   absent is refused with the EV5 sentence (`TestSpawnRefusesAnInertEnv`, `TestSpawnRefusesTwoEnvironments`,
   `TestGatePathStillScrubsWithoutAChildEnv`). An inert env can never stand in for a resolved one on a success
   path — `internal/policy/token_forge_test` passes a real `execenv.Build` result on the authorized arm and the
   inert value only where the token check fires first.
3. **Two T1 goldens flipped, both named in the spec.** `TestSpawnInheritsEnvironmentTODAY` keeps its name (T1.md's
   table points at it) and asserts the opposite; `TestLegacyBackendStillInheritsAndSaysSo` was added as the
   control that the inherit still *works* when a person binds it. S57's bash-inheritance golden moved to
   `execenv.LegacyInherit()` with its bytes unchanged. `TestGitHonoursAmbientGitDirToday` flipped to three arms
   (stripped → no retarget; explicitly handed `GIT_DIR` → still retargets; no environment → refuses), so the pass
   proves the strip and not a git-side change.
4. **The test-harness env names moved out of the denied namespace.** The port-holder probe read
   `AEON_TEST_PORT_HOLDER`/`_READY`, which the scrubbed env strips (`AEON_` is a denied prefix) — so the group-kill
   proof timed out. Renamed to `S59_TEST_PORT_*` and passed via the fixture's allowlist. The deny list was **not**
   loosened for a test.
5. **EV6's trigger is the backend, not the `legacy` column.** `CreateEnvironment` can only ever write `legacy = 0`;
   the sole row with `legacy = 1` is the migration's `env-host-inherit`, which exists only on an upgraded store.
   Reading the column alone left a *deliberately created* `host-inherit` environment outside the unattended
   tightening — an unattended loop would have inherited the daemon's provider keys because nobody had migrated a
   row. `execenv_wire.go` sets `Legacy: row.Legacy == 1 || row.Backend == "host-inherit"`.
6. **`Build` does not produce the inherit value; the resolver does.** Nothing in `execenv` calls
   `LegacyInherit()` from `Build`, so an attended step on a legacy binding would have received `Build`'s *empty*
   allowlist instead of the inherited environment — a silent break of the continuity EV6 promises an upgraded
   store. The resolver still runs `Build` (the spec must parse, the set values must be legal, the references must
   clear the deny list) and then replaces the child's environment with `execenv.LegacyInherit()` when the resolved
   backend is `host-inherit`.
7. **The binding read happens even with no component.** `BindingFor("")` answers the workspace scope; skipping it
   whenever `ComponentForRoot` says `ErrNotFound` made a workspace-bound step read as unbound — a refusal to run at
   all. The sentinel distinguishes "no component registers this root" from a store failure; the sentence is never
   matched.
8. **`StepExecResolver.Attended` is an injected seam** (nil ⇒ the store path, reusing `OperatorPresentFor`'s read:
   step → loop → `LoopAttended`, every failure read as unattended). It exists so the one cell the store cannot
   produce on command — the loop says *attended* and the read FAILS — has a test.
9. **`Emit` is nil at the daemon's construction sites.** The resolver hands names, sources and the outcome to it;
   the `step.environment` event is T6's to register with the protocol (it needs the event type and the door). The
   **row** is the record and it is written on both paths, so nothing is unrecorded in the meantime.
10. **`daemonCredentials()` is assembled from its owners** — `daemon`'s provider constants, `forge.TokenEnvNames()`
    (A2), `narrow.KeyEnv`, plus the two names with no exported constant (`AEON_CARD_SIGNING_KEY`,
    `CURSOR_SIGNING_KEY` — the latter is not `AEON_`-prefixed, which is exactly why the namespace rule alone left
    it referenceable). `SecretLookup` (A1's `store` kind) is **not** wired at the construction sites: no door hands
    a credential id yet, so a `store`-kind reference refuses with `store-not-wired` rather than the empty string.
    T6 wires it with `secretref.*`.
11. **`action.GitActions.client()`'s `&git.Client{}` fallback stays refusing** (production always injects), and
    the package's tests now build clients with `git.NewClient(env)` through one `gitReal()` helper.
12. **The spec's `TestTerminalAndMCPEnvUnchanged` is not a new test.** The two T1 goldens —
    `TestTerminalEnvironmentGolden` and `TestMCPStdioEnvironmentGolden` — are that behaviour, both still pass with
    their bytes unchanged; `terminal/session_unix.go` and `mcp/client.go` gained EV10 paragraphs (comment-only)
    naming the deliberate inherit and the `scrubbed-own` rule.

    verdict, a receipt, a timeout or a process group by running a real command — and before T5 the environment that

    (the reactor's own "terminal lookup failed" branch) instead of a crash, which is the whole requirement; the
    residual window between a caller's check and its statement is not a crash any more, so it needs no mutex today.

    "substantial change" that triggers a split, and the split is its own task, not a smuggled-in side effect.
    **(b)** `daemon.go`'s trigger-access gate had two shapes for *the set could not be read* — the panic arm named its
    subject (`… · trigger_access · the policy read panicked …`) and the rejection arm did not, because before this
    fix the rejection arm was unreachable for a closed store: the panic always won. S29's
    `TestGovernanceFailsClosedWhenThePolicySetIsUnreadable` pins that the refusal "names what was asked about", and it
    was written against the only shape that existed. The rejection arm now appends ` · trigger_access`, so the shape
    of the failure no longer changes the words — which is what that test always said should be true.
