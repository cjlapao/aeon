### 4a. A1, read — what the `store` secret-reference kind actually has to build on (2026-11-03, operator-granted)

The package is two files. Its **exported** surface is five names and nothing else:

| Name | Shape | What it gives S59 |
| --- | --- | --- |
| `secrets.EnsureCursorSigningKey() error` | pre-`system.Initialize` provisioning of `CURSOR_SIGNING_KEY` | nothing — the cursor key is the framework's, not a person's secret |
| `secrets.RouteKeyPath(routeID) (string, error)` | the path of one credential | the **naming rule** to reuse, not to re-type |
| `secrets.SaveRouteKey(routeID, key) error` | write 0600, empty means "keep", `0700` parent | the **provisioning** door a `store` reference is imported through |
| `secrets.ReadRouteKey(routeID) (string, error)` | read, `""` when absent, an unreadable file **reported not treated as absent** | the **resolution** path `source_kind='store'` uses |
| `secrets.DeleteRouteKey(routeID) (bool, error)` | remove, reporting whether one existed | the un-provision door an archived reference needs |

**What this settles for T4 (D3):** `internal/secrets` holds **no value in the database** and never will — the file's
own argument (§"Why a file and not a column") is that C17 admits only the environment or a dedicated file path, and
the store is neither. `source_kind='store'` therefore means **a value held at
`$STATE/aeon/credentials/<name>.key`, 0600 in a 0700 directory**, provisioned once from a file the person names and
resolved through this package — the design's "imported once from a file the person names" reads literally, and EV7's
"NO value column, ever" stays exactly true: the `secret_ref` row keeps `source` = the credential **name**, never bytes.
The route-key file naming rule (letters/digits/`-`/`_`/`.`, no leading dot, no `..`, ≤ 128) is the validation a
`store` reference reuses, so a reference name cannot reach a path join as a traversal. `execenv` stays pure: it is
handed a `FileOpener`/getter by the caller and never imports `secrets`, `paths` or `os`.

**Deviation recorded:** the design guessed the `store` kind might need a new mechanism in `internal/secrets`. It
does not — it needs the one already there. No new package, no new directory, no migration. `TestStoreKindRefusedUntilApproved`
in T4 becomes `TestStoreKindResolvesThroughTheCredentialFile` (the approval exists and is recorded above, so the
"not built" refusal would now be the lie); the refused-until condition moves to the file's own rules — a symlink, a
mode wider than 0600, a foreign owner or an over-long value are refused with a sentence naming the reference and the
source, never the value.
