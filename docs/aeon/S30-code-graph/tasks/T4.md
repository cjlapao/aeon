# T4 — Incremental rebuild: the write-signal hook

## Why this exists

This is D5 and CG6, and it is the one place in this slice where getting it wrong means building the wrong
thing twice. **First action, before writing any code**: check whether S22 has already answered its own Q7
(*"how does the loop know it wrote files, and is there a hook?"*) by grepping
`aeon/internal/tools/write.go` and `aeon/internal/action/git_actions.go` — the two locations S22's own
brief names. If either already carries a write-completion signal, this task subscribes to it and stops;
building a second one is the exact duplication brief §8 R1 warns about.

If neither exists yet, **this task builds the hook at the tools layer, not inside `internal/graph`** — so
whichever slice (S22 or this one) needs it next finds it already there. Do not name the hook after this
slice; name it after what it signals (a file was written), so S22's own eventual implementation finds it
by its actual meaning rather than having to know this slice built it.

**Do not reach for a filesystem watcher under any framing**, including "just for local dev" or "just as a
fallback." S22's own N2 already states why: *"a watcher is a daemon, a permissions problem and a source of
phantom reindexes."* The same reasoning applies here without modification.

## Scope

**1. Locate or build the write-signal hook**, per the above. Record which of the two happened in this
task's notes — this is load-bearing information for whoever builds S22 later.

**2. On signal, re-parse only the changed file.** Delete that file's existing `graph_node` rows and the
`graph_edge` rows where either end belongs to it, then re-run T2/T3's parse for that file alone.

**3. Re-link, don't full-rebuild.** An edge from another file into the changed one must still resolve
correctly after the change — re-resolving only the edges that reference the changed file's symbols, not
every edge in the project.

**4. Prove the scaling bound (D6).** A fixture of at least 500 files; edit one; assert via instrumentation
(a counter on rows touched, not a wall-clock timer) that work stays bounded to that file's own nodes and
edges plus the edges referencing them — not proportional to the fixture's total size.
