# T7 — Test-bench UI: a `graph` tab

## Why this exists

"Including using the app" was explicit in the request that produced this slice — a feature an agent can
call is not finished for a human trying it out until there is a way to drive it from the test bench, the
same way `AskPage.tsx` exercises the model layer and `PolicyPage.tsx` exercises the policy engine.

**Read first:** `aeon/ui/src/features/test-bench/pages/AskPage.tsx` and `PolicyPage.tsx` for the page shape
this must match — form fields, a result panel, the subscribe-before-call ordering where relevant. Match the
register; do not invent a new page layout convention for one more tab.

## Scope

**1. Add `"graph"` to `BENCH_TABS`** in `aeon/ui/src/app/routes.ts`, and the corresponding menu entry.

**2. `GraphPage.tsx`**: three form modes matching T5's three actions (`explain`, `path`, `query`), each
taking structured arguments (a symbol name, a project root, for `path` a second symbol) — **no free-text
"ask the graph a question" box.** D7/N4 forbid a prose-returning tool; a free-text input on this page would
invite the thing the tool itself was built to refuse. **Calls `graph.explain`/`graph.path`/`graph.query`
over the socket** (T5, P34) — the same methods `aeon/ui/src/lib/protocol.ts` declares types for — never the
native tool, which the app has no way to invoke directly.

**3. The result panel renders all four states visibly differently** — not variations of the same empty-ish
list. `not-built` should read distinctly from `not-found` (something like "no graph exists for this
project yet" versus "nothing matched"), and `ambiguous` should list every candidate rather than picking one
silently.

**4. `project_root` is a required field on the form**, never implied or defaulted, matching T5's tool
contract.

## Validation

- [ ] all four result states (`found`, `ambiguous`, `not-found`, `not-built`) render with visibly distinct
      copy and layout, asserted by a snapshot or explicit text-content test per state
- [ ] no free-text input exists anywhere on this page — asserted by querying the DOM for a prose-style
      textarea and expecting none
- [ ] submitting with no `project_root` is refused client-side with a stated reason, matching the tool's
      own required-argument contract (T5)
- [ ] the page matches `AskPage.tsx`'s and `PolicyPage.tsx`'s established layout conventions, confirmed by
      a reviewer reading both side by side
