# T5 — The `graph` tool: `explain`, `path`, `query`

## Why this exists

This is where D7, D8 and D9 become an actual response type instead of a description. The tool's result
must be a tagged union of four variants — `found`, `ambiguous`, `not-found`, `not-built` — never a
boolean-plus-nullable-list that lets a caller conflate "nothing matched" with "nothing has ever been built
for this project." And it must never carry a synthesized-explanation field: raw node and edge references
only, the calling agent decides how to summarize.

**Read first:** S22's `search` tool registration (`internal/tools/`, once it exists) for how a native tool
is registered and described to a model — match that registration shape, not a new one. The tool's
*description*, read by a model deciding whether to call it, should say plainly that it returns structure,
not prose — the same way S22's O7 makes `search`'s description say it complements `grep` so a model does
not reach for the wrong tool.

## Scope

**1. `explain <symbol>`**: the node itself plus its direct edges (one hop), both directions (what it calls
and what calls it; what it imports and what imports it).

**2. `path <symbol> <symbol>`**: the shortest connecting chain between two named symbols, if one exists
within a bounded hop count — bound the search explicitly; an unbounded graph traversal on every `path` call
is a cost nobody asked for.

**3. `query <filter>`**: broader search by `kind`, name prefix, or `file_path` — the closest analogue to
"browse," for when the caller does not yet know the exact symbol name.

**4. Every action returns the four-state result.** `ambiguous` fires when a name resolves to more than one
exact-match node; `not-built` fires when the named `project_root` has zero rows in `graph_node` at all,
distinguished from `not-found` (rows exist; nothing matched this particular query).

**5. `project_root` is a required argument on every action, never defaulted** — the same "no default
corpus" reasoning S22's O8 states for its own two corpora.

**6. `graph.explain` / `graph.path` / `graph.query` are registered socket methods, not only the native
tool (D16-equivalent, I10, P34 — added 2026-10-26).** Without this, T7's test-bench UI has nothing to call
— every other test-bench page (`AskPage`, `PolicyPage`) reads through the socket, and the tool registered
in this task is callable only by an agent inside a loop step, never by the app directly. Each socket method
calls the identical `internal/graph/query.go` function the tool action calls — not a second query
implementation — and returns the same four-state result (D7/D8), never a flattened one just because the
caller is now a person instead of a model.
