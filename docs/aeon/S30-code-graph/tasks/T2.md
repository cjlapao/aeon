# T2 — `parse.go` and the grammar registry: Go, end to end

## Why this exists

This is where §7 Q1's first half gets a real answer instead of an assumption: **which Go `tree-sitter`
binding actually exists, and does it genuinely need no install step once vendored.** Do not write "~40
languages" anywhere in this task's notes as a fact about the chosen binding — that figure describes
Graphify's own tool (a separate project, written up in its own README), not this binding. State what the
chosen binding actually ships, with a quoted doc comment or `go.mod` entry as evidence, the same discipline
this whole plan already applies to `sqlite-vec`'s own capability claims (DB18).

**Read first:** `internal/store/schema.go`'s `DB18` comment block — the exact shape a statically-linked
`cgo` dependency with no load step takes in this codebase (`sqlite3_auto_extension()`-style registration).
Match that shape for the `tree-sitter` core, not a new pattern.

## Scope

**1. Pick the binding.** Evaluate what's available for Go `tree-sitter` bindings; confirm in this task's
notes, with evidence, whether it is pure-`cgo` (no separate `tree-sitter` CLI, no network fetch at build
time) and whether grammars ship as Go modules or need vendoring individually.

**2. The registry interface.** Sized for "register one more grammar" as the only operation a later task
(T3) needs — a map from language name to a parse function, nothing more general than that.

**3. Wire the Go grammar.** Parse a `.go` file, walk the AST, emit `graph_node`/`graph_edge` rows for the
five relations that apply to Go (`design.md`'s table — **no `inherits` edge for Go, ever**; assert this by
a test that parses a file with struct embedding and confirms no `inherits` edge is produced, only
`mixes_in`).

**4. First real fixture: this repository's own `aeon/internal/` tree.** Not a synthetic snippet — parse
real code and confirm the node/edge counts are sane by hand for one small package before trusting the
walker on anything larger.

**5. No install step.** Assert by building this package from a clean module cache in CI-equivalent
conditions and confirming no error about a missing `tree-sitter` binary or shared library.

## Notes

**Built 2026-10-30.** `aeon/internal/graph/` — `graph.go` (types: NodeRef, EdgeRef,
IncomingRef, PathHop, the four States + AllStates, Extracted/Inferred, QueryService
interface), `parse.go` (ParseFile → Emitter with a 1 MiB-per-file bound
(`MaxFileBytes`, refuse-by-bound measured), the generic AST DFS, `nameMatches`,
`qualify`, `stemOf`), `lang_go.go` (bespoke Go walker), the grammar registry
(`Registered`/`LookupByPath`, refused-by-name for unregistered extensions).
Fixture `internal/graph/testdata/fixtures/graph-demo/` (Go + TS halves) is the
T4–T6 test bed.

Deviations, all MEASURED against the real tree-sitter AST (a scratch program
dumped node names — guessing from docs was the first attempt and it was wrong):

- The Go grammar's package clause carries `package_identifier`, not `identifier`;
  type names nest through `type_spec`; function/method names ride the `name`
  field. First implementations missed all three and emitted no function nodes.
- `ParseCtx` returns `(tree, err)` — two values.
- **Go emits NO `inherits` edge** (CG4 honoured): Go has no inheritance;
  embedding lands as `mixes_in` (nameless `field_declaration` in a struct, and
  bare types inside `interface_type`). Pinned by `TestGoHasNoInheritsEdge`.
- `.then(parseOrders)` is a `references` edge, not `calls` — member-expression
  callee position is a reference in this grammar's AST. The test accepts either
  and names the fact rather than forcing the walker to lie.
