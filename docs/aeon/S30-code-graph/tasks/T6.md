# T6 — Dispatch-boundary test

## Why this exists

D10 and CG9. A13 made `by-tech-tag` a closed registry with no fallback, for a reason that applies just as
well to a structural shortcut as to an embedding-similarity one: a graph edge is similarity-shaped enough
to tempt "this file touches a lot of auth-tagged nodes, send it to the auth agent" as a convenient-looking
heuristic later, by someone who never read this slice's brief. **A prose rule nobody asserts is a rule
nobody obeys** — this task is the assertion.

**Read first:** `internal/agents/` or wherever `by-tech-tag`'s resolver actually lives once S13 is built —
confirm the real package path before writing the import-boundary check; do not assume a path that turns out
wrong when S13 lands.

## Scope

**1. An import-boundary test in both directions.** Nothing under the resolver's package imports
`internal/graph`. Nothing under `internal/graph` imports the resolver's package. Static, by inspecting
import graphs — not a runtime check that could pass by accident on one code path and miss another.

**2. Written against what exists today**, even before S13 lands, so the moment either side is built with a
crossing import, this test starts failing immediately rather than being written retroactively after
somebody already shipped the shortcut.

**3. If S13 does not exist yet when this task runs**, the test is written against the package path
`design.md`/`brief.md` name as the expected eventual location, with a note that it must be re-confirmed
once S13 actually lands.
