# T8 — Walk the demo, write the QA suite

## Why this exists

AGENTS §4a: a `DEMO.md` is only real once it has been walked, with a §Findings table recording what the
prediction got wrong. Everything in `DEMO.md` before this task runs is a prediction, written before any of
T1–T7 existed in code.

## Scope

**1. Walk `DEMO.md` end to end** against a freshly built daemon, using the exact fixture project it
describes. Every `curl`/CLI/UI step must actually be run, not read and assumed correct.

**2. Append a §Findings table** to `DEMO.md`: what matched the prediction, what did not, and what changed
as a result (a corrected command, a renamed field, a result shape that turned out different from the
mock-up).

**3. Map every Definition-of-Done item (brief §2, D1–D11) to the named test that proves it.** Where an
earlier task's gate test already covers a D-item, name that test here rather than writing a new one. Where
none does, write it now — this task is the last chance before the slice is considered done.

**4. Confirm the final grammar count (from T3's notes) is the number actually stated in `brief.md`'s and
`design.md`'s prose**, correcting either document if T3 measured something different from what was written
when the slice was only a brief.

## Validation

- [ ] `DEMO.md`'s §Findings table exists and names at least one real deviation from the prediction, or
      states explicitly that none was found
- [ ] a table in this task's notes maps D1–D11 to a named test each — no D-item left unmapped
- [ ] `STATUS.md`, `TASKS.md`, and this slice's own `brief.md`/`design.md` are checked against T3's actual

- [ ] the walked artifact (a pasted command output, a query result, a UI screenshot description) is
