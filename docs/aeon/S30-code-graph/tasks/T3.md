# T3 — TypeScript, plus whatever else the binding ships for free

## Why this exists

T2 proved the registry on one language. This task proves it generalizes by adding a structurally different
one (TypeScript has `inherits` and `mixes_in` where Go has neither), and then — the part this task exists
for — **states the real grammar count instead of repeating Graphify's "~40" as if it already applied here**
(brief §7 Q1, R2). This is exactly the kind of claim this project's own planning discipline has caught
going wrong before: a figure that describes someone else's tool repeated as a fact about this one.

## Scope

**1. TypeScript, through the same registry T2 built.** If adding it requires changing the registry
interface, that is a signal T2's interface was shaped around Go specifically — fix the interface, do not
special-case TypeScript around it.

**2. `design.md`'s per-language table, TypeScript column, confirmed or corrected** against what the grammar
actually produces — `extends` for `inherits`, `implements` or a mixin pattern for `mixes_in`.

**3. Register every other grammar the chosen binding ships prebuilt**, mechanically, each proven against a
small fixture file in that language — a parse that produces at least one node and does not error. This is
the bulk, repetitive half of this task; it is one task, not eight, because each addition is the same three
lines of registration plus one fixture, not a new investigation.

**4. State the final count, with the list of languages, in this task's notes.** Where a language Graphify
covers is not available in the chosen binding, name it explicitly as a gap rather than silently omitting it
from the list.

## Validation

- [ ] unit test `TypeScript proves the registry generalizes` passes — specifically, no change to the
      registry's exported interface was needed, or the change made is documented and justified
- [ ] **the real grammar count is stated in this task's notes**, as a number with the language list, not as
      "~40" or any other figure carried over from Graphify's own README
- [ ] unit test `every registered grammar parses its own fixture without error` passes, enumerated — one
      assertion per language, not one assertion over a loop that could silently skip a failure
- [ ] `design.md`'s per-language table is corrected if TypeScript's real behaviour differed from what was
      guessed when it was written
