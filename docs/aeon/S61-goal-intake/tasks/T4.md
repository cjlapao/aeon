# T4 · Bootstrap actions: `repo.scaffold`, `forge.createRepo`, person-door only

**Prefix:** GI · **Rules:** GI8, GI9, GI10, GI12, GI18 · **Depends on:** T3.

## Goal

Two new entries in the closed action registry with declared classes, a `Door` that makes them invisible to blueprints,
the git helpers they need, and the optional `forge.RepoCreator` — with `forge.createRepo` implemented and **off**.

## Files

- `aeon/internal/action/class.go` — constants `RepoScaffold = "repo.scaffold"` (local), `ForgeCreateRepo =
  "forge.createRepo"` (outward) in the one `classes` map; `Entry.Door` field (`""`/`loop` default, `person`).
- `aeon/internal/action/registry.go` — the two entries (args: `dir`, `template`, `vars` / `owner`, `name`, `private`,
  `description`, `dir`; `Source: "code"` for all — nothing from evidence/handoff); `Names()` **excludes** `Door=="person"`;
  new `PersonNames()`; `Dispatch` takes a `Caller` and refuses a person-door action for any non-person caller with a fixed
  sentence. `Strategy()`: `repo.scaffold` check-then-act (target already matches template ⇒ done), `forge.createRepo`
  check-then-act (`GET repo` first; exists and empty ⇒ adopt only when `adoptExisting` — default refuse).
- `aeon/internal/action/scaffold_action.go` — handler: `CheckTarget` → `Render` → `Write` → `git init -b <branch>` →
  `git add -A` → commit with resolved identity (GI12) → evidence `{commit_sha, branch, files}`; on failure `Cleanup`.
- `aeon/internal/action/forge_create_repo.go` — handler: gates (setting seam, S56 grant seam, `publish`, `confirmPublic`)
  evaluated **before** any request; `forge.RepoCreator` assertion (absent ⇒ "this forge cannot create repositories");
  create → `git remote add origin <clone_url>` (refuse if `origin` exists) → `Client.Push` (verifies by `ls-remote`);
  evidence `{repo_url, default_branch, pushed_sha}`.
- `aeon/internal/git/plumbing.go` — additive methods: `Init(ctx, dir, branch)`, `AddRemote(ctx, dir, name, url)`,
  `IdentityResolved(ctx, dir) (name, email string, ok bool, err error)` (reads `git config`, does not set it). **No
  force-push, no branch/tag deletion** (the existing `TestNoForcePushAnywhere` must stay green and be extended to the
  new methods).
- `aeon/internal/forge/forge.go` — `RepoRequest`, `Repo{URL, CloneURL, DefaultBranch, Private}`, `RepoCreator` interface
  (optional, like `StatusLister`); `aeon/internal/forge/github.go` — `CreateRepo` (user vs org endpoint chosen by
  `Owner` vs the authenticated user — T0 records how to know; if unknown, the request names the endpoint explicitly in
  `RepoRequest.OwnerKind`); error mapping reuses `classify` (name taken ⇒ `conflict`, 403 ⇒ `refused`); `Fake.CreateRepo`
  with call log and `FailMethod` support. **No token handling changes.**
- `aeon/internal/blueprint/validate.go` — **no edit expected**: the validator already takes `action.Names()`; a test pins
  that `repo.scaffold`/`forge.createRepo` in a blueprint are `unknown-action`.

## Behaviour (each a test)

1. A blueprint naming either action is refused at validate (`unknown-action`); `Dispatch` with a loop caller is refused.
2. `repo.scaffold` follows GI9 end to end against a temp dir, a real `git`, and an injected identity; a missing identity ⇒
   the refusal sentence and **nothing created**.
3. `forge.createRepo` with any of the three keys missing ⇒ a refusal naming the missing key, **zero** Fake calls.
4. All three present ⇒ one `CreateRepo` call, `Private` true unless `publish=public`; description = the short description
   field only (a test plants charter text in the plan and asserts it never reaches the request).
5. Unattended resolution (`action.Resolve(name, attended=false, allowOutward=true)`) still denies `forge.createRepo`.
6. Re-running after success is a no-op; a half-done state (repo created, remote not added) resumes.

## Notes

Notes (landed 2026-11-05, branch `s61-goal-intake`).

1. **The door is one string field.** `Entry.Door` (`""`/loop default, `"person"`); `Names()` excludes person
   entries — the blueprint validator receives `Names()` and therefore reads either name `unknown-action`
   (pinned in `person_actions_test.go`, validator untouched); new `PersonNames()` is the daemon-side
   enumeration; `Names() + PersonNames()` is the registry exactly (16 + 2 = 18). `Dispatch` refuses a
   person-door entry with the fixed `personDoorSentence` BEFORE examining arguments — the door is the
   answer and does not depend on what was asked with.
2. **Deviation from the spec wording, recorded.** The spec says "Dispatch takes a `Caller`". `Dispatch`'s
   only production caller is the loop (`internal/loop/execute.go`); making it fabricate a caller would
   give the loop a person-shaped type. Instead: `DispatchFrom(ctx, svc, Caller{Kind,ID}, name, a)` is the
   person door — `CallerPerson` is the only admitted Kind, anything else (including the empty Caller)
   meets the fixed sentence; a person caller for a LOOP action routes through `Dispatch` unchanged, so
   the loop door stays the one implementation. Both doors share `checkRequiredArgs` and the
   no-services sentence — one schema, two doors. `Resolve` also denies person names before any class
   arithmetic (DENY regardless of attendedness or `allowOutward`): a person-door action is not in the
   loop-executable set the flag lifts, and it is not in `Names()` either (truth table tested both
   attended arms).
3. **Censuses paid, dated.** `class_test.go` want-list 16→18 (`repo.scaffold` local,
   `forge.createRepo` outward). The S56 strategy census (`TestStrategiesAreEnumerated`) does NOT move
   (12/3/1) — person names are absent from `Names()`, which is the point of the door — so it grew a
   second loop: `PersonNames()` must be exactly two and both must declare `check-then-act`. The S56
   vocabulary census (`internal/autonomy/autonomy_test.go` `countLocal`) was comparing `Classes()` (18,
   carries the doors) against `Names()` (16, excludes them); fixed to count local classes that are IN
   `Names()` — dated comment says why. Autonomy package green.
4. **git helpers, additive.** `Init` (`init -b <branch> <dir>`, run from the nearest EXISTING ancestor —
   a child process cannot start in a directory that does not exist yet), `AddRemote` (the one remote
   door; ADDS only; url starting with a dash refused), `RemoteURL` (exit 2 is absence: `("", false, nil)`
   — presence as data, what GI10's never-retarget rule reads), `IdentityResolved` (`git var
   GIT_AUTHOR_IDENT`/`GIT_COMMITTER_IDENT`, read never set, walking to the nearest existing ancestor so a
   not-yet-created target resolves the identity its first commit will inherit). `refUnsafe` is the floor
   under git's own `check-ref-format`: empty, leading `-`, leading/trailing `/`, `.lock`,
   `" ~^:?*[\` + control chars, `..`, `//`. Unresolved is `ok=false, err=nil` — a RESULT the caller owes
   a sentence for; the no-environment refusal (`KindRefused`) propagates as the ERROR it is, because a
   wiring bug must not wear absence's clothes.
5. **The unresolved-identity test is scripted, not environmental.** An earlier draft pointed git at an
   empty HOME and asserted non-resolution; on this host git resolves the fallback ident
   (`user@hostname`) and the test would move whenever someone sets their name. The exit-128 answer is
   now injected through the `Exec` seam (`t4_plumbing_test.go`): what is pinned is the DISCRIMINATION —
   exit ⇒ absence, refused ⇒ error, unshapeable output ⇒ absence — and the action-level refusal proves
   the ORDER: the fake `Exec` fails the test if git is asked ANYTHING after the identity refusal.
6. **`TestNoForcePushAnywhere` untouched and green** — it walks every `.go` in `internal/git`, which now
   includes the new methods and the new test file; the spec's `TestGitHelpersNeverForcePush` is that
   guard, extended by walking, not by a twin.
7. **The scaffold handler's order IS the safety** (GI9+GI12): pin parse → template-version agreement →
   closed vars (`DisallowUnknownFields`, the offending key named) → `CheckTarget` → branch-name floor →
   IDENTITY (before the first write: "refuse with a sentence" and "nothing was created" are the same
   fact) → Render → `Write`(ledger) → `init -b` → `add -A` → commit `Initial commit (Aeon intake <id>)`.
   Every post-write failure runs `takeBack`: the ledger's own paths, then the `.git` this run created —
   but ONLY if the directory holds exactly that `.git` and nothing else; a planted stranger's file makes
   the broom report `"did not finish"` and leave the stranger alone (tested: the stranger survives,
   the run's own README does not).
8. **The createRepo gate order**: setting seam (`intake.allowRemoteCreate`, unwired = its default false,
   both sentences name the key) → grant seam (unwired = the contracted sentence VERBATIM

   publish answer (`private`/`public` only, the value named in the refusal; `public` without
   `confirm_public` refuses naming the field). Then the capability asserts: `RepoCreator` absent ⇒ "this
   forge cannot create repositories"; `RepoReader` absent ⇒ refuses too, because POSTing blind violates
   the strategy. All three refusals leave the Fake at ZERO calls and the git log at ZERO commands
   (asserted for every arm).
9. **Deviation: `publish`/`confirm_public`/`adopt_existing` args, not `private`.** The registry args
   carry the PERSON's answer (`publish`) and the two explicit confirmations; `Private` is derived
