# T5 · Proposal kinds `charter_save` and `intake_plan`, with validators and the desk apply

**Prefix:** GI · **Rules:** GI4, GI7, GI17 · P6 · **Depends on:** T2, S45 (`internal/desk`, generic `proposal.commit`) merged.

## Goal

Two new closed `proposal.kind` values, each with one validator shared by create and commit (parity), and a desk `Apply`
for `charter_save`. `intake_plan`'s apply is **not** the generic one: the generic door refuses it and points at
`intake.commit` (T6/T7).

## Behaviour

1. `proposal.create` for both kinds runs `desk.Validate` first — nothing inert-and-invalid is ever persisted (TD3).
2. A `charter_save` commit by a person writes one revision with the committer as actor; commit twice ⇒ second is
   `AlreadyApplied` (no churn).
3. An agent-created proposal's `created_by` is the agent actor (stamped); params naming one ⇒ parse error.
4. The per-agent open-proposal limit (S45's constant) applies to both kinds.
