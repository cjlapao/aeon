## Tables

- `charter_revision` — GI1 exactly. Triggers `charter_revision_no_update` / `_no_delete` (`RAISE(ABORT, 'charter history
  is append-only')`). Index `(root_id, revision DESC)`. A trigger refuses an insert whose `root_id` names a **child**
  component (`component_tree`'s parent column from S44-extra) — "the charter lives on the project".
- `goal_criterion` — GI5; FK to `goal(id)` (already in the post-rebuild FK list), `ON DELETE CASCADE`; `check_kind` CHECK;
  `text` length CHECK ≤ 512.
- `intake` — GI6; trigger `intake_root_once` (update allowed only when `OLD.root_id IS NULL AND NEW.root_id IS NOT NULL`
  and no other column changes); `created_by_kind` CHECK `'user'`.
- `intake_step` — append-only by trigger; `outcome` CHECK; `UNIQUE(intake_id, ordinal)`.
- `scaffold_template`, `scaffold_template_revision` — GI14; revision append-only by trigger; `origin` CHECK;
  `slug` UNIQUE with a slug CHECK (`GLOB` for lowercase/digits/hyphen).
- Roadmap provenance: **only if** P-C says it is a CHECK — a one-word widening of that table via the 0016 rebuild shape
  with a copy guard and a final `pragma_foreign_key_check` guard, reading the current DDL; otherwise no SQL here.
- `proposal.kind` is **not** widened here (T5 owns it).

**Deviations (recorded per T0's instruction):**

1. `intake_root_once` generalizes the spec's literal clause (update legal only on
   root NULL→set with no other column changing) into a **per-column set-once law**: the
   literal trigger would refuse the `SetIntakeLoop` write GI6 needs before any root link
   exists. Immutable columns stay frozen on every update; `loop_slug`, `target_path` and
   `root_id` each go NULL→set exactly once. The SQL's own comment carries this.
2. The store API gains **`SetIntakeLoop(id, slug)`** (not in the spec's list; GI6's
   `loop_slug` needs exactly one writer), and `SetIntakeRoot` carries the
   **`target_path` in the same write** as the root link — the linking act names where the
   repo lives. A `target_path`-only re-write stays refused.
3. The spec's `TestMigrationDrill` row lands as **`TestGoalIntakeMigrationDrillFreshEqualsUpgraded`**
   (the slice's `-run` selector reaches it via `Migration`/`Intake`), S60 T2's drill shape:
   seed at the PRE-goal_intake vintage through the store's public API, reopen to migrate,
   then data-checksum equality, widened CHECKs LIVE (an `'intake'` goal and roadmap row
   land on the upgraded store), `PRAGMA foreign_key_check` empty, idempotent re-open,
   `SchemaFingerprint().Equal` vs fresh, and catalog counts (6 tables, 2 indexes, 9
   triggers incl. the goal pair). Its literal index pin (file #97) fails loudly if another
   migration lands first.
4. `TestCharterRevisionNumbersNeverReset`: the store is single-writer (DB15), so the
   table's "concurrent appends" serialise by construction; the test proves max+1 across
   three appends and kills a hand-forged duplicate revision at `UNIQUE(root_id, revision)`
   — the same key that closes the lost-update window.
5. The I4 guard (`loops_test.go` `TestEveryScopedQueryComposesTheScopeHelper`) text-matches
   `UPDATE intake SET loop_slug = ? WHERE id = ?`; that is a SET clause, not a predicate —
   the row is selected by its own primary key and `intake` has no component_root to scope
   by. One-statement exemption added in the guard's own provisions.go style.
6. SIZE1: `store.go` was already past the line (now 1545); this change adds only the
   21-line S61 row to its surface table (comment, not code). The comment block's split is
   standing debt, not this task's.
