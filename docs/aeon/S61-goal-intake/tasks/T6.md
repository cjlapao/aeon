# T6 · The intake engine and `intake.commit`: ledger, resume, crash matrix

**Prefix:** GI · **Rules:** GI6, GI7, GI11–GI13, GI18, GI20 · P2, P3 · **Depends on:** T1, T2, T3, T4, T5.

## Goal

`internal/intake`: the engine that turns an `intake_plan` proposal into a registered, scaffolded, seeded project — one
digest-bound, resumable, idempotent run — and the read side (`Plan`/`Preview`/`Status`). This is the integration task and
the riskiest; it is proved by a **crash matrix**.

## Files

- `aeon/internal/intake/engine.go` — `Engine{Store, Charter, Scaffold, Actions, Components, Clock, Setting seams}`.
  - `Plan(ctx, intakeID, proposalID) (Preview, error)` — pure: loads the proposal, validates again, computes the step list,
    runs `scaffold.Plan` per component against a `targetPath` candidate (optional) and returns the **digest** = SHA-256 of
    the canonical `{payload digest, per-component file previews, git commands, publish request (owner, name, visibility)}`.
  - `Commit(ctx, in CommitInput, actor) (Result, error)` — `CommitInput{IntakeID, ProposalID, Digest, TargetPath,
    Publish, Owner, ConfirmPublic}`.
  - `Status(ctx, intakeID) (Status, error)` — derived state (GI6) + ledger.
- `aeon/internal/intake/steps.go` — the ordered step list (GI13) and, for each step, `Do` and `Verify` (evidence check):
  `verify-digest`; per component `scaffold` (Verify: target dir exists, every template file's SHA matches, `git rev-parse
  HEAD` exists and the commit subject carries this intake id), `verify-git`, `publish` (Verify: `origin` set and
  `RemoteRefSHA` equals local HEAD), `register` (Verify: component with this root exists with the planned slug); `tree`
  (promote/attach — Verify: parent/child relation holds); `charter` (Verify: a revision with `source_ref = intakeID`
  exists); `records` (Verify: intake-marked epics/goals/items count); `link` (Verify: `intake.root_id` set).
- `aeon/internal/intake/records.go` — the **single DB transaction** for `records`: epics (`CreateEpic`), goals
  (`CreateGoal`, `SourceKind:"intake"`, `SourceRef:intakeID`, `Submit:true` ⇒ `in_review`) with `goal_component` stakes
  mapped from `componentSlugs` and `ReplaceGoalCriteria`, roadmap items (status `idea`, priority `unknown` unless a label,
  provenance `intake`, epic by key). `store` gains `IntakeApplyRecords(tx-func)` if the existing creators cannot join one
  transaction (T0 inventory) — SQL stays in `internal/store`.
- `aeon/internal/intake/resume.go` — the ledger algorithm: before each step read `intake_step`; `done` ⇒ run `Verify`; if
  verify fails ⇒ **refuse** with a sentence naming the step and the mismatch (never redo over unexpected state); `failed`
  ⇒ re-run; absent ⇒ run. Each step appends `done`/`skipped`/`failed` with a fixed-template detail.
- Scratch workspace helper `ScratchDir(stateDir, intakeID)` creating 0700 (used by T9).

## Behaviour (each a test)

1. `Commit` refuses unless the proposal is `open`, kind `intake_plan`, belongs to this intake, and `Digest` equals a fresh
   `Plan` digest (a changed template or plan since the preview ⇒ "the plan changed since you saw it — review again").
2. Order and atomicity as GI13; the **first failure stops the run**; earlier completed steps stay (real repos) and the
   ledger says where; `Status` shows `committing` with the failed step.
3. Re-running `Commit` with the same digest resumes; **no duplicate** directory, commit, component, goal, epic, item,
   revision.
4. Publish only when `Publish≠none` and the three keys hold (T4); `public` needs `ConfirmPublic`.
5. A tree plan (`root`+`child`) registers the first child standalone → `component.promote` → remaining children with
   `parentId`; a single component registers standalone.
6. After `link`, the proposal is marked applied through the S45 desk's decide path with the **committer** as actor (the
   desk's own function; this task adds no decide logic); the intake loop is closed (`loop.close`) if idle.
7. No step reads or writes a secret; error text never contains a token (planted-sentinel test).

## Commands

P10, `./internal/intake/ ./internal/store/ -run 'Intake|Commit|Crash|Resume' -count=1 -race -v`.

## Definition of done

- [ ] Crash matrix green; stale-digest refusal; atomic records; goals `in_review`; no duplicates on resume.

## Do NOT

- Do not approve a goal or mark an item ready. Do not overwrite or delete a directory this run did not create. Do not
  continue past a failed step. Do not add decide logic (use the desk's). Do not execute `proposed.verify[]`.

## Notes

Built 2026-11-05. No migration added (the 101 applied set is unchanged; the goldens stay paid).

**What was built.** `internal/store/intake_records.go` (223): `ApplyIntakeRecords` files the plan's epics, goals (with stakes and criteria) and items in ONE transaction — plan epic keys mint to ids once and are reused, goals arrive `review_state='in_review'`, `source_kind='intake'`, `source_ref=<intake id>`, created by the committer; items enter as `idea` with plan-derived priority (label required with a known state, nothing invented without one) and the estimate trio riding together with basis "intake plan"; criteria mirror `goals.go`'s own `ReplaceGoalCriteria` laws (caps, checks-complete, ordinals). `internal/intake/` (scratch 52, engine 326, steps 629, resume 163, status 137; tests harness 406, engine 462, crash 300 — SIZE1 measured, largest 629): `Plan` renders the preview — the SAME `scaffold.Render` over the same template pins, so the previewed shas are the bytes the action will write — plus the fixed three-command git sequence publish will run, and the digest of the CHOICE (intake id, proposal id, plan payload digest, target path, per-component slug/name/template-version/target, publish mode/owner/public-confirmation), never of the disk. `Commit` re-digests BEFORE any write (a moved plan is refused with "the plan changed since you saw it"), then walks `verify-digest → (scaffold → verify-git → publish → register):<slug>… → tree → charter → records → link`, every step carrying Do and Verify, every truth one ledger row; `Status` derives interviewing/planned/committing/committed/abandoned from the row, the proposal and the ledger — no state column was invented.

**The resume law the crash matrix proved.** `done` ⇒ run Verify, and a mismatch refuses, records a failed row, and does NOT demote the step: one `done` row keeps a step on the verify road forever, and only a `failed` with no `done` under it re-runs. That is the spec's "refuse, never repair" read literally: a stray hand's bytes survive the resume (proved — the file still says "tampered" after the refused run), and restoring the preview's own bytes lets the same run finish. `records` says `failed` honestly when its transaction dies (the fault hook fires mid-tx, and the rollback proves total — no epic, no goal, no criterion, no item); a crash BETWEEN steps says nothing in the ledger (proved at every position). At every kill point the finished run's census equals the uninterrupted run's: every file path and byte under the target, component/goal/item/criteria/revision counts, the proposal's word, the ledger's last-words — and no step ever reaches `done` twice.
