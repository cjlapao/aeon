# T2 · `internal/charter`: the closed body, validation, revisions, descriptions

**Prefix:** GI · **Rules:** GI1–GI4, GI17 · P3, P6 · **Depends on:** T1. Parallel-safe with T3.

## Goal

The pure core of the charter: the typed body, canonical JSON, one validator used by every door (person write, proposal
create, proposal commit — parity by construction), the revision write path, and the one description formatter.

## Files

- `aeon/internal/charter/body.go` — `Body` struct per GI2; `Canonical(Body) ([]byte, error)` (sorted keys, no
  insignificant whitespace, stable ordering of arrays as given); `Parse([]byte) (Body, error)` (unknown fields refused).
- `aeon/internal/charter/validate.go` — `Validate(Body, Vocab) *Refusal`: byte caps, counts, `acceptance[].id` uniqueness
  and format `ac-<n>`, `check` enum, `ref` rules, `proposed.budgetUsd` ≥ 0 or absent, `proposed.autonomy` ∈ `Vocab.Autonomy`
  (absent vocabulary ⇒ the field is refused, OD12), `proposed.verify[]` length caps and **no NUL/newline**; every refusal
  a sentence naming field and limit.
- `aeon/internal/charter/describe.go` — `Describe(Revision) Description`: the one formatter (PM5 shape): one-line summary,
  counts, "proposed: not applied" lines. **Fixed templates from ids and enums**, never raw user text (SEC-033).
- `aeon/internal/charter/write.go` — `Service{Store}`: `Save(ctx, actor, rootID, Body, note, source, sourceRef)` →
  `Validate` → resolve root (`RootOf`; refuse a child) → `store.AppendCharterRevision`; `Get`, `List` (with details),
  `Revisions`. The actor is a parameter supplied by the caller (the daemon stamps it from the peer, T7).
- `aeon/internal/charter/vocab.go` — `Vocabulary()` returns check kinds, caps, and the autonomy enum **supplied by a func
  seam** (`AutonomyVocab func() []string`, nil until S56 wires it).
- **No import** of `internal/policy`, `internal/loop`, `internal/action` (GI2 "grants nothing"; T7 asserts it).

## Behaviour

1. `Save` is the **only** writer; `Validate` is the only validator (a grep test: the caps appear once).
2. A save equal to the current canonical body is a **no-op** (no new revision, returns the current) — never churn history.
3. Revision `summary` template: `"charter r{n} by {actorKind}:{actorID} ({source})"` — ids and enums only.
4. `Describe` never prints the body's free text beyond fixed-length field counts (the UI shows the body itself from the
   read, in a separate field the client treats as data).

## Notes

`describe.go` 90, `write.go` 206, `charter_test.go` 477, `testdata/canonical.golden` 1.
All under the line; `go build ./...` BUILD-OK, `go vet ./internal/charter/` clean, gofmt clean.
Ten tests (the table's nine plus `TestNoopReturnsTheCurrentVerbatim` and
`TestCapsHaveOneHome` — Behaviour 1's "caps appear once" grep law as a mechanism), 27 cap
subtests, all green `ok … 2.033s`; `-race` deliberately UNRUN host-wide (tsan ENOMEM — the
standing record).

Decisions the spec left open, made here and pinned:

1. **note has no column, and the summary is a fixed template (SEC-033)** — so a PERSON's
   note rides `source_ref`, the one column with no other meaning when source is `person`;
   a `proposal`/`intake` save arriving with a note is refused (`note-source`) — its reason
   lives on the proposal / the intake ledger. Documented at the Save doc-comment.
2. **`MaxVerify = 20`** — the design gave per-item caps everywhere else but only said
   "length caps" for `proposed.verify[]`; 20 commands is a gate list, not a script. Pinned
   in the caps table and `Vocabulary()`.
3. **ref rules** made decidable: a ref without a check is refused (nothing to check);
   `command`/`test` without a ref is refused (a phantom); `manual` with a ref is refused
   (a human reading checks nothing by path).
4. **NUL is refused in every string**; newline additionally in tags, refs, env refs and
   verify (GI2's "no NUL/newline" line); `goal` may hold newlines (it is a paragraph).
5. **Empty lists are absent lists** in both directions (Parse normalizes, Canonical
   omits) — one digest per statement; the golden pins the byte spelling.
6. **no-op saves answer the CURRENT row verbatim**, whoever re-sends (the no-op is about
   the body, not the wisher); the read→append pair is serialised by a service mutex, since
   the revision number in the summary must be the number the store will write (single
   process, single writer — DB15).
7. `store.Refusal` crosses the package boundary verbatim — the child-refusal sentence that
   names the project is T1's, not re-worded here.

The golden was generated by a temporary in-package generator (run, inspected field-by-field
against GI2's struct order, kept; generator file deleted). `TestPackageImportsNothingThat
Grants` carries a canary (the guard must SEE a store import); the ban list covers policy,
loop, action, tools, daemon, execenv, desk. The other half of "grants nothing" — who may
import `internal/charter` — is T7's guard, as specced.
