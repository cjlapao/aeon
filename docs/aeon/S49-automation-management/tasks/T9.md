# T9 · Settings → Automation

**Prefix:** AN · **Rules:** AN10, AN11, AN13 · P34 · standing rule 3 · **Depends on:** T3, T4, T5 and **S45 T9** (shared components) and **S48's blueprint list** (the picker). Parallel-safe with T7, T8.

## Goal

A person manages everything that starts agents on its own from one place: a unified list that says in plain words what each does and whether it can fire, forms that preview the schedule and test the match **before** saving, an authority confirmation whose text comes from the daemon, a fire log that keeps the five
outcomes distinct, archive instead of delete, and an audit. Descriptor-driven. **The bench `AutomationPage.tsx` and its JSON textarea stay as diagnostics** (untouched).

## Behaviour

**List** (`automation.list`, filters as params): source pill, name, **description sentence** (daemon text), state word (`Enabled`/`Disabled`/`Paused`/`Archived`), blueprint with a **health dot** (`ok`/`missing`/`invalid`/`unverifiable` — text + colour), last outcome pill, next fire (schedules, from `show`/preview), "needs attention" count (`canFire:false` while enabled). Archived hidden unless the filter asks. Empty ⇒ the daemon's statements.
**Drawer** (`automation.show`): description, canonical schedule/match, limits, **health reasons** (webhook secret `env NAME: set|unset` — never a value; workspace; scope; blueprint with the report counts and a link to the blueprint in S48's screen), last fires, loops started (`automation.runs`, linking to the loop), changes. Actions: Edit, Enable/Disable (reason for disable), Pause/Resume, Fire now (schedules), Archive (reason) / Unarchive.
**Forms** from `automation.vocabulary`:
- **Schedule/webhook:** blueprint picker (S48 list; each option shows its health when known), cron field with **live preview** (`automation.preview`, debounced; renders the next instants with their DST/window notes verbatim; the daemon's refusal text is shown under the field as the user types — client-side cron parsing is **not** done), timezone **select** from the vocabulary (no free text), window (start/end/days), workspace, goal; webhook: **secret env var name** input validated by the daemon-sent grammar (an entry with `=` or whitespace is refused client-side with "enter the variable's name — the daemon reads its value from its own environment") and a presence indicator after save.
- **Event:** event select ⇒ the `MatchBuilder` shows **only the keys applicable to that event** (`applicableKeys`, from the vocabulary), values as chips with the allowed task types; a **sample tester** (`automation.test`) with per-key ✓/✗ explanation; a "would have matched in the last N events" count and list (`automation.dryrun`, explicitly labelled "not fired — a read of past events"); limits; scope pickers (S38 project/component list methods, T0 names); kickoff template text.
- Save ⇒ `automation.trigger.create`/`update`, `trigger.add`/`update`; a refusal shows the validator's sentence **verbatim** and **keeps the draft**.
**Authority confirm** (`AuthorityConfirm`, via `useConfirm`) for Enable, Fire now, Unarchive and Save-as-enabled: the text is **the daemon's `authorityStatement` with the trigger's description**, followed by the **health result** (if `canFire:false` the confirm says why and the primary button reads "Enable anyway"); declining sends nothing. Disable/Archive confirm with a required reason.
**Fire log** (`automation.fires`): the five outcomes as distinct pills (text + colour), `could-not-say` visibly its own state with its reason, `reason` verbatim, `loop` link when started, filters daemon-side, cursor paging (`beforeId`).
**Audit** (`automation.changes`): newest first, fixed-template summaries. **Proposals tab:** S45's desk filtered to `automation_disable` (preview = description + recent fires + health; commit/reject via the generic methods with the before/after confirm; the "proposed by an agent" badge).
**Cross-cutting.** Offline/reconnecting ⇒ writes disabled with the kit affordance; reads show last data; after any write the row comes from the **response**, never optimistically; no `localStorage` for automation data; no `fetch`; no client-side cron/matching/formatting of descriptions; i18n parity; no new dependency.

## Do NOT

- Do not parse cron, match events, describe a trigger or write authority text in the UI; do not offer a free-text timezone or an inapplicable match key.
- Do not display or accept an env **value**; do not enable without the authority confirm; do not add a delete control.
- Do not edit `contract.ts`, the bench page, S48's screen or the existing panels; do not add a dependency.
