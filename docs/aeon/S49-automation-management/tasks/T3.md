# T3 · The unified reads: list, show, fires, runs, health, vocabulary, previews, changes

**Prefix:** AN · **Rules:** AN1, AN5, AN7, AN8, AN10, AN11 · P34 · **Depends on:** T1, T2 (health's blueprint half needs S48; every other read does not).

## Goal

The daemon can answer, over one view of both families: *what automations exist, what each does and in plain words, what happened, what loops it started, whether it could fire right now, when it fires next, whether a sample event would match, and who changed what* — read-only, none on the narrow surface.
The existing `trigger.*` and `automation.trigger.*` reads are untouched.

## Files

- `aeon/internal/protocol/automation_read.go` — **new**: local interface `AutomationReads` (the S33/S35 pattern: no `internal/store` import) and handlers; `Table.AutomationReads` (nil ⇒ the methods are **absent**, V13).
  - `automation.list {source?, enabled?, archived?: "exclude"|"include"|"only", blueprint?, rootId?, componentId?, q?}` → `{automations: AutomationView[], statement?}`; `q` = substring over name/id/description; empty result with a filter ⇒ `"no automations match this filter."`, empty store ⇒ `"no automations. nothing starts agents on its own."`.
  - `automation.show {source,id}` → `{automation: AutomationView, schedule?|webhook?|event? (canonical), description, health, recentFires: [≤5], changes: [≤5]}`; unknown ⇒ `ErrAutomationUnknown` naming the nearest ids.
  - `automation.fires {source?, id?, outcome?, limit?, beforeId?}` → `{fires: FireView[], counts{started,refused,limited,skipped,couldNotSay}, nextBeforeId?}` from `automation_fire_view` (T1); each fire carries its `reason` verbatim and `loopId/loopSlug` when started.
  - `automation.runs {source,id,limit?}` → `{loops: [{id, slug, status, startedAt}], total}` (T1).
  - `automation.health {source?, id?}` → `{health: [{source, id, blueprint{state, counts}, webhook?{envName, set}, workspace{exists}, scope{exists}, canFire, reasons[]}], evaluatedAt}` — **inputs read by the daemon adapter**, composed by `automationview.ComposeHealth`.
  - `automation.vocabulary {}` → `automationview.Vocabulary()`.
  - `automation.preview {source:"schedule"|"webhook"?, id? | spec{expr,zone,window?}, n?, from?}` → `{instants: [{at, note?}]}` (webhooks have no clock ⇒ `ErrBadParams` naming why); `n ≤ 20` default 5; `from` default now.
  - `automation.test {match, sample}` → `{matches, perKey[]}`; `automation.dryrun {id, sinceOutboxId?, limit?}` → `{wouldMatch: [{outboxId, event, subjectKind, subjectId, at}], scanned, from}` (read-only scan of `automation_event`; never inserts a claim).
  - `automation.changes {source?, id?, limit?}` → `{changes, statement?}` ("no automation changes recorded." only when empty).
- `aeon/internal/daemon/automation_read.go` — **new**: the adapter assembling views from `trigger_schedule`/`event_trigger` rows (incl. `lastFire`), the unified view, the audit, and health inputs: **blueprint** via the S48 source + the **same `Analyze` call `loop.start` uses** (state `unverifiable` when S48's source is unwired — explicit, never `ok`), **webhook secret presence** via `os.LookupEnv(name)` (a bool; **the value is never read into a variable that outlives the call and never logged**), **workspace** `os.Stat`, **scope** via S38's read functions (T0 names). No cache (N8). `At` injected at the adapter.
- `aeon/internal/protocol/method.go` — ten consts in a labelled block; `RequiresInitialize`, **not** `Debug`; conditional on the seam. `errors.go` — `ErrAutomationUnknown`, `ErrAutomationPreview` (a clock/validation refusal carrying the validator sentence verbatim). Contract chain: conformance cases, handshake block "S49 reads", fixtures, `make protogen`.

## Behaviour notes

1. **Reads write nothing and claim nothing** (spy: store writes, recorder, outbox claims all zero). `dryrun` is a pure scan.
2. **Health never gates:** the engines' run-time checks and outcomes are untouched; a test fires a trigger whose health says `blueprint: invalid` and observes the engine's own `refused` outcome unchanged.
3. **Secrets:** no method returns, logs or hashes an env value (acceptance 5; a test sets `ENV_X=topsecret` and asserts the bytes appear nowhere in any response/log/audit).
4. **Compat:** `trigger.list/history` and `automation.trigger.list/show/fires` fixtures are byte-identical to before.
5. **Archived** automations are excluded by default and shown with `archived:true` when requested; an archived trigger's `canFire` is false with the reason "archived".

**What the task file could not have known:**

- **The preview param bug the tests caught.** `AutomationPreviewParams.validate`
  had its XOR inverted (rejected spec-only drafts, accepted `{}`). Fixed to
  `(p.ID == "") == (p.Spec == nil)` with the truth table beside it.
- **`AutomationCanonical` has no `canonical` string.** The unified canonical
  form IS the shape — clock rows answer `{expr, zone, window}`, webhook rows
  `{secretEnv}`, event rows carry the rule as `match` (raw JSON). The plain
  words live in `description`, and `description` is SHOW-ONLY: the list view
  has none (AN9's list stays cheap).
- **`automation.runs` on a typo refuses, it does not answer empty.** The
  first pass answered `{loops:[],total:0}` for `sch-mornin` — an empty
  answer is only true if the automation exists, so the empty case re-consults
  `findRow` (same sentence `show` speaks).
- **Cross-family ids name their family.** An event id shown as a schedule
  answers `"... is a event, not the schedule named — the source is part of
  the name"` — the sentence uses the SOURCE VOCABULARY word verbatim (so
  "is a event" reads broken on purpose: the enum word, not prose).
- **The dry-run family refusal was a real bug.** The first pass refused an
  EXISTING schedule id with `-31890 unknown`; a row `findRowByID` finds must
  answer ErrBadParams naming the family ("is a schedule — a dry run is an
  event trigger's verdict…"), and only a nowhere-id is `-31890`.
- **Health-never-gates needed a LIVE event to prove anything.**
  `RecordEventFire` is `ON CONFLICT DO NOTHING` and `ListEventTriggersFor`
  returns disabled triggers — so re-draining the fixture's old outbox rows
  writes nothing new (correctly!). The test creates a NEW manual bug task
  after disabling, drains again, and demands the engine's own
  `skipped / "disabled: parked for the test"` row, the already-decided row
  unmoved, the open claim still open, and the starter never consulted.
- **The outbox fixture writes tasks, not events.** AU3's DB trigger makes a
  hand-written `task.created` outbox row impossible without the task row;
  the honest fixture is `CreateManualTask` itself (AU4's emitter), so the
  events are real and `Admits` sees real `task_type`s.
- **Grammar keys are snake_case on the wire (`task_type`)** — `internal/match`
  owns them — while `automation.test`'s SAMPLE is the protocol's own camelCase
  (`taskType`). Both directions pinned; the first fixture draft mixed them and
  the validator refused, verbatim, as designed.
- **The vocabulary fixture is generated bytes**, not hand-written: it must
  equal `automationview.Vocabulary()` marshalled — same bytes as the seam.
- **protogen forces fixtures for all ten consts** (it AST-reads `method.go`
  registration-agnostically), so the `automation-reads/` fixtures feed both
  the conformance walkers AND protogen; `contract.ts` regenerated,
  `make check-protogen` green.
