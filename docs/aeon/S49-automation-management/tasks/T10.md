## The migration drills (two migrations)

1. **Fresh apply** — columns, `automation_change`, the view, triggers; the `proposal` rebuild accepts `automation_disable`, refuses an unknown kind.
2. **Upgrade from a pre-S49 store** with existing schedules (schedule, webhook), event triggers, fire history and outbox rows: both migrations apply; **every pre-existing schedule has `created_by_kind='user'`, `created_by_id=''`** (never a fabricated id); counts and checksums of `trigger_schedule`, `trigger_fire`, `event_trigger`, `event_trigger_fire`, `automation_event`, `proposal` unchanged; the fire view's counts equal the sums of the two tables.
3. **Archive drill** — archive a schedule and an event trigger: the **real clock and dispatcher** (injected time) do not fire them; unarchive ⇒ still disabled/paused; enabling is a separate act; history intact.
4. **Idempotent re-open**; **append-only** — `UPDATE`/`DELETE` on `automation_change` fail; **forward-only** — no rollback; recorded.
5. **Attendedness drill** — start one loop each from a schedule, a webhook (signed test POST) and an event trigger: each pinned `attended=0`, `allow_outward=0`, `started_by` ∈ `trigger|webhook|event`, `trigger_id` set.
