# T6 · The `automation_disable` proposal kind

**Prefix:** AN · **Rules:** AN9 · S35 TD1/TD3/TD4 · S37/S46/S48 (the rebuild precedent) · **Depends on:** T4, T5 and **S45 T1/T5** (the `internal/desk` registry and generic `proposal.commit`).

## Goal

Agents can *propose to narrow* — to disable an automation — as an **inert** proposal a person commits. It is the **only** automation write an agent can ever initiate, and it can only reduce authority. The closed `proposal.kind` enum gains one kind by the established table rebuild.

## Files

- `aeon/internal/store/migrations/<14-digit>_proposal_automation_disable.sql` — **new**: the S37 T1 / S46 T6 / S48 T9 rebuild pattern. **Read the CURRENT `proposal` DDL first** (it carries `agent_import`, and `mcp_grant_revoke`/`blueprint_save` if those slices merged) and use the **real current kind list**; copy the precedent's structure verbatim and change only the CHECK. Update the Go closed-kind list/validator and lock test and every **literal** migration-count assertion (T0 item 8: edit what `grep` shows).
- `aeon/internal/desk/` (S45) — register `automation_disable`: payload `{source, id, reason}` (closed shape; reason 1–256):
  `Validate`: the automation exists, is **enabled** (event) / **not paused** (schedule/webhook) and **not archived** (refused at create otherwise — "already off", S35 TD3: nothing inert is carried to commit); `AlreadyApplied`: already disabled/paused; `Apply`: **T4's disable/pause path with the committing person as actor** (audit `disable`/`pause`, summary names the proposal id). The effect func is supplied to `desk.Seams` by the daemon wiring.
- `aeon/cmd/aeon/proposal_validators.go` / `proposal.go` — the CLI's per-kind arm delegates to `desk`.
- Preview for `proposal.get` (S45 T5 hook): the automation's `Describe` sentence, its last 5 fires and health — read-only, advisory.

## Behaviour

1. **Narrowing only, by construction:** the payload names no target state; `Apply` can only disable/pause. A fuzz test over payloads asserts no accepted payload results in an enabled/unpaused/unarchived automation.
2. **Inert until committed:** with proposals present, `automation.list/show`, the clock and the dispatcher are unchanged (the S35 arbiter pattern extended).
3. **Commit is S45's generic commit** (digest-bound, effect-then-flip, crash-safe retry, before/after = the view before/after, reject needs a reason). No new socket method.
4. **No kind exists to create/enable/update/archive** — and none is added (a guard in T5/T7 asserts the kind list contains exactly one `automation_*` kind).
5. The per-agent open-proposal limit (S45's named constant) applies.

Deviations from the spec, recorded:

1. **The audit sentence is the write path's own frozen one, not a proposal-phrase.** The spec's
   `automation_change` example shows a disable row naming the proposal. It cannot: the
   event path's summary (`"disabled event <id>"`, store-side) and the pause summary
   (`"pause schedule <id>"`, engine-side, AN14-frozen) are byte-frozen, and adding a SECOND
   audit row per change is the double-count AN4 forbids (T4's `fire_now` precedent — one
   audit, the path's own). Mitigation as built: the event row's `disabled_reason` carries the
   person's reason plus `(proposal #N)`; for a pause the proposal id lives in the proposal row
   and the decision record. The committer IS the audit actor in both — the spec's essential
   rule.
2. **Test names:** `TestCreateAndCommitValidatorsAreOneFunction` is taken by `mcp_proposals_test.go`
   → `TestAutomationDisableCreateAndCommitValidatorsAreOneFunction` (the blueprint/environment
   per-kind suffix pattern). `TestProposalKindMigrationPreservesRowsAndIndexes` likewise takes
   the suffix (`…AutomationDisable`). `TestProposalKindListMatchesGoMirror` needed no edit —
   it reads the live DDL and widened automatically (asserted by the store suite).
3. **`TestDeskImportsNoStoreOrDaemon`** is kept as named but asserts the S49 file's import block
   specifically; the package-wide purity test (`internal/desk/imports_test.go`, covering store
   AND daemon AND protocol for the whole package) already exists and stays the load-bearing guard.
4. The kind refuses ALREADY-OFF at create while AlreadyApplied at commit completes an
   off-state flip — no contradiction: the create-side rule is TD3's nothing-inert-carried, the
   commit-side is TD4's crash/manual window; Validate runs at commit only when AlreadyApplied
   says false.
