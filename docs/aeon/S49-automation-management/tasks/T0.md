### 5. Outcomes and the AU12 mapping (view direction)

`trigger_fire.outcome` (0032 CHECK): `fired | did_not_fire | could_not_say | skipped | refused` (`trigger/record.go:25-40`); columns `schedule_id, instant, outcome, reason, loop_id, at` + UNIQUE(schedule_id,instant); **no** subject/depth/cost/slug columns. `event_trigger_fire.outcome` (0039 CHECK, NULL while claimed-open): `started | refused | limited | skipped | could-not-say`; reasons closed per AU12; `cost_note ∈ ('',cost-unknown,cost-floor)`; `loop_slug` present.

AU12 maps S40→S20 (S40 design AU12). **The view needs S20→AU12**, which is not injective — decision: the view's `outcome` carries the AU12 word; map `fired→started`, `refused→refused`, `skipped→skipped`, `could_not_say→could-not-say`, **`did_not_fire→skipped`** — AU12's table sends both `limited` and `skipped(disabled)` into `did_not_fire`, so the reverse arrow cannot recover which; `reason` stays verbatim and carries the distinction. `event_trigger_fire.outcome NULL` (claimed, undecided) maps to no view row — the view selects decided rows only (a claim is not an answer). No S20 value lacks a counterpart; the one merge is `did_not_fire`. **could-not-say range/count rows are `trigger_gap` (0034), not fire rows — the view covers fire rows only; gaps stay in `trigger.history`.**
