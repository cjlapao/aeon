# T7 · Agent tools: four reads and one propose-to-disable

**Prefix:** AN · **Rules:** AN9 · standing rule 2 · S38 OL2/OL3/OL10 · S40 AU1 lock 1 · **Depends on:** T3, T5, T6.

## Goal

Agents can **see what runs on its own** and **ask a person to turn something off** — and nothing else. Five catalog specs, one definition with socket twins, registered and granted to no one by default. S40's AU1 lock 1 ("no agent tool references a trigger write") is **preserved**: the one write-shaped tool creates a *proposal*, never a trigger change.

## The five specs (`internal/records/catalog.go`, additive; family `automation`)

| Tool | Socket twin | Class | Mutates | What it does |
| --- | --- | --- | --- | --- |
| `automation_list` | `automation.list` (T3) | safe | no | List what starts agents on its own: schedules, webhooks and event triggers — name, source, state, the blueprint it starts, and a plain-words description |
| `automation_show` | `automation.show` (T3) | safe | no | One automation in full: description, schedule/match, limits, last fires, whether its blueprint still works |
| `automation_fires` | `automation.fires` (T3) | safe | no | Recent fire outcomes (started / refused / limited / skipped / could-not-say) with their reasons, optionally for one automation |
| `automation_health` | `automation.health` (T3) | safe | no | Whether an automation could fire right now: blueprint state, secret env set/unset, workspace, scope — as of now |
| `automation_propose_disable` | `automation.proposeDisable` (new, this task) | detectable | **yes** | Create an **inert proposal** to disable one automation (kind `automation_disable`); a person decides; nothing changes until then |

## Rules (each a test)

1. **Schemas** are `additionalProperties:false` with **no** `actor`, `source-of-authority`, `status`, `kind`, `enabled`, `archived` fields; `automation_propose_disable` input `{source, id, reason}` (`source` ∈ the closed trio; `reason` 1–256). Identity is stamped (OL3).
2. **No tool creates, enables, updates, archives, pauses/resumes directly, or fires** — and none can *propose* any of those (the only automation proposal kind is `automation_disable`, T6). T5's guards assert the registry/catalog/narrow/agent-service doors.
3. **Propose is validated at create** with T6's `desk.Validate` (already-off or unknown ⇒ refused naming why; nothing created); a valid one creates an inert proposal with `created_by` = the stamped agent through the same path as `proposal.create`.
4. **Reads equal the socket reads** field for field (one implementation); health carries `evaluatedAt`; **no env value** in any output (names and a `set` bool only).
5. **No MC2 analogue:** triggers are not private between agents — but the tools are **read-only data**; an agent learns what standing authority exists, which is intended (it is the same thing a person sees).
6. Per-agent open-proposal limit (S45's constant) with a counted refusal naming it; **counted registry bump +5** (from T0's recorded count; dated comment); descriptions ≥ 40 chars; **not** in `DefaultGrant()`.
7. S40 AU1's original lock-1 guard (T0 located it) passes **unedited**: it must not match any of the five names (so the names avoid the guard's forbidden words — verify with the real regexp; if a name collides, rename the tool, never edit the guard).
