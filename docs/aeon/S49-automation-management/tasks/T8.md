# T8 · The CLI as a client: `aeon automation`

**Prefix:** AN · **Rules:** AN10, AN12 · standing rule 1 · P34 · S45 PM4 · **Depends on:** T3, T4, T5. Parallel-safe with T7, T9.

## Goal

Event triggers get a CLI **for the first time**, schedules get `update` and `archive`, and both families share one verb set — all as **clients of the socket methods** (parity is a test), with an offline fallback through the same code. `aeon trigger …` keeps working unchanged.

## Verbs

```
aeon automation list      [--source schedule|webhook|event] [--enabled|--disabled] [--archived include|only] [--blueprint N] [--component C] [--q TEXT] [--json]
aeon automation show      SOURCE:ID [--json]               # description, canonical form, health, recent fires, recent changes
aeon automation fires     [SOURCE:ID] [--outcome O] [--limit N] [--json]
aeon automation runs      SOURCE:ID [--limit N] [--json]
aeon automation health    [SOURCE:ID] [--json]
aeon automation changes   [SOURCE:ID] [--limit N] [--json]
aeon automation vocabulary [--json]
aeon automation preview   (SOURCE:ID | --cron EXPR --timezone ZONE [--window-start … --window-end … --window-days …]) [-n N] [--json]
aeon automation test      --match JSON --sample JSON [--json]          # does this sample event match
aeon automation dryrun    SOURCE:ID [--since-outbox-id N] [--limit N] [--json]
aeon automation add-schedule --id ID --blueprint B --cron EXPR --timezone ZONE [--workspace P --goal G --window-* …] [--enabled] [--yes]
aeon automation add-webhook  --id ID --blueprint B --secret-env NAME [--workspace P --goal G] [--enabled] [--yes]
aeon automation add-event    --name N --match JSON --blueprint B --max-runs-per-hour N [--max-cost-per-day-usd X] [--component C --root R --kickoff T] [--enabled] [--yes]
aeon automation update    SOURCE:ID [--blueprint B --cron … --timezone … --workspace … --goal … --window-* … --secret-env NAME --match JSON …]
aeon automation enable    SOURCE:ID --yes          disable SOURCE:ID --reason R          pause|resume SOURCE:ID
aeon automation fire-now  SCHEDULE_ID --yes
aeon automation archive   SOURCE:ID --reason R      unarchive SOURCE:ID --yes
aeon trigger list|pause|resume|fire-now|add|history      # unchanged flags and output; each is a client of the same methods
```

`SOURCE:ID` is `schedule:nightly`, `webhook:ci`, `event:approved-features`. **Secrets:** only `--secret-env NAME` (a variable **name**); there is no flag, prompt or stdin path for a secret value (C17), and the usage text says the daemon reads it from its own environment.
`--yes` gates what **grants or restores authority** (`enable`, `fire-now`, `unarchive`, and `add-*` with `--enabled`): a seatbelt for a typo, **not** a security control (the human door is the socket). Without it the verb prints the daemon's `AuthorityStatement` with the description and the health, says "re-run with --yes", exits non-zero, writes nothing.

## Files

- `aeon/cmd/aeon/automation_cmd.go` — **new** (`cmdAutomation`, verbs, usage); `aeon/cmd/aeon/trigger.go` — verbs call the same door (**flags/output unchanged**, goldens); `main.go` — dispatch + usage.
- `aeon/cmd/aeon/automation_client.go` — **new**: `automationDoor` with `socketDoor` (default) and `directDoor` (offline: the same `internal/daemon` read adapters and write service over a directly opened store, actor `{cli,cli}`, audited `actor_kind='cli'`); `selectDoor()` as S45 T8 (dial; "no daemon" ⇒ direct + the fixed stderr line `daemon not running — applied directly to the store`; any other dial failure refuses). `test`/`preview --cron` need no store and work offline via `automationview`.
- `aeon/cmd/aeon/automation_parity_test.go` — the parity guard.

## The CLI re-validates nothing

Flag parsing refuses only what cannot be a value (a non-JSON `--match`, an unknown `SOURCE`, a non-numeric `-n`). Cron, zone, window, match grammar, blueprint validity and scope are the **daemon's** sentences printed verbatim. `preview`/`test` print the daemon's output; no client-side cron or matching.

## Printer — what it must never hide

`list`: source, id/name, state word (`enabled|disabled|paused|ARCHIVED`), blueprint with its **health dot as a word** (`ok|MISSING|INVALID|unverifiable`), the description sentence, last outcome. `show`: description, canonical schedule/match, limits, **health reasons**, last fires (outcome words + reasons verbatim), last changes (who/what/when). `fires`: the five outcomes as distinct words, `could-not-say` printed as such (never "ok"). `preview`: instants with their notes. `health`: webhook secret as `env NAME: set|UNSET` — **never a value**. Empty results print the daemon's statements.

## Definition of done

- [ ] `aeon automation` covers both families and the event-trigger CLI that never existed; `aeon trigger` unchanged; parity guard both directions.
- [ ] Authority verbs gated by `--yes` with the daemon's statement; no secret-value path; validator sentences verbatim; offline via the same code (or `preview`/`test` store-free).

## Do NOT

- Do not re-validate cron/match/blueprint in the CLI; do not add any path for a secret value; do not print an env value.
- Do not fall back on a non-"no daemon" error; do not keep a local copy of write logic; do not change `aeon trigger`'s output.
