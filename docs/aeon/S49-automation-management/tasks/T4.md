# T4 · The write side: authority locks for both families, the audit, `trigger.update`, archive

**Prefix:** AN · **Rules:** AN3, AN4, AN6, AN14 · S40 AU1/AU2/AU15 · **Depends on:** T1, T2. **Adapts the S20/S40 write paths — S49's own change, listed in Notes.**

## Goal

Every write on both families is **person-only, peer-stamped and audited exactly once**; schedules get the **missing `update`**; both families get **archive/unarchive**. The engines, attendedness and outward rules do not move. This is where AU1's three locks are extended to
the S20 family.

## Files

- `aeon/internal/store/` — extend the **existing** write functions (T0 item 3's inventory) with an `actor store.Actor` parameter and a **tx-variant** that also writes the `automation_change` row: schedule add/pause/resume/fire-now and S40's create/update/enable/disable. A non-`user` actor kind is refused **before any SQL** (lock 3 in Go; the CHECK is the net). `trigger_schedule` inserts set `created_by_kind='user'`, `created_by_id=<peer uid or "cli">`. Existing signatures are kept via thin wrappers only where an existing test calls them (listed); otherwise callers move to the new ones.
- `aeon/internal/daemon/automation_write.go` — **new**: the single write service for both families (`Add, Update, Pause, Resume, FireNow, Create, UpdateEvent, Enable, Disable, Archive, Unarchive`); it is the **only** daemon file calling the store's trigger writers (T5 pins it). `FireNow` records `automation_change op='fire_now'` with the fire id **and** performs the existing fire exactly as today (attendedness/outward unchanged).
- `aeon/internal/protocol/trigger.go` / `automation.go` — the **existing handlers** now take the `*Session`, resolve the actor with `table.ActorFor` (unresolvable ⇒ `ErrAutomationNoActor`, nothing written), **refuse an `agent` actor** with S40's sentence *"triggers are written by a person; this actor is an agent"* (now for every write), and decode with `DisallowUnknownFields` (a request carrying `actor`/`createdBy`/`origin` is a shape error). **Params and results are otherwise unchanged** (compat; fixtures byte-identical except where a new refusal is added).
- `aeon/internal/protocol/automation_write.go` — **new**: `trigger.update`, `automation.archive`, `automation.unarchive`:
  - `trigger.update {id, blueprint?, cron?, timezone?, workspace?, goal?, windowStart?/windowEnd?/windowDays?, secretEnv?, clearWindow?}` → the updated `AutomationView` + `changed` + the `nextFires` preview for schedules. **Validates exactly like add** (cron via the same validator and its own words, explicit IANA zone TR6, window pairing, blueprint resolvable **and** `Analyze`-clean via the S48 source, workspace rule); `id` and `kind` are immutable; a webhook's secret is changed only by changing **`secretEnv` (a name)**, validated by the env-name grammar — no value field exists; identity, history and `created_by_*` are preserved; unchanged ⇒ `changed:false`, no audit row. Updating a **paused/archived** schedule is allowed and does **not** enable it.
  - `automation.archive {source,id,reason}`: reason 1–256 bytes required; archived already ⇒ `changed:false`; sets `archived_at` and the engine-invisible off state (T1); audit `archive`; a loop the trigger started is untouched. `automation.unarchive {source,id}`: leaves it **disabled/paused**; audit `unarchive`.
  - Every result for a state-changing call carries the **before/after** `AutomationView` and, for enable/unarchive-adjacent calls, the `health` so the caller sees what was just turned on.
- `aeon/internal/protocol/method.go` — three consts in a labelled block; `RequiresInitialize`, not `Debug`; conditional on the write service for the new ones. `errors.go` — `ErrAutomationNoActor`, `ErrAutomationRefused` (carries the validator/`Analyze` sentence verbatim). Contract chain: conformance, handshake block "S49 writes", fixtures (success + every refusal), `make protogen`.
- **`aeon/cmd/aeon/trigger.go`** — the CLI's schedule verbs call the same service with actor `{user,cli}` (the offline door) — **flags and output unchanged** (goldens); T8 owns the new verbs.

## Behaviour notes

1. **One audit row per changing write, none otherwise** (refusal, no-op, read). Summaries are fixed templates from ids and enums (`"updated schedule %s (cron %q → %q)"` is **not** allowed — it would put user text in the audit; use `"updated schedule %s (fields: cron, window)"`).
2. **Enable/fire-now/unarchive widen authority:** they require a resolved human actor and return health; the daemon does **not** require a confirm token (a socket cannot prove a human — S45 PM7's stance); the UI/CLI confirm layers (T8/T9) add the friction.
3. **The engines are untouched:** the clock/dispatcher code paths, outcomes, `StartFromTrigger`/`StartFromEvent`, cascade guard, limits and cursors are byte-identical (git diff check in Notes). **AU2 holds:** a test re-runs S40 T4's pinned-row assertion (`attended=0`, `allow_outward=0`) for schedule, webhook and event starts, and the grep on the only `Attended:`/`AllowOutward:` assignments.
4. **Archive never deletes:** `archive` then `unarchive` round-trips all columns except `archived_*`; fire history and audit remain.
5. **`created_by_id` for pre-existing schedule rows is `''` forever** (never backfilled with a guess).
6. **Order for a write:** decode strict → actor → validate (the validator's own sentence) → single tx (row + audit) → re-read the view → return; a refusal leaves nothing.
