# T6 — the forward Gantt

## Why this exists

The sketch's own framing, now literal: *"the forward Gantt is the same component S25 built pointed the
other way."* This task does not build a second Gantt component.

## Scope

**1. Reuse `S25-history`'s lane/Gantt component exactly**, feeding it roadmap items instead of loops —
history occupies the past, this occupies the future, the present is wherever a loop is actually running
(unchanged framing from both sketches).

**2. Lanes: by epic, by priority** (`design.md`'s locked decision — not by agent, a built-loop concept this
stage's items mostly don't have yet).

**3. Priority and estimate render through D2/D3's typed shapes** — `unknown` priority is visually distinct,
never a blank or implied-low; an estimate is always "min–max (basis)," never a bare figure, matching S24's
and S25's own UI precedent.

**4. Provenance (D5) is visible** — an `authored`/`triggered`/`triaged` tag on each item, the same "say
what it does not do" instinct S9's bench pages already use for unfinished capability, applied here to say
*where an item actually came from*.

## Validation

- [x] vitest: `unknown` priority renders distinctly from `known`/`assumed`, asserted on markup
- [x] vitest: an estimate renders as `min–max (basis)`; an item with no estimate yet renders an explicit
      "not estimated" state, never a blank cell
- [ ] the Gantt component imported here is the literal same one `S25-history`'s `HistoryPage.tsx` uses, not
      a copy — a call-site/import check, not eyeballed
- [ ] calls go through the generic `rpc()` bridge; no new Tauri command
