# T5 — CLI and socket

## Why this exists

The first concrete surface over `internal/roadmap`, combined because the socket methods mirror the CLI 1:1
with no independent validation of their own — unlike S24's `queue.*` (CG9 there, a deliberate write-access
departure from policy's CLI-only rule), this slice has no comparable boundary decision to make twice.

## Scope

**CLI verbs**: `aeon roadmap add --title … [--epic …] [--priority known|assumed|unknown] [--priority-label
…]` · `list [--epic …] [--status …]` · `show <id>` · `cancel <id>` · `estimate <id> --min N --max N --basis
"…"`.

**Socket methods**: `roadmap.add`, `roadmap.list`, `roadmap.show`, `roadmap.cancel`, `roadmap.estimate` —
same calls into `internal/roadmap` underneath, mirroring `S24-loop-queue`'s CG9 precedent (write-capable,
not CLI-only — a roadmap item is ordinary project content, the same trust tier as a loop's own `goal`).

**Every priority/estimate render goes through D2/D3's typed shapes** — "unknown priority" prints as the word
"unknown," never a blank, a dash, or a sort-last silently-implied-low placeholder (R2 in the brief, guarded
here first).

## Validation

- [x] `TestRoadmapSocketAndCLIProduceIdenticalRows` — same fixture, both entry points, byte-identical rows
- [x] `TestUnknownPriorityRendersHonestlyEverywhere` — a fixture with `priority_state: unknown` renders the
      word "unknown" in `list`, `show`, and both socket equivalents — no code path renders a blank instead
- [x] every socket method requires `Initialize`, matching `policy.*`/`queue.*`'s convention
