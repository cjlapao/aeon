# T3 — ideation and planning dispatch

## Why this exists

This is `design.md`'s R3 and D9 made real — and the one task where the brief's §2 correction most matters:
it would be easy to reach for a new blueprint shape out of habit. There isn't one.

**Read first:** `design.md` §2 in full (the GAP-7 correction) before writing a line. **Read second:**
`internal/loop/advance.go`'s and `continue.go`'s `missingArtifact` call sites — this task adds no code
there, it only starts a loop whose blueprint already declares `produces: [brief.md]` and watches for the
existing `done` transition.

## Scope

**1. Ideation dispatch** (`idea → ideating`): starts an ordinary loop (`loop.start`, unchanged, the existing
entry point) with a blueprint that declares `produces: [brief.md]` on its (possibly only) step. On that
loop's `loop.finished` event, if the artifact exists (the engine already refused `done` without it —
`missingArtifact`), transition the item `ideating → brief-agreed`.

**2. Planning dispatch** (`brief-agreed → planned`): dispatches `project-planner` (S13's existing handler
body, `internal/handler/bodies/project-planner.md` — read its frontmatter first: `tools: [read, write, edit,
glob, grep, todo]`, no `bash`) exactly the way S24's T5 dispatched `sizing-estimator` — a step/loop assigned
through the existing registry, nothing bespoke. On success (its handoff's `task_count` present and `plan.md`
on disk), transition `planned`.

**3. No new `produces:` kind, no new gate type, no new blueprint field.** A test greps this task's own diff
for any change to `internal/blueprint/` — there should be none.
