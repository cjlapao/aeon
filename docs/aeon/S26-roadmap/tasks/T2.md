# T2 — `internal/roadmap`: the core package

## Why this exists

Every other task calls into this package rather than touching `roadmap_item` rows directly — the same
discipline `internal/queue` (S24) established first for this project's planning-stage tables.

**Read first:** `internal/queue/transitions.go` (S24) for the exhaustiveness-test pattern this task repeats
for R1's eight values instead of S24's seven.

## Scope

**1. `Item` and `Status`** (`types.go`): the Go mirror of T1's row shape.

**2. `AllowedTransitions() map[Status][]Status`**: `idea→ideating`, `ideating→brief-agreed`,
`brief-agreed→planned`, `planned→ready`, `ready→running`, `running→done`, every non-terminal
status`→cancelled` (D7). `running` has no edge to `cancelled` — a loop in flight is the loop's own record,
not roadmap history (mirrors S24's identical rule for queue items).

**3. `IsReady(item) bool`** (design.md's R1): re-evaluates **all three** of D4's conditions at the moment of
the `planned → ready` transition attempt — brief agreed, plan exists, `priority_state != 'unknown'` — never
cached from whenever each individually became true, since a priority can be downgraded to `unknown` after a
brief was agreed (a re-triaged item, say) and a stale cached `ready` would miss that.

**4. Store CRUD**: `Create`, `List` (filterable by `epic`/`priority_state`/`status`), `Transition` (refuses
anything not in the table, a discriminated result per DB19), `Cancel` (sets `cancelled`, never deletes the
row — the same "never silently lose a record" pattern S24's `Remove` and S25's archive-merge both follow).

## Validation

- [x] `TestTransitionTableIsExhaustiveAndClosed` — every listed edge succeeds, every unlisted pair across
      the full 8×8 cross product is refused
- [x] `TestReadyRequiresAllThreeConditionsAtTransitionTime` — a `planned` item whose priority is downgraded
      to `unknown` after planning cannot transition to `ready`
- [x] `TestCancelFromAnyNonTerminalState` — every non-terminal status can reach `cancelled`; `running` and
      `done` cannot
- [x] tests never point at the real store

## Notes (2026-10-29)

**What exists.** `aeon/internal/roadmap/` — `types.go` (closed vocabularies `Statuses()`/
`ValidStatus`, `PriorityState`, `Provenance`, `Estimate`, `Item`, `ItemFromRow`), `transitions.go`
(`AllowedTransitions`, `ValidateTransition` → `TransitionResult{OK,Reason,Legal}`, `IsReady`,
`SortedTargets`/`LegalSentence`), `store.go` (the door: `New(s)`, `Refusal{Reason,Moved,Legal}`,
`Create`/`List`/`Show`/`Count`/`Transition`/`Cancel`/`SetEstimate`/`SetPriority`/`SetArtifacts`/
`RecordLoop`). The door wraps `internal/store`'s claimed-FROM writers; SQL lives only there (the
door split the queue follows). Tests: `transitions_test.go` + `store_test.go`, 11 tests, all through
`store.Open` on `t.TempDir()` — the real store is never pointed at.

**Deviations, each decided against a stronger rule.**
1. `IsReady` returns `(bool, string)`, not `bool` — the house refusal rule ("a refusal names the
   reason AND the thing refused") applies at the door and at `roadmap.show`, so the sentence names
   WHICH of D4's three conditions failed.
2. **The table has 11 edges, not 12** — measured: 5 forward (`idea→ideating→brief-agreed→planned→
   ready→running`) + `running→done` + 5 off-ramps (one from each pre-loop rung). The test asserts
   `edges == 11` and the full 8×8 cross product otherwise refused.
3. `TestCancelFromAnyNonTerminalState` implements the brief's reading (D7): cancel is legal from the
   **five pre-loop rungs**; `running` refuses (a loop in flight is the loop's own record — T4 and
   `loop` verbs own it), `done` and `cancelled` are terminal; the `cancelled → cancelled`
   self-transition is legal as the machine's own idempotence law, which the test exempts explicitly.
4. Transitions are claimed-FROM (`WHERE id = ? AND status = ?`), so a lost race returns
   `Refusal.Moved` — a fact of concurrency, not a legal-target refusal, and `roadmapRefusal` on the
   wire keeps the three parts distinct.
