# T3 · `config.Store`: live reads, the one write boundary, precedence

**Prefix:** CS · **Rules:** CS1, CS2, CS4, CS5, CS7, CS8, CS10 (view semantics), CS11 · **Depends on:** T1, T2.

## Goal

The accessor itself. `config.Store` composes T2's registry with a `Repo` seam (which T1's SQL will sit behind via
T4's adapter), the process environment, and a clock, and offers `Get`, `List`, `Set`, `Unset`, `History`, plus the
read-only `Reader` consumers take. This task is tested **entirely against an in-memory fake `Repo`** — no SQLite —
so it is fast and hermetic; T4 proves the same contract against the real store. It also lands CS1's
"the five layers are untouched" guard.

## Files to create / modify

All **new**, in `aeon/internal/config/` (no existing file edited):

- `settings_store.go` — `Repo`, `Store`, `NewStore`, `Reader`, the `View`/`Event` result types, all methods.
- `settings_store_test.go` — tests below, with an in-test `fakeRepo`.
- `settings_untouched_test.go` — the CS1 byte-pin guard.

## The seam and the constructor

```go
// Repo is everything config.Store needs from storage. It holds no domain rule (CS2); internal/store implements the
// SQL half (T1) and internal/daemon bridges it (T4).
type Repo interface {
	SettingGet(ctx context.Context, key string) (RepoRow, bool, error)
	SettingList(ctx context.Context) ([]RepoRow, error)
	// SettingPut upserts the row and appends ev in ONE transaction; the repo fills ev.OldValue from the row it replaced.
	SettingPut(ctx context.Context, row RepoRow, ev RepoEvent) error
	SettingDelete(ctx context.Context, key string, ev RepoEvent) (existed bool, err error)
	SettingEventList(ctx context.Context, key string, limit int) ([]RepoEvent, error)
}

type RepoRow   struct{ Key, Value, UpdatedAt, UpdatedBy string }
type RepoEvent struct {
	ID int64; Key, Op string; OldValue, NewValue *string
	Sensitive bool; ShadowedBy, Actor, OccurredAt string
}

type Options struct {
	Registry *Registry                       // nil → DefaultRegistry()
	LookupEnv func(string) (string, bool)    // nil → os.LookupEnv   (injected so tests never touch the real environment)
	Now      func() time.Time                // nil → time.Now().UTC
}

func NewStore(repo Repo, opt Options) *Store     // panics on a nil repo: a Store with nowhere to read is a wiring bug (DB19: programmer error, not data)
```

## The view a read returns (CS4, CS10)

```go
type View struct {
	Setting                     // the declaration: Key, Area, Type, Default, Description, Sensitive, bounds, EnumValues
	Value         string        // EFFECTIVE value, canonical form
	Source        Source        // "default" | "database" | "environment"   (type name collides with creds.go's Source — use SettingSource)
	Stored        *string       // what the table holds, nil when no row
	ShadowedBy    string        // the env var name when the environment is in force AND a row exists or a write just happened; "" otherwise
	EnvInvalid    string        // env var name whose value failed validation and was NOT used; "" otherwise
	StoredInvalid bool          // the row's value fails the CURRENT declaration; the effective value is then Default
	UpdatedAt, UpdatedBy string  // from the row; "" when none
}
```

**Name note:** `creds.go` already exports `type Source string` (`SourceEnv`, `SourceFile`). The new source type is
named `SettingSource` with constants `SettingDefault`, `SettingDatabase`, `SettingEnvironment` to avoid editing
or shadowing the existing one.

### The resolution algorithm (one function, `resolve`, used by every read and every write result)

1. Look the key up; absent → `ErrSettingUnknown` (with `Nearest`). (`Get`/`Set`/`Unset` all do this first.)
2. `LookupEnv(EnvName(key))`. If set **and non-empty-after-nothing-trimmed**: `ParseValue` it. Valid → `Value` =
   that, `Source = environment`. Invalid → record `EnvInvalid = <var name>`, **do not use it**, fall through.
   (An env var set to the empty string counts as set; for bool/int/enum it fails validation and is reported as
   `EnvInvalid` — an exported-but-empty variable is a common mistake and must be loud, not ignored.)
3. Else read the row. Absent → `Value = Default`, `Source = default`, `Stored = nil`.
4. Row present → `ParseValue(row.Value)`. Valid → `Value` = canonical, `Source = database`, `Stored = &value`.
   Invalid → `StoredInvalid = true`, `Stored = &raw`, `Value = Default`, `Source = default`.
5. `ShadowedBy` is set when `Source == environment` and a row exists (`Stored != nil`) — "your saved value is
   being overridden".

A repo error during a read is **returned**, never swallowed into a default: a store failure must not make a
`Sensitive` guard silently read as "unset → default" while the real stored value is the permissive one. (The
default is restrictive by CS8 convention, but "we could not read it" and "it is unset" are different facts, P31.)

## The write boundary (CS8)

```go
func (s *Store) Set(ctx context.Context, key, raw, actor string) (View, bool, error)   // changed bool
func (s *Store) Unset(ctx context.Context, key, actor string) (View, bool, error)
func (s *Store) Get(ctx context.Context, key string) (View, error)
func (s *Store) List(ctx context.Context, area string) ([]View, error)                 // declared keys only, sorted; area "" = all
func (s *Store) History(ctx context.Context, key string, limit int) ([]Event, error)
```

`Set`, in order, **each step a refusal before the next runs**:

1. `actor` must be non-empty and ≤ 256 bytes (an unattributed write is refused — the audit column is NOT NULL and
   "unknown" is not an honest actor). T4/T5 pass what T0 item 3.3 decided.
2. Unknown key → `ErrSettingUnknown`.
3. **Defensive credential-name re-check** (CS5): `isCredentialName(key)` → `ErrSettingNotWritable`, even though
   a credential-named key cannot have been declared. The registry is a package global a test could mutate; the
   write path does not trust it for the one rule C4 calls non-negotiable.
4. `ParseValue(raw)` → canonical, or `ErrSettingInvalidValue`.
5. Read the current row (live — see CS7). If a row exists and `row.Value == canonical` → return the current `View`,
   `changed=false`, **write nothing, no event**.
6. Build the event (`op=set`, `new_value=canonical`, `sensitive = decl.Sensitive`, `shadowed_by = "env"` iff the
   environment currently overrides the key per `resolve` step 2, `actor`, `occurred_at = Now()`), call
   `repo.SettingPut` (one transaction, atomic with its event), then **re-`resolve` and return the fresh `View`**
   with `changed=true` — the caller sees what is *now* in force, not what it just sent.

`Unset` mirrors it: steps 1–3, then `repo.SettingDelete`; `existed=false` → `changed=false`, no event. On a
delete the event carries the old value the repo read.

**No cache, no memo, no "last known good", no goroutine, no timer** anywhere in `Store` (CS7) — two tests hold it: reflection
asserts the struct's fields are exactly `repo, reg, lookupEnv, now` (no map, no mutex, no timestamp), and a source
grep over `settings_store.go` finds no `sync.`, `time.AfterFunc` or `go func`.

## `Reader` (CS11)

```go
type Reader interface {
	Bool(ctx context.Context, key string) (bool, error)
	Int(ctx context.Context, key string) (int, error)
	String(ctx context.Context, key string) (string, error)
	Enum(ctx context.Context, key string) (string, error)
}
```

`*Store` implements it by `Get` → type check → convert. A key declared with another type returns
`ErrSettingInvalidValue`-shaped refusal? **No** — it is a programmer error, not user data: return a distinct
`ErrSettingWrongType{Key, Declared, Asked}` defined in this file's error block (three-part, `settings_errors.go`
is T2's file and is not edited — define it at the top of `settings_store.go`). A `StoredInvalid` / `EnvInvalid`
read still returns the effective value (the restrictive default) **and a nil error**; the loud signal is in
`Get`'s `View`, not in a consumer's hot path.

### `settings_untouched_test.go` — CS1 made mechanical

`TestFiveLayerFilesAreUntouched` computes SHA-256 of `layers.go`, `validate.go`, `creds.go`, `config_test.go`,
`creds_test.go` (read via `os.ReadFile` relative to the package dir) and compares each to the digest **T0
recorded**, embedded as constants with a comment giving the commit they were taken at. Failure message: "the five
layers are CS1's untouched contract — if you meant to change one, this slice's pin is the thing to update, in a
slice that says why". Also `TestNoSettingsFileImportsStore` parses every `settings*.go` import block and fails on
`internal/store`, `database/sql`, or `gorm` (CS2).

## Definition of done

- [ ] `Repo`, `Store`, `NewStore`, `Reader`, `View`, the three errors' new member, all five operations.
- [ ] Precedence environment → database → default, with `Source`, `Stored`, `ShadowedBy`, `EnvInvalid`,
      `StoredInvalid` all populated per the algorithm.
- [ ] One write boundary; no-op writes record nothing; every changing write records exactly one event.
- [ ] No cache of any kind (structural test + call-count test).
- [ ] The five-layer pin test and the no-store-import test green.
- [ ] `-race` green. Existing `internal/config` tests unchanged and green.

## Do NOT

- Do not edit `layers.go`, `validate.go`, `creds.go`, or their tests, and do not add a `Layer` constant.
- Do not import `internal/store`, `database/sql` or `gorm` in any `settings*.go` file.
- Do not cache, memoise, debounce, or "optimise" reads — a future reader who adds one breaks CS7 and the
  slice's first acceptance criterion.
- Do not turn a repo read error into a default, ever (P31).
- Do not put a stored value in any error other than `ErrSettingInvalidValue`'s truncated `Got` (the value the
  caller just offered). Errors from a failed read name the key and the cause, never the stored value.
- Do not add a flag path (`--set key=value`) — CS4: flags are not supported for registry keys.
