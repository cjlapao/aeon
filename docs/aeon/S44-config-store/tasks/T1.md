# T1 · The `setting` and `setting_event` tables, and the store's SQL half

**Prefix:** CS · **Rules:** CS2, CS3, CS6, CS8 · **Depends on:** T0 (trigger-parsing answer, item 3.1; `actor`
answer, item 3.3). Parallel-safe with T2 — no shared file.

## Goal

One forward-only migration file creating the two tables, and `internal/store/settings.go` holding **only** the SQL
(invariant I2). The key/value table is deliberately schema-less in its *vocabulary* (CS3: typing happens in the
write boundary), but its **shape** is constrained hard enough that a caller who skipped the boundary gets a CHECK
error — the same "database net under the boundary's refusal" division `policy` documents in
`internal/store/policy.go`'s header.

## Files to create / modify

- `aeon/internal/store/migrations/<14-digit>_settings.sql` — **new**. Name from `date +%Y%m%d%H%M%S` at
  creation time, **never hand-picked**; it must sort after the newest file T0 recorded. First line is a `-- `
  comment that becomes the `Description`; it must say, in one sentence: key/value text with typing enforced in
  the Go write boundary (CS3), global scope only with no scope column on purpose (CS6), append-only audit (CS8).
  Per the README, **no edit to `schema.go`**.
- `aeon/internal/store/settings.go` — **new**. SQL accessors only, no domain rule.
- `aeon/internal/store/settings_test.go` — **new**, tests below.
- `aeon/internal/store/store_test.go` — **not edited**; `TestNoSQLLivesOutsideTheStore` must pass unchanged
  (this file is its allowed home for the new SQL).

## The DDL

```sql
-- S44 T1: the daemon-wide settings store — key/value TEXT with typing enforced by the Go write boundary (config.Store, CS3), global scope only on purpose (CS6: a scope column nothing fills is the TL5 mistake), and an append-only audit table (CS8) whose UPDATE/DELETE are refused by trigger. No credential is ever admitted: the registry refuses credential-shaped key names (CS5), so the audit table may hold values in clear.
CREATE TABLE setting (
  key        TEXT PRIMARY KEY
             CHECK (length(key) BETWEEN 3 AND 128
                    AND key NOT GLOB '*[^A-Za-z0-9.]*'
                    AND key LIKE '%.%' AND key NOT LIKE '.%' AND key NOT LIKE '%.' AND key NOT LIKE '%..%'),
  value      TEXT NOT NULL CHECK (length(value) <= 4096),
  updated_at TEXT NOT NULL,
  updated_by TEXT NOT NULL CHECK (length(updated_by) BETWEEN 1 AND 256)
);

CREATE TABLE setting_event (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  key         TEXT NOT NULL,
  op          TEXT NOT NULL CHECK (op IN ('set','unset')),
  old_value   TEXT,                       -- NULL = there was no stored row (the default was in force)
  new_value   TEXT,                       -- NULL on 'unset'
  sensitive   INTEGER NOT NULL CHECK (sensitive IN (0,1)),
  shadowed_by TEXT CHECK (shadowed_by IS NULL OR shadowed_by = 'env'),
  actor       TEXT NOT NULL CHECK (length(actor) BETWEEN 1 AND 256),
  occurred_at TEXT NOT NULL,
  CHECK ((op = 'set' AND new_value IS NOT NULL) OR (op = 'unset' AND new_value IS NULL))
);
CREATE INDEX idx_setting_event_key ON setting_event (key, id);

CREATE TRIGGER setting_event_no_update BEFORE UPDATE ON setting_event
BEGIN SELECT RAISE(ABORT, 'setting_event is append-only: an audit row is never rewritten (S44 CS8)'); END;
CREATE TRIGGER setting_event_no_delete BEFORE DELETE ON setting_event
BEGIN SELECT RAISE(ABORT, 'setting_event is append-only: an audit row is never deleted (S44 CS8)'); END;
```

Design notes the SQL cannot say:

- **No FK from `setting_event.key` to `setting.key`.** An `unset` deletes the `setting` row; the audit history of
  that key must outlive it. An FK (with or without cascade) would either block the delete or erase the trail.
- The `key` CHECK is a **net**, not the validator. The registry (T2) owns the real key grammar and the good error
  message; the CHECK only keeps a skip-the-boundary caller from writing `''`, a key with spaces, or `a..b`.
  Both layers must agree that `agents.allowUnsignedImport` is valid and `agents..x`, `.x`, `x.` and `a b.c` are not
  (a test pins the two against each other).
- `value` is capped at 4096 to match the registry's default string cap; a string key with a smaller `MaxLen`
  enforces its own cap in Go.
- If T0 item 3.1 found the migration parser **cannot carry a trigger body**, delete the two `CREATE TRIGGER`
  statements, move the append-only rule into `SettingEventInsert`'s package (no `Update`/`Delete` function exists),
  add `TestSettingEventHasNoUpdateOrDeletePath` (greps the package for `UPDATE setting_event`/`DELETE FROM
  setting_event` — must find none), and record the downgrade from DB-enforced to code-enforced in Notes and in
  the migration's own description line.

## Store accessors — `internal/store/settings.go`

Names follow `PolicyAdd`/`PolicyListAll`. Types are plain structs in this package; the daemon adapter (T4) maps
them to `config.Repo`'s types, so this package imports nothing from `config`.

```go
// SettingRow is one stored value. UpdatedAt is RFC3339 UTC, written by the caller (the store takes no clock).
type SettingRow struct {
	Key, Value, UpdatedAt, UpdatedBy string
}

// SettingEvent is one audit row. OldValue/NewValue are pointers: nil is SQL NULL, and NULL means something
// (no row existed / unset), never "".
type SettingEvent struct {
	ID          int64
	Key, Op     string
	OldValue    *string
	NewValue    *string
	Sensitive   bool
	ShadowedBy  string // "" or "env"
	Actor       string
	OccurredAt  string
}

func (s *Store) SettingGet(ctx context.Context, key string) (SettingRow, bool, error)
func (s *Store) SettingList(ctx context.Context) ([]SettingRow, error)            // ordered by key
// SettingPut upserts the row AND appends ev in ONE transaction. ev.Op must be "set"; ev.Key must equal row.Key;
// ev.OldValue is filled by Put from the row it replaced (the caller does not race a read against the write).
func (s *Store) SettingPut(ctx context.Context, row SettingRow, ev SettingEvent) error
// SettingDelete removes the row and appends ev ("unset") in one transaction; existed=false writes NO event.
func (s *Store) SettingDelete(ctx context.Context, key string, ev SettingEvent) (existed bool, err error)
// SettingEventList: newest first; key=="" is every key; limit is clamped to [1,500], default 50.
func (s *Store) SettingEventList(ctx context.Context, key string, limit int) ([]SettingEvent, error)
```

Rules for the SQL: statements are parameterised (no string concatenation of `key`/`value`); `SettingPut` reads
the old value and writes both rows inside the same `BEGIN IMMEDIATE`-style transaction the rest of the store
uses for read-then-write (VERIFY the helper name — `grep -n 'func (s \*Store) .*[Tt]x' aeon/internal/store/*.go`
— and use it; do not open a second transaction idiom); a `SettingGet` of an absent key is `(zero, false, nil)`,
never an error (DB19).

Use the existing in-package store test helpers (`helpers_test.go`) to open a fresh migrated store.

| `TestSettingKeyCheckAgreesWithTheGoGrammar` | `INSERT` of `agents.allowUnsignedImport` succeeds; of `''`, `a`, `a b.c`, `.x`, `x.`, `a..b`, a 129-char key, `agents.x-y` each fails the CHECK | the SQL net and the intended grammar disagree |
| `TestSettingPutThenGetRoundTrips` | Put then Get returns the same Key/Value/UpdatedAt/UpdatedBy | accessor mapping wrong |
| `TestSettingPutOverwriteRecordsOldValue` | second Put on the same key leaves one `setting` row and one extra `setting_event` whose `old_value` equals the first value and `new_value` the second | upsert duplicated, or old value read outside the transaction |

| `TestSettingValueCap` | a 4097-byte value is refused by the CHECK | the net is missing |

## Do NOT

- Do not edit `schema.go` or any shipped migration (forward-only; the README's one rule).
- Do not add a `scope` column (CS6), a `type` column, or a `Sensitive` column on `setting` — typing and
  sensitivity are registry facts, not row facts (CS3, CS8). The event row's `sensitive` is a **historical
  record of what the registry said at write time**, not a live join.
- Do not put a domain rule in this file (no key grammar beyond the CHECK net, no "is this key declared").
- Do not add `FOREIGN KEY` from `setting_event` to `setting`.
- Do not import `internal/config` here.
