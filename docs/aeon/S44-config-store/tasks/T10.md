# T10 · Adopt S43's unsigned-import setting onto the config store

**Prefix:** CS · **Rules:** CS3, CS4, CS8, CS11, **CS15** · **Depends on:** T9 **and S43 merged to `main`**.

## Why this task exists

S43 is being built by another agent and **cannot be changed from here** (operator ruling, CS15). S43 will implement
`agents.allowUnsignedImport` however its own T0/T5 decide. Anything that has to change in S43's code so that
setting lives on this store — a read-site switch, a retired write path, a data migration — is **S44's work, done
here, after S43 has merged, in S44's own change.** This is a *refactor of already-merged S43 code under S44's name*,
not a coordination request to S43. Until this task runs, S43's setting works exactly as S43 built it.

If S43 never merges, or merges without the setting, or builds it in a shape that cannot move without changing its
behaviour (step 5), this task is closed **"not applicable"** with the reason in Notes. S44's mechanism (T0–T9) is
unaffected either way.

## Step 3 — The refactor (files are determined by step 1; the shape is fixed)

- `aeon/internal/config/settings_decl_agents.go` — **new, S44-owned**. One `mustDeclare(Setting{Key:
  "agents.allowUnsignedImport", Area: "agents", Type: TypeBool, Default: "false", Sensitive: true, Description:
  "<what it lets in, and that the default refuses an unsigned agent card — at least 40 characters per T2's rule>"})`.
  Use **S43's exact key spelling** if it already chose one that fits the grammar; if it chose a different spelling,
  prefer S43's and record it (the key is part of its public behaviour).
- **S43's read site(s)** — change **only** how the boolean is obtained: take a `config.Reader` (or the func seam
  S43 already used, backed by `Reader.Bool`) and call it **at each import call**, never at construction (CS7/CS11).
  No other line of S43's import, signature or card code changes.
- **S43's wiring** — the serve wiring passes the one shared `*config.Store` (T4) to wherever S43 built its reader.
- **S43's bespoke write path** — if S43 gave the setting its own socket method, CLI verb or UI control: **retire it
  in favour of `settings.set` and the generic panel**, in this order so nothing is ever unreachable: (1) the
  generic panel and `settings.*` already exist (T5/T8), (2) point S43's own control, if any, at the same methods or
  remove it, (3) remove the bespoke method last. A removed method is a protocol change: update the conformance
  fixtures, the handshake want-list and `make protogen` exactly as T5 did, and record the removal. **If another
  caller (a script, a test fixture) depends on the old method, keep it as a thin forwarder to `settings.set` for
  this release and say so** — retirement is a later, announced step, not a surprise.
- `aeon/internal/config/settings_test.go` — flip `TestDefaultRegistryIsEmptyInProduction` to assert the registry
  contains **exactly** `agents.allowUnsignedImport` (T2 left the comment saying this task does it).

## Step 4 — Carry the stored value across (only if step 1 found stored data)

A new migration **file** `internal/store/migrations/<14-digit>_s44_adopt_unsigned_import.sql` (timestamp from
`date`, after S43's newest): `INSERT INTO setting (key, value, updated_at, updated_by) SELECT … FROM <S43's
storage> WHERE <value differs from the default>`, with `updated_by = 's44-adoption'`, plus one matching
`setting_event` row (`op='set'`, `old_value` NULL, `actor='s44-adoption'`, `sensitive=1`). It **inserts nothing when
S43's stored value equals the default** (a no-op adoption writes no audit row — CS8) and **never overwrites** an
existing `setting` row (`INSERT … WHERE NOT EXISTS`). Forward-only, immutable once merged.
