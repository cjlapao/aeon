## The interface — `internal/protocol/settings.go`

The same "local interface, store types in signatures" pattern as `TelemetryStore` (S33 T8), except this one
carries `config` types and so the protocol package depends on `internal/config` for the **value types only**
(`config.View`, `config.Event`) — **VERIFY first that `internal/config` imports nothing that cycles back to
`internal/protocol`** (it imports only `internal/errs`, fact 2). If that import is rejected by an existing
boundary test (`agent_import_boundary_test.go` pins some protocol import edges), define wire-only mirror structs in
`protocol` and map in the daemon adapter instead — record which in Notes.

```go
type SettingsService interface {
	List(ctx context.Context, area string) ([]SettingView, error)
	Get(ctx context.Context, key string) (SettingView, error)
	Set(ctx context.Context, key, value, actor string) (SettingView, bool, error)
	Unset(ctx context.Context, key, actor string) (SettingView, bool, error)
	History(ctx context.Context, key string, limit int) ([]SettingEventView, error)
}
```

(Wire types mirror design CS10 exactly: `SettingView`, `SettingEventView`. Nullable strings are `*string` with
`json:"…"` **without** `omitempty` for the fields whose `null` is meaningful — `stored`, `shadowedBy`,
`envInvalid`, `updatedAt`, `updatedBy` — so the generated TypeScript says `string | null`, not an optional field;
a client must be able to tell "no row" from "field omitted".)

## Params and handlers

| Method | Params (JSON) | Validation, in order | Result |
| --- | --- | --- | --- |
| `settings.list` | `{ "area"?: string }` | strict decode (`decodeParams` — unknown fields refused, the transport only checks the envelope) | `{ "settings": SettingView[] }` |
| `settings.get` | `{ "key": string }` | `key` required non-empty → `ErrBadParams`; undeclared → `ErrSettingUnknown` | `{ "setting": SettingView }` |
| `settings.set` | `{ "key": string, "value": string }` | `key` required; `value` **present** (a missing `value` is `ErrBadParams`, an empty string is a real value for a string key); undeclared → `ErrSettingUnknown`; bad value → `ErrSettingInvalidValue` | `{ "setting": SettingView, "changed": bool }` |
| `settings.unset` | `{ "key": string }` | as `get` | `{ "setting": SettingView, "changed": bool }` |
| `settings.history` | `{ "key"?: string, "limit"?: int }` | `limit` < 0 → `ErrBadParams`; otherwise clamped by the service (default 50, max 500); an undeclared `key` is **allowed** (history of a removed declaration stays readable — T3) | `{ "events": SettingEventView[] }` |

**Shape errors vs domain refusals** (the `queue.settings` rule, fact 4): a malformed request is `ErrBadParams`,
decided *before* the service is touched; a request about a key that does not exist or a value that is not allowed
is the typed domain error above. `value` for `settings.set` is **a JSON string always** — a JSON `true` or `3` is
`ErrBadParams` ("send the canonical text form, e.g. \"true\""), because accepting two encodings would let the wire
and the table disagree about what the canonical spelling is (CS3/CS10).

The handlers take the actor from the `table.ActorFor` seam (kernel peer identity, T0 item 3.3 — the same stamp
S35's proposals and S38's records use) — **never from params**; an unresolvable peer refuses the write. A caller cannot name
who it is.

The `SettingView.value` is always the **effective** value; `stored`, `source`, `shadowedBy`, `envInvalid`,
`storedInvalid` come straight from `config.View` (T3) — the handler adds no logic, only mapping. A handler that
re-derived precedence would be a second implementation (P25's "one protocol, N projections" rule).

### Deviations (recorded, not silent)

- **The interface returns `config.View`/`config.Event`, not `SettingView` (the spec's T5.md line 52–58).** The spec's literal interface returns `SettingView`, but T4's `NewSettings` returns `*config.Store` directly, so `*config.Store` must satisfy the interface — and `*config.Store`'s methods return `config.View`/`config.Event`, not `SettingView`. The handler is therefore a thin `config.View→SettingView` map (no logic), exactly the "map config.View only" the spec's line 87–88 requires; the daemon adapter (`settingsService`) is a nil-guard, not a mapping adapter. Following sub-option (B). Recorded as a deviation from the spec's literal interface.
- **An unknown field in params is IGNORED, not refused (`ErrBadParams`).** The package ignores unknown fields (T3 / D3, asserted by `TestNothingCallsDisallowUnknownFields` + the conformance round-trip), so `{key, bogus}` succeeds with `bogus` dropped, not refused. The task's literal "unknown field refused" cannot be honored without breaking the package's own invariant; honored instead by ignoring.
- **The actor comes from the session, never the params (CS8).** The handler reads `t.ActorFor` (the connection's actor), so a params `actor` is ignored; a sensitive value travels to the wire as the event's, never a forged one.
