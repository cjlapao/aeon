## The migration drill

The slice adds one migration file and one pair of tables, so the drill is short but must be **run**, not assumed:

1. **Fresh apply:** a new temp store → both tables, the index and the two triggers exist (`pragma_table_info`,
   `sqlite_master`).
2. **Upgrade apply:** take a store file created at the **commit before this slice's migration** (check out the
   parent commit's binary, or build a fixture by applying `Migrations()` minus the last entry) → open with the
   new binary → migration applies, nothing else changes (`SELECT count(*)` on three unrelated tables before/after).
3. **Idempotent re-open:** open the upgraded store again → no second apply, ledger has one row for this file.
4. **Rollback is not offered** (forward-only): record that explicitly; the only "undo" is a new migration.
5. **The ledger name check:** `aeon db info` lists the migration with the `Description` from the file's first
   comment line (VERIFY the subcommand output).
