# T11 · The CLI: `loop stop|resume|cancel|raise|requests|dismiss`, `budget`, `watchdog`

**Prefix:** LC · **Shape:** P5 (client half; deviation recorded) · **Rules:** LC22 · standing rule 1 · **Depends on:** T5, T8, T9. Parallel-safe with T10.

## Goal

Everything the daemon can do for loop control, budgets and the watchdog is reachable from the CLI as a thin client — and the existing rule-1 gap (`step stop|continue` have socket methods and UI but **no CLI verb**) is closed. The CLI re-validates nothing.

## `--yes` and the confirmation digest

`--yes` is a **seatbelt**, not a security control: for verbs that loosen a guard or cannot be undone (`cancel`, `raise`, `budget remove`, `budget set` that raises/disables, `watchdog disable|remove`), the CLI first calls the dry-run, **prints the daemon's statement**, and only then sends the digest. Without `--yes` it prints the statement and exits non-zero. No flag, stdin or prompt accepts a secret (there is none in this slice).

## No offline fallback (deviation from P5, recorded)

Stop/resume/cancel/raise/budget/watchdog act on a **running** daemon (a stopped daemon has nothing to stop and applies no budget). With no daemon: the fixed sentence — *"no daemon is running — there is nothing to stop"* (loop verbs) / *"budgets and watchdog rules are applied by a running daemon — start it with `aeon serve`"* — and a non-zero exit. A dial failure other than "nobody is home" refuses, never falls back (the S45 T8 rule). No verb here opens the store (`TestCLIControlVerbsNeverImportStore`, a `go/parser` test).
