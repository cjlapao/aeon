# T2 · Storage: `loop_control_event`, `loop_control_request`, store functions

**Prefix:** LC · **Shape:** P3 · **Rules:** LC2, LC4, LC10, LC15, LC21 · **Depends on:** T1.

## Goal

The two tables the control core and the agent request path write, the store functions that move loop state by **compare-and-set** in one transaction, and nothing else. No loop-table change.

## Schema

```sql
CREATE TABLE loop_control_event (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  loop_id     TEXT NOT NULL,                 -- no FK: history outlives the loop row (P3)
  at          TEXT NOT NULL,
  kind        TEXT NOT NULL CHECK (kind IN ('stop','resume','cancel','raise','cap_hit','watchdog','request','dismiss')),
  actor_kind  TEXT NOT NULL CHECK (actor_kind IN ('user','cli','system','agent')),
  actor_id    TEXT NOT NULL DEFAULT '',      -- peer uid / 'watchdog' / 'budget' / agent slug (never user text)
  step_id     INTEGER,
  rule_id     TEXT NOT NULL DEFAULT '',      -- watchdog rule or budget id, ids only
  reason      TEXT NOT NULL DEFAULT '' CHECK (length(reason) <= 512),   -- person-authored, own column, never in a summary
  detail      TEXT NOT NULL DEFAULT '{}'     -- JSON of enums/numbers only (closed keys, validated in Go)
);
CREATE INDEX idx_loop_control_event_loop ON loop_control_event (loop_id, id);
-- append-only by trigger (P3):
CREATE TRIGGER loop_control_event_no_update BEFORE UPDATE ON loop_control_event BEGIN SELECT RAISE(ABORT,'loop_control_event is append-only'); END;
CREATE TRIGGER loop_control_event_no_delete BEFORE DELETE ON loop_control_event BEGIN SELECT RAISE(ABORT,'loop_control_event is append-only'); END;

CREATE TABLE loop_control_request (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  loop_id      TEXT NOT NULL,
  requested_at TEXT NOT NULL,
  by_agent     TEXT NOT NULL,                 -- slug stamped by the daemon (S43), never from params
  by_step_id   INTEGER,
  reason       TEXT NOT NULL CHECK (length(reason) BETWEEN 1 AND 512),
  status       TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open','honored','dismissed')),
  decided_at   TEXT,
  decided_by   TEXT NOT NULL DEFAULT ''
);
CREATE INDEX idx_loop_control_request_open ON loop_control_request (loop_id, status);
```

`loop_control_request` is mutable only in `status/decided_*` (one transition `open → honored|dismissed`, enforced by a trigger that refuses any other update and any delete).

## Store functions (each one transaction, each audited with one event row **only when it changes state**)

- `ParkLoopStopped(id, actor, reason) (Parked, error)` — `UPDATE loop SET status='waiting' … WHERE id=? AND status='running'`; also rewrites `loop_blueprint.runtime_json` (`LastReason="stopped"`, `StepStates` for a parked step) so the pinned state and the row agree — **reuse the engine's `save` helper through a store-level function T0 names**, never hand-edit JSON. `Parked{Changed bool, Status string}`: `Changed:false` (lost race / not running) writes **no** event.
- `ResumeLoop(id, actor)` — CAS `waiting`(stopped)|`blocked`(stuck) → `running`; refuses otherwise with a typed `ControlRefusal{Kind, Detail}` (DB19: `error` is for infrastructure).
- `CancelLoop(id, actor, reason)` — sets the aborted flag in runtime JSON, clears position, returns the state for the engine's `endStatus/emitIfOver` path (T3) — the **store does not write `aborted` itself** (one-writer rule, LC4).
- `AddControlRequest(loopID, agent, stepID, reason)` with the limits (5 open per loop, 20 per agent; refusals are `ControlRefusal{Kind:"request-limit"}` with the count) and `DecideControlRequest(id, status, by)`; `ListControlRequests(filter)`; `ListControlEvents(loopID, limit)`.
- `AppendControlEvent(tx, …)` shared by the above; `detail` keys validated against a closed set.
