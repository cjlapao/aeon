# T9 · The watchdog: rules, seed set, service, actions

**Prefix:** LC · **Shape:** P3, P4, P8 · **Rules:** LC1, LC17, LC18, LC20 · standing rule 6 · **Depends on:** T3, T5; **S43-extra T3** (the seed engine).

## Goal

A daemon service turns "a running loop that is not progressing" into a notification, a stop (attended) or a block (unattended), driven by **records** an operator can list, edit and disable, shipped as a seeded default set. It never touches a loop that is legitimately waiting on a person, and it never retries or re-dispatches anything.

## Files

- `aeon/internal/store/migrations/<timestamp>_watchdog.sql` — **new**:
  ```sql
  CREATE TABLE watchdog_rule (
    id         TEXT PRIMARY KEY,
    scope      TEXT NOT NULL CHECK (scope IN ('workspace','component')),
    subject_id TEXT NOT NULL,                       -- 'workspace' or a component id (a root's rule covers its tree)
    signal     TEXT NOT NULL CHECK (signal IN ('no-activity','same-position','repeat-block-reason','step-over-deadline')),
    threshold  INTEGER NOT NULL CHECK (threshold >= 0),   -- ms for time signals, a count otherwise; unit is the signal's (watchdog.vocabulary)
    action     TEXT NOT NULL CHECK (action IN ('notify','stop','block')),
    enabled    INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
    origin     TEXT NOT NULL DEFAULT 'user' CHECK (origin IN ('system','user')),
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
    UNIQUE (scope, subject_id, signal, action, threshold)
  );
  ```
  Audit rows for rule changes use `loop_control_event`-style append-only `watchdog_event` (create/change/remove/disable; actor; ids only) — added in this migration.
- `aeon/internal/watchdog/` — **new pure package**: `Signal`, `Rule`, `Observation{LoopID, Status, Attended, LastActivityAt, Position, PositionDispatches, LastReasonHash, ReasonRepeats, StepRunningSince, StepDeadline}`, `Evaluate(rules, obs, now) []Firing` (pure, table-tested), `Episode` identity so a firing is **once per (loop, rule, episode)** and a loop that makes progress resets its episode.
- `aeon/internal/daemon/watchdog.go` — **new** service: a ticker (constant 30 s ± jitter, a named constant, not a setting) that reads `running` loops, builds observations, evaluates, and acts: `notify` ⇒ event `watchdog.fired` + `loop_control_event{watchdog}`; `stop` (attended) / `block` (unattended, `BlockedReason{Kind:"stuck"}`) ⇒ the **T2 CAS functions** with actor `{system,watchdog}` (never `user`); an attended loop's `block` rule is applied as `stop` and vice versa per LC17. **Only `status='running'` loops are observed** (a waiting/blocked/idle loop is never "stuck"). The service starts after `StartLoops` and stops with the daemon ctx (T4's drain), errors are logged never fatal (the serve recovery-goroutine bargain).
- Observation sources (T0 §2 names each, VERIFY): last activity = max(latest `loop.*`/`step.*` event `at` for the loop, latest step row/checkpoint update, `loop.started_at`); `PositionDispatches` from the pinned state's per-position counters or a count of step rows at the position; `ReasonRepeats` from `LastReason` history; `step-over-deadline` from `Manifest.DeadlineAt` of a `running` step. If a source does not exist, the signal's `watchdog.vocabulary` entry says `available:false` and a rule on it is refused — never silently inert.
- **Seed set `watchdog.default`** (P8): `aeon/internal/seed/decl_watchdog.go` + `aeon/internal/watchdog/watchdogseed` — class **inert** (it only ever restricts running work), applied at daemon start and `aeon init`; `Applier{Upsert,Fingerprint,Retire,GuardAffecting:false,Operator{Edit,Remove,Disable}}` writing through the one write path (`store.WatchdogSet`); per-record `Version` guarded by a golden ("content changed but version did not — bump it"). Content: `workspace/no-activity/15 min/notify`, `workspace/no-activity/60 min/stop` , `workspace/same-position/6/stop`, `workspace/repeat-block-reason/3/stop`, `workspace/step-over-deadline/0/block` (thresholds are the OD14 defaults). An operator's edit/disable/removal is never re-seeded (`diverged`/`removed`); `restore` is explicit.
- Socket (human door, P4): `watchdog.list` (read; list-with-details: rule, scope, signal, action, threshold in human units, enabled, origin, last fired, fire count, loops currently in an episode), `watchdog.show`, `watchdog.vocabulary` (read; signals with units and availability, actions), `watchdog.set`, `watchdog.setEnabled`, `watchdog.remove`. Loosening (disable, raise a threshold, remove a **system** rule) requires the confirmation digest (T8's pattern). Refusals `ErrWatchdogRefused`. Conformance, handshake, protogen as T5.
- Guards `aeon/cmd/aeon/watchdog_amend_test.go` (new): `{watchdog.set, watchdog.setEnabled, watchdog.remove}` human-door positive + negative per door + canary + call-graph (`ParkLoopStopped`/block CAS callable from the watchdog only via the service) — T5's shape; **no agent write exists** (OD10).

## Behaviour (each a test)

1. A running loop with no activity past a `notify` threshold fires once; a second tick does not refire; progress then silence starts a new episode.
2. Ladder: `notify` at 15 min then `stop` at 60 min on one loop — attended parks `waiting/stopped`, unattended blocks `stuck`; both audited with `{system,watchdog}`.
3. A loop `waiting` on a question for days, `blocked`, `idle` or terminal is never touched.
4. `same-position` fires on N re-dispatches the reject counters did not cap (e.g. a model-error retry loop through `loop.retry_handler_block` patterns).
5. `step-over-deadline` blocks a step the runtime failed to stop.
6. `loop.resume` resumes a watchdog `stuck` block and a watchdog stop; `loop.raise` refuses it ("not a cap-hit block").
7. Disabling or removing rules changes behaviour at the **next tick** (no cache); a removed system rule is not re-seeded.
8. **No automatic retry exists:** a grep test forbids the watchdog from calling `Advance*`, `Runner.Start`, `RetryHandlerBlock`, `Resume*`.

## Definition of done

- [ ] Rules as records, seeded inert set, service acts only on running loops with the right actor and action, doors guarded, no auto-retry.

## Do NOT

- Do not observe non-running loops. Do not call any advance/start/retry function from the watchdog. Do not make the seed set a guard-class set. Do not stamp a `user` actor. Do not hardcode the signal/action vocabulary in a client.

### Deviations from the task spec

- **The `watchdog.fired` event fixture was missing, found on the first full
  protocol-suite run this close-out.** The kind was registered in `Kinds()`
  but no fixture existed, and `TestEveryEventKindHasAFixture` matches none of
  the P10 `-run` words — the filtered green was not full-suite evidence for
  the protocol package. Fixed: `conformance/events/watchdog-fired.json`, and
  `WatchdogFiredPayload` gained camelCase json tags (`loopId`/`ruleId`/
  `signal`/`action`/`metric`/`episode`; `ComponentRoot` is `json:"-"` — the
  envelope carries the root, the budget events' shape, S31 D1). Without the
  tags the wire keys were PascalCase, inconsistent with every other event
  payload. Lesson recorded: after adding an event kind, run the UNFILTERED
  protocol suite.
- **Two store bugs found by the tests and fixed this task.** (1)
  `WatchdogRunningStep` scanned `step.context_manifest` as a plain `string` —
  a NULL manifest (a step with no manifest row yet) failed the scan and broke
  `observe()` for EVERY loop with a running step (hours of debugging; the
  daemon logger is logrus `level=info`, so the service's error log was being
  filtered out of the test output). Now `sql.NullString`. (2) `WatchdogSet`'s
  `changed` event stamped `OldValue` AFTER the flip, so old == new always; the
  old state is now captured before the flip.
- **The seed applier restores over live (SD6).** `Upsert` →
  `WatchdogRestoreTx` unconditionally, on the agentseed precedent
  (`internal/agentseed/applier.go:91`) — an inert-class set must not fight an
  operator's edits on the apply path; `restore` stays the explicit act.
- **The seed record key grammar is `scope:subject:signal:action:threshold`** —
  action BEFORE threshold (`watchdogseed/content.go` `key()`). The spec lists
  the five records without fixing key order; the grammar is the column order,
  and restore depends on it being stable and total. The default set's five
  keys include `workspace:workspace:no-activity:stop:3600000`.
- **`loop.raise` on a watchdog stuck-block answers -31861 with kind
  `blocked`, not `no-cap`.** `CheckRaise` gates on STATE first: a blocked
  loop is refused "the loop is blocked — it has its own remedy, not a raise"
  before the cap check; `no-cap` is only the cap-hit crash window where
  `CapHit == nil` after a nil refusal. Spec behaviour 6 ("raise refuses it,
  not a cap-hit block") is satisfied by the `blocked` kind. Also: the raise
  params must name exactly one cap, or the -32602 shape fault lands first.
- **Test loops must pin a PARSEABLE blueprint.** `loop.Pinned` (called by
  both the resume and the raise doors) refuses bare content with
  `pin-unparseable: unsupported schemaVersion 0; supported: 1`; the test
  helper now uses `const wdBlueprint` (schemaVersion 1, one model-step lane).
- **`TestWatchdogStuckIsResumableAndRaiseRefuses` nils `d.loopRunner`.**
  t15-built daemons have a LIVE `loopRunner` (daemon.go:1047 →
  `initBlueprints` → blueprint.go:393); a real-daemon resume kicks a runner
  goroutine that outlives the test's store and SIGSEGVs in
  `store.EffectiveForRoot` (nil `s.r`) in the NEXT test. The door under test
  is the resume/raise control, not the re-dispatch. Field-assignment pattern
  precedent: `automation_test.go:28`.
- **`internal/daemon/seed_test.go` (S43's file) got a minimal fix.**
  `TestStartupFailureOfOneRecordDoesNotAbortStart` builds its engine over
  `seed.DefaultRegistry()`, which now includes `watchdog.default` (registered
  at init) — the engine refused "set watchdog.default has no applier". Added
  `failingApplier{setID: watchdogseed.SetID}` + the import. Nothing else in
  the file touched.
- **`now_task` has no writer** (reserved column; read only at
  `loops.go:250`), so a service-level `same-position` dispatch count is not
  constructible through the store door. The signal is covered at the
  store-observation level (`WatchdogPositionDispatches`) and the pure-package

### Unverified, named

- **The notify arm can re-fire ONCE after a daemon restart.** The
  once-per-episode memory (`lastFired`) is in-process only; after a restart,
  a loop still silent past the threshold is observed with an empty memory and
  fires once more. The stop/block arms are unaffected (their loops are no
  longer `running`, hence unobserved). Named, not fixed: persisting the
  episode marker would mean writing to the loop's own rows, which is the
  watchdog's one forbidden direction.
- **The T11 CLI verbs (`aeon watchdog …`) do not exist yet.** The guard pins
  only that no client carries a vocabulary copy (the literal walk above,
  re-measured 2026-11-01).
