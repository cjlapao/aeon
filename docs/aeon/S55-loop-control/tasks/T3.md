# T3 · The control core: runner interrupt, stop, resume, cancel, escalation door

**Prefix:** LC · **Rules:** LC1–LC4, LC6, LC16 · **Depends on:** T2.

## Goal

The engine can stop, resume and cancel a loop with the exactly-once and ordering guarantees of LC2–LC4, the escalation question is answerable through `loop.answer`, and one eligibility function per operation serves both the daemon and `loop.show`. No socket method is registered yet (T5) — T3 ships the in-process operations and tests them through the daemon seams.

## Behaviour (each a test)

1. **Stop mid-step:** step parks `suspended`/`user`, loop `waiting/stopped`, `loop.waiting{reason:"stopped", stepId}` once, a control event `stop`, result `{stopped:true, parkedSteps:[id]}`.
2. **Stop between steps:** runner interrupted with cause; park CAS runs; no step row touched.
3. **Stop races a step that is finishing:** whichever wins, the loop ends in a consistent state and **no step is `failed`**.
4. **Stop on a parallel loop:** every running unit parks; all worktrees stay for resume.
5. **Stop is a no-op, not an error** for waiting-at-question, blocked, idle, terminal: `{stopped:false, status, note}` with the remedy.
6. **Resume** (parked step / between steps / watchdog `stuck` block); `message` delivered exactly once; refusals per `CheckResume`.
7. **Cancel** from running/waiting/blocked/idle: terminal `aborted`, run `cancelled`, `loop.finished{status:"aborted"}`, `on_abort` lane **not** run, control event `cancel` with the reason in its own column; a second cancel is refused ("already aborted").
8. **Escalation:** attended exhaustion → `loop.answer {continue|abort}` over the daemon seam works end to end (the S17 walk, previously orphaned).
