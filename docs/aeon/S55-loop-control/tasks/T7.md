# T7 · Budget engine and enforcement: boundary, in-step, start, cap-hit, raise

**Prefix:** LC · **Rules:** LC9–LC12 · **Depends on:** T3, T6.

## Goal

Budgets are enforced: before a step is dispatched, before each model call inside a step, and at `loop.start`; a hit parks the loop `blocked`/`cap-hit` (boundary) or suspends the step `pause_reason='cap'` (in-step), and the in-process raise-and-resume operation exists. The socket doors are T8.

## Files

- `aeon/internal/budget/evaluate.go` — **new, pure**: `Evaluate(budgets []Budget, spend map[string]Spend) Verdict`. `Verdict{OK bool, Hits []Hit, Warns []Warn, Notes []string}`; `Hit{BudgetID, Scope, SubjectID, Dimension, SpendFloor, Cap, Window, Reason}` where `Reason ∈ {over-cap, cost-unproven}`. Rules: a dimension breaches when `spendFloor >= cap` (a cap is exhausted **at** the cap: the next call is what it forbids); `usd` with `unknown_policy='stop'` and `USDUnknown>0` ⇒ `cost-unproven` hit; with `proceed` ⇒ a `Notes` entry `cost-unknown (N steps)`; tokens analogous with `TokensUnknown`; deterministic ordering (scope narrow→wide, then budget id) so "the tightest breach reported" is stable; `warn_pct` crossing emits a `Warn` once per (budget, window period) — the store remembers the last warned bucket in a `budget_event{warned}` row.
- `aeon/internal/loop/advance.go` — `Deps.Budget func(ctx context.Context, st LoopState) (budget.Verdict, error)` (nil = unenforced, like `Deps.Records`, `advance.go:61`). **E1:** in the `ActRunModelStep` arm, before `dep.Model`/`dep.RecoveredStep` dispatch (`advance.go:~225-247`): evaluate; on a hit, set `Status="blocked"`, `LastReason`, `BlockedReason{Kind:"cap-hit", Detail:<sentence from Hit>}`, `closePhase`, `save`, emit `loop.blocked` (existing event) and write `budget_event{hit}` through a `Deps` callback; **position unchanged, nothing in flight**. A `Deps.Budget` **error** blocks with kind `budget-unreadable` (fail toward stop, never toward spend).
- `aeon/internal/runtime/loop.go` + `types.go` — **E2:** `StepRequest.Budget func(ctx context.Context) (budget.Verdict, error)` (pattern of `HasOperator`/`Telemetry`); checked at the top of each iteration **after** the MaxIterations/DeadlineAt bounds (`loop.go:223-232`) and **before** the model request. On a hit the step returns the **suspended** result with `PauseReason:"cap"` and a typed `Cause` carrying the hit (NOT `OutcomeBlocked`, OD6). The runtime stays pure: the seam is a func supplied by the daemon.
- `aeon/internal/daemon/blueprint.go` (~258-266 and `recover.go` ~193-199) — map `PauseReason=="cap"` to `ModelResult.Kind "capped"`; `loop/advance.go` handles Kind `capped` beside `stopped` (`advance.go:285-302`): `Status="blocked"`, `BlockedReason{Kind:"cap-hit", StepID}`, `StepStates` waiting with the step id, `budget_event{hit}`, `loop.blocked`.
- `aeon/internal/daemon/budget_seam.go` — **new**: builds both seams from `store.ApplicableBudgets` + `SpendFor`; caches **nothing** across calls (N8: read fresh every time, like the parallel cap, `advance_parallel.go:39`).
- `aeon/internal/daemon/start_loop.go` — **E3:** before pinning, evaluate the budgets that would apply (component/root/workspace; epic/loop if named); a hit ⇒ the typed refusal "budget `<id>` on `<scope>` `<subject>` is exhausted (`<dimension>` `<floor>` of `<cap>`) — raise it (`aeon budget set`) or start later". `loop.start` with `{budgetCheck:false}` does **not** exist; there is no bypass.
- `aeon/internal/loop/control.go` — `CheckRaise(st) *ControlRefusal` and `Raise(ctx, dep, id, actor, change, hooks)`: one transaction `UpdateBudget` + `budget_event{raised}`, then resume — **E1 hit:** CAS `blocked`→`running`, runner start; **E2 hit:** the step-continue path (`pause_reason='cap'` is a valid continue reason: extend `handleStepContinue`'s precondition in `protocol/step_stop.go:~140-150` from `user` to `user|cap`, with the cap-continue reachable **only** through `Raise`, not through a bare `step.continue`: a bare `step.continue` on a `cap` step is refused with "this step stopped on a budget — raise it with `loop.raise`"). Refusals: not `blocked`/`cap-hit`; new cap not above the spend floor; `budgetId` not applicable.
- `aeon/internal/daemon/queue_reactor.go:62-70` — T0 §2 decides whether the queue question raised on `loop.blocked` needs to carry the `cap-hit` reason; if so, a one-line text change here with a test, otherwise none.

## Behaviour (each a test)

1. **Boundary hit** (spend at cap before a dispatch): the step is **not started**; loop `blocked`/`cap-hit`; the reason names budget, scope, subject, dimension, floor, cap.
2. **In-step hit:** an iteration that finds the cap exhausted suspends the step with its checkpoint intact; `loop.raise` continues it; the transcript has no gap or duplicate.
3. **Overshoot is bounded and stated:** a fake route whose single call costs more than the remaining cap completes that call (checked *before*), the next check blocks; `budget.show`'s worst-case note (T8) is computed from the route.
4. **Unknown cost:** `proceed` → continues with the `cost-unknown` note; `stop` → `cost-unproven` hit; tokens/steps/wall caps hold regardless of price.
5. **Tightest breach reported:** loop/epic/component/root/workspace budgets all applicable; the narrowest breached one is named; the others re-evaluated on resume.
6. **Unattended and attended behave the same** (OD5): no question row in either.
7. **Raise:** below-floor refused; above-floor resumes; the loop re-blocks on a *different* budget if one is also exhausted, with that budget named.
8. **`loop.start` refusal** when a budget is exhausted; none for an absent budget.
9. **Seam errors fail closed** (`budget-unreadable` block), never open.
10. **No caching:** lowering a cap mid-run takes effect at the next check.

### Deviations from the task spec

- **The E1/E2 seam is `loop.Deps.Budget` + `runtime.LoopDeps.Budget` + `RunOpts.Budget`,
  not a `StepRequest.Budget` field.** The engine reads the verdict through the dep seam
  it already uses for the model; the daemon wires the one function for both (fresh
  dispatch in `advance.go`, top of `RunLoop` in `loop.go`).
- **`Evaluate` gained `warned map[string]bool, now time.Time`** over the spec's
  `Evaluate(budgets, spend)`: warn dedup needs the store's memory of the last warned
  bucket, and the rolling 24h day window needs a clock. The engine stays pure (both are
  inputs); the daemon supplies them (N8 still holds — it caches nothing, it is just
  handed what to dedupe against).
- **E1 sits ONLY in the fresh-dispatch else-branch** (the `StepInFlight` re-run path is
  E2's business at the step boundary, OD6). A seam error blocks as `budget-unreadable`
  (fail toward stop), distinct from a cap hit.
- **Crash window tolerance:** if the process dies between the E2 raise's CAS (the loop
  is `waiting/cap-hit`) and the kick, the loop is left `waiting/cap-hit` with no live
  re-run — recoverable by `resume`, so `ResumeLoop` in `store/loop_control.go` now
  admits `waiting/cap-hit` alongside `waiting/stopped` and `blocked/stuck`. This
  contradicts T3's "re-runs cold" note: the in-step re-run is the **live
  same-row-from-checkpoint** path (`step.continue` machinery, `ContinueCapStep`), and
  the recovery finish-shortcut is NOT taken, because the parked transcript ends with a
  USER tool-result message, not an assistant one.
- **`RaiseLoop` refusals** (daemon seam): `no-cap` (the pin has no cap record — the
  crash-window shape; names resume), `below-floor` (newCap ≤ SpendFloor),
  `terminal` (done loops), and a lost-race CAS refusal verbatim from the store.
  **The E3 start refusal rides `ErrLoopControlRefused` (-31860) until T8 adds
  `ErrBudgetRefused` (-31861)** and moves the budget family onto it.
- **E2's spend rides the checkpoint → step-row path:** `SaveRunningCheckpoint` writes
  `cost_usd` on EVERY checkpoint, and the loop checkpoints after each stream and after
  the assistant append (cost accumulated before the checkpoint), so the step-scope
  `SpendFor` sum over step rows is current at the in-step check without any new writer.
- **`CommitRecoveredStep` gained a `pauseReason`** (a recovered step that parks as
  suspended carries why) and **`ContinueCapStep` is in-process-only** (it flips the
  parked step back to running for the raise's kick; the socket door T8 exposes the
  refusal, not the flip).
- **The runtime's K6 import allowlist gained `"Budget"`** (the `runtime.BudgetVerdict`
  type the `Table.Budget` seam names) — no store import.
- **Test-fixture shape — why the budget tests need tool-use turns:** a turn with NO tool
  use is a FINISHING turn (`loop.go:419` → `st.finish` at `:1173`, which extracts a
  handoff or makes ONE tool-free retry call before failing). A plain-text scripted turn
  ends the step after one `RunLoop` iteration, so the in-step (E2) check never gets a
  next iteration. The daemon fixture turns that must keep the step alive carry
  `readUse` tool uses (`costedModel` emits them; `seedRules` allows read for read-only).
- **`waitLoopDone` vs `waitLoopSettled` after an E2 raise:** after the raise the loop is
  ALREADY `waiting/cap-hit` (the raise's CAS) while the parked step re-runs in a
  background goroutine — `waitLoopSettled` returns immediately for a waiting loop and
  races the re-run. The tests poll `ReadPinnedLoop` for `done` instead (`waitLoopDone`,
  15s deadline).
- **E1 raise-kick race (found and fixed this round — production bug):**
  `Runner.Start` returns false while an entry for the loop is in its active map, and
  the parked loop's own runner is still IN ITS EXIT PATH when the raise kicks (the
  block is emitted before the goroutine leaves the map; a blocked loop holds no
  goroutine as an invariant, so the entry cannot be a live runner — a live runner would
  mean the loop was running when the raise's CAS committed, and the CAS would have been
  refused). The original kick code assumed "a concurrent raise won the kick" and
  reported success with a note that the existing runner "carries the re-dispatch" — a
  departing runner re-dispatches nothing, and the loop sat `running` forever with
  nobody behind it (reproduced: `TestPreDispatchCap…` timed out at 30s, `status running
  active false`). Fix in `RaiseLoop`: on `Start == false`, `Wait` up to 5s for the old
  runner to settle, then re-`Start`; the two remaining refusals (old runner never
  settles; draining daemon) return honest errors naming that the cap IS raised and the
  loop IS running in the store, and what carries it (a resume / the next start).
- **The same latent window exists on `loop.answer`'s fresh-runner kick** (a gate loop
  also holds no goroutine once waiting) — NOT fixed here (out of T7 scope, and a human
  answer is never fast enough to hit it); recorded for the close-out.
- **`TestBlockedQueueCarriesTheCapReason`'s first run** fell to the full daemon suite:
  its name matches none of the P10 filter's words, so it had never executed. It needed
  (a) `Blueprint` + `WorkspaceRoot` (the store requires component root, blueprint, goal
  AND workspace root) and (b) the two FK targets to exist — a `component_root` row and
  a real pinned loop row with the slug the item is stamped with (the
  `(component_root, loop_slug) REFERENCES loop` FK, and the gate question the block
  raises rides that loop's slug). Seeded the house way (`CreateComponent` +
  `CreatePinnedLoop`, reusing `queueBlueprintYAML`).

### Three T6 store bugs found by T7's tests (fixed in T7)

1. **Typed-nil panic** in `validateBudgetRefusal` on partial-dimension budgets (a
   dimension whose cap is unset is a nil `*float64` the comparison dereferenced) — fixed
   with `v != nil &&` guards.
2. **`ApplicableBudgets`/`ApplicableBudgetsFor` treated `RootOf`'s `ErrNotFound` as an
   error** — a bare workspace root (no component) refused EVERY start. Fixed:
   `ErrNotFound` ⇒ no component tier, the workspace tier still applies.
3. **`UpdateBudget` wrote the OLD cap values into the UPDATE statement** (it read
   `cur`, composed the statement from `cur`, and only then merged `in`) — the row kept
   the old cap while the returned `Budget` showed the new one: a `changed` audit event
   for a change that never landed. Fixed by merging into `newUSD/newTokens/newWallMs/
   newSteps` locals first, writing the merged values, then assigning to `cur`.
