# T1 — The generic RPC bridge and the one event channel

**Notes (2026-10-18):** The test bench already supplied the persistent Rust session, generic `rpc_call`, one `aeon://event` notification channel, correlation, and endpoint resolution. S9 kept that tested implementation in `main.rs`, `session.rs`, `rpc.rs`, and `bridge.ts` rather than moving it to the planned filenames. Errors now carry explicit `transport`, `timeout`, or `rpc` kinds; a daemon refusal without `data` stays an RPC refusal. The web subscriber ignores unknown additive event kinds using the generated event set. The Go method table boundary test allows only the three bootstrap/liveness literals `initialize`, `version`, and `ping` in Rust; these are required to establish and confirm the session. Rust socket tests, the boundary test, and the web bridge tests passed.

## Why this exists

A browser has no unix-socket API, which is why S1's T5 made the Rust shell the UI rather than packaging around a
served page. Every request the app makes goes through it.

**The naive shape is one Tauri command per protocol method, and it is wrong.** That produces a second copy of S2's
closed method table, written in Rust, that drifts from the Go one — and P25 was explicit that Aeon has **two**
surfaces, the socket and the narrow HTTP projection. It must not grow a third.

So: **one command that does not know the method list**, and therefore cannot disagree with it (U11).

## Scope

### The bridge

```rust
#[tauri::command]
async fn rpc(
    state: tauri::State<'_, Conn>,
    method: String,
    params: serde_json::Value,
) -> Result<serde_json::Value, RpcError>
```

It frames a JSON-RPC 2.0 request, writes it, reads the response, and returns it. It does not validate `method`
against anything — validation is the daemon's, which is the entire point.

### Errors are discriminated (O2)

```rust
enum RpcError {
    Transport { detail: String },   // the socket: refused, closed, path wrong
    Timeout   { after_ms: u64 },
    Rpc       { code: i32, message: String, data: Option<Value> },  // the daemon answered, with an error
}
```

Three different things. A single "request failed" makes a daemon-side **domain refusal** — "this transition is not
allowed" — look like a broken socket, and sends whoever is debugging to the wrong problem entirely.

### The event channel

One subscription, one channel. The Rust side holds the socket subscription and emits every event to the webview as
`aeon://event`, **carrying the daemon's `seq` unchanged**.

`seq` is the `event` table's rowid (S4), so a filtered subscriber legitimately sees gaps. The Rust side does not
interpret that — it forwards. T3 owns what the web layer does about it.

### The connection

`conn.rs` in this task holds the socket, resolves its path **the same way `serve` does** (S1's T3, including the
platform difference between a unix socket and a named pipe), and exposes connect/disconnect.

**No timing logic in this task.** Liveness, staleness and reconnection are T3. Splitting them keeps this task's
failures about the socket rather than about a clock.

### The web-side call

`lib/rpc.ts` — an untyped `rpc(method, params)` wrapper over `invoke`, plus an event subscriber. T2 puts generated
types on top of it; nothing here names a method either.

### Unknown events are ignored (O5, I7)

The web-side subscriber **ignores** an event type it does not know, per S2's additive rule. A client that breaks on
a new event type makes every future slice a breaking change, and S2 chose additive precisely so this would not
happen.

## Tests

| Test | Asserts |
| --- | --- |
| `TestNoMethodNamesInRust` | Grep `src-tauri/` against **S2's method table as the source of truth** — not a hand-written list — and assert **zero** matches. One name appearing means U11 is broken and a second method table has been born (D3) |
| `TestBridgeErrorsAreDiscriminated` | A refused socket yields `Transport`; a slow one yields `Timeout`; a daemon JSON-RPC error yields `Rpc` with its **code preserved**. Three distinct variants, asserted separately (O2) |
| `TestRpcRoundTrip` | Against a fake socket speaking JSON-RPC: a request goes out well-formed and the response comes back unaltered |
| `TestSeqIsForwardedUnchanged` | An event with a non-contiguous `seq` reaches the webview with that exact `seq`. The Rust side does not renumber, fill, or interpret |
| `TestUnknownEventIsIgnored` | A synthetic event of an unknown type is dropped by the web subscriber **without error** (O5) |
| `TestSocketPathMatchesServe` | The resolved path is identical to `serve`'s, on every platform the build targets. A path that differs by a directory is a bug that presents as "the daemon is not running" |
| `TestNoTimingLogicHere` | A review check: `conn.rs` in this task contains no interval, no retry loop, no clock read. Those are T3 |

`TestNoMethodNamesInRust` is the test that will still be earning its keep in a year, and its source of truth
matters: a hand-written list of methods to grep for is itself a second method table.
