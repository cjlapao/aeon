# T5 — The port — what comes over from v1, and what does not

> **Completed · 2026-10-19.** The port is a reviewed adaptation to S8's daemon contract. `frontmatter`, `duration`, and `RelativeTime` came across with their pure tests. `product/` supplies the loop, ladder, question, transcript, and recovery compositions using ui-kit 0.2.3; its behavior is tested in `test/product.test.tsx`. `PORT.md` accounts for every v1 source module and the new components. `test/port.test.ts` guards that inventory, the exact kit version, and the absence of HTTP, direct filesystem calls, and v1 modals. The old platform module was excluded because its `plugin-fs` read methods violate U16/D10. The browser fallback is the fake daemon bridge used by the UI tests. V1 phase/task widgets and their unchanged tests cannot describe S8's lane/item/step schema; their behavior is tested against the generated S8 contract instead. This resolves the earlier T5 wording conflict in favor of S9's security and protocol invariants.

> ## The components you are porting are already built on `@cjlapao/ui-kit`
>
> v1's `packages/loop-state-ui` depends on `@cjlapao/ui-kit@^0.2.0` today — `LoopCard` imports
> `{ Alert, Pill, Progress }`, `TaskSteps` imports `{ EmptyState, Pill, Spinner }`, and `main.tsx` imports
> `@cjlapao/ui-kit/styles.css`.
>
> **So this is a port of compositions, not a reimplementation.** Bringing a component across means bringing
> its ui-kit usage with it. A hand-rolled replacement for something the kit already provides is a
> regression, and it is the thing to look for in review.


## Why this exists

U10 said *"port v1's `src/api/` hook layer rather than rewriting it — it is tested, and none of its problems are the
ones this slice is solving."*

**The line is drawn in the wrong place**, and `packages/loop-state-ui` says so. The advice was right that the
components are tested and worth keeping, and wrong about which layer that was. The correction is already landed in
the superseded design (I2) — this task implements it.

It is **its own task** (R6) because a port spread across screen tasks is a port nobody can review, and the
interesting output is the list of what was *left behind*.

## Scope

**Read `packages/loop-state-ui/src/` and do not edit it** (N10). The app lives at `aeon/ui/` (S1's B5); v1's package
is a source, not a destination.

### What comes over

| From v1 | Change on arrival |
| --- | --- |
| `components/PhaseTimeline.tsx`, `LoopCard.tsx`, `TaskSteps.tsx`, `TaskLifecycle.tsx` | Their presentation is adapted in `product/Ladder.tsx` and `LoopsScreen.tsx` against S8's lane/item/step schema |
| `components/RelativeTime.tsx` | Unchanged — it has no imports to re-point |
| `components/RecoveryPanel.tsx` | Its content is adapted in `product/SystemScreen.tsx` against S7's structured recovery result |
| `components/ConnectionPill.tsx` | Extended by T3 |
| `api/frontmatter.ts`, `components/duration.ts` | Moved to `lib/`. Pure, tested, transport-free |
| `platform/{index,tauri,web}.ts` | Excluded: v1's Tauri implementation grants direct filesystem reads. Aeon's browser test fallback is the injectable bridge |

### What does not

| Left behind | Why |
| --- | --- |
| `api/client.ts` | `fetch` against `loop-state-api`. The transport is now a socket behind a Rust bridge (T1) |
| `api/connection.tsx` | `EventSource`. Subscriptions come over one Tauri event channel now |
| `api/endpoints.ts`, `api/repos.ts`, `api/useProjects.ts`, `api/useLoops.ts` | HTTP endpoint shapes. Replaced by generated methods (T2) |
| `api/types.ts` | **Regenerated** (U12). Hand-carried types are the drift the generator exists to remove |
| Modal components (`ProjectEditModal`, `TaskStatusModal`) | U4: a question renders inline, never as a modal. Whatever they do is re-thought at the screen that needs it, not ported |
| `Markdown`, document and project widgets | S8 has no daemon document-content or project method; pinned blueprint and transcript data arrive from the existing RPC views |

### `useLabels` — the one shallow coupling that reaches everywhere

It fetches, and **most components import it**. Answer Q5 first: what does it actually fetch?

- If the labels are static UI strings, **the re-point is a deletion** — inline them and delete the module.
- If they are daemon-provided, it becomes a generated call.

Either way it cannot be left as-is, and it is the reason this port is not a file copy.

### `PORT.md` (D20's evidence)

A committed manifest: every v1 module, whether it came over, and for the ones that did not, **why**. Six months from
now the question "why is there no `client.ts`" has an answer that is not archaeology.

It is also what makes the port reviewable: a reviewer checks the manifest against the tree rather than diffing two
package trees by eye.
