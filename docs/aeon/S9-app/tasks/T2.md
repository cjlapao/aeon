# T2 — Generating the app's types from S2's contract

**Notes (2026-10-18):** `make protogen` now emits `ui/src/proto/contract.ts` from the Go method table, conformance request/result examples, event fixtures, and Go event declarations. `make check-protogen` runs in `make ci`; regeneration equality, missing-method refusal, and coverage-limit tests passed. The web bridge offers `rpcTyped` for S9 screens while the existing test bench keeps its generic call. The generated shapes contain fields observed in fixtures only: an optional field absent from every fixture cannot be inferred. The deliberate future fields in `forward-compat.json` are excluded from production types. All 30 current method names have request and result fixtures; 26 event kinds were derived from fixtures or Go declarations/emission sites.

## Why this exists

Hand-maintained client types are the drift S2's conformance fixtures were built to prevent. And in a **UI**, drift
does not present as an error — it presents as a **blank panel**, because a field renamed on the daemon simply
arrives as `undefined` and React renders nothing.

That is the worst failure shape available: no error, no log, and a screen that looks like a design decision.

## Scope

### The generator

`tools/protogen` reads S2's conformance fixtures and emits TypeScript into `ui/src/proto/`. Go, because the
contract is Go's and a generator in a third language is a third thing to keep working.

**Checked in and hand-runnable** (O3): `make protogen`. Not a hidden CI step. A contributor who cannot regenerate
locally will hand-edit the generated file, and the CI diff check then reads as an obstacle rather than a guard —
which is how a guard gets deleted.

### What it emits (Q9)

Types **and typed method signatures**:

```ts
// GENERATED by tools/protogen. Do not edit.
export interface StepGetParams { stepId: string }
export interface StepGetResult { /* … */ }

export const methods = {
  "step.get":    (p: StepGetParams)    => rpc<StepGetResult>("step.get", p),
  "loop.start":  (p: LoopStartParams)  => rpc<LoopStartResult>("loop.start", p),
  // …
} as const;
```

The signatures are what make **a removed daemon method fail the build** rather than at runtime. A types-only
generator leaves every call site a string, and a string that no longer resolves fails when a user clicks something.

Every file carries a `GENERATED — do not edit` header, and the directory is excluded from formatting and from
hand-edit review.

### Coverage must be stated, not assumed (Q1)

**Answer Q1 first**: does S2's conformance set describe every method and event, or only some?

If it is partial, the generator's coverage is partial, and that must be **recorded in the generated output** — a
committed manifest listing what was generated and what was not, with the reason. A silent gap here becomes a
hand-written type later, which is the drift this task exists to remove.

Do **not** extend S2's fixtures to close the gap. That is a protocol-side change and N9 says a missing method is a
finding to raise, not something to add here.

### CI (D4)

CI runs `make protogen` and fails on any diff. That check is worth more than the generator: it is what converts
"we generate types" from an intention into a property.

### The typed layer

`lib/rpc.ts` gains the typed wrapper over T1's untyped call. **It still names no method** — the names live in
generated code, and the generated code came from Go.
