## Why this exists

This is the screen someone opens when they want to know **what actually happened**, which means it is the screen
where silent omissions do the most damage. Everything below is a rule about not hiding something.

## Scope

### The transcript

Assistant text, tool calls with input and result, in order. The canonical message format (P3) is what arrives, so
this renders blocks, not provider-shaped payloads.

**Thinking blocks and their signatures** (M17) are present in the data and must not be rendered raw — a signature is
an opaque token and displaying it is noise. Show that thinking occurred; keep the signature out of the view.

### Truncated in view, complete on expand (D16)

Long tool output is summarised in the flow and **complete on expand**. Truncation in the summary is fine; silently
shortening the underlying data is not — **a UI that shortens tool output is one you cannot debug from**, and debugging
from it is the whole reason to open this screen.

Assert the expanded content against the full stored result, not against a truncation of it.

### The manifest (D18, S6's K14)

The declared context: every file, its hash at declaration, and — for a step that suspended and resumed — **whether it
changed while suspended**, and whether it went missing. S6 records that distinction as a `user`-role note; this screen
shows it structurally.

A changed file the reader does not notice is how a step's output gets trusted when it should not be.

### Compaction (D17)

If the step was compacted, **say so**, show where in the transcript the summary sits, and include the summary call's
cost in the total.

An invisible compaction makes the cost look wrong — someone sees a total that does not match the visible turns and
concludes the accounting is broken. And a transcript that silently omits what was compacted away is a transcript that
lies about what the model saw.

### Recovery (D14, T4)

If the step was recovered or failed in recovery, render S7's structured `RecoveryFailure`: the tool name and the
receipt state. *"It started and we cannot say what happened"* is a different fact from *"it failed"*, and only one of
them tells someone to go look at their repository.

Case B — a re-issued model call — must show **both calls' cost** (S7's D3, O1). Those tokens were billed.

### Cost and bounds

The step's cost through T4. Iterations used against the bound, and the absolute deadline (S5). A step that stopped
on a bound must say **which** bound.

### Live

`step.*` events append as they arrive; a running step's transcript grows without a refetch.

## Tests

| Test | Asserts |
| --- | --- |
| `TestToolOutputCompleteOnExpand` | Expanded content equals the **full stored result**, not a longer truncation (D16) |
| `TestChangedFileIsMarked` | A file changed while suspended is marked, and a missing one is marked **distinctly** (D18) |
| `TestCompactionIsVisible` | The step says it was compacted, the summary's position is shown, and its cost is in the total (D17) |
| `TestCostMatchesVisibleTurnsOrExplainsWhy` | For a compacted step, the total exceeds the visible turns **and the screen accounts for the difference** |
| `TestSignaturesAreNotRendered` | A thinking block's signature does not appear in the output; that thinking occurred does (M17) |
| `TestRecoveryFailureNamesToolAndState` | From the structure, not the prose (D14) |
| `TestReIssuedCallShowsBothCosts` | Case B renders two model calls (S7's D3) |
| `TestBoundStopNamesTheBound` | Iterations versus deadline, distinguishable |
| `TestTranscriptGrowsFromEvents` | A running step appends without a refetch |
| `TestEmptyTranscript` | A step with no messages yet renders its state, not a blank panel (D19) |

`TestToolOutputCompleteOnExpand` asserting against the **full stored result** is the point. Comparing against a
longer truncation passes while the data is still being lost.
