Deviations from the task file, each argued:

1. **`triage.board` requires `componentRoot`.** The task lists it optional; the
   S29 law this board stands beside reads "a bug list is scoped to one root"
   (`triage.list` refuses an empty one), and the store has NO cross-root read
   by design. An unscoped board would be a new store surface S51 did not ask
   for. The board therefore requires the root and every FILTER stays optional;
   the fixtures observe exactly that shape.
2. **`update` refuses state keys too** (not just the identity keys T1 lists):
   TM1 says the params ARE {id, title?, body?}; a param carrying
   `validationState` is a caller asking to change something the verb may not
   change — the refusal is the answer, silence is not.
3. **Attempt "last outcome" is read from the bug's CURRENT validation state
   plus the newest `validate` row's time**, not parsed out of summaries — the
   board row carries both (`describe.validationSentence` + `lastAttemptAt`),
   so the reading never depends on template wording.
4. **History is capped the way `BugChangeList` bounds** (limit 0 ⇒ default
   50, cap 500) — the read bound every other triage list keeps.
5. The door's `Describe` renders a state word outside the closed set as
   `"validation: %q — outside the closed set"`: the sentence exists so a
   corrupted row is LOUD on a board, not silently blank.
