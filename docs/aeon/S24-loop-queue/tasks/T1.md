# T1 — `schema.go`: the two `project` columns and `queue_item`

## Why this exists

Everything else in this slice writes rows somewhere. This task is where CG7 and CG8 (`design.md`) become
real SQL.

**Read first:** `design.md` §2's measurement that `project` has no settings table today, and CG7's finding
that an inline `CHECK` on `ALTER TABLE ... ADD COLUMN` works on this driver (verified against mattn's bundled
SQLite, 3.50.4) — use a plain `ALTER`, not the heavier rebuild-and-copy pattern `0016`/`0019`/`0024` needed.
Those three rebuilt tables that already had rows depending on the *old* shape; `project` is only gaining
columns with safe defaults, nothing is narrowed. Find the current highest migration number in `schema.go`
at the time this task starts — do not hardcode `0026` if something else has landed first.

## Scope

**1. `project.queue_advance`**: `TEXT NOT NULL DEFAULT 'ask' CHECK (queue_advance IN ('auto','ask'))`.
Default is `'ask'`, not `'auto'` — R4 in the brief, restated as CG6 in `design.md`: the safe default is the
one nobody has to think about.

**2. `project.sizing_mode`**: `TEXT NOT NULL DEFAULT 'manual' CHECK (sizing_mode IN ('manual','skill'))`.

**3. `queue_item`**: `id` (PK), `project_root` (`NOT NULL`, FK to `project_root`), `position` (`INTEGER NOT
NULL`), `status` (`TEXT NOT NULL CHECK (status IN ('pending','sizing','ready','running','done','blocked',
'cancelled'))` — CG1's seven values, no eighth), `blueprint`, `goal`, `workspace_root`, `tech` (all mirroring
`LoopStartParams`, CG3), `with_json` (`TEXT`, JSON-encoded map, nullable), `attended` (`INTEGER`, nullable —
three states: `1`/`0`/`NULL` for declared-true, declared-false, never-declared, same shape `loop.attended`
already uses), `size_min`, `size_max` (`INTEGER`, both nullable until sized), `size_basis` (`TEXT`, nullable),
`loop_slug` (`TEXT`, nullable, FK to `loop(project_root, slug)` — absent until materialized, D10: no
sentinel, the column is simply unset), `created_at`, `updated_at`.

**4. Index on `(project_root, position)`** — the ordered-list read every later task does first, the same
reasoning as `idx_loop_updated`'s comment in the existing schema.

## Notes

**Measured (2026-10-29).** The plan's `0026` is a document, not the
machine: the highest migration at T1's start was **0040** (S22's retrieval
tier), so the queue is **0041** — the task file anticipated exactly this and
demanded it be found, not hardcoded. The count moved at **five pin sites**:
three in `policy_test.go`, one in `schema_test.go`, and `counters_test.go`
(which pins `len` AND `last.ID`/name in one test — S39's record counted it
as two moves; the name it now expects is `loop_queue`, and S22 T1's
retrieval sentence retired with its rank).

**The rename the slice's docs predate.** Every layer of this design —
brief, plan, task — says `project.queue_advance` on `project`. S38 T1's
OL1 (0035) moved the repo-with-a-root under `component`; the columns are
**on `component`** (the row that owns roots and loops — a group-tier column
would let two repos share an advance mode, which is not what a per-repo
backlog means), and `queue_item` keys `component_root`, the live name for
the same key every loop already rides. Same table, same intent; the brief
was written 2026-10-26 against names the machine has since moved. CG7 held
exactly as verified: plain `ALTER ... ADD COLUMN` with inline `CHECK` on
the bundled SQLite — no rebuild-and-copy, nothing narrowed, defaults
`'ask'`/`'manual'` land on every existing row (R4).

**Found by the tests:** `CreateLoop` does **not** create the tier rows —
the loop table's `component_root` column predates the tier and is not
itself FK-enforced, so `seedLoop` left zero `component`/`component_root`
rows and every queue insert died on a foreign key the loop never needed.
`queue_item` is the first loop-adjacent child that enforces the tier for
real, and the gates seed through `CreateComponent` for that reason. The
composite `loop_slug` FK (no cascade — the ledger of intent survives its
product) refuses `ghost` and admits a real same-root loop; the size CHECK
refuses a bare number, a basis without numbers, an inverted range and an
**empty** basis (D8 unwritable at the database level, not discouraged in
Go); `attended` keeps loop's three states and refuses `2`.

**Gates:** `TestQueueAdvanceAndSizingModeCheckedVocabulary` (defaults +
closed sets + legal-pair control, wrong-case `ASK` refused — TEXT CHECKs
are exact), `TestQueueItemSevenStatusesClosed` (six refusals × CHECK +
all seven admitted), `TestQueueItemScopedByProjectRoot` (FK both
directions, D10 absence-as-NULL, materialization FK, the size law, the
attended triplet). Fresh-equals-migrated (`TestAFreshSchemaAndAnUpgradedSchemaAreIdentical`)
green with 0041 included; store and loop suites green whole.
