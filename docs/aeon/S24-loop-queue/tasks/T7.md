# T7 — `queue.*` socket methods

## Why this exists

CG9 in `design.md` is the explicit departure from PL15: queue authoring is socket-writable, not CLI-only,
because a queue item is ordinary project content, the same trust tier as `loop.start`'s own params (already
socket-writable). This task is where that decision becomes methods — and where the test that proves it is
one implementation underneath two transports, not two, belongs.

**Read first:** `internal/protocol/method.go`'s existing `MethodPolicyList`/`MethodPolicyWhy` registration
shape, and S2's standing rule that every protocol addition is **additive** (`conformance/forward-compat.json`
is the standing test — this task's new methods must not touch it in a way that breaks an older client).

## Scope

**Methods**: `queue.append`, `queue.list`, `queue.reorder`, `queue.remove`, `queue.setSize`,
`queue.settings` (get and set, mirroring T6's CLI verb exactly). Every one calls the *same* `internal/queue`
functions T6's CLI calls — this task adds no new validation logic, only the JSON-RPC marshaling around calls
T6 already proved.

**Unlike policy's four read-only socket methods, every one of these is a write** — that is the whole point
of CG9, so do not reach for policy's read-only shape out of habit.

## Validation

- [ ] `TestQueueSocketAndCLIProduceIdenticalRows` — append the same item through both entry points against
      one store, assert byte-identical resulting rows (barring the two different generated ids)
- [ ] `TestQueueMethodsAreAdditiveToProtocolVersion` — the forward-compat conformance fixture still passes
      unmodified except for the new methods' own addition
- [ ] every method requires `Initialize` the same way `policy.*`'s methods do (no queue method answers
      before the daemon finishes booting)
