# T4 · Rehydrate: the open list reaches the model

**Rules:** TD7. **Depends on:** T2.

## Steps

1. In `internal/runtime/compile.go`, after the chosen-skills section, append a `SectionSpec{Title: "Open todo list", Category: CategoryInjectedContext, Destination: SectionSystem}` when the compile input carries an active list. Add the field to `CompileInput` (`TodoList *TodoSection`: rendered text, open count, total) and fill it in the daemon where the step request is built (find where `ChosenSkills` is filled; same place). Render with the tool's own renderer, exported from `internal/tools` for this one use, so the model sees the format it writes.
2. End the section with the fixed rule sentence from one constant in `internal/tools` (shared with T5's reminders).
3. Add the `todo: N open of M` note to `step.started` (the `Notes` path the skills marker used).
4. No list, closed list, or unwired seam: no section, byte-identical compile (the absence test pattern in `compile_skills_test.go`).
5. Tests: a loop with an active list compiles the section into the system half and not the user half; a closed list does not; the note; the byte-identical absence case.

## Definition of done

- The compiled system text of a second chat step contains the first step's list (test over the real daemon path if one exists, else the compile test plus T2's daemon test).

## Do not

- Do not put the list in the user half: that half is the person's words alone (S68 B3).
