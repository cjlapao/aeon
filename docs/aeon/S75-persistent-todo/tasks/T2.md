# T2 · The tool seam, the amended guard, the event

**Rules:** TD2, TD3, TD4, TD5, TD11, TD12. **Depends on:** T1.

## Goal

`todo` reads and writes the loop's persisted list through an init-time seam, still returns the full render on every result, and the runtime emits `todo.updated`.

## Steps

1. `internal/tools/todo_store.go`: the `TodoStore` interface (`Load(loop) ([]todoItem-shaped, revision, error)`, `Replace(loop, step, expectRevision, items) (revision, closedBy, error)`) in terms of tools-local types, and `SetTodoStore`. No package variable other than the one seam holder; amend `todo_test.go`'s AST guard BY NAME for that one variable, with a comment saying W20 is reversed for the loop (2026-11-07) and why the package still imports no store.
2. The tool needs the loop identity and the step id. Find how the toolset learns the loop and step today (`grep -n "Loop\|StepID" internal/tools/toolset.go internal/tools/exec.go`); thread them to `Todo()` the way `ask_agent` receives its caller. A call with no loop in context behaves as unwired (TD3).
3. `todo` first call in a step: `Load`. `set`: validate (unchanged), `Replace` with the revision it loaded, render, and when the store reports `closedBy`, append the sentence `List closed: all items done.` (or `cleared`). A stale revision is surfaced as a refusal naming it, with the current list in the result so the model can reapply. `list`: `Load` fresh (another step may have changed it).
4. Unwired: append the TD3 sentence exactly.
5. Daemon wiring (`internal/daemon`): an adapter over `store` implementing `TodoStore`, installed once where the other seams are wired; and emit `todo.updated` (new event kind constant in `internal/runtime/types.go` beside `EventStepCompacted`, plus the protocol-notified list and the durable-view registration the way `step.compacted` is handled). The event payload is TD5's.
6. Tests: the existing `todo_test.go` passes unchanged except the named guard amendment; new tests with a fake `TodoStore` (loads on first call, replaces on set, close sentence, stale refusal, unwired sentence); a daemon test over a real store proving a second step in the same loop starts with the first step's list.

## Definition of done

- A second step in one loop sees the first step's list through `todo list`.
- `todo.updated` reaches a subscriber (test) with the TD5 fields.
- `go test -tags sqlite_fts5 ./internal/tools ./internal/runtime ./internal/daemon -run 'Todo'` passes; the full packages are no worse than at base (record the base failures).

## Do not

- Do not import `internal/store` from `internal/tools`.
- Do not change the argument shape, the bounds, or the render format.
