# T2 — `useSkillPicker` and the hosts' spread

## What exists

`lib/skills.ts` gained: `SkillPickerRow/Chip/Panel` (structural twins —
no component import, the dependency arrow stays components → lib),
`skillWeaveLine`, `skillIsPickable`, and `useSkillPicker(connected)`
returning `{ open, openFor, close, clear, toggle, rows, chips, panel,
weave, steerWith, messageWith, selected, onSpecialKeyChange,
onAddAction }`. Hosts (all three) now read:
`picker={skills.panel ?? undefined} onPickerDismiss={skills.close}` +
composer `{ onSteer: skills.steerWith(send), onSpecialKeyChange,
onAddAction, chips }`; `LoopWorkspaceView` also
`onMessage: chat.onMessage ? skills.messageWith(chat.onMessage) : undefined`.

## Notes

- **The test caught the design flaw the first draft had**: hosts
  wrapping `onSteer` by hand drifted (the test harness — a host too —
  forgot the wrap and asserted the weave anyway, correctly failing).
  The wrappers moved INTO the hook (`steerWith`/`messageWith`); now a
  host cannot forget the rule, and the tests exercise exactly what the
  real hosts use. One sentence, one order, one clear-on-success.
- **Clear happens only after the send resolves** — a failed send keeps
  its chips. Losing chosen context to a socket error is the one failure
  the row must never have.
- `skillIsPickable` mirrors S66's offer line (valid ∪ warn, unshadowed)
  — the picker and the daemon offer exclude exactly the same set, and
  the disabled rows say WHY in the catalog's own words.
- The picker stays OPEN on select (multi-pick; the chips are the
  state); the README's single-pick example no longer matches — noted in
  the brief as a deliberate deviation.
- jsdom fact worth recording: `fireEvent.click` on a picker row is
  swallowed by the panel dock's outside-dismiss logic in this test
  environment (native `.click()` reaches the handler fine) — the test's
  `clickRow` helper goes native and the comment says why. A component
  behavior note, not a product bug (a real browser dispatches
  pointerdown/mousedown/click and the row wins its own target check).
