# T1 — the chip row in the composer base

## What exists

`MessageComposer.tsx`: `ComposerChip` (id/label/title/onRemove,
exported from the package index) + `chips?: readonly ComposerChip[]`;
row renders above the textarea in BOTH variants with
`<testId>-chips` / `-chip-<id>` / `-chip-<id>-remove` (so the chat
surface gets `agent-chat-composer-chips` and the home surface gets
`message-composer-chips` — same furniture, its own prefix). `ChatComposer`
passes `chips` through unchanged (it is part of the shared props).
Empty/absent renders nothing — an empty row would read as tidiness
about something that is not there.

## Notes

- The chip is deliberately NOT the attachment row: attachments are
  bytes that ride the send; chips are CHOICES that ride the send as
  text. Two receipts, two rows, no merged meaning.
- The base owns zero catalog knowledge — `title` carries whatever
  sentence the host supplies, which keeps the daemon's words flowing
  through without the component ever knowing what a skill is.
