Written by `golang-engineer-loop`; checked by the record pass (loop T20) against the committed code. Code:
`aeon/internal/tools/write.go`, `edit.go` and their tests, against the one resolver in
`aeon/internal/tools/paths.go`.

**The invariant the spec was reaching for, and where the code actually keeps it.** The spec's wording said the
resolver "stays in `files.go`"; the resolver has lived in **`paths.go`** since S5 and `files.go` only *calls*
it. Nothing was moved, and the structural test is what makes the intent checkable: **exactly one definition, in
`paths.go`, plus one call site per tool, and no private path handling in any tool file.** Four implementations of
the check are four chances for one to skip it (W18), so the test, not the prose, is the enforcement.

**Six deviations, all forced and all named in the sitting that made them.**

- **D1 — the `write_file` alias stamps its own name.** The spec said `func WriteFile() Tool { return Write() }`.
  A bare delegation reddens `TestEveryToolInTheRegistryIsUsableAndDescribed`, which requires
  registry-key == `Spec.Name`, and would show a step granted `write_file` a spec named `write` it was not
  granted — so the model would call `write` and hit O6. Shipped as `t := Write(); t.Spec.Name = "write_file"`
  with **Run-pointer identity** tested, so the behaviour is still one body.
- **D2 — a fixture flip the spec forbade.** `TestRerunClassesMatchCommittedList` **errors** on a `pending: true`
  entry that exists in the Registry, so adding the entries *mechanically requires* flipping `write`/`edit` to
  committed. Names, the `detectable` class values and the 11-count are unchanged — that flag's whole lifecycle
  is "declared-but-not-built → built", so the flip is the fixture working as designed. (Same forced-flip pattern
  T15, T16 and T17 each hit; the memory lesson is "expect companion edits".)
- **D3 — `toolset_test.go` is outside the spec's `File(s)` list** but hardcodes the exact registry name list; any
  registry growth must update `want`, and that update *is* the decision the W11 comment demands.
- **D4/D5 — wording pinned by the spec's own grep:** the delegation comment may not contain the literal
  `wrote %s`, so it references the sentence without quoting it (the engineer's own structural test caught this
  on first run).
- **D6 — the delegated alias's event prefix** became `write rel · size` while the content sentence
  `"wrote %s (%d bytes)"` stayed verbatim as pinned.

**Two argument facts the spec left open, and how they were settled.** An empty `old_string` is refused
**before** the resolver, because `strings.Count("", s)` returns `len+1` and would land it in the repeat-match
branch with a nonsense count — it is an argument fact, checked pre-resolve like `write`'s 1 MiB cap. The cap is
on the **result**: a 700 KiB file plus a 1 MiB replacement refuses **with the original intact** (tested).
Refusal wording mirrors `list`/`read`: `write refused %q: <Reason>` / `edit refused %q: <Reason>`, and the 0- and
2-match sentences use the spec's format strings verbatim.

**TOCTOU posture, stated rather than claimed.** Symlink containment is checked at `Resolve` time (post-resolution
`EvalSymlinks`; nearest-existing-ancestor for not-yet-existing targets) and the rename targets `resolved.Abs`.
This is the repo's **existing** posture, shared with the pre-existing `write`/`read` path; **no new atomicity
claim is made against a resolve→rename race, and nothing was weakened.** A reader who needs more than that
should read this paragraph as the limit of what S11 promises.

**Why `edit` failing loudly is load-bearing beyond convenience.** A stale `old_string` must fail, not fuzzy-match
and not no-op, because S7 classified `edit` as `detectable` on re-run *precisely* on that property (W19): a
fuzzy `edit` would make crash recovery re-run an edit and corrupt a file while believing itself safe. That is
`TestEditFailsLoudlyOnStaleString` and `TestEditIsNotFuzzy`, not a style preference.

# T7 — One path-enforcement point

## Why this exists

W2 exists because of a **recorded** bug: a model re-typed an absolute path wrongly — `/home/cjlapao` written as
`/home/cjayapao`. The MCP's fix was to take a slug so that no path ever leaves the model; the file tools take the same
medicine.

W18 makes it **one** enforcement point rather than one per tool, because five call sites with five implementations are
five chances for one of them to skip the check — and the one that skips is the one nobody tests.

It comes before `write`, `edit`, `glob` and `grep` (T8, T9) so none of them can build their own.

## Scope

```go
// Resolve turns a model-supplied path into an absolute path inside root,
// or refuses. The only path handling any file tool performs.
func Resolve(root, supplied string) (string, error)
```

Refuses:

- **absolute paths** — `/etc/passwd`
- **`..` traversal** — `../../etc/passwd`, and `a/../../..` which normalises outside
- **anything resolving outside the root**, including through a **symlink**

The root is supplied by the caller, **never by the model** (W2).

### The resolved path, not the written one (D18, I5)

**This is the case that separates a correct implementation from a plausible one.** A check on the *written* path
accepts `escape/passwd` where `escape` is a symlink to `/etc`; a check on the *resolved* path does not.

So: resolve symlinks, then verify containment — and verify it on the **fully resolved** path, not on a lexically
cleaned one.

**Answer Q8**: what method detects the escape, and does it work on every platform the build targets? Windows junctions
and macOS's `/tmp` → `/private/tmp` symlink both matter — on macOS a correct implementation must not refuse a
legitimate path merely because the root itself resolves elsewhere. Resolve **both** sides before comparing.

### Absorb, do not duplicate (Q7)

S5's `read` already resolves paths. **Absorb that handling into `Resolve`** rather than leaving two implementations —
which is precisely what W18 forbids, and leaving `read` alone would create the second implementation on day one.

Its behaviour must not change: S5's existing `read` tests pass unchanged.

### Not in scope

No permission check. Paths are about **where**, policy is about **what** — `bash` is guarded by T4's evaluator and file
tools by this. Conflating them would put file access under a pattern matcher built for command lines.

## Tests

| `TestAbsoluteAndDotDotRefused` | `/etc/passwd`, `../../etc/passwd`, and `a/../../../etc/passwd` all refused, each naming the path (D18) |

the prefix — passes every other test in this list.
