## Notes (T1, golang-engineer-loop, 2026-10-22)

**Measured on this checkout** (independently of the extractor, with a separate
`yaml.v3` harness, then re-confirmed from the committed `corpus.json`):
**75** agent `.md` files under `opencode/agents`, **38** carrying a `permission.bash`
block, **367** rules, **51** distinct patterns, **245 deny / 115 allow / 7 ask**.
The seven `ask` rules are the two in `git-loop` (`git reset --hard*`, `git branch -D*`)
and five in `github-steward`. `depricated/opencode/agents` (69 files) and
`reference-edition/opencode/agents` (4) are unreachable by construction: the walk is a
non-recursive `os.ReadDir` of the resolved agents directory, and a test snapshots the
source tree — path list, mode, size, sha256 — and requires it byte-identical after
generation, no file created either.

**Q1 (block-shape uniformity) — answered: the bash blocks are uniform; the front
matters are not.** Every authored `permission.bash` is a block-style mapping of quoted
or plain-string patterns to plain-string verdicts (comments after rules are fine and
kept). What is *not* uniform: **four files — `git-loop.md`, `project-initializer.md`,
`qa-engineer-loop.md`, `qa-runner.md` — author an unquoted `description:` plain scalar
containing `": "`, which strict YAML rejects** even though the `permission:` block
itself is well formed. Dropping those four would have dropped `git-loop` — the slice's
own worked example — from the corpus, so the extractor is **strict-first, then
recovers**: on a strict failure it extracts the top-level `permission:` block and parses
*that* strictly; rules are read through `yaml.Node` pairwise, so authored order survives
(`git-loop` records `git clean*: deny` at index 2, ahead of `gh pr merge*: allow` at 6).
A file whose *permission block itself* is malformed is a build failure naming the file.

**Refusals implemented** (each is a build failure, never an inert row): malformed
permission block; non-string pattern (kind/tag checked — `1: allow` is refused);
non-string verdict (`"x": true` and sequence values refused); any verdict outside
`allow|deny|ask` — a typo'd `allowd` stops `make ci`. `bash:` authored with no content
(null) and `bash: {}` both emit `"rules": []` — "authored, empty" is kept distinct from
"not authored" (that agent is omitted entirely). Duplicate patterns within one block
are preserved in authored order rather than refused; the cross-agent
`conflicting_patterns` property surfaces any pattern carrying more than one verdict.

**Properties as committed** (`corpus.json`, 33,534 bytes, deterministic — a second
`make corpusgen` is byte-identical): `wildcard_chars: ["*"]`;
`has_mid_star_pattern: true` (`docker buildx build*--push*`, `docker buildx bake*--push*`
— the matcher cannot be prefix-only); `has_exact_pattern: true` (`pwd`, `gh`,
`git branch --show-current`); `conflicting_patterns: ["*", "gh pr merge*", "git push*"]`
with `*` allow+deny, `gh pr merge*` allow+ask+deny, `git push*` ask+deny — the per-agent
irreducibility (G13), measured not transcribed. No count-shaped key appears anywhere in
the emitted JSON (a test greps the marshalled bytes for `"count` and `"total`), binding
the no-count rule to the generator as well as the tests.

**Deviations and why.** (1) `generate` takes `(agentsDir, outPath)` rather than the
single-argument sketch — the read-only-ground test in the task spec calls it with an
output path outside the source tree; `outPath == ""` means render-only, which is what
`--check` uses. (2) `main` delegates to `run(args, stdout, stderr) int` so the skip,
write and stale paths are testable without `os.Exit`; behaviour matches protogen's.
(3) `source` is recorded as the repo-relative `"opencode/agents"` whenever the resolved
directory ends in `opencode/agents` (the default-discovery case): an absolute path would
make `check-corpusgen` fail on every machine but the one that generated the file. An
explicit `--agents` override is recorded as passed.

**Why a missing agents directory is a NAMED skip, not a failure:** the corpus input
lives *outside* `aeon/`, and after the P24 extraction `opencode/agents` may not exist at
all in Aeon's own repository. A mandatory-but-absent input that the tool cannot own
must say so out loud and exit 0 — the same convention as `make test` printing why the
Rust half did not run — so `make ci` stays green in the extracted repository while the
committed corpus continues to carry whatever was last extracted from the monorepo.

# T1 — The corpus extractor

## Why this exists

**The corpus is the specification.** Not a fixture written to suit the matcher — the actual policy, already written
across this repository's agent definitions, which the matcher must satisfy.

It comes first because every matcher test is enumerated from it.

## Scope

### Extraction

`tools/corpusgen` reads `opencode/agents/*.md` front matter, pulls each `permission.bash` block, and emits
`internal/policy/testdata/corpus.json`: per agent, an **ordered** list of `{pattern, verdict}`.

Order matters and must survive extraction. G2 makes policy an ordered array precisely because v1's YAML *mapping*
depends on key order that the YAML spec does not guarantee — so the extractor must read the source order and record
it explicitly, never rely on a map's iteration.

**Answer Q1 first**: is the block's shape uniform across all 38 files? **If it is not, handle each variant and record
which files used which.** A file the extractor silently skips is an agent silently ungoverned, and it would look
exactly like an agent with no policy.

**It only reads `opencode/`, never writes it** (O7, standing constraint).

Committed generated output with a CI diff check, exactly as S9's protocol types are (O7). `make corpusgen` runs it by
hand.

### Properties, not counts (G19, D5, I2)

The extractor also emits the corpus's **structural properties**, and those are what the tests assert:

```go
type CorpusProperties struct {
    HasMidPatternWildcard  []string  // patterns with * not at the end
    HasNoWildcard          []string  // patterns with no *
    ConflictingVerdicts    map[string][]string  // pattern → the verdicts it receives across agents
    WildcardCharsUsed      []string  // must be exactly ["*"]
}
```

**No test in this slice asserts a count.** The superseded design transcribed three — 37 of 74 files, 354 rules,
104/243/7 — and re-measurement found all three stale, because an agent was added. Every *structural* claim held
exactly. Those properties are what G9 and G13 rest on, and they survive an agent being added; the numbers do not.

That correction is already landed in `docs/_archive/aeon-v1-horizontal/04-permissions/design.md`. **Do not re-edit it, and do not
reintroduce a count assertion.**

### What the properties currently are

Recorded here as the expected shape rather than as an assertion:

- **Mid-pattern `*`** — `docker buildx build*--push*`, `docker buildx bake*--push*`. This is why the matcher cannot
  be prefix-only.
- **No wildcard** — `pwd`, `gh`, `git branch --show-current`. This is why a pattern without `*` must match exactly.
- **Conflicting verdicts** — `*` is allow **and** deny; `git push*` is ask **and** deny; `gh pr merge*` is allow,
  ask **and** deny. This is why policy is irreducibly per-agent (G13).
- **`*` is the only wildcard character anywhere.**

If a future extraction finds a *fourth* wildcard character or loses the mid-pattern cases, that is a change to the
matcher's requirements and the tests should fail. That is the point of asserting properties.

## Tests

| Test | Asserts |
| --- | --- |
| `TestCorpusPropertiesHold` | Mid-`*` patterns exist; no-wildcard patterns exist; at least one pattern carries conflicting verdicts; `WildcardCharsUsed` is exactly `["*"]`. **No count** (D5) |
| `TestEveryPermissionBlockIsExtracted` | Every agent file containing a `permission.bash` block appears in the corpus. Asserted by independently counting files that contain the block and comparing to the corpus's agent count — **so a silently skipped file fails** |
| `TestRuleOrderIsPreserved` | For an agent whose block starts `"*": allow` followed by denials, the extracted order matches the file's order. A map-iteration bug reverses this test's outcome nondeterministically |
| `TestRegeneratingProducesNoDiff` | Run the extractor, `git diff --exit-code` on `testdata/corpus.json` (O7) |
| `TestExtractorOnlyReads` | A filesystem spy: no write, create or rename under `opencode/` |
| `TestVariantShapesRecorded` | If Q1 found more than one block shape, each is handled and the variant is recorded per file |

`TestEveryPermissionBlockIsExtracted` counting files **independently** is the point. Comparing the corpus to itself
passes while a parse failure silently drops an agent.
