# T3 — Segment splitting, and the limit that is documented rather than fixed

## Why this exists

`cd sub && git push origin main` must not pass because its **first** segment is harmless (G8). So a command is split
and **any denied segment denies the whole**.

And this task's second half is more unusual: it **documents what the matcher cannot do**, as a test and as
user-facing prose. The alternative — a half-complete shell parser — produces confident wrong answers, which is worse
than a stated limit.

## Scope

### Splitting (G8, O2)

Separators: `&&`, `||`, `;`, `|`, **and newlines** (O2).

Newlines are this brief's addition to the inherited set. The superseded design lists newline-separated commands among
what it does *not* catch, but **a multi-line command string is ordinary rather than adversarial** — a model writing a
two-line script is not obfuscating — and a newline is a separator in every shell. Splitting on it costs nothing and
closes an accident-shaped hole, which is exactly the class G8 targets.

Every segment is evaluated. **Any `deny` denies the whole**; any `ask` with no `deny` present makes the whole an
`ask`. The verdict names **which segment** produced it, because "denied" on a four-segment command is unactionable.

### The limit, stated (D11, O3)

Splitting is **not a shell grammar**. It does not understand:

- quoting — `bash -c "git push"`
- substitution — `git $(echo push)`, `` git `echo push` ``
- heredocs

So those are **not caught**, and `bash -c "git push"` evaluates to whatever `bash*` matches.

**This is asserted as a documented expectation** (D11), so nobody later reads it as a defect and nobody reads the
matcher as a sandbox. Two things make it acceptable, and both belong in the documentation rather than only here:

- **The corpus's denials target accidents, not adversaries.** An agent running `git push` when it should not is the
  threat. A model deliberately obfuscating a denied command is a different threat that **no pattern matcher
  addresses**.
- **The tool allow-list is the actual boundary.** An agent without `bash` cannot run anything at all.

**There is no sandbox.** Standing non-goal.

### Where the limit is documented (O3)

Not only in a design file — **where a user meets it**:

1. `aeon/docs/POLICY.md` — how policy works, what it does and does not cover, in plain terms.
2. **`aeon policy check`'s output**, when the command being checked contains a construct the splitter cannot see:
   a note saying the verdict covers the literal text and that quoting or substitution is not analysed.

3. **The `bash` tool description the model receives** (G20) — a limits string naming `bash -c`, `$( )` and
   backticks, and stating that **evading the policy violates it regardless of whether the matcher catches it**.

The second is useful to whoever is deciding whether their policy does what they think. **The third is the only control
that exists for the bypasses at all.**

That reasoning comes from the existing QA suite's QAP-05, which specified this before the design did: *"the mechanism
cannot stop this, so the instruction is the control."* A model told that `$(echo push)` is out of bounds will not
usually reach for it; a model never told may use it as an ordinary shell idiom without any intent to evade. **A missing
string is a failure even when the bypasses behave exactly as documented.**

## Tests

| Test | Asserts |
| --- | --- |
| `TestAnyDeniedSegmentDeniesAll` | `cd sub && git push origin main` denied, and the verdict names the **second** segment (G8, D10) |
| `TestAllSeparators` | `&&`, `\|\|`, `;`, `\|` and newline each split |
| `TestNewlinesAreSeparators` | A two-line command with a denied second line is denied (O2) |
| `TestAskWithoutDenyIsAsk` | A command whose segments yield `allow` and `ask` is an `ask` |
| `TestDenyBeatsAsk` | A command yielding both is a **deny** |
| `TestStatedLimitIsExpected` | `bash -c "git push"` is **not** split into a `git push` segment — asserted as the **documented expectation**, with a comment naming D11 so a future reader does not "fix" it (D11) |
| `TestSubstitutionIsNotAnalysed` | `git $(echo push)` likewise |
| `TestCheckWarnsOnUnanalysedConstructs` | `aeon policy check` on a command containing quotes or `$(` prints the note (O3) |
| `TestBashDescriptionNamesTheLimits` | The tool description the model receives contains the limits string, naming `bash -c`, `$(` and backticks, and the statement that evasion violates the policy regardless (G20, D22a) |
| `TestSeparatorsInsideQuotesAreStillSplit` | `echo "a && b"` splits — a **known** over-split, asserted as expected. Over-splitting is the safe direction: it can only produce extra denials, never extra permissions |

`TestSeparatorsInsideQuotesAreStillSplit` is worth having explicitly. The naive splitter over-splits, and the instinct
is to fix it by understanding quotes — which is the first step toward the half-complete parser this task refuses to
write. Over-splitting fails **closed**; that is the trade being made deliberately.
