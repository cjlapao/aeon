**The sentence a reader must not skim: there is no address-space restriction in this tool.** `webfetch` ships
**no SSRF guard**. Not because the risk was missed — it is named in the file's own doc comment rather than papered
over — but because the spec pins none and the slice DEMO's §7 depends on fetching a local header-echo listener.
What gates egress today is the **grant** (`Registered ≠ default-granted`: `DefaultGrant()` is `read, list, write`
and names no egress) and, from loop T19, the handler-policy attachment plus
`TestNoPresetGrantsWebfetchWhileTheHostSpaceIsUnscoped`. **Do not assume `169.254.169.254` is blocked.** The
open finding is tracked as **SEC-T16-01**, and the condition recorded at T19's audit is what the next person
must discharge *before* webfetch appears in any grant list, preset, example or walked demo step:

> the **SEC-T16-01 dial-seam** (a `DialContext` over **resolved** addresses, dialing the validated IP,
> default-deny `169.254.0.0/16` + link-local + metadata IP, with DNS rebinding closed **in the same change**)
> plus the **SEC-T16-02 header-budget wrapper** (same seam). **SEC-T16-09** sits on the same gate: the build
> toolchain must be ≥ **go1.26.10** before webfetch becomes grantable, because two client-relevant advisories
> (x509 distrust, HTTP/2 framing) sit on the `net/http` client path this tool uses.

**Because that seam is not in the tree, the walked record declines the §7 demo step.** `docs/aeon/DEMO.md` §S11
step 12 records the precondition verbatim and says the step is **deferred** rather than staging a loopback fetch
that would imply the gate had been passed. The operator-granted, **loopback opt-in** reading of §7 stands as the
only sanctioned shape for a local listener; what is missing is the address half.

**Three layers say "no credential", and each is a separate fact (I5).** (1) `webfetchRequestHeader` is the
**only** place a header is created, and it creates two entries. (2) The guard **replaces** the header map rather
than merging it — a merge would keep whatever a later edit adds — and refuses non-GET and any URL carrying
userinfo. (3) There is **no cookie jar** (`Jar: nil`), so `net/http` cannot store or restore a `Cookie`.
Supporting choices, all deliberate: `Proxy: nil`, because an ambient `HTTP_PROXY` may carry `user:pass` and
`net/http` would turn it into a `Proxy-Authorization` header — a credential from ambient state arriving through a
tool that promises none; `DisableCompression: true`, so the header set asserted in the tests **is** the wire set;
and unknown arguments die at the **decode** layer naming the argument with **zero requests made**, because
ignoring an unknown key would let a model try smugglers and only learn about the ones this decoder happened to
notice.

**Same-origin is stricter than the design asked for.** Same-origin means **scheme + host + port** with
default-port normalisation, and a **scheme change is a refusal** rather than a follow — the safer answer to "did
the server just move me?" is to say so and let the caller ask for the `https` URL deliberately. `WebfetchMax-
Redirects`, `WebfetchTimeout` (30 s), `WebfetchBodyCap`, `WebfetchBodyCountCeiling` (32 MiB, beyond which the
report says **"at least"** — P31) and `WebfetchMaxURLBytes` (4 KiB) were chosen where the spec left them open;
the `User-Agent` and `Accept` strings are pinned, and a test checks that `Accept` agrees with the tool's own
allow-list rather than drifting from it.

**Two dead branches deleted rather than performed tests for** (the S3-T4 precedent), both with a proof in the
commit: `checkRedirect`'s nil-URL guard (`net/http` always builds the URL before calling) and `renderWebfetch-
Body`'s `total == 0` guard (reaching that branch implies `total ≥ len(kept) > cap`). A test for unreachable code
is a test that passes forever.

# T10 — `webfetch`

## Why this exists

Fetching library documentation is the use case across every agent that declares this tool. Everything else it could do
is a liability.

## Scope

**GET-only, size-capped, timeout-bounded, and it never sends a credential header** (W9).

### No credential, ever (D20)

No `Authorization`. No `Cookie`. No bearer token. No API key header. Not configurable, not overridable per call.

The tool builds its own request headers from a fixed set — a `User-Agent` and `Accept` — rather than starting from a
default client and removing things. **Removal is a list that gets out of date; construction is not.**

### A POST is refused (D20)

Method is not a parameter. A POST is an **exfiltration path nothing needs** — and the model has no legitimate reason to
send a body to an arbitrary host.

### Redirects (O4, D20)

**This is where a "GET-only, no-credential" fetcher classically leaks.**

- A same-host redirect is followed, up to a bounded count.
- A **cross-host** redirect is **not** followed silently: it returns a result naming the target, so the model can decide
  to fetch it as a new call.
- The original request's headers are **never** replayed to a redirect target.

A fetcher that follows redirects blindly turns any URL a model can be persuaded to fetch into a request to a host
somebody else chose.

### Bounds

- A size cap, with **truncation reported** in the result (W13's discipline)
- A timeout (W3's reasoning: a hung fetch stalls an unattended loop)
- `exec.signal` honoured (W10)

### No captured headers in the record

**A recorded capture must never include request headers with credentials** — there are none to include, which is the
point, and the recording must not become the place one appears. `aeon debug last-fetch --headers` exists for the demo
and prints what was **actually sent**, redacting anything credential-shaped as `<redacted>` in case a future change
introduces one.

That redaction is belt-and-braces on a tool that should have nothing to redact. It is cheap, and the failure it guards
against is a token in a committed test fixture.

### Re-run class

`safe` (S7's W16): read-only, and the no-credential rule means a repeat leaks nothing new.

## Tests

| Test | Asserts |
| --- | --- |
| `TestNoCredentialHeaderEverSent` | Against a local listener recording headers: **no** `Authorization`, `Cookie`, `X-Api-Key`, or any bearer token. Asserted on the **recorded request**, not on the code's intent (D20, C9) |
| `TestHeadersAreConstructedNotFiltered` | The request carries exactly the fixed set. A test that adds a header to the default client and expects it absent proves the construction approach |
| `TestPostIsRefused` | Method is not a parameter; an attempt to specify one fails (D20) |
| `TestCrossHostRedirectIsExplicit` | A redirect to a different host is **not followed**; the result names the target (O4) |
| `TestSameHostRedirectIsFollowedBounded` | Followed, up to the cap; a redirect loop terminates |
| `TestRedirectDoesNotReplayHeaders` | Even the fixed headers are rebuilt for the target rather than replayed |
| `TestSizeCapReportsTruncation` | An oversized response is capped and the truncation is **in the result the model sees** |
| `TestTimeoutBounded` | A slow listener produces a timeout, not a hang |
| `TestHonoursSignal` | A cancelled context aborts an in-flight fetch (W10) |
| `TestDebugFetchRedactsCredentialShapedHeaders` | If a credential-shaped header somehow exists, the capture shows `<redacted>` |
| `TestNonHTTPSchemesRefused` | `file://`, `ftp://`, `data:` all refused. A `file://` fetch is a path-traversal tool wearing a URL |

`TestNonHTTPSchemesRefused` is worth having explicitly: `file://` would bypass T7's path enforcement entirely, through
a tool nobody thinks of as a file tool.

## Definition of done

- [ ] GET-only; method is not a parameter
- [ ] Headers **constructed** from a fixed set, never filtered from a default
- [ ] No credential header of any kind, asserted on the recorded request
- [ ] Cross-host redirects returned rather than followed; headers never replayed
- [ ] Same-host redirects bounded; loops terminate
- [ ] Size cap with truncation reported; timeout bounded; signal honoured
- [ ] `file://`, `ftp://` and `data:` refused
- [ ] Debug capture redacts anything credential-shaped
- [ ] `make test`, `make lint` green
