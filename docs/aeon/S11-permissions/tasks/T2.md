1. **The spec's rationale for `len(rest) >= len(last)` is inaccurate.** `strings.HasSuffix` already performs

   (`a*a`/`a`, `ab*ab`/`ab`, `aa*aa`/`aa`, `*x*x`/`x`), and the mutant is kept in the test file so the proof is
   re-run every time. The clause was **kept** (the spec pins the implementation, it costs nothing, and it is the

   the spec's claim.
2. **The bare `*` pattern cannot have a negative probe** — it matches every string including `""`. The probe
   table carries it with a `noNegative` reason and the test asserts universality over nine commands instead of
   skipping. Any *other* pattern declaring `noNegative` is itself a failure, and a pattern missing from the
   table is a failure, so "one match + one non-match each" holds for every pattern that can have one and the
   remaining one is held to the property that replaces it. Nothing is silently skipped.
3. **Two of the engineer's own expectations were wrong and were corrected against the grammar, not the code:**
   `docker buildx build*--push*` **does** match `docker buildx build --push --platform x` (a mid-star plus a
   trailing star places `--push` anywhere after the prefix — it does not pin order after it), and an
   `a\\*b`/`a\*b` fixture was confusing enough to replace; the pinned case is now `a\*b` matching `a\XXb` but
   not `ab`. Both are cases in the table.

**Grammar as shipped, from the closed set rather than a description:** `*` is the only wildcard character
anywhere (asserted from the corpus's own `wildcard_chars`), a pattern **without** `*` must match exactly (this

**Left for the reader:** the matcher has no opinion about shell grammar. It does not understand quoting,

**accidents**, and a model deliberately obfuscating a denied command is a different threat no pattern matcher
addresses. `docs/aeon/S11-permissions/DEMO.md` §4 says this; the walked record restates it because it is the

# T2 — The matcher

## Why this exists

**The smallest, most-tested, highest-consequence code in the slice**, and it gets its own task (R6) because a matcher
that gets one case wrong passes almost every other test while silently over-permitting.

Every property below is a **measurement**, not a preference (G9). Each traces to the corpus T1 extracted.

## Scope

```go
// Match reports whether cmd matches pattern. Pure.
func Match(pattern, cmd string) bool
```

### Three properties, three sources

| Property | Traces to |
| --- | --- |
| `*` may appear **anywhere**, including mid-pattern | `docker buildx build*--push*` and `docker buildx bake*--push*`. **A prefix matcher cannot express these**, so prefix matching is not an option |
| A pattern with **no** `*` matches **exactly** | `pwd`, `gh`, `git branch --show-current` |
| `*` is the **only** wildcard | Nothing else appears in 50 patterns. `?`, `[a-z]`, `{a,b}` and `**` are **literal characters** |

### The one that matters most (D1)

**`gh pr merge` against a policy whose only `gh` rule is the bare word `gh` must be DENIED.**

A matcher that assumes a trailing `*` — which is the natural implementation, because most patterns have one — matches
`gh pr merge` against bare `gh` and **permits it**. That is a **silent over-permit**, and over-permitting is the worst
failure direction a guard has: nothing errors, nothing logs, and the command runs.

Write this test first. It is the one that distinguishes a correct matcher from a plausible one.

### Implementation note

`*` translates to "any sequence, including empty". Every other character is literal, so a pattern must be escaped
before translation — `git branch --show-current` contains `-` and `.` may appear elsewhere, and a regex built by naive
substitution would treat them as syntax.

`Match` is **pure** and takes no options. A matcher with a case-sensitivity flag is a matcher with two behaviours, and
the corpus has one.

## Tests

Enumerated from T1's corpus (D4): for **every** pattern, a command it must match and a command it must not.

| Test | Asserts |
| --- | --- |
| `TestNoWildcardMatchesExactly` | `gh` matches `gh` and **not** `gh pr merge`; `pwd` not `pwd -P`; `git branch --show-current` not `git branch --show-current --quiet` (D1) |
| `TestWildcardAnywhere` | `docker buildx build --platform linux/amd64 --push` matches `docker buildx build*--push*`; a command with the parts in the wrong order does not (D2) |
| `TestStarIsTheOnlyWildcard` | `rm -r?` does not match `rm -rx`; `rm -r[abc]` does not match `rm -ra`; `git **` behaves as two literal stars (D3) |
| `TestEveryCorpusPatternMatchesAndRejects` | All 50 patterns, each with a positive and a negative case, enumerated from the corpus (D4) |
| `TestPatternMetacharactersAreLiteral` | A pattern containing `.`, `+`, `(`, `[` and `$` matches those characters literally — proving escaping happens before translation |
| `TestEmptyPatternMatchesNothing` | Not "matches everything", which is what an unescaped empty regex would do |
| `TestMatchIsPure` | No I/O, clock or environment; the same inputs give the same answer |

## Definition of done

- [ ] `*` matches anywhere, including mid-pattern
- [ ] A pattern with no `*` matches exactly — **D1's test written first**
- [ ] `*` is the only wildcard; every other metacharacter is literal
- [ ] Every corpus pattern has a positive and a negative test
- [ ] An empty pattern matches nothing
- [ ] `Match` is pure and takes no options
- [ ] `make test`, `make lint` green
