## Why this task exists

`agent_import` is the sixth proposal kind (S37). Its effect path is agent-import code — `internal/plugin` (S15) — which
**S43 is rewriting** (cards, signature, versioning, slugs). S43 is being built and cannot be changed from here, so
S45 T1/T5 deliberately left this one kind committable only through the CLI (`proposal.commit` over the socket answers
"not available yet — use `aeon proposal commit`", and the UI shows the exact CLI command). That leaves a gap against
the operator's rule "anything the CLI has must exist on the daemon". This task closes it **after S43 has merged**, as
S45's own change, on S45's branch — it is *not* a request to S43.

If S43 changes or removes the `agent_import` kind, or merges in a shape this task cannot adopt without changing S43's
behaviour, T10 stops, records why, and closes **"not applicable"** (or re-plans inside S45 with the operator). The slice
is then **Partial** with this gap stated — never silently Built.

## Step 2 — The change

- **Register the kind's effect through the existing seam.** T1 declared `agent_import` as a `desk.Seams` kind whose
  effect `cmd/aeon serve` supplies (so `internal/daemon` imports no plugin code). T10 supplies the three funcs
  (`Validate`, `AlreadyApplied`, `Apply`) from the code the CLI already uses — the *same* functions, moved or exposed,
  not a second implementation — and registers them in `serve`. The CLI's `agent_import` arm becomes a call to the same
  registry entry (so there is one implementation, as for every other kind).
- **`proposal.commit` for `agent_import`** now follows the generic path (T5): digest-bound, effect-then-flip with the
  crash-safe retry, before/after (for an import: the agent roster/lifecycle state before and after, rendered by the
  same preview helper S37 built — never reformatted), audit (`policy_change` is policy-specific; record this commit in
  the **proposal row's own** decide fields — `decided_by_*` — and, if S43 added an agent-change audit, use it; **do not
  write an `agent_import` row into `policy_change`**: it is an authoring audit for policy, T0/T3's vocabulary has no
  such op).
- **R6 stands.** `agent.import/install/uninstall/update` as *direct* socket methods stay absent
  (`TestNoPluginManagementOnNarrowSurface` unchanged and green): the only way an agent is imported over the socket is
  **a previously created, validated proposal committed by a person**. The change updates the T5 refusal sentence to the
  new behaviour and removes the "(S45 T10)" pointer from the UI's disabled-commit text.
- **UI:** the Proposals tab's `agent_import` card enables Commit with the same confirm-with-preview flow (T9), the
  preview being S37's `AgentImportPreview`. No other UI change.
