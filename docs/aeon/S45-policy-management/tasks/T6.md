### The hash mechanism, chosen and recorded (the spec leaves the choice to this task)

`TestOriginalGuardsAreByteIdentical` pins the pre-amendment assertion **LOGIC** of the five
superseded/amended guards by: **(1) EXTRACT** the function with `go/ast` (FuncDecl — `func`
keyword through its own matching `}`, doc comment excluded); **(2) UNDO the recorded listed
amendment** — each line the amendment added must appear EXACTLY ONCE and is deleted, and the one
recorded non-additive edit (T5's predicate line in `TestOnlyProposalIsSocketWritable`'s §7 walk) is
recorded as a `{current, pre-amendment}` replacement and reversed. A reverse-op that does not apply
fails the test: a pin whose record no longer matches the body is not a pin; **(3) NORMALISE** to
assertion logic — drop blanks, comment-only lines, the `t.Skip(...)` first line, and the whitelist
`map[string]bool{…}` DATA blocks (the half option 1 lets grow; the assertions are not); **(4)
SHA-256** the remaining lines joined by `\n` with a trailing newline, hex.

Pinned values were produced by that same code from `git show <parent-of-the-amending-commit>:<file>`
(T4's parent `3cf22736`, T5's DATA parent `a0388ecd`, T5's supersession parent `48b36239`) and
cross-check against the pre-amendment BODY digests T0/T4/T5 recorded with their `awk` recipe — with
ONE difference worth knowing: `awk '/func NAME/,/^}/'` stops at the first column-0 `}`, which for
`TestOnlyProposalIsSocketWritable` is a line INSIDE its inline canary's raw string, so T0's recorded
`013de5bf…` covers 45 of that body's ~112 lines. `go/ast` cannot be fooled that way, which is the
only reason the pin re-extracts rather than reusing the recorded digests. The teeth-check proves the
mechanism sensitive: replacing the narrow guard's (b)-clause condition with `if false` changes the
digest (had it not, the pin would be decoration).
