# T1 · Characterize the CLI, then extract `internal/desk`

**Prefix:** PM · **Rules:** PM2, PM4 (one implementation), PM11 · **Depends on:** T0.

## Goal

The effect code a socket commit needs lives in `cmd/aeon` and the daemon cannot import it (design fact 5). Move it to a
new `internal/desk` package **without changing a byte of behaviour**, with the CLI still working as it does today. This
is a pure refactor and the slice's riskiest mechanical step, so it is done **characterization-first**: pin what the CLI
prints and writes *before* touching it, then move, then prove the pins still hold.

### Phase A — three things the task's table guessed wrong, pinned as they are

1. **`proposal-reject` without a reason is not refused.** TD5's own text ("rejecting loosens nothing, so
   the CLI requires no reason but accepts the empty one") is what the code does; `proposal-reject-without-reason`
   pins the success. The reason-mandatory door is PM7.5's, and it belongs to the socket (T5).
2. **`--tool NAME` alone cannot author a `tool_access` row** — the sugar writes `toolName` only, and the
   boundary's validator requires `state`, so the accepted form is `--tool bash --spec '{"state":"deny"}'`.
   The goldens use it; the parity table should say so (T8's evidence).
3. **A flag after the positional id is not the verb's shape.** `aeon proposal reject 1 --reason "…"` is
   refused (`reject takes exactly ONE id`) because Go's flag parser stops at the first non-flag argument;
   the working spelling is `reject --reason "…" 1`. Both are pinned (`proposal-reject-reason-after-id`).
4. The MCP kinds' commit door behaves as TD4 says and as no table row spelled out: an `mcp_server_remove`
   whose config is absent is **already-applied** and the flip completes, while an `mcp_server_add` with no
   config is legitimate and creates the file. Pinned as `proposal-commit-mcp-no-config-remove` and
   `-add-no-config`.

### The seam signatures, who registers them, and who may import `internal/mcp`

```go
type Boundary interface {                                       // internal/desk/boundary.go
    AddPolicy(ctx context.Context, p policy.Policy, now time.Time) *policy.Reject
    RemovePolicy(ctx context.Context, id string) (bool, error)
    ListPolicies(ctx context.Context, at time.Time) ([]policy.Policy, *policy.Reject)
    RecordAuthoredPolicy(ctx context.Context, subject, policyID string, at time.Time) *policy.Reject
}
type BoundaryOpener func() (Boundary, func(), error)            // opened per effect, closed before returning
type Deps  struct { Boundary BoundaryOpener; Clock func() time.Time }
type Seams map[Kind]Effect
type Effect struct {
    Validate       func(ctx context.Context, payload []byte) error
    AlreadyApplied func(ctx context.Context, payload []byte) (bool, error)
    Apply          func(ctx context.Context, w io.Writer, payload []byte) error
}
func New(deps Deps, seams Seams) *Registry                       // read-only afterwards
func (r *Registry) Effect(kind string) (Effect, bool)             // false ⇒ Missing(kind) names the half
func (r *Registry) Missing(kind string) string
func (r *Registry) ValidateProposal(ctx context.Context, kind, payload string) error
func (r *Registry) AlreadyApplied(ctx context.Context, kind, payload string) (bool, error)
func (r *Registry) Apply(ctx context.Context, w io.Writer, kind, payload string) error
func RunSeedCorpus(ctx context.Context, w io.Writer, b Boundary, agents []string, dryRun bool, at time.Time) error
func SeedPolicyID(agent, pattern string) string
func ResolveSeedTargets(corpus policy.Corpus, agents []string) ([]SeedTarget, error)
```

### Deviations from the task's own text, and why

1. **`Effect.Apply` carries an `io.Writer`** (the task's struct had `Apply(ctx, payload)`). Two effects print for the human at the door — `agent_import`'s fresh consent (AA4, through `importAgentPackage`) and the seed runner's per-agent lines — and smuggling a writer through the context would be worse than naming it. `seed_corpus`'s apply still passes `io.Discard`, because the commit door never printed the seeder's progress and still does not.
2. **`Deps.Boundary` is an opener returning the `Boundary` seam, not a `*policy.Store`** (the task's text said the boundary itself).
