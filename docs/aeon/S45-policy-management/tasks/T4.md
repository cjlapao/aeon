# T4 · Socket authoring: `policy.add`, `policy.remove`, `policy.seedCorpus`

**Prefix:** PM · **Rules:** PM1, PM2, PM7 (before/after), PM8, PM11 · P34 · **Depends on:** T1, T2, T3.

## Goal

The daemon can author policy: add a rule, remove a rule, seed the shipped corpus (with a dry run) — over the socket, as
the human door (PM1), through the **same `internal/desk` code** the CLI uses, stamped with the peer identity, returning
the in-force sentence **before and after**, and leaving one audit row. PL1 holds verbatim. The methods are **not**
reachable from the narrow surface, agent services, tools or the records catalog — T6 pins that; this task must not
weaken it even temporarily (it lands behind T6's amended guards only once both are on the branch; see "Ordering").

## Wire shapes

```go
type PolicyAddParams struct {
    ID       string          `json:"id"`
    Type     string          `json:"type"`
    Target   PolicyTargetP   `json:"target"`            // {kind, id}
    Action   string          `json:"action"`
    Spec     json.RawMessage `json:"spec"`
    Source   string          `json:"source"`            // defaults to "operator" server-side when omitted — the CLI's default
    NotAfter *string         `json:"notAfter"`          // RFC3339 or null (never a sentinel, PL7)
}
type PolicyAddResult struct {
    Policy  PolicyDetail `json:"policy"`                // as policy.get would return it
    Warnings []string    `json:"warnings"`              // DEF-038's unmatchable-target warning etc., verbatim
    Before   InForceView   `json:"before"`            // InForceAnswer.Render() for the target, verbatim (D14)
    After    InForceView   `json:"after"`
}
type PolicyRemoveResult struct { Removed bool `json:"removed"`; Before InForceView `json:"before"`; After InForceView `json:"after"`; Policy *PolicyDetail `json:"policy"` /* the row as it was */ }
type SeedCorpusParams  struct { Agents []string `json:"agents"`; DryRun bool `json:"dryRun"` }
type SeedCorpusResult  struct { PerAgent []SeedAgentCount `json:"perAgent"`; Seeded, Unchanged int; DryRun bool }
```

`Source` on the **socket** is accepted (the CLI exposes `--source`), but PL1 applies exactly as everywhere: an `allow`
with a non-operator source is refused by `checkAuthorship` with PL1's sentence, carried verbatim. The **actor is never
a param** — `decodeParams` uses `DisallowUnknownFields`, so `{"actor": …}` is a shape error.

## Behaviour

1. **Order for `policy.add`** (each step a refusal before the next): resolve the actor via `table.ActorFor`
   (`ErrPolicyNoActor` if unresolvable — never a placeholder) → decode params strictly → build the `policy.Policy` →
   **`boundary.Add(ctx, p, now)`** (the *one* write boundary; the service does not re-validate — the CLI's pinned
   "one round-trip" property) → on success compute `InForce` for the target **before** (captured *before* the write)
   and **after** → write the `policy_change` row (`op='add'`, `policy_id`, a fixed-template summary:
   `"added <type> <action> for <target>"`, ids only) → return.
2. **Before/after** uses the existing `InForceAnswer` for the target the policy names (`all-agents` →
   the all-agents answer). The sentence is `Render()`'s output, **never** reformatted.
3. **`policy.remove`**: capture the row and the before-state, `boundary.Remove`, then after-state and audit
   (`op='remove'`). Removing an absent id is `removed:false`, no audit row, no error (DB19). Removing a **system** row
   (`origin='system'`) is allowed (PM16 — an operator's choice) and says so in the summary; the engine then reports that
   record `removed` and `seed.apply` will **not** resurrect it (T12).
4. **`policy.seedCorpus`** (**depends on T12**): a thin method over **`seed.Engine.Apply(set:"policy.corpus", via:explicit)`**
   — the same engine path `seed.apply`, `aeon policy seed-corpus` and a committed `seed_corpus` proposal use; it adds the
   per-agent filtering/`dryRun` semantics and the policy-flavoured result, and writes **one** `policy_change` row per run
   in addition to the engine's `seed_event`. It never writes rows itself. Calls `desk.RunSeedCorpus` only as the printer; `dryRun:true` writes **nothing and
   audits nothing** (a dry run is a read); a real run writes through the boundary exactly as the CLI does, calls
   `RecordAuthored` for each seeded subject as the CLI verb does (**the daemon's authoring service becomes the second
   sanctioned `RecordAuthored` caller — T6 adds it to `allowedAuthored`**), and writes **one** `policy_change` row
   (`op='seed'`, summary `"seeded <n> rules across <m> agents"`). Unknown agents are refused naming them (the same
   `resolveSeedTargets` refusal). Idempotent: a second real run reports `unchanged`, audits nothing new.
5. **No cache, no goroutine, no queue.** The next `policy.why` after a successful add reflects it (PM11).
6. **Crash gap** (T3's note): a crash between the write and its audit row is reported by the reconciliation read, not
   hidden. Implement `PolicyChangeMissing` use in `policy.changes` here (T3 left the field `[]`).
