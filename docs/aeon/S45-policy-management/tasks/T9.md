## Goal

A person manages policy from the real app, with details visible, authoring driven by the daemon's vocabulary, every
widening or removal behind a before/after confirmation, and the proposals desk able to commit and reject. **Nothing
in the UI knows the closed sets, the authorship rule, or a sentence — it renders what the daemon sends.** This is the
Settings surface (the real app), not a bench tab: `benchRegistry.ts` does not apply and the bench `PolicyPage`/
`ProposalsPage` are untouched.

## Behaviour

### Rules tab — the list with details

1. `policy.list` (with the filters sent as params, **filtering happens in the daemon**) rendered as a table: target,
   type, action (a `Pill` coloured by action — allow/deny/ask, with text as well as colour), the `describe` sentence,
   source, expiry (`RelativeTime`, "expired" shown, not hidden), id. Grouped by target on a toggle.
2. Filters: type, target kind + id (via `AgentPicker` for `agent` targets), source, action, "include expired". An empty
   result shows the **filter statement**; an empty store shows the D4 sentence — the daemon sends both.
3. Row → **detail drawer** (`policy.get`): all fields, the raw `spec` read-only in a code block, the `describe` sentence,
   acceptance and authored flags, and the audit history for that id (`policy.changes {policyId}`).
4. **Remove** (drawer): a confirmation (`useConfirm`) naming the policy, its `describe` sentence, and — fetched with a
   `policy.inForce` call for the target — the current in-force answer; on confirm call `policy.remove`; show the
   returned `before`/`after` in a result `Alert` (verbatim). A **system** row (`origin='system'`)'s confirmation adds the
   daemon-sent line that it is a shipped rule, that removal is allowed, and that it **will not be re-added by a re-seed**
   (restore is explicit — PM16). Every row shows an **origin badge** (`System` / `User`), and the list has an `origin`
   filter (a daemon filter param). A system row has **no edit affordance** (policies have none); the drawer says "to
   change this, add a rule — a `deny` outranks it (PL4)" using text the daemon sends in `policy.get`.

### Authoring form (a button on the Rules tab)

5. Loaded from `policy.vocabulary` **once** per session (cached in component state seeded from the response; refetched
   on reconnect). Fields: type (select over `vocabulary.types`), target kind (select) and target id (`AgentPicker` for
   `agent`; text with the identifier rules' hint for `loop`/`lane-type`/`mcp`; **none** for `all-agents`), action
   (select), spec (rendered from the type's `SpecField[]` descriptor: enum → select, string → text with `maxLength`,
   number → numeric), source (defaults `operator`), expiry (optional date-time; empty = **no expiry**, never a
   sentinel), id (suggested from type+target, editable).
6. **The authorship rule is rendered from the matrix**: choosing `allow` with a non-operator source disables Submit and
   shows the daemon's own PL1 statement (from `vocabulary`'s matrix `reason`), **never** UI-authored wording.
7. **Submit flow:** `policy.add`; if the action is `allow` **or** the target is `all-agents` **or** the policy would
   widen anything the `before/after` shows changed, the UI first shows a confirmation with the `describe` sentence and
   the target's current in-force answer, then — after `policy.add` — the returned `before`/`after`. A refusal shows the
   boundary's sentence verbatim under the form and **keeps the draft** (no silent reset — S35 test map #6 parity).

### Seed corpus

8. A "Seed shipped corpus" action — **the `policy.corpus` seed set** (S43-extra's engine; this is the Policy-section view
   of the same set the System records panel lists, `seed.status`): `policy.seedCorpus {dryRun:true}` first, rendering the
   per-agent counts table (agents × seeded/unchanged/**removed**/**diverged**, from the engine's per-record states); a
   second explicit **guard confirmation** (this set adds `allow` rows) runs `{dryRun:false}`; the result is shown. Records
   the operator removed are shown as `removed — restore?` with a per-record restore (`seed.restore`, confirm). Agent
   filter via `AgentPicker` multi-select. The dry run never writes (daemon-enforced, T4). The UI shows the set's
   **available vs applied version** from `seed.status`, so "the shipped corpus has changed since you applied it" is visible.

### Proposals tab — the desk with decisions

9. `proposal.list` (status filter, default `proposed`), each card: kind, who proposed (kind/id), when, `reason` (for
   agent proposals), the **live-vs-proposed preview** from `proposal.get`, and — for `agent_import` until T10 — a
   disabled commit with the daemon's honest sentence and the exact CLI command (the existing `command` field).
10. **Commit**: opens `useConfirm` with the preview and the current in-force; on confirm `proposal.commit {id, digest}`
    with the digest from the `proposal.get` the card displayed; show `effectApplied`, `before`, `after`, `warnings`.
    **Reject** requires a reason (an `Input`, required, ≤ 512); `proposal.reject`. **Discard** stays as S35 had it
    (socket `proposal.discard`, proposals the viewer's own).
11. A **"proposed by an agent"** badge (kind `agent`) so a person sees which restrictions agents asked for.

### In force tab and Audit tab

12. **In force:** a form (agent via `AgentPicker`, loop, lane type, MCP server, type, the question's field, `at`)
    calling `policy.inForce` and `policy.why`, rendering the daemon's sentences verbatim and the **three states**
    (D14) as three visibly different results; `unimplemented` rendered as its own state, not as a denial (SEC-033).
13. **Audit:** `policy.changes` newest first, with the `unauditedPolicyIds` reconciliation shown as its own warning
    ("these policies have no audit row — a crash between the write and its record"), never as "nothing happened".

### Cross-cutting

14. **No client-side vocabulary, matrix, sentence or id generation beyond the suggested id**; a grep test asserts the
    section's files contain none of the literals `tool_access`, `command_access`, `all-agents`, `lane-type`
    (they come from `vocabulary`), except in the i18n *test fixtures*.
15. Offline/reconnecting (`live.state !== 'current'`): reads render last data; every write control is disabled with the
    kit's reconnecting affordance.
16. **No `localStorage`** for policy data; component state seeded from the last response only.
17. **Accessibility basics:** the action pill carries text; confirmation dialogs trap focus (the existing
    `useConfirm`); the table is a real table with headers.
