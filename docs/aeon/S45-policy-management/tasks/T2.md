# T2 · Detail reads: `policy.get`, richer `policy.list`, `policy.vocabulary`, and the one formatter

**Prefix:** PM · **Rules:** PM5, PM6, PM11 · P34 · **Depends on:** T0. Parallel-safe with T3 (no shared file).

## Goal

Make policy a **list with details**: every rule's full content and a one-sentence description are readable over the
socket, the list can be filtered, and the closed vocabulary plus per-type spec shapes are served by the daemon so no
client hardcodes them. All additive and read-only; `policy.list`'s existing fields and `PolicyListEmptyStatement` are
unchanged.

## The filter semantics (one place, in the daemon)

Filters are applied **after** `store.List` (which re-decodes every row fail-closed, SEC-015), in `internal/policy` as a
pure `Filter(ps []Policy, f ListFilter, at time.Time) []Policy` so the CLI's offline fallback and the daemon share it.
`target` accepts the CLI's spelling (`agent:NAME`, `loop:SLUG`, `lane-type:NAME`, `mcp:NAME`, `all-agents`) parsed by
`ParseTarget` — an unparseable target is `ErrBadParams` naming it. Unknown `type/source/action` are refused through the
closed-set parsers, naming the value. A filter that matches nothing returns an empty list **with** the statement
`"no policies match this filter."` (distinct from the empty-corpus D4 sentence, so the two empties never read the same).

**Deviations, and why.**

1. Stub types' state enums are PROBED through each validator (`specSchema.acceptsState` builds a
   schema-shaped probe spec and asks `ValidatorFor(typ).Validate`) rather than restated — PM6's own word
   is that descriptors come "derived from the validator"; a restated enum would be the second truth the
   method exists to delete. `TestSpecDescriptorsCoverEveryType` re-derives acceptance independently.
2. `Describe` carries a second fixed sentence for rows that could not have come through the write
   boundary (`a policy of type %q whose row is not one the engine reads — nothing enforces it`). The
   spec pinned only the unregistered-type sentence; echoing unreadable raw bytes into a printed sentence
   would be SEC-046 re-imported through the formatter. Both sentences are fixed strings; nothing is
   assembled from refused content.
3. `describe`/`createdAt` are `omitempty` despite never being empty from a current daemon: absence is
   the meaningful fact of a pre-S45 renderer (the pre-S45 fixtures and old clients must round-trip
   byte-identical — measured: without `omitempty` the existing `list-one-rule.json` round-trip fails on
   the materialized empty fields). The task's "omitempty only where absence is meaningful" licenses
   exactly this; `TestPolicyListUnchangedWithNoFilter` is the pin.
4. The filter lives in `internal/policy` (`filter.go`) — the task said "one place, in the daemon" but
   named no file; the CLI's offline fallback (T8) must share the exact predicate, so the engine package
   is the one place both can reach without an import inversion.
5. Refusal doors: type/source/action → verbatim `-31400` `policyRefusal` (mirrors `policy.why`'s
   SEC-046 precedent — a closed-set parser's sentence is the boundary's own); malformed target →
   `-32602 ErrBadParams` naming it (the task's explicit "unparseable target is ErrBadParams naming it").
   `policy.get {id}` does NOT gate the id through `CheckIdentifier`: the id is equality-compared against
   a re-decoded store answer (no injection surface), and the nearest-ids refusal is strictly more useful
   than a params error for the mistype case the spec's "typo turns into a pick" clause serves.
6. `Empty()` counts `IncludeExpired == false` as a criterion (it removes rows), so a corpus whose every
   row is hidden answers the FILTER's sentence — D4's "nothing is granted" would be confident and wrong.
7. `authored` is answered over the subject's whole audit slice (`limit = math.MaxInt32`, the table is
   already 90-day-capped): a windowed scan could report false beside a row that exists, and an
   informational field that can lie is worse than none. Targets outside `agent`/`loop` answer false
   without asking — `parseSubject` makes such a row impossible at the write side, so it is a stated
   truth, not a gap.
