## The migration drill

Two new migration files (`policy_change`, `policy.origin`), so the drill is short but is **run** (add: the `origin` backfill marks `corpus.%` rows `system` on an upgraded store, and `policy` row counts are unchanged):

1. **Fresh apply:** a new temp store → table, two indexes, two triggers exist.
2. **Upgrade apply:** a store created at the commit before the migration → open with the new binary → the migration
   applies; counts of `policy`, `policy_event`, `proposal` unchanged.
3. **Idempotent re-open:** no second apply; one ledger row for the file.
4. **Append-only:** `UPDATE`/`DELETE` on `policy_change` fail with the trigger text (or the documented fallback test).
5. **Retention:** `PolicyEventTrim` far in the future leaves `policy_change` untouched.
6. **Rollback is not offered** (forward-only); recorded explicitly.
