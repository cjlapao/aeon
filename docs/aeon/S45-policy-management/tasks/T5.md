# T5 · Socket proposal decisions: `proposal.get`, `proposal.commit`, `proposal.reject`

**Prefix:** PM · **Rules:** PM1, PM2, PM7, PM8, PM11 · S35 TD1–TD5 (moved, not redesigned) · **Depends on:** T1, T3.
Shares T4's authoring-service wiring (develop on the same branch or after T4).

## Goal

A person can decide a proposal from the app: read it, **commit** it (applying its effect through the existing effect
path, then flipping the row) or **reject** it with a reason — over the socket, as the human door. The crash-safe
semantics S35 TD4 specified move into `internal/desk` and are reused unchanged; the new things are the digest binding,
the before/after, the peer-stamped actor and the audit row. `agent_import` is **not** committable here (T10, after S43).

## Files to create / modify

- `aeon/internal/store/proposal.go` — **extend minimally**: a `GetProposal` already exists (the CLI uses it); verify
  and, if the socket needs it, add `ProposalPayloadDigest(payload string) string` as a pure helper in `internal/desk`
  instead (no store change preferred). **No change to `DecideProposal`'s `Kind=="user"` rule or the schema CHECKs** —
  the socket actor is `{user, <peer uid>}`, which already satisfies them.
- `aeon/internal/desk/decide.go` — **new**. The orchestration both doors call:
  ```go
  func Commit(ctx context.Context, d Deps, id int64, digest string, by Actor) (CommitResult, error)
  func Reject(ctx context.Context, d Deps, id int64, reason string, by Actor) (RejectResult, error)
  ```
  `Commit`: load row → refuse unless `status=='proposed'` (`already <status> by <who> at <when>`, S35 TD1) → verify
  `digest` equals `sha256(canonical payload)` (refuse "the proposal changed since you read it" — immutable in
  practice, so this protects against a client committing something it never displayed) → `AlreadyApplied` →
  if not applied: `Validate` (failure ⇒ `SetProposalAppliedError`, row stays `proposed`, refusal names the reason) →
  capture the target's **before** state → `Apply` (failure ⇒ `applied_error`, row stays `proposed`) → capture
  **after** → `DecideProposal(…, "committed", by, "", at)` → `policy_change` row (`op='commit'`,
  `proposal_id`, `policy_id` when the kind names one, ids-only summary). `Reject`: row must be `proposed`; **reason
  required, non-empty, ≤ 512 bytes** (S35 TD5: reason discipline follows the direction of risk — a refusal to widen
  needs less than an approval, but the rule here is the stricter one S35 chose for rejects) → `DecideProposal(…,
  "rejected", …)` → `policy_change` (`op='reject'`). A reject applies **no** effect.
  The CLI's `cmdProposalCommit/Reject` (T8) become callers of these two functions with `by = {user, cli}`.
- `aeon/internal/protocol/proposals.go` — **do not edit**. The header documents the absence of commit/reject; the new
  methods go in a **new file** `proposals_decide.go` and the header comment is amended by T6 (not here), so this task's
  diff shows only additions.
- `aeon/internal/protocol/proposals_decide.go` — **new**. `proposal.get {id}` → `{proposal: ProposalRow, digest,
  preview?}` (the existing `ProposalRow`, plus the digest and, for `policy_add`/`policy_remove`/`seed_corpus`, a
  **live-vs-proposed preview**: the would-be `Describe` sentence and the target's current in-force answer, computed
  read-only — nothing written); `proposal.commit {id, digest}` → `{proposal, effectApplied bool, before, after,
  warnings}`; `proposal.reject {id, reason}` → `{proposal}`. Local interface `ProposalDecider` on `Table` (nil ⇒ absent).
- `aeon/internal/daemon/proposal_decide.go` — **new**. The adapter over `desk.Commit/Reject`; the second (and only
  daemon) caller of `store.DecideProposal` (T6 whitelists it) and of the effect `Apply`.
- `aeon/internal/protocol/errors.go` — `ErrProposalDecideRefused` (carries the reason verbatim), reuse `ErrPolicyNoActor`.
- `aeon/internal/protocol/method.go` — `MethodProposalGet`, `MethodProposalCommit`, `MethodProposalReject`, registered
  in a labelled block, conditional on the service (V13), `RequiresInitialize`, not `Debug`.
- Contract chain as T2/T4.

## Behaviour notes (each is a test)

- **Kinds covered:** `policy_add`, `policy_remove`, `seed_corpus`, `mcp_server_add`, `mcp_server_remove` (all five
  via the shared registry). The **`seed_corpus` effect applies the `policy.corpus` set through the seed engine**
  (`via:explicit`, actor = the committing person), so a committed proposal, `policy.seedCorpus` and `seed.apply` are one path
  (T12); a proposal carries the agent list it was created with. `agent_import` → refused by name: "committing an agent_import proposal over the socket is
  not available yet — use `aeon proposal commit` (S45 T10)". That sentence is **the honest state until T10**, and it is
  what the UI shows (the UI never hides an undecidable row).
- **`mcp_server_add/remove` effects** call `mcp.SaveConfig` from `internal/desk` — the T1 whitelist decision applies;
  `TestOnlyProposalIsSocketWritable`'s `allowedCommitEffect` is extended **only by T6**.
- **The preview is advisory** (S37 AA4): `proposal.commit` re-validates and re-reads, never trusts a stale preview.
- **Idempotence:** committing a `committed` row → the S35 refusal; committing when the effect is already present
  completes the flip (the crash-recovery path) and says so in `effectApplied:false`.
- **Concurrency:** two simultaneous commits of one id — the second loses at `decideGuarded`'s claimed-FROM
  (`UPDATE … WHERE status='proposed'`, zero rows changed) and refuses with the winner's identity; the effect must not
  apply twice (the `AlreadyApplied` re-check inside the single-writer section is what guarantees it — tested).

### Deviations (each measured, each stated)

1. **Digest verified BEFORE the status gate** (task text ordered status
   first): the binding check reads only the row the gate would leak — a
   caller who never displayed the row learns nothing about it from a
   mismatch either way, and the decided-row refusal stays byte-identical.
2. **CLI keeps its own status pre-gate** so `proposal-commit-decided-refused`
   keeps S35's sentence; the socket gets desk's winner-naming sentence.
   Same immutability, the door the golden was pinned at speaks the golden's
   words.
3. **Reject reason required only when `DecideDeps.ReasonRequired`** —
   the socket's true, the CLI's false (TD5's optional-reason ruling is
   golden-pinned; the ≤512 cap is enforced at both doors).
4. **`policy_remove` before/after needs the target, and the row names only
   a rule id** — the doors supply a `RemoveTarget` seam (their policy-store
   listing resolves id → rendered target) instead of desk reaching the
   store (forbidden by desk's own import guard).
5. **Effect registry injected once** (`RegisterSeams` in `cmd/aeon` init +
   `Options.Effects` from `serve.go`) because `internal/daemon` may not
   import the MCP/mcp layer; the daemon answer with no effects wired is
   desk's named per-kind refusal, never a silent no-op.
6. **`all-agents` renders bare** (`String()` names no id), so both doors'
   rendered-target re-parsers accept the colonless form for that kind only
   — found by the goldens, not by argument.
