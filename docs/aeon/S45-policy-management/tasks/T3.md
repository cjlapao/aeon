# T3 · The authoring audit: `policy_change`, its store accessors, and `policy.changes`

**Prefix:** PM · **Rules:** PM8, PM11 · **Depends on:** T0 (the "new table vs reuse" verdict, item 3.3; the actor
shape, item 3.4). Parallel-safe with T2.

## Goal

Record, **once and forever**, who added, removed, seeded, committed or rejected policy — with the kernel-stamped peer
identity — in an append-only table that retention can never trim. Today nothing but the row's own `created_at` (and
`RecordAuthored` for the seed verb) says who widened or narrowed a guard.

> If T0 item 3.3 ruled **reuse `policy_event`** (it can carry authoring without trimming), replace the migration below
> with the minimal change T0 recorded and keep every other section. The default and this file's text assume a new table.

## Files to create / modify

- `aeon/internal/store/migrations/<14-digit>_policy_change.sql` — **new**; timestamp from `date +%Y%m%d%H%M%S` at
  creation, sorting after the newest file T0 recorded; **no `schema.go` edit** (the migrations README's one rule).
  ```sql
  -- S45 T3's authoring audit: one append-only row per policy authoring write (add/remove/seed/commit/reject), naming the peer-stamped actor. A separate table from policy_event on purpose — that one holds verdict refusals and is trimmed by retention (D15); an authoring audit must never be trimmed. UPDATE and DELETE are refused by trigger, the S44 setting_event precedent.
  CREATE TABLE policy_change (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    op          TEXT NOT NULL CHECK (op IN ('add','remove','seed','commit','reject')),
    policy_id   TEXT,                       -- NULL for seed (many ids) and for reject
    proposal_id INTEGER,                    -- the proposal a commit/reject decided; NULL otherwise
    summary     TEXT NOT NULL CHECK (length(summary) BETWEEN 1 AND 1024),
    actor_kind  TEXT NOT NULL CHECK (actor_kind IN ('user','cli')),
    actor_id    TEXT NOT NULL CHECK (length(actor_id) BETWEEN 1 AND 256),
    occurred_at TEXT NOT NULL,
    CHECK ((op IN ('add','remove') AND policy_id IS NOT NULL) OR op IN ('seed','commit','reject'))
  );
  CREATE INDEX idx_policy_change_policy ON policy_change (policy_id, id);
  CREATE INDEX idx_policy_change_time   ON policy_change (occurred_at);
  CREATE TRIGGER policy_change_no_update BEFORE UPDATE ON policy_change
  BEGIN SELECT RAISE(ABORT, 'policy_change is append-only: an authoring audit row is never rewritten (S45 PM8)'); END;
  CREATE TRIGGER policy_change_no_delete BEFORE DELETE ON policy_change
  BEGIN SELECT RAISE(ABORT, 'policy_change is append-only: an authoring audit row is never deleted (S45 PM8)'); END;
  ```
  `actor_kind` is `'user'` (a socket peer, stamped by `table.ActorFor`) or `'cli'` (the offline fallback, T8 — the
  literal `{user, cli}` the CLI door already uses maps to `actor_kind='cli'`; **VERIFY with T0 item 3.4** that this
  keeps `DecideProposal`'s own `Kind=="user"` rule intact — `policy_change` is a *separate* audit and may use its own
  vocabulary; the proposal row keeps `decided_by_kind='user'`). No FK to `policy` (a removed policy's history must outlive it).
  If the migration parser cannot carry a trigger body (S44 T0 item 3.1 answers this — read its Notes), use the same
  fallback: no `Update`/`Delete` accessor exists plus `TestPolicyChangeHasNoUpdateOrDeletePath`, and say so.
- `aeon/internal/store/policy_change.go` — **new**; SQL only (invariant I2, `TestNoSQLLivesOutsideTheStore`):
  ```go
  type PolicyChange struct { ID int64; Op, PolicyID string; ProposalID *int64; Summary, ActorKind, ActorID, OccurredAt string }
  func (s *Store) PolicyChangeInsert(ctx context.Context, c PolicyChange) error
  func (s *Store) PolicyChangeInsertTx(tx *sql.Tx, c PolicyChange) error   // for writes that already hold a transaction
  func (s *Store) PolicyChangeList(ctx context.Context, policyID string, limit int) ([]PolicyChange, error) // newest first; "" = all; limit clamp [1,500], default 50
  func (s *Store) PolicyChangeCount(ctx context.Context) (int, error)
  ```
  Parameterised statements only. `PolicyChangeInsertTx` exists because T4/T5 want the audit row in the **same
  transaction** as the write where the store allows it (the policy `PolicyAdd`/`PolicyRemove` accessors are existing
  code; **VERIFY** whether they expose a tx variant — if not, add the audit row in a second statement immediately after
  and make the ordering **write-then-audit with a recoverable gap** explicit in Notes: a crash between the two leaves a
  policy with no audit row, which the next `policy.changes` read reports as `unaudited` for that policy via a
  reconciliation read (`PolicyChangeMissing`), never as "nothing happened" — the three-state honesty the policy events
  already follow, DEF-041).
- `aeon/internal/policy/store.go` — **no edit** (T12 adds `AddInTx` and the `origin` column; this task stays an audit task). The audit is written by the *callers* (T4/T5 in `internal/desk`), so
  the policy boundary stays pure and `evaluate.go` learns nothing (PM11).
- `aeon/internal/protocol/policy_changes.go` — **new**. `policy.changes {policyId?, limit?}` →
  `{changes: PolicyChangeView[], statement?: string}`; the statement is `"no authoring changes recorded."` only when the

**Deviations, and why.**

1. `PolicyChangeInsertTx` takes `ctx` as its first parameter (the sketch showed `(tx, c)`): every
   statement in this package honours cancellation, and the tx variant is no exception.
2. `PolicyChangeCount` takes `ctx` (the sketch showed `PolicyChangeCount()`), same reason.
3. The task's "callable but no production caller" is the WRITER pin, and it is exactly what holds:
   `TestPolicyChangeWriterHasNoProductionCaller` greps zero non-test call sites of the two insert paths
   (T4/T5 call them beside their writes). The READERS are wired to production — the daemon adapter is the
   one production caller of List/Count — because a registered socket read with no caller could not serve
   the request at all; the same test pins ≥1 reader under `internal/daemon`.
4. The protocol seam is the read-only `PolicyChangeStore` interface + daemon adapter (the `Proposals`
   seam pattern) rather than a direct `*store.Store` field like `Table.PolicyStore`: a read-only door
   deserves a read-only type — PM8's rule stated where the door can see it (the trigger is the store-side
   enforcement; the absent writer METHOD is the door-side).
5. The clamp lives solely in the store accessor; the handler passes `limit` through (the protocol test
   pins pass-through, the store test measures the clamp — restating [1,500] upstairs would be a second
   number free to drift).
6. `unauditedPolicyIds` returns `[]` always-present — per the task's own text ("this task returns `[]`
   until then"); T4's reconciliation read turns it into the measured answer.
7. The retention test seeds its `policy_event` rows with `policy_id ""` (NULL): `PolicyEventInsert` FKs a
   non-empty policy_id to `policy(id)`, and the point of the test is the TRIM call's reach, not FK
   theatre — `PolicyEventTrim(2100-01-01)` really runs, really trims 3 rows, and the audit count is
   measured unchanged around it.
8. `XDG_STATE_HOME` pinned to a fresh temp dir for every go command (the store tests open real stores;
   T0's environmental baseline note).
