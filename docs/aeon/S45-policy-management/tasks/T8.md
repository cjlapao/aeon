# T8 · The CLI as a client of the daemon

**Prefix:** PM · **Rules:** PM2, PM4 · P34 · **Depends on:** T4, T5, T6. Parallel-safe with T7, T9.

## Goal

`aeon policy …` and `aeon proposal …` stop being a second implementation that opens the store. They **dial the daemon
and call the socket methods** (T2/T4/T5), print what the wire said, and — only when no daemon is reachable — run the
**same `internal/desk` code** against the store directly, saying so (PM4, a flagged product call). The parity guard
proves no CLI verb exists without a socket twin, the goldens from T1 prove the output did not change, and the CLI
never re-validates anything.

## Files to create / modify

- `aeon/cmd/aeon/policy.go`, `proposal.go` — each verb becomes: **parse flags → build socket params → `dial(0)` →
  `c.Call(method, params, &out)` → print**. Presentation helpers stay. The two-access-path exception's justification
  comment (store.go note) is amended in one sentence: policy verbs now reach the store directly **only** as the
  documented offline fallback.
- `aeon/cmd/aeon/policy_client.go` — **new**. `type policyDoor interface { List/Get/Add/Remove/SeedCorpus/Why/InForce/
  Events/Changes(...) }` with two implementations:
  - `socketDoor` — the default: dials, calls, maps wire errors to the CLI's refusal text **verbatim**.
  - `directDoor` — the offline fallback: `desk.OpenBoundary` + the same `internal/desk`/`internal/policy` functions the
    daemon's services call (`desk.Commit/Reject`, `desk.RunSeedCorpus`, `Describe`, `Filter`). **The actor is
    `{user, cli}`** (the existing literal), audited as `actor_kind='cli'` (T3).
  - `selectDoor()` — `dial` once with a short timeout; success → `socketDoor`; "daemon not running/endpoint absent" →
    `directDoor` **and a fixed stderr line** `daemon not running — applied directly to the store` before any output;
    any *other* dial failure (permission denied, protocol mismatch, version skew) is **refused, not fallen back from** —
    falling back from an error that is not "nobody is home" would route around a daemon that exists.
- `aeon/cmd/aeon/policy_parity_test.go` — **new**: the parity guard.
- New verbs filled by the T0 parity table's gaps that are CLI-side: `aeon policy get <id>`, `aeon policy vocabulary`,
  `aeon policy changes [--policy ID] [--limit N]`, `aeon proposal show <id>` (twins of `policy.get/vocabulary/changes`,
  `proposal.get`). `aeon policy add --help` is **generated from `policy.vocabulary`** (live when the daemon is up, from
  `policy.Vocabulary()` offline) so the closed sets are never typed twice.
- `aeon/cmd/aeon/main.go` — usage text for the new verbs only.

## `aeon policy seed-corpus` after T12

The verb **stays** (parity; the T1 goldens pin its bytes) but is now an alias of `aeon seed apply --set policy.corpus
--yes` printed in the verb's original format: both doors reach the one engine path (`policy.corpus` is a **guard** set,
so the verb itself is the explicit operator action and never runs at daemon start). `--dry-run` maps to `seed.plan`;
`--agent` to the per-agent key selection. `aeon seed status` lists the set. The offline `directDoor` builds the
S43-extra engine over the store directly — still the same code.

## The CLI re-validates nothing (the standing drift rule)

Flag parsing refuses only what cannot be a value (a non-RFC3339 `--not-after`, an unknown `--type` via the *existing*
parser call). Everything else is the boundary's refusal printed verbatim. The `--tool`/`--command` sugar (expansion into
a spec) stays client-side as input parsing and is covered by the T1 goldens; the spy test from T1
(`TestDeskAddDoesNotRevalidate`) now runs through the socket door too.

## `proposal commit` over the CLI

`aeon proposal commit <id>`: `proposal.get` (to read the digest and preview) → print the **before/after** the daemon
returns and ask nothing (a terminal command is already a deliberate act; the confirmation friction is the UI's) →
`proposal.commit {id, digest}`. `--digest` may be supplied to bind to a previously displayed proposal. Reject needs
`--reason`. `agent_import` proposals: until T10, the CLI keeps committing them **exactly as today** (the direct door,
unchanged) — the parity table lists this as the one open gap with T10 as its closer.

## Definition of done

- [ ] Every policy/proposal verb dials the daemon; offline it uses `desk` and says so; other dial errors refuse.
- [ ] The parity guard passes in both directions with the T0 table as its fixture.
- [ ] T1's goldens identical through both doors; refusals verbatim; one round-trip per add.
- [ ] New verbs (`get`, `vocabulary`, `changes`, `proposal show`) present; help generated from the vocabulary.
- [ ] `agent_import` commit still works exactly as before; no new store-opening code outside `directDoor`.

## Do NOT

- Do not re-validate in the CLI or add a second formatter.
- Do not fall back on a dial error that is not "no daemon".
- Do not keep a local copy of any function T1 moved.
- Do not change any output byte (goldens are the contract); if the socket cannot return something the CLI printed,
  add it to the daemon (T2/T4/T5) — that gap is a defect in the *daemon*.
- Do not touch the `agent_import` commit path (T10).
- Do not accept a secret as a flag value (the standing rule) — and do not add `--value-from-stdin`-style secret paths.

### Deviations (with reasons)

1. **Mandatory operator lines ride stderr at BOTH doors** (commit's before/after window, the SEC-014 broad-allow warning). Goldens capture stdout only, so stdout bytes — the pinned contract — are untouched; the daemon road cannot print to a TTY through the wire, so the CLI prints what the wire SHIPPED. The fixed offline notice is the only stderr asymmetry, and it is asserted.
2. **Audit actors**: the direct door stamps authoring rows `{cli, cli}` (T3's ruling for the offline door — never impersonating a peer); the socket door's rows carry the daemon's peer stamp `{user, <uid>}`. DECISIONS stay `{user, cli}` offline (T5's CLI ruling). `TestDirectDoorAuditsItselfAsCliSocketDoorStampsPeer` pins all three.
3. **Seed door's agent-table check**: the socket seed door judges agents against the AGENT TABLE (T12's `policyseed`); the offline door runs `desk.RunSeedCorpus` (the task pins it — "do not fork semantics"), which predates that check. An agent in the corpus but absent from the agent table is refused on the socket and seeded offline. Unknown-to-corpus agents refuse at BOTH roads identically (the CLI pre-resolves through `desk.ResolveSeedTargets` before choosing a door). Closing the gap = re-basing the desk runner onto `policyseed` — T12-engine work, outside T8. The parity fixture stages the agent row on both stores so the seeded content itself is compared.
4. **Post-seed events compare by line SET**, not byte order: `policyseed` inserts hash-first, the desk runner corpus-first, so `policy_event` row NUMBERS legitimately differ while CONTENT must not. Every other read in the suite is byte-strict; `paritySet` still refuses a rule seeded on one road and not the other.
5. **`policy list --type` stays a client-side PRESENTATION filter** (the socket is called unfiltered): the goldens pin the CLI's own filtered-empty sentence and column layout; T2's server-side filter remains for app consumers. `--digest`, `--policy`, `--limit`, `--subject`, `--depth`, `--status` all travel as params (the guard's flag half).
6. **`policy events` trim/unaudited sentences are direct-door-only** (the wire ships rows + depth/cap/oldest only; the socket door says nothing it has no data for — three-state honesty, silence is never "nothing was refused"). `policy changes` carries the unaudited reconciliation on BOTH roads through the exported `UnauditedPolicyIDs`, with the offline fault-sentence twin (`policyChangesFaultText`).
7. **Flags after the positional are refused at both doors** (`reject <id> --reason X` refuses its own input) — T5's golden-pinned behavior (`proposal-reject-reason-after-id`); the usage strings keep T5's bracketed spelling for the same reason.
8. **Fixture finding (real, pre-existing)**: an in-process `dial()` ends in `appenv.Apply()`, which `os.Setenv`s the store paths PROCESS-WIDE — a later `daemonFixture` built from `os.Environ()` then inherits the REAL store. Only this suite dials in-process (its socket arm); the arm now snapshots/restores the env and `newBothDoors` re-pins `f.env()` through `doorEnv`. Other suites: no in-process dial, no exposure; named so the next daemon-fixture author knows.
9. **`TestPolicyRepoBridgeRoundTripsThroughTheRealStore`** red on this machine at HEAD (git-stash proven) — reported, not chased; it is the sweep's only failure.
