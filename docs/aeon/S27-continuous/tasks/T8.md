# T8 · Agent tools and the S44 settings

**Prefix:** CN · **Rules:** CN20, CN21 · standing rules 2, 4 · P6 · **Depends on:** T7, S44 merged (T3 of S44, the registry).

## Goal

Agents can **see** what the scheduler is doing and why — four catalog reads, one definition with a socket twin each — and nothing more. The four
daemon-wide knobs become S44 settings so they are changeable live and audited. **No write tool exists** (CN20).

## The four specs (`internal/records/catalog.go`, data only, family `scheduler`; the package keeps importing the standard library only)

| Tool | Socket twin | Class | Mutates | What it does |
| --- | --- | --- | --- | --- |
| `scheduler_status` | `scheduler.status` | safe | no | Whether the scheduler is on or paused, slots used vs cap, each repository's state and the reason it is or is not picking work |
| `scheduler_preview` | `scheduler.preview` | safe | no | What would be started next and, for everything ready that would not, the first reason (capacity, window, dependency, occupied…) |
| `scheduler_decisions` | `scheduler.decisions` | safe | no | The append-only record of scheduling decisions, newest first, filterable by repository, subject, decision or reason |
| `scheduler_attention` | `scheduler.attention` | safe | no | Items whose scheduler-started loop is blocked or waiting and needs a person, with the verbatim blocked kind |

- `additionalProperties:false`; descriptions ≥ 40 chars, telling siblings apart; **registered, not granted** (`DefaultGrant()` unchanged).
- `registerRecords` skips a twin whose dot-name already stands (T7 registered the four explicitly), so the specs reuse the socket methods; the scoped-read rule
  of S43/S52 applies: an agent sees **its own repository's** rows only when the records identity resolves one (`Identify` → component root); a person/CLI session
  sees all. T0 confirms `Identify` has the data; if not, the tools answer the **status header only** (no repository names) — recorded.
- `TestRegistryExactNames` bumped **+4, counted and dated** from T0's real count; `testdata/rerun_classes.json` updated; both want lists (`toolset_test.go:155,243`).
- `internal/records/catalog_test.go` — **siblings**: family `scheduler` exists; **every** spec in it is `Mutates:false`; no spec twinned to a control method.

## Settings (`aeon/internal/config/settings_decl_scheduler.go`, one file per area — S44 CS3's conflict-free declarations)

| Key | Type | Bounds | Default | Description (what a person reads) |
| --- | --- | --- | --- | --- |
| `scheduler.maxAgentSlots` | int | 1..64 | 2 | Agent slots the daemon may use at once across all loops; each running loop takes its repository's parallel-agent setting. A count, not a memory limit. |
| `scheduler.tickSeconds` | int | 5..300 | 15 | How often the scheduler looks for work. Finished loops wake it sooner. |
| `scheduler.maxStartsPerRootPerHour` | int | 1..60 | 6 | A backstop: the most loops the scheduler will start in one repository in an hour. |
| `scheduler.agingHours` | int | 1..720 | 24 | After this long deferred for capacity, a unit moves to the front of the line. |

- Not sensitive; not credential-named (CS5); environment override honoured per CS4. **Authority is not a setting** (CN21): the master and per-repository rows stay in
  the scheduler's own audited door. A test asserts no `scheduler.enabled`-like key exists in the registry.
- `daemon/continuous.go` reads them through S44's `Reader` **fresh** each tick (CS7: no cache); a change takes effect on the next tick and touches no running loop.

- [x] Four read tools, parity both ways, counted bump; four bounded settings read live; no write tool and no authority key.

## Do NOT

- Do not add a tool twinned to a control or a roadmap-edge **write** other than T3's two. Do not grant the tools by default. Do not add a `scheduler.enabled` setting.
  Do not cache a setting. Do not give the records package an import.
