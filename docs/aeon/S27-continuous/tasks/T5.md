# T5 · The daemon adapter: reader, starter, claim, reconcile, reactor kicks

**Prefix:** CN · **Rules:** CN1, CN3, CN4, CN8, CN13, CN14, CN17, CN19, CN23 · **Depends on:** T3, T4.

## Goal

The scheduler runs. `daemon/continuous.go` fills T4's seams from the store, walks the claim protocol, starts loops through the one start door as
**unattended** loops with deterministic slugs, recovers a crash mid-pick, and turns the S24/S26 reactors from *starters* into *kickers* **for enabled
repositories only**. Until S56 lands the outward/merge pins are **false/false** (tested) — the scheduler can build and commit locally, never open or merge.

## Behaviour

1. **Single starter (CN19).** Enabled repository: `loop.finished` ⇒ status write ⇒ kick ⇒ the next tick starts the next item; disabled: exactly today.
2. **Unattended always (CN3).** The started loop has `attended=0`, `allow_outward` and merge pin from the grant (or false).
3. **No restart of a blocked item.** The only `startLoopWith` call site of the scheduler is `Start(unit)`, and `unit` exists only for `ready` rows; a
   `refused` claim is final.
4. **Occupancy double-check:** after the claim and before the start, re-read `OccupyingLoops`; if now occupied (a person raced), `FinishStart(lost)` is **not**
   used — the claim is released by recording `deferred(repo-occupied)` **before** the transition (the order of CN14 puts occupancy ahead of the claim, so
   the re-check happens under the per-repository mutex before step 1; a person starting in the last microsecond is the recorded non-guarantee).
5. **`--no-recover`** ⇒ no scheduler (CN17). **No store or runner** ⇒ `RunContinuous` returns nil immediately.
6. **A `blocked` scheduler-started loop** (CN13): the next tick finds the repository occupied; the adapter writes one `needs-you` decision per block with the
   verbatim `BlockedReason.Kind` read from the loop's pin (a read, not an interpretation), deduplicated.

Deviations (all deliberate, all tested):

1. **Worker seam extends** (above) — `Record` answers the decision id the claim must name; a decision row that could not be written aborts the start (no claim without a decision is the store's law, and the adapter must not paper over it).
2. **A start's occupancy re-check may follow a written `started` decision row** — the decision row is the plan's word, the claim/occupancy re-check is the protocol's; a race between them appends a follow-up `deferred` row. The claim is still the only thing that starts anything.
3. **`BudgetOK:true`, `GrantAbsent:false`** at snapshot — S55's budget facts and S56's gate are not consulted at the pick; grants gate outward at pin time only. T6's seams consult them; the snapshot fields stay honest defaults until that seam lands.
4. **`AutonomyCap` is `""`** — the `autonomy_cap` columns exist (T2) but no Go reader does; the cap dimension of CN10 stays unenforced until one lands.
5. **`weightOf` defaults 1** for roots outside the component tree, and **first-deferral lookups filter `reason="capacity"`** (CN11's aging counts only capacity deferrals, per the truth table).
6. **`QueueLive` counts queue rows** (pending…blocked) — the drain gate (CN6.2) is about the queue's rows, and T4's plan treats `QueueLive>0` as roadmap-suppression only; a repository's queue candidates are unaffected.
7. **`needs-you`'s reason token is `start-refused`** — the store's `reason` column is a free coded token at the human-doors end, not one of CN15's 18; the SUMMARY carries the door's sentence verbatim (SEC-033-clean: ids and enums elsewhere).
8. **`SetLoopProvenance` is not called** — the extras carry `started_by`/`trigger_id` into the `NewLoop` row directly (`loop.started_by` is TEXT without a CHECK, and T2's `20261105025314` widened `loop_run.started_by_kind` to admit `scheduler`; the golden case `scheduler_word_kept` pins it).
9. **A refused queue start answers `refused` (not `needs-you`)** — the item blocks with its own question through `blockUndauntedStart`, which IS the human's door for a queue; `needs-you` rows are the roadmap's shape, where the row itself has no question mechanism.
10. **Reconcile's retry never re-claims** (the claim is already held) and skips claims whose repository or master is silent — those rows are left open, named in the log, for the person who silenced them.
11. **`usedWeights` counts loop rows whose status reads `running`** (runner-Active was tried and dropped): the continuous goroutine starts only after recovery, so a running row is a running truth — and CN8's per-repository occupancy keeps a repository's own loops out of double-counting.
