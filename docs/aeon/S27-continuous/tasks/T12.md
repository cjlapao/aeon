# T12 · Close-out: acceptance re-run, drills, the demo walk, the record

**Prefix:** CN · **Shape:** P9 · **Depends on:** T0–T11.

## Acceptance criteria (restated for the re-run; each maps to tests and a walk step)

1. A fresh store and an upgraded store: `scheduler_state.enabled=0`, no repository enabled; **nothing starts** with the scheduler built and idle.
2. A `ready` roadmap item or a `ready` queue item in an **enabled** repository is started by the scheduler as an **unattended** loop (`attended=0`), provenance `scheduler`, through the one start door.
3. An item with an open or cancelled dependency is never started; the preview says which, in the daemon's sentence.
4. A repository with any `running|waiting|blocked` loop — **including a person's** — has no candidate; a blocked item is **never** restarted by the scheduler (no start path exists; refused claims are final).
5. Capacity is a visible queue: deferrals name slots used, the cap and the weight; no preemption; the honest "count, not memory" statement is shown.
6. The window, rate backstop and aging behave per CN10–CN12 across DST and a restart.
7. A daemon killed at any point in a pick starts the item **exactly once** after restart.
8. Outward/merge permissions come only from S56 grants (false/false without S56), narrowed by the item's `autonomy_cap`, pinned at start; the grant revision is recorded.
9. Every decision is an append-only, deduplicated, templated row; the preview equals the tick.
10. The controls are human-door socket methods, absent from the narrow surface, agent services, the tool registry and the records catalog (reads only); default-off, never seeded, no inheritance.
11. CLI parity both ways; the four read tools; the four S44 settings read live; the Settings panel shows status, repositories, preview, decisions and needs-you.
12. Disabled and master-off repositories behave **byte-identically** to the pre-slice code (T1's goldens).
