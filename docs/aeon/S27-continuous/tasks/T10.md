# T10 · The "Continuous work" panel in Settings

**Prefix:** CN · **Rules:** CN13, CN15, CN22 · standing rules 3, 4 · P7 · **Depends on:** T7 (and S44-extra T9's compatibility pass; S45 T9's shared components **if merged** — T0 records which).

## Goal

A person can see and steer the scheduler from the app: what is on, what it will run next and **why the rest is waiting**, what needs them, and what it
decided. A panel on the real Settings screen (not the bench), descriptor-driven, daemon-first — it holds no vocabulary and no scheduling logic.

## Files (`ui/src/features/settings/continuous/`, new; existing panels and bench pages untouched)

- `ContinuousSection.tsx` — the section: **status header** (master, paused + reason, slots used/cap, next tick, open attention count), then four tabs via
  the existing `Tabs`: **Repositories**, **Preview**, **Decisions**, **Needs you**.
- `RepositoriesTab.tsx` — a list **with details** (rule 3): repository (grouped under its root component using `component.list`; a root with children shows as a folder — S44-extra's derived
  `kind`), enabled, template blueprint, window, minimum priority, last start, **state with the reason in the daemon's sentence** (`repo-occupied — loop X is blocked`);
  an edit form generated from `scheduler.status.descriptor` (blueprint choices from `blueprint.list`, priority states, window grammar); **enable confirms** with the daemon's statement
  through the existing `useConfirm`; the master and pause controls likewise; declining sends nothing.
- `PreviewTab.tsx` — `scheduler.preview` as "next up" plus one line per ready unit not started with its reason and (for `window-closed`/`rate-limit`) the instant; a note under it states
  the honest limit of the cap ("a count of slots, not a memory measurement").
- `DecisionsTab.tsx` — `scheduler.decisions` newest first with filters built from the descriptor (decision, reason, repository, subject); each row's summary is the daemon's template, never composed in the UI.
- `NeedsYouTab.tsx` — `scheduler.attention`: item, loop link (`/loops/:id`), the **verbatim blocked kind**, since-instant, and S55's raise instruction when the kind is `cap-hit`.
- `useScheduler.ts` — `useRpcQuery`/`useRpcAction`, rows updated **from the response**, never optimistically; offline ⇒ writes disabled, reads show last data (P7).
- `lib/i18n/en.json`, `pt.json` — `settings.continuous.*`, parity enforced by the existing i18n test; **no** scheduler vocabulary in these files except labels (reasons and sentences come from the daemon).
- `ui/src/features/settings/continuous/continuousRpc.guard.test.ts` — extracts every literal passed to the rpc helpers and asserts each is a registered method in the generated `contract.ts`
  (≥ 1 per tab, never vacuous), with a canary that flags a bogus method; a source grep test forbids a hardcoded reason/decision word.

## Behaviour

1. Disabled by default: the section opens with the master off and a one-sentence explanation from the daemon; no repository enabled.
2. Enabling a repository shows the template form; submitting an invalid blueprint shows the daemon's sentence **verbatim** and **keeps the draft**.
3. `stopAll` (when the method exists in the contract) confirms with the daemon's statement; absent method ⇒ the control is not rendered.
4. The preview refreshes on `scheduler.decision` / `loop.finished` / `loop.blocked` events via `useLiveSubscription` (existing), not on a poll.
5. No `localStorage` for domain data; no `fetch`; no new dependency.

**Deviations, named:**
1. **Live refresh subscribes `["loop.finished","loop.blocked","scheduler.*"]`.** The
   spec's `scheduler.decision` event does not exist — the contract's event list carries
   none and T7 publishes none — so the refresh rides the loop events (a finished or
   blocked loop is exactly when the ledger and needs-you tabs go stale), plus the
   `scheduler.*` prefix the plane may one day publish (kind-matching supports trailing
   `*` in `lib/useLiveSubscription`). No timer anywhere in the folder.
2. **Per-section i18n files, not `en.json`.** `lib/i18n/en.json`/`pt.json` measured 970
   lines each before this change — adding the 77 keys would cross SIZE1's 1000; the
   S54/S57 precedent is exactly this split (`en-system.json`, `*-gates.json`), wired at
   `lib/i18n/index.ts`. The namespace stays `settings.continuous.*`.
3. **Root grouping is by `component.list` `parentId`/`root` paths** via the projects
   folder's hook — the "S44-extra derived kind" the spec names does not exist on the
   generated row (contract `component.list` has no `kind`); a scheduler row matching no
   component root still renders, under its own path (the panel hides nothing).
4. **No loop link on needs-you rows:** `scheduler.attention` answers `loopSlug`, not a
   loop id, and `/loops/:id` routes by id — the panel names the slug as text rather
   than invent a route.
5. **`scheduler.status` carries no pause-reason echo**, so the reason's visible life is
   the pause ANSWER's sentence (`runningLoops`), verbatim, held as the last write's
   notice — not a re-read guess.
6. **Stop-all confirm** shows the daemon's live `slots.used` number as its children
   (no dedicated stopAll statement exists daemon-side; the enable statement is about
   widening and would mis-speak under a stop title).
7. **Decisions filters:** repository narrowing rides the door's own `componentRoot`
   param shape via local row containment; decision choices are the words the ANSWERED
   window carries; reason choices are `descriptor.reasons` verbatim. The panel queries
   the newest 200 once; narrowing is display, never a recompute.
8. **`make check-deps` reports Tauri's system libraries absent** (webkit2gtk-4.1 et al —
   machine-wide, the target itself says the web layer runs without them); the spec
   command's `npm run lint` does not exist as a script (`ui/Makefile`'s `typecheck`
   forwards to it and is red on pristine main with the `@types/node` family — recorded
   baseline). Substituted gates, both stronger than a lint: the whole-source
   `test/no-socket-in-web-layer.test.ts` scan (my banned-token list carries the S54
   truncated stem so it does not self-flag) and `npx tsc -p tsconfig.json --noEmit`
   filtered — zero diagnostics from any file this task wrote.
