# T9 · The CLI client: `aeon scheduler`, `aeon roadmap depend`

**Prefix:** CN · **Rules:** CN18 · standing rule 1 · P5 (client half) · **Depends on:** T7, T3. Parallel-safe with T8, T10.

## Goal

The CLI is a **client** of the socket methods — it has nothing the daemon lacks. `aeon scheduler …` drives the controls and reads; `aeon roadmap
depend|undepend` drives T3's edges. Every verb dials the daemon; there is **no offline door** (a scheduler without a daemon is not a thing — recorded
deviation from P5's direct-door shape, as S44-extra's CT13).

## Verbs (`aeon/cmd/aeon/scheduler.go`, new; `main.go` dispatches `case "scheduler"`; usage text)

```text
aeon scheduler status [--json]
aeon scheduler preview [--component PATH | --root ID] [--json]
aeon scheduler decisions [--component PATH] [--subject queue:7|roadmap:9] [--decision D] [--reason R] [--since RFC3339] [--limit N] [--json]
aeon scheduler attention [--component PATH | --root ID] [--json]
aeon scheduler enable --yes
aeon scheduler disable --yes
aeon scheduler pause --reason TEXT --yes
aeon scheduler resume
aeon scheduler stop-all --reason TEXT --yes          # registered only when the daemon reports it (S55)
aeon scheduler repo set --component PATH --blueprint NAME [--tech T] [--with k=v,…] [--window HH:MM-HH:MM --days 1-5 --zone Z] [--min-priority known|assumed] [--enable] --yes
aeon scheduler repo disable --component PATH --yes
aeon scheduler enable-tree --root ID --blueprint NAME [--tech …] --yes
aeon roadmap depend ID --on ID2          aeon roadmap undepend ID --on ID2
```

- Each verb: parse flags → build params → `dial(0)` → `c.Call(method, params, &out)` → print. `--json` prints the wire result verbatim. Human output is
  fixed templates over the wire fields: `status` shows master/paused, `slots 1/2`, a table of repositories with their **state and reason in the daemon's own sentence**;
  `preview` prints **"would start"** then every non-start with its reason (`window-closed — opens Mon 09:00 Europe/Lisbon`); `decisions` is newest first.
- **`--yes` is a seatbelt, not a security control** (P5): required for `enable`, `disable`, `pause`, `stop-all`, `repo set`, `repo disable`, `enable-tree`; `enable` and
  `enable-tree` first print the daemon's own statement (from `scheduler.status`) so the person reads what they are granting. No flag accepts a secret.
- The CLI **re-validates nothing**: a bad blueprint, window or zone is the daemon's sentence verbatim. Flag parsing refuses only what cannot be a value
  (a non-RFC3339 `--since`, a malformed `HH:MM`).
- `--window` accepts `HH:MM-HH:MM` as input sugar expanded client-side to `windowStart/windowEnd` (covered by goldens; the grammar itself is the daemon's).
- `aeon roadmap` gains `depend|undepend` and `show` prints dependencies (the wire's additive fields); existing verbs unchanged (T1/S26 goldens).
- **Parity (both directions, a test):** `schedulerVerbs`/`roadmapVerbs` single exported slices naming each verb's method; `TestEveryCLIVerbHasASocketMethod` and
  `TestEverySchedulerMethodHasACLIVerb` (the reverse), fixture = T0's parity table; an `open-gap` row must name its closing task.

**Deviations, recorded.**
1. **No offline door** (the spec's P5 deviation, S60 EV18's precedent):
   nobody home answers the standard typed `noDaemonError` line; the CLI
   never opens a store. `TestNoDaemonFailsHonestly` is the teeth.
2. **`stop-all` visibility is a plane probe, not a per-method probe.** The
   JSON-RPC handshake carries no capabilities list (PingResult has none),
   and T7 registers the twelve TOGETHER iff the seam is wired — so the only
   realizable state without `scheduler.stopAll` is a daemon without the
   plane, and `scheduler.status`' existence answers exactly that. Usage
   therefore hides the `stop-all` line when the status probe fails (no
   daemon or pre-S27 daemon) and says why in one line; the verb itself
   still passes the daemon's own unknown-method sentence through verbatim.
3. **The roadmap half of the census was already built** — T3 landed
   `cmdRoadmapDepend`/`cmdRoadmapUndepend` as socket clients with the graph
   print in `printRoadmapItem`. T9 adds the fixture rows and the behavioural
   test (`TestRoadmapDependVerbs`: depend prints `waits for #N(status)`,
   self-depend refuses verbatim through the CLI, undepend removes the
   edge); the S50 table's other fourteen rows ride the fixture for the
   forward census only.
4. **`enable-tree`/`repo set` print the statement too**, not just `enable`:
   the seatbelt law is read-before-grant, and CN2's bulk expansion grants
   the same authority as the master switch.
