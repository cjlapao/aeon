# T1 — The blueprint format, the loader, and the `schemaVersion` gate

**Notes (2026-10-17):** Added the strict YAML loader and tagged structs for the blueprint reference format. `produces` accepts one path or a list, unknown keys report their path and nearby spelling, and `kind`, `then`, and `schemaVersion` reject unsupported values. Loader tests cover a full-field round trip and refusal cases. The five existing derived blueprint files are the format input for later validation tasks.

## Why this exists

The format is **already specified**. `docs/_archive/aeon-v1-horizontal/07-loop-decide/design.md` has the complete field reference
table, and this task ports it — it does not redesign it. Read that table before writing a struct.

Two properties make or break the format, and both are about what it **refuses**.

## Scope

### The types

Every field in the superseded design's reference table, and nothing else. Tagged structs, not interfaces (M20),
because a blueprint round-trips through YAML and through the pin.

```go
type Blueprint struct {
    ID            string              `yaml:"id"`
    SchemaVersion int                 `yaml:"schemaVersion"`
    Version       int                 `yaml:"version"`
    Lanes         []Lane              `yaml:"lanes"`
    Questions     map[string]Question `yaml:"questions"`
}

type Lane struct {
    ID       string     `yaml:"id"`
    When     *Condition `yaml:"when,omitempty"`
    Step     *Step      `yaml:"step,omitempty"`
    Iterate  string     `yaml:"iterate,omitempty"`
    Ladder   []Step     `yaml:"ladder,omitempty"`
    Rework   string     `yaml:"rework,omitempty"`
    OnReject *OnReject  `yaml:"on_reject,omitempty"`
}

type Step struct {
    ID       string     `yaml:"id,omitempty"`
    Kind     StepKind   `yaml:"kind"`          // model-step | code-action | gate
    When     *Condition `yaml:"when,omitempty"`
    Agent    string     `yaml:"agent,omitempty"`
    Action   string     `yaml:"action,omitempty"`
    Question string     `yaml:"question,omitempty"`
    Sets     string     `yaml:"sets,omitempty"`
    Produces []string   `yaml:"produces,omitempty"`
    OnReject *OnReject  `yaml:"on_reject,omitempty"`
}

type OnReject struct {
    Goto    string            `yaml:"goto,omitempty"`
    With    map[string]string `yaml:"with,omitempty"`
    Counter string            `yaml:"counter"`
    Max     int               `yaml:"max"`
    Then    ThenAction        `yaml:"then"`   // escalate | fail-item | block
}
```

`produces` accepts a scalar or a sequence in YAML and is always a slice in Go — the superseded blueprint uses both
forms (`produces: prompt.md` and `produces: [plan.md, tasks/]`) and a format that accepts one is a format whose
examples do not parse.

`StepKind` and `ThenAction` are **closed**. An unknown value fails at load, quoting what it found and listing what
is accepted.

### `schemaVersion` — a loud refusal (P15, D11)

```go
const SupportedSchemaVersion = 1
```

An unknown version fails at load with both numbers in the message. A hand-written blueprint must survive a v2.3
that changes the format, and the only way that works is the version being in the data from the first commit rather
than inferred later.

**A missing `schemaVersion` is also a refusal**, not a default of 1. A blueprint written before the field existed
does not exist — this is the first commit — so a default would only ever mask a typo.

### Unknown keys are errors (D8)

The decoder is strict: any field outside the reference table fails, naming the path. **And it suggests**: `agents`
for `agent`, `lane` for `lanes`, `on-reject` for `on_reject`. A Levenshtein-1 match against the sibling field names
at that path is enough and is worth the twenty lines, because the whole class of error is a typo.

The format has **no extension point, by design**: an unrecognised key silently ignored is how a blueprint comes to
mean something other than what it says.

### Not in scope

**No validation beyond parsing.** Referential checks (does this agent exist, does this `goto` resolve) are T4 and
T5. This task's failures are all "this is not the format."

**No `Condition` internals** — declare the type, and let T2 own its evaluation and its own parse rules.

## Tests

| Test | Asserts |
| --- | --- |
| `TestUnknownSchemaVersionIsRefused` | `schemaVersion: 4` fails, and the message contains both `4` and `1` |
| `TestMissingSchemaVersionIsRefused` | Absent fails; it does not default |
| `TestEveryFieldRoundTrips` | A blueprint exercising **every field in the reference table** loads, re-marshals, and re-loads deep-equal. A field nobody round-trips is a field the pin will lose |
| `TestProducesAcceptsScalarAndSequence` | Both forms yield the same `[]string` |
| `TestUnknownKeyIsAnError` | `agents:` fails, the message names the path **and suggests `agent`** |
| `TestClosedSetsRejectUnknownValues` | `kind: model_step` and `then: retry` each fail, listing the accepted values |
| `TestLaneAcceptsStepOrLadderNotBoth` | Both present is an error at load — it has no meaning |

Fixtures live in `testdata/`, one file per case, named for what it trips.

## Definition of done

- [ ] Every field in the superseded reference table is present, and nothing else
- [ ] `schemaVersion` unknown **and** missing are both loud refusals
- [ ] An unknown key fails with a path and a suggestion
- [ ] `kind` and `then` are closed sets that name their accepted values on failure
- [ ] `produces` accepts both YAML forms
- [ ] A blueprint using every field round-trips deep-equal
- [ ] No referential validation in this task
- [ ] `make test`, `make lint` green
