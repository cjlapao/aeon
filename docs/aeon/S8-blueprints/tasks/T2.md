# T2 — The state manifest and the condition evaluator, from one declaration

**Notes (2026-10-18):** The manifest vocabulary is declared once in `fieldVocabulary`; `Fields`, `Slots`, type checking and the condition evaluator read it. Missing values raise an evaluation error. `aeon blueprint fields` publishes the table. S16 will consume these slots; no template engine was added here.

## Why this exists

L5 draws the line that stops the format becoming a runtime-interpreted language: conditions are
`{field, op, value}` triples over a **published** manifest, composed with `all`/`any`/`not`. Not expressions. That
is what makes them enumerable, renderable as a dropdown → operator → value picker, and checkable at load.

L18 is the reason this is **one task**: the manifest serves conditions, templates and a future UI builder, and three
copies of a field vocabulary drift. The drift presents as a condition silently evaluating false — a loop skipping a
lane for no visible reason, which is close to the worst failure this system can have because nothing looks broken.

## Scope

### One declaration (L18, D19)

```go
type Field struct {
    Path      string      // "mode", "flags.legal_review", "counters.qa_rounds", "tasks.count"
    Type      FieldType   // string | int | bool | enum | collection
    Enum      []string    // enum only
    Operators []Operator  // exactly what this type permits
    Doc       string      // rendered by the picker and by `aeon blueprint fields`
}

// Manifest is the single source. Conditions, templates and the UI read this and nothing else.
func Fields() []Field
```

`Operators` lives **on the field**, not in a global type→operators map, because `enum` fields permit `eq`/`neq`/`in`
and nothing else while `int` permits the comparisons, and encoding that per type in one place is where a special
case eventually gets added in the wrong one.

Expose it: `aeon blueprint fields` prints the table. A published vocabulary nobody can print is not published.

### The evaluator

```go
type Condition struct {
    Field string   `yaml:"field,omitempty"`
    Op    Operator `yaml:"op,omitempty"`
    Value any      `yaml:"value,omitempty"`
    All   []Condition `yaml:"all,omitempty"`
    Any   []Condition `yaml:"any,omitempty"`
    Not   *Condition  `yaml:"not,omitempty"`
}

// Evaluate is pure. A condition that reached here has passed validation.
func (c Condition) Evaluate(vals Values) (bool, error)
```

`Evaluate` returning an error at all is a **narrow** case: a validated condition against a well-formed `Values`
cannot fail. It errors only where the two disagree, which is a bug, and it must not silently return `false` — a
false-on-error evaluator is exactly the invisible lane skip L18 exists to prevent.

### Type checking is validation's job, not evaluation's (D20)

`{field: mode, op: gt, value: 3}` is **`invalid` at load**, and this task provides the check as a function T4 calls:

```go
// CheckCondition reports every problem with a condition against the manifest.
func CheckCondition(c Condition, path string) []Diagnostic
```

Four things it catches: an unknown field, an operator the field's type does not permit, a value of the wrong type,
and a value outside an `enum`'s set. Each with the path of the offending triple, not of the enclosing lane.

The last one is worth having: `{field: mode, op: eq, value: simpl}` is a typo that would otherwise evaluate false
forever.

### The template reader (L18)

Templates arrive at S16, but the **slot resolver** reads this manifest, and D19 asserts it now:

```go
// Slots returns the resolvable slot names. Same source as Fields().
func Slots() []string
```

It exists in this task solely so a test can prove the two readers share a declaration. A test that can only be
written after S16 is a test that does not constrain S16.

### Not in scope

No named predicates, no escape hatch (N8). A predicate registry is a code change by design; adding a hook here
makes the format a language.

## Tests

| Test | Asserts |
| --- | --- |
| `TestManifestIsTheSingleFieldVocabulary` | `Slots()` and `Fields()` derive from the same declaration — asserted by **set equality**, so adding a field to one and not the other fails (D19, L18) |
| `TestConditionOperatorMatrix` | Every field type × every operator: permitted ones evaluate, forbidden ones are rejected by `CheckCondition`. Table-driven, complete |
| `TestTypeMismatchIsAValidationError` | `gt` on a string, and a string value on an int field, are both `invalid` with the **triple's** path (D20) |
| `TestEnumValueOutsideSetIsInvalid` | `value: simpl` against an enum fails at load |
| `TestCompositionNesting` | `all`/`any`/`not` nest three deep and evaluate correctly; an empty `all` is an error, not vacuously true |
| `TestEvaluateNeverReturnsFalseOnError` | A `Values` missing a declared field yields an **error**, not `false` — the invisible-lane-skip guard |
| `TestFieldsCommandPrintsTheTable` | `aeon blueprint fields` lists every field with its type and operators |

## Definition of done

- [ ] One declaration; `Fields()` and `Slots()` read it, asserted by set equality
- [ ] Operators are declared per field, not per type globally
- [ ] `CheckCondition` catches unknown field, bad operator, wrong value type, out-of-enum value — each with the
      triple's path
- [ ] `Evaluate` errors rather than returning `false` when `Values` disagrees with the manifest
- [ ] An empty `all` is an error
- [ ] `aeon blueprint fields` prints the vocabulary
- [ ] No predicate escape hatch (N8)
- [ ] `make test`, `make lint` green
