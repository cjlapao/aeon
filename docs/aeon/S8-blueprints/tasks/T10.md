# T10 — `AdvanceLoop` and `execute` — model steps, gates, iterate, and a refused code action

**Notes (2026-10-18):** `AdvanceLoop` runs one action per call, saves each next position, enforces produced paths, stops at a gate, and blocks at an S16 code action. The two-step replay covers gate stop/answer, artifact checks and finish. S6 step-question continuation joins back into the loop; a separate test covers an in-flight step recovered by S7 without reissuing a model call. S9's step-question-to-gate replay found that completed suspended steps left the following lane `waiting`, preventing the runner from creating its gate. The continuation now restores `running` before advancing; a focused test covers the gate after the resumed step. `advisory` records a reject and advances; gate revise follows a bounded edge, while abort jumps to `on_abort` when declared.

## Why this exists

L2: `AdvanceLoop` is a **step function over persisted state**, returning `Advanced`/`Waiting`/`Blocked`/`Done`. A
thin runner calls it in a loop.

That shape is why a loop's crash recovery is free. Nothing lives in memory between calls, so a crash costs one step
and resume is calling it again. **S7 recovers the step; the loop needs no recovery of its own** — and it needs none
because L2 was chosen for a different reason entirely.

## Scope

```go
// AdvanceLoop reads a snapshot, decides, executes one thing, commits, returns.
// It holds nothing between calls.
func AdvanceLoop(ctx context.Context, dep Deps, loopID int64) (Result, error)
```

One `Decide`, one execution, one commit. Not a loop inside a loop.

### Dispatch

| Action | `execute` does |
| --- | --- |
| `RunModelStep` | Resolve `agent:` through T7's registry, compile, call S5's `RunStep`, persist through the `step` handler, check `produces:` |
| `AskGate` | Write a `question` row with `kind: 'gate'` and a **NULL `tool_use_id`**, return `Waiting` |
| `Skip` | Record `not-needed` or `skipped` per the action's `SkipAs` |
| `RunCodeAction` | **Refuse.** `Blocked` with `Kind: "unimplemented-action"`, the action name, and `Slice: "S16"` |
| `Waiting` / `Blocked` / `Done` | Terminal for this call |

### `produces:` is enforced (D4, O3)

After a `model-step` reports `ok`, check its declared paths. A missing artifact becomes a **`reject` naming the
file**, and routing takes over.

This is one of the more valuable things the format buys. The rule exists today in `dev-loop-protocol` as *"no file on
disk = the phase did not happen"*, enforced by asking agents to be honest. Here the engine enforces it.

T5 made the corresponding validation check: `produces:` without a resolvable reject target is `invalid` at load, so
this reject always has somewhere to go.

### A refusal is not a skip (D17, I8, L13)

`RunCodeAction` → the loop **stops**. It does not record the step as done, and it does not advance the position.

A skipped code action lets a loop reach `merge` having never pushed, and report success. That is the failure mode
worth spending a paragraph on, because "just skip what isn't built yet" is the natural instinct and it produces a
loop that lies.

Assert it three ways: the result is `Blocked`, the position is **unchanged**, and the code-action dispatcher spy is
at **zero**.

### The two doors (L11, D15, D16)

`aeon answer` dispatches on the question's `kind`:

| `kind` | `tool_use_id` | Door |
| --- | --- | --- |
| a step question (S6) | set | `ResumeStep` — the step continues |
| `gate` | **NULL** | `AdvanceLoop` — the loop moves on |

Both are `question` rows because a human answering something should not have to know which mechanism asked. They
resume differently because they are different mechanisms.

**An answer outside the question's declared `answers` set is refused at the answer boundary** (O6), leaving the loop
`waiting`. A gate whose closed set can be bypassed is not closed.

### `iterate` (L17, D18)

The ladder runs once per item, item-major. Zero items is a legitimate no-op — a lane that iterates an empty
collection completes immediately, and that must be a test rather than an assumption.

## Definition of done

- [ ] One decide, one execution, one commit per call; nothing held between calls
- [ ] `produces:` enforced, producing a reject that names the path
- [ ] A code action is refused: `Blocked`, position unchanged, spy at zero
- [ ] The two doors dispatch on `kind`, each asserted with the other spy at zero
- [ ] A gate question has a NULL `tool_use_id` and never enters a transcript
- [ ] An out-of-set gate answer is refused
- [ ] `iterate` runs item-major; zero items is a no-op
- [ ] `not-needed` and `skipped` stored distinctly
- [ ] No change to `RunStep`, `ResumeStep` or recovery (N9)
- [ ] `make test`, `make lint` green
