# T11 — The runner, the events, and `aeon loop show`

**Notes (2026-10-18):** The daemon starts S8 runners after S7 recovery, one active runner per loop, and releases them at waiting, blocked or done. It exposes `loop.start/show/answer` and blueprint methods; the CLI and Blueprints tab show the ordered ladder, pinned YAML, gate choices and retained events. S9's app replay found that `loop.show` omitted gate choices at the normalized single-step lane position and the CLI JSON view dropped `root` and `gateAnswers`; both snapshots now retain those fields, with focused tests. The waiting gate snapshot now also carries its pinned prompt, so the app can render it if the waiting event was pruned. Six loop events have conformance fixtures. A durable in-flight step link prevents duplicate model execution after restart.

## Why this exists

P29 says the daemon owns loop execution — there is no detached process per loop. So something has to call
`AdvanceLoop` repeatedly, and that something is a daemon-owned goroutine per running loop (L15).

**The ordering against S7 matters** (D23): the runner starts **after** the recovery scan. A runner started first
would advance a loop whose current step is being recovered, and the two would race over the same step row.

## Scope

### The runner (L15)

```go
// Run advances one loop until it is Waiting, Blocked, or Done.
func Run(ctx context.Context, dep Deps, loopID int64)
```

One goroutine per running loop, started by the daemon. It stops — and **releases the goroutine** — on `Waiting`,
`Blocked` and `Done`. A runner parked on a gate for three days is a goroutine held for three days, and P28's
per-loop memory budget is the reason that is not acceptable.

A `Waiting` loop resumes when its gate is answered: the answer path starts a runner. That is the same shape as S6's
suspension — no process while waiting — applied one level up.

**Start order in the daemon:**

```
socket opens          (S7 T6: so the daemon is inspectable during a slow recovery)
recovery scan runs    (S7)
runners start         (this task — after recovery, D23)
```

Independent of S6 and S7 as slices, this task **must** read S7's daemon start sequence to place itself. If S7 is not
yet merged, place the hook and note the ordering requirement in a comment naming D23.

### Concurrency

Loops run concurrently with each other; **one runner per loop, ever**. A second runner for the same loop would
double-advance it. Guard with a keyed registry, and assert it: start `Run` twice for one loop and prove only one
advances.

`AdvanceLoop`'s per-call commit is what makes a stopped-and-restarted runner safe, so the guard prevents duplication,
not corruption.

### Events

```
loop.started    { loopId, blueprint, version }
loop.advanced   { loopId, lane, item?, step, outcome, cost? }
loop.skipped    { loopId, lane, as }          // "not-needed" | "skipped"
loop.waiting    { loopId, questionId, prompt, answers }
loop.blocked    { loopId, reason }            // the structured BlockedReason (O4)
loop.finished   { loopId, status, totalCost }
```

`loop.blocked` carries T9's `BlockedReason` whole — `kind`, `detail`, `action`, `slice` — so S9 can render "not
implemented until S16" differently from "unresolvable reject" without parsing prose.

Additive per S2's rule, so no protocol version bump. Conformance fixtures in `testdata/conformance/loop.json`,
including one per `BlockedReason.Kind`.

### `aeon loop show` (O8, D21)

Renders the **shape**, not a flat list — lanes in order, an iterating lane's item count, each step's state, its
artifact, its cost:

```
loop 7c02  dev-loop   waiting
  clarify      ok           prompt.md            $0.0104
  discovery    not-needed   (when: mode != simple)
  plan         ok           plan.md, tasks/      $0.1832
  plan-gate    waiting      approve-plan
  build        pending      iterate: tasks (3)
  qa           pending      (when: flags.integration_surface)
                                          total  $0.1936
```

Three requirements:

- **A conditional lane that did not run shows `not-needed` with its condition** — not `pending`, which reads as
  "still to come" for something that will never happen. "Why did this not run" is the first question anyone asks of a
  ladder, and the condition is the answer.
- **`not-needed`, `skipped` and `pending` are visually distinct** (D21).
- **Cost per step and a total**, in S3's three honest states. A step whose cost is unknown says so; it never shows
  `$0.00`.

Also: `--wide` for the full form, `--blueprint` to print the pinned content (the demo's §3 uses it), `--json`.

## Tests

| Test | Asserts |
| --- | --- |
| `TestRunnerStartsAfterRecovery` | With spies on both, recovery completes before any runner starts (D23, L15) |
| `TestRunnerStopsAtWaiting` | The goroutine **exits** on `Waiting` — asserted by goroutine count, not by a log line. A parked runner is a leak (P28) |
| `TestRunnerStopsAtBlockedAndDone` | Both terminal states release |
| `TestAnswerRestartsTheRunner` | Answering a gate starts a runner and the loop completes |
| `TestOnlyOneRunnerPerLoop` | Two `Run` calls for one loop: one advances, the other returns immediately. Asserted on advance count |
| `TestConcurrentLoopsAdvanceIndependently` | Three loops, interleaved, no cross-contamination of position |
| `TestLoopEventsConformance` | Emitted events match the fixtures byte-for-byte after canonical marshalling |
| `TestBlockedEventCarriesStructuredReason` | One fixture per `BlockedReason.Kind` |
| `TestLoopShowRendersTheLadder` | Lanes in order; an iterating lane shows its item count; a conditional lane shows `not-needed` **with its condition** (O8) |
| `TestLoopShowDistinguishesThreeStates` | `not-needed`, `skipped`, `pending` render differently (D21) |
| `TestLoopShowCostIsThreeState` | An unknown cost renders as unknown, never `$0.00` |
| `TestLoopShowBlueprintPrintsThePin` | `--blueprint` prints the stored text, not the file |

`TestRunnerStopsAtWaiting` asserting on **goroutine count** rather than a log line is the difference between testing
the property and testing that someone remembered to log.
