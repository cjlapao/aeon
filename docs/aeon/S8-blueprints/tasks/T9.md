# T9 — `Decide` — pure, total, and closed

**Notes (2026-10-18):** `Decide` is pure over the pin and snapshot, returns the closed action set, and blocks malformed positions without panicking. Lanes and ladders advance in declared order; a false condition records `not-needed` or mode-driven `skipped`. Tests cover the action table and contradictory states.

## Why this exists

**Everything in the slice dispatches on this.** And L1's claim — that a user-authored protocol is impossible if the
graph lives inside a function — is only cashed in if `Decide` is genuinely pure: a test then supplies a three-lane
toy blueprint instead of constructing state against the whole real graph.

## Scope

```go
type ActionKind int

const (
    ActRunModelStep ActionKind = iota + 1
    ActRunCodeAction
    ActAskGate
    ActSkip
    ActWaiting
    ActBlocked
    ActDone
)

type Action struct {
    Kind     ActionKind
    Position Position
    Step     *blueprint.Step
    Question *blueprint.Question
    SkipAs   string          // "not-needed" | "skipped" (D21)
    Blocked  *BlockedReason  // structured, like S7's RecoveryFailure (O4)
}

// Decide is pure and total. No store, no clock, no I/O.
func Decide(bp *blueprint.Blueprint, m blueprint.Manifest, st LoopState) Action
```

`Action` is a **tagged struct, not an interface** (M20) — it is logged, persisted in events, and rendered by S9.

`BlockedReason` is structured (O4), not a formatted string:

```go
type BlockedReason struct {
    Kind   string  // "unimplemented-action" | "unresolvable-reject" | "pin-unparseable" | "contradictory-state"
    Detail string
    Action string  // the code action, when that is the cause
    Slice  string  // "S16", when known
}
```

S9 renders it and S17 routes on it; a sentence serves neither.

### The rules

Given a position, `Decide` walks forward:

1. **The current lane's `when`** is false → `Skip` with `SkipAs: "not-needed"`; a mode-driven skip is
   `"skipped"`. `PHASE_STATUS` already made that distinction and D21 requires it kept — a conditional lane that will
   never run must not read as `pending`.
2. **A `gate`** whose question is unanswered → `AskGate`; answered → advance.
3. **A `model-step`** → `RunModelStep`.
4. **A `code-action`** → `RunCodeAction`. **Yes, even though nothing implements it** (L13). `Decide`'s purity and
   totality must not be conditioned on what is built yet, or every later slice edits this function. `execute`
   refuses; that is T10's job.
5. **An iterating lane** advances `(item, step)` in that nesting order (L17): the ladder completes for one item
   before the next begins.
6. **The last lane complete** → `Done`.
7. **Waiting on a question** → `Waiting`.
8. **Anything contradictory** → `Blocked` with a reason. Because `Decide` is total over a closed action set, an
   unreachable or contradictory state is **a case that returns `blocked`**, not a panic and not a fallthrough. That
   is what makes the reconciliation pass an invariant of the machine rather than a separate audit.

### Outcome routing (L4)

Four outcomes, and **do not define a second set** — Q7 asks whether S5's `StepResult.Outcome` already carries
`ok`/`reject`/`blocked`/`failed`. If it does, use it.

| Outcome | Default routing |
| --- | --- |
| `ok` | the next step |
| `reject` | the enclosing ladder's `rework`, bounded by `on_reject` |
| `blocked` | stop the loop, raise to the human |
| `failed` | fail this item, continue to the next |

A counter at `max` follows `then:` — `escalate`, `fail-item`, or `block`. Validation guarantees `then:` exists
(D10), so this code has no default branch for its absence: an exhaustive switch with a **failing** default (I4).

## Tests

| Test | Asserts |
| --- | --- |
| `TestDecideActionTable` | Every `ActionKind` reached by a named subtest with a toy blueprint (D2). **An unreachable action is either dead code or a case `Decide` cannot produce, and both are bugs** |
| `TestDecideIsPure` | Called twice, deep-equal; inputs unmutated; the import list contains no store, clock or I/O (D1, I1) |
| `TestDecideNeverPanics` | A fuzz seed of malformed states — an empty blueprint, a position naming an absent lane, a counter above `max`, an iterating lane with a nil item — each returns an `Action` (D1) |
| `TestCodeActionIsReturnedNotSuppressed` | A `code-action` step yields `ActRunCodeAction`. **`Decide` does not know it is unimplemented** (L13) |
| `TestSkipDistinguishesNotNeededFromSkipped` | Both, with the right `SkipAs` (D21) |
| `TestIterateNestingOrder` | Two items, three steps: the order is item1×3 then item2×3, not step-major |
| `TestRejectRoutesToRework` | Inside a ladder, to the lane's `rework`; at lane level, to the step's own `goto` |
| `TestCounterAtMaxFollowsThen` | All three `then:` values, each producing a different action |
| `TestContradictoryStateIsBlockedNotPanic` | A position naming a step absent from the pinned blueprint — the shape an edited-and-repinned loop would have — yields `Blocked` with `Kind: "contradictory-state"` |
| `TestBlockedReasonIsStructured` | Not a formatted string; `Kind` is set for every path that blocks (O4) |

`TestContradictoryStateIsBlockedNotPanic` is the one that justifies L6. It is the failure the pin exists to prevent,
and `Decide` must survive it anyway.
