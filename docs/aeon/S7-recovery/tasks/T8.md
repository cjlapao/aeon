# T8 — Walk the demo with real crashes, and amend the QA suites

**Notes (2026-10-17):** `aeon/scripts/qa-s7-recovery.sh` passed seven local fixture cases using disposable state and real `SIGKILL`: completed receipt recovered without re-running `bash`, suspended question preserved, Case A read result preserved once, Case B model call reissued with honest unknown first-call cost, `--no-recover` leaving `running` unchanged, a crash during recovery after two atomic commits, and incomplete `bash` receipt failing with the tool named. The script prints its logs, result files and state directory for inspection. `DEMO.md` and the runtime/tools/store QA suites now describe these actual checks. The [Recovery test bench QA walk](../UI-QA-DEMO.md) gives a manual desktop procedure; that window and a live provider were not used in this replay-only validation.


## Why this exists

A slice is not done when its tests pass. It is done when someone who did not build it can follow `DEMO.md` and
watch the thing work (§14).

**This is the only task that kills a process.** Every unit test in T1–T7 constructs its states directly, which is
what T4's purity is for. But no constructed state proves the daemon survives a real `SIGKILL` at a real moment, and
that is the claim the slice makes.

## Scope

### Walk every section

Follow [`DEMO.md`](../DEMO.md) end to end on a throwaway repository, and **fix what does not match** — the demo, or
the code, whichever is wrong. A demo that needs a paragraph of explanation to work is a demo that failed.

The sections that decide whether the slice is sound:

**§4 — the receipt earning its place.** A `bash` that completed, a crash before the transcript write, and the
captured result recovered without re-running. Without the receipt this is indistinguishable from §3, and a `go test
./...` that passed would be discarded. If §4 does not work, the slice has no reason to exist.

**§3 — failing honestly.** A crash mid-`bash`, and a step that **fails naming the tool** rather than guessing.
Confirm it is not silently `ok` and not left `running` — a step left `running` is one the next start tries to
recover forever.

**§5 — a suspended step untouched.** This looks like a formality and is the check that prevents recovery from
ruining every loop correctly waiting for a human.

**§2 — the doubled cost.** Confirm `aeon step show --costs` shows **both** model calls. Those tokens were billed;
reporting one is the same class of error as printing `$0.00`.

Confirm the debug hooks (§4, §6) work under `make dev` and are **absent** from `make build` output.
