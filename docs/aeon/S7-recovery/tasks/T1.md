# T1 — The `tool_receipt` table and `arg_digest`

> **2026-10-17 implementation note:** Migration 0011 adds the receipt table. `store.ArgDigest` hashes the
> tool name, a NUL separator, and the exact JSON input bytes. The new receipt tests and the full store
> suite pass with an isolated HOME. The original machine HOME has an existing Aeon state WAL file and
> triggers `TestNoTestCreatesTheRealStateDirectory`, so S7 tests use `/tmp/aeon-s7-test-home`.

## Why this exists

Everything else in the slice reads or writes this table, and its one subtle property is that **`completed_at IS
NULL` is a signal, not a gap.**

**Why a table and not a column on `step_message`:** a receipt must exist **before** the tool runs, and the message
row holding that tool's result does not exist until after it finishes. A column on a row that is not there yet
cannot record that something is about to happen. This is settled (I2) — `ARCHITECTURE.md` §3a and S4's documents
already say so. **Do not edit them.**

## Scope

### The migration

Add a migration to S4's numbered ledger, following its existing discipline exactly: one transaction, one number,
recorded in the ledger table.

```sql
CREATE TABLE tool_receipt (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  step_id      INTEGER NOT NULL REFERENCES step(id) ON DELETE CASCADE,
  tool_use_id  TEXT NOT NULL,
  tool         TEXT NOT NULL,
  arg_digest   TEXT NOT NULL,
  started_at   TEXT NOT NULL,
  completed_at TEXT,
  result       TEXT,
  is_error     INTEGER,
  UNIQUE (step_id, tool_use_id)
);

CREATE INDEX idx_tool_receipt_step ON tool_receipt(step_id);
```

`completed_at IS NULL` **is** the unknown state (K31). It is not a default to be tidied away — it is the signal, and
nothing may backfill it.

### `arg_digest`

A hex SHA-256 over the **tool name and its arguments**, in that order, with a separator that cannot appear in
either:

```go
func ArgDigest(tool string, input json.RawMessage) string
```

Covering the name and not only the arguments (O2) because two different tools called with identical arguments in
one turn is unlikely and not impossible, and matching on arguments alone would cross them.

The digest exists so a captured result can be matched to the call it belongs to. Recovering a result onto a
different call would be worse than failing.

### The store methods

```go
// Begin records that an unsafe tool is about to execute. Written before the process spawns.
func (s *Store) BeginReceipt(ctx context.Context, stepID int64, toolUseID, tool, argDigest string) error

// Complete records the captured result. Called after the tool returns, before the transcript write.
func (s *Store) CompleteReceipt(ctx context.Context, stepID int64, toolUseID, result string, isError bool) error

// Receipts returns every receipt for a step, for recovery to read.
func (s *Store) Receipts(ctx context.Context, stepID int64) ([]Receipt, error)
```

Both writes go through S4's **single-connection writer** (S4's DB15). `BeginReceipt` uses `INSERT`, not upsert — a second
begin for the same `(step_id, tool_use_id)` is a bug and the `UNIQUE` constraint should say so rather than silently
overwriting a record of something that already started.

## Tests

| Test | Asserts |
| --- | --- |
| `TestReceiptRoundTrip` | Begin then Complete then read: `completed_at`, `result` and `is_error` survive; `is_error=false` is distinguishable from unset |
| `TestReceiptIncompleteReadsAsNull` | A begun-not-completed receipt reads back with `completed_at` nil — **the unknown state is representable and distinguishable from a completed one whose result was empty** |
| `TestReceiptSchemaFreshEqualsMigrated` | A fresh database and a migrated one are identical, extending S4's existing equivalence test rather than adding a second one |
| `TestReceiptCascadesWithStep` | Deleting a step deletes its receipts — proven by the **cascade**, not by reading the `foreign_keys` pragma |
| `TestReceiptDoubleBeginFails` | A second `BeginReceipt` for the same `(step, tool_use_id)` errors |
| `TestArgDigestSeparatesToolFromInput` | `ArgDigest("a", {"x":"b"})` differs from `ArgDigest("ab", {"x":""})` and from `ArgDigest("b", {"x":"a"})` — the separator holds |

Every test against a temp directory. Never the real store.
