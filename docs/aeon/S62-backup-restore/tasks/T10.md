# T10 · Adopt S44 settings; the Settings → Backups panel

**Prefix:** BK · **Shape:** P7 · **Rules:** BK11, BK12 · **Depends on:** T6, T9, and **S44 merged** (the generic settings
section, S44 T8, for the settings half; the list/actions half needs only T6). If S44 has not merged, only the list/actions
half (steps 2–3) can be built and T10 stays Partial for the adoption.

## Goal

The `backup.*` keys become real S44 settings (typed, ranged, audited, editable from the app), replacing the environment-only
seam without changing a key, a default or the pre-migration exception; and the app gets a **Backups** panel: a list of backups
with details, "Run now", verify, prune preview, and honest freshness.

## 1. Adopt S44 (daemon side)

- Declare the keys of BK11 in S44's key registry (its declaration API, read by T0 of this task's Notes at start): type, default,
  range (`interval` ≥ 15 m, `keep` ≥ 1, `dir` absolute), description, **not sensitive** (CS5: no credential ever). `backup.dir`'s
  description states the pre-migration exception in one sentence.
- `backup.Settings` gains a `ConfigSettings` implementation (env → `setting` table → default, S44 CS4/CS7: live reads, no
  cache) and the daemon constructor swaps `EnvSettings` for it; the **pre-migration hook still uses `EnvSettings`** (BK6) and
  a test asserts it performs **no database read**.
- Environment variables keep working and keep their precedence (S44 CS4), so existing `AEON_BACKUP_*` users are unaffected.
- Tests: `TestBackupSettingsPrecedence` (env beats db beats default; `source` reported), `TestInvalidSettingRefusedAtSetTime`,
  `TestPreMigrationIgnoresTheSettingsTable`, `TestChangingIntervalAffectsTheNextTick` (live read), `TestNoSecretKeysDeclared`.

## 2. The panel (UI: `ui/src/features/settings/backups/`)

Following P7 (descriptor-driven, P34-guarded), on the **real Settings screen** (not the bench):

- **List** (`backup.list`): rows with name, created (relative + absolute), size, schema, reason badge
  (`manual|scheduled|pre-migration`), verify state pill (`unverified|verified|verified+drill`), and "restorable with this
  version" (yes / no — names the unknown migration). Newest first, daemon-side limit.
- **Status header** (`backup.status`): state (`never|fresh|stale|failing`) in words, last success age, next due, the database's
  size and WAL size, schedule on/off — **all from the daemon**, none computed in the UI. "Never backed up" is a sentence with
  the Run-now button.
- **Actions:** *Run now* (`backup.run`), *Verify* per row (`backup.verify`, drill as a checkbox with a cost note), *Prune…*
  (`backup.prune {dryRun:true}` shows the plan in a dialog; confirming calls it with `dryRun:false` through `useConfirm`
  with the daemon's own statement). Offline ⇒ writes disabled, reads show the last data. Refusals shown **verbatim** with
  the draft kept; rows updated **from the response**, never optimistically.
- **Restore is not in the app.** A static, i18n'd explanation — "Restoring replaces the database and needs the daemon stopped:
  run `aeon backup restore <file>` in a terminal" — with a copy button for the command. No button calls anything.
- **Settings half:** S44's generic section renders the `backup.*` keys; this panel links to it. No setting is typed twice.
- en/pt parity, no new dependency, no `localStorage` for domain data, no `fetch`; existing screens untouched.
- A `backupRpc.guard.test.ts` extracts every literal passed to the rpc helpers and asserts each is a method in the generated
  `contract.ts` (≥ 1 per tab, never vacuous) with a canary that flags a bogus method; a grep test forbids the string `restore`
  as an rpc literal and forbids hardcoded state words (`never|fresh|stale|failing` come from the daemon's enum).

### Daemon half (steps 1)

- **`internal/config/settings_decl_backup.go` (123, new)** — the ten BK11 keys declared in S44's registry,
  beside the agents and gates declarations: `backup.enabled` (bool, `true`), `backup.dir` (string, `""` — the
  description states the pre-migration exception in one sentence), `backup.interval` (string, `24h`),
  `backup.timeout` (string, `10m`), `backup.keep` (int, `5`, Min 1), `backup.keepDaily` (int, `30`, Min 1),
  `backup.keepWeekly` (int, `12`, Min 1), `backup.keepPreMigration` (int, `5`, Min 1), `backup.verifyAfter`
  (bool, `true`), `backup.staleAfter` (string, `48h`). No key name, default or type changed. The four
  retention counts share one `minOne` Min pointer, so a keep of zero is refused at SET time (the declaration
  boundary), not at read time. None is Sensitive (CS5: none is credential-shaped).
  Two deliberate type choices: the three durations are **TypeString** (S57 T7's `gates.watchWindow`
  precedent — a duration's canonical text is the value, parsed at the read site; a TypeInt declaration would
  have re-meaned the established `AEON_BACKUP_*` environment variables existing operators export); and the
  two semantic rules the declaration cannot carry — the fifteen-minute interval floor and `backup.dir`'s
  absolute-path rule — stay in `backup.ResolveSettings`, which refuses with a sentence naming the key,
  exactly as a bad environment value always was.
  One init-ordering fact measured: `settings.go`'s init resets `defaultRegistry` to empty, and this file's
  init (`settings_decl_backup.go` sorts after `settings.go`) is what repopulates it — the registry test in
  `internal/config/settings_test.go` holds the whole set (ten backup keys + the two adopted ones) named.
- **`internal/backup/configsettings.go` (172, new)** — `ConfigSettings{store, env}`: the `Settings`
  implementation that reads environment → `setting` table → default (CS4) on every call, live, no cache,
  reporting the winning layer per key (`env` | `db` | `default` | `unreadable`). Precedence ruling, kept from
  the spec's "existing users unaffected": the established `AEON_BACKUP_*` name beats the S44
  `AEON_SETTING_BACKUP_*` form for the same key (an operator who exported the old name before S44 existed
  must not have their value shadowed). S44's `EnvInvalid` falls through with the S44 source; an established
  name with a garbage value is the resolver's to refuse, not the store's. An **unreadable** value is a repo
  fault, not a setting: it answers the declared default and the run proceeds (the daemon must not lose its
  safety net because one row is corrupt). Invalid accessors — an unparseable or non-positive duration, a
  negative count — refuse with the key named (`"invalid"`), never coerce.
- **`internal/backup/settings.go`** — the dir check moved onto the value: `""` is the default dir
  (`<state dir>/backups`), a set value must be absolute (the resolver's sentence, not the declaration's).
- **`internal/daemon/backup_service.go`** — `NewBackupService(st, settings *config.Store, version, publish,
  log)`: a nil `*config.Store` is the test mount (the suite's existing fakes pass none and get the
  environment-only seam); production passes the daemon's store.
- **`internal/daemon/daemon.go`** — the `settings *config.Store` field and constructor param, and the
  `NewBackupService(d.store, opts.Settings, …)` swap. The change is a small additive edit; the file stands at
  **1,508 lines after** (a standing SIZE1 violation inherited at base, recorded, not split here — this change
  is not the "substantial change" that triggers the split). The merge also gofmt-fixed pre-existing dirt in
  the file that sat on origin/main.
- **The pre-migration exception is pinned, not just kept.** `store_open.go` still constructs the hook over
  `backup.NewEnvSettings()` — the parser, never a table read, because the table is inside the very database
  the hook protects. Two tests in `cmd/aeon/bk_hook_guard_test.go` (370) hold it:
  `TestPreMigrationIgnoresTheSettingsTable` (a store with the settings table populated still opens
  pre-migration backups from the environment alone — the table is never consulted) and
  `TestEveryProductionOpenGoesThroughTheHook` (every production `store.Open` call site goes through the
  hook's `storeOpenOptions` constructor — a direct open would bypass the net).
- **Tests** — `internal/backup/configsettings_test.go`: `TestBackupSettingsPrecedence` (env beats db beats
  default, `source` reported per layer, incl. the established-name-beats-S44-form ruling) and
  `TestInvalidSettingRefusedAtSetTime` (a keep of zero refused at the declaration; a garbage duration refused
  by the resolver naming the key). `internal/config/settings_decl_backup_test.go`: `TestNoSecretKeysDeclared`
  (all ten declared, none Sensitive). `internal/daemon/backup_settings_test.go`:
  `TestChangingIntervalAffectsTheNextTick` (write the row, the next tick reads the new interval — the live
  read, no cache). All four PASS `-race`, with the two hook guards.
