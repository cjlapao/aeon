# T7 · Restore: CLI-only, daemon-down, atomic, keeps the replaced set

**Prefix:** BK · **Rules:** BK9, BK5, BK17 · **Depends on:** T2, T4. Parallel-safe with T5, T6, T8.

## Goal

A person can put a verified backup back, safely, with the daemon down, and can always get the replaced database back. The
operation overwrites the file the daemon owns, so it exists **only** as a CLI direct-door command: no socket method, no tool,
no catalog spec — ever.

## Files

- `aeon/internal/endpoint/probe.go` — **new**: `Probe() (Result, error)` with `Result{Alive bool; Peer string; Path string}`.
  Same endpoint resolution as `Claim()` (`Path()`), same dial with the same short timeout, but **never removes anything**:
  a stale socket file is reported `Alive:false, Stale:true` and left alone (T1's golden shows `Claim` reclaims). Windows
  named-pipe branch mirrors `Claim`. Tests in the package.
- `aeon/internal/backup/restore.go` — **new**: `Plan(ctx, Deps, file, opts) (RestorePlan, error)` (read-only: steps 1–4 of BK9)
  and `Restore(ctx, Deps, plan, yes) error` (steps 5–8). Uses `store.CheckFile`, `backup.Verify`, `endpoint.Probe`, an
  `exclusive lock` helper `store.LockExclusive(path) (release func(), error)` (**store file** `store/lock.go`, I2: it opens the
  live file with `locking_mode=EXCLUSIVE` + `BEGIN EXCLUSIVE` and holds it only for the pre-swap window).
- `aeon/internal/backup/restore_fs.go` — the file moves: stage dir `<state>/.restore-<id>` (0700), staged `state.db` (0600),
  `fsync` file and dir, same-device check (`EXDEV` ⇒ refuse), pre-restore directory
  `<state>/state.db.pre-restore-<UTC yyyymmddThhmmssZ>/` receiving `state.db`, `state.db-wal`, `state.db-shm` (whichever
  exist) with `os.Rename`, then rename the staged file in, `chmod 0600`, remove the stage dir through the fenced remover's
  restore variant (documented in T4's guard exception list: the stage dir only).
- `aeon/cmd/aeon/backup_restore.go` — **new**: `aeon backup restore FILE [--plan] [--yes]`: prints the plan (live file size and
  mtime, backup created-at/schema/row counts, what is kept, what the backup does **not** contain — BK2), refuses without
  `--yes`, runs `Restore`, prints the next steps. **It never dials the daemon to restore**; it uses `endpoint.Probe` only to
  refuse. This file is the single allowed home of the word `restore` on a command surface (T6's guard exception list).
- `aeon/cmd/aeon/backup_restore_log.go` — writes `<state>/restore-<ts>.log` (plain text: timestamps, steps, basenames; no
  row content, no secrets) beside the pre-restore directory.

## The steps (BK9), with the failure behaviour of each

1. `Probe` ⇒ refuse on `Alive` (names endpoint + peer); `Stale` is reported and proceeds.
2. `LockExclusive` on the live `state.db` ⇒ `SQLITE_BUSY` ⇒ refuse (names the possibilities); a missing file is allowed.
3. `Verify` level 2 of the backup ⇒ refuse on `checksum`, `integrity`, `fk`, `counts`, `newer-schema` (sentence names the unknown
   migration and says to use a newer `aeon`); an **older** schema is allowed and the plan says "the next start will migrate it
   and take its own pre-migration backup".
4. Plan printed; no `--yes` ⇒ stop, exit non-zero, **nothing changed**.
5. Extract to the stage dir; re-run `CheckFile` on the staged file; run the **drill** on a *copy* of it in a temp dir.
6. Move the live set into the pre-restore directory (**db + wal + shm together**); at this point the target dir must hold no
   `state.db-wal`/`-shm`.
7. Rename the staged file to `state.db`; fsync the directory; `chmod 0600`.
8. Remove the stage dir; write the log; print "start the daemon; it will open and (if needed) migrate and back up first".
   The command **does not start the daemon and does not open the store.**

**Failure after step 6 began:** the code moves the three files back, verifies `state.db`'s sha256 equals the recorded
pre-restore hash, and reports "restore failed and the previous database was put back"; if putting back itself fails it prints
the exact `mv` commands and the pre-restore directory (nothing is ever deleted).

## Commands

P10, `./internal/endpoint/ ./internal/backup/ ./internal/store/ ./cmd/aeon/ -run 'Probe|Restore|Exclusive' -count=1 -race -v`.

## Definition of done

- [ ] Daemon-down and holder proofs; every refusal listed; the replaced set kept together; fault-injected at every step.
- [ ] `Probe` is non-mutating; no remote door; restore never opens the store or starts a daemon.

## Do NOT

- Do not add restore to the socket, the tool registry, the records catalog or the narrow surface. Do not use `Claim()` as the
  daemon check. Do not delete the replaced database or its WAL/SHM. Do not leave a `-wal`/`-shm` in the target. Do not
  restore a newer-schema backup. Do not open the store in the restore path. Do not accept a path from anywhere but argv.

**Decisions the spec could not have known.**
- **T7 writes NO ledger row** (design.md BK10, final). A restore is a CLI act with the daemon down; the `backup_run` rows are the daemon's, and the kinds are a closed set that already has no `restore`. The record is the CLI's printed line and the `restore-<ts>.log` beside the pre-restore dir, written **iff `plan.Swapped || plan.RolledBack`** — a refusal and a plan-only run changed nothing, and an unchanged tree writes no record. The `restore-plan` kind and the `post-restore-check` reason stay RESERVED for T9's doctor line and never enter the closed set.
- **`Plan` → `PlanRestore`** (the spec's `Plan(ctx, Deps, file, opts)`): the name `Plan` is already owned by retention.go's retention plan in this package.
- **The stage dir is INSIDE the state dir** (`.restore-<16hex>`, 0700): the swap is one rename within the state dir, which is what makes it atomic; the backup dir (often a different filesystem — BK17) is only the source.
- **The same-fs check (BK17) compares the BACKUP dir and the STATE dir, pre-stage**, and is build-tagged: `syscall.Statfs` on both, `st_dev` compared, refused with `ErrKindIO` naming both dirs when they differ. On a platform without a device number (`ok:false`) the engine logs a stated line ("the filesystems could not be compared — proceeding") and proceeds: a refusal on an unanswerable question is not honesty. `Deps.sameDevice` makes the seam injectable; the refusal test drives it without any cross-device mount.
- **A fault at `rename-in` or `remove-stage` means the swap is COMPLETE** (the file is already the backup's): the error names the leftover stage dir and never rolls back — BK9's put-back is defined for failures after `move-old` began, and putting the old file back over a new one is a second swap nobody asked for. `move-old` failures get the put-back with `state.db`'s sha256 re-verified against the recorded pre-hash; `putBackBroken` prints the exact `mv` commands and the pre-restore dir (nothing is ever deleted).
- **The pre-restore dir exists only when ≥1 live file exists** (`state.db.pre-restore-<UTC yyyymmddThhmmssZ>/` 0700, receiving `state.db`, `-wal`, `-shm` — whichever exist — together); after a successful put-back the keep dir may remain empty — an empty dir is not a deletion.
- **`--plan` is a no-op alias** (plan-then-stop is the default; `--yes` is the only flag that moves a file) and the no-`--yes` stop is a `usageError` (exit 2 on the real door) — a stop is not a refusal, and a refusal records nothing either way.
- **The drill opens a COPY in a scratch dir, never the staged file in the state dir** (a drill on the staged file would let the drill's own WAL sit beside the swap, and the drill is a `store.Open` with migrations — a mutation). The drill's opener is the `Deps.OpenStore` seam: on the CLI door it is a plain `store.Open` with NO pre-migrate hook (the drill must not take its own pre-migration backup of a file that is not yet the store).
- **The lock is held for the whole operation** (step 2 through the final release), released by `defer p.Release()`; `Release` is idempotent and is called by every early return's path (the plan object is returned with the lock still held on every refusal, so the caller's `defer p.Release()` is the single exit).
- **The CLI door reads no environment itself**: the endpoint path comes from `endpoint.Probe` (the endpoint package owns its variable), the state dir from `paths.StoreDir()` — a second reader would be a second truth (pinned by source scan).
- **`LockExclusive`'s signature is unnamed** `(func(), error)`: go1.26.6's parser rejects the named form `func() error`-style returns here ("named return values" misparse — measured, worked around by removing the names).

**Measurements that fixed tests (not code).** The lock matrix, measured on go-sqlite3 v1.14.52 against a 76-migration store: **WAL** mode (the live store's actual mode — `open.go:430` sets `_journal_mode=WAL` on the live DSN, verified, not assumed) — an open transaction on a second connection, even a bare deferred `BEGIN` that never read, blocks `BEGIN EXCLUSIVE`; **DELETE** mode — an open read transaction blocks only once it has actually read a table (a bare `BEGIN` does not). The holder test uses the WAL shape (the live store's shape): `sqlOpenHolder` leaves `BEGIN` + a real `SELECT count(*) FROM restore_probe` open. A clean `store.Close()` leaves `state.db-wal`/`-shm` in place (zeroed, checkpointed — the driver does not unlink them), so the live set the plan reads is the database plus however many sidecars exist, and the tests assert the CLOSED set (`state.db` first, every name in the three), not a single file. The `stage` step logs two facts (the filesystem verdict and the staging itself), so the log's step sequence is checked for order and completeness with repeats of one step allowed. The pre-restore dir's `state.db` holds the bytes **at the swap** (post-mutation in the round trip), which is the correct "previous database" — the test hashes the file after the mutation, not before. vec0 in the fixture: the embedding is a **JSON-encoded float slice as a string** (`string(json.Marshal(vector))`), the KNN parameter is `string(raw)` — the shapes `retrieval.go` uses, not raw float bytes.
