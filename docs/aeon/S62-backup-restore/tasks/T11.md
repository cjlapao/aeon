### Step 2 — The three drills (date 2026-11-03, platform: this box, Linux)

**Drill 1 — backup under writes.** Fixture: the ~118 MiB store (5000 events + 100 chunks + 1 learning +
vectors, as `t11vintage`/`t11fixture` build it). Writer: `t11writer` (a sequential `AppendEvent` loop, 60 000
writes, reports rate + p50/p95/p95/max). Five concurrent `aeon backup run` (106.4 MiB artefacts) while the
writer ran:

- idle writer: **8603 writes/s, p95 112 µs** (same loop, no backup in flight);
- under the five backups: `writes=60000 total=16.391s rate=3660/s p50=102µs p95=251µs p99=6.632ms
  max=34.053ms` — **zero failed writes**, p95 still sub-millisecond (2.3×, not a stall in the operator
  sense; BK3's "cost" is throughput, 57% down, while backups share the writer's WAL);
- WAL sampled every 250 ms: **4 144 752 → 253 334 712 bytes** (4.0 → 241.6 MiB) at peak — the checkpoint is
  deferred behind the backup, and the WAL drains afterwards;
- backup duration: **18.2 s** under live writes vs **1.2 s** idle for the same 106.4 MiB file;
- all **8 artefacts** pass `aeon backup verify --drill` (level 3) and `t11check` (integrity, FK, counts).

**Drill 2 — `kill -9` mid-backup.** Six SIGKILLs at **0.15 / 0.30 / 0.45 / 0.60 / 0.90 / 1.20 s** into a
~1.5–2 s backup. Partial garbage observed on disk: `.tmp-<hex>/state.db` at 60% and 100% of final size, and
`.aeonbak.partial` at 97%. After **every** kill: `backup list` shows **zero** files with a final name, and
`t11check` on the live store is green (integrity=true, fk=0). The next `aeon serve` start **swept 5 partial
files** (the fenced sweep removes only its own patterns; everything else stayed).

**Drill 3 — restore round trip + the five refusals.** Round trip: backup `…032401Z-v79.aeonbak`, data changed
(129 355 extra event rows), daemon down, `aeon backup restore --yes` — the ten-phase log ran clean
(`probe → lock → verify L2 (120 counts) → plan (124 604 416 bytes, the set: state.db, -wal, -shm) → stage
(same filesystem) → check-staged → drill (ledger already current) → move-old → rename-in → remove-stage`),
the replaced set kept in `state.db.pre-restore-20261103T032539Z/`, daemon restarted, `t11query`: pre-backup
data present, vec and FTS queries answer. Refusals, each observed:

| Refusal | Observed |
| --- | --- |
| live daemon | `restore refused: a daemon is alive on the endpoint … — the restore overwrites the file the daemon owns; stop the daemon and try again`, exit 1 |
| process holding the file | `t11hold` held an open transaction on the db for 90 s → the lock probe refused, nothing moved |
| corrupt checksum | one byte flipped in the archive → the verify phase refused, the live file untouched |
| newer schema | `t11forge` fabricated a manifest naming a migration the binary does not know → refused at level 1 (NewerSchema) |
| no `--yes` | the plan is shown and the command refuses; the live file's mtime is unchanged |
