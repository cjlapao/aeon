# T9 · The CLI client, offline direct door, `doctor` and `db info` lines

**Prefix:** BK · **Shape:** P5 · **Rules:** BK15, BK17 · standing rule 1 · **Depends on:** T5, T6, T7, T8.

## Goal

`aeon backup …` and `aeon export …` are **clients of the daemon's methods**; with no daemon they run the **same code**
against the store opened **without migrating**; `aeon doctor` tells the truth about the database and its backups without
opening the store; `aeon db info` gains one line. Restore remains the one CLI-only verb.

## Files

- `aeon/cmd/aeon/backup.go` — **new**: `run`, `list`, `verify`, `status`, `prune`, `restore` (T7's file), `--json` on all but
  `restore`; helpers `backupDoor` interface with two implementations, exactly P5:
  - `socketDoor` — default: dials, calls `backup.*`, prints what the wire said, maps `ErrBackupRefused` to the sentence
    **verbatim**;
  - `directDoor` — offline: opens the store with `SkipMigrations: true` (actor `{cli,cli}`, `actor_kind='cli'`), builds the
    **same** `backup.Deps` and calls `backup.Run/Verify/List/Plan/Apply`; `go/parser` test: `directDoor` calls `backup.*`
    only, no copy of logic, and imports `internal/store` **only** here (`TestCLIBackupNeverImportsStoreOutsideTheDirectDoor`);
  - `selectDoor()` — dial once with a short timeout: success ⇒ `socketDoor`; "nobody home" ⇒ `directDoor` **and the fixed
    stderr line** `daemon not running — applied directly to the store`; any other dial failure (permission denied, protocol
    mismatch) is **refused, not fallen back from** (P5).
  - Flags re-validate nothing (a non-absolute `--dir` is the daemon's sentence); `--yes` is a seatbelt (required by
    `prune` non-dry-run and `restore`); no flag takes a secret.
- `aeon/cmd/aeon/doctor.go` — appends the four BK15 lines, built by a new `internal/doctor` section (`Report.Database`,
  `Report.Backups`) — **a directory scan + manifest-header reads + `backup.status` when a daemon answers; `doctor` never calls
  `store.Open`** (a test asserts no import of `internal/store` in the doctor path beyond the pure types). Wording is fixed
  templates: `never backed up — run \`aeon backup run\``, `last <age> ago (verified)`/`(unverified)`, `stale: last success <age>
  ago (limit <staleAfter>)`, `pre-migration dir <path> differs from backup.dir <path>`, and on Windows the permissions
  sentence of BK17. `doctor`'s "takes no arguments" rule is unchanged.
- `aeon/cmd/aeon/store_verbs.go` — `db info` appends **one** final line `backup   <last age or never> · <dir>` (the only change to
  its bytes; the T1 golden is updated and the diff listed); `db upgrade --dry-run` is unchanged.
- `aeon/cmd/aeon/main.go` — usage text for `backup` and `export` only.
- `aeon/cmd/aeon/backup_parity_test.go` — the parity guard (BK12): every `backup.*`/`export.*` method has a verb and every verb
  names its method; `restore` is the one explicit CLI-only exception (reason string cites BK9); fixture = the T0 table.

## Behaviour (each a test)

1. Every verb through **both doors** produces identical stdout and equal store/file state (a test daemon vs the direct door
   over the same fixture), except the one stderr line on the direct door.
2. `selectDoor`: endpoint absent ⇒ direct + the fixed line; permission-denied / version-mismatch ⇒ refused, **no** fallback.
3. The direct door **never migrates**: `aeon backup run` against an old-vintage store captures it as is (the backup's manifest
   `applied_migrations` equals the pre-open ledger) and the store's ledger is unchanged afterwards.
4. `aeon backup prune` without `--yes` shows the plan and removes nothing; with `--yes` only fenced removals happen.
5. `doctor` golden (T1) updated: daemon-down and daemon-up variants, "never backed up" variant, stale variant (fake clock),
   divergent pre-migration dir variant, Windows wording variant (build-tag test).
6. `doctor` and `backup list` work **with the store missing** (a fresh machine): "no database yet" is a sentence.
7. `--json` equals the wire result verbatim for `status`, `list`, `run`.

## Definition of done

- [ ] All verbs dial the daemon, fall back only for "no daemon", never migrate on the direct door; parity both ways with the
      single `restore` exception.
- [ ] `doctor` and `db info` state the database and backup facts honestly without opening the store.

## Do NOT

- Do not re-validate in the CLI. Do not open the store from `doctor`. Do not fall back on any dial error but "no daemon". Do
  not run migrations from `backup`/`export`. Do not change any byte of `db info` except the one listed line.

### Deviations and findings (what the task file could not know)

- **I2 caught this slice's own first commit, and the fix is the design.** The full internal suite failed two guards on the first run: `TestNoSQLLivesOutsideTheStore` (the doctor's `mode=ro` conn carried two `SELECT`s in a non-store file — I2's regex scans the whole repo) and `TestDriverImportedOnlyByDatabaseAndStore` (the vintage test blank-imported mattn to count the ledger rows — I2's line scan walks test files too). The fixes are the I2 shape, not exceptions: the two statements moved into the new `internal/store/readonly.go` (the doctor now asks `store.ReadOnlyFacts`, the store owns the SQL, as it owns every other statement), and the test imports `internal/database` and opens on `database.DriverName` (the driver stays registered by exactly the two packages that own it; the test holds no driver of its own). Both guards PASS after the move, and the doctor's own test battery (including `TestDatabaseFactsOfARealStoreCountsTheLedger`) stayed green — the accessor's answer is byte-identical to the conn's.
- **The fallback is ENOENT-only, classified on the unwrapped cause.** `dial()` wraps EVERY dial fault as `*noDaemonError` (the S55 control verbs need that shape), so the select cannot ask `errors.As` and trust it. `nobodyIsHome(err)` in backup.go answers true only when the error unwraps to a `*noDaemonError` **and** its cause `errors.Is` `os.ErrNotExist`. Measured: a leftover socket (ECONNREFUSED) and a mode-0000 socket (EACCES) are refused as-is, with their cause in the message, and the direct door is never reached; a garbage-protocol listener is refused at the handshake. The test's stale-socket fixture uses the bind-then-rename trick because Go's `net` unlinks the socket file on a graceful `Close()` — a leftover only stands when the daemon DIED, which is exactly the case that must not fall back.
- **The select's own dial was the F-T1-1 finding, in the opposite direction.** T1 measured doctor's `dial(1)` refused by the v2 daemon; the select had inherited the same constant. `dial(0)` ("whatever you support") is the only want that is version-proof.
- **`verify FILE --json` was refusing its own usage string.** The flag package stops parsing at the first non-flag argument, so a flag after the file was a second positional and an exit-2 usage error — the very order the usage line advertises. `cmdBackupVerify` now peels the one positional out before parsing, so the flags stand on either side of the file. No existing call site used the broken order (measured before the fix); the change is additive.
- **The doctor's socket leg was also fixed to `dial(0)`** — the leg that says "the daemon answers, here is what it says" must not refuse the answer it was dialing for.
- **The store the direct door opens is created empty.** `store.Open` pings the writer, and the open itself creates `state.db` (no tables) — so a fresh machine's first `backup status` leaves a 0-table store behind, and the next real open migrates it. That is the pre-existing seed-leg behaviour (T5's pre-migration hook is the one that would have backed it up, and there was nothing to back up); the direct door adds nothing to it, and the missing-store sentence is pinned at unit level (`TestDatabaseFactsOfANeverCreatedStoreIsAStateNotAnError`), not by pretending the CLI never creates the file.
- **And that 0-table store broke the status block, caught by the smoke run.** The task's own Commands step (`backup status` with no daemon, fresh machine) printed `db: 0 bytes + 0 bytes WAL · journal  · 0 applied / 0 pending` for a 4096-byte, `wal`-journal store the door had just made: `Store.Info()` needs the `_migrations` table that does not exist yet, and the db block then fell back to the zeros of a failed call — three lies (the bytes, the journal, and the pending count, which the registry knows is 79) in a block the doctor's own line next door states truthfully. Fixed in the direct door's `dbView` only (the daemon seam's twin can never meet the state — the daemon migrates at boot): on `Info()` failure the block falls back to `store.ReadOnlyFacts` (journal, applied) + the registry's total (pending) + a stat (bytes), pinned by `TestDirectDoorStatusOfAStoreItJustCreatedSaysTheTruth`. The renderer speaks sizes in human bytes (4096 prints `4 KiB`) — the test's pattern holds the three states, not a literal.
- **The parity normalisation is a token set, held minimal** (design.md's rule — the `verified` token is a point-in-time fact in the ledger, and the two worlds' ledgers genuinely differ in file names, sizes, actor stamps and ages, none of which is the door's voice): `$STATE` (the world's dir), `$FILE` (the backup's name — second precision, see below), `$STAMP` (ISO-ms), `$SHA` (64 hex), `$AGE` (`\d+ s`), `$SIZE` (bytes/KiB/MiB). The level-2 verify sentence's table count comes from the MANIFEST (`len(m.Tables)`, the 79-migration schema), identical in both worlds by construction — it is asserted byte-equal, not tokenised.
- **Two runs in the same second collide, and the second overwrites the first.** `FileName(t, applied)` has second precision (`aeon-state-YYYYMMDDTHHMMSSZ-vNN.aeonbak`), and the second run in the same second publishes under the same name over the first — measured, the battery's first run lost its first file to it. The battery's two runs stand 1.1 s apart by construction; the engine's own behaviour is the overwrite, recorded here rather than fixed (a fix is a filename change, a different task).
- **The never-migrates vintage is built by the codebase's own pattern, not by rolling a schema back.** Deleting ledger rows off a fully-migrated store and re-opening migrates the missing ones ONTO a schema that already has their columns — `duplicate column name: tools`, measured. So `TestDirectDoorNeverMigrates` deletes the 19 newest rows (a store at 60, `store_test.go`'s `TestPendingReportsWhatAnUpgradeWouldDo` pattern) and holds the door's contract directly: exit 0, an honest answer, the ledger still 60, no `.aeonbak`, and the control is the runner's own `Pending()` (19, the 19 the door declined) read through a `SkipMigrations` open. A full re-open is NOT the control — it would be applying 19 migrations over live columns.
