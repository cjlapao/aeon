# T4 · `internal/backup`: container, manifest, publish, lock, run/verify/list/status, fenced retention

**Prefix:** BK · **Rules:** BK2, BK4, BK5, BK8, BK11 (seam), BK17 · **Depends on:** T2, T3.

## Goal

The file-level engine. It contains **no SQL** (it calls T2/T3's store functions) and is the one implementation every door
(daemon ticker, socket, CLI direct door, pre-migration hook) shares. After this task `backup.Run(ctx, deps, opts)` produces
a verified `.aeonbak`; `List/Status/Verify/Prune` work on a directory; deletion is fenced.

## Files to create (`aeon/internal/backup/`)

- `names.go` — `const Name = "aeon-state"`, `var fileRE`, `FileName(t time.Time, applied int) string`,
  `ParseName(string) (ts, applied, ok)`, `partialRE`, `tmpDirRE`; the GLOB twin string for T3's test.
- `manifest.go` — the closed `Manifest` struct of BK4; strict decode (`DisallowUnknownFields`); `Validate()`; constants for
  `format=1`; `outside_db` is supplied by the caller (T0's list) — a setting-free code constant until S46/S48.
- `container.go` — tar writer/reader (stdlib): `Write(dst io.Writer, m Manifest, dbPath string)` (members in order
  `manifest.json`, `state.db`), `Open(path) (*Reader, error)` with member-size and **tar path hygiene** (refuse any other
  member name, absolute names, `..`, symlink/hardlink types, and `state.db` larger than `manifest.db_bytes`), streaming SHA-256.
- `publish.go` — the atomic flow of BK4: temp dir `.tmp-<id>` (0700) → `Store.SnapshotTo` → `CheckFile` (level 2 when
  `VerifyAfter`) → row counts from the **copy** → write `<name>.aeonbak.partial` (0600) → `Sync` → `Rename` → fsync dir →
  remove temp. Every error path removes its own temp (through the fenced remover) and returns a typed `RunError{Kind
  store.BackupErrorKind…}` mapped to T3's `error_kind` enum.
- `lock.go` — `.backup.lock` with `O_EXCL`, pid + start time + reason; stale rule (OD6); `Release()` idempotent; refusal names
  the holder.
- `space.go`, `space_unix.go`, `space_windows.go` — `FreeSpace(dir) (bytes uint64, state FreeState)` where `FreeState` is
  `ok|low|unknown` (BK17); threshold `1.2 × (db + wal)`.
- `run.go` — `Run(ctx, Deps, Options) (Result, error)` where `Deps` is an interface set (`Snapshotter`, `Checker`,
  `RunRecorder`, `Clock`, `Settings`, `Events`) so the daemon, CLI and hook pass real implementations and tests pass fakes.
  Records one `backup_run` row per run **when the recorder is available** (the pre-migration path defers it — T5).
- `verify.go` — `Verify(ctx, path, level)` per BK5 incl. the **drill** (extract to a temp dir under the backup dir, `store.Open`
  there with migrations enabled and `PreMigrate` = nil, `CheckFile` again); newer-schema detection via `KnownMigrationNames`.
- `list.go` — `List(dirs)` (final-named files only; reads each manifest header without extracting the db; joins the latest
  verify row; computes `CanRestoreWithThisBinary`), `Status(...)` (BK12's state machine: `never` / `fresh` / `stale` /
  `failing` — `failing` after ≥ 2 consecutive failed scheduled runs).
- `retention.go` — `Plan(listing, policy) []Decision` (pure; `keep`, daily, weekly, pre-migration separately, always the
  newest verified) and `Apply(plan)`; **`removeBackupFile`** (BK8) is the only remover; `SweepPartials(dir)`.
- `settings.go` — `Settings` interface and `EnvSettings` (BK11 pre-S44 implementation, env → default, with `source`).
- `doc.go` — the confidentiality statement of BK2 as the package comment.

## Behaviour (each a test)

1. **Round trip:** `Run` on a populated store yields a file whose manifest matches `CheckFile` of the extracted db (counts,
   fingerprint, sha256), mode 0600 in a 0700 dir (Unix), single file.
2. **Atomic publish:** with a fault injected at each step (after snapshot, after verify, mid tar write, before rename, after
   rename) a "crash" (the test aborts the goroutine and re-lists) never leaves a final-named incomplete file; `.partial` and
   `.tmp-*` are ignored by `List` and removed by `SweepPartials` **without** touching anything else in the dir.
3. **Container hygiene:** a hand-built tar with a `../evil` member, a symlink member, an extra member, a truncated db or a
   mismatching sha256 is refused by `Open`/`Verify` with the checksum or format sentence.
4. **Single-flight:** a second `Run` while the first holds the lock refuses naming the holder; a stale lock (dead pid / old)
   is reclaimed and the reclaim is reported.
5. **Disk space:** a fake `FreeSpace` returning `low` refuses with `disk-full`; `unknown` proceeds and the run says so.
6. **Verify levels:** a corrupted extracted db ⇒ `integrity`; a tampered manifest count ⇒ `checksum`/`counts`; a backup from a
   newer schema (a manifest naming a migration unknown to this binary) ⇒ `newer-schema` at level 1 and **refuses** levels 2–3
   with the unknown name in the sentence; the **drill** applies migrations to a copy of an older-schema backup and reports
   which ran, leaving the live state dir untouched (directory listing equal).
7. **Retention (pure):** table-driven policy cases (keep=3/daily=2/weekly=1 over 30 synthetic days; pre-migration governed
   separately; the newest verified is never removed even when it is outside every window; an unverified newest is not a
   substitute).
8. **The fence:** `removeBackupFile` refuses a path outside the dir, `state.db`, a symlink pointing at `state.db`, a directory,
   a `..` traversal, a look-alike name (`aeon-state-…aeonbak.bak`) — **canary**: a deliberately permissive copy of the
   function (in the test) is shown to delete them, proving the assertions can fail.
9. **Guards:** a source walk (≥ 20 files) over `internal/backup` and `cmd/aeon`: `os.Remove`, `os.RemoveAll`, `syscall.Unlink`
   appear only in `removeBackupFile`, the sweep (same fence), and (T7) the documented restore cleanup; `internal/backup`
   imports no `database/sql`; no network package is imported (`net/http`, `net` except via `endpoint` in T7).
10. **Settings seam:** `EnvSettings` reads `AEON_BACKUP_*` and reports `source=env|default`; invalid values (relative dir,
    `keep=0`, `interval<15m`) are refused with a sentence.
11. **Confidentiality:** a manifest never contains a path other than the file basename; `credentials_included` is always
    `false`; a test plants a fake secret in `route.extra_body`-like free text and asserts the manifest and run row do not
    echo row content (only counts).

### Decisions and deviations the spec could not know

- **Reason/actor refusals record no ledger row.** `manual-typo` or `actor: agent` is a caller bug before a run starts;
  the ledger counts runs, not caller bugs, so the refusal returns before any row is written (tested: the fake store sees
  zero rows).
- **`Run` wraps the lock's own error type.** A held lock surfaces as `RunError{Kind: "lock-held"}` carrying the
  `LockHeldError`'s sentence (pid, start, reason, or the in-process self-hold text); `*LockHeldError` stays inside the
  door and only `RunError` crosses it, so the ledger's closed set is the only vocabulary callers ever see.
- **The container distinguishes "third member" from "truncated".** A file cut inside the terminal zero padding short-reads
  as `io.ErrUnexpectedEOF`, which a naive `err != io.EOF` check labels "a third member" — a wrong diagnosis naming the
  wrong repair. `Open` now refuses a short final block with the truncation sentence (found by the hostile-tar test).
- **The canary resolver follows symlinks.** `porousRemover` resolves with `filepath.EvalSymlinks` before removing: a plain
  `os.Remove` on a symlink deletes the link, never the target, so a canary that does not follow links could never prove
  the fence's symlink refusal has teeth.
- **The drill test records at the moment of the open.** `Reader.Close` removes the scratch dir after the verify, so the
  fake `OpenStore` takes the scratch's listing while it holds the `.drill-marker`; the test then also asserts the scratch
  is gone afterwards (the reader's close owns its scratch).
- **Production bug found by the test phase:** `latestVerifyByFile` marked a file `verified` when an older success sat
  behind a newer failure, contradicting its own docstring. Rewritten with a per-file `decided` map — the newest verify
  row per file decides: ok at a restore level ⇒ verified, anything else ⇒ unverified.
- **`Result.SizeBytes` is the database member's size** (the manifest's `db_bytes`), not the archive file's — the archive
  is manifest + tar overhead and is strictly larger. The round-trip test asserts the manifest and the result agree with
  each other, and the file is larger than its database.

### What the tests do not cover (named, for T11)

- **Level 3 over a real store is not exercised here.** The drill test drives `Deps.OpenStore` with a fake (it proves the
  dir opened is the scratch beside the archive, never the state dir, and that the migrations-that-ran list is right);
  the real-sqlite drill — extract, open with migrations enabled, confirm the live state dir is byte-untouched — belongs
  to T11's acceptance drills. Levels 1–2 over a real store are covered (`RealDeps` round trip).
- **`SweepPartials` on a dir full of live files** is covered by the fence test; a concurrent run during the sweep is a
  T6 concern (the daemon's single-flight tick).
- **Windows paths** (`space_windows.go`, `pid_windows.go`) compile only — this box is Linux; the cgo shim and the test
  suite run the Unix twins.
