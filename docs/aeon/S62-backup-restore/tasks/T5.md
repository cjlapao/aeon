# T5 · The pre-migration backup inside `store.Open`, and `--no-backup`

**Prefix:** BK · **Shape:** P2 (characterize → move) · **Rules:** BK6, BK11 (exception), BK18 · **Depends on:** T4.

## Goal

No migration can run against a non-empty store without a verified copy on disk, **through the daemon and through every CLI
verb**, unless an operator says `--no-backup`. This is the highest-value task in the slice: migrations are forward-only and
nothing today copies the file first.

## Files

- `aeon/internal/store/open.go` — `Options` gains `PreMigrate func(ctx context.Context, s *Store, pending []Migration) (PreMigrateResult, error)`
  (nil = today's behaviour exactly) and `Open` calls it **between the successful GORM wrap and `s.Migrate()`**:
  1. skip when `SkipMigrations`;
  2. `applied, pending, empty, err := s.AppliedNamesAndPending()` (T2 — creates nothing); `len(pending)==0` ⇒ no hook; `empty`
     ⇒ no hook; a raw in-memory/DSN-without-file ⇒ no hook (reason carried to the result);
  3. else call the hook; a returned error **closes the store and fails the open** with the hook's sentence (the file is
     untouched — the hook only reads);
  4. after `Migrate()` succeeds, if the hook returned a `RunRecord`, `Open` writes it with `RecordBackupRun` (the table now
     exists) and, on success, asks the hook's `AfterMigrate` to prune pre-migration backups (BK6).
  The `SkipMigrations` doc comment is amended (**comment only, listed**): "no CLI path sets it" ⇒ "set by the backup/export
  direct doors, which must capture a store as it is."
- `aeon/internal/backup/premigrate.go` — `NewPreMigrate(deps Deps, opts PreMigrateOptions) store.PreMigrateFunc`: resolves the
  dir from `AEON_BACKUP_DIR` else `<state dir>/backups` + `/pre-migration` (BK6/OD8 — **no database read**), takes the
  single-flight lock, runs `Run` with `reason=pre-migration` and `VerifyAfter=true` (level 2 is **mandatory** here, whatever
  `backup.verifyAfter` says), returns a `RunRecord` for T3. `PreMigrateOptions.NoBackup` makes it return immediately with a
  `skipped: operator` record **and** print/return the sentence "no backup was taken before migrating (--no-backup)".
- `aeon/cmd/aeon/serve.go` — `--no-backup` flag (documented as scoped to the pre-migration backup); passes
  `PreMigrate: backup.NewPreMigrate(...)` to `store.Open` (line 177).
- `aeon/cmd/aeon/store_verbs.go` — `openStoreDirectly(opts)` takes the same flag for the verbs that accept it (`db info`,
  `db upgrade --dry-run`, `db query`) and passes the hook; the **backup/export direct door** uses `SkipMigrations:true`
  (T9). A shared `storeOpenOptions(noBackup bool)` builds the options so both callers use one constructor (the guard below
  asserts it).
- `aeon/cmd/aeon/bk_hook_guard_test.go` — sibling guard: a `go/parser` walk over `cmd/aeon` asserts every call to
  `store.Open(` outside tests either passes `Options` built by `storeOpenOptions` or sets `SkipMigrations: true`
  (≥ 10 files seen), with a **canary** (a synthetic file calling `store.Open(store.Options{})` is reported).
- T1's `TestOpenMigratesAnOldStoreWithoutAnyCopy` is **edited by this task (listed)**: it becomes
  `TestOpenMigratesAnOldStoreOnlyAfterACopy`, asserting the new truth; its header records the supersession.

## Behaviour (each a test)

1. **Pending on a non-empty store ⇒ copy first.** A store at vintage N−k, opened with the real hook: a verified
   `pre-migration/…aeonbak` exists **before** the first pending migration's effect is visible (a migration spy records the
   backup file's existence at the instant migration #1 starts), then migrations apply, then a `backup_run` row
   (`reason=pre-migration, actor_kind=cli|daemon`) is present. The copy's applied set is exactly the pre-open ledger.
2. **No pending ⇒ no work.** A current store: no file, no lock, no row, no measurable extra time (assert no `Backup` call
   via the fake).
3. **Empty/fresh ⇒ no backup.** Fresh dir, empty file, in-memory DSN: no backup; migrations run as today.
4. **Failure refuses the migration.** Unwritable dir, full disk (fake), integrity failure, lock held by a live holder ⇒ `Open`
   returns an error naming the reason, the dir and `--no-backup`; the **ledger is unchanged** and `state.db` bytes are
   identical (hash before/after).
5. **`--no-backup`** proceeds, no file, a `skipped: operator` row, and the sentence is printed by the CLI (asserted).
   There is **no env-var way** to get this behaviour (a test sets every plausible `AEON_*` name and asserts the refusal stands).
6. **Both callers covered.** The guard walk above; plus an end-to-end: the CLI verb `aeon db info` against an old-vintage
   store (daemon down) takes the backup and migrates; `aeon serve` against the same does too.
7. **Retention after success only:** with `keepPreMigration=2` and 4 prior pre-migration files, pruning happens after a
   successful migration; a **failed** migration prunes nothing (and the backup is kept — it is now the undo).
8. **A failing migration leaves the undo in place:** inject a failing migration after the backup; `Open` fails (existing D5
   behaviour), the backup file exists and passes `Verify` level 2, and `Restore`'s plan (T7) accepts it.
9. **Two openers race:** two processes with pending migrations — one backup is taken (single-flight), neither corrupts the
   other; no deadlock.

### Decisions the spec could not know

1. **The deferred record.** The hook runs BEFORE `Migrate()`, and `backup_run` does not exist until a pending
   migration creates it — so the hook's `Run` cannot write its own ledger row, not even failure rows (T4's
   `recordRun` would hit a missing table). The hook therefore wraps the store in a `deferredStore` that proxies
   everything and CAPTURES the `RecordBackupRun` call; the captured row returns as `PreMigrateResult.RunRecord`,
   and `applyPreMigrateAftermath` writes it with the real `RecordBackupRun` once `Migrate()` has succeeded (the
   table exists then). The row's timestamps are the run's, not the re-record's. Failed hook ⇒ no row (nothing
   exists to record); failed migration ⇒ no row, and the file stays (it is the undo). A record-write failure
   after the migration FAILS THE OPEN, deliberately: the row is owed, and the open that migrates and cannot say
   so is worse than one that refuses. It is a documented one-time event — the next open sees a current store,
   records nothing, opens cleanly; the file stands regardless (file is truth, row is index).
2. **Acquire's immediate refusal.** The single-flight lock refuses a LIVE holder at once (other-process: pid +
   since + reason; in-process: "an earlier call in this process"). There is no waiting: T4's four attempts are
   the stale-reclaim path, and a live holder at all four is a final refusal. The race test's loser leg is that
   refusal.
3. **The prune records nothing.** `AfterMigrate` = `List` + `Plan` (pre-migration family kept by count only —
   the newest `KeepPreMig`, no verified exemption) + fenced `Apply`. `Apply` records no ledger row (T4:
   retention is maintenance, not a run), so a successful pre-migration open leaves exactly one row.
4. **`--no-backup` is a flag, never an env** (BK18): the hook reads no environment for the opt-out; the CLI flag
   is the only path, and the env-var test sets eight plausible names to prove it.
5. **The sentence goes to `opts.Out` (wired to stderr in the CLI), exit 0**: the migration succeeded; the
   sentence is an announcement, not a failure.
