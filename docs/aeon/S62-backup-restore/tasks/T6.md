# T6 · The daemon: service, maintenance task, `backup.*` methods, events, read-only tools, guards

**Prefix:** BK · **Shape:** P4, P6 · **Rules:** BK7, BK12, BK13, BK16 · P34 · **Depends on:** T4. Parallel-safe with T5, T7, T8.

## Goal

The daemon runs backups on a restart-safe schedule (a maintenance task, **not** a trigger), exposes `backup.run|list|verify|
status|prune` as human-door socket methods, emits stable events for S58, and gives agents exactly two read-only tools. Every
absence (restore, narrow surface, agent services, write tools) is proven by a guard that is shown to fail.

## Behaviour (each a test)

1. **Schedule is restart-safe:** with a fake clock — last success 25 h ago, interval 24 h ⇒ runs once at start; 3 days of
   downtime ⇒ exactly one catch-up; disabled ⇒ never; a run in progress ⇒ the next tick skips, recorded `skipped: busy`.
2. **Daemon methods:** `backup.run` creates a verified backup and returns the view; `backup.list` returns newest-first with
   `canRestoreWithThisBinary`; `backup.verify {file}` with a path separator ⇒ `ErrBadParams`; `backup.status` reports `never`
   on a fresh store, `fresh` after a run, `stale` past `staleAfter` (fake clock), `failing` after two failed scheduled runs;
   `backup.prune {dryRun:true}` plans, `false` removes only per BK8.
3. **Events** carry only ids/enums/numbers and the basename; `backup.stale` fires once per transition and re-arms.
4. **SIGTERM mid-run:** cancel the context; no final-named partial; a `backup_run` row `cancelled`.
5. **Tool parity:** `backup_status` equals `backup.status` field for field (the records parity walk, both directions).
6. **Agent write tools do not exist:** registry exact-names test updated by exactly +1 here.
