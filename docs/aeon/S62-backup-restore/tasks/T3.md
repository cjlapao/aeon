# T3 · The `backup_run` migration and its store accessors

**Prefix:** BK · **Shape:** P3 · **Rules:** BK10 · **Depends on:** T1. Parallel-safe with T2.

## Goal

An append-only record of every backup, verify, prune and export — the source of "last success", "last verified" and
"age" — in one timestamped migration, with one write function and one read function, and no way to alter history.

## Files

- `aeon/internal/store/migrations/<date +%Y%m%d%H%M%S>_backup_run.sql` — **new**, leading `-- ` description line (the
  parser uses it). Timestamp **after** whatever is merged when T3 starts (T0 records it). Never edit `schema.go` or a shipped
  migration.
- `aeon/internal/store/backup_run.go` — **new**: `RecordBackupRun(in NewBackupRun) (BackupRun, error)`,
  `ListBackupRuns(f BackupRunFilter) ([]BackupRun, error)` (newest first, `Kind`, `Reason`, `Outcome`, `Limit` ≤ 500),
  `LastBackupRun(kind, outcome string) (*BackupRun, error)`. A discriminated refusal (`BackupRunRefusal`, the `ProjectWrite`
  shape — DB19) for a closed-set violation, so a caller never sees a raw CHECK error.
- Migration-count assertions bumped by **exactly one** per T0's list, each with a dated comment (`S62 T3`).

## The SQL

`CREATE TABLE backup_run (…)` per design BK10 (kind/reason/actor_kind/outcome/error_kind/verify_level/free_space_state as
CHECKed closed sets; `detail` `CHECK (length(detail) <= 512)`; `file_name` `CHECK (file_name IS NULL OR file_name GLOB
'aeon-state-????????T??????Z-v*.aeonbak')` — the regex of BK4 in GLOB form, with the Go constant and the SQL kept in
lockstep by a test); indexes `idx_backup_run_kind_outcome (kind, outcome, finished_at)`; triggers `backup_run_no_update`
(`BEFORE UPDATE` → `RAISE(ABORT,'backup_run is append-only')`) and `backup_run_no_delete`. **No FK to anything** (history
outlives files, P3).

## Behaviour

1. The actor stamped is a **parameter of the Go function** set by the caller's door (`user` socket, `daemon` ticker, `cli`
   direct door) — never read from JSON (BK10/P3); `agent` is not in the CHECK.
2. `detail` is built by the caller from a fixed template; the store refuses a `detail` containing a path separator run longer
   than the basename policy or any `/` outside `file_name` (a cheap tripwire against raw error text; the exact rule is a
   test).
3. Time via `s.Now()` (I9).

### Findings

- **F-T3-1 — the spec's P10 pattern does not match the spec's own test names.** The Commands line runs
  `-run 'BackupRun|Migration|frozen|Fingerprint'`, but the table names three tests without `BackupRun`
  (`TestRecordAndListNewestFirst`, `TestLastSuccess`, `TestDetailTripwire`) — under the spec's own pattern
  they would never run. Resolved by naming the tests `TestBackupRunRecordAndListNewestFirst`,
  `TestBackupRunLastSuccess`, `TestBackupRunDetailTripwire` (the spec's P10 line runs unchanged and now
  covers all nine). Same shape as F-T2-1: the spec contradicts itself; the resolution follows the repo
  convention and is recorded here.
- **F-T3-2 — "count assertions bumped by exactly one" is self-computing, not a literal edit.** T0 item 9's
  list (`helpers_test.go` frozen-count helpers, `policy_test.go:306-332`, `loop/counters_test.go:293-310`,
  the ledger `len(applied) == len(Migrations())` checks) all compute from `Migrations()` / the embedded
  directory, so the count moved 73 → 74 with zero edits. The only literal a new file adds is the pin this
  task's `TestMigrationCountAssertionsBumpedOnce` writes: `frozenFileCount() == 29`,
  `frozenMigrationCount() == 74`, dated comment. The `policy_test` / `counters_test` Fatal messages are
  historical prose about the FROZEN 45-block (this migration is a file, not a block entry) and were left
  untouched on purpose. The literal vintage slices (`Migrations()[:38]` etc.) must not move and did not.
- **F-T3-3 — `detail` cap: bytes in Go, characters in SQL.** The design says ≤ 512 bytes; the spec's SQL
  uses `length(detail) <= 512`, which for TEXT counts characters. The fixed templates are ASCII, where the
  two agree; the Go door enforces bytes (the stricter of the two), so the drift can only ever refuse, never
  admit. Recorded rather than "fixed" — the SQL is the spec's verbatim.
