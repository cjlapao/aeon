# T6 · Proposals: the `mcp_grant_revoke` kind, `desk` validators and effects

**Prefix:** MG · **Rules:** MG9, MG1 (one validator) · S35 TD1/TD3/TD4 · S37 T1 (the rebuild precedent) · **Depends on:** T5 and **S45 T1/T5** (`internal/desk` registry; generic `proposal.commit`).

## Goal

Agents can propose only *narrowing* MCP changes, and a person commits them through the **same generic commit** S45 built. The two existing MCP
proposal kinds move their effects off the file (they now write rows) and the closed `proposal.kind` enum gains **one** kind,
`mcp_grant_revoke` — the "design revision" S35 TD1 requires, made here.

- **Create-time validation** parity (S35 criterion 4): `proposal.create`'s validator seam resolves to the same `desk.Validate` — a payload refused by `proposal.create` is refused by `proposal.commit` for the same reason.
- `docs` untouched here (T7/T12 own the record).

## Behaviour

1. `mcp_grant_revoke` **can only narrow**: `Validate` refuses any payload whose effect would widen (there is none by construction; a test fuzzes the payload fields).
2. **Commit** is S45's `proposal.commit {id, digest}`: digest-bound, effect-then-flip, crash-safe retry, before/after = the affected agents' `GrantView` (verbatim); **reject needs a reason** (S45 T5). No new socket method is added by this task.
3. A proposal of any MCP kind is **inert**: `mcp.status`, the offer, `tools.grants` are byte-identical with proposals present (the S35 arbiter pattern, extended to MCP).
4. Existing proposals created before this slice (payloads naming agents by **name**, if any) are **migrated at read time** by the validator: a payload agent that does not resolve to a slug is refused at commit naming it (never guessed).
