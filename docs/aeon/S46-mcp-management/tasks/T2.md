# T2 · `internal/mcp`: pure `Assemble`/`Disassemble`, candidate validation, the round-trip law

**Prefix:** MG · **Rules:** MG1, MG2 (mapping), MG4, MG13 · MC11 · **Depends on:** T0. Parallel-safe with T1.

## Goal

Turn rows into the `mcp.Config` the **unchanged** registry consumes, and back, with **pure functions over mcp-local row structs** —
`internal/mcp` imports nothing new (no `internal/store`, no `database/sql`), so the layer stays deletable (MC11). Provide the
*candidate* operations every write uses: apply a change to the current config and run the one validator.

## Files (all in `aeon/internal/mcp/`; existing files **not edited**)

- `rows.go` — plain structs: `ServerRow{Name, Tier, AgentKey, Transport TransportConfig, Tools []ToolConfig, Enabled bool}`, `AgentRow{AgentKey, Core *[]string, Declares []string}`, `Rows{Servers []ServerRow, Agents []AgentRow}`. `AgentKey` is the **dispatch key** the registry uses (T0 item 4.2) — the caller maps slug→key before and after; `internal/mcp` never sees a slug.
- `assemble.go` — `func Assemble(r Rows, opt AssembleOptions) (Config, error)`; `AssembleOptions{IncludeDisabled bool}` (the registry path passes `false`, the **candidate** path `true`, MG4). Deterministic order: public servers by name, each agent's private by name, declares sorted. Returns the **validator's own error** (calls `Config.Validate()` on the result) — never its own sentence.
- `disassemble.go` — `func Disassemble(c Config) Rows` (all servers `Enabled:true`).
- `candidate.go` — `func (r Rows) With(change Change) (Rows, error)` where `Change` is a small closed sum: `AddServer`, `UpdateServer`, `RemoveServer`, `SetEnabled`, `Declare`, `Revoke`, `SetCore`; each returns the new `Rows` or a refusal naming the missing/duplicate thing; **the caller then `Assemble(…, IncludeDisabled:true)`** to validate.
- `rows_test.go`, `assemble_test.go`, `candidate_test.go`, `testdata/` (reuse S12's fixture configs: `grep -rn 'testdata' aeon/internal/mcp/*_test.go`).

## The round-trip law and the behaviours

1. `Assemble(Disassemble(c), {IncludeDisabled:true}) == c` for **every** fixture config (deep equal incl. `Core == nil` vs `[]`), and for 200 generated configs (a property test with a seeded RNG).
2. `Assemble` with `IncludeDisabled:false` omits disabled servers; it **keeps** `Declares` that name a tool on a disabled server (the grant stands, the server is merely not offered). Validation always runs on the **included-disabled candidate**, so a declaration cannot dangle; the registry config is then built by filtering *after* validation, so a declare on a disabled server resolves through the registry's existing "not configured" (`Refused`) path rather than a validation error. A test pins this exactly.
3. **One validator:** `Assemble` returns `Validate()`'s error text verbatim; a table of ≥ 15 bad configs (every refusal in `config_test.go`) produces the identical sentence via rows and via the file path.
4. **MC6 preserved:** an empty `rerun`/`effect` assembles as an unclassified tool (`Validate` accepts it as UNCLASSIFIED; `Registry.Refused` reports it) — identical to the file path.
5. **Env names only:** `Assemble` refuses an `Env` entry that fails `envNameRE` (via `Validate`) — a value-shaped string never reaches a `Config`.
6. `With(Change)`: adding a server whose name exists anywhere is refused naming it; removing a server removes its declarations **only if** the change says so (`RemoveServer{CascadeDeclares:true}`; default **refuses** while declared, naming the declaring agents — never a silent revoke); revoking an undeclared tool is a no-op with a reason.
7. **Deletability:** `internal/mcp`'s import list is unchanged from T0's baseline (asserted).

**Landmine pinned for T3 (the one thing this task could not silently resolve).** S12's `Registry.New(cfg)` re-runs `Validate` (unchanged, unchangeable). A law-2 view — disabled server omitted, its standing declares kept — is therefore deliberately NOT New-able: `TestAssembleOmitsDisabledForRegistryOnly` pins BOTH halves (New(view) refused by the unchanged validator; New(candidate) answers ToolsFor fully). **The offer path must build `New` from the validated INCLUDE-DISABLED candidate and apply the row's enabled-ness at the seam** — filtering the registry's view before New would let a disabled server's declaration reach New and be refused as a dangling declare, i.e. a validation error from a config nobody wrote. `Assemble(_, {false})` stays exactly law 2 (it is what the reads render); MG4's "only enabled servers are assembled into the config the registry sees" is honored one layer up, at the seam, where the row's flag lives.

**Deviations from the task file, recorded.** (1) `ServerRow.Tier` is S12's typed `Tier` constant (`registry.go`), not a new string const — the package already spells tiers, a second spelling would be a second source. (2) Round-trip law fixtures/generator are CANONICAL (sorted names/declares, nil-not-empty slices); an unsorted input Config loses ORDER and nil-vs-empty (never a fact — `Core`'s two empties are values and ride exactly). The spec's "deep equal incl. Core nil vs []" holds under that canonicalization; property = 200 seeded configs (`46022`). (3) The one refusal sentence whose text depends on map-iteration order (same server under two agents) is compared by shape, not bytes, in the verbatim table. (4) `Assemble` refuses impossible row shapes (public-with-agent, private-without, unknown tier, duplicate agent rows) with its OWN words — structural caller-bugs the T1 CHECK net already forbids; no Validate-shaped config reaches them, so "no second validator" stands (law 3's table proves rows==file for all 26 refusal cases). (5) `testdata/` not reused — the grep showed S12's configs are inline Go literals (`fixtureConfig` etc.), which is what the fixtures here extend.
