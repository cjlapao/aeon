# T9 · The CLI as a client of the daemon

**Prefix:** MG · **Rules:** MG5, MG6 · standing rule 1 · P34 · S45 PM4 · **Depends on:** T5, T7. Parallel-safe with T8, T10, T11.

## Goal

`aeon mcp` gains the management verbs as **clients of the socket methods** (T3/T4/T5), with the same offline fallback pattern as S45 T8 (one implementation, a second *caller*),
and **parity is a test**: no verb without a socket twin. `call` and `serve` keep their meaning.

## Verbs (final set decided by T0's parity table; expected)

```
aeon mcp list      [--agent A] [--include-refused] [--json]       # parity with today's output; now the person's unscoped view via mcp.servers/mcp.grants
aeon mcp show      NAME [--json]                                   # mcp.server
aeon mcp grants    AGENT [--json]                                  # mcp.grants (S12 states + reasons)
aeon mcp add       --name N --tier public|private [--agent SLUG] --transport stdio|http [--command C --arg A ...] [--env NAME ...] [--url U] [--tool NAME:RERUN:EFFECT ...] [--disabled]
aeon mcp update    NAME [--command … --arg … --env … --url … --tool …]
aeon mcp remove    NAME [--cascade-declares] [--yes]
aeon mcp enable|disable NAME
aeon mcp declare   --agent SLUG --tool SERVER.TOOL [--yes]
aeon mcp revoke    --agent SLUG --tool SERVER.TOOL
aeon mcp core      --agent SLUG [--set TOOL ...|--all]             # all = the whole core set (null)
aeon mcp import-config [--path P] [--dry-run] [--yes]
aeon mcp changes   [--server N] [--agent SLUG] [--limit N]
aeon mcp status / check [NAME]                                      # S34 reads: thin clients of mcp.status / mcp.check
aeon mcp call … / serve                                             # unchanged
```

`--env` takes **names only**; a `NAME=value` argument is refused client-side as input parsing (the same C17 rule), and the usage text says values come from the daemon's environment.
`--yes` gates the verbs that **widen** (`declare`, `import-config` replace) and `remove` of a server others declare; it is a seatbelt for a typo (S44/S45's stance), not a security control.

## The CLI re-validates nothing

Flag parsing refuses only what cannot be a value (a `NAME=value` env, a malformed `--tool` triple, a non-absolute `--path`). Every other refusal is the validator's sentence printed **verbatim**.
The `--tool NAME:RERUN:EFFECT` triple is input parsing (split on `:`), not a classification check.
