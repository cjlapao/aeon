# T10 · Seed sets `mcp.servers` and `mcp.grants`, declared and empty

**Prefix:** MG · **Rules:** MG10 · S43-extra SD2/SD5/SD6/SD12 · CONFIGURATION-ORDER rule 6 · **Depends on:** T5 and **S43-extra T3** (the engine). Parallel-safe with T8, T9, T11.

## Goal

Make "ship a default MCP server" a **record, not a new mechanism**. Declare two sets against the S43-extra engine and ship **zero** production records (none exist today — design fact 8): the empty
production set is tested and honest, and the machinery is proven with fake records so the first real default is a one-record change.

## The two sets (the engine's class gate forces the split)

| Set | Class | Records | Why |
| --- | --- | --- | --- |
| `mcp.servers` | **inert** | server **definitions**: name, tier `public`, transport, tools with classes, **`enabled=false`**, **no declarations** | A definition nothing is allowed to use permits nothing; applied at daemon start with the other inert sets |
| `mcp.grants` | **guard** | `declares` rows and any `enabled=true` flip for a system server | Enabling a server or granting a tool widens what an agent may do — **never automatic**, only an explicit human-door `seed.apply`/`restore` |

## Files

- `aeon/internal/mcpseed/` — **new** package (domain side; **imports no `internal/mcp`** — records carry the same plain row shapes T2 defines in `internal/mcp`, copied as a tiny local type to keep MC11): `decl.go` (`init()` registers both sets with **empty** `Records()`), `applier.go` (`Applier` over the engine's `Tx`: `Upsert` writes `mcp_server`+`mcp_server_tool` (`origin='system'`, `enabled` as the record says, always `0` for `mcp.servers`) or `mcp_declare`/enable flips for `mcp.grants`; `Fingerprint` = hash of the canonical live row; `Retire` flags only; `GuardAffecting()` false/true respectively; `Operator()` = `{Edit:false, Remove:true}`), `validate.go` (**the candidate is validated by the one validator** through a cmd/aeon-supplied `func(rows) error` seam — `mcpseed` must not import `internal/mcp`; `cmd/aeon serve` supplies it), tests.
- A system server's **removal** by an operator (`mcp.server.remove`, T5) is allowed and audited; the engine then reports it `removed` and never resurrects it; `seed.restore` brings it back. **Edit** of a system row is refused (T5), **duplicate** is `mcp.server.add` of a copy (origin user).
- `aeon/internal/seed/registry_test.go` — the default-registry assertion lists the sets present at this point (S43-extra's `agents.firstparty`, S45's `policy.corpus` if merged, **and** `mcp.servers` + `mcp.grants`); T0 records which exist.
- `aeon/cmd/aeon/serve.go` — supply the validator seam to `mcpseed` (one line).

## Behaviour

1. Production `Records()` are empty for both sets ⇒ `seed.status` shows each set `0/0 up to date` (an honest state, never an error).
2. **No startup path can reach `mcp.grants`** (S43-extra's class gate; re-asserted here with a fake record).
3. A fake `mcp.servers` record is validated by the candidate path **before** it is written (a record that would fail `Config.Validate` is refused at `go test` time by `mustRegister`'s content validation and at apply time with the validator's sentence).
4. An `mcp.servers` record with `enabled=true` or any declaration is **refused as a registration error** (it belongs in `mcp.grants`).
5. Adoption: a pre-existing **user** server with the same name as a seed record is a **conflict** (reported, never overwritten — S43-extra SD9); an operator-removed system server is `removed`, not resurrected.
6. Every apply writes `mcp_change` (`op='seed'`, ids-only summary) in addition to the engine's `seed_event`.

- [x] Two sets declared (inert/guard), zero production records, honest `0/0` status.
- [x] The class split enforced (registration refusal of enabled/private records in the inert set; no startup path to the guard set, asserted both ways); the one validator gates every record (seam supplied by cmd/aeon; nil fails closed).

- Do not ship a real server definition; do not put an enabled server or a declaration in the inert set.
- Do not import `internal/mcp` from `mcpseed`; do not bypass the validator; do not auto-resurrect a removed row.
- Do not add a startup path to the guard set.
