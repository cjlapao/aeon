# T1 — `card.go`: the A2A card, signed and optional

## Notes (2026-10-25, measured on this box)

- **Q2 answered (where does the card live): a file, for now — and no listener was opened.**
  `/.well-known/agent.json` is an HTTP convention and S19 owns HTTP; locally a card is
  `<agent-services dir>/<agent>.json` (`OpenCardStore(dir)` / `LoadCardFile`), the socket READ of
  cards is T10's method (registered once, in `method.go`), and the URL form is S21's remote-facing
  concern. The `AgentCard.URL` field is parsed but OPTIONAL locally — a first-party agent has no
  origin until S21; named here rather than smuggled.
- **The format is A2A's (0.x, as the design specifies — the design was written against
  `/.well-known/agent.json`), and v1.0's renames are recorded, not silently adopted:** v1.0 moved
  the well-known path to `agent-card.json` and card-level `url`/`preferredTransport` to
  `supportedInterfaces[]`. Nothing locally changes verification (it checks the bytes of the card the
  file carries), so S21 — which owns the remote surface — takes the v1.0 shape together with JWS.
- **The signature envelope is OURS, named as an addition (the only one):** A2A signs over HTTP with
  JWS (`AgentCardSignature`); a local agent has no origin, so the envelope is
  `{"card": <standard AgentCard JSON>, "publicKey": base64 ed25519, "signature": base64 ed25519}`
  detached over the card's **exact stored bytes**. `Sign` canonicalises to compact JSON at signing
  because `json.Marshal` **compacts** an embedded `json.RawMessage` — measured the hard way: signing
  pretty bytes stored under `Marshal` produced a card the file no longer carried byte-for-byte, and
  the *valid* fixture failed verification. The corollary is the sound half: `json.Unmarshal` keeps the
  `RawMessage` byte-for-byte, so a hand-edited file — even one inserted space inside the card object —
  breaks the signature (`TestWhitespaceInFileIsRefused` walks the disk-level attack). Fixtures are
  written with plain `Marshal` for the same reason (`MarshalIndent` re-indents embedded raw JSON).
- **Deviation from "S13's `Handler` gains an optional card and skills" — recorded, with the reason:**
  `handler.Handler` is **untouched**. A card/skill field there means `handler` imports `agentsvc`, and
  `agentsvc` importing `handler` (it must, to decorate the registry) would be a cycle — broken by
  moving types into `handler`, which makes the card layer structurally load-bearing and breaks T11's
  deletability. Instead `agentsvc` decorates: the card store is keyed by handler name, and AS1 is
  asserted the stronger way — **zero edits to any of the 25 bodies**, `handler.Lookup` + `handler.Build`
  on `golang-engineer` still work with an empty card store (`TestAgentWithNoCardStillDispatches`),
  which is what "an agent with none is markdown and a prompt" actually tests.
- **Refusal register:** every failure — tampered content, inserted whitespace, junk/short/wrong-length
  keys, emptied signature, a card filed under one agent naming another (both names printed), missing
  required fields, duplicate skill ids — returns `(nil, error)` naming the agent. No partial card
  exists in the type: `skills-look-fine` is unrepresentable. The authoring side refuses too: malformed
  bytes never get an envelope (`TestMalformedCardCannotBeSignedAtAll`).
- **No new signing dependency:** `crypto/ed25519`, stdlib. **No listener opened** (Q2's discipline —
  that is T10's and P25's).
- **Counts (dated 2026-10-25):** `internal/agentsvc` **9** `--- PASS` (valid, tampered ×4 shapes,

## Why this exists

An agent that cannot say what it does cannot be asked for anything. **"I am Groot, I can translate English
into Groot"** is a card.

**Two properties, and the second is the one with teeth.**

**Optional** (AS1). The 25 bodies S13 wrote have no card and must keep dispatching exactly as they do. If
this task makes a card required, the adoption story is gone and 25 files need editing.

**Signed** (AS2), and **a bad signature is a refusal, not a warning.** S15 imports agents from anywhere —
*"is this really from who it claims"* needs an answer that is not trust. A warning is a thing that scrolls
past; a refusal is a thing that stops.

**And the format is A2A's, not ours.** Agent Cards at `/.well-known/agent.json` with
`{id, name, description, tags, examples, inputModes, outputModes}` per skill. Inventing a shape here means
no third-party agent can ever be imported without a translation layer nobody will maintain.

**Read first:** the A2A card specification; S13's `Handler` struct — this **adds** to it; AS1 and AS2.

## Scope

**1. The card type matches A2A's shape.** Where our needs differ, extend with additional fields rather than
renaming theirs — a renamed standard field is a standard we do not implement.

**2. Signing and verification.** `crypto/ed25519` from the standard library is enough; no new dependency.
**Verification refuses**, and the refusal names the agent.

**3. A card is optional.** `Handler` without one is valid and dispatches. Assert with one of S13's 25,
unchanged.

**4. Answer Q2: where does the card live?** A2A's `/.well-known/agent.json` is an **HTTP** convention, and
**S19 owns HTTP** — so locally this may be a file plus a socket method until S21 needs the URL. Pick one,
state why, and do not open a listener for it (that is T10's and P25's concern).

**5. A tampered card is not partially used.** No "signature failed but the skills look fine" path. The
whole card is refused.
