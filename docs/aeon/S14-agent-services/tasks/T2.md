## Why this exists

**A typed request is reviewable. A free-text ask is not.**

The difference matters at two moments. At authoring time, a typed skill can be read and reasoned about —
*"this takes a topic and returns markdown"*. At call time, **a malformed request is refused before any
money is spent.**

That second one is the test that matters: a validation that happens after the model call is a validation
that costs exactly as much as no validation.

**And `inputModes`/`outputModes` earn their place.** They are what let a caller know a skill can accept a
file *before* sending one — which is the difference between a refusal and a wasted round trip.

**Read first:** A2A's skill shape; `card.go` (T1); AS3.

## Scope

**1. A2A's field set**: `id`, `name`, `description`, `tags`, `examples`, `inputModes`, `outputModes`.
`examples` is not decoration — it is what a discovering agent reads to decide whether a skill fits (T9).

**2. Validate before any model call**, and assert it with a `Client` spy at zero. The refusal names the
missing field.

**3. An unsupported mode names the supported set.** *"inputMode image/png not supported. Supported:
text/plain"*. *"Unsupported"* alone sends somebody to read source.

**4. Skills are optional** (AS1). An agent with a card and no skills is valid; an agent with neither is
valid.

**5. A skill is not a tool and not a prompt.** It does not appear in `ToolsFor(agent)` (S12's registry) and
it is not a system-prompt fragment. **If this task finds itself adding a skill to the tool registry, AS3 is
being violated** — a tool is a capability, a skill is a request for judgement.
