## Why this exists

**This task is A1's amendment, made true.**

> *"No spawn, no abort, no per-subtree cost rollup, because there is no tree."*

Right about process. Wrong about accounting. An agent asking an agent produces a **graph**, and the edges
exist whether or not anybody records them. **Refusing to record them did not make the cost unattributable
— it made it unattributed**, which is worse, because unattributed reads as zero.

**And the half that will get skipped: a `partial` child makes the parent `partial`.**

That is **P32** — an aggregate over uncertain values is itself uncertain. A rollup that sums numbers is
easy. A rollup that **propagates uncertainty** is the point, and a confident total over an uncertain child
is exactly the error S9's cost renderers exist to prevent, one level up.

**Read first:** S3's three-state `Cost` and P32; `chain.go` (T5); S13's design — **this task edits it** to
record A1's amendment.

## Scope

**1. A parent's cost is its own plus its children's**, computed over the recorded chain.

**2. The state propagates, and the rule is strict:**

| Any child | Parent becomes |
| --- | --- |
| `unknown` | **not `known`** — at best `partial`, and state which in the notes |
| `partial` | `partial` |
| all `known` | `known` |

**A parent is never more certain than its least certain child.**

**3. The rollup works after a restart.** The chain is rows (T5), so this is a query, not accumulated state.
**Do not cache a running total** — a cached total is a number that disagrees with the rows and nothing says
which is right.

**4. Record A1's amendment** in `docs/aeon/S13-agents/design.md`: still nothing spawns, and the no-rollup
conclusion is withdrawn. **Preserve the original wording and add the amendment** — the reasoning trail is
why these documents are trusted.

**5. A terminated chain still rolls up.** A refused cycle (T5) or a failed Task has a cost, and it is
attributable. A rollup that only works on success hides exactly the expensive failures.
