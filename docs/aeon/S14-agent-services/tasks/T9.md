# T9 — Discovery without dispatch

## Notes (2026-10-25, measured on this box)

- **Enumeration is the load path, not a second reader:** `CardStore.Discover` walks the cards directory
  and takes every card through `cs.Card` — the same `LoadCardFile` verdict (detached ed25519 over exact
  bytes) that `Invoke` consults. AS9's single truth holds by construction: a tampered card is excluded
  from the listing **and** refused at the door, and the test asserts both sides of that one verdict
  (`the listing excluded it but the door would honour it — two truths` is the failure it fears).
- **Broken cards are named, not swallowed:** `Discovery.Refuses` carries `"<agent>: <why>"` for every
  card the load path rejected (measured: tampered signature and non-JSON both land there, both named).
  Silence would be the worse bug — an operator who published a broken card should read the why, not
  notice an absence.
- **Candidates, never a choice:** `Discover` answers one struct holding slices, ordered by `sort.Strings`
  on the agent name (deterministic listing measured across two calls); there is no exported chooser in
  the package — the grep (`^func .*(Best|Pick|Choose|Select|Match)[A-Z]`) finds none, and would fail the
  day one appears. `SkillCandidate.CandidateSkillRef()` hands the chosen name over in the ONE spelling
  the policy door reads (`callee/skill`), so discovery and the door cannot drift apart.
- **The grep is the test, comments included** — measured twice the hard way: the first draft's own prose
  ("a 0.6 cosine match", "scores, ranks") tripped the vocabulary ban it documented, and the ban list
  itself overfired on `chain.go`'s local `best` counter in the longest-path walk — English, not an API.
  The final list bans the shapes that actually dispatch: `cosine · similarity · embedding · sqlite_vec ·
  vec0 · rank · bestMatch/bestAgent/bestSkill · nearest · topK · relevance` over every production file
  of the package, plus the adapter half (`cmd/aeon/agent_services.go` carries none of score/rank/
  similarity/best/candidate — the CLI takes a NAMED `skill:` and nothing else), and a regex holds that
  no exported entry point takes a `float` parameter (RollupCost RETURNS float64 money — a cost, not a
  fit; input position is what smuggles).
- **No embedding, no vector code** (asserted): `sqlite_vec`/`vec0` live in `internal/store` for S7's
  memory tables; this package imports neither, and the ban holds the boundary until S22 builds its
  index — which indexes THIS enumeration (scope 4: nothing here anticipates it beyond the flattening
  `SkillCandidates()`, still a list).
- **Deviation from `files_expected`:** none in Go files beyond the two named; the ban list's precise

## Why this exists

S22 will index cards and skills, and the next step is obvious and wrong: *"find an agent that can do X,
then call it."*

**A13 already refused this shape.** The handler registry is closed with **no generic fallback**, because
*"a generic handler writing Elixir produces something plausible, the loop reports `ok`, and the badness
surfaces three steps later attributed to the model."*

**Similarity-based dispatch is that failure with a better excuse.** A 0.6 cosine match is not a capability
claim; it is a sentence that looked nearby.

> **Similarity picks what to read about. A name picks what to call.**

**Read first:** A13 in S13; `skill.go` (T2) — `examples` is what makes a skill discoverable; AS9.

## Scope

**1. Cards and skills are enumerable** for discovery, with their `tags` and `examples` — which is what a
reader uses to judge fit.

**2. Invocation takes a name.** There is **no API, flag or parameter that accepts a score, a ranking or a
"best match."** Assert by grep over this package and the CLI.

**3. Discovery returns candidates, not a choice.** A ranked list is fine; a function that returns *the*
agent for a request is not, because every caller of it is a dispatch.

**4. S22's indexing is not this task.** This provides the enumeration S22 will index. **Do not add an
embedding here.**
