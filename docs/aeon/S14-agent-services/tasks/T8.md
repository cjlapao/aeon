## Why this exists

**The same rule, a third surface.**

| | |
| --- | --- |
| W23 | a tool **result** is untrusted |
| MC7 | a tool **description** is untrusted |
| **AS12** | a **skill result** is untrusted |

All three are prose from a stranger landing in a prompt — and **S15 makes the stranger importable from
anywhere**, which is why this cannot wait for a problem to appear.

**Read first:** W23 in S11, MC7 in S12 — **reuse their labelling mechanism, do not write a third**; AS12.

## Scope

**1. Label a non-first-party skill result** where it reaches a model, using the mechanism MC7 established.
A third labelling implementation is two too many.

**2. The label survives a spoofed label**, same as MC7: a result containing the literal label text must not
close the labelled region and appear to speak as Aeon.

**3. Verbatim.** Do not sanitise or rewrite. A rewritten result is one the model acts on while nobody can
see what the agent actually said.

**4. Answer Q3: where is "first-party" read from?**

The design's answer is that first-party results need no label, because those bodies are reviewed in a pull
request. **But S15 makes "first-party" a property of the registry, not of the code** — an imported agent
could be marked however the registry says.

So decide and state it: **is first-party a compile-time fact or a registry field?** If it is a registry
field, **an imported agent must not be able to claim it** — which makes this a security decision rather
than a formatting one.
