# T3 · Git worktree actions

**Prefix:** PA · **Rules:** PA5 · **Depends on:** nothing — parallel-safe with T1/T2. **Answers plan.md's Q1.**

## Q1 — does `CreateBranch`'s `Reused` pattern already cover a re-add?

Read `internal/action/git_actions.go:94-131`'s `CreateBranch` in full before writing `AddWorktree` — it
already distinguishes "branch exists, reuse it" from "branch is new, create it," returning
`GitResult{Reused: true}` in the first case. `git worktree add` has an analogous case (the path already
exists as a worktree — e.g. recovery re-running after a crash between insert and `add`, design.md PA12):
`VERIFY` whether `git worktree add -B <branch>` (force-create-or-reset) plus a pre-check with `git worktree
list --porcelain` is the right shape, or whether `git worktree add` itself answers idempotently enough
without one. Record the real decision in Notes — do not assume `CreateBranch`'s exact mechanism transfers
unchanged, since worktrees and branches are different git objects with different reuse semantics.

## Goal

Two new `GitActions` methods, same signature shape and effect-class convention as the three that already
exist.

## Files to modify

- `internal/action/git_actions.go` —
  ```go
  // AddWorktree is check-then-act (local class — it affects nobody until a
  // push does, same reasoning as CreateBranch). dir is the PRIMARY checkout
  // (where `git worktree` commands are run from); path is the new worktree's
  // location; the branch is created FROM baseSHA.
  func (a *GitActions) AddWorktree(ctx context.Context, dir, path, branch, baseSHA string) (GitResult, error)

  // RemoveWorktree tears one down. Idempotent: a path that is already gone
  // (a prior crash-safe retry, or an operator's own cleanup) is success, not
  // an error — the same "desired end state" discipline MergePR's AlreadyMerged
  // branch already uses (forge_actions.go:293-310).
  func (a *GitActions) RemoveWorktree(ctx context.Context, dir, path string) (GitResult, error)
  ```
- `internal/action/class.go` — register both in the same effect-class/strategy tables `GitCreateBranch`
  uses (`GitCreateBranch: StrategyCheckThenAct` at `class.go:71`, `EffectLocal` — both new actions are the
  same class: local until a push happens elsewhere in the ladder).
- `internal/action/git_actions_test.go` — the tests below, against a real throwaway git repo (this
  project's standing rule: never a fake git for S16-shaped code).

## Tests

| Test | Asserts | Fails when |
| --- | --- | --- |
| `TestAddWorktreeCreatesRealWorktree` | `git worktree list` in the primary checkout shows the new path after a call | the command/args are wrong |
| `TestAddWorktreeFromBaseSHA` | the new worktree's HEAD is exactly `baseSHA`, not the primary checkout's current tip | base pinning wrong — a race where the primary checkout moved between calls would otherwise leak into the new worktree |
| `TestAddWorktreeIsIdempotentOnRetry` (Q1's finding) | calling `AddWorktree` twice with the same args (simulating a recovery retry) succeeds both times, same resulting state | the idempotency decision from Q1 wasn't actually implemented |
| `TestRemoveWorktreeTearsDown` | the path is gone from `git worktree list` and from disk after the call | cleanup incomplete (a `.git` admin file left behind still blocks the branch name from being reused) |
| `TestRemoveWorktreeOnAlreadyGoneIsSuccess` | removing a path that doesn't exist (already cleaned up) returns success, not an error | idempotency missing on the teardown side |
| `TestWorktreeOperationsAreLocalEffectClass` | both actions classify as `EffectLocal`/`StrategyCheckThenAct` | misclassification would wrongly ask a human at use-time (L22) for a purely local operation |

## Definition of done

## Do NOT

- Do not make either method talk to the forge (remote) — these are purely local git operations, same as
  `CreateBranch`/`CommitAndPush`/`MergeBranch` (the local one, unused by this slice but present as
  precedent) already are.
- Do not leave a partial worktree (git metadata written, directory missing, or vice versa) on any error
  path — a test should kill the process mid-call and confirm `git worktree list` and the filesystem agree.
