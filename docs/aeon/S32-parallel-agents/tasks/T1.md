# T1 · Schema: the cap and the worktree ledger

**Prefix:** PA · **Rules:** PA14, PA5 · **Depends on:** nothing — first task.

## Goal

One migration: `component.max_parallel_agents` (the cap, PA14) and the new `loop_worktree` table (PA5's
write-ahead ledger for ephemeral, daemon-owned git worktrees).

## Files to create / modify

- `internal/store/schema.go` — append `{N, "00NN_parallel_agents", "<why>", migrationNN}` (N = the real
  next free number — `VERIFY: grep -n '^\t\t{[0-9]*, "' schema.go | tail -3` at write time, this repo's
  ledger moves fast; do not copy a number from this file). DDL:
  ```sql
  ALTER TABLE component ADD COLUMN max_parallel_agents INTEGER NOT NULL DEFAULT 1
    CHECK (max_parallel_agents BETWEEN 1 AND 16);

  CREATE TABLE loop_worktree (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    component_root TEXT NOT NULL,
    loop_slug      TEXT NOT NULL,
    owner_kind     TEXT NOT NULL CHECK (owner_kind IN ('lane','task')),
    owner_id       TEXT NOT NULL,
    path           TEXT NOT NULL,
    branch         TEXT NOT NULL,
    base_sha       TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    removed_at     TEXT,
    FOREIGN KEY (component_root, loop_slug) REFERENCES loop (component_root, slug) ON DELETE CASCADE
  );
  CREATE INDEX idx_loop_worktree_live ON loop_worktree (component_root, loop_slug) WHERE removed_at IS NULL;
  ```
  (SQLite partial indexes are supported; `VERIFY` this project's SQLite build/driver version admits the
  `WHERE` clause on `CREATE INDEX` — `mattn/go-sqlite3` does, but confirm against this repo's pinned
  version before assuming.) Bump every migration-count assertion repo-wide (the now-standard checklist:
  `grep -rn '!= [34][0-9]\|== [34][0-9]' internal/store internal/loop --include=*_test.go` after editing).
- `internal/store/components.go` — add `max_parallel_agents` to `UpdateComponent`'s settable fields
  (`VERIFY` current line — confirmed earlier this session around line 100-155 — the same `set +=
  ",project_id=?"` pattern applies: `if in.MaxParallelAgents > 0 { set += ",max_parallel_agents=?" ... }`),
  validated against the CHECK's own range (1-16), refusing and naming the value outside it — the CLI/socket
  layer should never discover the bound by provoking a SQL error.
- `internal/store/loop_worktree.go` — **new file**. `CreateLoopWorktree(sc Scope, ownerKind, ownerID, path,
  branch, baseSHA string, at string) (LoopWorktree, error)`; `ListLiveLoopWorktrees(sc Scope)
  ([]LoopWorktree, error)` (filters `removed_at IS NULL`); `SettleLoopWorktree(id int64, at string) error`
  (guarded `UPDATE ... SET removed_at = ? WHERE id = ? AND removed_at IS NULL` — the same claimed-row
  pattern `DecideProposal`/`TransitionPluginAgent` already use; a double-settle is a no-op row count of
  zero, not an error, since recovery (T6) may race with a normal teardown and both attempts are benign).
- `internal/store/loop_worktree_test.go`, `internal/store/components_test.go` — the tests below.

## Tests

| Test | Asserts | Fails when |
| --- | --- | --- |
| `TestMaxParallelAgentsDefaultIsOne` | a freshly created component reads `max_parallel_agents == 1` | the default drifted from PA1/PA14 |
| `TestMaxParallelAgentsBoundRefused` | `UpdateComponent` with a value outside 1-16 refuses, naming the value, before any SQL runs | the CHECK alone is the only guard (a SQL error is a worse UX, not a worse guarantee) |
| `TestLoopWorktreeCreateAndSettle` | a created row reads back live; settling it sets `removed_at` and a second settle is a benign no-op | the guard isn't idempotent, which T6's recovery race depends on |
| `TestListLiveLoopWorktreesExcludesSettled` | a settled row never appears in `ListLiveLoopWorktrees` | filter wrong |
| `TestLoopWorktreeCascadesWithLoop` | deleting the owning `loop` row (the same cascade `ArchiveLoop` already triggers) removes `loop_worktree` rows with it | FK/cascade missing — an archived loop must not leave ledger rows an operator finds confusing months later |
| `TestAFreshSchemaAndAnUpgradedSchemaAreIdentical` (existing) | still green | DDL diverges fresh vs. migrated |

## Definition of done

- [ ] Migration takes the real next free number; both schema pieces match design.md exactly.
- [ ] `UpdateComponent` validates the bound before touching SQL.
- [ ] `loop_worktree`'s settle is idempotent and cascades with its loop.

## Do NOT

- Do not place `max_parallel_agents` on `project` (the S38 group tier) — PA14 is explicit that this
  predates and corrects that naming.
- Do not let `CreateLoopWorktree`/`SettleLoopWorktree` be callable in a way that could race into two live
  rows for the same `(owner_kind, owner_id)` — this task does not need a uniqueness constraint for that
  (T5's dispatcher is the only caller and only ever creates one at a time per unit), but do not add a
  caller here that could violate it either.
