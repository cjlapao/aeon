# T8 · The two-shape acceptance tests

**Prefix:** PA · **Rules:** D1, D2 · **Depends on:** T5, T6, T7.

## Goal

The brief's D1/D2, as real end-to-end tests — a full loop run, not a unit test of `DecideReady` or the
fan-out in isolation. These are the tests that prove the pieces actually compose.

## Files to create

- `internal/loop/parallel_acceptance_test.go` — **new file**.
  - **D1 (Shape A).** A two-lane blueprint fixture (T2's clean `parallel_group` fixture, or a fuller one
    built for this test) run twice against a scripted/fixture model: once with the component's
    `max_parallel_agents = 1`, once with `= 2`. Assert: both runs reach the same final `LoopState`
    (position set empty/terminal, same `LaneStates`, same `StepStates` content) — **the serial and
    parallel runs must agree on outcome**, only on timing/interleaving do they differ. At cap 2, assert
    both lanes' worktrees existed concurrently at some point (a timing assertion via the fixture model's
    own controllable delay, the same technique this project's existing concurrency tests use).
  - **D2 (Shape B).** The brief's own T1-T5/T6/T7/T8-T10 ten-task dependency fixture, run at a cap ≥ 5.
    Assert: the three "waves" happen in the right order (T6 never starts before all of T1-T5 settle, T7
    never starts before T6, T8-T10 never start before T7), **without the test or the engine ever naming a
    wave** — the assertion reads task start/end timestamps and dependency edges, not a wave number, because
    the engine has none (design.md's own point).
  - Both tests also assert **zero orphaned `loop_worktree` rows** and **zero orphaned real directories**
    after the run completes — the cheapest possible regression check for R1.

## Tests

| Test | Asserts | Fails when |
| --- | --- | --- |
| `TestShapeAIdenticalOutcomeSerialVsParallel` | D1 | cap-2 run disagrees with cap-1 run on final state |
| `TestShapeAActuallyOverlapsInTime` | D1's concurrency claim is real, not just "allowed and never used" | the fixture never actually overlaps despite cap 2 |
| `TestShapeBWavesEmergeFromDependsOn` | D2 | the dependency-driven ordering is violated, or the engine turns out to secretly need wave numbers after all |
| `TestNoOrphanedWorktreesAfterEitherRun` | zero live `loop_worktree` rows, zero stray directories, after both D1 and D2's runs | T5's teardown path has a gap only a full run exposes |

## Definition of done

- [ ] D1 and D2 both pass as real, full-loop, end-to-end tests.
- [ ] Shape A's concurrency is proven to actually overlap, not just permitted.
- [ ] Shape B's waves are proven to emerge from `depends_on` alone.
- [ ] Zero orphaned worktree rows or directories after either run.

## Do NOT

- Do not write these as unit tests of `DecideReady` alone — they must run a real loop through to
  completion, the same way this project's other acceptance-style tests (S34/S36's "the slice is one test")
  do.
- Do not introduce a wave concept into the test's own assertions as a shortcut — assert on dependency
  edges and timestamps, proving the engine needs no wave concept, not assuming it.
