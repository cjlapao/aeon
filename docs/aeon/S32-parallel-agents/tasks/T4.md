# T4 · `RuntimeState.Position` → `Positions`

**Prefix:** PA · **Rules:** PA13 · **Depends on:** T1. **Answers plan.md's Q2 and Q3.**

## The audit list (R2) — confirmed this session

`grep -rln '\.Position\b' internal/loop internal/protocol internal/store --include=*.go | grep -v _test`
returns exactly nine files, **all inside `internal/loop`** — `retry.go`, `advance.go`, `state.go`,
`phases.go`, `runner.go`, `execute.go`, `continue.go`, `escalate.go`, `decide.go`. **Nothing in
`internal/protocol` or `internal/store` references `.Position` directly** — the field crosses to the wire
only inside the serialized `RuntimeState` JSON blob (`st.RuntimeJSON()`, confirmed in `runner.go`'s
`AnswerGate`). This is good news for Q3: there is no separate wire shape to widen, only the one JSON field,
which makes an additive, backward-compatible decode (below) sufficient — no second "positions" field
needed beside a kept "position" field on any protocol type, because no protocol type names it at all.

## Goal

Widen `RuntimeState.Position Position` to `RuntimeState.Positions []Position`, audit all nine files, and
provide a decode path so an existing stored loop (one `Position`, written before this task) reads back
correctly as a one-element `Positions` slice. **This task changes no behavior** — at the end of it, every
existing test in `internal/loop` passes with no assertion changes, because every loop that exists today has
exactly one position and will continue to be represented that way; only the *type* changed, from a bare
value to a one-or-more-element slice.
