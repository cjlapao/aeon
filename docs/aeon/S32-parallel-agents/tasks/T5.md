# T5 · `DecideReady` and the worktree-aware fan-out

**Prefix:** PA · **Rules:** PA8, PA9, PA10 · **Depends on:** T1, T2, T3, T4. **The slice's largest task.**

## Goal

1. `DecideReady(bp, st, cap) []Action` — `Decide`'s sibling, returning a set.
2. The fan-out inside `Run`/a new parallel path: one goroutine per ready action, a results channel, the
   loop's own goroutine (already running inside `Runner.Start`'s `go func()`) selects on it and re-decides.
3. Per-unit `WorkspaceRoot`: before a unit's first dispatch, create its worktree (T1/T3's functions,
   PA5's write-ahead order); on terminal, remove it.

## Files to modify

- `internal/loop/decide.go` — `DecideReady`, beside the existing `Decide` (`VERIFY` current line, confirmed
  this session at `decide.go:35`). At `cap <= 1`, **call `Decide` and wrap its result in a one-element
  slice — do not reimplement the single-action logic.** At `cap > 1`:
  - For each non-iterating, non-`ParallelGroup` lane: behaves exactly as `Decide` already would at that
    lane (call the same per-lane logic `Decide`/`decideStep` already use, factored out if it isn't already

  - For a live `ParallelGroup` (all members' `When` guards currently pass): include every member's action

  - For an `iterate: tasks` lane with `Parallel: true`: query ready tasks (`status == pending` and every

    `ActRunModelStep`-shaped action per ready task.
- `internal/loop/runner.go` / a new `internal/loop/advance_parallel.go` — the fan-out:
  ```go
  func AdvanceLoopParallel(ctx context.Context, dep Deps, id string, cap int) (Result, error) {
      // ... fetch st, compute ready := DecideReady(st.Blueprint, st, cap - inFlight) ...
      type unitResult struct { action Action; result ModelResult; err error }
      results := make(chan unitResult, cap)
      inFlight := map[string]context.CancelFunc{} // keyed by a stable unit id (lane id, or task id)
      for _, a := range ready {
          ctx, cancel := context.WithCancel(ctx) // per-unit, NEVER a shared cancel (PA7)
          inFlight[unitKey(a)] = cancel
          go func(a Action, ctx context.Context) {
              res, err := runOneUnit(ctx, dep, st, a) // PA10
              results <- unitResult{a, res, err}
          }(a, ctx)
      }
      for len(inFlight) > 0 {
          r := <-results
          delete(inFlight, unitKey(r.action))
          // persist r's outcome (existing per-position save/emit path, T4's Positions-aware version);
          // re-DecideReady for newly-ready units (a sibling's completion may satisfy a dependent's
          // depends_on) and launch any new ones up to cap - len(inFlight)
      }
      // ... existing loop/lane state transitions, unchanged in kind ...
  }
  ```
  **The per-unit `context.WithCancel` is deliberately never called except by that unit's own completion or
  the loop's own shutdown** — PA7 forbids a sibling's failure from cancelling another unit's context, and a
  test must prove this (test map below), not just a code comment.
- `internal/loop/run.go` (`Run`, confirmed this session at `runner.go:14`) — dispatches to
  `AdvanceLoopParallel` when the component's `max_parallel_agents > 1` **and** the current decision set has
  more than one ready action; otherwise calls the existing serial path unchanged (D8).
- `runOneUnit` (new, in the fan-out file) — PA10: resolve the unit's `WorkspaceRoot`. If the unit is new
  (no live `loop_worktree` row for its `(owner_kind, owner_id)`), create one — T1's `CreateLoopWorktree`
  **then** T3's `AddWorktree` (write-ahead order, PA5) — then call `dep.Model(ctx, st, step, prompt)` with
  that path as the workspace root. On the unit reaching a terminal state, call T3's `RemoveWorktree` then
  T1's `SettleLoopWorktree`.
- `internal/loop/decide_test.go`, a new `advance_parallel_test.go` — the tests below.

## Definition of done

- [ ] `DecideReady` at cap 1 is provably identical to `Decide`, for every existing fixture.
- [ ] Both parallel shapes produce the right ready sets, confirmed by dedicated tests.
- [ ] Worktree create/remove is exactly one per unit, in the write-ahead order.
- [ ] A sibling's failure never cancels another unit's context — proven, not asserted in a comment.
- [ ] Redecision is channel-driven, no polling.

## Do NOT

- Do not reimplement `Decide`'s single-action logic inside `DecideReady` — call through to it at cap 1.
- Do not share one `context.Context`/cancel across concurrently-dispatched units.
- Do not poll or sleep anywhere in the fan-out's redecision path — the channel receive is the only wakeup.
- Do not create a worktree for a unit before this task's write-ahead order (ledger row, then real `git
  worktree add`) — reversing the order defeats R1's whole mitigation.
