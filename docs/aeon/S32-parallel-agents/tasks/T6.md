# T6 · Recovery: per-position resume, worktree reconciliation

**Prefix:** PA · **Rules:** PA12 · **Depends on:** T5.

## Goal

Startup recovery resumes every active position in a loop (not one), and reconciles every live
`loop_worktree` row against reality before `DetermineCase` runs for the position it belongs to.

## Files to modify

- Wherever S7's startup recovery walk lives (`VERIFY: grep -rn 'StepsByStatus(StepRunning)\|RunningStepIDs'
  internal/daemon` — the brief cites both names; confirm the real current call site) — add the worktree
  reconciliation pass **before** the existing per-step `DetermineCase` walk: for every `loop_worktree` row
  with `removed_at IS NULL`, run `git worktree list --porcelain` against the component's primary checkout
  and classify:
  - **Git agrees the path is live** → proceed to that position's ordinary recovery, `WorkspaceRoot` = the
    worktree's path.
  - **Git has no record of it** (crashed between T1's ledger insert and T3's real `add`) → re-run
    `AddWorktree` with the row's own `branch`/`base_sha` (T3's idempotent-retry path, confirmed there) —
    then proceed to recovery.
  - **The position itself already reads a terminal status** (crashed between the unit settling and the
    worktree being removed) → run `RemoveWorktree` + `SettleLoopWorktree`, no position to recover.
- The per-step recovery loop itself: `VERIFY` its current shape assumes one step per loop (likely true
  today, confirmed by this slice's earlier recon that `StepsByStatus` already returns a list, not
  singular) — change it to recover each of a loop's several active positions independently, same
  `DetermineCase`/`RecoverStep` calls, one per position.
- `internal/daemon/recover_test.go` (or wherever S7's recovery tests live) — the tests below.

## Tests

| Test | Asserts | Fails when |
| --- | --- | --- |
| `TestRecoveryReattachesLiveWorktree` | a clean-crash case (worktree genuinely exists) resumes the position with the correct `WorkspaceRoot` | reattachment logic wrong |
| `TestRecoveryRebuildsWorktreeCrashedBeforeAdd` | a `loop_worktree` row with no matching `git worktree list` entry is rebuilt from `branch`/`base_sha`, then the position resumes | the crashed-before-add case isn't detected or isn't rebuilt |
| `TestRecoveryCleansUpAlreadySettledPosition` | a row whose position already reached a terminal status is settled and its worktree removed, with no recovery attempt on a position that doesn't need one | stale ledger rows accumulate |
| `TestRecoveryHandlesSeveralPositionsPerLoop` | a real `kill -9` with two running positions recovers both, each from its own checkpoint and its own (possibly rebuilt) worktree | recovery still assumes one step per loop somewhere |
| `TestRecoveryNeverDoublesAWorktree` | running the reconciliation pass twice (simulating a recovery that itself gets interrupted) never creates a second real worktree for the same row | the idempotency from T3/T1 doesn't actually compose across a second recovery attempt |

## Definition of done

- [ ] All three worktree-reconciliation cases (reattach, rebuild, cleanup) have a passing test with a real
      `kill -9`, not a simulated crash flag.
- [ ] Recovery resumes every active position in a loop, not just the first.
- [ ] Running the reconciliation pass twice is provably safe.

## Do NOT

- Do not trust a `loop_worktree` row's `removed_at IS NULL` alone — always confirm against real git state
  before resuming a position against it.
- Do not recover positions sequentially in a way that silently caps at one — the whole point is proving
  several at once.

## Notes

2026-10-30 (BUILT in `internal/loop`; daemon wiring a named gap). The worktree reconciliation (PA12) is `ReconcileWorktrees` (`internal/loop/reconcile_worktree.go`): for every live `loop_worktree` row it classifies against git (a `gitHas` seam — real `git worktree list` in the daemon, a recording fake in the test) and acts — reattach (git agrees the path is live: the row stands, `WorkspaceRoot = path`), rebuild (git has no record, crashed between T1's ledger insert and T3's real add: re-run `AddWorktree` with the row's own branch — T3's idempotent retry), or cleanup (the position already reads a terminal status: `RemoveWorktree` + `RemoveLoopWorktree`). It is provably safe to run twice (every action is idempotent — the guarded writes from T1, the `Reused` path from T3), so a recovery that itself gets interrupted cannot create a second real worktree for the same row. The daemon side is `ReconcileLoops` (`internal/daemon/reconcile_loops.go`), a per-loop PA12 pass: it lists every loop the daemon holds and, per loop, calls `ReconcileWorktrees` fed by the two seams the loop package cannot own — (1) `worktreeLive`, a real `git worktree list --porcelain` read through the daemon's own git client (the `--porcelain` output is parsed by the `worktree ` line prefix, so only a worktree's path is read live, not its HEAD/branch/locked state; a workspace the daemon cannot list is a named failure, never a false "nothing is live" that would rebuild every row on a guess), and (2) `TerminalFor` (`internal/loop/reconcile_worktree.go`), the per-position terminal read — a task is terminal on its closed successful set (complete/merged/skipped/superseded), a lane is never terminal on its own (its settle rides its loop), and an absent or unresolvable task answers not-terminal so it rebuilds rather than settles (a row with no row is a brand-new unit). It is wired into the serve recovery goroutine (`cmd/aeon/serve.go`) before `d.Recover` and `d.StartLoops` — a crashed loop's positions are reconciled against real git before any of them is recovered — gated by `--no-recover` and logged, never fatal (a reconciliation outage must not take the daemon with it, the same bargain as the recovery scan). A storeless daemon answers zero, not an error; a loop with a valid scope but no live rows is counted, not an error (the git seam is never asked).
