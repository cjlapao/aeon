# T4 — duplicate detection

## Why this exists

D5/N3, and R3's named risk: *"the first time someone wants to 'reduce noise,' auto-closing looks
tempting."* This task exists partly to make that temptation structurally unreachable, not just discouraged
in prose.

## Scope

**1. On bug creation**, compute and store an embedding in `bug_vec`, project-scoped (D6, N2 — no
cross-project lookup, ever).

**2. `SuggestDuplicates(bug) ([]Bug, error)`**: returns candidate matches within the same project, ranked by
similarity. **This function has no side effect** — it does not write `duplicate_of`, does not change
`validation_state`, does not close anything. It is a read, full stop.

**3. `ConfirmDuplicate(bug, of, confirmedBy string)`**: the **only** function in this package that writes
`duplicate_of`, and it refuses a `confirmedBy` that does not name an actual person-originated call path (the
same shape S24's policy-authorship check — `checkAuthorship` — restricts a write to a named, legitimate
source, applied here to confirm-duplicate rather than policy).

## Validation

- [ ] `TestDuplicateOfNeverSetWithoutHumanOriginatedCall` — a grep/call-site check: `duplicate_of` is
      written in exactly one function, `ConfirmDuplicate`, and nowhere else in this package or any caller
- [ ] `TestDuplicateSuggestionIsProjectScopedOnly` — a candidate from a different `project_root` never
      appears in `SuggestDuplicates`'s results, even with an identical embedding
- [ ] `TestNoAutoCloseUnderAnyThreshold` — a fixture with a near-perfect similarity match still requires an
      explicit `ConfirmDuplicate` call; nothing closes or transitions the bug on `SuggestDuplicates` alone
