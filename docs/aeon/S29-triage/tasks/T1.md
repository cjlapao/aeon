# T1 — `schema.go`: `bug`, `bug_vec`

## Why this exists

Everything else in this slice writes rows here. Find the current highest migration number at the time this
task starts — do not hardcode one.

**Read first:** `design.md` §3 (the schema shape) and §2 T1 — priority's shape is copied verbatim from
`S26-roadmap`'s `roadmap_item.priority_state`/`priority_label` columns (not re-derived), so a hand-off row
never needs translation between the two tables.

## Scope

**1. `bug`**: `id`, `project_root` (`NOT NULL`), `title` (`TEXT NOT NULL`), `body` (`TEXT NOT NULL`),
`validation_state` (`TEXT NOT NULL DEFAULT 'unvalidated' CHECK (validation_state IN ('unvalidated',
'reproduced','not-reproduced','could-not-tell'))` — D1's four, closed), `priority_state` (`TEXT NOT NULL
DEFAULT 'unknown' CHECK (priority_state IN ('known','assumed','unknown'))`), `priority_label` (`TEXT`,
nullable), `filed_by` (`TEXT NOT NULL`), `duplicate_of` (`INTEGER`, nullable, self-referencing
`REFERENCES bug(id)`), `roadmap_item_id` (`INTEGER`, nullable), `created_at`, `updated_at`.

**2. `bug_vec`**: a `vec0` virtual table (sqlite-vec), one row per `bug.id`, project-scoped (D6) — the
**second** `vec0` table in this schema (after `S28-memory`'s `learning_vec`). No row is required to exist;
a bug with no computed embedding yet is a normal, working state.

**3. No column, no FK, shares a table or a row-kind-discriminator with `learning`/`learning_vec` or any
S22 table.** N5, asserted as a test, not just a review comment.
