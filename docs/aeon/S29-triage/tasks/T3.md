# T3 — `file_bug` and automatic dispatch

## Why this exists

`design.md` §2 T2/T3: D7's self-filing needs a tool to call, and filing dispatches a validation attempt
automatically — no project gate, because G14 already bounds what an unattended attempt may do. **Read
`design.md` §2 T2 in full before assuming a gate is missing by accident** — it is a deliberate decision, not
an oversight to "fix" by adding one.

## Scope

**1. `file_bug` native tool**: known shape `{title, body, priorityLabel?}` — the schema **does not accept**
`validationState` or `priorityState` fields from the caller at all (not merely ignores them — they are not
in the schema, so a model cannot even attempt to set them). The engine sets both to their defaults on
`Create` (T2).

**2. On any bug creation** (via `file_bug` or the human-facing path T7 builds), **dispatch a validation
attempt immediately**: an ordinary `loop.start` (unchanged entry point, no second path), G14-pinned the same
way any loop is, with a prompt that reads the bug's `title`/`body` and attempts to reproduce it.

**3. On the attempt's completion**, call `internal/triage`'s transition (T2) to move the bug out of
`unvalidated` based on the attempt's outcome.

## Validation

- [ ] `TestFileBugRefusesValidationOrPriorityFields` — a crafted call including either field is refused
      before any model call (schema-level refusal, not a runtime check)
- [ ] `TestFilingDispatchesAttemptWithNoExplicitTrigger` — creating a bug through either path starts a loop
      without any separate "start validating" call
- [ ] `TestAttemptIsOrdinaryG14PinnedLoop` — the dispatched loop's attendedness, policy and cost-cap
      handling are identical to any other S5 loop's — no special-cased governance path
