# T7 · Post-merge watch and failures-to-triage: migration M3, `internal/gatewatch`, the terminal reactor

**Prefix:** VG · **Rules:** VG15, VG16 · **Depends on:** T2 (`ReadChecks`), T5 (`merge_event`), T6 (the merge seam and `verify-failed`).

## Goal

After a merge the daemon keeps looking at the base branch's checks for the merge SHA — cold, from rows, bounded — and when anything terminal goes red
(a verify run the loop could not fix, red CI that stopped a merge, a base branch that went red after landing) it files **one** unvalidated bug with a
fixed-template body and emits an event. No automatic revert (OD5).

## Behaviour (each a test, over `forge.Fake` + a fake clock)

1. Merge success ⇒ a `merge_watch` row `pending`; the watcher polls; checks `pending` then `success` ⇒ `green`, event `merge.watch.green`, no bug.
2. A check `failure` ⇒ `red`, one bug filed (`unvalidated`, `system:gates`), event `merge.watch.red`; a second red for the same subject files nothing and bumps the counter.
3. Daemon restart between polls ⇒ the next tick resumes from the row (`next_check_at`), nothing in memory; a restart after the window ⇒ `expired`.
4. Zero checks forever ⇒ `expired` with `none-reported`; **no event claims green**. Transport errors never produce `green` or `red`.
5. A forge with no `CheckReader` (or a non-GitHub origin) ⇒ no watch row; `merge_event.evidence` says `checks: not-reported`.
6. A loop blocked by exhausting `verify_rounds` ⇒ one bug; a loop that failed a verify and then passed ⇒ none; the same verify subject blocked twice (two loops) ⇒ one bug, `count=2`.
7. A check name containing a newline, markdown, or 500 characters ⇒ the title is filtered; the body never contains output text.

## Definition of done

- [ ] Cold row-driven watch with a bounded window; red files exactly one deduped bug with a fixed-template body; no revert; events emitted; migrations counted.

## Do NOT

- Do not revert, push or open a PR. Do not put forge-originated or output text in a bug body unfiltered. Do not file on a mid-rework red. Do not widen the notify-hint set. Do not poll from memory. Do not claim green on silence.

**Deviations from the spec text (measured against it):**

- (a) The spec's one title example, `Gate red after merge: <slug> PR #<n> (<check>)`, is the merge-watch title verbatim; the two other kinds get their own fixed templates (`Gate red: verify failed on <slug>` / `Gate red: verify exhausted on <slug>` — no PR, a verify red is not a merge; `Gate red: merge refused on <slug> PR #<n> (<check>)`), and an empty component slug is `the component`, never an empty title.
- (b) `ExpireStaleMergeWatches(now)` in the spec is `ExpireStaleMergeWatches(now, window)`: the window is the live setting and the store stays window-agnostic (the watcher resolves it per sweep).
- (c) `gate_filing`'s key: the spec says one row per (component root, subject, kind); the subject string already encodes root + kind (`<root>:verify`, `<root>:merge:<sha>`, `<root>:merge-refused:<pr>`), so the PK is `subject` alone with `kind` as a CHECKed column.
- (d) Settings: T0 item 12 said "if S44 has merged, else package constants" — S44 has, so the S44 declaration discipline applies: `gates.watchWindow` (default `2h`) and `gates.watchInterval` (default `30s`), string-typed duration text, area `gates`, ≥ 40-char descriptions (T2's rule); the watcher reads live per tick and falls back to the package defaults on an unreadable/non-positive value, logging and keeping the poll.
- (e) `Run` from `StartLoops` beside `triggers.Run` — implemented, with the deliberate extension that the watcher starts even when the daemon has no loop runner (the sweep's crash-window repair does not depend on one).
- (f) The record path makes no forge call (the merge event's `base_ref` stays NULL, T6), so the watch's `base_ref` is the component's declared default branch, else the fixed placeholder `unreported` — absence named, never a guessed branch.
- (g) The engine emits the blocked reason as a `*loop.BlockedReason` pointer on the loop row; the reactor's door (`blockedReasonOf`) accepts the pointer (and a bare value) and refuses a string reason. T1's golden is untouched — its string-reason case still gets the refusal.
- (h) The spec's `ClaimGateFiling(subject, kind)` is implemented as-is; the store additionally refuses `SetGateFilingBug` for an unfilled claim and for an empty subject, so the ledger cannot be stamped ahead of a filing or off-key.
- (i) `ListMergeWatches`' loop filter is the full `Scope` (both halves, or refused) composed through `Scope.Where`, not a bare slug predicate — the I4 grep guard (`TestEveryScopedQueryComposesTheScopeHelper`) is the enforcer, and it caught the bare `e.loop_slug = ?` on the first full run.
- (j) S62's two vintage tests (`TestBackupRunMigrationFreshAndUpgraded`, `TestOpenMigratesAnOldStoreOnlyAfterACopy`) built their "previous vintage" as `all[:len(all)-1]` — "everything but the last" — which was only true while `backup_run` was the last migration file.
