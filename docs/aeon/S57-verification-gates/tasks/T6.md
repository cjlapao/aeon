# T6 · Engine integration: `verify.run`, routing, the refactored gate, `merge_event`, `forge.postReview` retired

**Prefix:** VG · **Shape:** P2 (Phase B) · **Rules:** VG2, VG7, VG9, VG11, VG14 · **Depends on:** T4, T5. The only task that changes the loop engine.

## Goal

A blueprint can say `kind: code-action, action: verify.run` and the engine runs the component's gates, records the evidence, routes pass/fail/unverified, and
`forge.merge` evaluates the merge rule (baseline = today) and records a `merge_event`. `forge.postReview` is made unreachable from blueprints with a sentence.
The T1 goldens are the contract: everything not listed in Notes is byte-identical.

## Behaviour (each a test; drive a real loop with the fake forge and the fixture blueprint)

1. All required gates pass ⇒ the loop advances; evidence under the step key has the five `verify_*` keys; a `verify_run` row exists with the head SHA.
2. A required gate exits 1 ⇒ the loop routes to `implement` with reason `verify: …`; after `max` rounds ⇒ `then: block` ⇒ blocked with exhaustion; the second round writes a **new** run (attempt 2).
3. A gate times out ⇒ `unverified` ⇒ routes back, **charging only the loop ceiling**, not `verify_rounds` (pins `DecideUnverified`).
4. No gates configured ⇒ `unverified: no-gates-configured` ⇒ the loop does **not** advance as pass.
5. Policy denies a command ⇒ nothing spawns, the verdict sentence is in the run's result reason.
6. `forge.merge` with no rule row behaves as the T1 goldens (every sentence, every evidence key); with a rule `require_local=1` and no run for the head SHA ⇒ refused with the VG11 sentence; with a run for an *older* SHA ⇒ refused naming both.
7. `review_mode=aeon` without the token ⇒ refused; with the token for the head SHA ⇒ allowed with `aeon_review` in evidence; the model cannot set the token (the arg is `evidence`-sourced; a handoff field of that name is ignored — test).
8. A successful merge ⇒ exactly one `merge_event`; a re-run of the same action after recovery ⇒ still one.
9. A blueprint naming `forge.postReview` ⇒ validation `unrunnable-action`.
