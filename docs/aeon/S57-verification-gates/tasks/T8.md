# T8 · The daemon surface: socket methods, desk validators, two proposal kinds (migration M4), the human-door guards

**Prefix:** VG · **Shape:** P4 + P6 (the proposal half) · **Rules:** VG17, VG18, VG23 · P34 · **Depends on:** T3, T5, T7; **S45 merged** (`internal/desk`, generic `proposal.commit`, guard pattern). Gates T9–T11.

## Goal

Everything an app, a CLI or an agent needs exists **first** on the daemon: reads, human-door writes, and the two proposal kinds an agent may use to ask for a *tightening*. The guard amendment makes the human-door absences provable, with canaries.

### Rulings and deviations

1. **SIZE1 — the guard file split.** The spec names one `verify_amend_test.go`; as written it would land ~1,150 lines. Split by cohesion into `verify_amend_test.go` (758 — the surface/narrow/agent/tool/records absences and their canaries) + `verify_amend_propose_test.go` (449 — the proposal kinds and their inertness), same package, helpers shared in the first file. Both under the line, measured.
2. **`ChecksPolicy` tightening direction is counter-intuitive and was verified against the store's own table**: `required_only → reported_green` is the TIGHTENING (a rule that requires the named checks to pass accepts strictly fewer PRs than one that accepts any reported green). `Tightens` (and the loosener table in the propose guard) encode that; the pre-flight caught the inversion.
3. **The guard's text-grep floor is 40, not the spec's 50**: the walk (skipping `.tmp` — a gitignored build area that must never be counted as a surface) sees **45 files** under the four forbidden trees on this tree; a floor of 50 would be a vacuous-passing floor, and the spec's own intent (the walk is not vacuous) is met by the lower measured bound. Canary teeth proven in `TestGateGuardsHaveTeeth`.
4. **The daemon strips the `refused: ` prefix** when it carries a store refusal to the wire (`gateDetail`): the wire's `Detail`/`Data.What` is the sentence without the CLI's prefix; the sentence's substance (the thing refused, the alternative) is intact and asserted in `TestRefusalsAreTypedWithAlternatives`.
5. **No-op writes succeed quietly**: an archive of an archived gate, a restore of a live one, a DoD mark to the state it already is — the store's honest double-state, returned as success with nothing written (the audit must not say a change happened when none did).
6. **`verify.add` stamps `origin='user'`** (the spec's `origin` for the socket door; the desk applier's committed add carries the committer as actor, origin the same — a proposal never carries an origin of its own).
7. **`EffectiveMergeRule` answers `baseline` when the node and its root have no row** (source `baseline`, the rule in code, never in rows) — the preview and the gate therefore always evaluate a complete rule.
8. **`MergeRuleRefusalAlreadyApplied` = a re-set of the standing rule is a quiet no-op** — and `Tightens` is symmetric in its use at proposal create: the classification table is direction-complete (every field, both directions), which is what makes the reflect over it in `TestProposalKindsAreRestrictiveOnly` total.
9. **The requirement vocabulary is `required | advisory`** (`protocol/verify.go` — the list view's field; the spec prose's "reported" does not exist in the wire).
10. **A PR-named preview is untestable end-to-end in daemon tests**: `forgeClientForRoot` hardcodes `forge.DefaultBaseURL` (`https://api.github.com`) and the forge seam has no loopback base-URL option; tests never point at a real forge (§5). `TestMergeRulePreviewMatchesTheGate` therefore pins the HONEST three-state arms (no PR ⇒ cannot-say naming the PR; PR + no forge identity ⇒ cannot-say naming the forge, and the gate's `mergeGateAnswer` answers the same state) plus a structural one-evaluator pin: exactly one `mergerule.Evaluate(` call in each of `mergerule_service.go` and `verify_wiring.go` (a second call in either file is a second truth).
11. **A gate root must be a git repository with ≥ 1 commit** — `LocalHEAD` fails otherwise and the try refuses with the infra error. The test harness makes real repos (`gateGitRoot`).
12. **`XDG_STATE_HOME` at a throwaway dir** for every daemon/store invocation (tests never point at the real store). Under the 8-core sibling load, the full daemon suite intermittently hits `database is locked` — proven environmental (the isolated runs are green, and pristine main times out the full suite the same way, T7's finding); the eight tests here run isolated.
13. **The service stubs in the guard's boundary test are registration markers** (`var _ = ...`-shaped, one per boundary method) — the test walks the call sites, the stubs keep the method list from drifting from the walk.
