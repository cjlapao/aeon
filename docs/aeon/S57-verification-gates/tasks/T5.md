**Deviations from the spec, and why:**

- **`merge_event.pr` is `INTEGER NOT NULL`** (spec: `pr INTEGER`). A merge without a PR is not a fact this
  store records; the door refuses `PR == 0` before any SQL.
- **Brief ids are per-VERSION** (`internal/store/briefs.go` mints a fresh id per version). So
  `UNIQUE(brief_id, idx)` is per-version by construction: a new brief version is NEW rows at the same idx,
  never an in-place edit. `MaterializeDoD` queries the previous version's row per idx
  (`ORDER BY brief_version DESC, id DESC WHERE brief_id <> ?`) and carries `met` + evidence + marker over
  ONLY for the byte-equal text; changed text is a fresh unchecked row told by a `reset` event; the store
  never deletes a version's rows (history).
- **D23 / I4: `MaterializeDoD(sc Scope, b DoDBrief)`** takes the loop's `Scope{ComponentRoot, LoopSlug}`
  and the explicit item texts — no brief lookup, no loop-row read. `dod_item` carries both scope columns
  and `idx_dod_item_scope` on (component_root, loop_slug).
- **D21 doors:** `SetMergeRule` / `ClearMergeRule` take a human actor (user|cli) and refuse everything
  else before SQL (T3's sentences + "(S57 T5)"). `MaterializeDoD` takes NO actor — it is the engine's
  daemon-side write at loop start (T6 wires it); a person never materialises a DoD. `MarkDoD` takes
  user|trigger and returns a **`DodWrite` discriminated result** (`{Item, Refusal, Reason}`, `OK()`) —
  T3's shape, never a refusal-wrapped error (DB19). A `met` must name its evidence: `verify_run` paired
  with trigger, `manual` paired with user; a non-met mark clears the evidence.
- **Nil lists normalise to the empty list at the door.** `Baseline().RequiredChecks` is nil (Go's "none"),
  which encodes as JSON `null`; a null-rejecting door would make the baseline rule itself unsettable.
  `jsonStringList` accepts `null` → `[]string{}`; a bare string or object is still refused
  (`required_checks is not a JSON list of check names`).
- **`Rule.UpdatedAt` is an identity field** (the storage stamp): the evaluator never reads it,
  `IsBaseline` ignores it, and `Tightens` classifies it `identity` (the field-complete test pins the
  classifier set).
- **`EffectiveMergeRule(componentID) (Rule, error)`** folds the spec's `(rule, source, revision)` into the
  row: `Rule.Source` is `own|root|baseline` and `Rule.Revision` the row's (0 for the baseline). A child's
  own row REPLACES the root's whole row; the root's row is returned with `ComponentID` rewritten to the
  child and `Source="root"`; an archived node supplies nothing and takes nothing; unknown → `ErrNotFound`.
- **`RecordMergeEvent(rec)` takes no actor** (VG14: the engine's seam is the only writer) and is idempotent
  on `UNIQUE(component_root, pr, merge_sha)` — the re-entry returns the standing row (a nil-id re-entry),
  a re-merge after a force-push (new sha) is a new row.
- **One-way import, pinned twice:** `internal/store` may import `internal/mergerule` (added to
  `store_test.go`'s import-scan allow-list with a dated comment); `internal/mergerule` may import neither
  the store nor any I/O (`pure_test.go`'s parse scan bans `store`, `net`, `os`, `database/sql`, `time`,
  `context`).
