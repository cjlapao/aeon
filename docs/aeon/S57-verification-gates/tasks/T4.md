# T4 · The gate runner and the scrubbed environment

**Prefix:** VG · **Rules:** VG4, VG5, VG6 (the capture half), VG2 (the action's arguments) · **Depends on:** T1. Parallel-safe with T2, T3.

## Goal

`internal/verify` runs **one gate** under the same policy gate and limits as the `bash` tool, in a **scrubbed environment**, and aggregates a run's
results by the VG4 rules. Nothing spawns without a policy-issued allow token; nothing that did not complete reads as pass; no daemon secret reaches a
gate. This task writes no engine wiring (T6) and no records (T3 supplies them — the runner takes them through small seams).

## Files

- `aeon/internal/tools/spawn.go` — **additive**: `SpawnOptions.Env []string`. `nil` ⇒ `cmd.Env = nil` **exactly as today** (T1's `TestBashInheritsTheDaemonEnvironment`
  stays green, the comment at `:141-153` is amended with one sentence pointing at `GateEnv`); non-nil ⇒ the child's complete environment.
- `aeon/internal/tools/gateenv.go` — **new**: `GateEnv(parent []string) []string`, an **allowlist**: `PATH, HOME, USER, LOGNAME, SHELL, LANG, LC_*, TERM, TMPDIR, TZ`, a closed set of
  toolchain locations (`GOPATH, GOCACHE, GOMODCACHE, GOFLAGS, CARGO_HOME, RUSTUP_HOME, NPM_CONFIG_CACHE, PNPM_HOME, VIRTUAL_ENV`), and the constant `CI=1`. `GateEnvNames()` returns the
  allowlist (the daemon's `verify.vocabulary` reads it — no client types it). **Dropping is by omission** — a name not on the list is gone, including `AEON_*`, `GITHUB_TOKEN`,
  `GH_TOKEN`, any provider key and any `*TOKEN*|*KEY*|*SECRET*|*PASSWORD*`; there is no denylist to forget a name from.
- `aeon/internal/verify/runner.go` — **new** (package `verify`, imports `tools` and `policy`; **no `store` import**, no SQL — the onion rule):
  - Seams: `Verdict func(agent, command string) (policy.Verdict, bool)` (the daemon passes a closure over `CommandVerdictFor`; **T0 item 6** says what a code-action must supply for the
    frozen manifest — if an additive seam is needed it is the smallest one and is built here), `Now func() time.Time`, `Spawn` defaulting to `tools.Spawn`.
  - `type GateSpec struct { ID, Name, Command, Requirement string; TimeoutS int; MemoryMB *int }`, `type GateResult struct { … per VG6 … State, Reason string }`.
  - `RunGate(ctx, dir, agent string, g GateSpec) GateResult` — policy first (`deny`/no verdict ⇒ `unverified`, `reason="policy"`, the verdict sentence verbatim, **no spawn**); then
    `tools.Spawn(ctx, g.Command, SpawnOptions{Dir: dir, Timeout: min(g.TimeoutS, BashTimeout), Env: GateEnv(os.Environ())}, token)`; mapping per VG4 item 4: exit 0 ⇒ pass; non-zero ⇒ fail;
    `TimedOut`, killed (the exact heuristic `tools/bash.go` uses for OOM: exit 137 / SIGKILL — **reuse its helper**, do not copy), start error, ctx cancelled ⇒ `unverified` with
    a reason from a closed set `{policy, timeout, killed, start-failed, cancelled, no-gates-configured}`; sha256 of each stream (of the **captured, truncated** bytes) and the
    **true** byte counts; tails (≤ 2 KiB each) kept only for non-pass and passed through `Redact`.
  - `Run(ctx, in RunInput) RunResult` — takes the effective gates (a slice supplied by the caller), runs them **sequentially in `position` order without short-circuit** (OD2), aggregates
    (any required fail ⇒ fail; else any required unverified ⇒ unverified; else pass; advisory results recorded with `AdvisoryFail` and never change the state; **empty or all-disabled
    required set ⇒ `unverified`, reason `no-gates-configured`**), computes `digest` = sha256 of the canonical JSON of the ordered results, and a `summary` from a fixed template
    (`3 gates: 2 pass, 1 fail (required), 0 unverified`). A total deadline `in.Deadline` (T0 item 5) caps the sum: the remaining gates after it are `unverified: timeout`.
  - `Redact(s string) string` in `redact.go` (T0 item 7: reuse if one exists): best-effort for token shapes (`ghp_…`, `github_pat_…`, `sk-…`, `AKIA…`, `xox[baprs]-…`, `Bearer …`, 32+ hex/base64 runs after
    `key|token|secret|password=`); the doc comment says in the first sentence that it is **best-effort and not a guarantee**.
- `aeon/internal/verify/vocab.go`: the closed vocabularies (`States`, `Reasons`, `Requirements`) as the single source the daemon's `verify.vocabulary` reads.

## Behaviour (each a test)

1. A gate with an allow token runs in `dir` with exactly the scrubbed environment; `printenv` output contains only allowlisted names.
2. A gate with no verdict, a deny, or an `ask` (unattended ⇒ deny) **never calls Spawn** (a spawn spy with zero calls) and records the sentence verbatim.
3. Exit 0 ⇒ pass; exit 3 ⇒ fail with `exit_code=3`; `sleep` beyond `timeout_s` ⇒ `unverified: timeout` and the **process group is gone** (no orphan, as `tools/spawn.go` does); a `kill -9` ⇒ `unverified: killed`.
4. Cancelling `ctx` mid-run ⇒ `unverified: cancelled` and the group is terminated; remaining gates are not started.
5. No required gates ⇒ `unverified: no-gates-configured`; advisory-only set ⇒ also `no-gates-configured` (a run that proves nothing required is not a pass).
6. Two required gates, first fails, second passes ⇒ both ran, run `fail`. A required `unverified` and an advisory `fail` ⇒ run `unverified`.
7. Output beyond the 64 KiB caps ⇒ true counts reported, `truncated=true`, digest over the captured bytes; a pass stores **no tails**; a fail stores ≤ 2 KiB redacted tails.
8. Determinism: the same inputs produce the same `digest` (timestamps and wall times excluded from the digest — only exit, state, counts, stream digests).

## Commands

P10; `go test ./internal/tools/ ./internal/verify/ -run 'GateEnv|Verify|Runner|Redact|Inherits' -count=1 -race -v`.

## Definition of done

- [ ] Allowlist env with two canaries; policy first, no spawn without a token; every non-completion is `unverified`; empty is never pass; no short-circuit; tails only for non-pass, redacted.
- [ ] `bash`/terminal environments byte-identical (T1 golden green); the runner imports no store and spawns only through `tools.Spawn`.

## Do NOT

- Do not change `bash`'s or the terminal's environment. Do not add a denylist. Do not invent a pseudo-agent identity (OD3). Do not store a tail for a pass.
- Do not claim redaction is complete. Do not read a credential file; do not pass any secret through a gate (S59 EV owns app secrets).
