# T1 · Characterization goldens: the gate, GitHub, the engine's action path, the bash environment, triage filing

**Prefix:** VG · **Shape:** P2 (Phase A only) · **Rules:** VG5, VG7, VG11, VG16 · **Depends on:** T0.

## Goal

Pin today's behaviour **on the untouched code**, so T2, T4, T6 and T7 can each prove what they changed and what they did not. Every golden is
green before any production edit and names the later task expected to change it and how.

## Files to create (tests and testdata only)

- `aeon/internal/action/gate_golden_test.go` + `testdata/gate_golden/*.json` — `mergeGate` driven through `ForgeActions.MergePR` with `forge.Fake`,
  one case per branch, each pinned as (refusal sentence **verbatim**, evidence map, forge call log):
  no reviews; latest `comment`; latest `request_changes`; outstanding `request_changes` cleared by the **same** author vs. answered by **another**;
  approve with no `StatusLister` (`checks = "not-configured (N/A — the server reports no status API; …)"`); approve with the `gateForge` double
  implementing statuses: all success / one failure / one pending / `not-found` (N/A) / transport (refuse); `ThreadLister`: none / some /
  not-found / unsupported; reviews unreadable; already-merged PR (succeeds, recorded SHA); base-ref guard refusal; phantom-merge guard. Header comment
  per file: "T2 changes `checks` only on GitHub; T6 refactors the evaluation and must leave every sentence byte-identical".
- `aeon/internal/forge/github_golden_test.go` — against an `httptest` server: the exact request method, path, headers (no token value asserted —
  assert only that an `Authorization` header is present and **never logged**), and body for `OpenPR`, `ReadPR`, `ListReviews`, `PostReview`,
  `MergePR`, plus the response→type mapping, including that `Review.SubmittedAt` is `""` today and `PR` has no head SHA. Error classification table
  (401/403/404/409/5xx/rate-limit) pinned.
- `aeon/internal/loop/action_path_golden_test.go` — the engine's **code-action path** driven with a fake action service: success advances; an error
  blocks with `action-failed`; `deny` blocks with `action-denied` and the verdict sentence; a code-action step with `on_reject` (record what the
  validator and engine do today — T0 item 1 answers); `actionArgs` output for a representative step (`Dir`, `Task`, `Base`, `PRSummary`, no
  `StepID`/`Attempt`); evidence stored under the step key; the `loop.action.executed` payload.
- `aeon/internal/tools/env_golden_test.go` — the `bash` tool's child **inherits** the daemon environment today: plant a variable, run `printenv`
  through `Spawn` with an allow token, assert it is visible. This pins the behaviour VG5 must **not** change for `bash`/terminals (the scrub is
  opt-in by `SpawnOptions.Env`); header: "T4 adds `Env`; `nil` must stay byte-identical to this".
- `aeon/internal/daemon/gate_reactor_golden_test.go` — `publishLoop` on `loop.finished`/`loop.blocked`: which reactors fire and with which
  arguments (queue, roadmap, triage), pinned by a call recorder; no reactor files a bug for a `blocked` loop today.
- `aeon/internal/triage/file_golden_test.go` — `File` with a `FiledBy` of an agent name: stored defaults (`unvalidated`, `unknown`), dedupe behaviour
  for an identical and a near-identical title (T0 item 8 names the rule), rejection of an empty `FiledBy`.
- `aeon/internal/loop/review_evidence_golden_test.go` — where a finished `review` rung's `ok` outcome lives in `LoopState` (T0 item 10) so T6's
  `ok@<sha>` token has a pinned source.

## Rules for the goldens

Deterministic (fixed clock seam, fixed ids, sorted maps); no network (`httptest` only); **no real token anywhere** — the token source is a fake
returning a constant that the test asserts is never written to a log or an error string (a canary test for the C17 rule on this surface).

**Pre-flight finding — the §Commands line as written is missing the tag (measured, documented):**

The command above is the spec's line **plus `-tags sqlite_fts5`**, which the spec's line omits. Without it, `mattn/go-sqlite3` compiles without FTS5 and **every store-opening test fails at migration `0040_retrieval_index` with `no such module: fts5`** — verified by running the spec's line verbatim: it fails `loop`, `daemon` and `triage` (including pre-existing goldens, so this is not a T1 artefact), while the no-store packages pass. The P10 block and the Makefile (`GO_TAGS := sqlite_fts5`, "not optional from S22 on") both mandate the tag; all runs in this task (and the T0 baseline) therefore carry it. Read the spec's command as "P10 block" + the command + the tag.
