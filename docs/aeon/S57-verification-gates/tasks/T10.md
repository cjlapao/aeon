# T10 · The CLI client and the `verify.templates` seed set

**Prefix:** VG · **Shape:** P5 (+ P8 for the seed set) · **Rules:** VG20, VG21 · standing rule 1 · **Depends on:** T8; the seed set needs S43-extra T3. Parallel-safe with T9, T11.

## Goal

`aeon verify …`, `aeon merge-rule …`, `aeon dod …`, `aeon merge events` exist as **clients of the socket methods**, with the offline fallback for the pure record verbs; and the inert `verify.templates` seed set ships the per-stack gate templates a person applies to a component.

## Files — the CLI

- `aeon/cmd/aeon/verify_verbs.go`, `mergerule_verbs.go`, `dod_verbs.go`, `merge_verbs.go` — **new**; `main.go` dispatches `verify`, `merge-rule`, `dod`, `merge` and gains usage text.
  - `aeon verify list [--component C] [--effective] [--archived] [--json]`, `show ID`, `add --component C --name N --command CMD --requirement required|advisory [--timeout S] [--memory MB] [--yes]`, `update ID …`, `archive ID --yes`, `restore ID`,
    `apply-template --component C --template T [--names a,b]`, `try ID` (**daemon required**), `runs [--component C] [--loop L] [--state S] [--limit N]`, `run-show ID` (tails behind `--show-output`, with the "may contain secrets" line), `vocabulary`, `templates`.
  - `aeon merge-rule get --component C [--effective]`, `set --component C [--require-local] [--require-dod all_met|none] [--required-check NAME …] [--checks-policy …] [--no-checks …] [--review-mode …] [--threads-resolved] [--method …] --yes`
    (**`--yes` is required when the change loosens the effective rule** — the CLI asks the daemon's `mergerule.preview`-shaped diff, prints the daemon's own statement, and sends `mergerule.set` only with `--yes`; a seatbelt, not a control, P5), `clear --component C --yes`,
    `preview --component C [--pr N]`, `changes [--component C] [--limit N]`, `vocabulary`.
  - `aeon dod list --loop L`, `aeon dod mark ITEM --state met|unmet|unverifiable [--evidence-run ID | --manual --note TEXT]`.
  - `aeon merge events [--component C] [--loop L] [--limit N]`, `aeon merge watches [--state S]`.
  - Help text for every closed set is **generated from the vocabulary reads** (live from `*.vocabulary`; offline from the same Go constants) — no set typed twice.
- `aeon/cmd/aeon/gate_client.go` — **new**: `gateDoor` interface; `socketDoor` (default: dial, call, print the wire verbatim, refusals verbatim) and `directDoor` (the **same** `internal/verify`/`internal/mergerule`/store write services over a directly opened store, actor `{cli,cli}`); `selectDoor()` per P5 —
  "no daemon" ⇒ `directDoor` + the fixed stderr line `daemon not running — applied directly to the store`; any other dial failure refuses. `directDoor` has **no copy of logic** (a `go/parser` test) and `internal/store` is imported only there. **`try` has no direct door** (it spawns a process under the daemon's policy gate): offline it refuses with
  `verify try needs the daemon: it runs under the daemon's policy gate — start it with aeon serve`.
- The CLI re-validates **nothing**: flag parsing refuses only what cannot be a value (`--timeout` non-integer); every other refusal is the daemon's sentence verbatim; `--json` is the wire result verbatim. No flag, stdin or prompt accepts a secret (C17) — `add --command` is a command text, and the CLI prints the daemon's "gate commands run with a scrubbed environment; do not embed a credential" note when the command matches a token shape (daemon-side warning, shown verbatim).

## Files — the seed set (P8)

- `aeon/internal/verify/seed/seed.go` and `aeon/internal/seed/decl_verify.go` — `Source() []seed.Record` for set **`verify.templates`**, class **inert** (applies at daemon start and `aeon init`; changes nothing about what is permitted — a template is data a person copies), `origin='system'`, an `Applier` (`Upsert/Fingerprint/Retire/GuardAffecting/Operator`) writing through the **store's one `verify_template` write path** (T3). Operator rights `{Edit:false, Remove:true}` (a person may remove a template; never edit a system row — they copy and edit the copy).
- Content (final commands pinned and verified in this task against the real handler bodies — `golang-engineer.md:23-28`, `verifier-engineer.md:20-31`, the javascript/react/vue/python/rust/terraform bodies; **extracted, not invented**, each with its `timeout N` wrapper where the body uses one; every template is tested to pass the **corpus policy** for `verifier-engineer` with no policy edit, or the test lists which would be denied and the seed omits them):
  go: `go build ./...` (required, 600 s), `go vet ./...` (required), `go test ./... -count=1 -timeout 300s` (required), `golangci-lint run` (advisory); node: `npm run build` (required), `npm test -- --run` (required), `npm run lint` (advisory) — a template cannot know which scripts a repository defines, so `verify.applyTemplate` lists the names it copied and the person prunes; python: `python -m pytest -q`, `ruff check .` (advisory); rust: `cargo build`, `cargo test`, `cargo clippy` (advisory); terraform: `terraform validate` (required), `terraform plan` is **omitted** (needs credentials — S59 EV).
- A golden pins each record's content and `Version` ("content changed but version did not — bump it"), as every seed set does.
- Tests: provenance, idempotence, divergence never overwritten, removal never resurrected, explicit `restore`, startup never reaches a guard set (this one is not a guard set), the engine's `seed.status` lists it.
- **Not seeded (stated, tested):** `merge_rule` rows and `verify_command` rows — `TestNoMergeRuleIsSeeded` / `TestNoVerifyCommandIsSeeded` assert the engine's sets contain neither; the exemption reason is a comment citing VG21 (authority/execution-shaping records, like triggers — S40 AU1 lock 3).

- Do not seed a `merge_rule` or `verify_command`. Do not edit a seeded template in place — bump its `Version`.
