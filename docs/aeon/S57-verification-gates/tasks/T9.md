# T9 · Agent tools: nine catalog specs

**Prefix:** VG · **Shape:** P6 · **Rules:** VG13, VG17, VG19 · standing rule 2 · S38 OL2/OL3/OL10 · **Depends on:** T8. Parallel-safe with T10, T11.

## Goal

Agents can **see** what gates a component declares, what ran, what the merge rule is and what it would say now, and the definition-of-done state — and can **propose** a stricter gate or rule or mark an acceptance item with evidence. They
can never add, update, archive, try, set, clear, commit or loosen. One definition, two doors: each spec has a socket twin, a parity test walks both directions, and the new tool names are **granted to no one by default**.

## The nine specs (`internal/records/catalog.go`, data only, families `verify`, `mergerule`, `dod`)

| Tool | Socket twin | Class | Mutates | What it does |
| --- | --- | --- | --- | --- |
| `verify_list` | `verify.list` | safe | no | Gates in force for a component (own or inherited, with source), requirement, timeout, last run state |
| `verify_show` | `verify.show` | safe | no | One gate in full incl. the policy preview sentence |
| `verify_runs` | `verify.runs` | safe | no | Verify runs, **scoped to the caller's own loop and component** (no cross-component reads); digests and states, never tails |
| `mergerule_show` | `mergerule.get` | safe | no | The effective merge rule with source/revision and the autonomy-floor checklist |
| `mergerule_preview` | `mergerule.preview` | safe | no | What the merge gate would say for a PR right now — every refusal sentence |
| `dod_list` | `dod.list` | safe | no | The definition-of-done items of the caller's loop with state and evidence |
| `verify_propose_add` | `verify.proposeAdd` (new) | detectable | **yes** | Create an **inert** proposal to add a gate; nothing runs until a person commits |
| `mergerule_propose_tighten` | `mergerule.proposeTighten` (new) | detectable | **yes** | Create an inert proposal to **tighten** the merge rule; a loosening is refused at create |
| `dod_mark` | `dod.markAsAgent` (new) | detectable | **yes** | Mark an acceptance item: `unmet`/`unverifiable` freely; `met` only with a passing verify run of the same loop on the current head SHA |

## Schemas — what is deliberately absent (OL3's strict-schema rule)

Every schema is `"additionalProperties": false`. **No** `source`, `actor`, `createdBy`, `status`, `kind`, `origin`, `componentId` for the propose/mark specs — the daemon stamps the agent identity and resolves the component from the **caller's own loop** (an agent proposes
for the component it is working in; a cross-component proposal is a person's act). `verify_propose_add` input `{name, command, requirement, timeoutS, reason}` (`reason` required 1–512 bytes; `requirement` an enum of two; `timeoutS` 1–600). `mergerule_propose_tighten`
input `{fields: {…only the Rule columns…}, reason}` — each field's schema admits only its **tightening direction's** values where the domain has an enum with a clear direction (`no_checks: ["refuse"]`, `require_dod: ["all_met"]`, `review_mode: ["both"]`; `required_checks`
additive list) and the service re-checks with `Tightens` (the second line of defence — the same pattern as S45's `allow` unrepresentable). `dod_mark` input `{itemId, state, evidenceRunId?, note?}`.

## Behaviour (each a test)

1. **Forced identity.** The proposal's `created_by` is the agent actor the records service stamps; params naming one ⇒ parse error.
2. **Inert.** `verify.list`, `mergerule.get`, `mergerule.preview` are byte-identical before and after a propose; the `verify_command`/`merge_rule` tables are untouched.
3. **Validator parity.** A payload `verify.add` refuses is refused by the tool with the same reason (one `desk.Validate`); a loosening payload is refused with the field named, even if the schema were bypassed (direct service call).
4. **`dod_mark met`** with no `evidenceRunId`, a run of another loop, a run not `pass`, a run for an older SHA, or an item of another loop ⇒ refused with the sentence naming what is missing; `unmet`/`unverifiable` always allowed; every mark writes a `dod_event` with the agent actor.
5. **Scoping.** `verify_runs`/`dod_list`/`mergerule_preview` refuse a component or loop that is not the caller's, naming the caller's own; person sessions get the unscoped socket reads (T8), not these tools.
6. **Rate and size.** At most S45's per-agent open-proposal limit (a named constant imported, not copied); each payload ≤ 8 KiB.
7. **Granted to no one by default.** `tools.DefaultGrant()` unchanged; a handler that wants them lists them; the policy `tool_access` rows still decide per call. Each spec's doc comment says so.
8. **Counted registry bump.** `TestRegistryExactNames`'s want lists and count comment gain the nine names deliberately (`Count N → N+9 DELIBERATE (S57 VG19, <date>)`, N from T0's real count); `testdata/rerun_classes.json` gains them (the three mutating ones `RerunUnsafe`-classed as their siblings are — T0 reads the file's rules).
9. **No decision tool exists.** The catalog contains no spec twinned to `verify.add/update/archive/restore/applyTemplate/try`, `mergerule.set/clear`, `dod.mark`, `proposal.commit/reject` (T8's guard asserts it; T9 adds the positive list of the nine).
10. **Descriptions** ≥ 40 characters and distinguish siblings (the catalog test enforces).

**Where the spec's words meet the implementation:**

- **Rate and size (behaviour 6)** is inherited, not re-implemented: the gate arms call the
  shared `createInertProposal`/`openProposalsCap` (records_policy.go, S56) — the named
  constant `desk.MaxOpenProposalsPerAgent` is imported, never copied, and the payload
  ceiling is `maxProposePayloadBytes` (8 KiB). `TestProposeLimitPerAgent` pins the cap
  refusal at the autonomy arm; the gate arms share the same code path.
- **Validator parity (behaviour 3):** the shared proposal validator (wired in daemon.go
  next to the gate seam fields) re-runs `desk.ValidateVerifyCommand`/`ValidateMergeRule`
  plus the store's half (component exists / not archived / name free; the merge-rule
  closed sets and `mergerule.Tightens` against the component's **effective** rule), with
  sentences byte-identical to the human door's — `TestProposalKindsAreRestrictiveOnly`
  and `TestProposeKindsAreInertUntilCommitted` (cmd/aeon) pin both.
- **Tightening:** the schema admits only the tightening value where the domain has a
  direction (`require_dod ["all_met"]`, `checks_policy ["reported_green"]`, `no_checks
  ["refuse"]`, `review_mode ["both"]`, `required_checks` additive) — the loosening value
  is not a representable input; the service re-checks with `Tightens` as the second
  defence (`TestGateProposeTightenRefusesLooseningEvenIfSchemaBypassed`), and the
  forge↔aeon review switch is the one incomparable pair — refused as a switch in BOTH
  directions, which the test exercises both ways (both→forge is a plain loosening, not a
  switch: `both` is strictest).
- **`dod_mark met`** requires a `pass` run of the caller's own loop on the current head
  SHA; `unmet`/`unverifiable` are free with a note; a non-met carrying a run id is
  refused ("only a met carries"); a foreign item names the caller's loop; an identical
  re-mark is a quiet no-op (the store's honest state). Manual evidence is never accepted
  from an agent — the store's pairing rule (verify_run ⇒ trigger|agent, manual ⇒ user
  only) is the last line.
- **Scoping (VG19):** the scope is injected from the step's identity
  (`ident.ComponentID`/`ident.LoopSlug`), never a param — a smuggled scope field is a
  parse refusal (`additionalProperties: false`), and a foreign loop/component in a
  read's answer is a refusal naming the caller's own.
- **V13:** a store-less mount keeps the gate seam fields nil (the wiring sits inside the
  non-nil-store guard), and each arm says "needs the X gate service" rather than
  answering zero — `TestGateArmsUnwiredAreStated`.
- **Inert (behaviour 2):** `TestGateProposeIsInert` takes a byte-identical six-read
  surface (verify list/show/runs, mergerule get/preview, dod list) plus the raw
  store rows before and after both proposes; exactly two `proposed` rows land, one per
  kind.
