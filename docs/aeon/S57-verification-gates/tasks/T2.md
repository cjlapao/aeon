# T2 · Forge checks: `ReadChecks`, `ListStatuses`, `PR.HeadSHA`, `Review.SubmittedAt`, the Fake

**Prefix:** VG · **Rules:** VG8, VG9 (the forge half) · **Depends on:** T1. Parallel-safe with T3, T4.

## Goal

CI status becomes real. The existing optional `StatusLister` is implemented on `GitHub` and `Fake` so `mergeGate` (unchanged) starts refusing red
CI; a new optional `CheckReader` reads checks by **commit SHA** (a PR head now, the base branch after merge); review timestamps stop being
`(unset)`. Honest `unknown` everywhere the forge cannot say.

## Files

- `aeon/internal/forge/forge.go` — additive only:
  - `PR` gains `HeadSHA string`.
  - `type ChecksReport struct { SHA string; Checks []Check; State string; Complete bool; Source string; Reason string }`, `State` ∈ `success|failure|pending|unknown`
    (consts `CheckSuccess…CheckUnknown`; `Check.State` uses the same four — the existing prose in the `Check` comment ("success", "failure", "pending")
    stays true).
  - `type CheckReader interface { ReadChecks(ctx context.Context, sha string) (ChecksReport, error) }` — optional, asserted, like `StatusLister`.
  - A pure `Aggregate(checks []Check, complete bool) (state, reason string)` so GitHub and Fake share the rule (any failure ⇒ failure; else any pending ⇒
    pending; else incomplete or any unknown ⇒ unknown; else success; zero checks ⇒ `unknown`, reason `none-reported`).
- `aeon/internal/forge/github.go`:
  - `ReadPR` maps `head.sha` into `HeadSHA`; `ListReviews` maps `submitted_at` into `Review.SubmittedAt` (absent stays `""`).
  - `ReadChecks(ctx, sha)`: `GET /repos/{o}/{r}/commits/{sha}/check-runs?per_page=100` paginated by `Link` (≤ 10 pages ⇒ `Complete=false` beyond) and
    `GET /repos/{o}/{r}/commits/{sha}/status`; the mapping table of VG8 is one function `mapCheckRun(status, conclusion)` / `mapStatusState(state)` with
    an exhaustive test; an unknown API string maps to `unknown` (never `success`). Errors go through the existing `classify` (`github.go:199`): transport and
    auth are **returned**, never folded into "no checks" (O5); `404` on a SHA the forge does not know ⇒ `KindNotFound`.
  - `ListStatuses(ctx, pr)` = `ReadPR` → `ReadChecks(HeadSHA)` → `Checks` (so `mergeGate`'s existing `StatusLister` branch goes live). A PR whose head SHA is
    empty returns `KindNotFound`-shaped N/A so the gate records the absence as today.
  - Conditional requests are **not** used (no caching, N8); `MaxRetries` applies as for every call.
- `aeon/internal/forge/fake.go`: `SeedPR` accepts `HeadSHA`; `SeedChecks(sha string, checks []Check, complete bool)`; `ReadChecks`, `ListStatuses` implemented over the
  seeded data and logged in `Calls()`; `FailMethod("ReadChecks", …)` works like the others; compile-time `var _ CheckReader = (*Fake)(nil)` and
  `var _ StatusLister = (*Fake)(nil)`.
- `aeon/internal/action/forge_actions.go`: **no logic change**; the gate's `StatusLister` assertion now succeeds for `GitHub`. (T6 refactors the gate.)
- `docs/FORGE.md`: the scopes line gains "checks: read-only `checks:read`/`statuses` — no new write scope" (T0 confirms the exact GitHub permission names).

## Behaviour pinned by tests (names below)

- A PR head with all check-runs `success` + legacy status `success` ⇒ gate passes, `checks="name=success …"` evidence.
- A required-style red (`failure`/`timed_out`/`cancelled`) ⇒ the gate refuses with the **existing** sentence `PR #N check X is failure, not green`.
- `queued`/`in_progress` ⇒ `pending` ⇒ refuse (existing sentence says "not green").
- Zero check-runs and zero statuses ⇒ `Complete=true`, state `unknown`, `none-reported`; the *gate's* current behaviour for "no checks reported" (N/A passes)
  is **preserved** — only T5's rule can tighten it.
- 11+ pages ⇒ `Complete=false`; 403 rate-limit ⇒ retried then `transport`; 401 ⇒ `auth` ⇒ the gate refuses (transport/auth never read as N/A, `isNotApplicable`).
