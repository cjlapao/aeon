## Behaviour (P7, plus this domain's specifics)

1. **Gates tab.** One list: name, command (monospace, truncated with a reveal), requirement `Pill`, timeout, **"memory: declared, not enforced"** shown whenever a bound is set (the daemon's own flag — not a UI invention), source chip `own | inherited from <root name>` (daemon `source` + `suppliedBy`), enabled/archived, last run state `Pill` + `RelativeTime`, and the **policy preview** line ("would run as verifier-engineer now" / "currently denied by policy: <the daemon's sentence>"). Filters (`requirement`, `archived`) are **daemon-side params**. A child showing inherited gates has a **"copy from root"** action: the UI issues one `verify.add` per inherited gate (no new daemon method) and reports partial failure honestly, listing which gates were copied.
2. **Form** fields and their allowed values come from `verify.vocabulary` (requirements, timeout bounds, name grammar); no set, bound or sentence is typed in the UI. Refusals render **verbatim with the draft kept**; success updates the list **from the response**, never optimistically.
3. **Try.** `Try` calls `verify.try` only after `useConfirm` shows the **daemon's** statement (`ranIn` path unknown before the call, so the confirm text is the daemon's `tryStatement` field of `verify.vocabulary` (a sentence with the identity and the component's root path as fields the UI fills from data it already holds: "this runs the command now as the verifier identity in the component's root, with a scrubbed environment, under the policy gate")); declining sends **nothing**. The result shows state, exit, wall, true byte counts, and the tail behind an "**output may contain secrets**" disclosure (best-effort redaction stated).
4. **Template picker.** Lists `verify.templates` by stack with each command and requirement; applying shows the collision list from the daemon; all-or-nothing.
5. **Merge rule tab.** The **effective** rule with source (`own | root | baseline`) and revision; edit controls generated from `mergerule.vocabulary`; a **loosening** change shows the daemon's diff statement and requires `useConfirm`; a tightening saves without confirm but still shows the diff. A permanent **autonomy-floor checklist** (each missing ingredient with the daemon's sentence) answers "could an unattended merge ever arm here?".
6. **Preview.** `mergerule.preview` with an optional PR number: every refusal sentence **verbatim** in order, evidence keys, and "evaluated against head <sha>" — the same function the gate uses, so the screen cannot disagree with the merge.
7. **Runs tab.** List-with-details (loop link, state, reason, head SHA, summary, trigger, when); detail with per-gate results; **no tails** unless the person expands them; stale-SHA marker when the run's SHA is not the PR's current head (the daemon supplies `stale`).
8. **Offline:** writes and Try disabled with the reason; reads show last data from the response. **Two-window staleness:** a finding is recorded in T12 (a write in window A is not live in window B until refetch — the same finding S45 records).
9. `RpcClient`/`useRpcQuery` only; each action name is a literal checked by the guard test.
