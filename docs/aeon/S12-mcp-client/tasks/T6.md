# T6 — The public registry

## Why this exists

The tier that makes the adoption story work: **a company with only MCP servers writes agents with no tools
of their own, pointed at public ones, and has a working system.**

**Public tools are granted freely to any agent that declares them** (MC5), with no per-agent ceremony —
because **the effect class carries the risk.** A read-only docs server warrants no consent screen; an
`outward` or `irreversible` one **still asks at use time** (L22). Friction sits where the danger is rather
than on every declaration.

**And a deployment that disagrees needs no code change.** One `ToolAccess` deny for `all-agents` closes the
public door — which is MC4 paying off, because the grant was a policy so the revocation is a policy.

**Read first:** `registry.go` as T5 left it; MC5; L22 for effect classes and the use-time ask.

## Scope

**1. A public tool is usable by any agent that declares it.** Declaring is the agent naming it; there is no
grant step and no operator approval per agent.

**2. An `outward` or `irreversible` public tool still asks at use time.** The freedom in MC5 is about
*declaration*, not about *effects*. Assert this — it is the half of MC5 that makes the other half safe.

**3. The public door closes by policy.** An `all-agents` `ToolAccess` deny removes it for everyone, with
S10's sentence as the refusal. No code change, no config edit, no restart.

**4. Public is still namespaced** (MC8) — `context7.docs`, not `docs`.

**5. A public tool is not automatically declared.** An agent that does not name it does not have it. "Public"
means *available to declare*, not *granted to all* — otherwise MC5's freedom becomes every agent holding
every public tool, and the effect-class argument no longer covers it.

## Notes (built 2026-10-24)

**Where the policy consultation lives, and why here rather than in T7.** The checklist demands
"an all-agents deny closes the door, **with no code change**" — which cannot be tested against a call
path that does not consult policy yet. So `Registry.Call` grew the consultation in this task, and T7
becomes what its title says: the single-revocation assertion, the `at`-once-per-step rule, the
private-still-evaluated case, and the grep that this package holds no grant state. Reordering the two
would have meant writing the T6 test against a stub.

**The call order IS the semantics, and it is commented as such in `untrusted.go`:**
visibility → classification → policy → effect.

- **Visibility first**, before any policy is read: consulting the policy set for another agent's private
  tool would let **the policy set itself become the disclosure channel** T5 spent a task closing
  (`TestPolicyCannotConjureWhatConfigNeverDeclared` pins the byte-exact answer).
- **Policy third**: deny → S10's sentence, unprefixed and verbatim; `DefaultDeny` → the MC10 wording
  (an engine decision, not a rule that spoke); matched `ask` → S10's `asked:` sentence with
  `AskRequired`.
- **Effect last**: an **allowed** `outward`/`irreversible` tool **still asks at use** (L22/MC5).

**That last one is the half I want reviewed, because it reuses a name S10 already owns for a
different question.** `ToolAccess` answers *"may this agent use this server's tools at all"*. The
effect class answers *"does this use need a human"*. One policy type does not answer both, and a
grant named after the first must not silence the second. `CallOutcome` therefore carries
**`AskRequired`** — and it is deliberately **not** `IsError`: `asked` is S10's third decision, not a
failure (a caller that treats it as one will "handle" it by refusing, and the consent screen becomes a
silent deny). The registry **never blocks** waiting for a human: it reports that consent is owed and
returns, because the consent is an S11 gate + human event, and a library method that blocks on a
person is a deadlocked daemon.

**Two ways outward can fail open, both now refused by tests that count server invocations:**
a broad `allow` plus `outward` calling silently (the R4 failure, in the tool layer), and
*asking then calling anyway*. `TestOutwardPublicToolStillAsks` and
`TestMatchedAskRuleAsksWithS10Sentence` both assert the fake heard `0`.

**Deviations from the file's naming, so a grep for the checklist's names finds the right test:**
`TestTwoAgentsShareOnePublicTool` (file), `TestAllAgentsDenyClosesPublicDoor` (file),
`TestOutwardPublicToolStillAsks` (file), `TestReadonlyPublicToolDoesNotAsk` (file) — the intended
checklist names plus `Test…`; the semantics each asserts is what the checklist asks for.

**Policy helpers, and why they build `policy.Policy` directly.** `allowPolicy`, `denyAllAgents`,
`askRule` construct the struct with the same field set the store writes and the CLI reads, because
what the registry sees is that struct either way. The **CLI** write path is exercised in S10 and, for
MCP, at the CLI seam in T9/T10 — where a wrong flag shape becomes a finding rather than a passing
test that never touched a real row.
