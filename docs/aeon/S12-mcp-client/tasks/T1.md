## Notes (built 2026-10-24)

**Q3 — public config lives in its own section, and private nests under its agent.**
`Config` has exactly two places a server can be written:

```json
{ "public": [ {"name":"docsproxy", "transport":{…}, "tools":[…]} ],
  "agents": { "reddit-agent": {
                "private":  [ {"name":"fakeserver", …} ],
                "declares": ["docsproxy.docs"] } } }
```

**Why this shape makes a mis-tiered server hard to write:** the tier is the **position in the
file**, not a field. There is no `tier:` and no `private_to:` to set wrongly — a flat list with a
`private` boolean makes "forgot the boolean" mean public, which is the leak. Nesting makes
"forgot the nesting" a load error naming the server. `parseConfig` also **refuses unknown keys**,
so the field you remembered wrongly (`tier`, `visibility`, `private_to`) is an error rather than
an ignored key that silently means "public". MC12 falls out of the same shape: the same server
name in `public` and under an agent, or under two agents, is refused at load — a tier that
depends on who is asking has no auditable answer.

**`ToolsFor` is the only exported method returning `Tool` at all**, not merely the only one
returning a slice: `Availability` answers an enum + the missing class names, `Refused` answers
`Refusal` rows. The D3 grep pins `\[\]Tool | Tool | map[…]Tool` returns to the one name.
**Near-miss worth recording:** the first version of that grep had no `(?m)`, so `^func` matched
only the file's first line and the guard passed **by finding nothing** — the `seenFuncs == 0`
fatal is the thing that caught it. A grep guard without a "matched something" assertion is
decoration.

**Core classes are read from `internal/tools`, never re-declared.** `Tool.Rerun` for a core entry
is `tools.Registry()[name].RerunClass()`; a registry that re-declares classes is a second source
that disagrees with the first within a month. Core `Effect` is **empty**: `EffectClass` policy is
still S16's declared stub, so this registry refuses to invent classes for tools whose prose and
code it did not write. For **external** tools empty is a refusal (T3), which is the opposite
answer and deliberate — core effect enforcement belongs to S16's evaluator.

**`write_file` is filtered from every listing here too** (S11's rule for the hidden alias), and
granting it in `core:` is a load error naming it.

**Deviation, small and stated:** the task file expected three files; the config path resolution
belongs to `internal/paths` (the one path resolver — S4's redirect forbids a second), so this
task also adds `MCPConfigEnv`/`MCPConfigFile`/`MCPConfigFileFor` there with four tests. Windows
resolves to `%APPDATA%` (Roaming) while the **store** stays machine-local: a list of which
third-party servers exist is a preference, not machine state.

**Not built here, on purpose:** no transport call anywhere in this package yet (validation item —
`config.go` and `registry.go` import only `encoding/json`, `os`, `strings`, `regexp`, `sort`,
`fmt`, `io`, `bytes`, `net/url` and `internal/tools`). T2 brings the transport.

**25** top-level PASS in `internal/mcp` (13 config cases + 12 registry cases) and **8** in

# T1 — `registry.go`: the three tiers, and no list of everything

## Why this exists


**MC2 is a property of this file's shape, not of a check somewhere.**

> Private is invisible and uncallable to peers — not merely unauthorized.

The easy implementation is one list of every tool plus `if visible(agent, tool)`. **It works, and the first
caller that forgets the filter leaks every tool to every agent.** A filter is a thing somebody forgets to
apply; a list that never contained the tool is not.

So: `ToolsFor(agent)` is the only way to obtain tools, and **there is no function that returns all of
them.** Build it that way **before any transport exists** (T2), because a registry designed around a client
acquires the client's natural shape — and a client's natural shape is *"here are all the tools from all the
servers."*

**Read first:** the design's MC1, MC2 and MC12; S10's `ToolAccess` for what a grant is (T7 wires it; this
task may stub the grant source).

## Scope

**1. `ToolsFor(agent string) []Tool`** — core it was granted, public it declared, private configured for
it. **No other accessor returns tools.**

**2. No all-tools function.** Not `AllTools()`, not `Servers()[i].Tools()`, not an exported field. If a
diagnostic genuinely needs the whole picture (`aeon mcp list` with no `--agent`), it composes from the
configured set **and says it is a configuration view, not a capability view** — those are different
questions and conflating them is how the leak returns.

**3. `config.go` — and answer Q3.** Where does public configuration live relative to private? **Choose the
shape in which a mis-tiered server is hard to write.** A flat list with a `private_to:` field makes
"forgot the field" mean public; nesting private servers under their agent makes the mistake structurally
harder. State the choice and the reasoning.

**4. MC12: tier comes from configuration.** The same server cannot be private to one agent and public to
another. Otherwise *"who can see this"* depends on who is asking, which is not a property anybody can
audit.

**5. Namespacing by server** (MC8), established here so T2 has somewhere to put names.
