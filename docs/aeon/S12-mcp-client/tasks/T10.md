**§3** asserts a peer gets `unknown`, not `denied`. **If that passes immediately, check it is exercising

that to mean anything. If the step never listed the tool, nothing was labelled and nothing was proven.

## §3 — confirmed it exercises invisibility, not absence

The task warns the test and the mistake look identical from outside. Confirmation, three ways:
**(a)** the same qualified name **works for the owner** in the same config and the same store — §2
listed `fakeserver-private.post/search` for `reddit-agent` minutes before the peer's call returned
`unknown tool:` — so the tool was configured, dialled and callable; **(b)** the peer's refusal is
**byte-identical** to the refusal for `anything.tool`, a name that exists nowhere (the CLI prints the
same `unknown tool: <requested>`; `private_test.go` pins it byte-exact against the caller's own
requested name); **(c)** the peer's *listing* never names the private server at all, while the owner's
does. Existence for someone and nonexistence for the caller is exactly MC2's invisibility — the
`denied` branch would be the leak.

## §6 — confirmed the description reaches the surface, and where the walk cannot follow

The DEMO's `step show <step-id> --prompt` **does not exist** (no such flag; `step show` takes `-json`
and `-compactions`) and, deeper: no step's prompt carries MCP tools yet, because `internal/runtime`
must not import the layer (`TestNoUnconditionalImportOfMCP` forbids it by name) and step tool
assembly is S13's registry work. That is **F-1, recorded at Medium**, not softened. What CAN be
confirmed was: `ToolSpecsFor` — the one prompt-surface function — renders the injection-laden
description **verbatim inside a genuine per-label boundary** naming the server, marked third-party
DATA, and the counter-test `TestDescriptionReachesPromptBeforeAnyCall` asserts the fake's `calls`
witness read **zero** — the text arrived without the tool being invoked, which is the whole point of
W23's extension (MC7). The §4 walk output in the cumulative DEMO shows the same wrapper on a live
result with a fresh `crypto/rand` token per call.
