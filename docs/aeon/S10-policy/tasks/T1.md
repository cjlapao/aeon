> ### Four decisions this file could not have made
>
> 1. **`Target.ID` is the bare name** — `review`, not `lane-type:review`. The design's notation
>    `lane-type:<type>` and PL8's `target lane-type:review` both compose kind and name at render time, so
>    `Target.String()` emits `kind:id` and `ParseTarget` **refuses an ID that repeats its own kind**
>    (`agent` + `"agent:boss"` is a named refusal). Left unguarded that produces `agent:agent:boss` and a
>    second, unreachable spelling of a target that already exists — two spellings is how a reader ends up
>    guessing which one the store holds. T5's writer must supply the bare name and NULL for `all-agents`.
> 2. **The JSON envelope is snake_case with explicit tags**: `id`, `type`, `target{kind,id}`, `action`,
>    `spec`, `source`, `not_after`. Without tags, `not_after` would not bind to `NotAfter` at all and
>    `DisallowUnknownFields` would be matching Go field names. The names match the column names T5 writes,
>    so one policy reads identically in a fixture, a CLI flag file and a socket payload. `DecodePolicy`
>    refuses unknown fields at **every** level (a plai-backend-shaped `oneShot` or `metadata` field is
>    refused, not silently dropped), refuses trailing content, and runs every closed-set field through its
>    parser — so no path from bytes to a `Policy` bypasses the set.
> 3. **A refusal is `*Reject`, never `error`** (DB19) — `Reject` has no `Error` method and is asserted not
>    to satisfy the interface, reflectively as well as by compile-time signature pins. `Reason` always
>    quotes the value it refused. T3's evaluator, T5's write boundary and T11's three-state answer return
>    this same carrier; that is why the convention is asserted once, here, rather than in each.
> 4. **`NotAfter` is `*time.Time` with nil meaning no expiry (PL7)**, asserted against the type by
>    reflection rather than read out of the file: no sentinel, no pointer to the zero instant, `null` on the
>   way out, and **a malformed expiry is a refusal rather than a nil** — an unparsed expiry that became nil
>    would silently widen the permission, which is the wrong direction to fail in.

## Why this exists

Every decision in this slice is a consequence of one type declaration, and two fields on it carry the whole
security argument.

**`Source` is why a third-party agent can be trusted with a policy at all.** PL1 says an `Allow` may only be
authored by an operator — so `Source` is not metadata, it is the field T5's write boundary checks. Model it
as a closed enum, not a string.

**`NotAfter` is `*time.Time`, and `nil` means no expiry.** Not a far-future sentinel. A sentinel is a policy
that silently lapses on a day nobody chose, and the lapse presents as a bug in whatever it was guarding.

**The set is closed** (PL3) because an open set means a policy whose meaning nothing in the binary knows.
Adding a type is a code change: a schema, a validator, an evaluator.

**Read first:** the design's Decisions table; `aeon/internal/store/schema.go` for the three tables S4's T2
created — in particular the `CHECK` constraints on `policy.type`, `policy.action` and `policy.target_kind`.

## Scope

**1. The types.**

```go
type PolicyType string   // exactly seven; see the design
type Action     string   // Allow | Deny
type Source     string   // Operator | Agent | MCPServer | Import
type TargetKind string   // AllAgents | Agent | Loop | LaneType | MCPServer

type Target struct {
    Kind TargetKind
    ID   string // empty for AllAgents
}

type Policy struct {
    ID       string
    Type     PolicyType
    Target   Target
    Action   Action
    Spec     json.RawMessage // validated per Type — T3
    Source   Source
    NotAfter *time.Time      // nil = no expiry
}
```

**2. Parse, do not trust.** A constructor or parser that refuses an unknown type, action, source or target
kind, returning a **discriminated result rather than an `error`** (S4's DB19) — a bad policy is a domain
refusal, not an infrastructure failure.

**3. Answer Q3 first, and stop if it is wrong.** S4's T2 wrote the `CHECK` constraint on `policy.type`
months earlier in plan time. **Enumerate its seven values and compare them to the seven here.**

**If they do not match exactly, stop and report it.** Do not add a migration — N4 forbids it and the right
answer is a correction to S4's task, not a second migration over the same table. A mismatch found here is
cheap; found at T5 it looks like a store bug.
