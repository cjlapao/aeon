# T11 — `inforce.go`: the three-state answer

## Why this exists

**P31's eighth instance.** *"Is this policy in force?"* has three answers, and collapsing any two is how
the investment in uncertainty gets quietly discarded:

| | |
| --- | --- |
| **enforced and acknowledged** | the agent was told and said so |
| **enforced but unacknowledged** | **the agent was never told. It is still enforced** |
| **could not determine** | no evaluator for this type yet (T3's stubs) |

**The middle one is the valuable one.** A fleet of agents that never acknowledged their policies is working
but degraded — the policies apply, and the agents are wasting turns on calls that get refused because
nothing told them not to. **That is invisible unless something asks.**

**And the middle state must not read as a problem with enforcement.** It is *enforced*; the gap is in the
telling. If this renders as "not in force" somebody will go looking for a policy bug that does not exist.

**Read first:** `record.go` (T6) for acceptance; `spec_stubs.go` (T3) for what "could not determine" means;
the design's PL12.

## Scope

**1. The three states as a closed type**, not two booleans. Two booleans admit a fourth combination that
means nothing, and somebody will eventually render it.

**2. `could not determine` is specifically "no evaluator".** Not a catch-all. If a future reason appears,
it gets its own value — a bucket labelled "other" is how a real signal gets lost.

**3. Rendering keeps all three distinct**, and that is a test, not a convention. The failure mode is
cosmetic and total: `unacknowledged` rendered the same as `acknowledged` deletes the signal entirely while
everything still appears to work.

**4. `aeon policy in-force --agent <name>`** lists them per target, which is the demo's §7.

### The `Stub()` seam: an optional marker type, not the interface method the spec named

The spec said *"extend the T5 seam with one method `Stub() bool`, default false"*. **It shipped as an
optional marker interface (`StubMarker`) that `stubEvaluator` implements, not as a method on
`Evaluator`.** Three reasons:

1. **"default false" does not exist in Go interfaces.** An `Evaluator` method has no default: adding
   `Stub() bool` to the interface forces every future real evaluator — S11's matcher, S14's, S16's,
   S17's, S18's, S20's — to write `func (…) Stub() bool { return false }` forever. That is boilerplate
   whose answer never varies, in a diff whose whole job is to arrive and start deciding, and the registry
   is supposed to grow by *arriving* (PL3). With the marker, absence **is** the false.
2. **The marker's lifetime is the stub's lifetime.** When a real evaluator replaces a placeholder, the
   method leaves in the same reviewed diff, and the in-force answer moves from `could not determine` to
   an answer about enforcement automatically — no second file to remember, and no window where the
   evaluator is real but still reported as unanswerable.
3. **`evaluatorIsStub` is the only reader**, and it is a single type assertion with no failure channel to
   check — a registry question that could fail would be an answer surfaces drop on the floor, and
   `could not determine` would vanish exactly when the infrastructure is worst (S4's DB19, the same reason
   the answer type itself has no error).

**What guarantees an unmarked future evaluator cannot be misreported.** The default is false, and it is
false *structurally*, not by convention: `e.(StubMarker)` fails to hold → `false`, unconditionally, so an
evaluator that says nothing is reported as **decidable** — it gets an enforcement answer, which is the
truth about it. Reaching `could_not_determine` takes one of exactly two **deliberate, reviewable** acts:
implement `StubMarker` returning `true`, or not be registered at all (the other half of `noEvaluatorYet`
is `EvaluatorFor`'s own `!ok` — the same answer `Evaluate` acts on when it refuses rather than permits, so
the two components cannot disagree about whether a type is decidable). Neither is an accident waiting to
happen, and the dangerous direction — a **real** evaluator marking itself a stub — is a one-line lie
sitting in the diff that replaced the stub, where a reviewer sees it. Two locks hold it shut:
`TestTheStubMarkerAndNothingElseCausesCouldNotDetermine` drives the four registry shapes (live / marked /
silent / nil) out-of-band and asserts only the marked one answers `could_not_determine`, and
`TestCouldNotDetermineMeansNoEvaluatorSpecifically`'s sweep over `AllPolicyTypes` pins **exactly six**
placeholder answers today — a seventh is a failing test, not a quiet new state.

**What was refused, and why it matters more than what was chosen:** stub-ness is never read off
`MatchRes.Unimplemented`. Inferring it from a match result would weld back together the two facts T3 kept
apart — *"nobody can evaluate this type"* is not *"a rule refused you"* — and a genuine refusal would start
rendering as an operator's to-do list. `noEvaluatorYet` never calls `Match`; the specificity is the
criterion, and it is tested ("a decidable type is never answered could-not-determine").

### The expired-policy exclusion, and `expired` now being shared with `Evaluate`

Expired rows are **excluded** from the answer — neither in force nor not-in-force: **gone, not denied**
(D6/D7), the same treatment `Evaluate` gives them at the moment of a verdict. Reporting an expired rule as
`in force · unacknowledged` would be a phantom: an operator would chase a rule that stopped existing, and
the fleet would look degraded when it is not. The exclusion is the **caller's** question, not the store's —
`List` still hands back every row, because an audit that hides history is an audit that lies.

The spec offered "factor it out of `evaluate.go` if clean, else duplicate with a pointer to the original".
**It is shared, not duplicated: `expired(p Policy, at time.Time) bool` lives in `evaluate.go`, and `Evaluate`
and `InForceFor` both call it.** Duplication was the worse option — two spellings of "is this rule alive at
this instant" means two answers about one rule at one moment, and the in-force answer would have been free
to disagree with the engine that decides whether the rule binds. The sharing buys the disagreement a test:
flipping the boundary reddens T3's `evaluate` tests and `TestAnExpiredPolicyIsExcludedAtTheGivenAt`
together, so the two can no longer drift apart silently.

**The pinned boundary is unchanged and still active, matching T3:**
`expired` is `p.NotAfter != nil && !at.Before(*p.NotAfter)` —

- **`at` exactly equal to `NotAfter` is expired** (one nanosecond *later* obviously so);
- `at` one nanosecond earlier is **alive**;
- a nil `NotAfter` never expires (PL7 — no expiry is a decision, not a far-future sentinel).

`at` arrives as the caller's parameter and is validated: a zero `at` is refused **before any read**,
because against a year-1 clock every rule with an expiry reads as expired and the answer would be a
confident lie about a fleet of unenforced policies (`TestInForceForRefusesBeforeItReadsAnything`; D5 — no
boundary reads a clock it was not handed).

### Deviations and strengthenings the next editor should know

1. **`InForceAnswer` carries a fourth field, `Target`** (spec names three). It is the target the question
   was asked about, and the renderer's "acknowledged by …" must name **that**, not `Policy.Target`: a rule
   addressed to `all-agents`, asked about `agent:boss` and recorded as accepted by `agent:boss`, was
   acknowledged by `agent:boss`. Printing the rule's scope there credits a statement to a party that never
   made one. Pinned by `TestInForceForAnswersOnlyAboutTheTargetItWasGiven` and by the same-policy
   invariance arm of `TestNoStateCollapsesInRendering`.
2. **The target-matching probe is `requestForTarget(t) Request`, fed to the engine's own `targetMatches`.**
   Not a second equality written here — "does this rule govern this target" has exactly one implementation,
   so the answer cannot disagree with what enforcement would do. `AllAgents` fills nothing (it names
   everyone); each named kind fills exactly the identity field its kind governs. **There is no
   `PolicyRequest` type and no `WithTarget` method** — earlier notes claiming them were wrong; the shipped
   shape is `requestForTarget` → `Request`.
3. **`InForceFor` is stricter than the spec asked**: it rebuilds the target through `ParseTarget` and
   refuses a zero `at`, both **before** any DB read. A hand-cast `Target{Kind: "global"}` would otherwise
   decide who was told.
4. **No partial answers.** A failed acceptance read becomes a `*Reject` naming the seam, not an empty map —
   a half-read acceptance table would report `unacknowledged` for rules whose records the read simply lost,
   and *that* is the one wrong answer this file could give: it sends an operator to chase agents that had in
   fact been told (`TestInForceForFoldsAFailedReadIntoARefusalNamingTheSeam`).
5. **`TestNoStateCollapsesInRendering`'s pairwise table is homogeneous** (one shared `Policy`, one shared
   `Target`, varying only `State`, plus the instant the acknowledged answer exists to report). It was not,
   originally — three different policies with two different types. Heterogeneous inputs made the criterion
   test its own inputs: a renderer that collapsed two states while interpolating policy data still produced
   three different strings. Measured, not argued — planting exactly that collapse (every state rendering the
   acknowledged shape with the policy ID appended) **passed** the original table and **fails** this one. The
   test now also asserts the converse, that the sentence does **not** move when `Policy.ID`, `Action`,
   `Source`, `Spec`, `NotAfter` or `Policy.Target` move, and that `Policy.Type` may move only the
   `could not determine` sentence. Distinctness therefore comes from `State`, which is the whole claim.
6. **The unacknowledged sentence opens `in force`** deliberately (PL10/D13's other half) and the test bans
   `not in force` and `unknown` from it. The three pinned forms are the contract T12/T13/T14 print
   verbatim; they were byte-identical before this retry and remain so.
