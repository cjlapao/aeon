## Why this exists

**A slice is done when someone else can follow `DEMO.md` and watch it work** — not when its tests pass.
This task is a real walk on a clean checkout, and the steps you find yourself doing that the demo does not
mention are the omissions every later reader would hit.

**And this demo has one step that is harder to walk than it reads.** §3 asserts that a *specific allow
loses to a broad deny* — if that step passes too easily, check it is actually exercising PL4 and not a
mis-authored policy that was never allowing anything.

**Read first:** `DEMO.md` in full; `docs/test_suites/` for the house format and the id convention; S11's
QA suite note on why suites assert **properties, not counts**.

## Scope

**1. Walk all eight sections** on a clean checkout. Add what is missing. **Do not soften a step that
failed** — if the UI or CLI does not do what the demo claims, that is a finding, not a documentation bug.

**2. Keep the "what this demo does not show" section**, and check it is still accurate after T1–T11 —
particularly that `CommandAccess` is still schema-only and the six stubs still refuse.

**3. Write `docs/test_suites/aeon-policy.md`.** Status `draft`, ids `QAPL-01` upward. Cover at minimum:

| | |
| --- | --- |
| **Deny wins** | a specific allow against a broad deny, both authoring orders |
| **The authorship rule** | an `Allow` from each of the three non-operator sources, refused at write |
| **Expiry** | the boundary, and that an expired deny falls to the default rather than to allow |
| **The three-state answer** | all three reachable, none collapsing |
| **The age cap** | depth and cap reportable; events past it gone |
| **Purity** | no clock, no I/O in the evaluator — the grep, as a QA step |
| **The empty state** | `policy list` with nothing states the default deny |

**4. Assert properties, not counts.** *"Seven types exist"* is a count that will go stale the first time an
eighth is added; *"every type has either an evaluator or a refusing stub"* is a property that stays true.
