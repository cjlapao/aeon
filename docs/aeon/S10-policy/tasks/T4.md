# T4 — `verdict.go`: the sentence a refusal renders

> ## Notes — the Verdict grew two fields, and what every later surface must call, 2026-10-19
>
> Recorded by `golang-engineer-loop` while landing `aeon/internal/policy/verdict.go` (loop
> `aeon-s10-policy`, T4), the implementation this seed task describes. Read this before rendering a
> refusal anywhere (T8 records it, T9 returns it, T10 records the disagreement, T12/T13/T14 print it).
>
> ### The contract for later surfaces — say it plainly, they will quote it
>
> **Every one of them calls `policy.Verdict.Sentence()` and prints the result whole.** The runtime
> refusal (T9), the manifest/disagreement record (T10), `aeon policy why` (T12), `policy.why` (T13)
> and `PolicyPage.tsx` (T14) print the returned string; `record.go` (T8) writes it to
> `policy_event.detail`. None of them re-cases it, re-segments it, re-orders its segments, drops one,
> translates it, or substitutes its own prefix. `PLAN.md`'s "What you will have" shows `aeon policy why`
> answering `DENIED … no allow matched · default deny (PL5)`: if that is implemented by **replacing**
> the `refused:` prefix, it is a second formatter and the guard below fails it. A status column is
> fine while the sentence is present unmodified. Enforced by
> `TestSentenceIsTheOnlyFormatterInTheModule`, which walks every `.go` file under `aeon/` and fails any
> file that writes a sentence fragment (`no allow matched`, `has no evaluator yet`,
> `denied anyway, PL4`, `default deny (PL5)`) without mentioning `Sentence(`;
> `TestTheSoleFormatterGuardCanFail` proves that guard can fail, on synthetic source, in both
> directions.
>
> ### The `Verdict` grew two fields, not one — and why the second was unavoidable
>
> The task prescribes adding `Subject` (from `req.Subject()`). It turned into two: `Subject string`
> **and** `Type PolicyType`, both copied off the `Request`. The D10 line names `<type>`, and on that
> path `By` is nil — that is what makes it distinguishable from a policy deny — so the type had
> nowhere to live except the verdict. The alternatives were worse than the addition: parsing
> `Verdict.Reason` (a fixed string, `no evaluator for %q yet`) for a word would be prose-parsing in
> the one place prose is forbidden, and taking the type as a `Sentence(typ)` parameter would let a
> caller render one verdict's sentence from another request's type — the drift this file exists to
> kill. Both fields are set by one closure (`about`) that every return path in `Evaluate` passes
> through, so a branch added later cannot omit them; `TestTheSubjectAndTypeTravelFromTheRequestIntoTheSentence`
> pins all four paths (deny, allow, default deny, unimplemented) and M6-style mutation (stop setting
> `Subject`) fails it. `TestTheEvaluatorHasExactlyTheContractedSignature`'s Verdict lock moved from six
> fields to eight — that lock doing its job: the widening is a decision with a name on it, not a typo.
>
> ### "Plus the target renderer" was already built — so this file delegates to it
>
> `<target>` is rendered by **`Target.String()` in `types.go`** (T2's, the one target rendering in the
> product: `lane-type:review`, bare kind for `all-agents`). Declaring a second target renderer here
> would be the exact drift class `verdict.go` was created to prevent, so it reuses the existing one
> and pins the reuse instead (`TestTargetRendersComeFromTargetString`, and all five kinds in
> `TestEveryTargetKindRendersItsCanonicalForm`). The file's own renderers are the unexported
> `expiryLabel`, `targetLabel`, `sourceLabel`, `typeLabel` — none exported, because every exported
> rendering is another API a surface could legitimately call and drift with.
>
> ### The decisions the seed's three-rendering table left open, and the direction each fails in
>
> None of these are reachable from `Evaluate`; they are what happens when a `Verdict` is built by hand,
> and each is pinned so "it can't happen" is not the only defence.
>
> - **`By == nil` on the policy path renders the PL5 line, never `allowed:`.** A verdict that permits
>   nothing and can name no rule has said exactly what the default deny says. Fail closed.
> - **`Allowed` picks the prefix, not `By.Action`** (the task's dispatch rule). A hand-built `By`
>   holding an `Allow` the verdict does not call allowed renders as a refusal — someone loses a
>   permission rather than silently gaining one.
> - **`Unimplemented` outranks `DefaultDeny` in the dispatch order.** "Nobody can decide that yet" is
>   the answer a reader acts on differently, and it is the one T11's `could not determine` maps to.
>   The three shapes are asserted pairwise distinct.
> - **A blank field is said, not skipped** — PL7's rule generalized: `unnamed type`, `unnamed target`,
>   `unrecorded source`. An absent `Subject` renders `Request{}.Subject()`, i.e. what an anonymous
>   request renders. An empty policy ID renders `""`, because quoted-empty is visibly wrong where a
>   dropped segment is not. A test asserts no sentence ever contains a double separator or a trailing
>   one.
> - **A zero `NotAfter` renders `expires 0001-01-01T00:00:00Z`, never `no expiry`** — the one
>   conflation PL7 forbids, and the reason the check is on pointer nil-ness and nothing else.
> - The renderer is **not** a `fmt.Stringer`, deliberately: `Sentence()` is called on purpose, so the
>   sentence never appears in a log through a stray `%v` while T8 binds `detail` at one call site.
>

## Why this exists

*"Denied"* is unactionable. **The difference between a user filing a bug and a user changing a policy is
one sentence** (PL8, generalising G11).

```
refused: bash · ToolAccess "no-shell-in-review" · target lane-type:review · source operator · no expiry
```

Four things in it, each earning its place: the **id** so it can be found and edited, the **type** so its
spec can be read, the **target** so the scope is obvious, and the **source** so *"who decided this"* has an
answer.

**`no expiry` is printed, not omitted.** A policy with no lifetime and a policy whose lifetime nobody
checked look identical when the field is silent — and the second one is a policy about to stop working.

**And when a deny overrode an allow, say so.** PL4 is counter-intuitive: the more specific grant lost.
Naming the overridden allow turns surprising behaviour into explained behaviour.

**Read first:** `evaluate.go` (T2) for what a verdict carries; S4's DB19 on discriminated results.

## Scope

**1. The verdict is a discriminated result, never an `error`** (S4's DB19). A refusal is a domain outcome
the caller branches on; `error` is reserved for infrastructure failure, and one return type makes every
caller guess which it got.

**2. Three renderings**, and they must stay visibly different:

| Case | Shape |
| --- | --- |
| Denied by a policy | `refused: <subject> · <type> "<id>" · target <target> · source <source> · <expiry>` |
| Denied by default | `refused: <subject> · no allow matched · default deny (PL5)` |
| Denied, overriding an allow | the first, plus `(an allow exists: "<id>" · <target> — denied anyway, PL4)` |

**3. `<expiry>` is `no expiry` or `expires <RFC3339>`.** Never blank.

**4. Rendering is pure** and lives here, not in the CLI — so the app (S9) and `aeon policy why` (T10) print
the same sentence rather than two that drift.
