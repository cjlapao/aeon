> ### Q4, answered executably: one `Request` struct serves all seven types
>
> Yes — one struct, twelve fields: `Type`, the four identity fields (`Agent`, `Loop`, `LaneType`,
> `MCPServer`) the target kinds match against, and the seven per-type value fields (`Tool`,
> `Command`, `Route`, `Effect`, `Cost`, `Skill`, `Trigger`), exactly one meaningful per `Type`.
> The reason the test locks the field list (`TestTheEvaluatorHasExactlyTheContractedSignature`):
> seven per-type functions would mean seven totality contracts, seven purity audits, and seven
> places for the deny-wins order to drift. The field count is asserted so a per-type parameter
> cannot creep back in wearing the struct's clothes. A per-type value the engine itself must read
> (T9's step subject) never appears: the engine reads only `Type`, the identity fields, and — via
> the registered evaluator — the one value field.
>
> ### The determinism rules for `By` and `OverriddenAllow` (the spec left both open)
>
> A verdict must not move when a row is appended, so neither field may be chosen by slice
> position. The rule, applied identically to both: **target-specific beats `all-agents`; ties
> break by policy ID, lexicographically smallest first.** IDs are unique in the table, so the
> order is total and every caller, every run, names the same deciding policy. Both rules are
> pinned by tests that author every pair in both orderings
> (`TestDenyBeatsAllowRegardlessOfTargetSpecificity`, `TestADenyCarriesTheAllowItOverrode`).
> `OverriddenAllow` is set exactly when a deny beat a *matching* allow — an allow that was present
> but matched nothing is not "overridden", and naming one would put words in a human's mouth that
> T4 would then render.
>
> ### Three things the seed could not know, settled here
>
> | Decision | The rule, and why |
> | --- | --- |
> | `MatchRes.Unimplemented` contract | Meaningful when `Matched` is false: it records "the evaluator could not decide", and surfaces as `Verdict.Unimplemented` only when nothing decided — so T5's six refusing stubs stay distinguishable from both a policy deny (`By == nil`) and the default deny (`DefaultDeny == false`), which is what T11's `could not determine` reads. A `Matched == true` decision stands whatever the flag says. |
> | `Verdict.Reason` holds fixed strings only | Set only on the unimplemented paths (`no evaluator for %q yet`). > | Named-kind targets with an empty `ID` match nothing | Even against an empty request field. `ParseTarget` makes that shape unconstructable through the parser, but `Evaluate` is handed stored rows (SEC-005's read-side shadow), and a target naming nobody must not read as a target naming everyone. Refuse, never permit (D10). |

## Why this exists

**This is the slice.** Everything else is a spec type, a row, or a caller.

Two properties, and both are load-bearing:

**Pure and total** (PL6, generalising G1). It is consulted on every tool call, and a policy decision that
can fail open is not a guard. No I/O, no environment, and **no clock** — `at time.Time` is a parameter.

That parameter is what makes expiry testable. The boundary is evaluated at `NotAfter-1ns`, `NotAfter` and
`NotAfter+1ns` with **no sleeping and no clock injection** — which is strictly better than the design
without lifetimes, where the boundary was untestable because there was none.

**Deny wins, and specificity never rescues an allow** (PL4):

```
effective = (union of allows) − (union of denies)
```

**Not "most specific wins."** That is the intuitive rule and the wrong one: it lets an agent-level allow
defeat a system deny, which is exactly the union-of-permissions escalation this design exists to close.

**Do this before `ToolAccess` exists.** Deny-wins debugged through a real spec is deny-wins attributed to
that spec. Use a trivial test-only type here.

**Read first:** `types.go` (T1); G1–G13 in
[`docs/_archive/aeon-v1-horizontal/04-permissions`](../../../_archive/aeon-v1-horizontal/04-permissions/design.md)
— this generalises them, and G3/G4 are PL5.

## Scope

**1. The signature, and nothing more:**

```go
func Evaluate(ps []Policy, req Request, at time.Time) Verdict
```

**2. Answer Q4:** does one `Request` shape serve all seven types without a per-type parameter? If it needs
a per-type field, say so in the notes and keep it one struct — **not seven functions.**

**3. The order of operations**, and it is not negotiable:

- drop every policy whose `NotAfter` is non-nil and `!at.Before(*p.NotAfter)` — **expired is gone, not
  denied**
- drop every policy whose target does not match the request
- if **any** remaining policy is a `Deny` that matches → **denied**, and the verdict carries it
- else if **any** is an `Allow` that matches → allowed
- else → **denied by default** (PL5)

**An expired deny does not become an allow.** It stops existing and the default takes over. Assert that
distinction; it is the easy thing to get subtly wrong.

**4. When a deny overrides an allow, the verdict carries both** — the deny that fired *and* the allow it
overrode. That is what makes PL4 visible rather than surprising, and T4 renders it.

**5. An unimplemented type refuses.** Six of seven have no evaluator until later slices. A `default:` branch
that returns allow would silently grant everything they govern — so the default branch **refuses**, and
says it is unimplemented rather than denied by policy.
