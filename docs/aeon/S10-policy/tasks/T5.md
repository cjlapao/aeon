## Why this exists

**PL1 is the entire security argument of this slice, and this task is where it is true.**

> Allow is authored by an operator. Deny may be authored by anyone in the chain. Deny wins.

That is what makes an imported agent or a third-party MCP server safe **without trusting it**: whatever
policy it carries can only narrow it. The dangerous direction is closed at the type level rather than by
review.

**Enforced at the write boundary, in exactly one place.** Not at evaluation — a stored `Allow` from an
agent that "does not count" is one refactor away from counting, and nothing would notice. **Refuse the
write.**

**And a rule enforced in two places is a rule with a gap.** If validation appears both here and in the CLI,
one of them will drift. The CLI (T10) surfaces this refusal; it does not reimplement it.

**No migration** (N4). S4's T2 created `policy`, `policy_acceptance` and `policy_event` with their indexes
and `CHECK` constraints, and asserted by grep that S4 itself neither reads nor writes them. **This task is
the first reader and writer.**

**Read first:** `aeon/internal/store/` for the two-pool shape and DB19's discriminated results; S4's T2 for
the three tables and their constraints; `types.go` (T1).

## Scope

**1. The authorship check**, in one function, called by every write path:

```
if p.Action == Allow && p.Source != Operator  →  REFUSE, naming the source
```

The refusal says that a `Deny` from that source *would* be accepted — because the person hitting this is
usually trying to do something legitimate in the wrong direction.

**2. Reads and writes over S4's `policy` table.** Use S4's writer pool for writes and the reader pool for
reads; **add no migration**, and if the schema turns out to be wrong, report it rather than migrating (T1's
Q3 should already have caught that).

**3. Spec validation on write**, through T3's per-type validator. A policy whose spec does not validate is
refused with the type named.

**4. Expiry is not a write concern.** Do not filter expired policies here — `Evaluate` does it, with `at`
as a parameter. A store that hides expired rows makes T2's boundary tests unreachable and makes the audit
trail lie about what existed.

**5. No caching** (N8). The evaluator is pure and cheap; a cache is where a stale allow lives.

## Notes (golang-engineer-loop, 2026-10-19, loop `aeon-s10-policy` task T6)

- The adapter (`internal/policy/store.go`) imports neither `database/sql` nor `internal/store` — it talks to a
  consumer-side `Repo` interface, so `TestNoSQLLivesOutsideTheStore` stays green by construction; the wiring
  (`RepoFuncs` + `policy.Row`) converts `store.PolicyRow` ⇄ `policy.Row` and lives above the boundary, keeping
  store-SQL and adapter-logic in separate packages (the D3 grep counts files per package).
- `Add` has ONE return shape (`*Reject`): store-infrastructure failures fold into a `Reject` that explicitly says
  the row "was NOT written — the store failed", so no caller can mistake a backend outage for an authorization
  decision. `Remove` returns a plain `error` — there is no rule that can refuse a removal.
- The identifier gate measures **runes**, not bytes (`MaxIdentifierRunes = 64`; justified against the ~480-rune
  measurement rule: T8's 256-rune detail budget is the largest field an id can land in, and 64 is 25% of it —
  ids are keys, not prose). The cap REFUSES with the exact stored string and never truncates; the refusal says
  "refused, not truncated". Blank-gate is `visibleRuneCount` (strips U+200B/200C/200D/2060/FEFF), not
  `TrimSpace`; hostile-content refusals echo the value only through a `strconv.Quote` preview capped at 48 runes,
  so the error text itself cannot inject escape sequences.
- **Amended T4's guard (deliberate deviation):** `internal/store/schema_test.go`'s
  `TestNothingInThisSliceReadsOrWritesThePolicyTables` previously demanded no file besides `schema.go` name the
  policy tables — a slice that legitimately adds the write path makes that invariant unsatisfiable as written.
  The guard now exempts `policy.go` BY NAME (file-name based, so `TestNoSQLLivesOutsideTheStore` still keeps all
  SQL in `internal/store` and every other file is still held to the old rule).
- `List` is the whole read path (no cache — N8; `Store` holds exactly one field, `repo`, AST-asserted by
  `TestTheStoreAdapterHoldsNoCache`); it re-decodes every row through `DecodePolicy`, and a tampered row refuses
  the WHOLE list — failing closed instead of silently dropping a policy that may be a Deny. `List`'s `at`
  parameter is deliberately unused (D6/D8: expired rows are never filtered here — proven by
  `TestExpiredPoliciesAreStillReturnedByTheAdapter` and the store-side twin); the evaluator alone owns expiry
  visibility.
- Store-SQL notes: `Migration` has no `Version` field (the ledger count is read via `.ID`); the SELECT derives
  `subject` from the spec JSON via CASE because 0016 carries no subject column — a handed-in `Subject` is
  ignored at write time, exactly like `Confidence`/`Notes`.
