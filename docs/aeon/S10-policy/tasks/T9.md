# T9 — Policies into the manifest, and the disagreement record

## Notes (T10 build, golang-engineer-loop, 2026-10-20)

What this task's code actually did, that the spec above could not know:

- **Hash canonicalization.** The digest is `sha256hex(join(lines, "\n"))` over lines sorted by ID (stable,
  by ID only), each line `ID|Type|TargetKind|TargetID|Action|Source|rfc3339Nano(NotAfter)|jsonCompact(Spec)`.
  Empty spec canonically `{}` (the field is always in the line); an unparseable spec digests its RAW BYTES —
  `AssembleContext` pre-validates specs, so that fallback exists only for callers that digest without the
  pre-check. Pinned by `TestTheDigestLineIsTheFrozenShapeOfTheSet`.
- **The 32-rule prompt bound.** `## Policy` renders at most 32 canonical-ordered rules, then
  `… and N more (see the step's context manifest)`. The bound is on the PROMPT only — the manifest always
  freezes the full set (100-in/100-frozen asserted), because a bounded manifest would be a gate with
  amnesia. `TestThePromptRenderingIsBounded`.
- **Pre-S10 replay fallback.** A recovered step rebuilds its gate from `snapshot.ContextManifest.Policies`
  when non-empty; empty (or nil `RunOpts.PolicySet`) falls back to the LIVE store — pre-S10 steps must still
  run gated, and their store is all they ever had. The disagreement row additionally requires
  `ModelRequested && StepID > 0` (model-emitted + server-attributed); scripted handler calls record no
  disagreement — they were never the model asking. E2E proof: `TestRecoveredStepIsJudgedByItsFrozenSetNotTodaysStore`
  (daemon), including the two mirror controls that keep "still refused" from meaning "nothing ever runs".
- **Audit rows need a boundary-valid subject.** The gate asks with `Handler.Name`; the ad-hoc default
  `step:ad-hoc` carries a colon, which SEC-013 refuses as an id — refusal AND disagreement rows then fail
  closed (denial still stands). Blueprint handlers carry valid names; the ad-hoc gap is pre-existing
  (T4's subject construction) and is left as a flag, not a T10 change.

## Why this exists

Two halves of PL9, and they are different mechanisms with one declaration:

> **The runtime enforces. The agent is informed so it can behave well — never so it can be trusted to.**

T8 built the enforcement. **This task builds the informing, and the record of when the two disagree.**

**A model told not to do something may still try.** That is not a defect to design away — it is why
enforcement exists. Conflating the two would make a prompt into a security boundary.

**The disagreement log is telemetry, not just audit.** A rising rate means **the policy text is not landing
in the model's context** — a failure you would otherwise never see, because the system keeps working
perfectly. It is the cheapest available signal that an instruction has stopped being read.

**And the manifest is what makes S7's replay honest.** `step.context_manifest` already exists (S4), and it
already freezes the declared context. Policies go in it so that **a replayed step is evaluated against the
policy set it originally saw, not today's** — otherwise a crash recovery silently re-decides the past.

**Read first:** `internal/runtime/context.go` as S5 left it — manifest assembly; S4's `context_manifest`
column and S7's replay path; `record.go` as T7 left it.

## Scope

**1. Write the policies in force into `step.context_manifest`**, at first assembly, with the same freezing
discipline the manifest already uses for files.

**2. Render them into the prompt** in a form a model can act on — the type, the target, the state. Short:
this is an instruction, not an audit record, and the audit record is the manifest row.

**3. Replay reads the manifest, not the store.** S7's recovery path must reproduce the **original** set.
Assert it with a test that changes the live policies between the original run and the replay, and proves
the replay used the old set.

**4. Record a disagreement** when the gate refuses something the agent attempted. It is a `policy_event`
with a distinct kind — the subject, the step, the agent, the policy that fired.

**5. The runtime wins, always.** There is no path where a prompt-level instruction overrides the gate.
Assert that too; it reads as obvious and is exactly the kind of thing a well-meaning refactor breaks.
