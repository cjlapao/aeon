**Prefix:** MD · **Rules:** criteria 1, 3, R4 · **Depends on:** T4.

## Goal

The slice's real acceptance test — a **real loop step**, not a unit test of the seam in isolation — proving
the whole chain works end to end, plus the `ask`/unattended edge and the SEC-059 canonicalizer edge.

## Test map items this task owns

1. **The slice test (criterion 1).** Fake MCP server (reuse S12's existing conformance fake pattern —
   `VERIFY: grep -rln 'fake' internal/mcp/testdata/ internal/mcp/*_test.go` for the established shape, do
   not build a second fake-server harness) + a seeded config entry + an operator `ToolAccess` allow row
   for that exact `server.tool` → start a real loop step with a handler granted MCP access → the model
   (scripted/fixture-driven, this project's existing no-credential-needed pattern) is offered `server.tool`
   with the server's live schema in its `specs` → it calls the tool → the fake server answers → the result
   lands as a `tool_result` in the transcript, readable back from the store afterward. This is the test
   that proves T1–T4 compose, not just that each compiles.
2. **`ask` parks (criterion 3).** Same setup, but the `ToolAccess` row is `ask` (or `allow` under an
   `outward`/`irreversible` effect class, L22) → dispatch suspends on the **existing**
   `pendingPermission` path (`VERIFY: grep -n 'pendingPermission' internal/runtime/loop.go` — lines 76, 663
   per the brief, confirm) → `approve` resumes and the call proceeds → an **unattended** loop with the same
   setup denies at once, no question row (S11's rule, verbatim). **Grep the diff for this task and T1–T4's:
   no new `if` branch was added to `loop.go` for MCP** — the whole point is that a qualified name is just a
   name to the existing gate (brief §2, confirmed: `loop.go:619` stamps `PolicyGateRequest{Tool: use.Name}`
   from the handler side).
3. **The canonicalizer meets the dot (R4, SEC-059).** A `ToolAccess` row spelled in the
   pre-canonicalization alias style (the `write_file`/`write` alias shape SEC-059 fixed, `S11-permissions/
   tasks/T12.md`'s T21 — `VERIFY` the real canonicalizer function, `grep -rn
   'SetToolNameCanonicalizer\|CanonicalizeToolName' internal/`) tested against a qualified `server.tool`
   name: the two name spaces (first-party aliases vs. `server.tool`) must not cross-canonicalize into each
   other. A row that happens to share a substring with a qualified name must not match it, and vice versa.

### Where the tests live (deviation, recorded)

The task proposed `internal/daemon/mcp_dispatch_e2e_test.go`, but the E2E must
reach the dial (`cmd/aeon`'s `dialServer`/`buildMCPBundle`), the daemon
(`BuildTools` → the composite), AND the runtime (`RunStep`) at once — only
`cmd/aeon` imports all three (`internal/runtime` cannot import `internal/daemon`,
`internal/daemon` cannot import `internal/mcp` on the non-test build — MC11).
So all five tests live in `cmd/aeon/mcp_dispatch_e2e_test.go`. The runtime
harness (`runOpts`, `newFakeClient`, `testRequest`, …) is unexported there, so
the test re-derives the exported pieces (`RunOpts`, `StepRequest`,
`ContextManifest`, `StepHandler`, `DefaultHandoffSpec`, `OpeningTranscript`,
`DiscardSink`) and supplies its own scripted model client — the same shape the
runtime's own `fakeClient` uses.

### What exists and is green

- **Item 1 — the one real-loop-step test** (`TestRealStepOffersCallsAndRecordsMCPTool`):
  the real `StepMCP` (`buildMCPBundle`, fake dial via `setDial`) → the real
  composite (`daemon.BuildTools`) → the real loop (`runtime.RunStep`). The model
  is offered `alpha.search` with the server's **live schema** (MD2), calls it,
  the fake server answers, and the answer lands as a `tool_result` in the
  transcript (`res.Messages`), read back and validated by `model.ValidateTranscript`.
  The only fake is the dial; the gate and the loop are real. (The runtime
  persists nothing — K6 — so "readable back from the store" is asserted on the
  transcript the runtime produced, which the daemon's step handler is the one
  that persists; the store read is the daemon's separate concern, not this
  step's.)
- **Item 2 — the `ask` edges** (`TestMCPToolAskParksOnExistingPendingPermission`,
  `TestMCPToolUnattendedDeniesAtOnce`): a `ToolAccess` row `ask` makes the
  attended step suspend on the **existing** `pendingPermission` path (S11) with a
  `permission` question naming the block's own id; the unattended step denies
  **at once** (verdict sentence as an `IsError` `tool_result`) with **no**
  question row. Both reuse S11's mechanism — no MCP-specific suspension.
- **Item 3 — the canonicalizer edge** (`TestCanonicalizerKeepsNameSpacesApart`,
  SEC-059 / R4): a first-party alias row (`write_file`) and a qualified name
  (`alpha.search`) do not cross-canonicalize — `policy.Evaluate` over both
  directions matches neither, while a qualified row matches its own qualified
  call (canonicalisation did not break exactness).
- **The diff check** (`TestNoMCPBranchAddedToLoopGo`): `internal/runtime/loop.go`
  asks the gate about the tool in its raw name (`Tool: use.Name`) and gains no
  MCP-aware branch — the dot lives in the daemon composite, not the gate.
  Confirmed by diff: `git diff --stat b5620631 -- internal/runtime/loop.go` is
  empty for the whole branch.
