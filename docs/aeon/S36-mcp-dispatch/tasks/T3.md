# T3 · Live enumeration and the budgets

**Prefix:** MD · **Rules:** MD2 (dial half), MD4 · **Depends on:** T2.

## Goal

For each server holding ≥1 offered tool (T2's partition), dial it, list its live tools, and build the
final `[]model.ToolSpec` from the **live** schema — never a synthesized one from stale config. A tool T2
marked offered that the server no longer lists is **withheld**, with a named sentence ("no longer listed" or
similar — pick one string, test its exactness, same discipline as every other sentence in this slice): the
disagreement between config and the live server always costs the call, never gains one (brief §R3, quoting
`step.go`'s own words). Unreachable/timed-out servers also degrade to withheld for every tool they would
have offered — the step starts anyway (criterion 4's build-time half).

Two named budgets, each a constant, each measured and recorded (MD4):

```go
// cmd/aeon/mcp_dispatch_seam.go (beside T2's code)
const mcpDialBudget = 3 * time.Second   // per server, at build; parallel across servers
```
(`mcpCallDeadline` is T4's — do not add it here, even though MD4 lists both; each lands with the task that
uses it, so a diff reviewer sees the budget beside its first real use.)

## Definition of done

- [ ] `mcpDialBudget` is one named constant, used, measured.
- [ ] Zero offered tools ⇒ zero dial attempts, proven by spy.
- [ ] Live schema always wins over config's declared one.
- [ ] Dials run in parallel across servers; a slow/dead server never blocks others or the step start beyond
      its own budget.

## Do NOT

- Do not synthesize a tool schema from config when a live one is available or when one isn't — withhold
  instead of guessing.
- Do not dial a server that offers nothing to this agent.
- Do not add `mcpCallDeadline` in this task — that's T4's, landing beside its first use.

## Notes

Built 2026-10-29 (worktree `s36-mcp`, on top of T2 `51e3cc3a`).

**What exists** — `cmd/aeon/mcp_dispatch_dial.go` (new) + the `mcpDialBudget` constant added beside T2 in `mcp_dispatch_seam.go` (the spec asked for the constant "beside T2's code"; `mcpCallDeadline` is NOT here — T4's, beside its first use).
- `const mcpDialBudget = 3 * time.Second` — the one named budget, used and measured.
- `mcpClient` interface (ListTools / CallTool / Close) — the sliver of `*mcp.Client` the seam needs; `*mcp.Client` satisfies it, a fake implements it in tests. `dialServer` is a package var (default `mcp.Dial`) the tests override — the one dial path, no second door.
- `buildMCPBundle(ctx, agent, ps, at)` — the StepMCP implementation: `loadMCPConfig` (Q1) → `mcp.New` → `partitionOffer` (T2) → group offered by server → parallel dial under the budget → live `ListTools` → intersect → `*daemon.MCPBundle{Specs, Withheld, Call, Close}`. No offered tools ⇒ no dials, an empty bundle (MD8).
- `enumerateServer` — one server's dial-and-intersect. Every failure degrades to withheld: no server config ⇒ withheld; dial error ⇒ withheld with the error text (the same `down[srv] = err.Error()` shape `cmdMCPList` uses — MD9, not a new wording); ListTools error ⇒ withheld (client reaped); offered-but-not-live ⇒ withheld with the **named** `noLongerListedSentence` (MD9, tested exact in `TestOfferedButNotLiveIsWithheld`). Live schema wins (MD2): the spec carries the server's live `InputSchema`, never a synthesized one.
- `makeCall` / `closeClients` — a working dispatch and a Close that reaps every client (one error reported, the rest still closed). T4 refines the Call (deadline + isError→error) and wires Close at the four `BuildTools` callers; here the Call is a working dispatch so the composite (T1) is never handed nil.

**Decisions.** The dial is an injectable seam (`dialServer`, a var) returning `mcpClient` — the tests fake it without a subprocess (the spec's "fake-server" intent, done as a client seam because `*mcp.Client` is concrete). No `errgroup`: `golang.org/x/sync/errgroup` is not in `go.mod` (verified), so the parallel phase is a `sync.WaitGroup` + a mutex-guarded results map. `splitQualifiedName` is a local copy of `mcp`'s (unexported) `splitQualified` — first dot is the separator, a tool name may contain dots.

**A bug, found and fixed.** The intersection first failed (`specs=0`) because the loop read `tool, _, _ := splitQualifiedName(...)` — the *server* (the first return) — and matched it against the live-tool map keyed by tool. Fixed to `_, tool, _ := ...`. The live map and the offered name were correct; only the assignment was wrong.

**Measured (MD4, recorded not folklore).** Against the fake (config via `AEON_MCP_CONFIG`, `dialServer` overridden, `XDG_STATE_HOME` throwaway, `-tags sqlite_fts5`):
- `TestDialTimeoutWithholdsNotHangs` — a server that never answers: elapsed **3.003 s** against the 3 s budget (a long-lived parent ctx; only the budget bounds the wait); the tool is withheld, the build does not error.
- `TestDialsAreParallelAcrossServers` — three servers each hanging for the budget: wall **3.004 s** (≈ one budget, not ~9 s sequential); `elapsed > 2×budget` fails.
- `TestZeroOfferedMeansZeroDials` — a dial spy counts **0** attempts when nothing is offered.

**Validation.**

- `go test -tags sqlite_fts5 ./cmd/aeon/ -count=1` (full suite) — green (`ok`, 113 s, 0 fail).
- `go list -deps -tags sqlite_fts5 ./internal/daemon/... | grep -c 'internal/mcp$'` — **0** (MC11 holds; the dial seam lives in `cmd/aeon`, not `internal/daemon`).

**Not run / not shown.** No real dial (the seam is faked in every test); no loop dispatch, no `mcpCallDeadline`, no `Close`-at-the-four-callers wiring (T4); no end-to-end step (T5). The Call is a working but unrefined dispatch.
