# T4 · Dispatch, degradation, lifecycle

**Prefix:** MD · **Rules:** MD3, MD4 (call half), MD5 · **Depends on:** T3. **Answers plan.md's Q3.**

## Goal

1. `Bundle.Call`: dial (cached per server for the bundle's lifetime — one dial per server per step, not
   per call) → `CallTool(ctx-with-mcpCallDeadline, name, args)`. Any failure (dial, timeout, call error,
   server crash) becomes an **error-text `tool_result`**, never a thrown error that kills the step — the
   step continues (criterion 4's dispatch half).
2. `mcpCallDeadline = 60 * time.Second` (MD4's second constant, landing here beside its first use).
3. **Lifecycle**: `MCPBundle.Close` closes every cached connection for this bundle (kill + reap, via the
   client's own `Close` — `internal/mcp/client.go:227`, confirmed this session). Wire it at **all four**
   `BuildTools` call sites via an `io.Closer` check on the returned composite caller (`VERIFY` each site's
   current line with `grep -rn 'BuildTools(' internal/protocol/step.go internal/daemon/recover.go
   internal/protocol/step_stop.go internal/protocol/answer.go` — none of the four currently closes
   anything after `BuildTools`, confirmed this session, because there has never been anything to close
   before this slice). Each site needs a `defer` (or equivalent explicit close on every return path,
   including error returns and panics if the function doesn't already defer-recover) that checks `if c,
   ok := toolset.(io.Closer); ok { _ = c.Close() }` **after** the step/recovery/resume finishes using the
   toolset, not immediately after `BuildTools` returns (the connections must stay open for the step's whole
   run).
4. **Q3**: withheld-tool lines ride the **existing** event channel as additive fields (`VERIFY` the real
   `step.started` event struct — `grep -n 'type.*StepStarted\|EventStepStarted' internal/protocol/*.go
   internal/runtime/*.go` — and add a `withheld []string`-shaped field there if one doesn't exist, rather
   than inventing a new event kind; MD7's additive-only rule and TB12-style old-client harmlessness both
   argue for extending an existing event over adding a new one). Record the decision and the exact field
   added in Notes.

## Definition of done

- [ ] `Bundle.Call` degrades every failure shape to an error-text result; never hangs past `mcpCallDeadline`.
- [ ] All four callers close the composite's MCP connections; a child-count test proves zero leaks across
      the kill-`-9` path specifically.
- [ ] Resume re-dials cold, proven by test.
- [ ] Q3 answered; withheld lines ride an existing event additively.

## Do NOT

- Do not let any dispatch failure propagate as a Go error that aborts the step — degrade to a tool_result.
- Do not reuse a pre-suspension connection on resume.
- Do not add a new event kind if an existing one can carry the withheld list additively.

### What exists

- **MD4 dispatch budget** (`cmd/aeon/mcp_dispatch_seam.go`): `mcpCallDeadline` is a `var` (60 s, not a
  const) so a test shrinks it and restores via `t.Cleanup` — the same seam shape as `dialServer`.
  `makeCall` (`mcp_dispatch_dial.go`) applies `context.WithTimeout(ctx, mcpCallDeadline)` per call; the
  parent ctx may be long-lived, only this budget bounds the wait.
- **Degradation, every shape → an error-text result** (criterion 4's dispatch half): a
  transport/timeout/call error returns `("error: "+err, err)`; a server-reported `IsError` returns
  `(res.Text, err)`; a forged, unknown-to-the-server name is rejected by the server and degrades the
  same way. The composite (T1) turns the `(string, error)` into a `ToolOutcome{IsError: err != nil}`, so
  the step sees an error-text `tool_result` and continues — never a thrown error that kills the step.
- **Lifecycle / MD5** (`step.go`, `recover.go`, `step_stop.go`, `answer.go`): each of the four
  `BuildTools` callers `defer`s `if c, ok := toolset.(io.Closer); ok { _ = c.Close() }` **after** the
  toolset is used, not immediately after `BuildTools` returns — the connections stay open for the step's
  whole run. `MCPBundle.Close` reaps every cached client; one error is reported, the rest still close.
- **Q3 — withheld lines ride the existing `step.started` event** (additive, MD7/TB12): a `Withheld
  []string` field on `StepRequest` (carried by the daemon, `runtime/types.go`) and on `StepEvent`
  (`json:"withheld,omitempty"`, so a decoder that reads only the pre-existing fields is unaffected — the
  additive-only rule). `step.go` populates `compiled.Request.Withheld` from the composite's `Withheld()
  []string` via a type-assertion (the composite projects `bundle.Withheld` sentences); `runstep.go`
  emits `req.Withheld` on the event. No new event kind.

### Deviation (spec #9 wording)

The task's `TestForgedDotToolRejectedByFirstPartyPath` (map #9) says a forged `srv.evil` "routes to the
first-party caller's unknown-tool refusal, never reaching `Bundle.Call`". MD10 ("the dot is the
router") is the opposite for a dot name: `srv.evil` HAS a dot, so the composite routes it to the
BUNDLE, and the bundle degrades it (the test above). The property both agree on — a forged name never
silently succeeds — is what the test proves; a non-dot forged name would instead route to the
first-party caller's unknown-tool refusal (T1's composite), so the two halves cover the same guarantee
from both sides of the router.
