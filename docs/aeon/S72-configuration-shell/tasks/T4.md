# T4 · Walk every page, record the truth, close out

**Rules:** acceptance 7, 8. **Depends on:** T2, T3.

## Goal

The operator said the management UIs "do not really do anything". This task finds out what each page actually does, on a running app, and records it. It fixes nothing.

## Steps

1. Start a daemon on a throwaway state directory (`XDG_STATE_HOME` set to a temp dir, never the real store) and the UI (`make dev` and the UI dev server; note `vite.config.ts` now ignores `src-tauri/target`). In a plain browser the Tauri bridge is missing, so use the desktop shell if it builds on this machine; if it does not, drive the UI with Playwright through the system Chrome (the earlier session used `channel: "chrome"`) against a stubbed or fake-daemon harness, and say plainly in Notes which one you used and what that cannot show.
2. Open each of the fourteen pages. For each, do the one primary action the page offers (create, edit, list, toggle) and note the result.
3. Write the findings table in Notes: page, connection state, what loads, what the primary action did, what is broken or missing, severity (blocking / degraded / cosmetic). Be literal: "list renders empty with a seeded store" is a finding.
4. Check keyboard focus and the panel on a narrow window once, and record it.
5. Update `docs/aeon/STATUS.md` (add S72 to the Stage 5 board with the measured result) and add a short "Adding a configuration page" section to `docs/aeon/README.md`: create `features/config/pages/<id>.ts`, add one line to `registerAll.ts`, nothing else. Keep both under their size rules; `STATUS.md` is already over 1000 lines (standing violation, operator-deferred), so put detail in this slice's Notes and add only the board row.
6. Run the full UI suite and record the measured pass count and any red tests with their cause. Mark each red as pre-existing (proved at base with `git stash`) or new.

## Definition of done

- Findings table complete for all fourteen pages.
- STATUS row and README section added.
- Full-suite numbers recorded.

## Do not

- Do not fix a page in this task. Open a follow-up line per finding in Notes instead.
- Do not report a page as working because its test passes; the walk is the evidence.
