# T2 · Move the twelve sections to pages; shrink Settings

**Rules:** CF3, CF6, CF8, CF10. **Depends on:** T1. Answers Q2.

## Goal

Every section currently stacked on `SettingsScreen` is its own Configuration page, rendered with the same props it gets today. Settings keeps only appearance and language.

## Steps

1. For each row of the CF3 table except `agents`, add a registration file `src/features/config/pages/<id>.ts` calling `registerConfigPage` with `render: (ctx) => <Lazy… controller={ctx.controller} live={ctx.live} canWrite={ctx.canWrite} />`. Pass exactly the props `SettingsScreen.tsx` passes today. Note the one deliberate difference: `ToolsSection` receives no `canWrite` today; keep it that way. Add one import line per page to `registerAll.ts`. Delete `_fixture.ts` and its registration.
2. **Answer Q2.** Open each section and note whether it renders its own title panel. Set `frame: "bare"` for those and `"titled"` for the rest. Record the table in Notes. Do not edit any section to change its header.
3. Edit `SettingsScreen.tsx` per CF8: remove the thirteen section renders and imports; add a clear link to `/config` in the "Other configuration" panel. Keep `data-testid="product-settings"`.
4. Update the tests that pinned the old layout: `test/i18n.test.tsx`, `test/product-shell.test.tsx`, `test/DaemonSettingsPanel.test.tsx`, and any other hit from `grep -rln "product-settings\|SettingsScreen" test src`. Change only assertions about content that moved; record each change and the reason in Notes. The sections' own `*.test.tsx` files must pass without edits.
5. Add the per-page smoke test (CF10): mount `ConfigScreen` at `/config/<id>` with the fake daemon helper and assert the section's root element renders. One parametrised test over all twelve is fine.
6. Confirm `DaemonSettingsPanel`'s daemon-settings content is reachable only through `/config/daemon-settings` now, and that the backup, system-records, policy and MCP deep content is unchanged.

## Definition of done

- Twelve pages reachable; Settings shows appearance, language, tones, preview, link.
- Section test files unchanged (`git diff --stat` shows none of them).
- `tsc`, the touched tests, and `npm run build` pass.
- Q2 table in Notes.

## Do not

- Do not restyle, rename or split a section here. If a section file is already over 1000 lines, record it as a standing violation in Notes and leave it.
- Do not change which RPC methods any section calls.
