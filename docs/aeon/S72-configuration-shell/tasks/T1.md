**Q1 — disabled links: NOT supported, and the spec's fallback needs one correction.**
`SideMenuItemLink` (kit `index.d.ts` ~5599) has no `disabled` field; the `item.disabled`
reads in the bundle belong to the Accordion. A failing `guards` entry HIDES the item
(`passesGuard` gates visibility), it does not disable it. The design expected a
path-less link to render inert — in the installed build every link renders as
`<Link to={link.path}>` unconditionally, so a path-less row resolves `to: ""` and
navigates to Home when clicked (measured by DOM dump, `data-sidemenu-meta` row).
**Deviation, recorded per CF4:** planned rows carry their real `/config/<id>` path
plus `meta: 'planned'`, and `PageLayout` passes an `onItemSelect` to the secondary
menu that cancels the click (`event.preventDefault()`, which react-router honors) for
any row with `meta === 'planned'`. Net behaviour equals the design's intent: the row
never navigates, always says "planned", and a typed deep link to it lands on CF5's
planned state rather than a blank or Home. `meta` renders on expanded rows (kit span
`data-sidemenu-meta`) — verified, so the row really says why. The row keeps `role=link`
in the a11y tree (kit limitation; no `aria-disabled` offered) — follow-up candidate.
