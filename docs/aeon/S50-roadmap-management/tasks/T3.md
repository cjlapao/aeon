**Prefix:** RM · **Rules:** RM3, RM6 (health) · **Shapes:** P2 · **Depends on:** T2, **S44** (registry + `config.Reader` + `settings.*`), **S48** (source, `Analyze`).

Area `roadmap`. (S44's tests that assert the default registry's contents are extended by S44-owned logic; if S44's `TestDefaultRegistryContains…` is exact, this slice **adds its two keys to that assertion** — listed in Notes, an S44-owned data edit.)
- `aeon/internal/daemon/roadmap_dispatch.go` — `ideate`/`plan` read the names **at each dispatch** from the injected `config.Reader` (no construction-time capture; a seam `func(ctx) (name string, err error)` supplied by wiring); then resolve through S48's source and require `Analyze` OK; a missing/invalid choice **refuses** with `"roadmap.ideationBlueprint is \"x\", which does not exist/does not validate — pick one in Settings → Roadmap"` and **never** falls back to the default. The `roadmapIdeationBlueprint` const is deleted (its value is the setting's default).
- `aeon/internal/protocol/roadmap_manage.go` — `roadmap.health {}` → `{settings: [{key, name, state: ok|missing|invalid|unverifiable, reportCounts?}], evaluatedAt}` (unwired S48 ⇒ `unverifiable`, never `ok`); a read.

Deviations and rulings, named:

1. An **explicit `blueprint` param still short-circuits the setting** on `ideate` (the
   `loop.start` precedent): the setting answers when the caller does not name one. The
   param's own errors ride raw as they always did; the "pick one in Settings → Roadmap"
   sentences apply to setting-sourced choices, which is who would otherwise get a fallback.
2. A stored **empty string** refuses with its own sentence ("is empty — pick one in
   Settings → Roadmap") — S44 considers `""` a valid string value, and running `""` would
   be the fallback this rule exists to end.
3. `unverifiable` refuses at dispatch too (the fourth sentence above). The spec named two
   refusal states for dispatch; an unverifiable row is not an Analyze-OK row, and RM3's law
   is *refuse unless provably OK* — starting it silently would be a fallback by another name.
4. Health on a broken setting answers `invalid` and names what a dispatch would refuse over:
   the stored raw value (stored-invalid) or the environment variable (env-invalid) — not
   the default the S44 reader would quietly serve.
5. `roadmap_blueprint_move_test.go` (T2's characterization) now names `"roadmap-plan"` as
   a literal instead of the deleted const; the byte-identity it pins is untouched.
