## Notes

Built 2026-11-04 (worktree `s50-roadmap-management`). One migration
(`20261104012856_roadmap_change.sql`), no `schema.go` edit; the migration
count pin moved to 40 files / 85 applied (`backup_run_test.go`,
`bk_golden_test.go`, both bk goldens regenerated — fingerprint.golden grew
+12 lines / −0 removals, every line inside `roadmap_change`).

Design placement: the audit rides the STORE writers, not the socket. Six
audited twins (`roadmap_audited.go`) run each write and its `roadmap_change`
row through `RoadmapWithTx` — one transaction (RM2), the setting_event /
policy_change / automation_change house law. The plain writers keep their
signatures (S26 test callers unchanged), and every production call site
moved: the seven protocol write handlers, the ideate/plan/materialize
dispatch, the reactor's brief landing, terminal-done landing and loop
records, and triage's hand-off create+ideate. The store surface table names
all new exports (S50 row). The wrapper list (plain signatures retained):
`Create`, `Transition`, `Cancel`, `SetEstimate`, `SetPriority`,
`SetArtifacts`, `RecordLoop` — called by S26 tests only; production uses
`CreateAudited`, `TransitionAudited`, `CancelAudited`, `SetEstimateAudited`,
`SetPriorityAudited`, `LandBriefAudited`, `LandPlanAudited`,
`RecordLoopAudited`.

Actor vocabulary: new `store.RoadmapActor{Kind,ID}` (`roadmap.Actor` alias)
deliberately separate from `store.Actor` — user/cli/system with a non-blank
id; `agent` is refused by the schema CHECK and by `Valid()` (RM4). Socket
handlers stamp `{user, uid}` from the connection (`roadmapActor`); a nil
stamp or uid `"0"` answers −31931 `ErrRoadmapNoActor` (fixture
`roadmap/add-no-actor.json`); identity keys `actor`/`actorKind`/`who` are
refused by a key-bag pre-check (−32602, fixture
`add-identity-key-refused.json`) because `decodeParams` is lenient by
design. Reactor writes carry `{system, reactor}`; triage carries
`{system, triage}`. The three seam types (`RoadmapIdeate/Plan/Materialize`)
take the actor as a Go argument, never a wire param.

Deviations and decisions recorded:

  lands artifact pointers only on a won claim, then one audit row — an
  early ordering landed artifacts even on a lost claim; fixed before commit.

  because the id is born inside the transaction. Every other summary is the
  door's fixed template (ids/statuses/enums only, SEC-033; the hostile-title
  test proves no user text reaches a row).
- The TriageHandoff seam itself does not carry a person actor (its callers
  are not person-socket-driven yet); its roadmap writes stamp
  `{system, triage}`. Threading a person through that seam is out of T1
  scope.
- CLI `'cli'` actor kind is compiled into the CHECK but has no live issuer
  yet — offline doors arrive with T6.

  blocked-event reactor pass, every refusal and every lost CAS.
