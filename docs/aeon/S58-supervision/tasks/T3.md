# T3 · Acknowledge and snooze: the write half, audited, human-door

**Prefix:** SV · **Rules:** SV3, SV12, SV13 · P3, P4 · **Depends on:** T2.

## Goal

A person can hide an item they have seen (acknowledge) or until a time (snooze) and undo it; every change is attributed, append-only, and the number in `summary` never lies. No agent can do it.

## Files

- `aeon/internal/attention/ack.go` — **new**: `Acker` over the store: `Ack(ctx, actor, key)`, `Snooze(ctx, actor, key, until)`, `Unack(ctx, actor, key)`. Validation: the key must match `<source>:<id>:<since>`; the key must name an item **currently** returned by `Evaluate` (else `ErrInboxScope`: "that item is no longer needing attention" — acking a ghost is refused so the table cannot be filled with arbitrary keys); `until` must be in the future and ≤ now + 7 days (`MaxSnooze` constant, SV-D11); an `ack` of an already-acked key and an `unack` of an un-acked key are **no-ops** (no row — one row per *changing* write, P3).
- `aeon/internal/store/attention.go` (T1) — `AppendAttentionAck` also appends a `notify_change`-style audit? **No** — `attention_ack` *is* its own append-only audit (actor in the row); a second audit row would double-count. Recorded as a P3 deviation here.
- `aeon/internal/protocol/inbox_write.go` — **new**: `InboxAckParams{key}`, `InboxSnoozeParams{key, until}`, `InboxUnackParams{key}`, result `{item?: AttentionItem}`; handlers take the actor from **`table.ActorFor(ctx, sess)`**, refuse an actor of kind `agent` and an unresolvable actor (`ErrBadParams` wording: "acknowledging is a person's act"), never read an `actor` from params. Constants `MethodInboxAck/Snooze/Unack`; registered only when the `Acker` is wired (V13).
- `aeon/internal/attention/evaluate.go` — apply `LatestAcks` to the evaluated items: `acked={by, at, until?}`; a snooze whose `until` has passed is **not** acked (computed at read from `until`, no job); `summary.acked` counts hidden items so `total` is honest.
- Contract chain: three fixtures (success each + a refusal for an agent actor + a ghost key), handshake lines, `make protogen`.
- `aeon/cmd/aeon/` — nothing here (T6 adds the CLI client).

## Behaviour

1. `inbox.ack {key}` ⇒ one `attention_ack` row (`op='ack'`, actor from the peer); the item disappears from the default `inbox.list`, appears with `acked` under `includeAcked`, and counts under `summary.acked`.
2. `inbox.snooze {key, until}` ⇒ hidden until `until`; after it, the item is live again with **no job running** (the filter is a comparison at read time).
3. `inbox.unack {key}` ⇒ one `op='unack'` row; the item returns.
4. A **recurrence** (new `since`) is never hidden by an old ack (T2's key rule, re-proved here end to end).
5. Acking never touches the loop, the question or any other row.
