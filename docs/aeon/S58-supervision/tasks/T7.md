# T7 · The shell: tray, close-to-tray, deep link

**Prefix:** SV · **Rules:** SV9, SV10 · **Depends on:** T4 (the hint carries `deepLink`). Parallel-safe with T6, T8.

## Goal

With the window closed, OS notifications still arrive and the person can get back in. Done **Rust-side only**: the web layer's capabilities do not change. Quitting is explicit and honest about what it stops.

## Files

- `aeon/ui/src-tauri/Cargo.toml` — `tauri = { version = "2", features = ["tray-icon", "image-png"] }` (a Cargo **feature**, no new crate family) and `tauri-plugin-deep-link = "2"` (one new Rust crate; justified below). Versions pinned as the repo's `Cargo.lock` convention; `cargo update` is not run for unrelated crates.
- `aeon/ui/src-tauri/src/background.rs` — **new**:
  - `pub fn close_policy(has_live_session: bool, quitting: bool) -> ClosePolicy { Hide | Close }` — **pure**, unit-tested: `Hide` only when a daemon session is live and we are not quitting; otherwise `Close`.
  - `pub fn tray_items(inbox: Option<u32>, daemon_is_ours: bool) -> Vec<TrayItem>`: *Open Aeon*, *Inbox*, a disabled count line ("3 need you" / "Inbox unavailable" when `None`), *Quit Aeon (stops the daemon this app started)* when `daemon_is_ours` else *Quit Aeon* — pure and unit-tested (the honesty rule).
  - `pub fn build_tray(app: &AppHandle) -> tauri::Result<()>` — `TrayIconBuilder` with the menu, the app's own PNG icon (`icons/`), `on_menu_event` (Open ⇒ `show` + `set_focus` the `main` window; Inbox ⇒ same plus `emit("aeon://navigate", "aeon://inbox")`; Quit ⇒ set `quitting`, `app.exit(0)`), left-click ⇒ show.
  - `pub fn parse_link(url: &str) -> Option<NavTarget>` — **pure**: accepts only `aeon://inbox`, `aeon://loop/<id>`, `aeon://root/<id>` where `<id>` matches `^[A-Za-z0-9_-]{1,64}$`; everything else `None` (unit-tested with malformed, oversize, path-traversal and query-string inputs).
- `aeon/ui/src-tauri/src/main.rs` — `.setup`: add `build_tray` (failure is **logged and non-fatal**: where there is no tray host the app behaves exactly as today and records `background_presence = "unavailable"` in `AppState`); `.on_window_event`: `CloseRequested` on `main` ⇒ per `close_policy` either `api.prevent_close(); window.hide()` or fall through; register `tauri_plugin_deep_link` and `on_open_url`: for each URL `parse_link` ⇒ show/focus the window and `emit("aeon://navigate", target)`; a `None` ⇒ emit `aeon://navigate-refused` with a fixed reason enum, never the raw URL. The existing `RunEvent::Exit` handler (`stop_if_spawned`) is **unchanged** and remains the only place the daemon is stopped.
- `aeon/ui/src-tauri/src/session.rs` — expose `inbox_count()` to `background.rs` through the **existing** session (a `inbox.summary` call the shell already can make; a failure ⇒ `None`); polled when the window is hidden every 60 s and on every `aeon://event` the shell already forwards (no second subscription).
- `aeon/ui/src-tauri/tauri.conf.json` — the deep-link scheme entry (`plugins.deep-link.desktop.schemes = ["aeon"]`) only; `security.capabilities` untouched.
- `aeon/ui/src-tauri/capabilities/default.json` and `README.md` — **expected unchanged**. If building the deep-link plugin forces a capability entry, the diff and its justification go in `README.md` per its own rule ("adding a permission is a reviewed diff with the reason written down") **and** in this task's Notes; the default expectation is none (all handling is Rust-side; `listen` is already granted by `core:event:default`).
- `aeon/ui/src-tauri/tests/background_policy.rs` — **new** (the repo has `tests/remote_transport.rs`, so integration-style Rust tests exist): tests for the three pure functions above and for "capabilities unchanged" (reads `default.json` and asserts the permission list equals the recorded five entries unless this task's Notes record a diff).

## Platform behaviour (T0 records the real bundle targets: deb, appimage, dmg, nsis)

macOS and Windows: native tray. Linux: needs an app-indicator host; when `build_tray` errors, close behaves as today (window closes) and the doctor panel/`aeon doctor` shows "background presence unavailable: no system tray". **No autostart** (SV-D5).

**The deadlock the poller exists to prevent, in one paragraph:** the shell
forwards daemon notifications on the session reader thread. That thread is
the only thing that can READ a response; a `Session::call` made from it
waits for a response it will never get to read. So the event sink only
POKES a one-slot channel, and the poller thread — which is allowed to dial —
answers the poke and the 60 s heartbeat alike. This is the spec's "no
second subscription" honored structurally: there is one listener (the sink)
and one caller (the poller), and neither can starve the other.

### Follow-up correction — the dot did not show for the person testing (2026-11-06)

The operator walked it on Linux and reported what the first cut could not
satisfy: test notifications appeared in the app's notification panel while
the window was open, and the tray icon never moved. Both halves were true by
construction, and the construction was wrong for the ask:

1. **`should_refresh` gated on the window being HIDDEN** (the original S58
   rationale — the tray exists for the hours the window does not). A watched
   tray that only updates in hiding is a tray that visibly lies while
   watched; the gate is gone. The tray now refreshes on every poke and
   heartbeat while a tray host is up — one coalesced `inbox.summary` read per
   poke burst on the local socket, bounded by the one-slot channel.
2. **The dot read only the daemon's inbox**, and in-app notifications never
   reach the inbox — the bell's panel and the daemon's roster are different
   truths. The ask ("the user sees there is something for him to do") is the
   bell's number, so the icon now mirrors it: the web layer reports the
   store's unread count to the shell (`tray_unread` — a display mirror, reads
   no daemon state, can decide only the dot) on every unread-count change and
   once on mount (a reload re-syncs a shell that never saw the pushes).

**The dot's rule, final:** unread notifications > 0 **or** the daemon's
inbox is pending — `tray_badge(LastInbox, unread)`, with `LastInbox` now
three-state (`NotAsked` — never asked, no claim, no dot; `Unreadable` —
asked and failed, never a reassuring zero; `Count(n)`). The focus-clear arm
is removed: the dot now mirrors live truth (the bell's number stays honest
while the window is open; "mark all read" or acking items clears it through
its own door).

**The near-miss the walk exposed, recorded because it was a real bug:** the
first cut's `Focused(true)` arm called `apply_badge` from the **event-loop
thread**, and `set_icon`'s `run_item_main_thread!` dispatch WAITS on that
loop — a focused window with an active dot would have hung the whole app.
It never fired in the field only because the dot had never latched true.
Now documented at `apply_badge`: callable from any thread EXCEPT the loop's
own; which is also why `tray_unread` is an ASYNC command (off-loop, like
Tauri's own tray commands) and why the poller thread remains the only
`inbox.summary` caller.
