# T6 · Mission status, the CLI (`aeon inbox | status | notify`), and agent reads

**Prefix:** SV · **Rules:** SV11, SV13, SV16 · standing rules 1 and 2 · P5, P6 · **Depends on:** T2, T4, T5. Parallel-safe with T7, T8.

## Goal

The overview a person (or an agent) reads — per root component: what is running, waiting, blocked, what needs you, what it costs against its cap, what comes next — with the CLI as a pure client of the socket methods and own-view agent read tools.

## Files

### Daemon: `mission.status`

- `aeon/internal/mission/` — **new** (standard library + `internal/store` reads + `internal/attention`): `Evaluate(ctx, scope)`:
  - **loops** — counts by `loop.status` per root (a root includes its children): `running|waiting|blocked|idle` (done/aborted excluded; a `terminal` count is not invented). Store accessor `LoopStatusCountsForScope` (SQL in `internal/store/mission_read.go`).
  - **needsYou** — `attention` summary for the same scope; **a consistency test** asserts it equals `inbox.summary`.
  - **spend** — the S44-extra telemetry rollup of the root's component row (a root's row **is** the subtree total — CT7): `{state: "reporting", usdAtLeast, costState}` (the P32 floor, never presented as exact when `partial|unknown`), and `cap` from the **S55 `BudgetReader` seam** (`func(ctx, rootID) (CapInForce, bool, error)`): absent ⇒ `cap: {state: "not-wired"}`.
  - **nextReady** — the **S27 seam** (`NextReady(ctx, rootID)`); absent ⇒ `{state: "not-wired"}`.
  - `lastActivityAt` — max of loop `updated_at` in scope. **No composite health score.**
- `aeon/internal/protocol/mission.go` — **new**: `MissionStatusParams{rootId?}`, `MissionStatusResult` per SV11, `MethodMissionStatus`, V13.
- `aeon/internal/daemon/mission.go` — wiring + the **exported seam registrars** `RegisterBudgetReader`, `RegisterNextReady` for S55/S27.
- Contract chain: fixtures (`mission/status.json` with `reporting` and `not-wired` groups), handshake, `make protogen`.

### Doctor

- `aeon/cmd/aeon/doctor.go` / `internal/doctor` — add: a **Notifications** block (channels: name, host only, enabled, last outcome, consecutive failures; ≥ 3 failures flagged), the **sources** list (`reporting|not-wired|failed`), and the tray/background capability line when the app reports it (T7). Read-only; never prints a URL path or secret ref.

### CLI (P5 — every verb a client of a socket method; parity is a test both ways)

- `aeon/cmd/aeon/inbox.go` — **new**: `aeon inbox list [--root ID] [--severity S] [--kind K] [--include-acked] [--limit N] [--json]` (human output: severity-grouped, `reason`, age, the **door sentence**, a trailing sources line), `summary [--root ID] [--json]`, `ack KEY`, `snooze KEY --until RFC3339|--for 4h`, `unack KEY`.
- `aeon/cmd/aeon/status.go` — **new**: `aeon status [--root ID] [--json]` → `mission.status` (a tree of root → counts, needs-you, spend vs cap with the floor labelled, next ready; unwired groups printed as `not wired (S55)` etc.).
- `aeon/cmd/aeon/notify.go` — **new**: `aeon notify classes [--json]`, `class update KIND [--variant V] [--enable|--disable] [--tone T] [--title T] [--body T]`, `channels [--json]`, `channel show ID`, `channel create --name N --url U --secret-file PATH [--allow-private] [--root ID --min-severity S ...] --yes`, `channel update ID ...`, `channel enable|disable ID`, `channel archive ID --reason R --yes`, `channel test ID --yes`, `deliveries [--channel ID] [--outcome O] [--limit N]`, `vocabulary`. **No flag, stdin or prompt accepts a secret value** (C17): `--secret-file` is a path; a test greps the CLI's own source for any `--secret`/`--token`/`--password` value flag. `--yes` is a **seatbelt**, required for channel create/archive/test (authority and outward act), not a security control.
- The CLI **re-validates nothing**: flag parsing refuses only what cannot be a value; every other refusal is the daemon's sentence verbatim; `--json` is the wire result verbatim. **No offline fallback is added** (none of these verbs works without a daemon: the inbox is live state and channels need the secrets store the daemon owns — recorded P5 deviation).
- `cmd/aeon/main.go` — dispatch + usage for `inbox`, `status`, `notify` only.

### Agent tools (rule 2, P6) — all read-only, own-view

`aeon/internal/records/catalog.go` (data only, no import added), family `supervision`, `Mutates: false`, class `safe`: **`inbox_list`**, **`inbox_summary`**, **`mission_status`**, **`notify_class_list`**, **`notify_channel_list`** (host, enabled, last outcome, failure count — **never** the URL path, secret ref or subscription detail). Twins: `inbox.list`, `inbox.summary`, `mission.status`, `notify.class.list`, `notify.channel.list`. `internal/daemon/records.go` `Do` cases scope every call to the agent's own root component tree (`Identify` supplies the root, `daemon/records.go:89-108`); a `rootId` naming another tree is refused with the own-view sentence. **No write tool exists** — the spec header comment says why (acknowledging hides problems; a channel is authority). `TestRegistryExactNames` (both want lists, `internal/tools/toolset_test.go`) bumped **+5, counted and dated** from T0's real count; `testdata/rerun_classes.json` updated; registered, **not granted** (default grant unchanged).

## Definition of done

- [ ] `mission.status` with named unwired groups and honest cost; CLI parity both ways; no secret flag; five own-view read tools; registry bump counted; doctor shows hosts only.

## Do NOT

- Do not add a write tool; do not return a URL path, secret ref or subscription detail to an agent; do not invent a health score; do not print a zero for an unwired group; do not add an offline door; do not accept a secret value.
