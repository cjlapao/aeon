> ## Notes — done 2026-10-15

> ### One deviation: I1 permits an import that would be a cycle
>
> I1 allows `internal/model` to import `protocol`'s error helpers. **That permission cannot be taken**,
> because this task puts `ask` in `internal/protocol` — so `protocol` imports `model`, and `model` importing
> `protocol` back is a cycle. The same shape as T5's, demonstrated rather than assumed.
>
> So `model` is a **strict** leaf: it returns plain Go errors, and `protocol/ask.go` maps them onto Aeon
> codes — exactly as `internal/daemon` already maps protocol errors onto wire errors. The mapping lives with
> the layer that owns the vocabulary. The leaf test was tightened to match.
>
> ### Four codes allocated, in the band the registry reserved for domains
>
> `-31012` unknown subscription (the subscriptions band), and `-31100`–`-31102` route, buffer, provider
> failure (the domain band S2 set aside). Each with three parts and a fatal marker, each with a conformance
> fixture — **S2's staleness check demanded them immediately**, which is that check earning its keep across a
> slice boundary on its first opportunity.
>
> ### `ask.done` carries a structured error, not a string
>
> It was a string, and **walking the demo showed what that costs**: in streaming mode the failure arrives
> there rather than as a JSON-RPC error, so a string meant the three-part shape was lost in exactly the mode
> a person uses — `aeon ask` printed the provider's sentence and no remedy. It is now the same `*Error` the
> synchronous path returns, with its own fixture.
>
> ### Three tests that exist because of how they could pass wrongly
>
> The subscription is validated **before** the call, so a bad id does not cost money — asserted by checking
> no events were emitted. A subscription id from **another connection** must not resolve, or one client could
> stream into another's subscription. And `PROTOCOL_VERSION` is asserted unchanged: a method and two event
> kinds are additive by the rule beside the constant, and this is the first slice since the protocol existed
> to test that rule.

## Context

The first domain method, and the first test of S2's promise that the table grows **additively**.

**`PROTOCOL_VERSION` must not move.** A new method and new event kinds are additive by S2's rule (T2), and a
test asserts the constant is unchanged. If this addition forced a bump, either the rule is wrong or this
addition is not what it appears to be — and either way it should be noticed here rather than at S19 when three
clients exist.

**Streaming rides subscriptions** (M23). `ask` takes an optional `subscriptionId`; deltas arrive as `event`
notifications with kinds `ask.delta` and `ask.done`. That reuses S2's filtering, cursor and teardown rather
than building a second streaming path that would need reconciling at S9 when the app wants both.

**The buffered mode is explicitly a different mode** (O5). Without a `subscriptionId`, `ask` returns the whole
reply in its result. That path exists for a script and for tests — and it is the one that would **hide a
streaming bug**, because a buffered reply looks identical whether or not the stream worked. So it is bounded
(Q9) and named, not a fallback that happens when a field is missing by accident.

**Read first:** `internal/protocol/method.go` and `subscribe.go` (S2); `internal/model/client.go` (T9); S2's
error registry — the codes this slice adds are allocated there (I2 of S2), not locally.

## What to do

**1. `ask.go`** — params: `route` (required), `prompt` (required), `subscriptionId` (optional),
`maxOutputTokens` (optional, defaulted), `temperature` (optional). Result: `askId`, plus `text`, `usage` and
`cost` **only** in buffered mode.

**2. With a `subscriptionId`**: return `{askId}` immediately, then emit `ask.delta` events carrying the `askId`
and the text, and one `ask.done` carrying `usage` and `cost`. Emit through S2's registry so the subscriber's
filter and cursor apply.

A `subscriptionId` that does not exist, or belongs to another connection, is a named error — not silently
ignored, which would leave the client waiting for a stream that will never arrive.

**3. Without one**: buffer to a **stated bound** (Q9) and return the whole reply. On exceeding the bound,
truncate and **report the truncation** in the result. An unbounded buffer is a memory hole with a
prompt-shaped cause.

**4. Allocate the error codes in S2's registry** — unknown route (listing configured ids, O6), unknown
subscription, buffer exceeded, provider failure. Each with its three parts and a fatal marker.

**5. Cancellation.** A client disconnecting cancels the `ctx`, and the partial `usage` and `cost` are still
emitted as `ask.done` where a subscription exists. A cancelled `ask` that reports nothing loses the spend
(M15).
