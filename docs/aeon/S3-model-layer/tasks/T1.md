> ## Notes — done 2026-10-15
>
> ### The `Usage` presence mechanism, and why pointers
>
> **All fields are `*int`.** The alternative — `InputTokens int` plus
> `HasInputTokens bool` — was rejected for a specific reason: it doubles the field count and creates a state
> where the two disagree, which no test would catch because both halves look right in isolation. A pointer
> *is* "absent or present", in one field, and survives a JSON round trip in both directions with nothing to
> keep in sync. The cost is `*int` at every read site, and `cost.go` is the only place that pays it often.
>
> ### Two struct-tag guards, and a correction to the first one
>
> `Cost.State` and `Block.IsError` carry no `omitempty` (O2, O3). Both were first tested *behaviourally* —
> and a negative control showed **the `Cost.State` test was not a guard at all**: `omitempty` omits only the
> zero value, and `"known"` is not empty, so adding the tag changed nothing observable and the test stayed
> green.
>
> The tag is still wrong, because it is safe only *in combination with* CostState's current constants: the
> day `CostState` becomes an int, or a constant is reordered so `known` is the zero value, a known cost
> serialises with no state and is indistinguishable from an absent one. **Two steps, the second in a
> different file months later** — so both guards are now structural, asserting the tag by reflection. Both
> verified by a negative control.
>
> ### Added beyond the task: `Route.APIKey` is `json:"-"`
>
> This is the slice most likely to commit a key. A `Route` can reach an event payload or a log line by
> accident, and `json:"-"` means the accident cannot leak it rather than every call site having to remember.
> Tested.
>
> Prices moved into their own `Prices` struct, which T4's `ComputeCost(u, *Prices)` signature asks for.

## Context

The shape everything else builds on, and the slice's one deliberate loss of type safety.

**Tagged structs, not interfaces** (M20). Go has no sum types, and the TypeScript version's four-member `Block`
union does not translate — an interface-based union needs hand-written `MarshalJSON`/`UnmarshalJSON`, and
**transcripts are persisted (S4), replayed (S5) and recovered from (S7)**, so JSON round-trip fidelity outranks
compile-time exhaustiveness. A hand-written codec is exactly where a lost `thinking` signature would come from.

The cost is real and stated: a `text` block can carry a `ToolUseID`. `Validate()` is what buys it back, and it
runs at **every boundary that accepts a `Block` from outside** (Q10) — so the invalid state exists in theory
and never in a stored transcript.

**Two struct tags are where M9's honesty could be undone silently:**

- `Cost.State` must have **no** `omitempty` (O2). A genuinely-known zero cost must still serialise its state,
  and without this a `known` zero becomes indistinguishable from an absent one.
- `Block.IsError` must have **no** `omitempty` (O3). Otherwise a failed tool result and a successful one
  serialise identically and the model sees no difference.

**`Input` is `json.RawMessage`, not `any`** — it round-trips byte-identically, and S7 replays those bytes.

## What to do

**1. Create `internal/model/types.go`** with the design's `Block`, `Message`, `Usage`, `Cost`, `Route`,
`ModelRequest`, `ToolSpec` and `Delta`.

`FormatVersion` is an exported int, `1`. `Usage`'s fields are all pointers or all `omitempty`-with-a-presence-flag
— **choose one and state why**: absent must be distinguishable from zero (M9), and Go's zero value makes that a
design decision rather than a default.

**2. Constructors for all four block kinds** — `TextBlock`, `ThinkingBlock`, `ToolUseBlock`, `ToolResultBlock` —
each producing a value that passes `Validate`. They are the ordinary path; a bare struct literal is the
exception and the one `Validate` catches.

**3. `Validate()` on `Block`**, rejecting any field foreign to its `Kind`. Enumerate the checks; a `default:`
that permits an unknown kind is the hole.

**4. `ToolSpec.Parameters` is `json.RawMessage`** (M22) holding a JSON Schema this layer never inspects. A doc
comment says so, and says who owns it (S6).

**5. Prove the leaf boundary** (I1): a test greps the package's imports and asserts nothing under `internal/`
except `protocol`'s errors.

**6. Write the round-trip test as the primary one.** Marshal a `Block` of each kind, unmarshal, marshal again,
and compare **bytes** — not deep equality. Byte comparison is what catches a `RawMessage` renormalised by the
encoder, which is Q5's question and S7's dependency.
