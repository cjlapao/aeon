## Context

The guard on a **stored schema**. A transcript is written when a step suspends or crashes and read back later —
possibly after a release, possibly against a different provider (S7, S18). That makes this file's rules the
thing standing between a persisted transcript and a provider 400.

Two rules are subtle and each protects a different failure.

**Anthropic constrains ordering**: no two consecutive assistant messages, and never starting with one. Catching
it here means the error names the offending index; not catching it means a provider 400 that says nothing about
which message was wrong.

**A suspended transcript is valid.** It ends on an assistant turn containing a `tool_use` with no matching
`tool_result` — which is precisely what a pending question looks like (S6). A validator requiring every
`tool_use` to be answered would reject every suspended step, which is the normal resting state of a waiting
loop.

**`ValidateTranscript` returns a result, never an error for malformed input** — it is called on data read from a
database, and a panic or an error-shaped failure there takes down a recovery.

**Read first:** `types.go` (T1); `docs/_archive/aeon-v1-horizontal/02-store/design.md` for what suspension persists;
`docs/_archive/aeon-v1-horizontal/01-model-layer/tasks/T2.md` for the TypeScript version of these rules.

## What to do

**1. `ValidateTranscript(msgs []Message) ValidationResult`** — a struct with `OK bool`, `Reason string` and an
optional `Index int`. Not an `error`: the caller distinguishes "this stored transcript is unusable" from "the
database failed", and an `error` conflates them.

Rules, each with its own reason string:

- non-empty
- does not begin with `assistant`
- no two consecutive `assistant` messages, with `Index` set to the second
- every `tool_result.ToolUseID` matches a `tool_use.ID` appearing **earlier**
- every `tool_use` has a matching `tool_result` **unless** it is in the final assistant turn — in which case
  the transcript is suspended and valid
- no message has an empty `Content`
- every `Block` passes `Validate` (T1)

**2. `MigrateTranscript(stored []byte) MigrationResult`** — parses a versioned envelope. A `formatVersion`
**greater** than `FormatVersion` is a loud refusal naming both numbers: a newer Aeon wrote it, and a
best-effort parse would silently drop fields it does not understand — plausibly including a `thinking`
signature. A lower version is where future migrations go; today only `1` exists, so a lower one is also a
refusal with a **distinguishable** reason.

**3. Write the tests as a table of malformed inputs** — each rule violated, plus `nil`, an empty slice, a
message with an unknown `Kind`, and malformed JSON for the migration path. Assert every one returns a result
and **none panics**.

Assert the suspended case returns `OK` **explicitly**, with a comment naming why — it is the case a future
contributor will read as a bug.
