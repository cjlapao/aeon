> ### The credential check, and why the match is never printed
>
> Six patterns, including a catch-all for any 48+ character base64-ish run — the one that would catch a
> token from a provider nobody has integrated yet. **On a hit the match is deliberately not printed**:
> putting it in a CI log would be a second copy of the mistake the test exists to catch.
>
> The check is proven against five credential shapes in a temp file rather than by committing a key, and the
> capture script's redaction is proven separately — including that it leaves an ordinary stream body
> untouched, since a scanner that mangles JSON produces a fixture that fails for the wrong reason.
>
> ### The capture script duplicates the adapters on purpose
>
> It builds its own provider requests rather than calling `ToWire`. **A fixture built with the code under
> test would agree with that code's assumptions**, which is the one thing a recording is for. It also sets
> `stream_options.include_usage` for OpenAI, without which every capture would be a usage-absent one and
> `known` cost would be untestable — asserted by a test.

## Context

Every stream test in this slice is worth exactly what its fixture is worth — and a fixture's trustworthiness is
**invisible in the test that uses it**. A hand-written fixture encoding what the author believed a provider
sends will pass its test and be wrong in production. So each one is labelled `recorded` or `hand-written`, and
a hand-written one names what was not verified (O4).

This task also carries the slice's highest security risk. A recorded SSE capture is made against a real
endpoint with a real key, and the naive capture writes request headers into the file. **This is the most likely
place in the whole project to commit a credential.**

**Read first:** the brief's §8 standing non-goals; `docs/_archive/aeon-v1-horizontal/01-model-layer/tasks/T5.md`, which this ports.

## What to do

**1. `scripts/capture-fixture.go`** — takes a provider, a route from `AEON_CAPTURE_*` environment variables and
a scenario name; makes one real streaming call; writes the **response body bytes verbatim** to
`internal/model/testdata/<provider>/<scenario>.sse`.

Redaction on write:

- **Never write request headers.** The response body is the fixture; the request is not needed to replay it.
- Scan the body for credential shapes — `sk-`, `sk-ant-`, `Bearer `, long base64-ish runs — and replace with
  `<redacted>`. Providers do echo request metadata in some error bodies.
- Never write a URL containing a query-string key.

**2. Capture the set.** Per provider: text-only; one tool call; usage present; usage **absent**. For Anthropic
additionally: a **signed `thinking` block** (T8's fidelity test asserts against it) and **two tool calls in one
turn** (T8's merge test).

**3. `manifest.json`** — one entry per fixture: path, provider, scenario, `origin`, capture date, and for
hand-written ones a `notVerified` string. An unlabelled fixture is a failed self-check.

**4. `fixtures_test.go`:**

- every file has a manifest entry and every entry has a file
- **no fixture contains a credential** — match `sk-[A-Za-z0-9]{16,}`, `sk-ant-`, `Bearer [A-Za-z0-9]`, and any
  run of 32+ base64 characters
- every fixture parses through `ReadSSE` (T3) without error

The credential test runs on every commit, so a key added by a later capture is caught rather than shipped.
