> ## Notes — done 2026-10-15
>
> ### A correction to my own earlier deviation
>
> T5's signature is `ToWire(req)`. I had added a `route` parameter in T5 — and T9's `Stream(ctx, req)` with
> no route argument is why the spec had it that way: **the route belongs on the request**, because the same
> messages against a different route are a different call with a different cost. Reverted, and `Route` is now
> a field on `ModelRequest`.
>
> ### The retry boundary, and the test a naive version passes
>
> `deltaYielded` is the whole rule: **once a delta has reached the caller, a retry would duplicate it.** The
> test for the after-case counts the delta — a test that only checks for an error passes against an
> implementation that retried and rendered everything twice.
>
> ### Two backoff caps, because one was wrong
>
> They were one constant at 30s, and a test caught it: **a `Retry-After` of 90 seconds is an ordinary
> rate-limit instruction**, and clamping it to 30 meant retrying into the same limit twice more before
> giving up — the opposite of what honouring the header is for.
>
> Now `maxBackoff` (30s) bounds *our exponential guess* and `maxRetryAfter` (2min) bounds *the provider's
> instruction*. The provider's number is information; ours is a guess. A long wait is safe because `sleep`
> honours the context, which is what made the original clamp unnecessary — cancelling a loop is still
> immediate, and there is a test with a one-hour backoff to prove it.
>
> ### Cost is constructed in exactly two files, asserted by AST
>
> `cost.go` has the arithmetic; `client.go` calls it once. The guard walks the AST for a `Cost` composite
> literal or a `ComputeCost` call anywhere else, and was **verified with a negative control** in
> `internal/daemon`. An adapter computing its own cost would let a third adapter at S18 get it wrong in a way
> nothing would catch — and the figure would look plausible.

## Context

The composition point, and the home of two rules that cannot live anywhere else.

**Cost is computed exactly once, here** (O1, I4). An adapter must not compute it, so that a third adapter at S18
cannot get it wrong. Structural, enforced by grep, not by convention.

**The retry gate is a flag, not a counter** (M14). Retrying a 429 or a 5xx is correct — **until a delta has
reached the caller.** After that, output is on a screen, and a retry either duplicates it or asks the UI to
un-render. So the gate is *"has any delta been yielded on this attempt sequence?"*, and once set the call fails
rather than retries. A plain attempt counter cannot express that and will happily retry after streaming half a
response.

**A cancelled call still reports cost** (M15). The tokens were spent and will appear on a bill. Resolving with
nothing loses real money from the accounting; returning an error loses it too.

**Read first:** both adapters (T7, T8); `cost.go` (T4); `registry.go` (T5) for `Finalise`; the brief's §11.

## What to do

**1. `internal/model/client.go`:**

```go
type StreamResult struct {
    Usage      Usage
    Cost       Cost
    StopReason string
    Dropped    int
}

type Client struct { HTTP *http.Client }   // injectable — D15

func (c *Client) Stream(ctx context.Context, req ModelRequest) (<-chan Delta, <-chan StreamResult, <-chan error)
```

Three channels: deltas for display, one result for accounting, errors distinguishable from a clean end. An
injectable `HTTP` is what makes the suite pass with no network.

**2. The flow.** Resolve the adapter from `req.Route.Provider` (T5). `ToWire`, send with `ctx`. Non-OK → decide
retry. OK → `ReadSSE` (T3) → `FromWire` (T7/T8). Forward each delta, **setting `deltaYielded = true` on the
first**. On completion or cancellation, call `Finalise`, then `ComputeCost`, and send one `StreamResult`.

If the stream was cut before any usage arrived, override the cost to `unknown` with reason
`stream-aborted-early` — the one reason `cost.go` deliberately does not produce (T4).

**3. The retry rule.**

- Retryable: 429, 500–599, and transport errors.
- **Not** retryable: any other 4xx. A 400 is a schema or content error; retrying wastes time and money.
- **Never** retry when `deltaYielded` is true, whatever the status.
- Honour `Retry-After` in **both** seconds and HTTP-date form; otherwise exponential backoff with jitter and a
  bounded attempt count.
- A cancelled `ctx` during a backoff delay ends immediately rather than sleeping it out.

**4. The owed error result.** When T7 reported unparseable tool arguments, make it unambiguous on the
`StreamResult` that a `tool_result` with `IsError: true` is owed. S5's runtime writes it into the transcript;
this layer's job is to say so rather than invent a tool outcome.

**5. The two tests that matter.** A 500 **before** the first delta retries and succeeds. A 500 **after** fails,
and the test asserts the delta was yielded **exactly once** — a test that only checks for an error passes
against a duplicating implementation.
