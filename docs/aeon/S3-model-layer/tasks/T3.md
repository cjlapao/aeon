> ### The parity loop, which is the whole point
>
> The sample stream is replayed at **every chunk size from 1 to its length** and compared frame-by-frame
> against the unchunked parse. Plus the multi-byte case explicitly: a `data:` line containing an emoji, split
> at **each of the three interior byte boundaries of that rune**.
>
> That hazard is genuinely absent in Go rather than handled — the reader accumulates `[]byte` and converts to
> `string` exactly once, with a whole frame in hand. There is no incremental decoder to carry state across a
> chunk, which is the JavaScript failure mode M19 supersedes M7 over.
>
> ### Separators: five forms, not two
>
> The task names `\n\n` and `\r\n\r\n`. Also handled: `\r\r`, `\n\r\n`, `\r\n\n` — a proxy
> normalising line endings can produce any of them. **On a tie the longest separator wins**, so `\r\n\r\n`
> is not parsed as `\n\r\n` leaving a stray `\n` to open the next frame with an empty line.
>
> ### Two details the SSE specification has and a careless parser loses
>
> **Exactly one leading space** after the colon is framing; a second is data. Trimming all whitespace
> corrupts a value that legitimately begins with one. And **multiple `data:` lines in one frame join with a
> newline**, which OpenAI relies on for multi-line content.
>
> Two channels rather than one of `(Frame, error)` pairs, as specified — and the reason is worth restating:
> the error channel is how a **truncated** stream is told from a clean end, and a single channel of pairs
> makes every consumer branch on a nil error at every receive. The one place somebody forgets is the place a
> truncation is reported as a completed call.

## Context

**No dependency** (M19, superseding M7). The TypeScript slice used `eventsource-parser` for a good reason: in
JavaScript a `TextDecoder` carries state across chunks, and getting that wrong truncates a tool call. **That
hazard is a JavaScript problem.** In Go, working in `[]byte` and decoding once at the end removes it, and the
wire format is blank-line-delimited `field: value` — a hundred lines we would have to exhaustively test either
way.

**Keep the test that made the dependency worth having.** Offset independence is the property, not the library:
replay a fixture chunked at **every** byte offset and assert identical output. That is cheap in Go and it is
what proves the reassembly.

Four edge cases from the format, and each has bitten somebody:

- **`\r\n\r\n` as well as `\n\n`** separates frames. A reader that only handles the latter works against one
  provider and truncates against a proxy that normalises line endings.
- **A final frame with no trailing blank line** must still be delivered. Some servers close without it.
- **`data: [DONE]`** is a sentinel, not content — and Anthropic never sends it, so its absence must end cleanly.
- **An erroring reader must propagate.** A truncated stream that looks like a clean end is reported as a
  completed call.

**One reader, both providers** (I3). A second framing implementation diverges, only one gets tested, and in a
stream parser divergence means one path truncates.

**Read first:** the plan's Q4 answer — which `bufio` approach handles both separators and a missing trailing
blank line; `docs/_archive/aeon-v1-horizontal/01-model-layer/tasks/T3.md` for the test list this inherits.

## What to do

**1. `internal/model/sse.go`:**

```go
type Frame struct { Event, Data string }
func ReadSSE(ctx context.Context, r io.Reader) (<-chan Frame, <-chan error)
```

Two channels rather than an iterator: the error channel is how a truncated stream is distinguished from a clean
end, and a single channel of `(Frame, error)` pairs makes every consumer branch on a nil error.

**2. Work in bytes.** Accumulate `[]byte`, split on the frame separator, and convert to `string` only when a
complete field value is in hand. Do **not** decode incrementally — that is the JavaScript failure mode this
decision exists to avoid, and it is available in Go too if you reach for `bufio.Scanner` with a rune-based
split.

**3. Handle both separators, a missing trailing blank line, `[DONE]`, comment lines and `retry:`.**

**4. Honour `ctx`** between frames, and release the underlying reader when it is done — a leaked body on a
long-lived daemon is a slow file-descriptor leak.

**5. Write the parity loop first.** Take a real fixture's bytes and replay them chunked at every offset from 1
to the length, asserting deep equality against the unchunked parse each time. Keep the fixture small enough
that the loop is cheap; it is the only test that actually proves offset independence.

Then the multi-byte case explicitly: a `data:` line containing an emoji, split **inside** that rune.
