> ## Notes — done 2026-10-15
>
> ### One deviation, and it is an import cycle
>
> The task puts the `Adapter` interface in `adapters/registry.go`. **That cannot compile.** Its signatures
> are made of `model`'s types, so `adapters` imports `model` — and `client.go` (T9) lives in `model` and
> needs an adapter, so `model` would import `adapters`. **Demonstrated with a throwaway module before
> changing anything**: `import cycle not allowed`.
>
> Resolved with Go's own driver pattern — the one `database/sql` uses and that this project already relies on
> for `sqlite_vec`: **the contract and the registry belong to the consumer, and implementations register
> themselves.** The interface and registry are in `model`; `adapters/registry.go` is still the single
> aggregation point, so **M12's promise is unchanged**: a third provider is one file plus one line there.
> The cost is one blank import outside `model`, which `internal/daemon` carries.
>
> ### M12's proof, and what it required
>
> `registry_test.go` is in package `adapters_test`, not `adapters` — deliberately external, so it reaches
> the adapters only the way the product does: `model.AdapterFor` after a blank import. A same-package test
> could call `newOpenAI()` directly and would prove nothing about whether registration happens.
>
> The fictional provider (`acme-llm`) is driven end to end and **its definition is inside a test file** —
> which is the point: nothing outside `adapters/` changed to add it.
>
> ### A test that was asserting Go's allocator
>
> "Each resolution returns a fresh adapter" compared pointers, and **failed on correct code**: an adapter
> with no fields yet is a zero-sized struct, and Go may return the same address for every zero-size
> allocation. It now counts factory invocations, which asserts the actual contract and keeps working once the
> adapters have fields.
>
> `Delta` has exactly four fields, enumerated by a test, with the fragment-shaped names (`Index`, `Partial`,
> `ArgumentsSoFar`, …) named and forbidden — M8 as a property of the type rather than a rule in a document.

## Context

This task exists so M12 — *a third provider is one adapter file plus a registry entry* — is **structural rather
than aspirational**. It comes before either adapter (R4), because an interface extracted after two
implementations tends to be the shape of whichever was written first, and S18's whole cost estimate depends on
this being true.

**`Delta` is the enforcement point for M8.** If there is no representation for a partial `tool_use`, an adapter
cannot yield one. That is a stronger guarantee than a rule in a document, and it is why the type belongs here
rather than in an adapter.

**`ToWire` performs no I/O.** It builds an `*http.Request` and returns it. That is what makes it testable
without a network and what keeps `client.go` the only place a request is sent — asserted with an `http.Client`
whose transport panics.

**`Finalise` is separate from the stream** because usage arrives at different points per provider — a final
chunk for OpenAI, `message_start` plus `message_delta` for Anthropic — and the caller needs it **after** the
stream is exhausted, including when it was cut short by cancellation (M15).

**Read first:** `types.go` (T1); `sse.go` (T3) for `Frame`; the design's §The two providers table, which is what
the interface must accommodate without favouring either.

## What to do

**1. The interface**, in `adapters/registry.go`:

```go
type Adapter interface {
    Provider() string
    ToWire(req model.ModelRequest) (*http.Request, error)
    FromWire(ctx context.Context, frames <-chan model.Frame) <-chan model.Delta
    Finalise() (model.Usage, string, int)   // usage, stopReason, dropped
}
```

**2. `Delta` in `types.go`** — the canonical increment:

```go
type DeltaKind string  // "text" | "thinking" | "tool_use" | "stop"

type Delta struct {
    Kind    DeltaKind
    Text    string  // text, thinking
    Block   *Block  // tool_use — COMPLETE, never partial (M8)
    Reason  string  // stop
}
```

`Block` is a pointer and only set for `tool_use`, and the doc comment states it is always complete. A test
asserts there is no field an adapter could use to express a fragment.

**3. The registry** — provider id → adapter constructor. An unknown **route** id fails with a named error
**listing the configured ids** (O6): at this stage the list is short enough to print, and "route not found" on
its own is a support question.

**4. A stub adapter in the test** for a fictional provider, driven end to end. That test is M12's proof: if it
passes without touching anything outside `adapters/`, adding the compatible path at S18 is one file.
