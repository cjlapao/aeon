## Context

The other task this slice exists for, and it carries **the property that fails furthest from home**.

**`thinking` must round-trip byte-identically, signature included** (M17). Anthropic rejects a tool-use turn
whose prior thinking block was altered or dropped. Because **S7 recovers a crashed step by replaying a stored
transcript**, a signature mangled here surfaces four slices later, in a different package, as a provider 400
about signatures — with nothing pointing at this adapter. So the test asserts the **exact string**, and the
provider's constraint is **quoted in the test file** so the assertion is written against the rule rather than
against a guess.

Four rules here have no counterpart on the OpenAI side:

**`system` is hoisted** out of the message array to a top-level parameter (M5). Leaving it in is rejected.

**Tool results merge.** All `tool_result` blocks for one assistant turn go in a **single** following user
message. Emitting one per result is rejected — and this is the row most easily missed, because it works with one
tool call and fails with two.

**`max_tokens` is required** (M16). Its absence is a 400, not a default.

**Usage arrives in two places** — `message_start` carries input and both cache counts, `message_delta` carries
output. A reader that looks at one gets half the cost.

**Read first:** `sse.go` (T3); `registry.go` (T5); T6's Anthropic fixtures including the signed-`thinking` and
two-tool-call ones; the plan's Q2 answer — **quote it into the test file.**

## What to do

**1. `ToWire`** — `POST {baseURL}/messages`, headers `x-api-key`, `anthropic-version: 2023-06-01`,
`Content-Type`. **Not `Authorization`** — copying OpenAI's header set is the natural mistake and it fails with a
confusing 401.

- **`system`**: join every `system`-role message's text into the top-level parameter. Omit the parameter
  entirely when there is none; do not send an empty string.
- **content** passes as typed blocks: `text` → `{type:"text"}`; `thinking` → `{type:"thinking",thinking,
  signature}` **verbatim**; `tool_use` → `{type:"tool_use",id,name,input}` with `Input` as an **object**;
  `tool_result` → `{type:"tool_result",tool_use_id,content,is_error}`.
- **Merge tool results**: consecutive `tool`-role messages after an assistant turn collapse into **one**
  `role:"user"` message whose content is every `tool_result` block, in order.
- `max_tokens` always. `stream: true`. `temperature` when set. `tools` as `{name,description,input_schema}`.
  `ExtraBody` last — where a variant's `thinking` config lands.

**2. `FromWire`** — walk the event types:

- `message_start` → accumulate `usage.input_tokens`→input, `cache_creation_input_tokens`→cacheWrite,
  `cache_read_input_tokens`→cacheRead. **Only when present.**
- `content_block_start` → note type and index; for `tool_use` record `id` and `name`; for `thinking` begin a
  text buffer **and a signature slot**
- `content_block_delta` → `text_delta` yields text; `thinking_delta` appends and yields a thinking delta;
  **`signature_delta` appends and yields nothing** — the signature is replay metadata, not display content;
  `input_json_delta` appends to that index's argument buffer
- `content_block_stop` → for `tool_use`, unmarshal and yield a complete block; for `thinking`, the buffer and
  signature are final
- `message_delta` → accumulate `usage.output_tokens`→output; record `stop_reason`
- `message_stop` → yield `stop`
- unrecognised event types → increment `dropped`

**3. `Finalise` must expose the completed `thinking` blocks with their signatures**, so S5's runtime can persist
them into the transcript. A thinking delta yielded for display is not enough: display text is lossy and the
signature never appears in it.

**4. The fidelity test.** Stream the signed fixture, reassemble the canonical `Message`, pass it back through
`ToWire`, and assert the emitted wire block is **deep-equal to the fixture's original** — same thinking string,
same signature string, byte for byte. Quote the provider constraint above it.
