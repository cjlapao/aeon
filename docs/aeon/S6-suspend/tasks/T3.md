# T3 — `resume.go`: `ResumeStep` on the shared loop

**File(s):** `aeon/internal/runtime/resume.go`, `aeon/internal/runtime/resume_test.go`
**Engineer:** golang-engineer-loop · **Tech:** go · **Depends on:** T2 · **Est. changed lines:** ~290

## Context

The second door, and the rule is **one loop, two doors** (K26, I1, O1). Two loop implementations would drift, and
T6's identity test is precisely the test a drift would fail — months later, without saying why.

The doors differ in their preconditions, which is why they are separate functions rather than one with an optional
argument: `RunStep` assembles context and may have no transcript; `ResumeStep` assembles **nothing** and requires
both a transcript and an answered question.

**"Assembles nothing" is invisible without a spy** (I7). A `ResumeStep` that re-assembled would work perfectly
until a file changed, so the test asserts `AssembleContext` was called **zero** times.

**The changed-file note is a `user`-role message** (K14, D8). This is not stylistic. Anthropic hoists **every**
`system` message to a top-level parameter (M5), so a mid-transcript `system` note would be silently relocated to
the **head** of the conversation — arriving before the content it comments on, which inverts its meaning.

**Changed and missing are kept distinct** (D8). "This file changed while you waited" and "this file no longer
exists" call for different responses, and merging them into one list loses that.

**And the transcript still quotes the original.** Nothing is re-read into context (K13). A transcript quoting one
version while its context describes another is internally inconsistent, and a model will act on whichever it
notices.

**Read first:** `loop.go` (T2); `internal/runtime/context.go` (S5 T2) for `Rehash`;
`internal/model/adapters/anthropic.go` (S3 T8) for M5's hoisting, which is why K14 exists;
`docs/_archive/aeon-v1-horizontal/03-step-runtime/tasks/T6.md`.

## What to do

**1. `resume.go`:**

```go
func ResumeStep(ctx context.Context, req ResumeRequest, opts RunOpts) StepResult
```

`ResumeRequest` carries the transcript, the manifest, the answered question, and the compiled request's static
parts — everything a caller read from the store.

**2. In this order:**

- `Rehash(manifest)` → `changed`, `missing`
- if either is non-empty, append a **`user`**-role note naming them, keeping the two lists **separate**
- append `tool_result(question.ToolUseID, question.Answer)`
- call `RunLoop` with the manifest's existing `IterationsUsed` and `DeadlineAt` — **not fresh ones**

**3. Cap the paths named** (O3). A step declaring two hundred files that all changed would produce a note longer
than the context it protects. Name up to a stated number and say how many were omitted.

**4. An empty answer is valid** (O5) and passes through as an empty `tool_result`. Refusing it would make "I don't
know" unexpressible, and a model handles an empty answer better than a step that will not resume.

**5. Assemble nothing.** Assert it with a spy (I7).

**6. Tests.** The role assertion is on the message object, not on the rendered text. The bounds test suspends and
resumes and asserts `IterationsUsed` continued.
