# T2 — Suspension in the loop: detection, siblings-first, the return

**File(s):** `aeon/internal/runtime/loop.go`, `aeon/internal/runtime/suspend_test.go`
**Engineer:** golang-engineer-loop · **Tech:** go · **Depends on:** T1 · **Est. changed lines:** ~280

## Context

Fills the `suspended` variant S5 shipped unused (K21). Two properties, and the second is subtle enough to be got
wrong by a reasonable implementation.

**A `question` tool call is never executed** (K18, D6). There is nothing to execute — the answer comes from a
human. Passing it to the toolset would either error or, worse, reach the panic W15 wrote for exactly that case.

**Siblings execute first** (K25, D5). A model may emit `read` and `question` in one turn. Suspending straight
away looks correct and leaves `read`'s `tool_use` in the transcript **with no result** — so there are now **two**
unanswered calls. `ValidateTranscript` rejects that, and no resume path can repair it: the answer has nowhere to
attach, because there are two holes and only one answer.

So: partition the calls, execute everything that is not a `question` **serially** (K9), append their results, and
**then** suspend. The answer arrives into a transcript whose turn is otherwise complete, with exactly one hole.

**The assertion is on the transcript's final shape, not on call order.** Call order would pass against an
implementation that ran `read` and then discarded its result before suspending.

**One loop** (I1). S5 built it and this extends it; a second copy is what D1's identity test would eventually
fail on without saying why.

**Read first:** `internal/runtime/loop.go` as S5 left it; `internal/model/format.go` (S3) for exactly why
`ValidateTranscript` accepts a suspended transcript — that rule exists for this slice;
`docs/_archive/aeon-v1-horizontal/03-step-runtime/design.md` §The bounded loop.

## What to do

**1. Partition the tool calls** each iteration: those named `question`, and the rest.

**2. Execute the rest serially** (K9), appending each `tool_result` — unchanged from S5.

**3. If a `question` was present**, return `{Kind: suspended, Question: {…}, Manifest: …, Messages: …}` after
those appends. The `Question` carries the `tool_use` id, the text, the options and the kind.

**4. A suspension consumes an iteration** (O4). Increment `IterationsUsed` on the **manifest** before returning,
so a model looping on questions exhausts `MaxIterations` rather than running forever.

**5. More than one `question` in a turn**: take the first, and treat the others as ordinary unexecuted calls —
which means the transcript would have two holes, so **refuse instead**: return `failed` with a reason naming the
count. A model asking two things at once is asking wrongly, and inventing an order would answer one of them with
the other's answer.

**6. Write the tests.** The sibling test asserts on the final transcript: two `tool_use` blocks, **one**
`tool_result`, and the unanswered one is the `question`. Then run S3's `ValidateTranscript` over it and assert it
accepts.
