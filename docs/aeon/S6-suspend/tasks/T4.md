# T4 — `compact.go`: the estimate and the range selector

**File(s):** `aeon/internal/runtime/compact.go`, `aeon/internal/runtime/compact_test.go`, `aeon/internal/runtime/compact_property_test.go`, `aeon/internal/model/types.go`
**Engineer:** golang-engineer-loop · **Tech:** go · **Depends on:** T3 · **Est. changed lines:** ~300

## Context

The exclusion that fails **furthest from home**, and a test shape that matters more than the code.

Three ranges are structurally excluded, and each has a different consequence:

- **The head sections** — they are the step's instructions. Summarising them summarises the task away.
- **The last assistant turn's `thinking` blocks** — the provider rejects a tool-use turn whose prior thinking was
  altered (M17, P21). That failure surfaces as a **400 about signatures during a later resume**, in a different
  package, with nothing pointing at the compactor.
- **Any `tool_use` whose `tool_result` falls outside the range** — orphaning one is a 400 on Anthropic and a
  **silent degradation** on OpenAI, and the silent one is worse.

**The selector enforces them, not a check afterwards** (K16, I2, D11). A post-hoc validation can only reject a
summary **after the model was paid to write it** — and the step is then still over budget, facing the same wall
with less money. So the proof is a refusal with the `model.Client` spy at **zero** calls.

**The tests are property-based over a generated corpus** (R6, D10). The transcripts that break compaction are
shapes nobody enumerates: an orphaned `tool_use` two messages from the boundary, a `thinking` block that happens
to be last, a head section longer than the middle. A handful of examples passes and ships a compactor that breaks
the first time a real step calls three tools in one turn.

**The estimate is a heuristic** (K17). An exact count needs a tokeniser per model, and compaction only needs to
know "close to the limit".

**Read first:** `docs/_archive/aeon-v1-horizontal/03-step-runtime/tasks/T7.md`, which this ports; `internal/model/types.go` for
`Block` and whether `Route` carries a context window (plan Q2); M17 and P21.

## What to do

**1. Add a context window to `Route`** if Q2 found it absent. The estimate is a fraction of *something*, and
hardcoding a number per model here would put a model catalogue in the wrong layer.

**2. `EstimateTokens(msgs) int`** — characters over a constant, plus a per-message overhead. **State the constant
and the safety margin in a doc comment, and state both are uncalibrated.** Do not add a tokeniser (K17).

**3. `SelectRange(msgs, budget) SelectResult`** — returns a range provably containing no excluded content, or a
refusal with a reason. Specifically: start **after** the head sections; end **before** the last assistant turn;
and expand or refuse so that every `tool_use` inside the range has its `tool_result` inside it too.

A transcript with no admissible range returns a refusal, which the loop turns into `blocked` (K28, T5).

**4. Write the property tests.** Generate transcripts varying: message count; presence and position of `thinking`
blocks with signatures; `tool_use`/`tool_result` pairs at varying distances, including interleaved and adjacent;
head-section count; and message sizes. For every generated transcript that triggers compaction, assert all three
properties. **Record the corpus size**; aim for the hundreds.

**5. Write the negative unit test.** A transcript with no admissible range refuses **with no `Client` call** —
spy at zero. An implementation that summarises and then validates cannot pass it, which is the point.
