# T6 — The keystone: resume identity

**File(s):** `aeon/internal/runtime/identity_test.go`
**Engineer:** golang-engineer-loop · **Tech:** go · **Depends on:** T5 · **Est. changed lines:** ~220

## Context

**The smallest task in the slice by line count and the largest by consequence.**

Every other test here can pass against an implementation that quietly depends on something surviving in memory
between suspension and resume — a closure over the original transcript, a cached manifest, a package-level
counter, a `sync.Map` keyed by step id. All of those work perfectly in a single-process test and fail the first
time a real step waits overnight and the process exits, **which is the entire promise of P2.**

The only test that rules it out **serialises through JSON, reconstructs in a fresh object graph that shares no
reference with the original, and asserts deep equality against a run that never suspended.** That is the
property, and it is worth stating as one: *suspension is invisible in the result.*

**And the test's own convenience can defeat it.** If the `ResumeRequest` is built in a scope that still holds the
original transcript, a single forgotten field reference reintroduces exactly the dependency being ruled out. So
the request is constructed in a scope with **no access** to the originals — a helper function taking only the
serialised bytes is the straightforward way.

Three variants, each exercising different state that could leak:

- **Plain** — the transcript and manifest round-trip.
- **With compaction** — T5 rewrote the transcript mid-step, so the compacted state must survive too.
- **Across two suspensions** — the iteration counter and absolute deadline must **accumulate** rather than reset,
  which a fresh-budget bug reveals only on the second resume.

**Read first:** `resume.go` (T3); `loop.go` (T2, T5); `docs/_archive/aeon-v1-horizontal/03-step-runtime/tasks/T8.md`, which is the
closest thing to a specification of this test that exists.

## What to do

**1. `identity_test.go`.** For each variant, the same shape:

- **Run A** — a fake `Client` scripted to complete the step without ever asking. Record the `StepResult`.
- **Run B** — the same script, except one turn emits a `question`. Run to suspension. Then:
  - marshal the transcript, the manifest and the question to JSON, and unmarshal into new values
  - **assert the reconstruction shares no reference with the originals** — walk both graphs, or freeze the
    originals and confirm the copies are independent. Do this **explicitly**; the whole test rests on it, and
    "we serialised it so it must be fresh" is the assumption under examination
  - build the `ResumeRequest` in a **helper taking only the serialised bytes**, so the calling scope's variables
    are unreachable
  - answer with what the scripted client would have produced
  - `ResumeStep` to completion
- **Assert** Run B's result is deep-equal to Run A's: `Messages`, `Outcome`, `Handoff`.

**2. Exclude only what must differ, and list each with its reason.** Candidates: the changed-file note (use
identical files so there is none), any timestamp that leaks into the transcript, and the compaction summary's cost
in variant two — Run A did not pay for a summary.

**Every exclusion is a hole in the assertion.** Keep the list as short as the design allows, and **`Messages`,
`Outcome` and `Handoff` may not be excluded** — excluding any of them voids the test.

**3. Variant two** scripts enough tool output to trigger compaction in **both** runs, so the summary happens on
both sides and the transcripts stay comparable.

**4. Variant three** emits a `question` at two different turns and additionally asserts the step exhausts
`MaxIterations` at the **original** bound rather than a multiple of it.

**5. A header comment** stating this is the slice's keystone and what its failure means: that a resumed step
differs from an unsuspended one in a way no other test can localise.
