## Goal

`aeon proposal commit <id>` on an `agent_import` row re-reads the package from disk and runs **the exact body `aeon agent import` runs** — one extracted function, two callers. On success the agent is imported `disabled`, carried denials stored, fresh consent printed, row flipped to `committed`. On any refusal the row stays `proposed` with `applied_error` set.

## Notes

**Built.** The commit dispatch for `agent_import` is one `case` in `cmd/aeon/proposal.go`'s effect door calling the ONE extracted body `importAgentPackage` (agent.go), which both `aeon agent import` and `aeon proposal commit` end at (AD4). No second import, no direct `recordImport`/`Register`/store insert, no preview-as-gate.

**The extraction (AD4).** `cmdAgentImport` is now arg-check + `return importAgentPackage(w, args[0])`; the body moved verbatim, the only edit inside being `args[0]`→`pkgPath`. The existing `cmd/aeon` agent/import/consent/reimport suite passes untouched (full `cmd/aeon` package green — see validation), which is the proof the move is byte-identical.

**The case.** `case "agent_import"` decodes `{"pkgPath":…}`, refuses a stored path that is not absolute (`strings.Contains(…, "://") || filepath.IsAbs(…)` — the same rule the create half enforces, AD2/AA3), then `return importAgentPackage(w, p.PkgPath)`. A returned error rides S35's existing path (`SetProposalAppliedError` + row stays `proposed`, AD5); on `nil` the dispatcher flips the row exactly as for the other kinds. `effectAlreadyApplied`'s `agent_import` arm returns `false, nil` (Q14 — never "already applied"; see below).

**Q14 — the deliberate divergence from S35 TD4's idempotent recovery (step 3, for human approval).** S35's per-kind "effect already present → complete the lost flip" has no safe version for `agent_import`: a live `plugin_agent` row of that name may have come from the CLI, not the proposal, and there is no way to attribute it to a proposal. So the recovery detector reports *not applied* (`effectAlreadyApplied` → `false`), a re-commit after a lost flip re-runs the body, and the `plugin_agent_live` unique index refuses the second import with the existing text (`already has a live record`). The row stays `proposed`; the human runs `aeon proposal reject <id> --reason "imported by an earlier commit"`. The test asserts on the row's `applied_error` (the durable AD5 record), because the effect door returns the refusal as an `error` with empty output — it does not print a pretty line.

**Carried-denial store refusal (same as the CLI).** A carried denial the policy boundary refuses to store is PRINTED, not an error (as `aeon agent import` does today); the import still completes and the row still flips. An unstored denial is a hole somebody must see, never a silent success.

**Test-name / setup deviations from the design's list.** The seven tests are named `TestAgentImportCommit*` / `TestAgentImportCarriedDenial*` (coverage maps to the design's seven: happy-path+flip, refusal+row-stays-proposed, second-of-a-live-name refuses with the existing text, fresh-consent, the carried-denial store refusal, and the exactly-one-body grep). Two extra facts the design's list did not name are covered: a re-import after a revocation prints the AP4 "was REVOKED" notice, and a carried-denial store refusal prints and still flips. Tests 3 and 5 open the store through `openAgentStore` (NOT `proposalHome`): `proposalHome` re-runs `agentHome`, which resets `XDG_STATE_HOME` to a fresh temp dir, so the CLI import and the commit would hit different stores and the shared-store premise (the double-import refusal, the revoked-transition history) could not hold. `agentHome` is called once at the top; the handle keeps it.
