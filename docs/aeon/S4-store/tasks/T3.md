> Four tests pin the shape: the overlay adds `secure → complete` in `poc` and not in `standard`, the PR

> does not mutate the standard one.
>
> ### Enumerated, not listed
>
> `TestEveryPairAbsentFromAllowedTransitionsIsRefused` walks the cartesian product of 14 statuses — 196
> pairs minus self-transitions minus the table — and asserts a count floor of 100, so an enumeration that
> breaks and checks nothing fails rather than passes.
>
> `TestTheStatusLadderAndTheTableAgree` closes the loop both ways: every status in the ladder has a row, and
> every row and target is in the ladder. A status with no row can never move again.
>
> `TestTheShortestPathIsActuallyShortest` asserts the exact 7-step route from `pending` to `complete`. A BFS
> returning the first route found rather than the shortest would pass the walkability check and still send
> a caller the long way round.
>
> ### Two deviations
>
> **The tables are returned by functions, not exposed as package `var`s.** A caller holding the package's
> own map could mutate the machine for every other caller in the process, and the symptom would be a
> transition that is legal in one goroutine and not another. The cost is an allocation per call, on a path
> that runs once per task status change.
>
> **`machine.go` has no imports at all**, including `strings` and `strconv` — `quote` and `joinStatuses` are
> four lines each. `TestMachineGoHasNoImports` parses the file and asserts it, because the temptation to
> import `strings` for one `Join` is constant and the pure table is what lets two packages read it without
> either owning the other.
>
> ### Coverage
>
> `ValidateTransition` is exercised over invalid, empty and unknown input; an unknown `from` is REPORTED
> rather than panicked over, because a store reading a status no build understands should say so.

## Context

Pure, table-driven, and encoding experience rather than design. `ALLOWED_TRANSITIONS` is not something anyone
reasoned out from first principles — it is the accumulated record of which task-status moves turned out to be
legal in practice, and `POC_TRANSITION_OVERRIDES` exists because one loop mode needed to bypass some of them.
**Port it; re-deriving it would discard what was learned.**

`Caps` is published as **data** because `08-loop-decide` reads the same table. Two copies of a cap eventually
disagree, and the disagreement presents as a loop stopping for no visible reason.

**No dependencies**, so it can run concurrently with T1 and T2.

**Read first:** `packages/loop-state-mcp/src/validation.ts` in full — `ALLOWED_TRANSITIONS`, `TASK_STATUS`,
`LOOP_PHASE`, `TRACKED_PHASES`, `PHASE_STATUS`, `CAPS`, `LOOP_MODE`, `POC_TRANSITION_OVERRIDES`,
`validateTransition`, `shortestStatusPath`, `transitionsFor`. The plan's Q5.

## What to do

**1. `machine.go`**, porting v1's exports and **keeping the names** — later slices' specs were written against
them, and renaming would mean amending reviewed work for no gain.

Tables as package-level `var` maps or slices with derived types, so the type comes from the data rather than
being declared alongside it. A separately declared set of constants drifts from the table; a derived one cannot.

**2. `ValidateTransition(from, to, mode)`** returns a **result, never an error** (DB19). A refusal **names both
states** and, where v1 supplies one, the shortest legal path — which turns "transition refused" into "you need
to go through `in_progress` first", the difference between an error a caller can act on and one it can only log.

**3. `POC_TRANSITION_OVERRIDES`** — port it if Q5 found it still needed. If dropped, **say so in this task's
notes with the reason**: a silently dropped override reappears as a loop mode that suddenly cannot advance.

**4. Tests enumerated from the tables**, not listed:

- every pair **in** `AllowedTransitions` is accepted
- every pair in the **cartesian product** of `TaskStatus × TaskStatus` **not** in the table is refused

Enumerating is what stops the test drifting from the table it tests. A hand-written list passes forever after
somebody adds a transition.

**5. Assert `Caps` against v1's values, quoted in the test file.** This is a port; the test should fail if a
number changed by accident.
