# T9 — `documents.go`, `archive.go`

> ## Notes — done 2026-10-15
>
> ### Eleven refusals, each by attempt
>
> D14 asks for five; there are eleven cases, because the shapes differ: absolute POSIX, a Windows drive
> path, `..` at the start, `..` in the middle (`tasks/../../escape.md`), a directory outside the allowed
> set, nesting two deep, a bad extension, NO extension, empty, whitespace-only, and a NUL byte.
>
> Each asserts three things: the write was refused, the refusal carries the RIGHT reason, and **no document
> exists afterwards** — because the failure mode being ruled out is a refusal that silently became a write
> somewhere else.
>
> ### The check runs on the raw input, and there is a test for the specific trap
>
> `TestTheCheckRunsOnTheRawInputBeforeNormalisation` uses `tasks/../plan.md`, which CLEANS to `plan.md` —
> a legal name. A path cleaned first and checked second would pass every check and write, making the
> traversal attempt succeed at a different target. Nothing in `ResolveDocumentName` cleans, joins or
> normalises: the returned name is assembled from segments that were each checked.
>
> Backslashes are treated as separators as well as slashes, so a Windows-shaped path cannot smuggle a
> segment past a check that only splits on `/`.
>
> ### Deviation: a refusal is a string enum, not a boolean
>
> `DocumentRefusal` has seven values, so the CLI can render each differently and a caller can branch on the
> reason. The alternative — one `ok bool` plus a message — makes "which rule did I break" a string-matching
> exercise for every consumer.
>
> ### `Unchanged` is a third outcome
>
> A write whose sha matches the head is DROPPED rather than stored twice (v1's behaviour), and reported as
> `Unchanged` rather than as a plain success: a caller that believed it created a revision would show a
> history with a duplicate in it. `plan.md` is rewritten on a task split and again for QA-fix tasks, so this
> is the common case rather than an edge.
>
> ### The digest is verified on READ
>
> `sha256` covers the RAW bytes, matching `loop_archive_file` so both stores verify the same way. A document
> whose content does not match its hash is corruption, and reporting it at the read is the only place
> anybody would notice.
>
> ### The archive's content is read BEFORE the transaction opens
>
> A loop with a hundred revisions would otherwise hold the single writer connection while it decompresses
> them, blocking every other write. The transaction holds only the inserts and the two deletes.
>
> `loop_document` is deleted explicitly rather than by cascade, because it has no foreign key to `loop` —
> v1 gave it none deliberately, since a document outlives the worktree its loop was created in.
>
> ### DB10, asserted by grep
>
> `TestOnlyOpenGoTouchesTheFilesystem` looks for `os.Create`, `os.WriteFile`, `os.MkdirAll`, `os.Remove`,
> `os.OpenFile` and `os.Rename` outside `open.go`. `store.go`'s `os.Stat` is allowed and named in the
> comment: reporting a file's size is not writing to it, and `db info` prints it.

## Context

The remaining ported tables, with one sharp edge: **document paths**.

`loop_document` holds the loop's documents — `prompt`, `discovery`, `plan`, `tasks/T1.md`. v1 accepts either a
friendly name from `KNOWN_FILES` (`plan` → `plan.md`) or a path under an allowed directory, where
`ALLOWED_DIRS = ['tasks','scratch']` and extensions are `.md`, `.jsonl`, `.txt`.

**That confinement is a security property, not a convenience.** A document name reaching this store **comes from
a model**, and an absolute path or a `..` segment must be **refused**, never normalised into range. A silent
clamp turns an escape attempt into a successful write somewhere unexpected — and it looks like the feature
working.

**The store writes no files** (DB10). v1's `loop_writeFile` also mirrored the document to
`{projectRoot}/.projects/loops/{slug}/`. That mirror is a separate module outside the store, and this slice does
not build it: the store is the source of truth, the mirror is disposable.

**Read first:** `packages/loop-state-mcp/src/loop-files.ts` for `KNOWN_FILES`, `ALLOWED_DIRS` and the extension
set; v1's `event`, `memory`, `loop_archive` and `loop_archive_file` DDL.

## What to do

**1. `documents.go`** — `WriteDocument`, `ReadDocument`, `ListDocuments`. Resolve a name through `KNOWN_FILES`
first, then as a path under `ALLOWED_DIRS`.

**Refuse — returning a discriminated result, not an error** (DB19) — for each of: an absolute path; any `..`
segment; a directory outside `ALLOWED_DIRS`; an extension outside the allowed set; an empty name. **One test per
reason, each proving refusal by attempt.**

Do the check on the **raw input** before any normalisation. A path cleaned first and checked second is a path
whose escape has already been resolved away.

**2. `archive.go`** — `ArchiveLoop` moves the loop and its documents into `loop_archive` and `loop_archive_file`
**in one transaction**, and `ReadArchive` reads them back. An archive that copies documents but leaves the loop
live, or the reverse, is a half state with no owner.

**3. Assert the store writes no files.** A test greps the slice's sources for `os.Create`, `os.WriteFile`,
`os.MkdirAll` and asserts none outside `open.go`, which legitimately creates the state directory.
