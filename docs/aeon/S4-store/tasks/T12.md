> **Four were code** — the last two found by the user, after the slice was reported done:
>
>   - **Routes still did not persist, and the Providers page still said so.** S3 shipped route management
>     with `persisted: false` and the app said *"persistence arrives with the store (S4)"*. **S4 shipped
>     without keeping that promise** — the same unkept-promise shape T8 fixed for S2's `seq`, and I missed
>     it here. Migration `0007_route` adds the table; `MutableRoutes` gains a write-through seam
>     (`RoutePersistence`, implemented in `internal/daemon` over the store and `internal/secrets`); the
>     Providers page now says the truth in BOTH directions; and `aeon routes list|set|delete` exists so the
>     question "is my configuration saved" can be answered without opening a window.
>
>     **The credential does not go in the database.** C17 is one rule for the whole product — the
>     environment, or a dedicated file path, never a config file — so a route's key is written to
>     `$STATE/aeon/credentials/<id>.key`, 0600, in the 0700 state directory, by the same package that
>     already holds the cursor signing key. That also means **S14 can encrypt a file without a migration
>     over a live store full of secrets.** Guarded three ways: a test reads the database's **raw bytes** and
>     fails if a key appears; a test refuses any `route` column whose name parts include `key`, `secret`,
>     `token`, `password`, `credential` or `auth`; and the integration test walks the whole state directory
>     after a restart, asserting the secret is in `credentials/` at 0600 and nowhere else.
>
>     `--api-key-file` and deliberately no `--api-key`: a value in `argv` is in the process list and in
>     shell history, and that failure is silent (C17, S19's O1).
>
>   - **`store.info` sent `"pending": null`, and the tab went blank** (below).
>
> **And three from the walk itself:**
>
>   - **`store.info` sent `"pending": null`, and the tab went blank** — detail: Go marshals a nil slice as `null`,
>     and `pending` is empty on every healthy store — so it was `null` **every time**, and the page crashed
>     on `info.pending.length`. React unmounts on a render throw, so the reason reached the console and the
>     person reached an empty window.
>
>     **My fixture is why no test caught it.** The conformance fixture said `"pending": []` and the UI test
>     used the same shape — a shape nothing produced. A hand-written fixture asserts what somebody BELIEVED
>     the shape was. Four changes came out of it: every collection is normalised **in the handler** (the last
>     gate, so no `Memory` implementation can leak one), `TestNoStoreMethodEverSendsNullForACollection`
>     marshals each handler's real output through `Dispatch` and fails on `null`, the UI's shared fixture now
>     carries `pending: null` so the whole suite guards it, and `TabBoundary` wraps every tab so a render
>     error **shows its message** instead of blanking the window. Each was verified by removing the fix and
>     watching the test fail.
>
> **Two more were code**, both found in the walk itself:

>   - `db query awaiting` printed its explanation only when loops WERE awaiting, and the explanation is

## Context

The store is the one component whose failures are **invisible from where they happen**. A wrong migration, a lost
`thinking` signature or a stale derived answer all present somewhere else — a replay rejected in S7, a loop the
app shows as running that is actually waiting. So a human needs a procedure for looking directly at the file.

**This task also has an obligation to another slice.** S2's demo tells the reader that `seq` resets on restart,
because at S2 it did. T8 changed that. **If S2's demo still says it, the two documents now contradict each
other**, and a reader trusts whichever they find first. Updating it is a deliverable here, and this task's notes
must confirm both demos agree.

**When a step does not match, record which was wrong.** Editing the demo is faster than fixing the code and is
therefore the default; a demo silently adjusted to match a bug is worse than none.

**Read first:** `DEMO.md` in full; `docs/aeon/S2-protocol/DEMO.md` step 8; `docs/test_suites/aeon-store.md` as it
stands, which was written for TypeScript.
