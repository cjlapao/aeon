# T2 · `tools.grants {agent}`: what the agent may use, already decided once

**Prefix:** TB · **Rules:** TB1, TB7 (the buckets are the product) · **Depends on:** T1 (shares the roster
read for the unknown-agent error's name list).

## Reality finding — design.md §2.2's four buckets do not exist; `GrantView` does, and is better

Verified this session: `internal/mcp/grants.go`'s `Registry.GrantView(agent string, ps []policy.Policy, at
time.Time) []GrantView` already joins *exactly* what this method needs — `Registry.ToolsFor(agent)` (every
tool the agent's config declares access to: core + its declared public + its private) evaluated against the
S11/S12 policy set — and returns, per tool:

```go
type GrantView struct {
    Qualified string
    Tier      Tier       // "core" | "public" | "private"
    State     GrantState // "available" | "unavailable" | "refused" | "ask"
    Reason    string     // populated for everything except a clean "available"
}
```

This is **not** the brief's imagined `declared / granted / registered_ungranted / unregistered` four
buckets — it is a richer, already-correct, already-tested answer to the same question ("what may this agent
use, and why"), built for exactly this purpose by S12 (`GrantView`'s own doc comment: "for listing and for
revocation-visibility"). Re-deriving the brief's four buckets from scratch would be a **second
implementation of the double gate** (visibility × authority) that S36's MD2 explicitly refuses to do even
once, let alone twice. **Ship `GrantView`'s real shape.** TB7 ("the four buckets are the product") still
holds in spirit — the *distinction between states* is the product — it is just four states, not four
buckets of tool names, and "registered not granted" reads as one `GrantUnavailable`/`GrantRefused` row with
its `Reason`, not a second list.

Write this finding into `../design.md` §2.2 and §TB7 in this task's commit — replace the fabricated JSON
with the real `GrantView` array shape, and reword TB7's "four buckets" language to "four states" so T6 is
not written against a shape that was never real.

agent's name; an unknown agent is a method-level error naming the valid roster (test map #4), not an
empty/zeroed list.
