# T3 · `mcp.status`: the config truth, as it really loads

**Prefix:** TB · **Rules:** TB1, TB2, MC11 · **Depends on:** nothing daemon-side — parallel-safe with T1/T2/T5.
**Introduces the seam T4 extends.**

## Reality finding — config load is all-or-nothing; there is no per-server "refused" field

Verified this session (`internal/mcp/config.go`): `LoadConfigFile` → `parseConfig` → `Config.Validate()`
returns **one error for the whole file**, or none. There is no partial load where some servers succeed and
others carry a `refused` string — `Validate()` walks every server and every tool and returns the FIRST
problem found; a config with one bad server does not load at all. Design.md §2.3's example (a `github`
server with `"refused": null` beside a `scratch` server with `"refused": "not on the loopback tier…"` in the
*same* successful response) **cannot happen** with the real loader.

The real three states, which `mcp.status` must actually render (this supersedes MC11's two-state framing in
the brief — there is a third):

1. **Absent** — `errors.Is(err, mcp.ErrNoConfig)`: `{"present": false, "configPath": "<path tried>"}`.
2. **Present and valid** — the ordinary case: `{"present": true, "configPath": "…", "servers": [...]}`.
3. **Present and broken** — the file exists but `Validate()` (or the JSON decode) refused it:
   `{"present": true, "configPath": "…", "loadError": "<Validate()'s message verbatim>"}`, no `servers`
   key at all (there is no partial `Config` to report from — `parseConfig` returns `Config{}, err`).

Write this into `../design.md` §2.3 in this task's commit, replacing the per-server `refused` field with
this three-state shape. **`refused` as a per-*tool* concept still exists** (an unclassified tool is refused
at call time — that is T2's/S12's territory, GrantView's `refused` state) — this finding is specifically
about `mcp.status` having no per-*server* partial refusal, which is a different claim.

There is also no `tier: "trusted"/"untrusted"` field on a server in the real config — `Tier` (`core` /
`public` / `private`, `internal/mcp/registry.go:21-23`) is a *derived* fact (which list the server sits in),
not a stored one. Derive it: a server in `Config.Public` is `"public"`; a server in some agent's
`AgentConfig.Private` is `"private"` (and belongs to exactly that one agent — MC2). `declared_by`: for a
public server, every agent whose `Declares` contains a qualified name with that server's namespace prefix
(`strings.HasPrefix(d, server.Name+".")`); for a private server, the single agent it is private to.

## Goal

dispatched by method name — not one field per method), because `internal/protocol` must never import
`internal/mcp` (`internal/mcp/absent_test.go`'s banned list names `internal/protocol` explicitly —
`VERIFY: grep -n '"github.com/cjlapao/aeon/internal/protocol"' internal/mcp/absent_test.go`). `mcp.status`
is the first method dispatched through it; T4 adds the second (`mcp.check`) to the same seam rather than
inventing a sibling.

## Probe cache stub (T4 fills it in)

T3 does not probe anything — it only needs `probes` to be a legitimate, renderable field. Define the cache
type now so T4 has somewhere to write:

```go
type probeResult struct {
    OK        bool   `json:"ok"`
    Tools     int    `json:"tools,omitempty"`
    Error     string `json:"error,omitempty"`
    Ms        int64  `json:"ms"`
    CheckedAt string `json:"checkedAt"` // RFC3339; empty means "not checked" — render that, not a zero time
}
```
Held where `mcpHandleFor`'s closure can reach it (a small mutex-guarded map in `cmd/aeon/mcp_services.go`,
keyed by server name, empty at daemon start — "restarting the daemon returns not checked, never a stale
lie," brief §5). `mcp.status` reads it; it stays empty until T4's `mcp.check` writes to it. Do not pre-seed
it with a fake "not checked yet" entry per known server — an **absent** key already means not-checked; a
present key with `CheckedAt: ""` would be a second way to say the same thing (TB2's "no invented zeros," one
spelling per fact).
