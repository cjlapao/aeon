# T1 · `agent.list`: the roster, as identity

**Prefix:** TB · **Rules:** TB1 (one door per fact) · TB2 (three states, no invented zeros) · **Depends on:**
nothing — parallel-safe with T3, T5. **Answers plan.md's Q2.**

## Goal

A new read-only socket method, `agent.list`, exposes the agent roster — first-party bodies and imported
plugins alike — with identity, provenance and state, over the exact same facts `aeon agent list
--provenance --all` already reads. No new domain logic: this task is exposure, proven by a fixture, not a
feature.

## Prerequisites — read the real vocabulary before writing the fixture

**Design.md's `state: "enabled" | "blocked" | "never_arrived"` is a guess written before this task read the
code. It does not match what exists.** Verified this session:

- `internal/store/plugin_state.go`'s `PluginAgentStates = []string{"disabled", "enabled", "revoked"}` — three
  states, none spelled `blocked` or `never_arrived`.
- `internal/plugin.Agent` (`internal/plugin/import.go:47-66`) has no `Capabilities` field either — the
  design's `"capabilities": ["code_review"]` is invented. First-party bodies come back from `plugin.Agents()`
  (`import.go:291`) as `{Name, FirstParty: true, State: "running"}` — a fourth state, `running`, that exists
  only for first-party bodies and is not in `PluginAgentStates` at all, because the store's CHECK governs
  imported rows only.

**Do not ship the design's vocabulary.** Read `internal/plugin/import.go` and `internal/store/plugin_state.go`
in full, enumerate the real states a reader can see (likely: `running` for first-party, `disabled` /
`enabled` / `revoked` for imported rows — confirm, don't assume there is a fourth "known but never checked
in" state; if there genuinely is no such state today, the fixture says so and the design note below is
corrected in the same commit, not silently worked around), and write the fixture from what the code actually
returns. The UI (T6) copies the fixture's words. If the real vocabulary has no `never_arrived` equivalent,
add a one-line amendment to `../design.md` §2.1 stating that plainly — do not invent a state to match a
sentence written before the code was read.

Also confirm: `VERIFY: grep -n 'func Agents()' internal/plugin/import.go` and `grep -n
'func.*PluginAgentsAll' internal/store/plugin_state.go` still match the signatures below (the code may have
moved since this was written).

## Steps

1. Read the real state vocabulary (*Prerequisites*) and write it down in this file's Notes before touching
   code — this is the task's actual investigation, not busywork.
2. Define the wire type in `agent_roster.go`:
   ```go
   type agentRosterEntry struct {
       Name       string `json:"name"`
       Provenance string `json:"provenance"` // "first_party" | "imported"
       State      string `json:"state"`      // the REAL vocabulary from step 1 — not design.md's guess
       Source     string `json:"source,omitempty"`
       ImportedAt string `json:"importedAt,omitempty"`
   }
   type agentListResult struct {
       Agents []agentRosterEntry `json:"agents"`
   }
   ```
   Drop `version`/`capabilities` from the design's sketch unless step 1 finds a real source for them — an
   invented field is a lie the fixture would then pin forever (TB2's spirit, applied to shape as well as
   state).
3. Write `agentRosterHandleFor` in `cmd/aeon/agent.go`: reject non-empty params exactly like
   `pluginsHandleFor` does (copy its validation block verbatim — same refusal wording convention); read
   `plugin.Agents()` for first-party entries (`Provenance: "first_party"`) and `st.PluginAgentsAll(true)`
   for imported ones (`Provenance: "imported"`); merge, sort by name, return `agentListResult`.
4. Write `handleAgentList` in `internal/protocol/agent_roster.go`: params must be empty (decode and reject
   on any key, same convention as `agentPluginsCall` — `VERIFY: grep -n 'takes no params' agent.go'`); call
   `t.AgentRoster`; `nil` seam → `ErrNotWired`-shaped refusal naming this task, not a panic (the "unwired is
   visible" rule every seam in this file follows).
5. Register the method and wire the seam (*Files*).
6. Write the fixture from a real run (see *Commands*), not from imagination — `grep -c` the response JSON
   against what `aeon agent list --provenance --all` prints for the same store to catch a drift between the
   two doors (TB10's comparison mandate, checked here even though TB10 itself is a T6/T7 UI rule).
