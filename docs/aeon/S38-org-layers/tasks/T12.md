# T12 · Contract enforcement: missingRecord, the prompt block, the nudge

**Prefix:** OL · **Rules:** OL5 · OL6 · criteria 3, 12 · **Depends on:** T10, T11

## Goal

Make `emits:` real at run time: a model step whose lane declares a contract does not complete `ok` until the records exist, the step prompt tells the agent what it must also create, and the refusal names the record and the call to make.

## Prerequisites

T11 merged. Read `internal/loop/advance.go:270-300` (the `missingArtifact` branch), `:~395-446` (`modelPrompt`), `continue.go:~60-110`, and `store.Step` (to find the step id on `ModelResult`). Check: `go test ./internal/loop/ -count=1` green.

## Steps

1. **Counting readers (store):** `func (s *Store) CountRecordsByStep(kind string, stepID int64) (int, error)` for kind ∈ goal|epic|brief|task (`SELECT COUNT(*) FROM <table> WHERE source_step = ?`), and `func (s *Store) StepAttachments(stepID int64) ([]string, error)` (documents attached by that step: `SELECT document FROM attachment WHERE step_id = ?`).
2. **Interface in `loop`:**
   ```go
   type RecordsReader interface {
       CountByStep(kind string, stepID int64) (int, error)
       AttachedByStep(stepID int64) ([]string, error)
   }
   ```
   Add `Records RecordsReader` to `Deps`; nil means "no contract can be checked" and a step that declares `emits` then **blocks with reason `contract-unverifiable`** (never silently passes — P31).
3. **Pure helper (`contract.go`):**
   ```go
   func missingRecord(dep Deps, step blueprint.Step, stepID int64) string  // "" when satisfied; else the sentence
   ```
   For each `Emit`: `n := CountByStep(emit.Type, stepID)`; `min := max(emit.Min,1)`; if `n < min` → sentence `lane step must create %d %s record(s), found %d — call %s` with the catalog tool name from the same map T11 uses (export the type→tool map from `blueprint` as `blueprint.EmitTool(type)`; do not duplicate it). For each `Attach` path: if not in `AttachedByStep` → `… attach %s to the %s with `attach``. Join multiple problems with `; `.
4. **advance.go:274-279:** after the `missingArtifact` branch add
   `if outcome == "ok" { if why := missingRecord(dep, *action.Step, result.StepID); why != "" { outcome = "reject"; reason = "declared record was not created: " + why } }`. Same in `continue.go` next to its copy of the artifact check. (Rejection routes exactly like a missing artifact: rework via `on_reject`, or block.)
5. **Prompt block** in `modelPrompt`, after the produces sentence: if `len(step.Emits) > 0`, append a paragraph built by `contractPrompt(step.Emits)`: *"This step is not complete until these records exist (they are separate from the files): …"* listing each as `<tool>(…)` plus the attach instruction. Keep it one short paragraph; add a golden-text test.
6. **The in-step steer nudge is NOT in this task** unless T0-Q4 said the runtime can hold a finished turn open: if it did, add the follow-up paragraph from `design.md` OL6 as a separate commit; otherwise record in Notes that rejection-and-rework is the contract path.
7. **Wire** `Records` in `daemon/blueprint.go` with a small adapter over `store.CountRecordsByStep` / `StepAttachments`.

## Notes (2026-10-27)

* **The steer nudge (T0-Q4) was NOT feasible — recorded, step 6 honoured.**
  The runtime treats a finished turn as finished: suspension is EXITING (P2)
  and there is no door that holds a finished step open for a follow-up
  paragraph (the S31 steers land at step boundaries, never inside a
  completed turn). So **rejection-and-rework is the contract path**, exactly
  as the task anticipated; no follow-up paragraph was added, and the design
  half rides with S39's chat work if it ever needs one.
* **The contract has one renderer:** `contractRejection` (contract.go) is the
  single source of `declared record was not created:` — grep measured **1**
  occurrence outside tests; advance.go and continue.go both route through it,
  so the two doors cannot drift into two truths.
* **The third state blocks, in both directions:** reader unwired + `emits:` →
  `BlockedReason{Kind: contract-unverifiable}` (never silently ok); and a
  reader that ERRORS refuses as "could not be read … never waved through",
  not as "absent, so reject forever". Both tested.
* **The counting doors** (store/records_counts.go): `CountRecordsByStep` over
  a closed table whitelist (the BumpTaskCounter argument) — an unknown kind
  NAMES the closed set rather than reading as zero (a typo'd entity would
  else reject a good step forever) — and `StepAttachments` (documents pinned
  by that step, drained then returned, single-connection safe). Reader pool
  for both (O6). Both named in the surface table.
* **Measured traps on the way:** (1) the loop's own load gate (T11's) caught
  the test lane before the runtime could — `agent: default` is refused
  `emits-tool-missing` at LOAD, so the witness is the REAL `proposal-author`
  (granted `goal_create` and `attach` in its body; attach is a produced
  file, because validation refuses a pointer to nobody's file — the gates
  agreeing with each other is the design working); (2) `LoopState.Position`
  lives in the embedded `RuntimeState` — a composite literal may not name
  promoted fields; (3) the artifact door runs FIRST, so the contract tests
  write all their `produces` files and leave the RECORDS as the only gap —
  otherwise they test the wrong door and pass for the wrong reason; (4) one
  suspension belongs to one step — the blocked-reject does not re-suspend,
  so the second resume-door case needed a fresh loop.
* **Byte-identical proof:** every shipped blueprint step declares neither
  `emits:` nor `decides:` (asserted per step — the test owns the claim, and
  fails the day a shipped file grows one), `contractPrompt` is empty for
  them, and a file-only loop with the reader unwired runs the same event
  sequence as before.
