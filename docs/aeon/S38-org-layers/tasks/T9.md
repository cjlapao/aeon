## Steps

1. **Spec (pure):**
   ```go
   package records
   type Spec struct {
       Name        string          // tool name, snake_case: "goal_create"
       Method      string          // socket twin: "goal.create"
       Family      string          // project|component|epic|goal|brief|attachment|loop|task
       Description string          // >= 40 chars (the registry test enforces it)
       Schema      json.RawMessage // JSON schema, "additionalProperties": false
       Class       string          // "safe" | "detectable"  (never "unsafe")
       Mutates     bool
   }
   func Catalog() []Spec
   ```
2. **Catalog (this task's names; T10 adds the task family; T0-Q9 may adjust the list):**
   `project_list, project_show, project_create, project_update, component_list, component_show, component_create, component_update, epic_list, epic_show, epic_create, epic_update, goal_list, goal_show, goal_create, goal_update, goal_submit_review, brief_show, brief_create, attach, attachments_list, loop_list, loop_get`.
   Reads are `Class: "safe"`; writes `Class: "detectable"`. **Forbidden names** (a test fails on them): any name containing `decide`, `accept`, `approve`, `trigger`, `policy`, `mcp`, `proposal`.
   Schemas (hand-written JSON): `goal_create` = `{title (req), type (req enum bug|feature|chore|refactor|investigation), body_note?, epic_id?, document?, components:[{component (req: id or name in this project), rationale?, estimate_usd?, confidence? enum low|medium|high, basis?[]}] (req, minItems 1)}`; `brief_create` = `{goal_id?, scope (req), out_of_scope?, acceptance_criteria?[], constraints?[], test_plan?, document?}`; `attach` = `{subject: {kind enum goal|brief|epic|task, id (req)}, document (req)}`; `component_create` = `{name, root, project_id?, short_description?, description?}`; others follow the store types from T2/T6.
3. **Service (`daemon/records.go`):**
   ```go
   type Actor struct{ Kind, ID string }          // "agent"/handler name, or "user"/peer id
   type Failure struct{ Sentence string }          // a domain refusal — never a Go error
   type Identity struct{ StepID int64; Agent, LoopSlug, ComponentRoot, ComponentID, ProjectID string }
   type RecordsService struct{ store *store.Store }
   func NewRecordsService(st *store.Store) *RecordsService
   func (r *RecordsService) Identify(ctx context.Context) (Identity, *Failure)     // stepctx.StepID(ctx) → store.ReadStep → ComponentForRoot
   func (r *RecordsService) Do(ctx context.Context, by Actor, name string, input json.RawMessage) (any, *Failure, error)
   func (r *RecordsService) Invoker() tools.RecordsInvoker  // Identify, Do as agent, marshal result as indented JSON text; Failure → isError=true with the sentence
   ```
   One `switch name` in `Do` calling small per-action methods; each decodes into a typed struct with `json.Decoder.DisallowUnknownFields()`.
4. **Identity rules (the security core — write the tests first):** loop, component, step, agent and `created_by` come from `Identify`, **never from `input`**. `goal_create` sets `ProjectID=ident.ProjectID`, `SourceKind` = `brainstorm` when the loop's blueprint id is `brainstorm` else `manual`, `SourceLoop=ident.LoopSlug`, `SourceStep=&ident.StepID`, `CreatedBy={agent, ident.Agent}`, state `in_review` (call `CreateGoal` with `Submit:true`). Each `components[].component` must resolve (by id, else by exact name) to a component whose `project_id == ident.ProjectID`, else `Failure{"component %q is not in this project"}`. `brief_create` uses `Scope{ident.LoopSlug, ident.ComponentRoot}` and `Version` from the store. `attach` uses the loop's own `Scope`; refusing a `subject` that does not belong to this project/loop.
5. **`document:` shorthand** on `goal_create`/`brief_create` = create the record, then `Attach` that document in the same call; the result lists the attachment and its pinned rev.
6. **Tools projection (`tools/records_tools.go`):**
   ```go
   func recordTools() map[string]Tool {
       out := map[string]Tool{}
       for _, sp := range records.Catalog() {
           sp := sp
           out[sp.Name] = Tool{
               Class: RerunClass(sp.Class),
               Spec:  model.ToolSpec{Name: sp.Name, Description: sp.Description, Parameters: sp.Schema},
               Run: func(ctx context.Context, tc ToolContext, in json.RawMessage) Result {
                   content, isErr := recordsOrFail(tc)(ctx, sp.Name, in)
                   return Result{Content: content, IsError: isErr, Summary: sp.Name}
               },
           }
       }
       return out
   }
   ```
   In `Registry()` add `for k, v := range recordTools() { m[k] = v }` **before** the alias line. Convert `RerunClass` from the string constants in `class.go` (VERIFY their names).
7. **Wire it:** `daemon.New` builds `NewRecordsService(opts.Store)` and sets `runner.Records`.
8. **Registry pins (all six):** add each new name (sorted) to `want` in `TestRegistryExactNames` and the second copy at :149; raise the count in `class_test.go` (`len(entries) != 10` → the new total); add every name to `testdata/rerun_classes.json` (`"goal_create": {"class":"detectable"}`, reads `"safe"`); raise `skill_test.go:~154`. Above each changed list add `// 2026-10-27 (S38 T9): added the management catalog (<N> names) — <decision>; registry is now the honest <total>. Count 10 -> <total> DELIBERATE.` Fix the stale "honest ten" prose (toolset.go ~:87-100; toolset_test.go:215/227/246).

* **The catalog as finally filed (23 names):** `project_list · project_show ·
  project_create · project_update · component_list · component_show ·
  component_create · component_update · epic_list · epic_show · epic_create ·
  epic_update · goal_list · goal_show · goal_create · goal_update ·
  goal_submit_review · brief_show · brief_create · attach · attachments_list ·
  loop_list · loop_get`. Reads safe, writes detectable (none is unsafe — a row
  write spawns nothing); the registry is **the honest 33** (was 10), and the
  probe test holds the line the vocabulary cannot cross: no name contains
  decide/accept/approve/trigger/policy/mcp/proposal, and a WRITE schema that
  even names `project_id`/`loop_slug`/`created_by`/`author`/`source_step`/
  `agent` fails the catalog test — identity fields are not offered because
  they are not arguable (OL3).
* **The schema closes the door the decoder enforces:** `additionalProperties:
  false` everywhere plus `DisallowUnknownFields` means smuggling
  `"project_id":"prj-other"` into `goal_create` is a refusal *naming the
  smuggle*, not an ignored field. The stamped values are read through the
  chain step → loop → component_root → component → project, and every miss
  refuses with a sentence — a workspace no component registers has NO
  component, and the service says so rather than inventing one.
* **One measured surprise (mine):** `blueprint_id` is **not a loop column** —
  it lives on the `loop_blueprint` pin table (`blueprint.go`). My first
  `LoopBlueprintID` read `SELECT blueprint_id FROM loop` and would have run
  its wrong query forever; the store test's compile passed and the daemon
  test's brainstorm case caught it. The reader now joins the pin, and an
  un-pinned loop reads `ErrNotFound`, which the service honestly folds to
  `source_kind=manual` (only a loop PINNED to the brainstorm blueprint is a
  brainstorm goal).
* **DB19 applied at the read doors:** `goal_show`/`epic_show`/`component_show`
  answer a missing record with the Failure *sentence* (`refused: X is not a
  record the store has`), not the error channel — caught by the test that
  asked for a goal that is nobody and read `f == nil` as success.
* **The projection is a loop, not a map:** `recordTools()` iterates
  `records.Catalog()` — a hand-written copy would be a second catalog that
  somebody forgets to update — and `Do` gates every name through
  `catalogKnows` so the service and the tools can never disagree about what
  exists. `goal_update`'s `reason` rides the RESULT (the transcript is the
  review trail an edit leaves); `GoalEdit` itself stays reason-free because a
  review row belongs to a DECISION.
* **The six registry pins, all moved in one commit** (two `want` copies in
  `toolset_test.go`, `class_test.go`'s count, `testdata/rerun_classes.json`
  at 33 entries, `skill_test.go`'s listing count) — each carrying the
  `Count 10 -> 33 DELIBERATE` line. `DefaultGrant()` is still exactly
  `read, list, write` — pinned by `TestNoCatalogToolIsDefaultGranted`; and an
  ungranted `goal_create` never reaches the injected door
  (`TestUngrantedCatalogToolIsRefused`, which fails if the invoker is touched
  for an ungranted call).
