# T2 · Store Go layer: Component, Project, ComponentRoot
## Notes (2026-10-27 — built with T1–T4 as the plan-approved merge commit)

* **Two files, two tiers.** `store/components.go` (git mv from `projects.go`) is the workspace tier:
  `Component` gained `ProjectID/ShortDescription/Description/DefaultBranch/BranchPrefix`
  (`projectId` etc. on the wire); `CreateComponent` is ONE tx — workspace-dup guard
  (`SELECT component_id FROM component_root WHERE component_root=?`), implicit group INSERT when no
  group is named (id DERIVED `'prj-'||<component id>` — the 0035 backfill's shape, so the prefix is
  uniform across migration-made and runtime-made rows), the 16-column component INSERT, the primary
  root row. `store/projects.go` is the GROUP tier: `Project`, `NewProject`, `ProjectEdit` (+
  `ClearIcon`), `ProjectWrite{Project,Refusal,Reason}` with refusals `"" |name-empty|icon-both` —
  the DB19 discriminated result, the documents.go pattern; callers check `.OK()`.
* **Keep-semantics are the §4c discipline:** an empty name/description/icon on update KEEPS the
  existing value; only `ClearIcon` removes the icon, because an empty string cannot tell "unset" from
  "do not change". The `implicit` flag is never editable — it records how the row was born.
* **`UpsertComponent` makes the implicit group in its own tx** (`loops.go`): after 0035 a component
  without `project_id` is a schema error, and "component with no group" must never be one —
  same-tx, not a second door.
* **Moving a component between groups validates the destination** (`UPDATE` path checks the group
  EXISTS — a missing group is a refusal-style error, never a silent NULL); `TestMovingAComponent
  KeepsItsLoops` pins that loops ride the move untouched (they key on `(slug, component_root)`,
  not on the group).
* **Tests:** `components_test.go` (git mv) = the 3 legacy tests renamed + 5 new — implicit-group
  creation, named-group filing + missing-group refusal, the move, and
  `TestSameSlugTwoComponentsNoCrossRead` (two components, one slug, `ComponentScope{ComponentRoot}`
  isolation both ways).

## Steps

1. **Find every site:** `grep -rn "project_root\|ProjectRoot\|projectRoot\|ProjectScope\|\bproject\b" internal/store --include='*.go' | wc -l` (expect ≈270 with tests). Keep the list in Notes.
2. **Rename the exported Go identifiers with the tool, not by hand:** `gopls rename -w internal/store/scope.go:<line>:<col> ComponentRoot` for the `ProjectRoot` field (find the position with `grep -n ProjectRoot internal/store/scope.go`), same for `ProjectScope`, the `Project*` types and funcs in `projects.go`. If `gopls` is unavailable use `gofmt -r 'ProjectRoot -> ComponentRoot' -w` **per file listed above only** and fix compile errors.
3. **JSON tags:** every `json:"projectRoot"` in `internal/store` becomes `json:"componentRoot"`; the component's own `json:"root"` stays.
4. **SQL strings:** replace the column `project_root`→`component_root`; the tables `project`→`component` and `project_root`→`component_root` in `loops.go:298-313` and the former `projects.go:51,62,67,92,104,119,135` lines. The roots table's columns are now `(component_root PK, component_id, remote_key, repo_key, is_primary, added_at)`.
5. **New group type (`projects.go`):**
   ```go
   type Project struct { ID, Name, ShortDescription, Description, IconEmoji, IconImage string; Implicit bool; CreatedAt, UpdatedAt string }
   func (s *Store) CreateProject(in NewProject) (Project, error)   // explicit group; implicit=false
   func (s *Store) UpdateProject(in ProjectEdit) (Project, error)
   func (s *Store) ReadProject(id string) (Project, error)
   func (s *Store) ListProjects() ([]Project, error)               // ORDER BY updated_at DESC, id
   ```
   Refuse (domain result, DB19 — follow the `Refusal` pattern in `documents.go`) an icon with both fields set.
6. **`CreateComponent` creates its implicit project in the same transaction** unless `NewComponent.ProjectID` names an existing project; `Component` gains `ProjectID`, `ShortDescription`, `Description`, `DefaultBranch`, `BranchPrefix`. `UpdateComponent` may change `ProjectID` (move to another group); a component never has NULL `project_id` after this task.
7. Update every existing test with the same renames (`sed -i '' 's/ProjectRoot/ComponentRoot/g'` limited to `internal/store/*_test.go`), and update the **post-migration** assertions in the frozen-seed upgrade tests (the seed INSERTs target 0005 names and stay as they are).
8. The I4 guard test greps the package for a bare `loop_slug = ?` — if it matches strings you renamed, update the expected pattern, never loosen it.
