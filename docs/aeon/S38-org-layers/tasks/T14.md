## Steps

1. **`brainstorm.yaml`:**
   ```yaml
   id: brainstorm
   schemaVersion: 1
   version: 1
   output: [goal, proposal.md, brief.md]
   lanes:
     - id: capture
       step:
         kind: model-step
         agent: brainstormer
         produces: [proposal.md, brief.md]
         emits:
           - { type: goal, attach: [proposal.md, brief.md] }
   questions: {}
   ```
   (S39 adds `after: converse` and `converse:` later; do **not** add them here.)
2. **`goal-to-brief.yaml`:**
   ```yaml
   id: goal-to-brief
   schemaVersion: 1
   version: 1
   requires: [{ any_of: [{ type: goal, state: approved }] }]
   output: [brief, brief.md]
   lanes:
     - id: brief
       step:
         kind: model-step
         agent: brief-author
         produces: brief.md
         emits:
           - { type: brief, attach: [brief.md] }
     - id: brief-gate
       step: { kind: gate, question: approve-brief, decides: brief }
       on_reject:
         goto: brief
         with: { mode: revise }
         counter: brief_rounds
         max: 2
         then: escalate
   questions:
     approve-brief:
       prompt: Approve this brief and hand it to a planner?
       answers: [approve, revise, abort]
   ```
3. Append both names to `standardNames`. Run `TestShippedBlueprintsValidateInCI`; both must be 0 invalid (the handlers hold the tools from T10).
4. **brief-author body:** add a paragraph: *"When run by a blueprint that declares a brief contract, write `brief.md` in the workspace root, then call `brief_create` with the goal id from the loop's goal, and `attach` `brief.md`. A revision is another `brief_create` (it becomes the next version)."* VERIFY the body does not already instruct a different output path; if it does, say so in Notes and keep the instruction conditional on the loop having a goal.
5. **Gate join (`loop/answer_decides.go`):**
   ```go
   // DecideFromGate applies a gate answer to the entity the gate step decides. Idempotent: DecideBrief is claimed-FROM.
   func DecideFromGate(dep Deps, st LoopState, step blueprint.Step, answer string, by store.Actor) error
   ```
   Mapping for `decides: brief`: `approve`→`DecideBrief(sc, latestVersion, "approved", …)`; `abort`→`"rejected"`; `revise`→**no state change** (the brief lane will call `brief_create` again, producing the next version). For `decides: goal` use `DecideGoal` against `loop.goal_id/goal_version`. `by` is the answering user (peer identity already on the answer path — VERIFY name). Call it from the gate-answer handler **after** the answer is durably saved; because the decision is claimed-FROM, a crash-and-resume that re-runs it is harmless.
6. **Replay tests** use the existing replay model lane (see `internal/blueprint/dev-loop_test.go` for the pattern) with scripted tool calls: brainstorm: `write proposal.md`, `write brief.md`, `goal_create`, `attach` ×2; goal-to-brief: `write brief.md`, `brief_create`, `attach`, then answer `approve`.

## Notes (landed 2026-10-27, S38 T14)

**What shipped.** `brainstorm.yaml` and `goal-to-brief.yaml` verbatim from the
spec (with header comments), joined `standardNames` (now 10);
`internal/loop/answer_decides.go` — `DecideFromGate` joins a gate answer to
`DecideBrief`/`DecideGoal` ONLY (approve→approved, abort→rejected, anything
else — `revise` above all — changes no state: the lane files the next version
itself); wired from `AnswerBlueprintLoop` AFTER the answer is durable, with
the gate step captured before the answer advances the position. The answering
actor is `store.Actor{Kind:"user", ID:<OS username>}` — P26's one-user trust
makes the socket peer and the daemon process the same person; the
`socket-peer` fallback names the door, never a guessed identity.

**The bridge the spec could not know about (the deviation).** An agent lane
had NO way to make `attach` succeed: `write` files bytes on the workspace
disk; `attach` pins a `loop_document` ROW; the only writer of those rows was
the person-side `Memory.WriteDocument` door (and `tasks_manual` internally).
T12's attach half of the contract therefore could only ever reject a real
lane. T14 adds `pinWorkspaceDocument` in the records arms (attach +
brief_create's `document` param): when the named document has no row (or its
head pins different bytes) and the file EXISTS under the loop's component
root, the row is written from those bytes — through the one tools resolver,
1 MiB cap like the write tool, stamped with the calling agent. "An
attachment pins what exists, never a hope" is honoured literally: absent
file → the store's ordinary refusal. This is the smallest door that makes
criteria 2/3 walkable; a deliberate document-write tool for agents remains
open (recorded, not built).
