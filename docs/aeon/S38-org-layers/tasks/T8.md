# T8 · Tool plumbing: step identity and the records seam

**Prefix:** OL · **Rules:** OL3 · criteria 1, 10 · **Depends on:** T6, T7

## Goal

Give catalog tools what they need and nothing more: the step id in the call context, and an injected `Records` function on `ToolContext` that the daemon fills in. No `BuildTools` signature change, no store import in `internal/tools`.

## Prerequisites

T7 merged. Read first: `internal/tools/read.go` (ToolContext, Tool, Result), `internal/daemon/step.go:50` (StepRunner) and `:250` (BuildTools), `internal/runtime/loop.go` around the tool dispatch (grep `d.Tools.Call\|Caller.Call` — VERIFY the exact line), `internal/tools/toolset.go` (`Toolset.Call`).

## Files to create / modify

- NEW `aeon/internal/stepctx/stepctx.go` and `stepctx_test.go` — a tiny package (stdlib only) so `runtime`, `tools` and `daemon` can share a ctx key without import cycles.
- `aeon/internal/runtime/loop.go` — set the step id into the ctx **once**, immediately before the tool call.
- `aeon/internal/tools/read.go` — `ToolContext` gains `Records RecordsInvoker`; define the type there.
- `aeon/internal/tools/toolset.go` — **VERIFY** `Toolset.Call` passes `ctx` to `Tool.Run`; if it does not, make it.
- `aeon/internal/daemon/step.go` — `StepRunner` gains `Records tools.RecordsInvoker`; `BuildTools` copies it into `tc`.
- `aeon/internal/daemon/daemon.go` (~:204, the `runner = StepRunner{…}` literal) — leave `Records` nil for now (T9 wires it).

## Steps

1. **stepctx:**
   ```go
   package stepctx
   type key struct{}
   func WithStepID(ctx context.Context, id int64) context.Context { return context.WithValue(ctx, key{}, id) }
   func StepID(ctx context.Context) (int64, bool) { v, ok := ctx.Value(key{}).(int64); return v, ok && v > 0 }
   ```
2. **runtime:** at the dispatch site found by grep, `ctx = stepctx.WithStepID(ctx, st.Request.StepID)` (the field is `runtime/types.go:~351`). If `StepID` is 0 (ad-hoc step before the row exists) the ctx simply has no id — tools then fail closed.
3. **tools:**
   ```go
   // RecordsInvoker runs one catalog action for the step whose id is in ctx. content is the tool result text.
   type RecordsInvoker func(ctx context.Context, tool string, input json.RawMessage) (content string, isError bool)
   ```
   Add the field to `ToolContext`. A helper `func recordsOrFail(tc ToolContext) RecordsInvoker` returns a function that yields `("records are unavailable in this runtime", true)` when `tc.Records == nil` (storeless = fail closed, as `bash` does).
4. **daemon:** add the field to `StepRunner`; in `BuildTools` set `tc.Records = r.Records`. Do **not** change the method signature (four callers + three test fakes depend on it).
5. Tests below. Do not register any tool yet (T9).

## Notes (2026-10-27)

* **Verified before writing, all three VERIFY items:** the dispatch site is
  `runtime/loop.go:732` (`d.Tools.Call` — the comment there calls it the ONLY
  call site, G12, and it stayed the only stamping site too); `Toolset.Call`
  already hands the caller's ctx all the way to `tool.Run` (`toolset.go:302`
  → `runSafely` → `tool.Run(ctx, t.tc, input)`) — so it needed a PIN, not a
  fix; and `runtime/types.go` carries `StepRequest.StepID` (:379, server-side
  stamped).
* **stepctx exists because a context key unexported where it is used is
  unreachable where it is needed:** `runtime` sets, `tools` reads, `daemon`
  wires — any of them owning the key is an import cycle, so the smallest
  possible thing got its own stdlib-only package. Zero is not an identity:
  an ad-hoc step before its row exists reads as ABSENT and the tools that
  stamp provenance fail closed — pinned by `TestAdHocStepCarriesNoIdentity`.
* **`Records` is a function field, not a store**, for the same reason
  `CommandVerdict` is — the onion (the tools package must not know a store
  exists) — and nil fails CLOSED with the sentence "records are unavailable in
  this runtime": a storeless runtime never answers "no goals" from an injected
  nothing the model would file as fact (`TestRecordsAreUnavailableWhenUnwired`
  pins both halves).
* **No signature moved:** `BuildTools` is byte-identical (grep-pinned at
  step.go:358), the four callers and the test fakes untouched, `daemon.go`'s
  `runner = StepRunner{…}` leaves `Records` nil for T9 to wire, and no tool
  was registered — `TestRegistryExactNames` never noticed the commit.
* **The wiring pin reads an unexported field** (`toolCaller.set.tc.Records`)
  through `reflect` comparing FUNCTION POINTERS — `Interface()` panics on
  unexported, `Pointer()` does not, and comparing code pointers is exactly the
  question "did BuildTools copy the field", nothing more.
* **Measured:** 7 new tests (stepctx 2, runtime 2, tools 2, daemon 1);
  the four named packages green; full suite **2590 PASS / 0 FAIL**
  (2583 + 7); `make fmt`/`go vet ./...` green.
