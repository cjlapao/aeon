# T7 · Task store: loop tasks and manual tasks, one table

**Prefix:** OL · **Rules:** OL14 · criteria 4, 6 · **Depends on:** T5, T6

## Goal

Extend the task store for the two kinds of task: loop tasks (`manual=0`, owned by a loop, read-only to people) keep working unchanged; manual tasks (`manual=1`) can be created with no loop, typed, assigned, approved by a person, and linked to loops. Add the filtered read the board needs, with a floor-flagged cost.

## Prerequisites

T5 merged (new columns exist). Check: `go test ./internal/store/ -run Migration0036 -count=1` green and `go test ./internal/store/ -run Task -count=1` green on the OLD tests.

## Files to create / modify

- `aeon/internal/store/tasks.go` — `Task` gains `ID, Manual, AssigneeKind, Assignee, ComponentID, GoalID, ParentTaskID, Type, ApprovalState, CreatedByKind, CreatedByID, SourceStep`; json tags `id, manual, assigneeKind, assignee, componentId, goalId, parentTaskId, type, approvalState, createdByKind, createdById`; `CreateTask` keeps its signature and now writes `id`, `manual=0`, the owner `task_loop` row and `assignee`=`engineer`.

## Steps

1. Add the new columns to `Task`, `scanTask`, every `SELECT` list in `tasks.go` (`GetTask` :143, `ListTasks` :158) and `CreateTask`'s INSERT (:56) — an `id` of `"tsk-" + 8 random bytes hex` for loop tasks too. **Do not** change `Scope.Where` usage for loop tasks.
2. **Manual create:**
   ```go
   type NewManualTask struct{ ComponentID, Title, Type, Body string; AssigneeKind, Assignee string; GoalID, ParentTaskID *string; By Actor; RequireApproval bool }
   func (s *Store) CreateManualTask(in NewManualTask) (Task, *Refusal, error)
   // manual=1, loop_slug NULL, status 'pending', approval_state 'pending' when RequireApproval else 'none'; Type must be one of the five; ComponentID must exist.
   ```
3. **Read-only guard for loop tasks:** `UpdateManualTask(id string, edit ManualTaskEdit) (Task, *Refusal, error)` returns `Refusal{Kind:"loop-task-read-only", Sentence:"task X belongs to loop Y and is managed by its agent; it cannot be edited here"}` when `manual=0`. `SetTaskStatus` (the machine, loop-scoped) is **unchanged**; add `SetManualTaskStatus(id string, to TaskStatus) (SetTaskStatusResult, *Refusal, error)` that runs `ValidateTransition(from, to, ModeStandard)` for manual tasks.
4. **Approval (human only):** `DecideTask(id string, decision string, by Actor, reason string) (DecideResult, *Refusal, error)` — only `manual=1`, `by.Kind=='user'`, claimed-FROM `WHERE approval_state='pending'`; inserts a `review` row (`subject_kind='task'`). Decisions `approved|rejected`.
5. **Link a loop:** `LinkTaskToLoop(taskID string, sc Scope, role string) error` (`role` `worker` for a manual task); and parent rule: `CreateTask` may take `ParentTaskID`, which must name an existing task **in the same component** (store-enforced; there is no FK).
6. **The board read:**
   ```go
   type TaskFilter struct{ ProjectID, ComponentID string; Manual *bool; AssigneeKind, Assignee, Status, Type, GoalID, LoopSlug, ParentTaskID string; Limit int }
   type TaskRow struct{ Task; CostUSD float64; CostIsFloor bool; LoopSlugs []string }
   func (s *Store) ListTaskRows(f TaskFilter) ([]TaskRow, error)
   ```
   Cost group-by (loop tasks): `SELECT t.id, COALESCE(SUM(s.cost_usd),0), MAX(s.cost_state IN ('partial','unknown')) FROM task t LEFT JOIN step s ON s.component_root=t.component_root AND s.loop_slug=t.loop_slug AND s.taskid=t.taskid GROUP BY t.id`. `CostIsFloor` is true when any contributing step is `partial|unknown` (P32). A manual task's cost is the sum over its children (`parent_task_id = t.id`); same floor rule. Order: `updated_at DESC, id`; default `Limit` 200, max 1000.
7. **Pinned test:** `TestLoopTaskStatusPathIsUnchanged` replays the existing machine table over loop tasks (copy the cartesian-product style of `machine_test.go`).

## Notes (2026-10-27)

* **One table, two populations, one ladder** (OL14): `CreateTask` stayed the
  engine's door — same signature, same key, `SetTaskStatus` and the
  `(component_root, loop_slug, taskid)` semantics untouched — and gained only
  what 0036 made possible: a `tsk-` surrogate (generated exactly the way the
  migration's rebuild generated them), the derived `assignee_kind` (named
  engineer = agent, blank = NO assignee — never an anonymous agent), the
  owner `task_loop` row in the same transaction, and a `ParentTaskID` whose
  same-component rule the STORE enforces (the schema cannot: no FK across a
  rebuild, per 0036's own comment).
* **The refusal sentences are the feature:** `UpdateManualTask`/
  `SetManualTaskStatus` on a loop task answer `loop-task-read-only` naming the
  owning loop — the app shows the engine's tasks and never manages them;
  `DecideTask` refuses loop tasks (`loop-task-not-approvable`), refuses agents
  (`decider-not-human`), and refuses `parked` — a task is parked nowhere,
  approval is approved|rejected only.
* **Bodies are OL4's division applied to tasks:** the prose is a DOCUMENT the
  author owns; the task row keeps only the pointer. A manual task has no loop
  to borrow a document namespace from, so its body lives under the TASK's
  namespace (its surrogate id, in its component's primary root) — the body
  belongs to the task, not to whatever loop is later started on it. The
  write goes through `writeDocumentInTx`, the insert half of `WriteDocument`
  extracted so a body and its attachment row land in one transaction or
  neither.
* **Cost is computed, floor-flagged, never stored** (P32/OL11): loop tasks sum
  their `step` group-by; a manual task sums its CHILDREN's step costs (the
  *what* costs what its *how* cost); `CostIsFloor` lights when any contributing
  step is `partial|unknown` — an unknown cost is absent from the sum and
  SHOUTS about it, never silently zero.
* **The machine replay** (`TestLoopTaskStatusPathIsUnchanged`): every
  (from, to) pair of the ladder against `SetTaskStatus` on a loop task answers
  EXACTLY what `ValidateTransition` says — the columns did not bend the
  machine.
* **Caught on the way** (mine, all four): a 20-column INSERT with 19
  placeholders; the manual INSERT whose `created_at` slot got the `'pending'`
  literal; `taskColumns` needing `COALESCE` on `loop_slug/component_root/taskid`
  because manual tasks hold NULLs exactly where loop tasks hold their key
  (that NULL is the fact — the scan reading `''` is the honest rendering);
  and the board's loop filter rewritten as a JOIN through `loop` so the
  scope-composition guard sees a real loop behind every slug.
* **Measured:** 10 new tests (9 in `tasks_manual_test.go` + the replay), all
  87 task/manual test lines green including EVERY old task test unchanged;
  full suite **2583 PASS / 0 FAIL** (2573 + 10); `make fmt`/vet green.
