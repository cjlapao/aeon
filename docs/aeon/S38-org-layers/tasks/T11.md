## Steps

1. **Types:**
   ```go
   type Emit struct {
       Type   string `yaml:"type" json:"type"`                 // one of the catalog entities: goal|epic|brief|task
       Min    int    `yaml:"min,omitempty" json:"min,omitempty"` // default 1
       Attach Paths  `yaml:"attach,omitempty" json:"attach,omitempty"`
   }
   type Requirement struct{ AnyOf []RequirementTerm `yaml:"any_of" json:"anyOf"` }
   type RequirementTerm struct{ Type string `yaml:"type" json:"type"`; State string `yaml:"state" json:"state"` }
   ```
   Add to `Blueprint`: `Output []string `yaml:"output,omitempty" json:"output,omitempty"``; `Requires []Requirement `yaml:"requires,omitempty" json:"requires,omitempty"``. Add to `Step`: `Emits []Emit `yaml:"emits,omitempty" json:"emits,omitempty"``; `Decides string `yaml:"decides,omitempty" json:"decides,omitempty"``. (Unknown-key detection is automatic via tags — no loader change.)
2. **Validation** (`validateStep`, use the `add(state, kind, path, msg, slice)` closure; paths `lanes[<id>].step.emits[<i>].type`):
   - `emits` only on `model-step` → else `Invalid` kind `emits-needs-model-step`.
   - `emits[i].type` ∈ {goal, epic, brief, task} → else `Invalid` `emits-unknown-type`; `min >= 0`; each `attach` path must also appear in the same step's `produces` or be written by it (check membership in `Produces`; else `Invalid` `emits-attach-not-produced`).
   - **Handler check:** the emit type maps to a catalog tool (`goal→goal_create`, `epic→epic_create`, `brief→brief_create`, `task→task_create`); if `attach` is non-empty also needs `attach`. `opts.AgentTools(agent)` → tools list: tool missing → `Invalid` `emits-tool-missing` (message names the agent and the tool); agent has no body (`ok=false`) → `Unverifiable` `emits-agent-unverifiable` (P31, slice S13). `AgentTools == nil` → `Unverifiable` `emits-registry`.
   - `decides` only on `gate` steps and ∈ {goal, brief} → else `Invalid` `decides-unknown-or-misplaced`.
   - `requires[*].any_of[*]`: `type` ∈ {goal, task}; `state` ∈ {approved} for goal and ∈ {approved} for task (`approval_state`) → else `Invalid` `requires-unknown-type` / `requires-unknown-state`.
   - `output` entries: each is a catalog entity name or a file name; an entity must be emitted by some lane, a file must be in some step's `produces` or `attach` → else `Invalid` `output-unreachable`.
3. `handler.ToolsFor(name)`: read the allow-list from the same place `handler.Verify` uses (`registry.go` lookup); no new parsing.
4. Update production option literals; update `broken-fixture.yaml` with one bad `emits` and extend the `want` kind list in `TestBrokenFixtureReportsSeveralClassesAtOnce`.
5. **Do not touch any shipped blueprint yet** (T12/T14 do). The test below proves the unchanged set.

* **`requires` speaks a NARROWER vocabulary than `emits`:** goal|task only.
  An epic or a brief is context, not a precondition a run declares (OL8) —
  the spec line read `type ∈ {goal, task}` and the check honours it exactly.
  State is `approved` and nothing else: the prerequisite vocabulary is the
  PERSON'S verdict vocabulary, not the ladder's.

  `handler.ToolsFor` reads `Lookup` — the same entries dispatch builds from,
  so validation checks grants against what dispatch would actually hand the
  model. `fullGrant` stubs the positive cases; the NEGATIVE witness is the
  real `intent-clarifier` body (granted read/write/edit/todo — never
  `task_create`), and the refusal must name agent AND tool or it fails.
