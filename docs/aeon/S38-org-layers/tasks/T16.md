# T16 · CLI: aeon goal, brief and task verbs

**Prefix:** OL · **Rules:** OL10 · criterion 8 · **Depends on:** T15

## Goal

Add the terminal client for the surface (P34: the socket is primary, the CLI is a client): `aeon goal list|show|create|submit|decide`, `aeon brief show|decide`, `aeon task list|show|create`. Decisions go through the socket and are recorded as the terminal user.

## Prerequisites

T15 merged. Read `cmd/aeon/{client_verbs.go,store_verbs.go,routes_verbs.go,dial.go,main.go}` for the verb pattern (how a verb dials the socket, parses flags, prints). Check: `go test ./cmd/aeon/ -count=1` green.

## Files to create / modify

- NEW `aeon/cmd/aeon/{goal.go,brief.go,task.go}` and `*_test.go`; `main.go` verb table and help text.

## Steps

1. Copy the smallest existing client verb (VERIFY: `routes_verbs.go` or `client_verbs.go`) as the template: flags via the same helper, `dial.go` for the connection, output printed with the existing table/JSON helpers (`--json` flag if the pattern has one).
2. Verbs and flags: `aeon goal list [--project ID] [--state S]`, `goal show ID`, `goal create --project ID --title T --type TYPE --component C[,C…] [--body-file F]` (creates through `goal.create`; prints the id and `in_review`), `goal submit ID`, `goal decide ID --version N --decision approved|rejected|parked [--reason R]`; `brief show --loop SLUG [--component PATH]`, `brief decide --loop SLUG --version N --decision …`; `task list [filters]`, `task show ID`, `task create --component C --title T --type TYPE [--assignee user:NAME|agent:NAME]`.
3. `decide` verbs call the socket's `*.decide` — **no direct store access** (unlike `aeon policy`, which is store-direct by PL15; goal/brief/task decisions are P34 socket-first).
4. Help text: one line per verb in `main.go`.
5. Tests with the CLI fixture pattern (`cli_integration_test.go`): start a test daemon, run each verb, assert output and exit code.

## Notes (2026-10-27 — built)

* **The refusal table contradicted this task, and this task won.** T15's
  `personDoorRefusal` refused `goal_create`, `goal_submit_review`, `brief_show`
  and `task_create` to a person — a design extrapolation the T15 spec never
  asked for, and T16's spec asks for exactly those doors from the terminal.
  They are OPENED: each arm grew a person branch that takes the stamped half
  as said arguments (project, component, assignee kind) — the same store calls,
  the same refusals, no second rules. The refusal map shrank to eight.
* **P34 in-product:** the three verb files import `protocol` and nothing else —
  `grep -n "store\." cmd/aeon/{goal,brief,task}.go` answers nothing (the DoD),
  and `TestOrgVerbsNeverOpenTheStore` makes that a test, not a convention.
  Unlike `aeon policy`, which is store-direct by PL15.
* **Usage is exit 2, failure is exit 1.** A `decide` without `--version` is a
  thing not asked, not a thing that failed: `usageError` maps to 2 in `main` —
  the same 2 the argument checks above the dispatch have always used, so
  scripts can tell the two apart.
* **Scar:** the flag package stops parsing at the first positional, so
  `aeon goal decide ID --version 1 …` lost every flag behind the id. The
  leading id is now taken BEFORE Parse.
* **The walk's finding the spec could not have had:** `aeon loop create` runs a
  loop in a directory — it does NOT register a component (loops carry no FK),
  and NO CLI verb registers components at all; they arrive only through the
  socket's `component.create` (the app's door). The person's `task create`
  refuses an unregistered root BY NAME — correctly, and the test then seeds
  the component through the daemon's own store file (WAL serialises the second
  connection, the access path PL15 already sanctions for `aeon policy`;
  `internal/paths` puts the database under `$XDG_STATE_HOME/aeon`, and seeding
  the state home itself silently builds a private second database — measured,
  when the first seed appeared to vanish).
* **Slug ambiguity is a fact, not a hypothesis:** two components can run the
  same slug (`db_test`'s two `refactor` loops), so `personLoopScope` takes a
  `--component` root hint and `brief.decide` gained an additive optional
  `component` param (PROTOCOL_VERSION stays 2; no fixture carries the field, so
  contract.ts is unchanged). One resolver now serves `brief.show` and the brief
  decision method — never two resolvers disagreeing about what a slug means.
* **The grep guard fired on its own file a second time:** the `brief_show`
  comment spelled the brief decision method's dot-name and
  `TestDecideDoorsHaveExactlyTheDeclaredCallers` caught it. Comment reworded;
  the guard stays verbatim, tokens counted even in prose.
* **The kernel's stamp, end-to-end:** the CLI decide goes over a REAL socket,
  so the ledger row carries the TEST RUNNER'S OWN uid (3002 on this box) —
  `goal show` prints `user/3002` and the test asserts the shape. T15 pinned
  the rule with an injected 4321; this proves it outside the fake transport.
