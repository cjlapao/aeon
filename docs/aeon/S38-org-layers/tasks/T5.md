# T5 · Migration 0036: records tables, loop columns, task rebuild

## Notes (2026-10-27)

* **0036_records shipped as the task's SQL, with three additions the writing
  earned.** (1) The copy guard (`task_copy_guard` with `CHECK (moved = total)`,
  dropped after) makes row loss a FAILED MIGRATION, not a test failure —
  0035's CASCADE scar written into the schema itself. (2) The loop-key index is
  PARTIAL (`WHERE loop_slug IS NOT NULL`): manual tasks carry no loop key and
  SQLite lets NULLs conflict, but the index states plainly which population the
  uniqueness governs. (3) `assignee_kind` derives `CASE WHEN engineer <> ''
  THEN 'agent' END` + `NULLIF` — a blank engineer must not become an anonymous
  agent; the derivation is asserted (2 agent, 1 NULL from the seed).
* **The child census was a step, not an assumption**: `grep REFERENCES task`
  over schema.go returned nothing, so the rebuild needs no 0019-style parking.
  (If a future migration gives something an FK to task, 0035's lesson applies —
  check the CASCADE verb before the DROP.)
* **`parent_task_id` carries NO FK on purpose** (the DoD's Do-NOT): SQLite
  cannot self-reference a table during its own rebuild; the store enforces
  parent existence at T7.
* **brief's FK targets `loop (component_root, slug)`** — legal because the
  parent UNIQUE is declared in exactly that column order; a reversed FK
  (`slug, component_root`) would fail `foreign key mismatch` at INSERT, not at
  migration time. Worth knowing before T7's rewrite path.
* **loop gains `goal_id/goal_version/scope`** — scope defaults `component`
  (loops that predate the column were each one workspace's; `project` scope is
  S40's brainstorm shape).
* **Measured:** 6 new tests (`records_schema_test.go`) — the CHECKs proven by
  DIRECT SQL (the store API would never write a manual=0 + approval_state row;
  the FK-miss-wearing-CHECK's-clothes trap was defused by seeding the loop
  first so only the CHECK can answer). Full suite **2558 PASS / 0 FAIL**
  (2552 + 6), store green, `make fmt`/`guard` green. The fresh-vs-upgraded
  drift fingerprint test covers the seven new tables without new code.

## Steps

1. **New tables** (adjust column lists to T0-Q3's verdict; these are the design defaults). `source_step` columns record which step created the row (the identity the tools stamp):
   ```sql
   CREATE TABLE epic (id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES project(id), title TEXT NOT NULL,
     objective TEXT NOT NULL DEFAULT '', owner TEXT NOT NULL DEFAULT '', target_date TEXT, budget_usd REAL,
     source_step INTEGER, created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
   CREATE TABLE goal (id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES project(id), epic_id TEXT REFERENCES epic(id),
     version INTEGER NOT NULL DEFAULT 1, title TEXT NOT NULL, type TEXT NOT NULL CHECK (type IN ('bug','feature','chore','refactor','investigation')),
     body_note TEXT NOT NULL DEFAULT '', source_kind TEXT NOT NULL CHECK (source_kind IN ('manual','brainstorm','webhook','cron','event')),
     source_ref TEXT NOT NULL DEFAULT '', source_loop TEXT, source_step INTEGER,
     review_state TEXT NOT NULL DEFAULT 'draft' CHECK (review_state IN ('draft','in_review','approved','rejected','parked')),
     created_by_kind TEXT NOT NULL CHECK (created_by_kind IN ('user','agent','trigger')), created_by_id TEXT NOT NULL,
     created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
   CREATE TABLE goal_component (goal_id TEXT NOT NULL REFERENCES goal(id) ON DELETE CASCADE, goal_version INTEGER NOT NULL,
     component_id TEXT NOT NULL REFERENCES component(id), rationale TEXT NOT NULL DEFAULT '',
     estimate_usd REAL, confidence INTEGER CHECK (confidence IS NULL OR confidence IN (1,2,3)), basis TEXT NOT NULL DEFAULT '[]',
     PRIMARY KEY (goal_id, goal_version, component_id));
   CREATE TABLE brief (id TEXT PRIMARY KEY, loop_slug TEXT NOT NULL, component_root TEXT NOT NULL, goal_id TEXT, goal_version INTEGER,
     version INTEGER NOT NULL, scope TEXT NOT NULL DEFAULT '', out_of_scope TEXT NOT NULL DEFAULT '',
     acceptance TEXT NOT NULL DEFAULT '[]', constraints TEXT NOT NULL DEFAULT '[]', test_plan TEXT NOT NULL DEFAULT '',
     review_state TEXT NOT NULL DEFAULT 'in_review' CHECK (review_state IN ('draft','in_review','approved','rejected','parked')),
     source_step INTEGER, created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
     UNIQUE (component_root, loop_slug, version),
     FOREIGN KEY (component_root, loop_slug) REFERENCES loop (component_root, slug) ON DELETE CASCADE);
   CREATE TABLE review (id INTEGER PRIMARY KEY AUTOINCREMENT, subject_kind TEXT NOT NULL CHECK (subject_kind IN ('goal','brief','task')),
     subject_id TEXT NOT NULL, subject_version INTEGER NOT NULL,
     decision TEXT NOT NULL CHECK (decision IN ('approved','rejected','parked')),
     by_kind TEXT NOT NULL CHECK (by_kind = 'user'), by_id TEXT NOT NULL, reason TEXT NOT NULL DEFAULT '', decided_at TEXT NOT NULL);
   CREATE TABLE attachment (id INTEGER PRIMARY KEY AUTOINCREMENT, subject_kind TEXT NOT NULL CHECK (subject_kind IN ('goal','brief','epic','task')),
     subject_id TEXT NOT NULL, loop_slug TEXT NOT NULL, component_root TEXT NOT NULL, document TEXT NOT NULL, rev INTEGER NOT NULL,
     step_id INTEGER, created_at TEXT NOT NULL, UNIQUE (subject_kind, subject_id, document, rev));
   ```
   (`brief.UNIQUE` and `review.by_kind='user'` are the invariants the tests pin; `review` has **no** `agent`/`policy` value — widening is a later rebuild.)
2. **Loop columns:** `ALTER TABLE loop ADD COLUMN goal_id TEXT; ALTER TABLE loop ADD COLUMN goal_version INTEGER; ALTER TABLE loop ADD COLUMN scope TEXT NOT NULL DEFAULT 'component' CHECK (scope IN ('component','project'));`.
3. **Rebuild `task`.** First verify nothing references it: `SELECT m.name FROM sqlite_master m, pragma_foreign_key_list(m.name) f WHERE f."table"='task';` must return no rows; if it does, park those children per the 0019 pattern (schema.go:598-660). Use the 0016 shape (schema.go:371-405):
   ```sql
   CREATE TABLE task_new (
     id TEXT PRIMARY KEY, loop_slug TEXT, component_root TEXT, taskid TEXT,
     ord INTEGER NOT NULL DEFAULT 0, title TEXT NOT NULL, tech TEXT NOT NULL DEFAULT '', engineer TEXT NOT NULL DEFAULT '',
     depends_on TEXT NOT NULL DEFAULT '[]', status TEXT NOT NULL, issue TEXT, pr TEXT, branch TEXT,
     retries INTEGER NOT NULL DEFAULT 0, security_rounds INTEGER NOT NULL DEFAULT 0, review_rounds INTEGER NOT NULL DEFAULT 0,
     est_changed_lines INTEGER, success_summary TEXT, last_evidence TEXT, started_at TEXT, created_at TEXT, updated_at TEXT NOT NULL,
     manual INTEGER NOT NULL DEFAULT 0 CHECK (manual IN (0,1)),
     assignee_kind TEXT CHECK (assignee_kind IS NULL OR assignee_kind IN ('agent','user')), assignee TEXT,
     component_id TEXT REFERENCES component(id), goal_id TEXT, parent_task_id TEXT,
     type TEXT CHECK (type IS NULL OR type IN ('bug','feature','chore','refactor','investigation')),
     approval_state TEXT NOT NULL DEFAULT 'none' CHECK (approval_state IN ('none','pending','approved','rejected')),
     created_by_kind TEXT NOT NULL DEFAULT 'agent', created_by_id TEXT NOT NULL DEFAULT '', source_step INTEGER,
     CHECK (manual = 1 OR approval_state = 'none'),
     CHECK (manual = 1 OR loop_slug IS NOT NULL),
     FOREIGN KEY (component_root, loop_slug) REFERENCES loop (component_root, slug) ON DELETE CASCADE);
   INSERT INTO task_new (id, loop_slug, component_root, taskid, ord, title, tech, engineer, depends_on, status, issue, pr, branch,
       retries, security_rounds, review_rounds, est_changed_lines, success_summary, last_evidence, started_at, created_at, updated_at, assignee_kind, assignee)
     SELECT 'tsk-' || lower(hex(randomblob(8))), loop_slug, component_root, taskid, ord, title, tech, engineer, depends_on, status, issue, pr, branch,
       retries, security_rounds, review_rounds, est_changed_lines, success_summary, last_evidence, started_at, created_at, updated_at,
       CASE WHEN engineer <> '' THEN 'agent' END, NULLIF(engineer,'') FROM task;
   CREATE TABLE task_copy_guard (moved INTEGER NOT NULL, total INTEGER NOT NULL, CHECK (moved = total));
   INSERT INTO task_copy_guard SELECT (SELECT COUNT(*) FROM task_new), (SELECT COUNT(*) FROM task);
   DROP TABLE task_copy_guard;
   DROP TABLE task;
   ALTER TABLE task_new RENAME TO task;
   CREATE UNIQUE INDEX idx_task_loop_key ON task (component_root, loop_slug, taskid) WHERE loop_slug IS NOT NULL;
   CREATE INDEX idx_task_status ON task (status);
   CREATE INDEX idx_task_component ON task (component_id, manual);
   CREATE TABLE task_loop (task_id TEXT NOT NULL REFERENCES task(id) ON DELETE CASCADE, loop_slug TEXT NOT NULL, component_root TEXT NOT NULL,
     role TEXT NOT NULL CHECK (role IN ('owner','worker')), PRIMARY KEY (task_id, loop_slug, component_root),
     FOREIGN KEY (component_root, loop_slug) REFERENCES loop (component_root, slug) ON DELETE CASCADE);
   INSERT INTO task_loop SELECT id, loop_slug, component_root, 'owner' FROM task WHERE loop_slug IS NOT NULL;
   ```
   (`parent_task_id` deliberately has **no** FK: SQLite cannot self-reference during a rebuild; the store enforces it, T7.)
