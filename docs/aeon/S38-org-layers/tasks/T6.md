# T6 · Entity store functions: goal, epic, brief, review, attachment

## Notes (2026-10-27)

* **The version model, settled before code:** a goal is ONE row whose
  `version` bumps (0036's PK is `id` alone); history lives in `review` rows
  and in `goal_component`'s per-version sets. Callers address (goal_id,
  goal_version) coordinates and a superseded version KEEPS meaning — it names
  the goal as it was when it was judged. `UpdateGoal` claims the row at its
  current version (`WHERE id=? AND version=?`), so a concurrent bump makes
  the edit refuse (`goal-changed-underneath`) rather than clobber.
* **Claimed-FROM, twice:** `DecideGoal`/`DecideBrief` UPDATE only while the
  exact version still sits `in_review`; the loser gets `Changed=false` with
  State + WHO/WHEN read from the ledger — never a silent no, never an
  overwrite. Exactly one review row per decided version (pinned by reading the
  ledger back, not just the flag).
* **`by_kind` is the literal 'user' in the only INSERT** (`reviewInsert`),
  reached only from the two Decide bodies after `decideRefusal` proves the
  actor human BEFORE any SQL — a model's queued answer is not a person.
* **Three measured lessons, all house rules the new files tripped:**
  (1) O6's reader pool is real — `TestReadsUseTheReaderPoolAndWritesTheWriter`
  failed my five files until every read moved to `s.r` (writes, `s.w`; the
  transactions, `tx`). (2) The writer pool is ONE connection: a head-rev
  `QueryRow` issued inside an open `rows.Next()` loop **deadlocks forever** —
  `ListAttachments` drains the result set first, then reads heads (the stack
  dump was a `sql.go:1842` wait, 90s timeout). (3) The exported-surface table
  in `store.go` names every new method with its consumer (S38 T8's daemon
  wrappers/`aeon record`, T9's source_step-stamping tools), pinned by
  `TestEveryExportedMethodIsNamedInTheSurfaceTable`.
* **Guard scoping, argued:** the grep bans `'approved'` in non-Decide files —
  `schema.go` was spared the LITERAL probe because 0036's CHECK vocabulary
  must name `approved` to admit it; a CHECK is not a write. The writer probes
  (`review_state='approved'`) spare nobody, and the review-ledger grep pins
  `INSERT INTO review` to exactly ONE statement in `reviews.go` — no UPDATE,
  no DELETE anywhere.
* **Two test bugs the runs caught (mine, both):** re-attaching while the head
  moved pins the NEW rev legally — the `already-attached` refusal belongs to
  the same (subject, document, rev) triple, so the test now attaches twice
  and refuses on the third; and the "all-known" rollup case had actually left
  both estimates nil.
* **Noop honesty:** `UpdateGoal` with nothing changed returns the goal
  unchanged — no version bump, nothing reopened (an edit that edits nothing
  must not revoke an approval).
* **Measured:** 15 new tests (goals 6, briefs 2, attachments 2, epics 1,
  reviews 1, guards 3), store package green; full suite
  **2573 PASS / 0 FAIL** (2558 + 15); `make fmt`/vet green.

## Goal

Implement the store API for the new entities with the spec invariants enforced in code: every goal passes `in_review`, a decision is claimed-FROM, only a user can decide, a material edit bumps the version, attachments pin a document revision and report their currency.

## Steps

1. **Domain results, not errors** (DB19; copy the style of `documents.go`): `type Refusal struct{ Kind, Sentence string }`. Infrastructure failure is `error`.
2. **Actor:** `type Actor struct{ Kind, ID string }` — `Kind` ∈ `user|agent|trigger`; `Decide*` accepts **only `user`**, anything else returns `Refusal{Kind:"decider-not-human"}` before touching SQL.
3. **Epics** (`epics.go`): `CreateEpic(in NewEpic) (Epic, error)`, `UpdateEpic`, `GetEpic(id)`, `ListEpics(projectID string)`. No status field.
4. **Goals** (`goals.go`):
   ```go
   type GoalComponent struct{ ComponentID, Rationale string; EstimateUSD *float64; Confidence *int; Basis []string }
   type NewGoal struct{ ProjectID, EpicID, Title, Type, BodyNote, SourceKind, SourceRef, SourceLoop string; SourceStep *int64; Components []GoalComponent; By Actor; Submit bool }
   func (s *Store) CreateGoal(in NewGoal) (Goal, *Refusal, error)          // draft, or in_review when Submit
   func (s *Store) UpdateGoal(in GoalEdit) (Goal, *Refusal, error)          // material edit: Version+1, copy components to the new version, state → in_review
   func (s *Store) SubmitGoalForReview(id string) (Goal, *Refusal, error)   // draft → in_review
   func (s *Store) GetGoal(id string) (Goal, error)
   func (s *Store) ListGoals(f GoalFilter) ([]Goal, error)                  // ProjectID, EpicID, ReviewState, Type
   func (s *Store) DecideGoal(id string, version int, decision string, by Actor, reason string) (DecideResult, *Refusal, error)
   type DecideResult struct{ Changed bool; State, DecidedBy, DecidedAt string }
   func SourceUntrusted(kind string) bool // true for "webhook" only; a Go function, never a stored column
   ```
   `DecideGoal` runs in ONE transaction: `UPDATE goal SET review_state=?, updated_at=? WHERE id=? AND version=? AND review_state='in_review'`; if `RowsAffected==0` read the current row and the latest `review` row and return `DecideResult{Changed:false,…}` naming who decided and when; else `INSERT INTO review(…, by_kind='user', …)`. Decisions: `approved|rejected|parked`.
   **Confidence** is ordinal 1=low, 2=medium, 3=high; NULL = unknown (P31). `GoalRollup(g Goal) (minConfidence *int, sumKnownUSD float64, costIsFloor bool)`: `costIsFloor` is true when any component estimate is NULL.
5. **Briefs** (`briefs.go`): `CreateBrief(sc Scope, in NewBrief) (Brief, error)` computes `version = COALESCE(MAX(version),0)+1` for `(component_root, loop_slug)`, state `in_review`; `GetBrief(sc, version)`, `LatestBrief(sc)`; `DecideBrief(sc Scope, version int, decision string, by Actor, reason string) (DecideResult, *Refusal, error)` with the same claimed-FROM guard.
6. **Reviews** (`reviews.go`): `ListReviews(subjectKind, subjectID string) ([]Review, error)`. Append-only: **no** UPDATE/DELETE function exists.
7. **Attachments** (`attachments.go`):
   ```go
   func (s *Store) Attach(sc Scope, subjectKind, subjectID, document string, stepID *int64) (Attachment, *Refusal, error) // pins the CURRENT rev via ReadDocument; refuses an unknown document
   func (s *Store) ListAttachments(subjectKind, subjectID string) ([]AttachmentView, error)
   type AttachmentView struct{ Attachment; Currency string /* current|superseded|missing */; HeadRev int }
   ```
   Currency: `current` when the pinned rev is the head; `superseded` when a newer rev exists; `missing` when the document or its loop is archived.
8. Pinned greps in `records_guard_test.go`: no SQL in the package writes `review_state='approved'` (or an `approved` bind) outside `DecideGoal`/`DecideBrief`; no SQL mentions `execution_state`; `review` has no UPDATE/DELETE.
