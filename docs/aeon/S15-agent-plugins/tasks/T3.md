# T3 — `state.go`: four states

## Notes — built 2026-10-25

**Double enforcement is the point.** The verbs and the transition table refuse in `internal/plugin`
(fake-backed tests); migration **0023** refuses the same moves in the database — the partial unique index
(one live row per name: *a re-import after revoke is a NEW record* is the index's behaviour, not a

run the raw `UPDATE`/`INSERT` themselves and assert the database's own words ("terminal", per AP4).

**`not-installed` is the absence of a row** — `AllStates()` enumerates four, `PersistedStates()` the three
that can be written, and `TestPersistedStatesMatchTheMigration` pins the plugin list byte-equal to
`store.PluginAgentStates`, which the store's ledger tests pin to the CHECK (one vocabulary, two homes, a
test that notices drift — the S14 status-list pattern).

**Direction discipline:** `plugin` defines `StateStore` and its adapter `StoreBinding` imports `store` —
never the reverse (store must not learn what a plugin is). `TransitionPluginAgent` is UPDATE-guarded on
the caller's claimed FROM **and** ledger-inserted in ONE transaction; zero rows affected means "somebody
moved it under us", which is reported, not papered over. The import landing `(none) → disabled` has no
UPDATE to guard (the record was just created in that state) — it is refused if the record reads anything
but `disabled`, so a landing lands exactly once.

**The audit read is three-state** like S10's: `StateStore.Transitions` returns a `*Reject` alongside the
rows, and the adapter's refusal says **UNAVAILABLE, never "nothing happened here"** — a failed audit read
rendering as an empty list is how a revoked agent looks never-here.

**`Enable`/`Disable`/`Revoke` speak only of agents THIS process holds the package for** — a durable record
without its prompt-on-disk cannot run, and the refusal says so (import it first), rather than enabling a
row whose body nobody has read. First-party agents get the same refusal class ("first-party agents have
no plugin state") — this also pre-fixes DEMO §7's context7 idealisation, which T7's verbs re-state.

**Revoke's reason is refused at both ends** (verb: `--reason` missing; database: `length(trim(reason))`)

routine toggle gets you `"because"`, and then the column lies.

## Why this exists

**Two states cannot say what needs saying.**

| | |
| --- | --- |
| `not-installed` | never here |
| `disabled` | here, not running — **"not now"** |
| `enabled` | running |
| `revoked` | **"never again"**, and we are keeping the record |

**`revoked` is not `not-installed`** (AP4). The record must survive, or *"what did we once run, and why did
we stop"* has no answer — and that question is asked precisely when something has gone wrong.

**And `disabled` vs `revoked` is not cosmetic.** T5 makes them behave differently for in-flight work:
disable lets a Task finish, revoke refuses its result. **If both were one state, that distinction could not
exist** and somebody would reach for `disable` expecting it to stop something.

**Read first:** `check.go` (T2) — a failed check needs somewhere to leave an agent; S4's migration
discipline; AP4, AP12.

## Scope

**1. A closed type with four values.** Not two booleans — two booleans admit a fourth combination that
means nothing, and somebody will eventually render it.

**2. The transitions, and only these:**

```
(none) → disabled        import
disabled ⇄ enabled       enable / disable      — reversible, cheap
enabled → revoked        revoke                — terminal
disabled → revoked       revoke                — terminal
```

**3. `revoked` is terminal.** No transition out. A re-import creates a **new record** (T1's path), so
*"somebody put this back"* is visible rather than inferred.

**4. Every transition is recorded with its reason**, and `revoke` **requires** one. Enable and disable may
have none — they are cheap and reversible, and demanding a reason for a routine toggle gets you
`"because"`.

**5. The migration follows S4's discipline** exactly: one transaction, one number, ledger-recorded, and
fresh-equals-migrated still holds.
