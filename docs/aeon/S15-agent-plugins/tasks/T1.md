# T1 — `import.go`: the three-step path

## Notes — built 2026-10-25

**Q1, answered: a package is a directory** with an **allow-listed file set** — `agent.md` (front matter:
name, description, `requests: {tools, skills, routes}`; body = the prompt), `card.json` (S14's exact
`SignedCard` envelope, verified through `agentsvc.LoadCardFile` — the one implementation, AS2), and
optional `policies/*.json` (flat, denials; T2 judges them). The front matter **mirrors how a skill is
added today** (`opencode/skills/<name>/SKILL.md`) because that is the shape the user asked to reuse. The
enforcement of "no executable code" is the allow-list itself — **the format admits nothing unnamed**, so
there is no executable-detector to fool: unknown file, exec bit, symlink, or non-UTF-8 content are each
refused naming the format's promise. That promise is what keeps design's "its tools are the sandbox"
standing, and T9's walk must re-confirm no package acquired executable content.

**Q4, answered: the same registry** (AP1) — `plugin.Agents()` is ONE view: the 25 (from
`handler.RegisteredBodies`, `FirstParty: true`) beside every imported agent (`FirstParty: false`), and
`Dispatch(name)` builds an imported step handler on **the same primitive `handler.Build` builds on**
(`runtime.DefaultHandler`) — one runner, two sources. Tools come from `runtime.DefaultGrantNames()`,
never from the package's declarations: a declaration is a request (MC4).

**The mechanism by which `enabled` is unreachable (AP2):** `State` values imported can produce is the
single constant `StateDisabled`; **the running state is not declared in `import.go` at all** (T3's
`state.go` completes the closed set) — the grep test bans the word composed (`"en"+"abled"`) so the ban
cannot prosecute its own test file. `Import` has no field, default or branch that can name it.

**Deviations, each reasoned:** (1) `files_expected` named `testdata/packages/**` — fixtures are instead
**generated deterministically inside the tests** (card seed = `sha256(agent)`): committing signed bytes
would make every card-format change rot three fixtures, and a fixture whose signature is computed from
its own name is more honest about what the signature covers. (2) AP1's "same dispatch path" test asserts
through `plugin.Dispatch` rather than `handler.Build` — `Build` begins with a static `Lookup` a plugin
must not widen (widening it would make `handler` a plugin importer and break the deletability seam);
`Dispatch` rides the identical `runtime.DefaultHandler` primitive, which is the shared path that matters.
(3) The in-process registry (map + `Agents()/Lookup/Reset`) is what the AP1 tests observe; durable rows
are T3's table, `Reset` exists for T8's "no imported agents" state — **not a feature flag**.

`first_party` in a package is recorded (`ClaimedFirstParty`) and **changes nothing** — the registry sets
`FirstParty: false` unconditionally; T6 reports the attempt and pins the grep (no package-input struct
tag may name the field).

## Why this exists

**AP2 is a property of this path's shape, not a rule somebody follows.**

> import → security check → enable. **Never two steps.**

An agent that arrives `enabled` is a **one-line mistake** — a field set at construction, a default that
reads as convenient. And it is the mistake every plugin ecosystem makes once.

**So `enabled` must be unreachable from the import path**, by type or by construction, rather than merely
not set. A type that cannot express the mistake is cheaper than a test that notices it.

**Read first:** how a skill is added today (`opencode/skills/`) — this mirrors it; S13's registry, which
this adds to; S14's card; AP1, AP2, AP10.

## Scope

**1. Answer Q1: what is a package?** A directory, a tarball, a markdown file with front matter — **mirror
how a skill is added today**, because that is the thing the user asked for: *"same way as you can add
skills nowadays."*

**The hard constraint**: it carries **no executable code**. An imported agent is a prompt, a card and
declarations. Refuse a package containing anything executable, and say so — not because the check is
sufficient, but because the format's promise is what makes "no sandbox" defensible.

**2. `enabled` is unreachable from import.** State the mechanism in the notes.

**3. An imported agent is the same object** (AP1). Registered beside the 25, same dispatch path. **Answer
Q4** — and the answer should be "the same registry", because a second one is a second code path and the
less-tested one.

**4. Nothing is fetched** (AP10). A path, not a URL. T7 surfaces the refusal; this is where it is true.

**5. The 25 are untouched.** Importing must not alter a first-party body, its front matter or its
registration.
