# T2 — `check.go`: the security check, as a policy evaluation

## Notes — built 2026-10-25

**The check is one call to S10's evaluator** (AP3): `CheckRequests` asks the same
`policy.Evaluate(ps, Request{Type: ToolAccess, Agent: name, Tool: tool}, at)` the use gate asks, with
the caller-supplied operator rows — plugin reads no store, keeps no list (`TestNoToolListInThisPackage`
greps `check.go` for composed tool-name literals and for the presence of the `policy.Evaluate` call, the
two shape proofs the invariant demands). Refusal fires **only when a Deny rule matched** (`By != nil`,
action Deny): PL5's default-deny on an empty table is the USE answer *not granted yet*, and requests are
ungranted by design (MC4) — refusing those would turn the blocklist into a grant list. An `ask` match is
a question for first use, not an import refusal; the two stub evaluators (SkillAccess, RouteAccess) pass
here exactly as they pass at use — parity, not a special case.

**The refusal carries S10's sentence VERBATIM** — and the test pins it without quoting it (a quoted
sentence could drift, and the whole-module formatter sweep would prosecute it): the test re-evaluates the
same request at runtime and asserts the refusal **contains that sentence**, equality against the evaluator
itself. `ReadCarriedPolicies` presents policy's own authorship `Reject.Reason` unchanged, so the
package-Allow refusal is the real PL1 sentence, which already names source `import` and says a Deny or an
Ask would be accepted (T1's `files_expected` prose is satisfied by the boundary's own words plus the file
name and policy id my wrapper adds).

**The forgery this closes:** a package that sets its own `"source": "operator"` does not become an
operator — `Source` is **overwritten to `policy.Import` BEFORE policy's check reads it**, then re-encoded
through the ONE decoder `policy.DecodePolicy` (vocabulary, spec shape, authorship on the forced source).
Consequence, tested both ways: a package `allow` is refused by policy's own sentence even claiming
operator; a package `deny` claiming operator is accepted and stored `source: import`. Deny AND ask are
accepted (narrowing directions; MC4's safe side). **Accepted carried policies are attached to the agent
(`Agent.Carried`) but NOT persisted here** — plugin opens no store; the CLI (T7) writes them through
`policy.Store.Add` (the write boundary, which re-enforces authorship) so self-restriction reaches the set
the use gate decides with. That wiring is verified in T9's walk.

**Import became the three steps, never skippable:** `ImportChecked(pkgPath, ps, at)` is the ONE public
door — read/verify (`readPackage`, registers nothing) → carried policies → `CheckRequests` → register.
`Import(path)` is `ImportChecked(path, nil, now)`: nil rows is not "skip the check", it is "the operator
has authored no rules yet" — the check still runs, still refuses blocklist hits, still cannot land
anything enabled (T1's AP2 tests pass through the same door). Nothing half-installed is structural:
registration is the LAST statement of the last step, so any refusal leaves the registry byte-unchanged
(tested by before/after `len(Agents())` + `Lookup`).

## Why this exists

**The check is a policy evaluation, not a list** (AP3) — and that is the decision the whole task turns on.

The blocklist is `ToolAccess` deny policies targeting `all-agents`. The import check **evaluates them.**

**Which makes the import gate and the use gate the same gate.** A separate import-time list is easier to
write and it will eventually disagree with the real one — at which point **the import check becomes
advisory**, passing agents that will be refused in use, or refusing agents that would have been fine. Both
directions erode trust in the gate.

**And PL1 is enforced here** (AP6): an imported package may carry `Deny` and may never carry `Allow`.
**That is what makes a plugin trustable with policy at all** — the dangerous direction is closed at the
type level, so no cleverness in a package can widen anything.

**Read first:** S10's evaluator and `verdict.go`; PL1; `import.go` (T1); AS2 for cards; AP3, AP6, AP8.

## Scope

**1. Evaluate, do not list.** Call S10's evaluator for every tool, skill and route the package requests.
**No tool list, no blocklist file, no allow-set in this package** — assert by grep.

**2. The refusal is S10's sentence**, verbatim, naming the policy. One formatter.

**3. `Allow` in a package is refused** (AP6), naming the source as `import`, and saying a `Deny` would be
accepted — because whoever hit this was usually trying something legitimate in the wrong direction.

**4. `Deny` in a package is accepted.** An agent narrowing itself is always fine, and it is a feature worth
having: a well-behaved third party can ship its own restrictions.

**5. An unverifiable card is refused** (AP8), and **no skills are registered from it.** Not
partially-usable: the skills *are* the thing the signature attests.

**6. A failed check leaves nothing half-installed.** The agent is either imported-and-disabled or not
imported. No third state where some skills landed.
