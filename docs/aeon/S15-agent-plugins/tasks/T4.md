## Why this exists

**The easiest and worst mistake available in this slice.**

An imported agent **declares** what it wants. Under MC4 a grant is an operator-authored policy — so
**a declaration is a request, and the agent has nothing until somebody grants it.**

**A consent screen that renders as a list of capabilities teaches the operator that declaring is having.**
That lesson is wrong, it is learned once, and it is then applied to every future install — including the
one that matters.

So the screen says **REQUESTS**, says **none of these are granted yet**, and says **what granting each one
would mean.**

**Read first:** `check.go` (T2) — consent shows what the check evaluated; MC4; AP5; the demo's §1 for the
intended rendering.

## Scope

**1. Render requests, with the word.** Tools, skills, routes — each with *what granting it would allow*,
in a sentence rather than a flag name. `webfetch` means nothing; *"would allow outbound HTTP"* means
something.

**2. Assert requested ≠ granted.** The test is concrete: import an agent that requests three things, grant
nothing, and assert the screen shows **three requested and zero granted.**

**3. Show nothing as granted that is not.** Including the case where **some** requests are already granted
by a pre-existing policy — those are shown **distinctly**, not folded in.

**4. Q2's consequence: a re-import inherits grants.** Revoke does **not** delete the operator's policies
(T5), so re-importing an agent can find grants already in place. **The screen must say so** — consenting
to an agent that already has `webfetch` is a different decision from consenting to one that has nothing,
and the demo's §9 shows the wording.

**5. Consent does not grant.** This file renders and returns; it writes no policy. Granting is
`aeon policy add`, by an operator, deliberately. **If this task writes a policy, AP5 and MC4 are both
being violated.**
