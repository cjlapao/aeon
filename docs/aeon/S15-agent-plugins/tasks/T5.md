# T5 — `revoke.go`: revocation that revokes

## Notes — built 2026-10-25

**Q3, answered (AP12):** `disable` and `revoke` DISAGREE on in-flight work, deliberately and as two
tests: a **disabled** agent's in-flight Task **COMPLETES** and its result arrives (AS12-labelled — the
label, not a ban, is all disable ever was); a **revoked** agent's completed result is **refused on
arrival**. If both refused in flight they would read identically and somebody would reach for `disable`
expecting it to stop something. The arrival gate consults state for ONE decision — `revoked` — and lets
everything else through; the invocation gate refuses everything that is not enabled. So the two verbs
agree at creation and disagree at arrival, which is exactly the distinction the task demands.

**Q2, answered:** revoke **does not delete the granting policies** (tested: an operator `deny` row

inherits them — which is precisely why T4's consent renders them under "ALREADY APPLIES", so the
operator sees what re-granting does not change.

## Why this exists

**"Revocation that revokes" is a claim, and this task is where it is either true or approximate.**

The easy half is refusing new invocations. The hard half:

> **A Task already in flight will complete, and its result will reach a prompt — unless something stops
> it.**

**A revoked agent's answer landing in a model's context is exactly what revocation was supposed to
prevent.** So the result is refused **on arrival**, and the refusal is recorded (AP7).

**The cost is real: work already paid for is discarded.** That is the right trade, because the alternative
is revocation that revokes *eventually* — and a guarantee with "eventually" in it is not one.

**And the contrast is what makes `disable` mean anything** (Q3, AP12): a **disabled** agent's in-flight
Task **completes**. Disable is *"not now"* — cheap, reversible, a decision somebody may undo today. Revoke
is *"never again"*.

**If both refused in-flight work, they would read identically** and somebody would reach for `disable`
expecting it to stop something.

**Read first:** `state.go` (T3); S14's `task.go` for where a result arrives; AP7, AP12.

## Scope

**1. Revoke stops new invocations immediately.** The state transition is enough; assert it.

**2. Refuse an in-flight result on arrival.** The check is at the point the result returns, **not** at
creation — because at creation the agent was not revoked.

**3. Test it with a real Task.** The refusal path only executes in a race, so **a unit stub proves
nothing.** Create an async Task, revoke while it is in flight, let it complete, assert the result was
refused. This is the brief's R2.

**4. Record the refusal, with the cost.** The cost is **recorded, not recovered** — it happened, and
pretending otherwise makes the ledger lie. The record names the agent, the revocation instant and the
reason.

**5. A disabled agent's in-flight Task completes** (Q3). Assert it, alongside the revoke test, **as two
tests that disagree** — that disagreement is the point.

**6. Answer Q2: revoke does not delete the grants.** They are operator-authored policies with their own
lifecycle, and **silently deleting somebody's policy is a surprise.** State it, and note the consequence:
a re-import inherits them, so T4's consent must say so.
