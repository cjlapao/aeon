## Context

**The Makefile is the only entry point a contributor needs** (B6, I3), and it is a **serialization point** —
exactly one task edits it, and this is that task (R11).

The reason is not tidiness. A capability reachable only by a raw `go build -ldflags ... -tags ...` or a
`cargo tauri dev` incantation is a capability most people will not use, and this repository has three
toolchains. Seventeen slices of contributors each rediscovering the incantation is the cost.

**`make dev` starts both and stops both** (B7, D8). Two terminals is friction that compounds seventeen
times, and an orphaned daemon after `Ctrl-C` is worse than friction — the next `make dev` then refuses
because the socket is held (T3's O5), and the person has no idea why.

**It must refuse loudly when a toolchain is missing** (O3), naming which. A `make dev` that half-starts —
daemon up, app failed silently — is the worst outcome, because the app's absence looks like the app being
broken rather than absent.

**CI fails on any target** (B9, D12). `cgo` is on, so a cross-compilation break is the likely failure, and
finding it at release is finding it at the worst time.

**Read first:** the scaffolding's own Makefile and CI if any, and inherit what works; `aeon/docs/BUILD.md`
(T4) for the cross-compilation approach this must implement.

## What to do

**1. The Makefile**, with these targets and nothing surprising:

- `dev` — daemon and app together (B7)
- `build` — six targets to `dist/` (T4)
- `test` — Go tests and UI tests
- `lint` — Go lint and UI lint
- `fmt` — format everything; idempotent
- `clean` — remove `dist/`, build caches and any stale socket
- `help` — the default target, listing the above. A bare `make` should teach, not build.

**2. Prerequisite checks** (O3). Before `dev` does anything, verify Go, Node and a Rust toolchain, and on a
miss print which one and how to install it, then exit non-zero. Check before starting anything, so nothing
is half-started.

**3. Two-process supervision** (Q9). Name the mechanism — a process group with a `trap`, or a small
supervisor — and make `Ctrl-C` reach both. Assert it: process count before, `SIGINT`, process count after.

**4. CI** — on every push: `make lint`, `make test`, and `make build` for all six targets. **Fail the job if
any target fails**, and upload the six binaries as artifacts so a reviewer can run one.

**5. `make fmt` must be idempotent** — running it twice changes nothing, and `git status --porcelain` after
it prints nothing. A formatter that reformats its own output makes every diff noisy.
