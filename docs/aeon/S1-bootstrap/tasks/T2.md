## Context

The task that turns "the daemon runs only what we decided" from a claim into a property.

**An allow-list, not a subtraction** (B8). Aeon **names the services it wants** and registers those. It does
not remove anything from the framework's defaults, because you cannot delete from a module you do not own —
and the allow-list is the better discipline regardless. **A deny-list fails open on every upstream addition;
an allow-list makes a new upstream service inert by default.** It fails safe on every future upgrade rather
than only on the ones somebody remembered to audit.

**A committed fixture, not a code review** (I5, D5). Twenty slices from now somebody runs `go get -u` and the
framework registers something new. The only thing between that and a daemon quietly wider than anyone decided
is a golden file and a test that compares against it — in a program that runs shell commands.

**And that test matters more here than it did under a fork** (B11). A fork's upstream arrived only when
somebody deliberately merged it. A dependency's arrives with one command. **Making upgrades cheap is exactly
what makes this guard load-bearing.**

**The startup test must actually run without the services.** A daemon that boots because Redis happens to be
installed on the developer's machine is precisely the failure this catches — so the test runs with nothing
available, not with a mock.

**`core.GlobalTenantID` becomes the only tenant.** The framework's tenant-scoped queries keep working because
they all resolve to it, which is why single-user degenerates rather than needing 177 files edited.

**Read first:** T1's notes — the enumerated starting state; the framework's registration entry point and
whether it accepts a caller-supplied set; the design's B8 and B11; the plan's Q2, Q3 and Q5.

## What to do

**1. Answer Q1 first, and stop if the answer is no.** **Does the framework let a caller choose which services
are registered?** A public registration seam, an option struct, individually constructible services — any of
these is enough.

**If there is no seam and the framework registers everything internally, do not work around it.** Do not
copy its bootstrap into `aeon/`, and do not disable services by config — B8 exists because a config-disabled
service is one a stray key re-enables. **Record it as a finding and raise it as a framework request**, the
way the `localrpc` service was raised. Then register what is reachable and state in this task's notes exactly
which services Aeon cannot currently exclude, so the gap is visible rather than assumed away.

**2. Register the allow-list.** From the design: `config`, `logging`, `core`, `database`, `encryption`,
`validation`, `osutils`, `health`, `idempotency`, `events`, `update`, `app`, `appctx`. And **registered but
unmounted, for S19**: `api_keys`, `role`, `claim`, `ratelimit`.

**Treat the design's kept list as the contract** (O1). Enumerate what actually ends up registered and
reconcile any difference in this task's notes — a service arriving because something else pulled it in is
exactly what this task exists to find.

The services the design considered and refused — `oauth`, `webauthn`, `otp`, `session`, `sms`, `email`,
`notification`, `object_storage`, `media`, `redis`, `jobs`, `flipt`, `honeytrap`, `ipban`, `bruteforce`,
`tracing`, `profiling`, `metrics`, `swagger`, `websocket`, `device`, `activity`, `user`, `tenant`, `vaults`,
and the `api` HTTP handler tree — are **simply never named.** Nothing is deleted.

**3. Write `services.golden`** — the sorted list of registered service names, one per line, with the four
S19 ones marked. This is the test's input, not documentation.

**4. Write `registry_test.go`** asserting:

- the registered set equals the fixture, **exactly** — extra or missing both fail
- adding a service makes it fail, asserted by adding one in the test
- the daemon reaches a started state with **no Redis, no Postgres and no SMTP reachable** (Q3)
- `GlobalTenantID` is the only tenant: no path creates a second, and a tenant-scoped read resolves to it

**5. Confirm SQLite, not Postgres** (Q5). If a registered service assumes a Postgres DSN, make it SQLite or
record why it cannot be.

**6. Wire the fixture check into CI** (B11), so a dependency bump that changes the registered set fails the
build rather than landing. **This is the task's most durable output.**
