## Context

**A demo nobody has followed does not work.**

`DEMO.md` was written before the code, from the design. Every one of its stated outputs is a prediction, and
predictions about your own software are optimistic in a specific way: they describe what you meant, and they
omit the step you do without noticing. This task is where the prediction meets the binary.

It is also where the slice's honesty is enforced. `DEMO.md` must say what S1 does **not** show — no
protocol, no model call, no store schema, no UI capability — so nobody reads the garage as the skateboard.
That section is easy to write and easy to quietly drop, and dropping it is how a bootstrap slice gets
mistaken for progress.

**When a step does not match, either the code or the demo is wrong. Record which.** A demo silently edited
to match a bug is worse than no demo, and it happens by default because editing the demo is faster.

**Read first:** `DEMO.md` in full; `docs/test_suites/aeon-tools.md` for the suite format, case-id convention
and status markers; the brief's §2 for what each DoD item proves.

## What to do

**1. Walk `DEMO.md` end to end on a clean checkout** — a fresh clone, or a container with only Go, Node and
Rust. Not your working tree, which has caches, a built `dist/` and a running daemon.

For each step, compare the actual output against the stated one. Fix the mismatch in **whichever is wrong**,
and record in this task's notes which it was and why. A run with no mismatches is a suspicious result for a
first walk, not a clean one.

**2. Add the steps you found yourself doing** that the demo does not mention. Those are the omissions a
newcomer stumbles on, and they are invisible to whoever wrote it.

**3. Keep the "what this does not show" section**, and check it is still accurate after T2–T6.

**4. Write `docs/test_suites/aeon-bootstrap.md`.** Status `draft`, ids `QAB-01` upward. Cover:

- the six-target build, with each binary **executed**, and any unverified target named
- `make dev` on a real machine, and `Ctrl-C` leaving no orphan
- socket permissions checked by `stat`
- a second `serve` refused, and a **stale** socket reclaimed
- the service fixture, including that adding a service fails it
- a boot with **no** Redis, Postgres or SMTP available
- `aeon version` with no config file present
- the app showing the daemon's version, then showing disconnected when the daemon stops

Mark the **six-target build** as required before every release, and the **no-external-services boot** as the
case that catches a service booting only because something happened to be installed locally.
