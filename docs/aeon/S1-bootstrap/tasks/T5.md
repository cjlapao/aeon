## Context

**Its own task** (R8) because three toolchains in one task is three ways to be blocked.

The app exists now, sixteen slices before it has any capability, for one reason: **so its integration is
never a surprise.** A Tauri build introduced at S9 alongside the chat UI would mean debugging Rust
toolchains, code signing, socket access and React state simultaneously. Introduced now, it is a window with
a version string and every one of those problems is met alone.

**The one real requirement is easy to fake, so it is stated sharply** (O4): the window renders the
**daemon's** version, read over the socket. Not its own constant. A constant would pass a naive check while
the socket was entirely broken — and the whole point of building the app now is that its integration is
proven, which a constant proves nothing about.

**The Rust shell is the only place that touches the socket.** A browser cannot speak a unix socket, which is
why the Tauri shell stops being optional packaging and becomes the UI (superseding U1). The web layer calls
Tauri commands; the Rust side owns the connection.

**Read first:** `docs/_archive/aeon-v1-horizontal/10-ui-chat/design.md` for U1–U10 and what the app becomes at S9 — build
nothing of it now, but do not contradict it; `aeon/cmd/aeon/serve.go` (T3) for the socket path resolution
the shell must mirror.

**The UI toolkit is `@cjlapao/ui-kit`, and it is not a new decision.** v1's `packages/loop-state-ui`
already depends on `^0.2.0`, so S9's port is going to bring components built on it either way. Adopting it
here means **the window renders a real ui-kit component at seven tasks rather than at eighty** — which is
the same argument this task already makes for existing at all.

Three mechanical requirements, each of which fails confusingly if missed:

- **`react-router-dom` is a peer dependency** (`^6 || ^7`), alongside `react` and `react-dom`. It is
  required even though the app has one window.
- **`import "@cjlapao/ui-kit/styles.css"`** once, at the entry point. The CSS is **prebuilt Tailwind
  v4.3.3**, so this project's own Tailwind 4 config must coexist with it rather than recompile it.
- **One markdown renderer.** The kit ships a `./markdown` subpath (`@uiw/react-md-editor`); v1 uses
  `react-markdown` + `remark-gfm`. **Pick one here**, because two markdown stacks in one bundle is the
  same mistake S8's Q6 refuses for YAML.

## What to do

**1. `aeon/ui/`** — Vite 7, React 19, **`@cjlapao/ui-kit@^0.2.0`**, Tailwind 4, TypeScript 5.6, matching the stack the superseded UI
slice used so S9 inherits rather than migrates.

**2. `aeon/ui/src-tauri/`** — the Rust shell, with **one** Tauri command: fetch the daemon's version over
the socket. Resolve the socket path the same way `serve` does (T3), including the platform differences.

**3. The window** shows the version and a connection state. Three states, because a two-state UI is a UI
that lies when the daemon is starting: *connected* with the version, *disconnected* with the socket path it
tried, and *connecting*.

**Show the path it tried** in the disconnected state. It is the first thing anyone debugging this needs, and
the reason B10 prints it on the daemon side too.

**4. Tests against a fake**, not a real daemon (I6): the app renders the version a stubbed command returns,
and renders disconnected when it errors.

**5. No capability beyond that.** No loop list, no chat, no settings. S9 builds the app; this builds the
window.
