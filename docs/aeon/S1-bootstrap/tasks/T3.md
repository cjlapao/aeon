## Context

**One binary** (B4, I4). `aeon serve` is the daemon; every other verb is a client. No `cmd/aeon-daemon`
alongside `cmd/aeon` — the single binary is what makes the editor-extension path real, because `gopls` and
`rust-analyzer` are easy to embed for exactly that reason.

**The two startup lines are a contract, not logging** (B10, D2). Every later slice's demo begins by finding
the socket and the store, and a daemon that hides where it lives costs one question per demo for sixteen
slices.

**`aeon version` must work with no config file** (Q4). A binary that needs configuration before it can say
what it is cannot be diagnosed by the person who just downloaded it.

**Owner-only socket permissions are the entire access-control story** for first-party clients (P26, D3).
Everything appears to work with a world-writable socket, which is why the test is a `stat` assertion rather
than an observation that a client connected.

**A second `serve` refuses** (O5), naming the socket and the pid holding it. One daemon per machine (§1a);
two racing on one store is the failure this prevents, and "address in use" without a pid is a message that
sends someone hunting.

**Read first:** `internal/app/` and `internal/appctx/` for the lifecycle; `cmd/api/` as the model;
`internal/config/` for how paths resolve; the plan's Q1 answer — **if the scaffolding has no socket
transport yet, this task creates the socket file and accepts connections through the scaffolding's own
listener once it exists, and says so plainly rather than implementing one** (N2).

## What to do

**1. `cmd/aeon/main.go`** — verb dispatch. `version`, `serve`, and a usage message listing them. Unknown
verb exits non-zero with the list.

**2. `version.go`** — version, commit and Go version, from build-time ldflags with sane fallbacks. No config
read, no store open, no socket.

**3. `serve.go`** — resolve the socket path and the store path, print them **in that order on the first two
lines**, start the app lifecycle, create the socket `0600`, accept connections, and on SIGTERM shut down
cleanly and **unlink the socket**. A leftover socket makes the next start ambiguous.

Socket path per platform (Q10): `$XDG_RUNTIME_DIR/aeon.sock` on Linux with a documented fallback,
`~/Library/Application Support/aeon/aeon.sock` on macOS, a named pipe on Windows. State all three in a doc
comment.

**4. `--print-services`** — print the registered set and exit, for D5's demo step.

**5. Refuse a second instance** (O5). Detect the existing socket, determine the holding pid, and refuse
naming both. A stale socket with no live holder is **reclaimed**, not refused — otherwise a crash leaves the
daemon unstartable, which is the opposite of what S7 is for.

**6. Tests bind a temp socket path** (I6). No test touches the real one; a test run must never collide with
a developer's running daemon.
