# T5 · Signature verification

**Prefix:** AM · **Rules:** AM3 · **Depends on:** T4.

See `plan.md`'s T5 section and `design.md` AM3. Locked (`brief.md` §5): **Ed25519 signature over an X.509
certificate**, verified with Go's standard library only (`crypto/ed25519`, `crypto/x509`) — no third-party
crypto dependency.

Verification proves **tamper-evidence only**: the Ed25519 signature matches the certificate's public key
over the card's own bytes. It does **not** check the signer's identity against any trust root — there isn't
one in this slice (`design.md` AM3's explicit scope cut). A tampered card (signature doesn't match) is
refused on import, named as tampered — write that test first.

**Unsigned cards — locked, with a config override.** No signature at all refuses import **by default**.
Add a config setting (name it `agents.allowUnsignedImport`, default `false`; T0 settles exactly where it's
scoped — per-component or daemon-level) that, when `true`, imports the card anyway, visibly marked
`unsigned` for the UI (T7) to show. Write both paths: default refuses, override imports-and-marks. Also
write a test proving a *verified* card surfaces the signer's claimed identity from the certificate for the
UI to show.

## Notes

Built (verified 2026-10-30). Verification is `agentcard.VerifyCardSignature` — Ed25519 over an X.509
certificate, stdlib only (`crypto/ed25519`, `crypto/x509`), no third-party crypto. It proves **tamper-
evidence only** (the signature matches the certificate's key over the card's exact bytes); it does not
judge the signer (no trust root, no signer registry — the marketplace is another site), and surfaces the
signer's claimed identity from the certificate's `Subject` for the UI to show (AM3). The three states
(P31) are `verified` / `tampered` / `unsigned`; `unsigned` refuses by default and the
`AEON_AGENTMANAGE_ALLOW_UNSIGNED_IMPORT` env var (default false) is the one current override door, importing
the card marked `unsigned`. `agentmgr.verify` maps the `CardSignature` to the store refusal / import.

**This task is the one the agentsvc guard conflict was about.** The card verification first lived in
`internal/agentsvc/agentcard.go`; moving it to `internal/agentcard` (see T4's Notes) is what makes the
guards pass — `agentmgr` no longer imports the optional agentsvc layer and no `x509` sits in a non-test
agentsvc file. The `AEON_AGENTS_*` env var became `AEON_AGENTMANAGE_*` so `TestNoFeatureFlagWasAdded`
(bans the literal `AEON_AGENTS` module-wide) does not trip on S43's unrelated config var.
