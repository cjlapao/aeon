# T4 — the app: put on send, chips and previews under the bubble

**Built.** Spec AT2/AT8/AT11 (rulings 2+4).

Two dispatched agents died in the harness tool outage (one mid-scout, one
at context exhaustion, zero files written by either); this pass did the
work in-session. The second's scout (host lines, wrapper shapes) proved
exact and is what made the third pass quick.

What exists (`aeon/ui`):
- `src/lib/attachments.ts`: `AttachmentReceipt`/`AttachmentRef`/
  `AttachmentScope`, `putAttachment` (chunked base64 — one
  `String.fromCharCode` over 10 MiB would blow the argument stack),
  `declaredType` (browser guess → extension map → octet-stream; the DOOR's
  magic-byte verdict overrules and its sentence surfaces verbatim),
  `cachedAttachmentData` (pinned revisions cache forever; a FAILED read is
  evicted so the next render asks honestly again), `humanSize`,
  `putAllAttachments` (sequential, operator order, `undefined` for zero so
  the field stays ABSENT, never `[]`).
- `useChatActions.ts`: the scope is the LOOP ROW's own via a lazy
  `loop.show` (read once, first file only — a chat that never attaches
  pays nothing; a slug from a flag would be a claim, this is a fact);
  `onMessage` gained the files parameter and `onSteer` puts
  `request.attachments`; both spread `...(refs?.length ? { attachments:
  refs } : {})`; a refused put throws BEFORE the send — the composer's
  existing clear-on-resolve keeps the draft (pinned by the pre-existing
  `agent-chat-attachments.test.tsx`). `actions.attachmentPreview` is the
  cards' read door.
- `skills.ts` `messageWith` forwards the composer's draft FILES (the
  wrapper that dropped them was the wrapper that lost the person's
  attachment; the PUT rule lives at the send's owner, exactly as the NAME
  rule lives here).
- `types.ts`/`fromEvents.ts`: `attachments?: readonly AttachmentReceipt[]`
  on the message and steer items; `receiptList` validates EVERY field or
  draws nothing (a half-believed size/type never renders).
- `cards.tsx`: `AttachmentChip` — name · mediaType · human size from the
  STORE's fields; previewable images (`png/jpeg/gif/webp`) read their
  pinned revision and render `<img>`; a failed read renders ONE visibly
  broken chip naming document AND revision (ruling 3 — never blank, never
  a fake icon); non-preview types (pdf) are chips only, no read asked.
  Chips sit UNDER both person-side bubbles, beside the skills receipt —
  the words above stay the person's own (B3). `ChatStream` hands
  `actions` to `MessageBubble` (optional prop; every old caller unchanged).
- bench: ScenarioMode `onMessage` scripts the put (receipts as the store
  would answer; a file named *gone*/*missing* pins rev 900) and echoes
  `attachments` on the posted event; the scripted `attachmentPreview`
  rejects ≥900 — the broken chip, no daemon; the gallery scenario gained
  `g9`: a png (previewed), a pdf (chip), and a lost revision (broken).
  Live mode needs nothing extra — steer chips ride the real doors.

Tests: `test/agent-chat-attachment-receipts.test.tsx` (11, green in
isolation): put-then-send carries refs (params pinned incl. the base64);
zero files = field absent; refused put sends NOTHING; steer refs beside
words, absent when none; scope read ONCE from the loop's own row; posted
receipts map, forged receipts draw nothing; steer queued receipts map;
chip content (name/type/size); `<img src>` is the data URL; the broken
chip names document + revision; pdf asks no read. Harness note: jsdom's
File lacks `arrayBuffer` in this environment — the fixture defines it
(it is standard in browsers; the put path only needs the bytes).
