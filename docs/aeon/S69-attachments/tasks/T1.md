What exists:

  kinds (the M4 six-kinds comment); `Block` gains `Data`, `MediaType`,
  `Document`, `Rev`; `Validate` enforces the either/or — wire form

  `DocumentRefBlock`/`ImageDataBlock`/`DocumentDataBlock`.

  byte-identical — pinned), documents REFUSE naming route and fix;
  **openai_responses** `input_image` / `input_file{filename,file_data}`.

  (`attachmentDropped`, its own counter beside the response-direction
  `dropped` — (O1) untouched) and never half-sent.
- Tests: `anthropic_attachments_test.go` (3), `openai_test.go` +5,

Deviations (all in the commit message too):
1. `capability.go` untouched — it is the closed wire-BEHAVIOUR flag set;
   documents-on-chat is a fact about the wire FORMAT, so the adapter's
   refusal naming route-and-fix is the honesty mechanism, not a new flag
   category.
2. `attachmentDropped` is NOT folded into `countDropped` — request-
   direction drops never blur into the (O1) step record's response
   counter. Daemon-side accounting of the counter is left un-wired
   (recorded, not silently skipped).
3. Images ride the user role on both OpenAI wires; documents refuse at
   chat on any role; `input_file`'s filename falls back Name → document
   tail → "attachment" (the tail rung pinned via a direct call, since
   Validate's either/or means wire-form blocks never carry a Document).
