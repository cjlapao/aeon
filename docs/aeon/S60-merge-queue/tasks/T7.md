# T7 · The driver, the landing and resolution loops, conflict handling, recovery

**Prefix:** MQ · **Rules:** MQ2, MQ5, MQ9, MQ10, MQ11, MQ18 · **Depends on:** T3, T5, T6; **S48** seed engine (blueprint rows), S43-extra engine.

## Goal

Items actually move: a daemon reactor decides, **loops do the work**, conflicts take one of three exits, a restart re-derives everything, and the whole pipeline is proved on a real two-branch fixture including the conflict case.

## Behaviour — the pipeline (each a test on a real fixture repo pair with the `Fake` forge)

1. **Happy path**: enqueue a finished feature branch, `mode=manual`: `queued → catching_up → verifying → ready`; the item waits; `mergequeue.land` (T8) ⇒ `merging → merged`; `landed_sha` is on `origin/<base>`; the integration worktree is removed and its ledger row settled.
2. **Order and exclusivity**: three items for one base — exactly one holds the slot; order = position; a reorder (human door, T8) takes effect on the next decision; two bases proceed independently (two slots).
3. **Base moves while `ready`**: the driver sees `behind>0` ⇒ item back to `queued` (`catch_ups+1`) and a **new** `integrate/<id>-<n>` ref; after `max_catch_ups` ⇒ `failed(stale-exhausted)`; the old ref is never deleted.
4. **Conflict, `ask`, attended**: `catching_up → conflicted`, paths recorded; the landing loop's gate question (`resolve | abort`) is answered `resolve` by a person ⇒ resolution loop starts; `abort` ⇒ `failed(conflict)`.
5. **Conflict, `ask`, unattended**: item `conflicted`, **no loop started**, the S58 event is emitted; nothing else moves (G14: an unattended ask denies at once).
6. **Conflict, `resolve`**: the resolution loop runs in the integration worktree; on `done` the item returns to `queued` **at its original position** and goes through `verifying` against the **new** `integration_sha` again; a resolution whose gate is red ⇒ `failed(gate-failed)`. **The resolver cannot land** (blueprint has no outward/irreversible action; a stop test proves a model's attempt to call `forge.land` is refused as an unknown/unavailable tool-action).
7. **Secrets in hunks**: a fixture whose conflicting hunk contains a planted sentinel (`AKIA…`-looking string and a fake private-key header) ⇒ after the full conflict flow the sentinel appears in **no** DB table, event payload, log line, PR body or error (grep over the SQLite file bytes, the event log and captured logs); only **paths** do.
8. **Authority**: `mode=auto`, no S56 grant, unattended ⇒ the landing loop denies at `forge.land` ⇒ item `failed(denied)`; with a grant seam stub returning allowed + gates green + review approved ⇒ lands. `mode=off` ⇒ nothing starts even with items queued; flipping to `manual` starts the head.
9. **Recovery**: kill the daemon at each state (catching_up before/after worktree add, verifying, ready, merging before/after the forge call): on restart the reactor re-derives from the item row + loop row + git + forge (`ReadPR` merged?) and ends in the same final state as an uninterrupted run; an already-merged PR found at `merging` ⇒ `merged` without a second merge call.
10. **Loop stop (S55 contract)**: stopping/aborting the landing loop moves the item to `removed(loop-stopped)` when `queued`-equivalent work is unstarted, else `failed(loop-stopped)`; the worktree is cleaned by reconcile.
11. **Dequeue** of an open item stops its landing loop via the loop's own door, releases the slot in the same transaction as the `removed` transition.
12. `behind`/`ahead` reads: `ok{n}`, `unavailable{reason}` when the remote ref is missing or fetch failed; never `0` for unknown.
