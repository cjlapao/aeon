# T11 · A bench-level view and the descriptor-driven UI contract

**Prefix:** MQ · **Rules:** MQ17 · standing rules 3 and 4 · P7 (bench level) · **Depends on:** T8, S45 T9 (shared components, if merged — else the existing kit).

## Goal

The app can **see** the queue — a list with details per repository — without a UI redesign (the real product panel follows the app work on top of the S44-extra tree). This task adds a **bench-tab page** that proves the contract, plus the generated types the later panel will use. It is the P7 shape at bench scope: descriptor-driven, refusals verbatim, no optimistic updates.

## Files

- `ui/src/features/test-bench/pages/MergeQueuePage.tsx` — **new**: repository picker from `component.list` (repositories only: nodes with a root); the queue as a list with details — position, status pill, reason, branch → base, PR, loop link, staleness (three states rendered distinctly; `unavailable` shows its reason, **never** `0`), attended, enqueued by; a detail pane from `mergequeue.show` (transitions, integration refs, the `nextStep` sentence, conflict **paths**); actions **rendered from `mergequeue.vocabulary`'s legal-next table** (enqueue, dequeue, reorder, retry, land, settings) — no state or action name is typed in the page.
  - Authority-widening settings (`mode → auto`, `conflictPolicy → resolve`) and `land` **confirm with the daemon's own `statement`** (`useConfirm`; declining sends nothing); refusals are shown **verbatim** with the draft kept; rows update **from the response**, never optimistically; offline ⇒ writes disabled, reads show last data.
- `ui/src/features/test-bench/registry.ts` (or the bench index) — one tab entry; existing tabs untouched.
- `ui/src/lib/i18n/en.json`, `pt.json` — `bench.mergeQueue.*` keys, parity both ways (the page's own copy only; statuses/reasons come from the daemon).
- `ui/test/merge-queue-page.test.tsx` — component tests (mock `bridge`; VERIFY the neighbours' helper, e.g. `bench-telemetry.test.tsx`).
- `ui/src/features/test-bench/pages/mergeQueueRpc.guard.test.ts` — extracts every literal passed to the rpc helpers and asserts each is a registered method in the generated `contract.ts` (≥ 1 found, never vacuous) with a canary that flags a bogus method; a grep test forbids hardcoded status/reason/mode words in the page.
- No dependency added; no `fetch`; no `localStorage` for queue data.

### Deviations (the task file could not know these)

1. **i18n went to a fragment pair, not `en.json`/`pt.json`.** The task names those files, but `en.json` is
   970 lines — adding `bench.mergeQueue.*` would push it past SIZE1. Same SIZE1-forced split as the S57 T11
   precedent (`en-memory.json`/`en-history.json`), merged in `i18n/index.ts`. `test/i18n.test.tsx` covers
   only the core catalogs, so **en/pt parity lives in the feature guard test** (keys-equal, page-key-lookup,
   no-3-word-copy, and a teeth canary).
2. **The seatbelt follows the bench RM9 precedent, not `useConfirm`.** The task names `useConfirm`
   (`useConfirm.tsx` → `useTypeToConfirm`), which is the destructive **type-the-record's-name** hook
   (`settings/policy`). A `land` / `mode→auto` widening is not a type-the-name delete — it is the S50 T7
   `roadmap/ItemDrawer.tsx` daemon-authority gate: its own `role="dialog"` quoting the daemon's own words
   (the `land` digest + `nextStep`; the settings `statement` + the parsed `acknowledged "<digest>"`), press
   to act, **decline sends nothing**. `DeleteConfirmModal`/type-to-confirm would force typing a word the
   daemon did not gate on. Deviation is precedent-backed (S50 T7), not a shortcut.
3. **`settings-ok.json` request params widened → `contract.ts` grew by three, via `protogen`.** The task
   requires the `conflictPolicy → resolve` widening to be **typed**, but the fixture only sampled
   `componentRoot/mode/acknowledged`, so the generated params type lacked `conflictPolicy/landMethod/maxCatchUps`
   (TS2353 on the page's write). The sanctioned fix — not a cast, not a hand edit — was to widen the **fixture**
   (those fields exist on `protocol.MergeQueueSettingsParams:211-213`) and re-run `make protogen`. `check-protogen`
   and the full protocol conformance suite stay green (the harness compares parsed structures, so key order is
   irrelevant and the added params ride to the scripted service harmlessly).
4. **Staleness renders `state` + `reason`, never a count.** The daemon's `StalenessView` also carries
   `behind/ahead` ints, but **no fixture samples them**, so they are not in the type and the page renders none
   — which satisfies "`unavailable` shows its reason, **never `0`**" *by construction* (there is no number to
   show a zero). The three spellings render in three distinct data-shapes (`state` / `state-reason` / the
   absent `unread`, tested). The shared 20-fixture `list-ok.json` was **not** amended (behind/ahead) — it is a
   shared T0 artifact and a fabricated count is the one thing the rule forbids; no fixture was invented.
5. **`mergequeue.proposeEnqueue` is never referenced** in either owned file (asserted by guard: the pages carry
   no `/propose/i` once comments are stripped). The proposal twin belongs to T9's agent surface.
6. **`component.list` is the one borrowed door** (the root picker); a merge queue exists only under a root, and
   this is the same scope-picker note history's guard carries. Allow-list = 10 `mergequeue.*` + `component.list`.
7. **Guard is scoped by file name, not directory** — the bench `pages/` folder is shared by every bench page, so
   the census reads exactly `MergeQueuePage.tsx` + `mergeQueueRpc.ts` (the registry-registered scoping every such
   page forces). Vocabulary words to forbid are read OUT of the daemon's own `vocabulary-ok.json` + `list-ok.json`
   staleness + the two staleness spellings (`behind`,`settled`) the 20 fixtures do not sample — a guard may know
   the vocabulary; the page may not.
8. **ICU gotcha:** `useI18n().t` parses every catalog string as ICU, so an ASCII `'` is quoting syntax and
   `queue's` threw `IcuParseError: unterminated quoted section` at render. Catalog prose uses the typographic
   `’` (the `en-history.json` convention); the `{mode}`/`{policy}`/… placeholders interpolate normally.
9. **`npm run lint` (tsc) is RED at baseline on this checkout — not caused by this task.** A pristine-tree run
   (implementation stashed) shows **155 errors**, every one `node:fs`/`node:path`/`__dirname` in the **21 sibling
   guard tests** (history, roadmap, settings/*, test-bench), because `@types/node` is locked only as an *optional
   peer* and `npm ci` does not install it; the shared `tsconfig.json` sets `"types": ["vitest/globals"]` (no
   `node`). My **production** files (page, rpc owner, i18n, index, registerAll) contribute **zero** tsc errors;

   slice's dependency to pay. The real execution gate (`npx vitest`, esbuild) is green for all 26 tests.
10. **`make check-deps` is not a web-dep guard and has no `aeon/` target.** It lives in `ui/Makefile:94`
