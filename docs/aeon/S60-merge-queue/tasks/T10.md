# T10 · The CLI: `aeon mergequeue` as a client

**Prefix:** MQ · **Rules:** MQ17 · standing rule 1 · P5 (client half) · **Depends on:** T8. Parallel-safe with T9, T11.

## Goal

Every queue operation a person can do is a verb that dials the daemon, prints what the wire said, and re-validates nothing. Rule 1 holds trivially: the daemon exists first; there is **no** CLI-only behaviour.

## Files

- `cmd/aeon/mergequeue_verbs.go` — **new**: `list [--repo PATH] [--status S] [--all] [--json]`, `show ID [--json]`, `status [--repo PATH] [--json]`, `vocabulary [--json]`, `enqueue --branch B [--repo PATH] [--base BR] [--unattended] [--json]`, `dequeue ID`, `reorder ID [--before ID2]`, `retry ID`, `land ID [--yes]`, `settings [--repo PATH] [--mode M] [--conflict-policy P] [--land-method L] [--max-catch-ups N] [--yes] [--json]`.
  `--repo` defaults to the cwd's component root (the existing `componentFlag` helper, `store_verbs.go:387`). Every verb dials (`dial(*want)`, `addProtocolVersionFlag`); output is the wire result: `list` prints a table (position, status, branch, reason, behind/ahead, PR, loop); `show` prints the item, its transitions and the `nextStep` sentence; `--json` prints the wire result verbatim.
- `cmd/aeon/main.go` — dispatch `case "mergequeue"`; usage lines for the new verbs only.
- `cmd/aeon/mergequeue_parity_test.go` — **new**: the P5 parity test in both directions (every verb names its method; every `mergequeue.*` method has a verb); fixture = T0's parity table.

## Behaviour

1. **Closed sets come from the daemon**: `--status`, `--mode`, `--conflict-policy`, `--land-method` are validated by the daemon; `--help` text for them is **generated from `mergequeue.vocabulary`** (live when the daemon is up; when it is down the help says "start the daemon to list the allowed values" — no second typed list).
2. **`--yes` is a seatbelt** (required for `settings --mode auto` and `land`), not a security control; the daemon's `statement` for authority-widening settings is **printed before** the call and its acknowledgement digest sent (T8 behaviour 2); declining sends nothing.
3. Refusals print the daemon's sentence verbatim (what/why/do) and exit non-zero; a daemon that is not running prints the standard "daemon not running" line — **no offline fallback** (a recorded P5 deviation: a queue is meaningless without the daemon's loops).
4. No flag, stdin or prompt accepts a secret; `aeon mergequeue` never prints a token.
5. Existing verbs untouched (`aeon action check` golden from T1 changes only by the six new action rows, listed in Notes).
