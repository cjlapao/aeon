# T9 · Agent tools: reads, own-item dequeue, propose-only enqueue

**Prefix:** MQ · **Rules:** MQ14, MQ17 · standing rule 2 · P6 · **Depends on:** T8, S45 (`internal/desk`, generic `proposal.commit`).

## Goal

Agents can **see** the queue and **ask**; they cannot decide. Five specs in the records catalog (one definition, two doors), one new inert proposal kind, a person-only commit.

## The five specs (`internal/records/catalog.go`, data only, no import added; family `mergequeue`)

| Tool | Socket twin | Class | Mutates | Does |
| --- | --- | --- | --- | --- |
| `mergequeue_list` | `mergequeue.list` | safe | no | Items with status, position, reason, branch, PR, staleness; filters; **own-view**: only repositories the calling agent's loop has run in (T0 names the source, as S52 does) |
| `mergequeue_show` | `mergequeue.show` | safe | no | One item with its transitions, integration refs, next-step sentence |
| `mergequeue_status` | `mergequeue.status` | safe | no | Config, slot holder, queue length, three-state staleness for a repository |
| `mergequeue_dequeue` | `mergequeue.dequeue` (own-item path) | detectable | **yes** | Remove **this loop's own** `queued`/`conflicted` item — restrictive; an item in flight needs a person |
| `mergequeue_propose_enqueue` | `mergequeue.proposeEnqueue` (new) | detectable | **yes** | Create an **inert** proposal asking that a branch be queued; nothing happens until a person commits it |

Descriptions ≥ 40 characters and distinguish siblings. Schemas `additionalProperties:false`; **no** `status`, `actor`, `attended`, `position`, `mode`, `base` override fields — `propose_enqueue` input is `{componentRoot, branch, reason}` (reason 1–512 bytes); the base is resolved by the daemon (MQ15).

## Behaviour

1. **Forced identity and attendedness**: the service stamps `created_by` = the agent actor the records service stamps; a committed proposal enqueues with `attended = false`, actor `{proposal, <id>}` (MQ14.3). Params naming any of these are a parse error.
2. **Inert**: after `propose_enqueue` the queue tables are byte-identical (row counts and checksum); `mergequeue.status` unchanged.
3. **One validator**: `ValidateEnqueue` runs at proposal **create** (`desk.Validate`) and at **commit**; a payload refused by the socket `mergequeue.enqueue` is refused by the tool with the same reason (create/commit parity test).
4. **New proposal kind** `mergequeue_enqueue`: a `proposal.kind` CHECK **table rebuild** — read the **current** DDL, change only the CHECK, update the Go mirror, the lock test and the literal migration-count assertions (P6/S46/S48 precedent); timestamped migration; the generic `proposal.commit` path (S45) applies it with the **committer** as actor and `desk.Apply` = `ValidateEnqueue` + `Service.Enqueue`.
5. **Own-item dequeue** refuses another loop's item and any status other than `queued`/`conflicted`, with the sentence naming what a person can do; it is the only direct agent write.
6. **Rate and size**: per-agent open `mergequeue_enqueue` proposals ≤ S45's constant (counted refusal); payload ≤ 8 KiB.
7. **Granted to no one by default**: `tools.DefaultGrant()` unchanged; the five are registered, not granted; a handler lists them explicitly; the **policy** `tool_access` rows still decide per call.
8. **Counted registry bump**: `TestRegistryExactNames` (both want lists, `toolset_test.go`) + `rerun_classes.json` gain the five — count computed from T0's real current number, dated `(S60 MQ17)`; logic untouched.
9. **No decision tool exists**: the catalog has no spec twinned to enqueue-direct, reorder, retry, land, settings, or any of the six registry actions (T8's guard, extended with the positive list of the five).
