# T4 · Branch naming and base resolution: settings used and pinned per loop

**Prefix:** MQ · **Shape:** P2 (Phase B) · **Rules:** MQ15 · **Depends on:** T1, **S44-extra T4** (`EffectiveComponent`).

## Goal

`branch_prefix` and `default_branch` — stored since S38, read by nothing — decide branch names and the base. With empty settings **every T1 golden is
byte-identical**. Names are **pinned on the loop row at `loop.start`** so a later setting change cannot orphan a running loop's branches.

## Files

- `internal/action/git_actions.go` — `BranchNames` gains `Prefix string`; `NewBranchNames(loop, task)` unchanged (empty prefix); **new** `NewBranchNamesWith(prefix, loop, task)` (prefix validated
  `^([a-z0-9][a-z0-9._-]*/)?$`, refusal sentence names the rule); `TaskBranch()`, `FeatureBranch()` prepend it; **new** `IntegrationBranch(item string)` = `prefix+"integrate/"+item` (item id validated;
  used from T5). `branch()` unchanged otherwise.
- `internal/action/args.go` (the `Args` type) — `Prefix`, `FeatureBranch`, `BaseBranch` fields (`Source: "code"`).
- `internal/loop/execute.go` — `actionArgs`: take names via `NewBranchNamesWith(pinned prefix, …)`; `a.Base` = the **pinned** `feature_branch` when non-empty, else the derived name (back-compat for in-flight loops).
- `internal/loop/pin.go` / `daemon/start_loop.go` — at pin time resolve and **write** the loop row's `feature_branch`, `base_branch`, `default_branch`, `branch_mode='standard'` (the first writer those columns have, F14):
  `base_branch` = request/blueprint value → `EffectiveComponent.defaultBranch` → `refs/remotes/origin/HEAD` (read with the scrubbed-env git of `internal/workspace`) → empty. Empty base keeps today's behaviour.
  The prefix comes from `EffectiveComponent.branchPrefix` **once**, stored as part of `feature_branch` (so the prefix is recoverable from the pinned name; no new column).
- `internal/store/loops.go` — `CreateLoop`/pin insert writes the four columns (currently only scanned).
- `internal/action/git_actions.go` `CreateBranch` — when `BaseBranch` is set: `git branch <name> <base-ref>` (`origin/<base>` if present else local); else today's `git branch <name>`.
- `internal/protocol/` — **no wire change** (settings already travel through `component.update`); the loop view may expose `featureBranch`/`baseBranch` read-only if T0 finds the fields already in `LoopView`.

## Behaviour (each a test)

1. Empty settings ⇒ T1's `TestBranchNamesAndBaseGolden`, `TestActionArgsGolden`, `TestLoopRowBranchColumnsEmptyGolden` — only the last changes, from "all empty" to "feature_branch and branch_mode filled" (listed in Notes with its golden diff).
2. `branchPrefix = "aeon/"` ⇒ `aeon/task/<loop>/<task>`, `aeon/feature/<loop>`; the forge ops, `MergePR`'s guard and `IsAncestor` use the **same** names (end-to-end with the `Fake`).
3. **Pinned**: start a loop with prefix `aeon/`, edit the component's prefix to `x/`, advance the loop — branch names still `aeon/…`; a **new** loop gets `x/…`.
4. An in-flight loop pinned before this task (columns empty) keeps deriving names exactly as today.
5. Base resolution order exactly as MQ15; `origin/HEAD` unreadable and no setting ⇒ empty base, today's HEAD behaviour; the queue (T8 `enqueue`) is what refuses an unknown base, not `loop.start`.
6. Invalid prefix refused at `component.update` (daemon seam) with the sentence, and at `NewBranchNamesWith`.

## Tests

| Test | Asserts | Fails when |
| --- | --- | --- |
| `TestNamesByteIdenticalWithEmptySettings` | T1 goldens identical | a default changed |
| `TestPrefixAppliedEverywhere` | git actions + forge guards agree on prefixed names | split-brain names |
| `TestNamesPinnedPerLoop` | mid-loop prefix edit changes nothing for that loop | orphaned branches |
| `TestLegacyLoopWithoutPinStillDerives` | empty `feature_branch` ⇒ derived | in-flight loops break |
| `TestBaseResolutionOrder` | pinned → default_branch → origin/HEAD → empty | wrong precedence |
| `TestCreateBranchFromExplicitBase` | `git branch name origin/main` used when set | still cuts from HEAD |
| `TestPrefixValidation` | refusals | unsafe branch names |
| `TestNoReaderBypassesEffective` (S44-extra's grep test, extended to `branch_prefix`/`default_branch`) | only the resolver reads them | a second reader |

## Definition of done

- [ ] Goldens identical with empty settings; names pinned; the loop columns have a writer; base order proven.

## Do NOT

- Do not change `NewBranchNames`'s signature. Do not read `component.default_branch`/`branch_prefix` outside `EffectiveComponent`. Do not rename existing branches. Do not make the base mandatory at `loop.start`.
