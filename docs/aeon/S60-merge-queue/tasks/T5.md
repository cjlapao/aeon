# T5 · The step-workspace seam, integration worktrees on the S32 ledger, and the git actions

**Prefix:** MQ · **Shape:** P2 (Phase B for the seam) · **Rules:** MQ6, MQ7, MQ8 (git half), MQ9, MQ16 · **Depends on:** T2, T4, **S32 closed** (or T0's recorded closure of its worktree-workspace gap).

## Goal

Git work for a landing happens in its **own worktree**, never in the person's checkout, and a step can be told to run **there**. Four git-level pieces:
the `WorkDir` seam, the `integration` owner on the ledger (reconcile included), `AddIntegrationWorktree`, and three new registry actions
(`git.integrate`, `git.concludeIntegration`, `git.publishIntegration`) plus the typed conflict result.

## Behaviour (each a test, real-git fixture from T1)

1. `integrate`, clean: the integration branch's first parent is the base tip; the person's checkout (`HEAD`, branch, index, working tree) is **byte-identical** before/after (hash of `git status --porcelain=v2 -z` + `HEAD` + a tree hash).
2. `integrate`, two branches editing the same lines: `ConflictError.Paths` equals the planted path list; the worktree has unmerged paths; **the person's checkout is untouched**; the database and event log contain **no** line of the conflicting content (planted sentinel string grep, T7 re-proves end to end).
3. `concludeIntegration` refuses while markers remain, then succeeds after a resolution commit-ready tree; the resulting merge commit has both parents.
4. `publishIntegration` refuses `feature/x`, `task/x/y`, `main`, `integrate/../x`; pushes a new ref; `ls-remote` verified; a second push of the same SHA is a no-op.
5. Crash points: ledger row inserted, `git worktree add` not run ⇒ `ReconcileWorktrees` rebuilds; worktree exists, row `removed_at` unset after a terminal item ⇒ cleanup; directory deleted by hand with the branch present ⇒ rebuilt (the F17 case).
6. `WorkDir`: empty ⇒ goldens identical; set ⇒ the step's `WorkspaceRoot` is the worktree; a parallel unit (if closed here) runs in its own tree (a two-unit fixture writes to the same relative path and both survive).
7. Forbidden verbs: `TestNoForcePushAnywhere` unchanged and green; new sibling `TestIntegrationCodeAddsNoBannedVerb` also bans `rebase`, `reset --hard`, `clean -f` in the new code.

### Deviations (each deliberate)

1. `AddIntegrationWorktree` takes the FULL branch string, not `(prefix, item)` — the
   reconcile rebuild holds only the ledger row.
2. The action arg is named `root` (+`Args.Root = st.ComponentRoot`); `dir` may point at
   a worktree, `root` always the repository — T4's `BranchNames`/settings live on root.
3. `conclude`'s `dir` IS the engine `WorkDir` seam (the integration worktree); so is
   `publish`'s — F11 verifies a push against the tree that carries the branch, so
   `PublishIntegration` refuses a `dir` that does not carry it (message names both).
4. `head_branch` is a `With` key the T7 spec's list omits; `actionArgs` reads
   `With.{item,integration_branch,head_branch}` with NO derivation fallback — recorded
   again for T7 (which supplies them).
