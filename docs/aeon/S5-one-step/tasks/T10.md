>
> ### The 1-2-3-4 order asserted from INSIDE the run
>
> The spy store records every write in order, and the scripted runner takes a hook that runs mid-step. At the
> moment the runtime is working, the store has seen **exactly** `[CreateRunningStep]` and nothing else.
>
> That is what makes S7 possible: a row written only on completion means a crashed step leaves no trace, and
> S7's recovery query is `status='running'` — it finds nothing if nothing was written before the work began. It
> costs one write per step and buys the ability to notice a step that died.
>
> ### Every refusal happens before anything is spent
>
> No workspace root, an empty prompt, an unknown tool, a step that will not compile, an unknown subscription,
> and a store that cannot record the row — each asserted with the runner's call count at zero AND the store's
> write list empty. The unknown-subscription case is the one that would otherwise be silent: ignoring it leaves
> the client waiting for a stream that never arrives, which reads as a hung step after a minute of work.
>
> ### A failed persist does not lose the rest
>
> Each write's failure is collected and appended to the reason; none aborts the others, and `FinishStep` still
> runs. The step ran and spent money, and losing the record of it because one write failed is the worse outcome.
>
> ### Deviation found by the demo walk: the manifest went through a narrowing type
>
> `SaveStepContext` unmarshalled the runtime's manifest into `store.ContextManifest` and let the store
> re-encode, which silently dropped `maxIterations` and every file's `bytes`. `step show --manifest` printed
> `iterations 2 of 0`.
>
> Fixed in both directions — `store.SetContextManifestJSON` stores the bytes, and `store.Step` carries
> `ContextManifestRaw` so the read path does not re-encode either — with a store test that writes BYTES
> containing a field the store's own view does not declare and asserts it survives. **No existing test could
> have caught it**, because every test wrote through the store's own type, which cannot lose a field it declares.
>
> ### K24: the events are ordinary protocol events
>
> S2 already has subscriptions, filters and a cursor, so `step.*` is additive and `PROTOCOL_VERSION` is
> unchanged. The walk found the CLI's filter subscribing to `step.*` ALONE, which dropped `model.delta` — the
> step's actual answer — and printed nothing between "started" and "ok".

## Context

**This handler is the caller that persists** (K22). K6 says the runtime persists nothing, and this names who
does — which matters because it is the arrangement S7 depends on: recovery reads rows itself and calls the same
`RunStep`.

So the persistence is **here and only here** (I3's other half). A grep asserts no other package writes a step
row or a transcript.

**Streaming reuses S2's subscriptions** (K24), exactly as `ask` does. One streaming path for the whole product;
a second would need its own filter, cursor and teardown, and then reconciling at S9 when the app wants both.

**`PROTOCOL_VERSION` must not move.** A new method and new event kinds are additive by S2's rule, and a test
asserts the constant is unchanged. If this addition forced a bump, either the rule is wrong or the addition is
not what it appears to be — and it should be noticed here rather than at S19 with three clients.

**Read first:** `internal/protocol/ask.go` (S3 T10) — the pattern this follows; `internal/store`'s step and
transcript writers (S4 T5, T6); S2's error registry, where this slice's codes are allocated.

## What to do

**1. `step.go`** — params: `prompt` (required), `tools` (optional, defaulting to `["read"]`),
`subscriptionId` (optional), `maxIterations` (optional), `workspaceRoot` (optional, defaulting per Q10).
Result: `stepId`.

**2. The order of operations**, which matters for S7:

- create the step row with `status='running'` **before** calling `RunStep`, so a crash leaves a row recovery
  can find
- call `RunStep`
- persist the transcript, the manifest, the cost and the outcome
- set the final status

**Creating the row first is what makes S7 possible.** A row written only on completion means a crashed step
leaves no trace, and there is nothing to recover.

**3. Persist cost with its state** (S4's DB11) — `partial` keeping its `Missing` list. This is the fourth place
that distinction has to survive, and the first where it is written to disk in this slice's flow.

**4. Stream through S2's registry** when a `subscriptionId` is given, emitting `step.*` events. A
`subscriptionId` from another connection or one that does not exist is a **named error**, not silently ignored —
which would leave the client waiting for a stream that never arrives.

**5. Allocate this slice's error codes in S2's registry**, each with its three parts: unknown tool in the grant
list, missing workspace root, step not found, subscription not found.
