> ### The inherited warning, tested directly

> *"Balanced-span scanning must respect string literals and escapes — a brace inside a JSON string value must not
> end the span. Do not use a regex for strategy 3."*
>
> Two tests: `{"summary":"fixed the {weird} case"}` and `{"summary":"it said \"done {now}\" and stopped"}`. A
> regex counting braces finds the wrong end for both, and the failure is a handoff that ALMOST parses — which
> reads as a model mistake rather than as a scanner bug.
>
> ### Thirteen never-panics cases
>
> A nil transcript, an assistant turn with only a `tool_use`, an unterminated fence, an unmatched brace, a stray
> closing brace in prose, a bare array, literal `null`. Each is something a provider has actually produced, and a
> panic in extraction takes down a step that had otherwise finished its work.
>
> ### Two decisions worth recording
>
> **A ```json fence that does not parse is REPORTED rather than skipped.** The model said it was JSON; falling
> through to strategy 3 would hide a near miss (usually a trailing comma) and the retry would re-ask about "no
> handoff" instead of about the comma.
>
> **Literal `null` is not an empty handoff.** It unmarshals to a nil map, and treating that as an empty object
> would make a model saying nothing look like a model reporting nothing wrong.
>
> ### Validation quotes the value
>
> `handoff.status: expected one of [ok, reject], got "done "` — exact matching, no trimming. Accepting `"done "`
> means the next slice compares a stored status against `"done"` and finds it does not match, and the quoting is
> what makes the whitespace visible. A dedicated test asserts the trailing space is refused AND visible.

## Context

A near-verbatim port, and it should be treated as one. The three extraction strategies encode what was learned
about how models actually emit JSON — fenced, bare, or wrapped in prose — and re-deriving them from first
principles would discard that.

**The retry belongs to the loop, not here** (T8). This module extracts and validates; the loop decides to
re-ask. Keeping that split is what lets the retry's tool-free property be asserted on a **request object** rather
than inferred from behaviour — and that assertion is the point.

Because both halves of K4 matter. One retry bounds the tail: a model that cannot produce valid JSON twice will
not produce it on the fifth attempt, and each attempt costs money. **Tool-free is the more important half** — a
retry that can call tools **can start new work.** A step that already did its job could do it again, differently,
while ostensibly just restating its report.

**The three strategies, quoted from the v1 source** (plan Q1) — extraction order, **first match wins**:

> 1. the **LAST** ` ```json ` fenced block
> 2. the **LAST** ` ``` ` fenced block whose body parses as JSON
> 3. the **LAST** balanced top-level `{...}` span in the text
>
> *"**Last** throughout, because a model that reasons before answering emits example objects first and its real
> answer last."*

**That "last" is the whole point, and it is the part most likely to be lost in a port.** Taking the first match
returns the model's worked example instead of its answer — and the failure is silent, because an example is
usually well-formed JSON that validates.

**Strategy 3 is not a regex.** Balanced-span scanning must respect string literals and escapes: a brace inside a
JSON string value must not end the span.

**Read first:** `context.go` (T2) and `internal/model`'s message types.

## What to do

**1. `handoff.go`:**

```go
func ExtractHandoff(msgs []model.Message) ExtractResult   // { OK, Raw json.RawMessage, Reason }
func ValidateHandoff(raw json.RawMessage, schema Schema) ValidateResult
```

**2. Implement the three strategies** in the order above, stopping at the first that yields parseable JSON.
**Quote each strategy's description as a comment above its implementation**, so a reader can check the port
against the rule rather than against another document.

**3. Validate against the handler's schema.** A mismatch names the **failing path** —
`handoff.status: expected one of […], got "done "` is actionable; `validation failed` is not.

**4. Never panic.** `nil`, an empty slice, malformed JSON, a message with no text — each returns a result.

**5. This module performs no model call.** Assert it with a `Client` spy at zero.

**6. Tests:** one realistic case per strategy; order and short-circuiting; a schema mismatch naming its path;
extra keys rejected where the schema forbids them; and the totality table.
