# T5 — `tools/paths.go` and `read.go`

> ## Notes — done 2026-10-16
>
> ### Built: `paths.go` (243 lines), `read.go` (228), `tools/limits.go` (115), two test files
>
> **One resolver, and every refusal has a case**: empty, absolute, traversal, escape, unresolvable — plus a NUL
> byte and a backslash-separated traversal, because a path cannot be checked for `..` by splitting on `/` alone
> when a model trained on Windows paths sends `docs\..\..\outside`.
>
> ### Three decisions the tests are built around
>
> **`..` is refused IN THE INPUT, before cleaning.** `a/../a.md` resolves back inside the workspace and is still
> refused: a cleaned path has had its escape resolved away, so the check would be about a different string than
> the one that arrived.
>
> **The containment check uses `filepath.Rel`, never a prefix.** A prefix comparison says `/workspace-evil` is
> inside `/workspace` — the oldest bug in this family, one character of difference. There is a test with a
> look-alike sibling directory and a symlink pointing at it.
>
> **The ROOT is resolved too.** Found by a failing test on macOS, where `/tmp` is a symlink: resolving only the
> candidate makes every path look like an escape. The test builds a symlinked root and asserts an inside path
> still resolves.
>
> ### `resolveExistingPrefix` walks UP, and the reason is a write tool S5 does not have
>
> `EvalSymlinks` is all-or-nothing: given a missing leaf it reports IsNotExist and resolves nothing. So a resolver
> that gave up there would accept `escape/new-file.txt` through a symlinked directory — a write, through a
> symlink, to outside the workspace. There is a test for exactly that, and it is the reason the resolver is more
> complicated than it first looks.
>
> ### `read` reports the TRUE size when it truncates
>
> D9. "Truncated" alone cannot tell a model whether it is missing a line or a megabyte, and the note comes BEFORE
> the content: a truncation notice after 64 KiB of text is a notice nobody reads. Both asserted.
>
> An offset past the end says so, with the file's line count. Empty content with no explanation reads to a model
> as an empty file, and it will conclude the file is empty and move on.

## Context

**One resolver, and it lands before any file tool** (R5, I1). A second resolution path is a defect rather than
duplication: the two diverge, only one gets tested, and the divergence is an escape that works.

**The symlink check runs after resolution** (O3). A pre-resolution check sees `notes.md` and passes; the symlink
then resolves to `/etc/passwd`. That ordering is the escape this class of bug always uses, so resolve first and
compare the result against the workspace root.

**Every refusal is by attempt and never a clamp** (D11). A path silently normalised into range turns an escape
attempt into a successful write somewhere unexpected — and it looks exactly like the feature working. These paths
come from a model, not from a person.

**No ambient state** (I5). No `os.Getwd`, no `os.Getenv`. The workspace root arrives in `ToolContext`. This is
the invariant whose violation reintroduces path drift, and it passes review because the code works on the
author's machine.

**Read first:** `docs/_archive/aeon-v1-horizontal/05-tools/tasks/T1.md` and `T2.md`, which this ports; the plan's Q5 on
`filepath.EvalSymlinks` behaviour for a path that does not exist; Q7 on where the root comes from.

## What to do

**1. `paths.go`:**

```go
func Resolve(root, rel string) ResolveResult   // { OK, Abs string, Reason string }
```

Refuse, each with its own reason: an absolute input; any `..` segment **in the input**; an empty input; and — after
`filepath.EvalSymlinks` — a resolved path outside `root`.

Handle the not-yet-existing path case (Q5): a `write` target need not exist, so resolve its **parent** and check
that. State the behaviour in a doc comment.

**2. `read.go`** — the `read` tool. Parameters: `path`, optional `offset` and `limit`. Returns file content as a
tool result, **capped** per `limits.go`, with truncation **reported carrying the true size** (D9).

A tool result is a string with `IsError` (W14) — a tool that failed must be distinguishable from one that
returned the text "error".

**3. Honour `ctx`.** A cancelled step stops a large read promptly.

**4. Tests as refusals, by attempt.** Four reasons, four tests, each calling the tool with the offending path and
asserting a named tool error. Then the symlink case specifically: create a symlink inside the workspace pointing
outside it, and assert the refusal happens.
