# T4 — the wiring

## Why this exists

P34: one service value behind all doors. The daemon builds exactly one
`*asyncworkers.Manager`, registers the `graph.build` runner on it (the
existing `graph.Service.Build`, its `BuildReport` marshalled into the
row's `result`), hands it `d.publish` so events ride the EventLog and
the subscription rails like every other kind, and points
`Table.AsyncWorkers` at the same pointer. Recovery (`Recover`) runs in
`serve`'s recovery pass — interrupted rows get their spoken reason and
a count in the startup log; `Shutdown` drains workers before terminal
cancel. The storeless daemon gets the honest nothing: no seam, family
absent, `graph.build` refuses naming the manager, and the write-hook
falls back to a direct Build.

## Notes

2026-10-30. 3 tests (`asyncworkers_test.go`): the pointer-equality pin
(`reflect.Pointer` on `Table.AsyncWorkers` vs `Workers()`), the full
build through the real socket dispatch on a tiny Go project (`*
GraphBuildAccepted`, id `aw_`+32, row reaches `finished`,
`BuildReport` decodes with nodes ≥ 1, event kinds start `started` and
end `finished` when read back from the EventLog), and the storeless
absence. `notifyGraph` now starts a `graph.build` worker for unbuilt
roots (deduped by root, metadata `{"trigger":"write-hook"}`).
`aeon graph build` follows to a terminal state (1s polls on
`asyncworkers.get`, 35-minute budget, progress lines on change) and
prints the BuildReport from the row — the CLI's blocking UX preserved
by composition, not by a blocking verb. Measured live at T6.
