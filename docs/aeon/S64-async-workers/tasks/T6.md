## Notes

2026-10-30, walks run against a real `aeon serve` (binary built with
`-tags sqlite_fts5`, `XDG_RUNTIME_DIR`/`XDG_STATE_HOME` pointed at a
throwaway sandbox dir — the socket bound at
`.tmp/xdg-run/aeon/rpc.sock`, migrations applied, "aeon is ready"):

1. **Finished, end to end (19:25 UTC).** `aeon graph build --root
   .tmp/demo-proj` → CLI printed `graph built … 1 files (0 skipped), 3
   nodes, 2 edges, 0 references unresolved`, exit 0 — started through
   the ledger, followed at 1s polls, report read back from the row. Raw
   socket `asyncworkers.list {workerType:"graph.build"}` answered the
   finished row with the full BuildReport inside `result`, `workerId`
   `aw_0892905a…`, all three timestamps RFC3339 UTC, `types:["graph.build"]`.
2. **Interrupted (19:26 UTC).** Started the big-root build

   aeon serve`, exit 1), restarted → startup log
   `async-worker recovery: 1 worker(s) marked interrupted`;
   `asyncworkers.list {states:["interrupted"]}` returned the row —
   `error:"daemon stopped before the worker finished"`, no auto-restart.
3. **Cancelled (19:30 UTC).** `graph.build` on the socket answered
   `{workerId:"aw_e4c1547b…", state:"queued", started:true}` in well
   under a second on a big repo — the ten-minute verb became a handle.

   `cancelRequested:true`; two seconds later `asyncworkers.get` showed
   the terminal row: `state:"cancelled"`, `error:"cancelled"`,
   `finishedAt` set. Cancel is the ledger's only write door and it
   answered like the row, not like a promise.
