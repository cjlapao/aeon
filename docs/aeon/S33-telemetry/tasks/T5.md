# T5 · Compaction rows

**Prefix:** TL · **Rules:** TL7 (D3) · **Depends on:** T2.

## Goal

Every `CompactionRecord` becomes a queryable `step_compaction` row (not only the existing
`Checkpoint.Compactions` blob, which stays, byte-identical, for whatever already reads it), **and** gains a
durable `event` row — the first step-level event this codebase has ever persisted through `AppendEvent`
(design.md TL7: the third call site overall, correcting the brief's "second" by one).

  `Checkpoint.Compactions` (`VERIFY` current line, cited near `:111` for the type, the append call itself
  is elsewhere in the same file), add `d.Telemetry.RecordCompaction(ctx, stepID, rec)` (nil-guarded, same
  pattern as T3).
- Wherever the daemon already calls `AppendEvent` for comparable purposes (`cmd/aeon/store_verbs.go:927` or

  add one if none fits, following whatever naming convention the existing kinds use).
- `internal/runtime/compact_test.go` — the tests below.

## Definition of done

- [ ] `step_compaction` rows match the existing blob exactly, for every compaction.
- [ ] A durable `event` row exists per compaction and survives a restart.
- [ ] Nil-safety proven.

## Do NOT

- Do not remove or change `Checkpoint.Compactions` — this is additive, a second queryable home for the
  same fact, not a replacement.
- Do not invent a new event *transport* — use the existing `AppendEvent`/`event` table exactly as the two
  prior call sites do.

## Notes (2026-10-30, built in worktree branch `s33-telemetry`)

**Capture at the one append point**: `compact.go` calls
`deps.Telemetry.RecordCompaction(ctx, st.Request.StepID, record)` immediately
after `st.Compactions = append(...)` — nil-guarded as T3's turn capture, and
a failure is an accounting hole SPOKEN (`step.telemetry.error`), never a
compaction undone: the transcript has already been rewritten at that point,
so the compaction stands and the blob stays the byte-identical replay unit
it always was (the Do-NOT; `TestCompactionCaptureIsNilSafe` compares the
blob's values across nil-vs-wired runs of the same scripted compaction).

**The durable event lives in the daemon adapter, not the two file candidates
the task guessed.** The task pointed at `cmd/aeon/store_verbs.go` or
`internal/daemon/memory.go` "wherever is closer in shape"; both are further
than `telemetry_seam.go`'s `RecordCompaction` itself — the adapter IS the
compaction-time write, so the `AppendEvent` rides there: row first (the
step_compaction insert), then `ReadStep` for the loop slug and component
root, then `AppendEvent` — this codebase's THIRD AppendEvent call site,
design.md's count corrected as the task predicted. A failure of either half
returns an error the runtime turns into the spoken event; row-then-event
ordering means an event never exists without its row.

**Kind `step.compacted` is a durable-store kind only — deliberately NOT
registered in protocol's notification `Kinds()`.** That list is the live
stream's contract and `TestEveryEventKindHasAFixture` demands a notification
fixture per entry; this row exists for `history` and for surviving restart,
like the debug hammer's kinds. The runtime's live `EventStepCompacted`
emission is untouched — same string, two independent channels, neither
derives from the other.

**Payload = measurement, never prose**: `{stepId, start, end,
estimateBefore, estimateAfter, summaryChars}` — the same one-copy rule as
the row (TL7's length-instead-of-text), asserted by refusing to find the
summary text inside the payload bytes.

**The tests drive REAL machinery.** The daemon tests run
`runtime.RunLoop` over a history whose `Route.ContextWindow` forces the
runtime's OWN selection to buy a summary (`scriptedModel` turn 0 is that
summary) through the production adapter on a real store — a hand-planted
`CompactionRecord` would have tested only the accessor. Row values must
match `res.Compactions[0]` EXACTLY (start/end/estimates/summary length);
restart test closes the store and reopens the same directory, asserting the
event still carries its `seq`.

**`TestStepCompactionJoinableAcrossHistory` lives in the store package
(raw SQL is legal there), not daemon**: two loops → two steps under one
component, one join `step_compaction JOIN step WHERE component_root = ?`
returns both rows ordered by step. Deliberately NO new production accessor
— nothing reads compactions-by-component yet (T8's tiers don't ask), and an
accessor built for the test would be a second truth waiting for a caller;
the raw join still proves the FK direction and the index the claim needs.
