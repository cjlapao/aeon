## Notes (2026-10-30, built in worktree branch `s33-telemetry`)

**Q3, answered by measurement: NO bracket existed.** `grep 'd.Clock()'
loop.go` finds exactly two users before this task: RunLoop's per-iteration
deadline check (loop.go:217) and `emit()`'s event stamping (loop.go:925) —
neither straddles `d.Client.Stream`. So the bracket is NEW: one pair of
`d.Clock()` reads around the call inside `stream()`, taken **only when
`d.Telemetry != nil`** — with the seam off, `stream()` performs exactly the
clock reads it performed before the slice (I2), and the step spends no
instrumentation cost on a feature it never asked for.

**Capture point:** immediately after the four accounting lines
(`st.Usage = addUsage(...)` … `st.ThinkingDropped +=`), **before** the
`streamErr` return — the capture inherits M15 rather than re-implementing
it: a failed part-way call still spent what it spent, and the row records
what it spent (`TestCaptureSurvivesAFailedCall` proves the error path is
not a second, stricter gate). One row per model call, category
`assistant_output`, route = `st.Request.Route.ID`, wall from the bracket.
`iteration` is the loop's one-based number — the same the `model.delta`
events carry, pinned explicitly in the test.

**Capture failure is spoken, never fatal.** New additive runtime event
kind `EventTelemetryError` (`step.telemetry.error`) with `IsError: true`;
`TestCaptureFailureIsSpokenNotFatal` proves the step still ends OK with the
sink refusing to write, AND the stream says which turn went unrecorded —
an aggregate that silently reads complete while a turn is missing is the
exact wrong-number this event exists to prevent. The protocol step handlers
forward `e.Kind` verbatim (step.go:708/868/908) — additive kind, no
whitelist to widen, old clients ignore what they don't decode.

**D2's pair, two homes by design:** `(*LoopState).CurrentContextTokens()`
(loop.go) is the live number through the ONE estimator that already decides
compaction's threshold (compact.go's `EstimateTokens(st.Messages)` —
reused, not recomputed, per the task's VERIFY note); the CUMULATIVE is the
store's `CumulativeTokensTotal` SUM over `step_turn` rows (built in T1),
not a second in-memory accumulator — `st.Usage` already is that memory
total and the rows outlive the process.
`TestCurrentAndCumulativeAreDistinctNumbers` lives in
**internal/daemon**'s seam test (it needs both sides: the runtime accessor
and the store's SUM; internal/runtime's K22 keeps the store out of its own
tests entirely, even test files) — a post-compaction state (small
transcript + a `Compactions` row as the evidence) with 42,300 tokens of
captured turns: current small-and-positive, cumulative the rows' sum,
provably unequal.

**T2's vacuity check superseded, honestly:** `TestNilTelemetryIsANoOp`
asserted the sink stayed EMPTY because T2 added no call sites; with T3's
first call site live, that assertion would be testing the past. It now
asserts the invariant that survives — nil vs wired changes outcome,
transcript and accounting identically — with the positive control moved to
T3's own test where a call site exists to control.
