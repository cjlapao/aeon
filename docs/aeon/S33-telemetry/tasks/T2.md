## Goal

A new interface in `internal/runtime`, nil-safe exactly like `SteerSource`/`PolicyGate`, added to both
`LoopDeps` and `RunOpts`. This task adds the interface and wires a real adapter at every production site —
**it adds zero capture calls**. T3/T4/T5/T6 each add their own `d.Telemetry.RecordX(...)` call, guarded by
the same nil-check pattern, inside their own task.

## Notes (2026-10-30, built in worktree branch `s33-telemetry`)

**What exists.** `internal/runtime/telemetry.go`: the `TelemetrySink`
interface (TL12's four methods), `SectionCategory` + the four constants +
`SectionCategories()`, and the I2/nil-means-off contract written down.
`LoopDeps.Telemetry` and `RunOpts.Telemetry` fields, documented beside
`Steers`/`Policy`; forwarded at the three internal conversion sites
(runstep.go's `RunStep` literal, resume.go:41, recover.go:45's CaseC —
recover.go:144's `recoveryFailed` literal needs none: it builds a `failed()`
result only, no model call runs there). `internal/daemon/telemetry_seam.go`:
`newTelemetrySink(*store.Store) runtime.TelemetrySink` — nil store answers a
**nil interface** (a non-nil interface holding a nil store would turn a
skipped capture into a panic; `TestNewTelemetrySinkNilStoreIsNil` pins it).

**Signature deviation, recorded — `RecordTurn` carries `route string`
besides TL12's listing.** TL5's DDL makes `route` NOT NULL ("routes can
change mid-loop, S18") and the only place that fact exists is beside the
call; a row that cannot name its route after the fact is an aggregate
pretending to a detail it never captured.

**`SectionCategory` lives beside the interface, not in types.go's
SectionSpec block** (the design's placement guess). One vocabulary serves
both hook points TL6 names — SectionSpec classification (T4) and
transcript-append tagging (T3/T6) — and defining it at the interface keeps
runtime's own type file out of it until T4 adds the field.

**The four production wirings (plan.md Q2's answer, all measured):**
`internal/protocol/step.go`'s run literal and resume literal (`Telemetry:
t.Telemetry`), `internal/daemon/recover.go`'s recovery literal
(`newTelemetrySink(d.store)`), and `daemon.go` sets `table.Telemetry =
newTelemetrySink(opts.Store)` — the same adapter object through both doors.
`TestAllProductionSitesWireTheRealAdapter` is AST-based, not line-grepped:
it walks every `runtime.RunOpts{…}` composite literal in
internal/protocol + internal/daemon (tests excluded) and refuses an OMITTED
`Telemetry` — an omitted field and a deliberate `Telemetry: nil` compile
identically and state different decisions; only the second may exist. The
scan carries a `sites >= 3` lower bound so a rotted scan fails too.

**The one guard amended deliberately:** `TestRunOptsHasNoStoreShapedDependency`
gained `"Telemetry": true` with the argument its own failure message invites
("add it to this list deliberately"): TelemetrySink is a package-local
interface the caller implements — the Policy/Steers shape — the runtime
imports nothing new, and K22's import guard remains the proof.

**`ctx` parameters are accepted and unused at the adapter** — the store's
layer has no per-call context (one writer pool, Q7's finding); they exist so
the runtime can honour cancellation/propagation at T3+ capture sites
without a signature change.
