# T8 · The socket reads

**Prefix:** TL · **Rules:** TL10, TL11 · **Depends on:** T1, T7.

## Goal

Four read-only methods, public like `policy.*`/S34's reads, **designed as the primary surface for this
data** — a future agent calling `telemetry.component` to size a project gets the same answer a human reading
the (not-yet-built) UI tab would. No write methods; this slice mutates nothing a caller asks it to.

## Files to create / modify

- `internal/protocol/method.go` — `MethodTelemetryLoop`, `MethodTelemetryComponent`,
  `MethodTelemetryProject`, `MethodTelemetryWorkspace` (`"telemetry.loop"`, `"telemetry.component"`,
  `"telemetry.project"`, `"telemetry.workspace"`), registered after S34/S35/S36's blocks (`VERIFY` the real
  current tail). `RequiresInitialize: true`, not `Debug` — these are product reads an agent or the app

  local-interface pattern S35 T3 used for `ProposalStore` — `internal/store` is not banned from

  (store.ComponentTelemetry, error)`, `ProjectTelemetry(id string) (store.ProjectTelemetry, error)`,
  `WorkspaceTelemetry() (store.WorkspaceTelemetry, error)`, plus whatever `telemetry.loop` needs for the
  live detail (per-turn rows, D2's two numbers — likely a richer method than a single struct read; shape
  it against T1's/T3's real accessors, not a guess written here).
- `internal/daemon/daemon.go` — `Table.Telemetry TelemetryStore` field, wired via a small adapter beside
  `stepStore`/`proposalStore` (S35 T3's precedent): `telemetryStore(s *store.Store) protocol.TelemetryStore`.

## Notes (2026-10-30, built in worktree branch `s33-telemetry`)

**The table field is `TelemetryReads`, not the task's `Telemetry`.** T2 already
took `Table.Telemetry` for the runtime's WRITING sink; the slice's one rule —
writes at the capture seams, reads at the wire — is now literally two fields,
and the naming says which way each faces. Everything else landed as specified:
four consts registered as a block in `method.go`, the local-interface seam
`TelemetryStore` in the new `internal/protocol/telemetry.go` (store types in
the signatures exactly as the S35 T3 ProposalStore precedent allows), and the
daemon adapter in the new `internal/daemon/telemetry_reads.go`.

**`LoopTelemetry` is the one method the adapter assembles** — and it assembles
the one number the protocol layer could not compute itself: `currentContextTokens`
is `runtime.EstimateTokens` over the transcript rows, THE same estimator
compaction's budget runs on, so the wire's "next call would carry" and the
runtime's own sizing can never disagree. It lives in the adapter because
internal/daemon is the only layer that may know both runtime and store. Paging:
`StepTurns` is T1-capped (default 100/page), so the adapter walks pages to the
end — a truncated history read would quietly understate a loop. An
unparseable transcript REFUSES the loop read rather than fabricating a current
estimate of 0; cumulative-only readers do not get to launder that (P31), and
D2's pair is atomic — both numbers or neither.

**D2's drift, caught by the daemon end-to-end test, in writing:** my first
assertion folded the compaction row's usage into `cumulativeTokensTotal`. TL11
defines the field verbatim as *"the same number `step_turn`'s rows sum to"* —
T1's SQL honors that, and RecordStepCompaction bumps the ROLLUP tiers with the
summary's usage without making it a step_turn row. The fixture, the doc
comment and the assertion were all corrected to the design; the daemon test
now asserts the boundary and says why (folding compaction in would change
D2's meaning).

**`telemetry.workspace` answers absence as data** (`exists:false`) while the
id-bearing reads REFUSE with the id in the sentence (new typed error
`ErrNoTelemetry`, -31801, registered + error fixture) — TB2's rule, with the
one justified asymmetry: a singleton has no id to mistype.

**Guards walked:** handshake want-list += the four (with their S33 block);
conformance `paramsTypeFor`/`resultTypeFor` cases added the way S30's graph
family did (the loop fixture's `step` object must round-trip `store.Step`
EXACTLY — `cost`, `endedBy`, `source` are no-omitempty fields; the fixture
carries them and the round-trip test caught the first version that omitted
