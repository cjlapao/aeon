## Q1 — can `step.wall_ms` be NULL on a settled step?

Before deciding whether `*_telemetry.wall_ms_total` needs a three-state companion column: `VERIFY: grep -n
'wall_ms' internal/store/*.go internal/daemon/*.go | grep -v _test` and read every writer. Record in Notes:
does a crashed-and-recovered step (S7's Case B/C) ever settle with `wall_ms` unset, or does recovery always
produce a number (possibly a lower bound, still a number)? If every writer always sets it, `wall_ms_total`
stays plain `NOT NULL`. If a genuine NULL-producing path exists, add `wall_ms_state TEXT NOT NULL DEFAULT
'known' CHECK (wall_ms_state IN ('known','partial','unknown'))` beside it at every tier, same discipline as
`cost_state`.

## Goal

## Notes (2026-10-30, built in worktree branch `s33-telemetry`)

**Q1 — answered: `step.wall_ms` has NO writer in the codebase.** Measured:
`grep -rn 'wall_ms'` over `internal/store internal/daemon cmd/aeon` finds the
column only in the DDL (`schema.go` 0002) and one SELECT (`steps.go:194`); no
INSERT or UPDATE ever sets it, `agent_ms` likewise. Every step's `wall_ms` is
NULL, settled or not. Nothing in this slice reads it: every rollup wall total
sums `step_turn.wall_ms`, measured at the capture site and NOT NULL by
construction, so design TL9's conditional — "carry a `wall_ms_state` column
beside it if any such case exists" — resolves to **no companion column at any
tier**. `TestTheRollupWallSumsNeverReadStepWallMs` is not needed because no
statement reads it at all (verified by the same grep, in the record).

**Migration:** file-form per the 2026-10-30 amendment —
`internal/store/migrations/20261030084236_telemetry.sql`, all seven tables.
No schema.go edit, no count bump: `store_test.go` counts `len(Migrations())`
dynamically and `TestAFreshSchemaAndAnUpgradedSchemaAreIdentical` stayed green.

**Deviation, measured — `category` on `step_turn`.** design.md TL5's DDL has
no category column while TL12's `RecordTurn` carries one and TL6 tags
transcript turns at their append points; the row needs a home for what its
method carries. Added `category TEXT NOT NULL CHECK (… four closed values)`;
`tool_schema` stays absent (TL6). `RecordStepTurn` refuses a fifth value by
name before the CHECK hears about it.

**Deviation, measured — no `RecordSections` door exists, and none was added.**
The two context-side categories (`system_prompt`, `injected_context`) are
carried by `SectionSpec`/`ContextManifest` (T4) and reach the store through
the checkpoint the runtime ALREADY writes (`step.context_manifest`);
`StepContextManifest` hands the bytes to `telemetry.loop`, which decodes via
`runtime` (the type's owner). Transcript rows land in `step_turn` with
`assistant_output`/`tool_result`.

**`loops_run`'s unassigned write path.** TL9 names the column; no task names
its writer. It bumps in `CreateLoop`'s own transaction (the loop row is born
when a run starts; TL2's same-write rule), unregistered-root loops count
nowhere — the same attribution rule as every `RecordX` bump. Pinned by
`TestLoopsRunBumpsWithTheLoopRow`.

**I1 keeps `CompactionRecord` out of `internal/store`.** plan T1's
`RecordStepCompaction(stepID, rec)` cannot take the runtime type — the store
imports only `internal/model` — so it takes the record's fields; the daemon
adapter (T2) unrolls `runtime.CompactionRecord` at the seam.

**Non-spend rows do not speak to cost.** `tool_result` turns and file/command
rows insert and bump their own counts but contribute NO cost state — a tier's
`cost_state` is floored only by model-call contributors (turns, compactions).
Pinned in `TestCostStateFloorsAcrossContributors`.

**Three repo guards touched, deliberately:**
- `store_test.go`'s model allow-list gains `Usage` (TL5 mirrors `model.Usage`
  exactly; a store-owned copy would be the second definition M9 exists to
  prevent).
- `steps_test.go`'s cost-grep re-pointed at what the rule protects —
  `UPDATE step SET … cost_*` — the bare `cost_state =` pattern fired on the
  rollup tier's own D9 lattice columns, a name collision, not a step write;
  steps.go's single-writer half of the guard is unchanged.
- `store.go`'s surface table gains the S33 row (the every-exported-method pin).
