## Notes

**Implemented 2026-10-31 (this turn, sequentially — ≤3–4 files per step).** The project API is fully
removed and the socket speaks the tree:

- **Removals.** `project.*` and `telemetry.project` are gone from the socket (`MethodProject*` /
  `MethodTelemetryProject` and their registrations removed; `Table.Projects` deleted; `daemon/projects.go`,
  `protocol/projects.go`, `cmd/aeon/project_verbs.go` deleted). No residual `project.*` method reference in
  non-test Go (grep clean). The `telemetry.project` method is **kept** — it is the telemetry tier (the slice's
  own note), not the removed project API; its `ProjectID` wire field is the only `projectId` left in
  `contract.ts`.
- **Renamed wire fields (CT8).** `protocol/goals.go` `GoalView.ProjectID`⇒`RootID` (`rootId`);
  `protocol/tasks.go` `TaskListParams.Project`⇒`Root` (`root`); `protocol/triggers.go` `ProjectID`⇒`RootID`
  on view/list/create. Consumers fixed: `daemon/records_socket.go` `GoalShow` (`RootID: g.ComponentID`),
  `daemon/records.go` identity + scope checks, `daemon/triggers.go` `triggerView`/list/create + `checkScope`,
  `cmd/aeon/goal.go` + `task.go` (`--project`⇒`--root`, `projectId`⇒`rootId`), `internal/records/catalog.go`
  (schemas `project_id`⇒`root_id`), `internal/records/catalog_test.go`.
- **Two latent bugs found and fixed while renaming.** (1) `records.go` `Identify` stamped
  `ProjectID: comp.ParentID` — empty for a standalone root — and `goalCreate` used it as the goal's
  `ComponentID`; now `RootID` via `store.RootOf` (the tree's root, not the parent). (2) `candidatesFor`
  (`blueprint.go`) listed goals on the workspace's **child** component; goals hang on the **root** (CT10), so
  it now resolves `RootOf(comp.ID)` and lists goals there. Both were the root cause of the 3 unmet-requires
  daemon failures.
- **Trigger scope.** `checkScope(rootID, componentID)` checks both ids of the scope (a ghost root or a ghost
  component refuses with `no component "…"`); the trigger write test's project case rewritten against the
  component tier; `internal/store/ctcensus` exempted from the one-caller walker (a characterization builder,
  not a production door).
- **Contract chain.** Conformance fixtures `projectId`⇒`rootId` / `project_id`⇒`root_id` (records, store,
  goal, trigger, automation fixtures; `telemetry/project.json` and `learnings`/`store/info` left untouched as
  kept/literal). `make protogen` regenerated `ui/src/proto/contract.ts`; `make check-protogen` green
  (exit 0) — the only `projectId` left is the kept `telemetry.project`. Daemon/records goldens regenerated
  (the untracked T1-era goldens deleted and re-written by the write-if-absent tests).
