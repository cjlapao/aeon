# T3 · Migration B: re-key epics, goals and automation; drop `project`

**Prefix:** CT · **Rules:** CT5 (B), CT10, CT11 · **Depends on:** T2. **Merges with T2 and T4.**

## Goal

Every reference to a project id becomes a reference to a root component id, through the map T2 left; then
`project_telemetry`, `project` and the map are dropped. After this migration no table, column or FK names the old
group.

## Files

- `aeon/internal/store/migrations/<timestamp>_project_rekey.sql` — **new** (timestamp after T2's).
- `aeon/internal/store/ct_migration_b_test.go` — **new**.

## The SQL, in order

1. **`epic` rebuild** — `epic_new` = current columns with `project_id` replaced by `component_id TEXT NOT NULL
   REFERENCES component(id)`; values `SELECT m.component_id … JOIN zz_ct_project_map m ON m.project_id = e.project_id`.
   Children of `epic` (at least `goal.epic_id`; T0's FK list) are parked/restored as in T2. Copy guard.
   Index `idx_epic_component (component_id)` (none existed; list reads filter by it).
2. **`goal` rebuild** — same, `project_id` ⇒ `component_id`; children parked: `goal_component` (CASCADE — the hazard),
   and whatever T0 found (`brief.goal_id`? `attachment`?). Copy guard. Index `idx_goal_component (component_id)`.
3. **Root-only triggers** — `epic_root_only` and `goal_root_only` (BEFORE INSERT / BEFORE UPDATE OF component_id):
   abort `'component tree: epics and goals belong to a root component'` when the target has a parent.
4. **`goal_component` membership** — no trigger (the store enforces CT10's "root or its children" with a sentence;
   a migrated goal's members already satisfy it by construction — a test proves it on the census).
5. **Automation** — `ALTER TABLE automation_event RENAME COLUMN project_id TO root_id`; `ALTER TABLE event_trigger
   RENAME COLUMN project_id TO root_id`; `UPDATE … SET root_id = (SELECT component_id FROM zz_ct_project_map WHERE
   project_id = root_id) WHERE root_id <> ''`. **VERIFY** the `automation_event_manual_only` trigger and the
   `automation_event_subject` index survive a column rename untouched (they do not name the column — T0 confirms).
6. **Stored match JSON** — rewrite each `event_trigger` match whose object has a `project` key: new object with key
   `root`, each value mapped through the map, other keys unchanged, canonical key order preserved as
   `store/trigger_match.go` produces it (T0 records the canonical form and the exact column). Prefer one `UPDATE`
   using `json_object`/`json_each`/`json_group_array`; if the canonical ordering cannot be produced in SQL, the
   migration refuses to run with a clear message and T3 instead adds a **one-time Go data step** registered beside the
   migration — **decide in T0**, record which.
7. **Drops** — `DROP TABLE project_telemetry; DROP TABLE project; DROP TABLE zz_ct_project_map;` — after verifying no
   FK still targets `project` (a guard over `pragma_foreign_key_list` of every table).
8. **Final guards** — fk guard; "no column named `project_id` remains" guard (over `pragma_table_info` of every table,
   excluding none — `loop.scope` is a column named `scope`, not `project_id`).

## Definition of done

- [ ] Epics, goals, automation events, triggers re-keyed; every child row kept; guards physical.
- [ ] `project`, `project_telemetry`, the map gone; no `project_id` anywhere; fresh == upgraded.

## Do NOT

- Do not change a trigger's semantics beyond the key rename and id mapping. Do not drop `project` before every FK to
  it is gone. Do not edit a shipped migration.

## Notes

**Built 2026-10-30 — merge-unit intermediate; T4 (the store rewrite) is required for the runtime to be green. T2–T4 are one unit.**

`aeon/internal/store/migrations/20261030200001_project_rekey.sql` (timestamp after T2, so it applies after). One transaction over the store's `_foreign_keys=1` connection; reads the map T2 left.

Does: rebuilds `epic` (`project_id` → `component_id` REFERENCES `component(id)`, values via the map; `goal` is parked around the swap because `goal.epic_id` references `epic`); rebuilds `goal` the same way (`goal_component` — the CASCADE hazard — is parked around the swap); installs `epic_root_only`/`goal_root_only` triggers (an epic/goal may only attach to a root, CT10); renames `project_id` → `root_id` on `automation_event` and `event_trigger` (their trigger/index do not name the column) and re-keys the value through the map; rewrites each stored match JSON's `project` key to `root` through the map; drops `project_telemetry`, `project` and the map; installs the fk / no-`project_id`-column / no-FK-to-`project` guards.

**Deviation (recorded per §4a, the spec's own allowance):** the stored-match-JSON rewrite in this migration maps the values and produces a valid JSON, but the exact *canonical byte form* (empty lists omitted, sorted) is a one-time Go data step — step 6's fallback in the spec. The SQL form maps the values so no match silently stops matching (the hazard the rule guards); the canonical bytes are a follow-up.

Validation (env preamble AGENTS §6, `XDG_STATE_HOME=$(mktemp -d)`):
- the migration applies on a fresh store (after T2): `pragma_foreign_key_check() = 0`; `project`, `project_telemetry` and `zz_ct_project_map` are dropped; `epic` and `goal` have `component_id`; `component` has no `project_id`.
- `go build ./...` green.
