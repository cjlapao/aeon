# v1 UI port inventory

This inventory covers every module under `packages/loop-state-ui/src`. The source package is read-only for S9. `copied` means code is in `aeon/ui/src`; `adapt` means the concern is implemented against S8's contract rather than copied with v1's types; `excluded` means it does not belong in the daemon-backed app. The adapted compositions are exercised by `test/product.test.tsx`, and the port boundary and inventory by `test/port.test.ts`.

Aeon's own `components/ErrorPanel.tsx` and `components/TabBoundary.tsx` came from S1–S4 and are covered by `test/bridge-errors.test.tsx` and `test/boundary.test.tsx`. `components/ConnectionPill.tsx` is the S1 connection surface adapted by S9. `components/kit.tsx` sets Aeon's glass default for kit surfaces while retaining explicit per-control variants. The `features/` compositions replace v1's phase, task and HTTP-shaped pages with the S8 pinned loop state; they use `@cjlapao/ui-kit@0.2.3`. [The source layout](src/README.md) describes the route and feature boundaries.

Aeon's own agent chat, `components/agent-chat/` (2026-10-24), is new rather than ported: v1 had no chat. Its files — `components/agent-chat/AgentChat.tsx`, `components/agent-chat/ChatStream.tsx`, `components/agent-chat/ChatComposer.tsx`, `components/agent-chat/MessageComposer.tsx` (the field the S67 skill chips and S69 attachment previews ride on; `ChatComposer.tsx` is the read-only rendering half), `components/agent-chat/ChatPanels.tsx` (+ `components/agent-chat/chatPanels.css`, the zoom panel's motion), `components/agent-chat/MessageIndex.tsx` (+ `components/agent-chat/messageIndex.css` and `components/agent-chat/useMessageIndex.ts`, the loop-scoped jump index over saved transcripts), `components/agent-chat/ComposerAddMenu.tsx` (the plus menu's actions), `components/agent-chat/ComposerAttachments.tsx` (+ `components/agent-chat/composerAttachments.css`, the local attachment drafts — preview URLs are never sent), `components/agent-chat/items.tsx`, `components/agent-chat/cards.tsx`, `components/agent-chat/parts.tsx`, `components/agent-chat/agentStyle.ts`, `components/agent-chat/types.ts`, `components/agent-chat/fromEvents.ts`, `components/agent-chat/fromTranscript.ts`, `components/agent-chat/fromLoopTranscript.ts` (the cross-step loop-page mapping), `components/agent-chat/session.ts`, `components/agent-chat/policyText.ts` (the verdict sentence split into rule and chips, never reworded), `components/agent-chat/handoffText.ts` (a step's closing handoff JSON shown as its summary prose; `components/agent-chat/handoffText.test.ts` pins it), `components/agent-chat/mood.ts` (an agent's avatar mood read off the chat's items and session: stuck, thinking, working, idle, done), `components/agent-chat/agentChat.css` (its motion — enter, expand, attention, settle — all off under reduced motion), `components/agent-chat/README.md` (its own design record) and `components/agent-chat/index.ts` — render daemon events and saved transcripts through one presentation model, and are covered by `test/agent-chat-adapters.test.ts` and `test/agent-chat-component.test.tsx`. The kit's own `Chat` was not used: it owns its storage and streams from an OpenAI-compatible endpoint, where Aeon's chat is driven by the daemon's event stream.

Aeon's own icon set, `components/icons/` (2026-10-25) — `components/icons/AppIcon.tsx`, `components/icons/AeonIcon.tsx` (the brand mark as an inline currentColor glyph, beside the file-based registry), `components/icons/icons.ts` and `components/icons/index.ts` — is a React port of plai-client-app's AppIcon registry, changed to read the SVG files in `src/icons/` as drawn (per-icon viewBox and paint, sanitised at load) instead of inner markup kept in a TS map. The kit's CustomIcon stays for kit-style glyphs; AppIcon is for markup Aeon draws itself. Covered by `test/app-icon.test.tsx`, which also holds the contract that every file in `src/icons/` is a registered name (the brand images live in `src/assets/`, not there — `Logo.tsx` imports them as Vite assets, not inline icons).

Aeon's own `components/Logo.tsx` (S41) replaces the three-deep copy of "two `<img>` tags, one `dark:hidden`, one `hidden dark:block`" that `app/PageLayout.tsx` and `app/SplashScreen.tsx` each carried separately, built on the kit's `useIsDarkMode` — a read-only observer of the `dark` class, not a second owner of theme state alongside `lib/appSettings.ts`. It imports the four brand marks from `src/assets/` (`logo.svg`, `logo_animated.svg`, `logo_dark.svg`, `logo_dark_animated.svg`) as Vite assets — kept out of `src/icons/` so the icon registry's "every file is a registered name" contract (`test/app-icon.test.tsx`) stays honest. `features/home/pages/HomeScreen.tsx` keeps its own animated logo pair rather than using it, by choice, not oversight.

Aeon's own `components/OverlaySidePanel.tsx` is the one right-edge detail panel (a portal overlay that mounts closed and opens on the next frame so the kit's slide plays, and slides out before the page unmounts it); the agents page and the Tools page share it. Covered by the agents and tools suites. Aeon's own `components/AgentPicker.tsx` (S45 T9, PM12; S46 reuses it) is the one agent-identity picker the Settings surfaces (policy, MCP, tools) share: a searchable, disabled-when-unavailable control whose output is always a real `agent.list` roster value or empty — never a free-typed slug. Covered by `components/AgentPicker.test.tsx`. Aeon's own `components/AgentTagPicker.tsx` is the same roster-only identity rule drawn as the kit's tag picker (`AgentTagPicker` for one agent, `AgentTagsPicker` for several); the Policy page uses it for every target, covered by the policy suites. Aeon's own `components/PageTitle.tsx` is the title block of a management page: the heading, its purpose line and, when there is something to explain, the kit's `HelpButton` rendering Markdown from the i18n catalogs (the Gates page uses it first), covered by the Gates suite.

Aeon's own diff surface (2026-11): `components/diffModel.ts` reads a unified diff into drawable rows — pure, no DOM and no highlighter — covered by `test/diff-model.test.ts`; `components/DiffView.tsx` draws those rows with old/new line numbers and add/delete shading, and with `components/CodeBlock.tsx` — Aeon's read-only syntax-highlighted code block, its `prism-react-renderer` theme driven by the `--code-*` CSS variables in `src/index.css` so it follows the app's light and dark palette, and its element tree can never become markup — shows a file's diff in the loop workspace's Changes and Files inspector tabs. `components/DetachedNote.tsx` is the one quiet "detached / deleted / closed" note the record surfaces share (the roadmap page first): the notes on a screen read `loop.tombstones` through one rate-limited cached read rather than one per row, covered by `test/loop-lifecycle.test.tsx`.

Aeon's own `components/agent-chat/` additions (2026-11): `components/agent-chat/useStableItems.ts` keeps a chat item's identity stable across event re-derivation so a live stream does not remount or reorder rows (`test/stable-items.test.tsx`); `components/agent-chat/WorkingIndicator.tsx` is the foot-of-stream line naming what the loop is waiting on between events, silent while a reply streams, a call runs, or the loop waits on the person — rendered through `ChatStream.tsx`, with no dedicated suite of its own (a validation gap); `components/agent-chat/ChangesPanel.tsx` is the changed-files list with per-file `+`/`−` counts and staged "Show more" (`test/changes-panel.test.tsx`); `components/agent-chat/QuestionForm.tsx` renders the multi-question form the daemon encodes in a question's `form:`-prefixed options, a skipped question answering `(skipped)` (`test/question-form.test.tsx`); and `components/agent-chat/TurnMeta.tsx` is the quiet per-turn tokens/cost/duration line, where an unreported cost reads as unreported and never `$0` (`test/turn-meta.test.tsx`).

Aeon's own `components/minion-avatar/` (vendored per its README, S43 agent avatars) — `components/minion-avatar/index.ts`, `components/minion-avatar/MinionAvatar.tsx`, `components/minion-avatar/MinionAvatarDemo.tsx`, `components/minion-avatar/MinionAvatar.test.tsx`, `components/minion-avatar/MinionAvatar.css`, `components/minion-avatar/CatFeatures.tsx`, `components/minion-avatar/catCharacters.ts`, `components/minion-avatar/characters.ts`, `components/minion-avatar/useMinionAnimation.ts`, `components/minion-avatar/README.md` and `components/minion-avatar/vitest.config.ts`, `components/minion-avatar/minionIdentity.ts`, `components/minion-avatar/minionIdentity.test.ts` (its own isolated vitest root) — is a portable React+TypeScript avatar with no runtime dependencies beyond React. It renders the agent avatars on the S43 agent-management surface. It is not a v1 port (v1 had no avatars); its `node_modules/` is its own test cache, ignored and skipped by this inventory's walker.

The v1 platform exception is deliberate: copying `platform/tauri.ts` as specified in T5 would introduce direct `readTextFile` and `listDirectory` calls in the web layer, breaking S9's no-store-filesystem contract. The app does not import the v1 HTTP client, `EventSource`, or platform filesystem API.
